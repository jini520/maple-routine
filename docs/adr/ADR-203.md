# ADR-203: 금액 칸은 글자를 들고, 셈만 숫자로 한다

> 🟢 유효 · 2026-09-02 · **구현 완료** · 실기기 미검증

## 맥락

시트의 금액 칸은 값을 **숫자로** 들고 있었고, 화면에 그릴 글자를 그 숫자에서 다시 만들었다.

```tsx
value={typed === 0 ? '' : typed.toLocaleString()}
onChangeText={(text) => setTyped(parseMesoText(typed, text))}
```

그래서 **가운데를 고칠 수 없다.** `80000000000` 을 `60000000000` 으로 바꾸려면 `8` 과 `0` 사이에
커서를 두고 `8` 을 지운 뒤 `6` 을 치는 것이 보통인데, 그 순간 이렇게 된다.

```
80,000,000,000  →  8 을 지운다  →  0,000,000,000
                →  숫자로 접는다 →  0
                →  글자를 다시 만든다 → ''   ← 칸이 통째로 비었다
```

앞자리 하나를 지웠을 뿐인데 **처음부터 다시 쳐야 한다**(사용자 보고 2026-09-02). 자릿수가 많은
메소 금액에서 특히 아프다.

원인은 `parseMesoText` 가 앞자리 0 을 접는 것이 아니라, **값이 화면 글자의 유일한 출처**라는 데
있다. 편집 중인 글자는 값으로 접히면 사라지는 정보다.

## 결정

### 결정 1. 칸은 사용자가 친 글자를 그대로 들고, 셈은 그 글자에서 뽑는다

폼이 `useState<string>` 을 들고, 필요할 때 `mesoValueOf` 로 숫자를 뽑는다.

| 함수 | 하는 일 |
|---|---|
| `acceptMesoText(prev, next)` | 칸에 남길 글자. 숫자만 남기고 상한을 넘기면 안 먹는다 |
| `mesoValueOf(text)` | 셈에 쓰는 값. 빈 칸도 0 이다 |
| `mesoTextOf(value)` | 값을 칸의 글자로. **0 은 빈 칸**이다 |
| `settleMesoText(text)` | 커서가 빠질 때 정리(결정 2) |

`acceptMesoText` 가 `parseMesoText` 와 갈리는 자리는 하나다. **앞자리 0 을 안 걷는다.**
`0000000000` 은 편집 중인 상태이지 0 이 아니다.

**칸의 콤마를 뺀다**(사용자 지정 2026-09-02). 글자를 그대로 들고 있어야 커서가 안 튀는데, 콤마를
다시 붙이려면 타건마다 서식을 다시 입혀야 하고 그러면 같은 문제가 돌아온다. 자릿수를 읽어 주는
일은 밑의 큰 숫자가 이미 한다([[ADR-202]] 결정 9) — `80000000000` 밑에 `8조` 가 선다.

### 결정 2. 앞자리 0 은 커서가 빠질 때 걷는다

`0000000000` 인 채로 칸을 벗어나면 **빈 칸**이 되고, `007` 은 `7` 이 된다.

타건마다 걷으면 결정 1 이 막으려던 그것이 그대로 되살아난다. `8` 을 지운 `0000000000` 이 즉시
빈 칸이 되어 다시 처음부터 쳐야 한다.

필수 칸에 0 이 남는 것은 이것으로 막힌다(사용자 지정 2026-09-02). 저장을 막는 판정은 그대로다 —
`canSave` 가 합계를 보고 있어서, 빈 칸이든 0 이든 저장 버튼은 꺼져 있다.

### 결정 3. 키보드는 숫자판 그대로다

값이 글자가 된 것과 **무엇으로 치느냐**는 다른 이야기다. `keyboardType` 은 `number-pad` 로 둔다.
글자 키보드를 열면 자판을 한 번 더 옮겨야 하고, 이 칸에 들어갈 것은 여전히 숫자뿐이다.

### 결정 4. 칸을 `sheet-fields` 의 `AmountInput` 한 부품으로 모은다

커서가 빠질 때 정리하는 일(결정 2)이 칸의 성질이라 칸마다 손으로 달면 한 곳이 빠졌을 때 **그
칸만 조용히 안 정리된다.** 여덟 자리가 같은 모양이었으므로 부품 하나로 모은다.

| 자리 | 칸 |
|---|---|
| `income/ItemSaleForm` | 판매 대금 |
| `income/HuntManualForm` | 획득 메소 |
| `income/EtcForm` | 금액 |
| `income/form-shared` `FragmentFields` | 솔 에르다 조각 · 조각 가격 |
| `spend/ItemBuyForm` | 단가 · 구매 비용 · 수량 |
| `spend/EtcForm` | 금액 |

시세 칸 둘(`income/EtcForm` · `spend/form-shared` 의 `RateRow`)은 **원래부터 글자를 들고 있어서**
이 문제가 없었다. 모양이 달라(값이 없으면 에러색) 그대로 뒀다.

## 대안과 버린 이유

**콤마를 유지하고 커서 위치를 직접 계산한다.** 타건마다 커서 앞의 자릿수를 세고, 서식을 다시
입힌 뒤 그 자릿수에 해당하는 자리로 `selection` 을 되돌린다. 읽기는 그대로 지킬 수 있다.
그런데 이 칸은 [[ADR-170]] 정정 10·12·13 이 **세 번 연달아 고친 자리**다(안드로이드 IME 조합,
되쓰기, 줄 상자). 통제하는 상태를 하나 더 얹으면 그 셋이 다시 열린다.

**`parseMesoText` 가 앞자리 0 을 안 걷게 고친다.** 한 줄이면 된다. 그런데 값이 화면 글자의 출처인
구조는 그대로라, `0000000000` 이 `Number` 로 접히는 순간 다시 `''` 이 된다. 원인이 파서가 아니라
**값에서 글자를 다시 만드는 것**이라 그 자리를 고쳐야 한다.

## 열린 질문

`components/molecules/MesoPad/MesoAmountField` 도 같은 모양이라 같은 버그가 있다(드롭 판매가
화면). 이번 지정이 수입·지출 시트였으므로 안 건드렸다. 그쪽은 앱 키패드가 값을 넣는 자리라
([[ADR-124]] 결정 5) 커서를 옮길 일이 있는지부터 봐야 한다.
