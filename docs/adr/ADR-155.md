# ADR-155: 저장소를 앱 하나로 편다 — 캐패시터 소스 삭제와 모노레포 해체

**날짜**: 2026-08-21
**상태**: 결정 · **구현 완료**(2026-08-21) — 태그 `store-1.0.6-capacitor-sunset` 이 재구성 전 트리를 고정한다
**관련**: [[ADR-128]](RN 전환 — 이 ADR 이 그 5단계를 닫는다) · [[ADR-154]](캐패시터 앱의 종료 —
결정 4 가 소스 삭제를 스토어 일정에서 풀어 놨다) · [[ADR-137]](RN OTA · runtimeVersion) ·
[[ADR-129]](에셋 목록을 커밋 시점에 만든다) · [[ADR-001]]·[[ADR-002]](이 ADR 이 폐기하는 것)

## 맥락

`packages/` 가 셋으로 갈린 이유는 **두 앱을 나란히 두고 옮기기 위해서**였다([[ADR-128]] 0단계) —
캐패시터 앱이 스토어에서 도는 동안 RN 앱을 그 옆에서 키우고, 둘이 함께 쓰는 것을 `core` 에 뒀다.

그 이유가 전부 사라졌다.

- **스토어 바이너리는 RN 이다.** iOS build 13 · Android versionCode 21 이 그것이고, 같은
  `com.mapleroutine.app` 이라 기존 사용자는 스토어 업데이트 한 번으로 넘어온다.
- **캐패시터 앱에 마지막으로 할 일이 끝났다.** [[ADR-154]] 1단계가 `1.0.6.zip` 을 올렸고, 남은
  2·3단계는 `gh release upload ota/latest.json --clobber` **한 줄**이라 소스도 빌드도 안 쓴다.
  그 ADR 의 결정 4 가 이 삭제를 «어느 스토어도 안 기다리는 일» 로 만들어 뒀다.
- **`core` 를 «공유» 층이라 부를 상대가 없다.** 앱이 하나면 그것은 공유가 아니라 그냥 층이다.

한편 워크스페이스는 비용을 계속 낸다 — 설정이 층마다 갈리고(`tsconfig` 넷 · `vite.config` 둘 ·
`package.json` 넷), 루트 `npm run build` 가 **캐패시터를 부르는 이름**이며, `@core/*` 매핑이 네
곳에 흩어져 있다. 지울 앱을 위해 이 비용을 계속 낼 이유가 없다.

## 결정

### 결정 1 — `packages/app-capacitor` 를 지운다. 남기는 것은 셋뿐이다

지우는 것은 소스·네이티브 프로젝트(`android/`·`ios/`)·에셋·테스트 전부다(추적 파일 322개).
**그 앱이 남긴 것 중 앞으로도 필요한 것은 셋이고, 셋 다 캐패시터 코드가 아니다.**

| 남기는 것 | 왜 | 어디로 |
|---|---|---|
| `ota/latest.json` | [[ADR-154]] 2·3단계를 켜는 **유일한 재료**. `url`·`checksum`·`size` 는 그 빌드에서만 나오는 값이라 재생성할 방법이 없다 | 그 자리 |
| `parseLiveUpdateManifest` | 위 파일이 **기기에서 실제로 파싱되는지** 지키는 가드가 이 함수를 쓴다 | `ota/manifest-parser.ts` 로 **동결 사본** (결정 5) |
| Tailwind v4 축 | RN 의 `tailwind.config.js` 가 이것 없이는 안 뜬다 (결정 4) | `tailwind-v4-axes.cjs` 에 **값 동결** |

**`capacitor` 라는 낱말이 붙었다고 지우지 않는다.** `modules/capacitor-storage` ·
`src/storage/adapters/capacitor-storage-keys.ts` 는 프레임워크가 아니라 **기존 사용자 데이터가
들어 있는 저장소의 이름**이다(`CapacitorStorage` SharedPreferences 파일 · `UserDefaults` 키 접두사
— `docs/migration/data.md` 결정 1). 지우면 기존 사용자의 데이터가 조용히 안 읽힌다.

### 결정 2 — 저장소 루트가 곧 Expo 앱이다. `core` 는 최상위 디렉터리로 내려앉는다

```
/                       ← Expo 프로젝트 루트 (app.json · App.tsx · metro.config.js · android/ · ios/)
├── src/                ← **앱 전부**. 화면·컴포넌트·네비게이션·어댑터 + 로직·데이터·에셋·포트
│   ├── app/ components/ navigation/ theme/     (옛 app-rn/src)
│   └── features/ data/ assets/ nexon/ types/   (옛 core/src)
│       lib/ native/ storage/                   ← 세 디렉터리는 양쪽이 **합쳐졌다**
├── ota/                ← 캐패시터 최종 매니페스트와 그 가드      (결정 5)
├── scripts/ workers/ site/ docs/ phases/
└── package.json        ← 하나. workspaces 없음
```

`packages/` 가 없어지고 `node_modules` 도 한 벌이 된다. **Metro 가 프로젝트 밖을 안 보게 되는
것**이 부수적으로 따라온다 — `watchFolders` 로 저장소 루트를 끌어오고 `nodeModulesPaths` 를 둘로
두던 모노레포 배선이 통째로 필요 없어진다(`metro.config.js` 의 ①·②).

### 결정 3 — `core` 를 해체해 `src/` 에 **완전히 병합한다**. `@core/*` alias 는 없앤다

디렉터리를 옮기고 alias 를 유지하면 «패키지가 하나 줄었다» 일 뿐, 코드를 읽는 사람에게는 여전히
두 세계다(`@core/lib/...` 와 `../../lib/...` 가 한 파일에서 섞인다). 앱이 하나면 층은 **디렉터리
이름**으로 충분하고, 그 이상의 경계 장치는 비용만 남는다.

```
core/lib      →  src/lib        (합침 — 파일 이름 충돌 0건)
core/native   →  src/native     (core 는 포트, src 는 `adapters/` — 나란히 산다)
core/storage  →  src/storage    (〃)
core/features →  src/features   (src 에 없던 디렉터리라 그대로 내려앉는다)
core/{data,assets,nexon,types}  →  src/…
```

**옮기기 전에 충돌을 셌다 — 0건이다.** 겹치는 것은 세 디렉터리 이름뿐이고 그 안의 파일 이름은
하나도 겹치지 않아, 이름을 바꾸거나 합치는 판단이 필요 없었다.

import 은 **929곳을 상대 경로로 기계 치환**했다(`@core/X` → 그 파일에서 `src/X` 까지의 상대 경로).
`from`·동적 `import()`·`jest.mock`·`typeof import()` 가 전부 같은 형태(따옴표 안 모듈 지정자)라
한 규칙으로 덮인다. 그 결과 **저장소에 alias 가 하나도 남지 않았다** — `tsconfig.json` 의 `paths` ·
`vite.config.ts` 의 `resolve.alias` · jest 의 파생 매퍼가 전부 사라졌고, tsc·Metro·jest 가 같은
상대 경로를 본다. 「선언이 한 벌이라 갈라질 자리가 없다」([[ADR-128]] 결정 3)가 「선언 자체가
없다」로 한 칸 더 갔다.

**잃는 것을 적어 둔다.** «core 는 `react-native` 를 모른다» 가 **디렉터리 구조로는 더 이상 강제되지
않는다.** 그 규칙은 이제 사람이 지킨다 — `src/features/`·`src/lib/`·`src/storage/`·`src/nexon/` 에
RN import 을 넣지 마라. 그 층들이 여전히 그런 이유는 ⓐ 테스트가 node 에서 3초에 도는 것이 그
성질에서 나오고 ⓑ 화면을 다시 그릴 때 갈아엎히지 않는 코드가 거기 있기 때문이다.

이 해체가 부순 가드 셋도 함께 손봤다(전부 «경로로 두 세계를 갈랐기» 때문에 성립하던 것들이다):

| 가드 | 무엇이 깨졌나 | 어떻게 고쳤나 |
|---|---|---|
| `interstitial-policy` | 광고 모듈이 `src/` 로 들어와 **정의 자체가 금지어에 걸렸다** | 정의 모듈(`features/ads/`)을 스캔에서 빼 **«아무도 부르지 않는가»** 로 되돌렸다 |
| `require-cycle-policy` | 그래프를 `RN_SRC` + `CORE_SRC` 둘로 모았다 | 하나가 됐다. `@core/` 해석 분기도 삭제 |
| `core-wiring` | 물음이 «`@core/*` 가 jest 에서 풀리는가» 였다 | **삭제** — 그 alias 가 없다 |
| `core-shims` | «core 모듈을 RN 구현으로 갈아끼우는 표» 를 지켰다 | 기구째 삭제(`core-shims.js`·Metro 훅·jest 매퍼). 살릴 값이 있는 **글롭 금지** 한 조만 `vite-only-api-policy` 로 옮겼고, 대상이 `core/` 에서 `src/` 로 넓어졌다 |

### 결정 4 — `tailwind-v4-axes.cjs` 는 **읽기를 그만두고 값을 동결한다**

이 파일은 지금 `packages/app-capacitor/node_modules` 의 **Tailwind v4** `theme.css` 를 읽는다.
읽은 값을 RN 의 `tailwind.config.js` 가 그대로 쓰므로, 캐패시터를 지우면 **Metro 도 jest 도
안 뜬다.** 삭제 전에 반드시 끊어야 하는 매듭이고, 이 ADR 에서 가장 조용히 위험한 자리다.

**동결이 맞는 이유는 대조할 상대가 사라지기 때문이다.** 원래 이 파일이 값을 베끼지 않고 읽은
이유는 *"두 앱이 서로 다른 Tailwind 메이저를 물고 있으니, 웹이 올라가면 이쪽도 따라 움직여야
한다"* 였다. 웹이 없어지면 **따라 움직일 상대가 없다.** 남는 것은 RN 이 필요로 하는 축 값들뿐이고,
그것은 이제 «파생» 이 아니라 «이 앱의 치수» 다.

읽어 오던 입력은 실제로 셋뿐이라 동결이 작다(파생 로직 `deriveSpacing` 은 그대로 둔다):

| 입력 | 값 | 출처 |
|---|---|---|
| `--spacing` | `0.25rem` | tailwindcss **4.3.3** `theme.css` |
| `--container-*` | 13종 (`3xs` 16rem … `7xl` 80rem) | 〃 |
| `--radius-*` | 8종 (`xs` 0.125rem … `4xl` 2rem) | 〃 |

값이 바뀌지 않는다는 것은 기존 테스트가 그대로 지킨다 — `src/__tests__/tailwind-axes.test.ts` 의
«v4 축 파생» 이 `spacing[13]=3.25rem`·`max-w-2xs`(288, [[ADR-121]]) 같은 **사람이 정한 수치**를
직접 단언하고 있고, 그 케이스들은 한 줄도 안 고친다. 같은 파일의 *"웹은 v4 를 집는다"* 하나만
지운다 — 그 웹이 없다.

### 결정 5 — 캐패시터 OTA 의 잔재는 `ota/` 한 디렉터리에 모은다

```
ota/
├── latest.json          ← 2·3단계에 gh 로 올릴 파일
├── manifest-parser.ts   ← 1.0.6 번들에 실린 파서의 **동결 사본**(발췌 3,005자, 한 글자도 안 다름)
└── __tests__/latest.test.mjs
```

`scripts/publish-live-update.mjs` 는 **지운다.** 그것이 하는 일은 «앱을 빌드해 zip 을 만들고
매니페스트를 갱신해 올리기» 인데 빌드할 앱이 없고, 남은 2·3단계는 `gh release upload` 한 줄이다
([[ADR-154]] 결정 4). 그 스크립트를 검사하던 테스트도 함께 지우고, **`ota/latest.json` 형식을
지키는 describe 하나만** 위 자리로 옮긴다.

**파서를 «동결 사본» 으로 두는 것이 이 결정의 요점이다.** 가드가 답해야 하는 질문은
*"기기에 있는 그 앱이 이 파일을 읽을 수 있는가"* 이고, 그 앱은 **1.0.6 에서 영원히 멈춰 있다.**
그러니 참조 대상도 멈춰 있어야 맞다 — 원본이 살아 있었어도 그것을 «개선» 하는 순간 가드는 기기의
현실이 아니라 저장소의 현재를 검사하게 된다. 파일 머리에 출처(원본 경로·커밋)를 적고 **고치지
말 것**을 명시한다.

### 결정 6 — 테스트 러너 둘은 그대로 두고, **경계를 경로에서 확장자로 옮긴다**

```
*.spec.ts(x)  → vitest — react-native 을 안 쓰는 순수 로직·데이터·저장소 (node, 1,849개 3초)
*.test.ts(x)  → jest   — RN 을 렌더하거나 RN 모듈을 목하는 것 (jest-expo)
```

결정 3 이 두 러너의 테스트를 **같은 `__tests__` 디렉터리에 섞어 놓았다.** 종전에는
`packages/core` 냐 `packages/app-rn` 이냐로 갈렸고 그것이 각 설정의 한 줄(`testPathIgnorePatterns` ·
`exclude`)이었는데, 한 트리가 되면서 경로로는 못 가른다. 그래서 파일 이름이 그 일을 한다 —
`core/` 에서 온 113개를 `*.spec.*` 로 바꿨다.

**러너를 하나로 합치지 않은 이유는 그것이 이 작업의 몇 배이기 때문이다.** vitest → jest 이관을
실제로 재 봤다: `vi.hoisted` 66곳(jest 에 짝이 없어 자리마다 재구성) · `vi.stubGlobal` 25곳 ·
`vi.waitFor` 39곳 · `expect(값, 메시지)` 170곳(jest 는 두 번째 인자를 **조용히 버린다**). 1,849개를
한꺼번에 옮기면서 실패 모드가 «조용히 덜 검사하는 것» 인 작업이라, 구조 변경과 같은 커밋에 둘 수
없다. 별도 작업으로 남긴다.

경계가 **조용히 어긋나지는 않는다** — 한쪽이 다른 쪽 파일을 집으면 그 자리에서 죽는다(vitest 가
`react-native` 를 import 하면, jest 가 `vitest` 를 import 하면).

캐패시터가 없어져도 vitest 가 남는 이유는 그것이 도는 대상이 «웹 앱» 이 아니라 **로직 층**이었기
때문이다. 다만 그 설정이 삭제 대상 **안에** 있어서(`app-capacitor/vite.config.ts` 를 루트가 그대로
re-export 했다) 슬림 `vite.config.ts` + `vitest.setup.ts` 로 새로 뒀고, `installNoopNativePorts` 는
포트 옆이 맞는 자리라 `src/native/__tests__/` 로 옮겼다.

### 결정 7 — 타입 검사 커맨드를 되살린다 (`npm run typecheck`)

지금 이 저장소에서 `tsc` 를 도는 유일한 자리는 **캐패시터의 `build` 스크립트**(`tsc -b && vite
build`)다. 그것이 사라지면 타입 검사가 **0** 이 된다(루트 `tsconfig.json` 은 참조 스텁이라
`--noEmit` 이 검사 대상 0개로 조용히 통과한다).

루트 `tsconfig.json` 이 RN 프로젝트 설정으로 바뀌면서 그 스텁 문제도 함께 없어지므로,
`"typecheck"` 를 둔다. **이 ADR 이 없애는 게이트를 그 자리에서 되돌려 놓는 것**이지 새 기능이 아니다.

프로그램은 **둘**이다(`tsc --noEmit && tsc --noEmit -p tsconfig.vitest.json`). 갈리는 이유는 하나뿐 —
core 의 vitest 테스트는 Vite 위에서 돌아 `import.meta.glob` 이 **사실**인데, 앱 프로그램에는 그 선언이
**일부러** 없다([[ADR-129]] 가 제품 코드에서 glob 을 없애며 선언까지 지웠다 — 남기면 "쓰면 타입은
통과하고 RN 런타임에 죽는" 함정이 산다). 종전에 `tsconfig.base.json` 의 `types: ["vite/client"]` 가
하던 일을 `vitest-import-meta.d.ts` 한 줄이 대신한다(`vite/client` 를 통째로 켜면 에셋 모듈이
`string`(URL)이 되어 RN 의 `number` 와 충돌한다 — 실측).

## 대가

### expo 지문이 바뀐다 — 심사 중인 바이너리에는 이 트리에서 OTA 를 못 쏜다

RN 의 OTA 는 버전이 아니라 `runtimeVersion`(= 네이티브 트리 fingerprint)으로 매칭된다
(`foundation/release.md` 「스토어 바이너리와 OTA 의 runtimeVersion」). 그 지문의 재료에는
**`.gitignore` · `package.json` 의 `scripts` · `node_modules` 파일들의 경로**가 들어 있고
(실측 92 소스), 이 ADR 은 셋 다 바꾼다.

| | 지문 | 소스 수 |
|---|---|---|
| 재구성 **전** | `b61176ace9d2139c3599319de60599e4417d3073` | 92 |
| 재구성 **후** | `32038814d84b7764ce98016692ab36544d46afdd` | 93 |

둘 다 2026-08-21 실측이다. 그래서 **iOS build 13/14 · Android versionCode 21 에 OTA 를 쏘려면 옛
트리가 필요하다.**

그 트리를 태그로 고정한다 — **`store-1.0.6-capacitor-sunset`**. 긴급 수정이 필요하면 그것을
체크아웃해 `publish-rn-ota.mjs` 를 돌린다.

**[[ADR-154]] 2·3단계는 이 대가와 무관하다** — 그쪽은 `gh release upload` 한 줄이라 트리를 안 쓴다.
iOS 심사가 끝나면 지금 이 저장소 상태 그대로 칠 수 있다.

### 그 밖

- **스냅샷의 경로 문자열이 바뀐다.** RN 스냅샷 8개가 `../../../packages/core/src/assets/...` 를
  담고 있다(17곳). **`jest -u` 를 쓰지 않고 그 문자열만 치환한다** — 통째로 갱신하면 이미 깨져 있는
  날짜 스냅샷(아래 «결과»)이 조용히 덮인다. 경로 외의 diff 가 나오면 그것은 회귀이고, 그것이 이
  변경의 검증 방법이다.
- **`ios/Podfile.lock` 을 다시 만든다.** `../../../node_modules` 가 `../node_modules` 가 된다.
  오히려 Expo 기본 배치로 돌아가는 방향이다.
- **`package-lock.json` 이 통째로 다시 쓰인다.** 워크스페이스 셋이 하나가 되므로 diff 가 크지만
  내용은 «호이스팅 대상이 원래 자리로 왔다» 뿐이다.

## 대안과 기각

- **`packages/` 를 유지하고 `app-capacitor` 만 지운다** — 가장 작은 변경이다. 기각: 워크스페이스
  하나짜리 모노레포는 설정 비용만 남고 이득이 0 이다. Metro 의 모노레포 배선·`@core` 매핑 네
  벌·`tsconfig` 넷이 «두 앱» 을 전제로 서 있는데 그 전제가 없어졌다.
- **`core/` 를 최상위 디렉터리로 남기고 `@core/*` alias 만 유지한다** — import 을 한 줄도 안 고쳐도
  되는 안이고, 실제로 **한 번 그렇게 만들었다가 되돌렸다**(사용자 지적, 2026-08-21). 기각: 그것은
  «패키지가 하나 줄었다» 일 뿐 코드를 읽는 사람에게는 여전히 두 세계다 — 한 파일 안에서
  `@core/lib/...` 와 `../../lib/...` 가 섞이고, 「어디에 두어야 하나」를 물을 때마다 사라진 경계를
  다시 설명해야 한다. 병합의 실제 비용은 예상보다 작았다(**파일 이름 충돌 0건**, import 은 기계
  치환 929곳).
- **테스트를 jest 하나로 통합한다** — 결정 6 에 실측한 이관 비용을 적었다(`vi.hoisted` 66 ·
  `vi.stubGlobal` 25 · `expect(값, 메시지)` 170 …). 언젠가 할 수 있지만 **이번 변경과 같은 커밋에
  둘 수 없다** — 실패 모드가 «조용히 덜 검사하는 것» 이라 판정 기준을 잃는다.
- **캐패시터를 브랜치로 남기고 main 에서만 지운다** — 기각: 태그가 같은 일을 하고 관리 비용이
  없다. 브랜치는 «따라와야 할 것» 처럼 보여서 오히려 오해를 만든다.
- **Tailwind v4 를 별칭 의존성(`npm:tailwindcss@4`)으로 루트에 남겨 계속 읽는다** — 기각: CSS
  파일 하나를 읽으려고 메이저 하나를 통째로 설치하는 것이고, 그렇게 지키는 «따라 움직임» 은
  결정 4 대로 상대가 없어 뜻이 없다.

**vitest 는 병합 전후로 한 개도 안 변했다** — 로직 층은 자리만 옮겼다.

jest 의 −16개는 전부 정산된다: `core-wiring`(2개)과 `core-shims`(16개)를 지우고
`vite-only-api-policy`(2개)를 더했다. 셋 다 **주체가 사라져서**이지 검사를 줄인 것이 아니다 —
앞의 둘은 `@core/*` alias 와 core 치환 기구를 지키던 테스트이고, 그 둘이 이 ADR 로 없어졌다.

빌드도 양쪽 다 확인했다 — `expo export --platform android`(hbc 5MB, `src/assets/…` 포함) ·
`./gradlew :app:assembleDebug` **성공** · `pod install` 로 `Podfile.lock` 211줄 경로 재생성.

jest 의 실패 1건은 이 작업 **전부터** 있었다 — `BossProfitScreen` 스냅샷이 「8월 13일 ~ 8월 19일」을
담고 있어 **주가 바뀌면 깨진다**(별개 결함, 이 ADR 의 범위 밖). 그래서 스냅샷 8개를 `jest -u` 로
갱신하지 않고 **경로 문자열만** 치환했다 — 통째로 갱신하면 그 결함이 조용히 묻힌다.

### 추적 밖 잔재 1.9GB 도 지웠다 (2026-08-21)

`git rm` 은 추적 파일 322개만 지운다. 디스크에는 gitignore 대상 1.9GB 가 남았고 — `ios/` 1.5GB
(Pods·DerivedData·build) · `android/` 367MB · `node_modules` · `dist` · `npx cap sync` 가 네이티브
프로젝트에 복사해 둔 웹 번들 — **그 앱은 다시 빌드되지 않으므로**(결정 1) 전부 지웠다. `npm run
lint` 가 그 안의 `native-bridge.js` 를 훑어 내던 **오류 12건도 함께 사라졌다.**

전수로 훑어 «저장소에 사본이 없는 것» 은 셋이었고, 그중 하나는 중복으로 판명됐다.

| | 판정 |
|---|---|
| `android/keystore.properties` | **중복** — 저장소의 `android/keystore.properties`(RN, gitignore 대상)와 바이트 동일 |
| `src/assets/ScreenEff/`(19MB·57파일) | 드롭 연출 프레임의 **최적화 전 원본**([[ADR-038]] — 저장소엔 최적화본만). 앱은 커밋된 webp 55장으로 돈다 |
| `resources/screenshots/`(26MB·38파일) | 스토어 리스팅 스크린샷. 최종본의 출처는 Play Console·App Store Connect 이고, 이 그림들은 **웹뷰 시절 화면**이라 RN 과 이미 다르다 |

뒤 둘은 앱이 쓰는 물건이 아니라 **소재**라 저장소 밖으로 옮겼다 —
`~/Developments/maple-routine-archive/`(체크섬 대조로 사본 확인, 출처는 그쪽 `README.md`).

### 삭제가 드러낸 것 셋

전부 «캐패시터가 대신 선언해 주던 것» 이고, 그것이 사라지자 드러났다.

- **`zustand` 가 미선언 의존이었다** — core 의 스토어 12곳이 쓰는데 `app-capacitor` 만 선언했고
  RN 은 호이스팅으로 얻어 썼다. 루트가 선언한다.
- **`lib/use-stack-back.ts`** — `react-router-dom` 을 쓰던 유일한 파일이고 참조가 0이었다.
- **`ToastAction.icon` 이 웹 타입이었다** — `lucide-react` 의 `LucideIcon` 이라 RN 아이콘이
  타입상 안 들어가 넘기는 쪽이 `as unknown as` 로 우회했다. `Toast.tsx` 가 파일 머리에 적어 둔
  해법(«플랫폼 중립 컴포넌트 타입으로 넓힌다») 그대로 고쳤다.

### 아직 안 한 것 — 소비자가 사라진 코드

캐패시터만 쓰던 core 코드가 몇 군데 «부르는 곳 0» 이 됐다. **구조 변경과 같은 커밋에 두지 않았다** —
그것들은 테스트 개수를 바꾸므로 위 «숫자가 같다» 판정을 흐린다.

- `src/features/ads/` · `src/storage/ads.ts` — 탭 전환 전면광고 오케스트레이션([[ADR-150]] 이
  RN 에서 걷었다). 인라인 광고 설계와 함께 판단한다(`features/ads.md` 열린 질문).
- `src/features/onboarding/flow.ts` — 그 파일 자신이 *"`app-capacitor` 가 걷히면 이 파일을 지우고
  `'all'` 만 남긴다"* 고 적어 뒀다([[ADR-143]] 결정 8).
- `src/lib/tracked-order.ts` — *"Capacitor 가 걷히면 이 함수는 core 정렬 안으로 흡수된다"*([[ADR-143]]
  결정 3).
- `src/types/image-asset.ts` — 웹 변형(`ImageAssetRef = string`). `moduleSuffixes` 가 `.native` 를
  먼저 고르므로 앱 프로그램은 이 파일을 안 본다(vitest 는 접미사를 안 봐 이쪽을 집는다).

## 열린 질문

- **`docs/migration/` 의 수명.** 그 디렉터리는 스스로 *"전환이 끝나면 문서도 함께 정리한다"* 고
  적어 뒀다(`docs/README.md`). 이 ADR 이 전환의 마지막 고리이므로 정리 대상이지만, `data.md`
  (기존 사용자 데이터를 RN 이 어떻게 읽는가)만은 **지금도 도는 코드의 설명**이라 남을 자리를 따로
  찾아야 한다(`persistence/` 가 유력).
- **`phases/` 의 옛 실행 기록.** 캐패시터 시절 경로를 가리키는 문장이 많지만 그것은 **그때의
  기록**이라 고치는 것이 오히려 거짓이 된다. 손대지 않는다.
