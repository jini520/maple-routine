# ADR-022+081 실패를 알리는 방법과 기간 데이터 상태

> 🟢 유효
> 옛 번호: ADR-008 · ADR-065 결정 4 · 5 · ADR-068 · ADR-114 결정 2 · 3 · 4 · ADR-117 결정 6
> 관련 소스: `nexon/http.ts` · `features/schedule-sync/errors.ts` · `features/schedule-sync/format.ts` · `features/schedule-sync/use-sync-error-toast.ts` · `components/molecules/ErrorState/StaleBanner.tsx` · `lib/boss/boss-profit-period.ts` · `app/boss-profit/CharacterIssue.tsx` · `features/nexon-maintenance/` · `app/NexonMaintenanceBanner.tsx` · `features/auth/store.ts` · `features/boss-profit/sqlite-guards.ts` · `components/organisms/ErrorBoundary/`

## 배경

이 앱은 넥슨 Open API, 기기 저장소(SQLite · Preferences), OS 기능에 의존해 동작한다. 셋 다 언제든 실패할 수 있다.
실패를 드문 예외로 다루면 화면이 아무 말 없이 멈추거나 옛 값을 최신처럼 보여 준다. 그러면 사용자는 왜 안
되는지 모른 채 게임을 다시 켜 보게 된다. 그래서 실패를 평소에 일어나는 상태로 보고, 무엇이 실패했는지와
사용자가 할 수 있는 일을 함께 알리기로 했다.

## 결정

### 결정 1. 실패해도 마지막으로 받은 값을 보여 주고, 자동으로 계속 다시 부르지 않는다

네트워크가 없거나, 시간이 초과되거나, 5xx 가 오면 마지막으로 받아 둔 캐시를 그대로 그린다. 다시 부르는 것은
사용자가 새로고침할 때뿐이다. 백그라운드에서 계속 다시 부르면 배터리만 쓰고 결과는 같기 때문이다.

- 넥슨 요청은 10초가 지나면 끊는다(`nexon/http.ts` 의 `REQUEST_TIMEOUT_MS`). 공식 권장값이 없어 모바일 API 의
  흔한 값을 골랐다.
- 응답이 JSON 이 아니면(차단 페이지 · 502 HTML 등) 네트워크 실패와 같이 다룬다. 응답 형식이 조금 다른 경우와는
  다른 문제라 따로 구분한다.

### 결정 2. 실패의 원인을 버리지 않는다

넥슨 호출이 던진 에러는 `toScheduleSyncError` 를 거쳐 아홉 종류(`ScheduleSyncError`)로 바뀐다. `invalidApiKey` ·
`rateLimited` · `characterUnavailable` · `periodOutOfRange` · `notCollected` · `network` · `signInRequired` ·
`gameMaintenance` · `apiMaintenance` 다.
`catch` 에서 `{ kind: 'network' }` 를 직접 만들면 401 과 429 가 화면까지 오지 못한다. 그래서 반드시 이 함수를
거친다. 모르는 400 코드는 `network` 로 떨어진다. 넥슨이 코드 체계를 바꿔도 다시 시도를 권하는 쪽으로 동작하게
하려는 것이다.

문구를 고르는 함수는 종류를 빠짐없이 다뤄야 한다. `tsconfig` 에 `noImplicitReturns` 가 없어서 경우 하나를
빠뜨려도 타입 오류가 나지 않는다. 그래서 `switch` 끝에 `assertNever` 를 두어, 종류를 더하면 바로 컴파일이
깨지게 했다.

### 결정 3. 문구의 양과 버튼은 문구가 놓이는 곳에 따라 정한다

같은 원인이라도 놓이는 곳에 따라 담을 수 있는 양이 다르다. 토스트 본문은 한 줄에서 잘린다. 그래서 토스트에는
원인만 쓰고, 처방은 줄을 더 쓸 수 있는 곳(목록 대신 보이는 `ErrorState` 와 스탈 배너)에 쓴다. 두 곳의 문구는
일부러 다르게 했으니 하나로 맞추지 않는다.

버튼은 누르면 실제로 문제가 풀릴 때만 둔다.

| 원인 | 토스트 | 목록이 없을 때(`ErrorState`) | 목록이 남았을 때(스탈 배너) |
|---|---|---|---|
| `rateLimited`(429) | 토스트 없음. 안내 모달이 알린다 | `호출 한도를 초과했습니다` / `입력하신 API 키가 서비스 단계 키인지 확인해주세요`, 버튼 없음 | `호출 한도를 초과했습니다. 서비스 단계 키인지 확인해주세요`, 버튼 없음 |
| `characterUnavailable` | `이 캐릭터는 조회할 수 없습니다`, 버튼 없음 | 버튼 없음. 계정을 바꾸라고 안내한다 | `이 계정의 캐릭터를 조회할 수 없습니다`, 버튼 없음 |
| `network` 계열 | `네트워크 오류가 발생했습니다` + `다시 시도` | `캐릭터 목록을 불러오지 못했습니다` + `다시 시도` | `목록이 최신이 아닙니다` + `다시 시도` |

- 429 에는 어디에도 `다시 시도` 를 두지 않는다. 일 한도를 다 썼으면 다음 날까지 안 풀리고, 처방이 키 단계를
  확인하라는 것인데 버튼이 다시 시도면 안내와 버튼이 서로 어긋난다.
- 429 문구에 초당 5건이나 일 1,000건 같은 수치를 넣지 않는다. 서비스 단계 키를 쓰는 사용자도 같은 문구를 보고,
  배너 한 줄에도 들어가야 하기 때문이다. 429 응답은 일 한도와 초당 한도를 구분해 주지 않으므로 앱도 둘을
  구분해 말하지 않는다.
- `characterUnavailable`(400 `OPENAPI00003`)은 영구 실패라 몇 번을 눌러도 같은 400 이 돌아온다.
- 스탈 배너는 아래에 목록이 남아 있어서 버튼이 없어도 사용자가 갇히지 않는다. `StaleBanner` 는 문구와
  버튼(선택)만 받고 `ScheduleSyncError` 는 모른다. 문구는 부르는 쪽이 `formatStaleRosterError` 로 만든다.
  molecule 이 feature 의 타입을 알면 컴포넌트 계층의 의존 방향이 거꾸로 되기 때문이다.
- 401 · 429 · 로그인 만료는 토스트 대신 닫을 수 없는 안내 모달로 알린다. 그 모달의 동작은 [[ADR-024]] 에 있다.

### 결정 4. 보스 수익의 한 기간은 다섯 상태 중 하나다

캐릭터 한 명의 한 기간이 어떤 상태인지는 `resolvePeriodDataState` 한 곳에서 정한다. 화면과 백필이 따로 판정하면
같은 기간에 `조회 불가` 와 `불러오지 못했습니다` 가 함께 뜰 수 있어서다.

| 상태 | 뜻 | 사용자가 할 일 |
|---|---|---|
| `recorded` | 기록이 있다 | 없음 |
| `confirmedEmpty` | 조회해서 0건을 확인했다 | 없음 |
| `notCollected` | 넥슨이 아직 집계하지 않았다(400 `OPENAPI00009`) | 없음. 시간이 지나면 풀린다 |
| `outOfRange` | 조회할 수 있는 날짜 밖이거나, 이 캐릭터에게만 막힌 기간이다 | 없음 |
| `failed` | 그 밖의 실패. 아직 받지 못한 기간도 여기에 속한다 | 다시 시도 |

- 한 번 0건을 확인한 기간은 시간이 지나 조회 가능한 날짜를 벗어나도 `confirmedEmpty` 로 남는다. 확인한 사실이
  시간이 지났다고 불확실해지면 안 되기 때문이다.
- 다시 해 볼 것(`notCollected` · `failed`)과 영구히 안 되는 것(`outOfRange`)을 같은 화면으로 보이지 않는다.
- 캐릭터가 여럿이면 `resolvePagePeriodState` 가 화면 하나의 상태로 합친다. 순서는 `recorded` > `failed` >
  `notCollected` > `outOfRange` > `confirmedEmpty` 다. 보여 줄 기록이 하나라도 있으면 그 기록을 보여 준다.
  그래서 목요일 리셋 직후 지난 주를 다시 받다 실패해도, 기록이 있으면 실패 문구를 띄우지 않는다. 사용자가
  할 일이 있는 `failed` 는 다른 상태 아래에 묻히지 않게 앞에 둔다. `confirmedEmpty` 는 모든 캐릭터가 확인했을
  때만 말한다. 하나라도 모르면 확인했다고 하지 않는다.
- 주간 합계 줄에서 금액은 `recorded` · `confirmedEmpty` 일 때만 보인다. `outOfRange` 는 `조회 불가`,
  `notCollected` 는 `집계 전` 이라고 적고, 버튼은 `failed` 의 `다시 시도` 하나뿐이다.

### 결정 5. 동기화에 실패한 캐릭터는 카드의 금액 위에 아이콘으로 표시한다

토스트는 실패한 인원 수만 말해서 어느 카드인지 알 수 없다. 그래서 지금 기간의 카드에서 금액의 왼쪽 위에
14px 아이콘을 띄운다. `unavailable`(조회할 수 없는 캐릭터)과 `failed`(동기화 실패) 두 가지다.

- 라벨 글자를 붙이지 않는다. 금액 옆에 글자 배지를 두면 캐릭터 이름이 여섯 글자부터 잘렸다.
- 아이콘만으로는 원인을 말할 수 없으니, 누르면 설명 팝오버가 열린다. 스크린리더는 `aria-label`(`조회 불가` ·
  `실패`)로 읽는다.
- 금액은 가리지 않는다. 카드 금액은 기기 DB 의 기록에서만 나오므로 동기화가 실패해도 틀린 값이 아니다.

### 결정 6. SQLite 조회는 5초를 넘기면 끊고, 읽기와 쓰기를 다르게 다룬다

앱을 다시 읽어 들인 직후 네이티브 SQLite 연결이 낡은 채로 남으면 첫 쿼리가 응답 없이 멈추는 일이 실기기에서
있었다. 그러면 화면이 불러오는 중에서 멈추거나, 기간 라벨만 바뀌고 숫자는 그대로 남는다. 그래서 SQLite 호출을
5초 타이머와 경쟁시킨다(`sqlite-guards.ts`).

- 읽기는 `withSqliteFallback` 이다. 시간이 넘으면 기본값으로 진행한다.
- 쓰기는 `withSqliteTimeout` 이다. 시간이 넘으면 실패로 던진다. 쓰기의 시간 초과를 성공으로 넘기면 저장되지
  않은 기간이 확인 완료로 남고, 다시는 받지 않는다.
- 앱을 다시 읽어 들이기 전(OTA 적용 · 데이터 삭제)에는 `closeBossProfitDb` 로 연결을 먼저 닫는다. 연결이 낡지 않게
  하는 것이 근본 대책이고, 위 타임아웃은 그래도 생기는 경우를 막는 장치다.

### 결정 7. 아무 신호 없이 끝나던 실패를 알린다

- **관리 화면의 추적 저장.** 컨텐츠 관리 · 보스 관리에서 체크를 저장하다 실패하면 체크가 되돌아갈 뿐 아무 설명이
  없었다. 이제 `추적 목록을 저장하지 못했습니다` 토스트를 띄운다. 무엇을 눌렀는지는 사용자가 알고 있으므로
  문구는 하나로 둔다. 다시 누르면 되는 일이라 버튼은 두지 않는다.
- **렌더 중 예외.** `App.tsx` 가 앱 전체를 `ErrorBoundary` 로 감싼다. 예외가 나면 흰 화면 대신 `화면을 표시하지
  못했습니다` · `앱을 다시 시작하면 대부분 해결됩니다.` 와 `다시 시작` 버튼 하나를 보인다. 다시 시작으로도 안
  풀리는 오류라면 앱 안에서 할 수 있는 일이 없다. 그래서 선택지를 하나만 두어 무엇을 누를지 분명하게 했다.
  다시 시작 방법은 `App.tsx` 가 넘긴다(`reloadAppAsync`). 기본값을 만들어 두면 같은 예외로 바로 돌아오는 버튼이
  될 수 있기 때문이다. 폴백이 뜨면 바로 스플래시를 내린다(`hideSplashScreen`). 부팅 중에 예외가 나면 네이티브 스플래시가
  폴백을 덮고 터치까지 막아서, `다시 시작` 버튼이 보이지도 눌리지도 않기 때문이다. 폴백을 위로 올리는 방법으로는
  터치가 막힌 것이 풀리지 않아서, 스플래시를 내리는 방법을 골랐다. 오류 보고 서비스는 없다.

### 결정 8. Open API 점검은 화면 맨 위의 배너 하나로 알린다

넥슨은 점검 중인 요청에 두 코드를 준다. 400 `OPENAPI00010` 은 메이플스토리 API 점검이고, 503 `OPENAPI00011` 은
넥슨 Open API 자체의 점검이다. 넥슨 문서는 `00010` 을 `게임 점검 중` 이라고 적지만, 앱 문구는 게임이 점검 중이라고
읽히지 않게 사용자가 정한 이름을 쓴다. 둘 다 키 문제도 네트워크 문제도 아니다. 그런데 `network` 로 접으면 사용자는
`네트워크 오류가 발생했습니다` 를 보고 연결을 확인하게 되고, 기다리면 풀린다는 것은 알 수 없다. 그래서 두 코드를
`gameMaintenance` · `apiMaintenance` 로 가르고, 무엇이 점검 중인지 각각 말한다. 둘을 한 종류로 묶지 않는 것은
사용자가 정했다.

- 판정은 `nexon/http.ts` 한 곳에서 한다. 400 · 503 응답 본문의 코드를 읽어 `NexonMaintenanceError` 를 던지고,
  `scope` 에 `game` 또는 `api` 를 담는다. 프렌즈 스트림의 `fail` 줄도 같은 판정을 거친다. 서버가 넥슨 본문의
  코드를 그대로 넘겨 주기 때문이다. 코드가 없는 503 은 지금처럼 `network` 다.
- **알리는 방법은 배너 하나다.** 실패가 난 자리마다 문구를 따로 두면 자리마다 모양이 달라 화면이 깨진다. 그래서
  점검은 결산 배너([[ADR-058]])와 같은 자리, 같은 모양의 띠(`NexonMaintenanceBanner`)로만 알린다. 첫 줄은
  `메이플스토리 API 점검 중입니다.` 또는 `넥슨 Open API 점검 중입니다.` 이고, 둘째 줄은
  `점검이 끝날 때까지 마지막으로 불러온 정보를 보여 줍니다.` 다. 아이콘은 렌치다. 다시 시도 버튼은 없다.
  기다리는 것 말고는 할 일이 없기 때문이다.
- 배너에서 `X` 가 아닌 곳을 누르면 `Open API 점검` FAQ 시트(`features/nexon-maintenance/faq.ts`)가 열린다. 결산 배너와
  같은 방식이다. 문답은 셋이다. 무엇을 불러올 수 없는지, 기록이 사라지는지, 어떻게 해야 하는지다. 불러올 수 없는
  것은 넥슨에서 받아 오는 정보 대부분이라고 넓게 적는다. 대부분의 기능이 마지막으로 불러온 기록을 기준으로 보여
  실제 게임 속 데이터와 다를 수 있다는 것과, 앱에 저장된 기록(가계부 · 보스 수익 기록 · 통계)은 그대로 쓸 수 있다는
  것도 함께 적는다. 점검 때 막히는 경로는 한 번 잰 것이라
  점검마다 다를 수 있기 때문이다. 좁게 적으면 적지 않은 것이 막혔을 때 사용자는 앱이 틀렸다고 읽는다. 넓게 적는 것은
  사용자가 정했다.
- 배너는 넥슨 데이터를 읽는 화면 모두에 선다. today · 컨텐츠 · 보스 · 보스 수익 · 가계부 · 설정 · 공지 목록 ·
  캐릭터 관리다. 지금은 실패를 알리지 않는 곳(today 의 위젯, 공지 목록)도 포함한다. 사냥 계산기의 메소 획득량은
  시트 안에서 실패하지만 배너는 가계부 화면 맨 위에 선다. 셋 다 사용자가 정했다.
- 점검 상태는 앱 전체에 하나다(`features/nexon-maintenance/store.ts`). `nexon/http.ts` 가 점검 응답과 성공 응답을
  알리고(`setMaintenanceReporter`), 스토어가 그것으로 배너를 세우고 내린다. `nexon/` 이 `features/` 를 직접 부르면
  계층이 거꾸로 서서, 부팅이 이 함수를 꽂는다.
- 배너를 내리는 기준은 점검마다 다르다. Open API 점검은 모든 경로가 막히므로 어느 요청이든 성공하면 내린다. 메이플스토리 API 점검은
  `character/list` 처럼 점검 중에도 200 인 경로가 있어서, 점검 응답을 받았던 경로가 다시 성공해야 내린다.
- `X` 를 누르면 이번 점검 동안 모든 화면에서 배너를 닫는다. 같은 점검을 화면마다 다시 닫게 하지 않기 위해서다.
  점검이 끝나 배너가 내려간 뒤 다음 점검이 오면 다시 선다.
- 배너가 서는 화면에서는 점검을 다른 방법으로 다시 알리지 않는다. 동기화 실패 토스트, 보스 수익의
  `일부 캐릭터를 불러오지 못했습니다 (N명)` 토스트, 캐릭터 관리의 스탈 배너가 점검일 때 뜨지 않는다. 캐릭터 관리에
  목록이 하나도 없을 때의 `ErrorState` 는 `캐릭터 목록을 불러오지 못했습니다` / `점검이 끝난 뒤 다시 불러와주세요` 를
  버튼 없이 보인다. 그 자리를 비워 둘 수 없기 때문이다.
- 로그인 · 키 입력 · 캐릭터 설정(온보딩)에는 배너를 세울 자리가 없다. 그래서 그곳만 토스트와 문구로 무엇이 점검
  중인지 말한다. 로그인 · 키 입력의 토스트는 `메이플스토리 API 점검 중입니다` · `넥슨 Open API 점검 중입니다` 다. 캐릭터
  설정은 캐릭터 관리와 같은 본문(`CharacterManageBody`)을 쓰지만 `place` 가 다르다. `ErrorState` 의 제목이
  `메이플스토리 API 점검 중입니다` · `넥슨 Open API 점검 중입니다` 이고, 목록이 남았을 때는 스탈 배너가
  `메이플스토리 API 점검 중이라 목록을 갱신하지 못했습니다` · `넥슨 Open API 점검 중이라 목록을 갱신하지 못했습니다` 로 선다.
  둘 다 버튼이 없다.
- 동기화 회차에서 첫 캐릭터가 점검이면 나머지 캐릭터는 부르지 않고 캐시로 채운다. 점검은 캐릭터 하나가 아니라
  넥슨 전체가 막힌 것이라 나머지도 같은 실패를 받기 때문이다([[ADR-021]] 결정 5).
