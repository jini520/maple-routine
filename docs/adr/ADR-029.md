### ADR-029: Android 전용 경량 `SplashActivity` 도입 — Capacitor를 거치지 않는 비트맵 스플래시로 다크모드 진짜 브랜드색 확보 (구현 완료)

**배경**: [[ADR-028]]에서 두 차례(OS 기본 타이밍 방치, JS→네이티브 신호) 시도한 "브랜드를 WebView/HTML 레이어로 옮긴다"는 접근이 전부 실패했다 — 원인은 WebView 자체가 그려지는 시점이 이미 콜드스타트 후반부(Capacitor 브릿지+8개 플러그인 초기화 이후)라, WebView에 무엇을 그려두든 사용자가 보기 전에 이미 실제 콘텐츠로 넘어가 버린다는 것. 사용자가 "타이밍이 아니라 색 자체가 문제"라고 재확인(2026-07-16) — `#D06100`(force-dark 통과 상한)이 아니라 실제 브랜드 오렌지 `#FB8101` 그 자체를 다크모드에서도 보고 싶다는 것. 무채색 다크 리디자인 대안(2가지 후보, 실기기 스크린샷 확인)도 제시했으나 기각.

**핵심 통찰**: MIUI/HyperOS force-dark는 **네이티브 테마의 solid color 속성만** 건드리고 **비트맵 드로어블은 안 건드린다**([[project_miui_forcedark_splash]] — 아이콘 PNG가 안 깎이는 것과 동일 원리, 이 세션에서 [[ADR-025]] 내내 재확인됨). [[ADR-028]]은 이 비트맵 면역성을 WebView(느림, force-dark 무관)로 살리려다 실패했지만, **Capacitor를 거치지 않는 별도의 초경량 네이티브 액티비티**로 살리면 WebView의 초기화 지연 없이 비트맵을 거의 즉시 그릴 수 있다는 가설을 세웠다.

**결정**:

1. **`SplashActivity`(신규, 플레인 `Activity`, `BridgeActivity` 아님)를 앱의 진짜 런처로 둔다.** `AndroidManifest.xml`의 `LAUNCHER` intent-filter를 `MainActivity`에서 `SplashActivity`로 옮긴다(`MainActivity`는 `exported="false"`로 전환, `SplashActivity`가 명시적 `Intent`로만 띄움).
2. **`SplashActivity`의 테마**(`AppTheme.SplashActivityLaunch` → `Theme.SplashScreen`, `postSplashScreenTheme`은 `AppTheme.SplashActivityContent`)는 OS가 강제하는 극히 짧은 첫 프레임만 무채색 기본값(브릿지 없음 + 아이콘 없음, [[ADR-028]] 결정 1과 동일한 안전 패턴, `@color/splash_background`)으로 두고, `SplashActivity.onCreate()`가 `activity_splash.xml`(전체화면 `ImageView`, `android:scaleType="centerCrop"`, `src=@drawable/splash`)를 `setContentView`한다. **주의**: 처음엔 `android:windowBackground`에 비트맵을 직접 지정했는데, `windowBackground`는 드로어블을 화면 실제 비율과 무관하게 늘려 채워서(`Gravity.FILL`) 실기기(1080×2400)에서 정사각형 원본이 가로로 눌려 보이는 버그가 있었다(2026-07-16, 사용자 리포트). `ImageView`+`centerCrop`으로 교체해 비율을 유지하도록 수정.
3. **`SplashActivity.onCreate()`는 Capacitor를 전혀 초기화하지 않는다** — `installSplashScreen()` 호출과 `Handler.postDelayed(1200ms)`로 `MainActivity`를 시작(`overridePendingTransition(0,0)`으로 전환 애니메이션 없이)하고 자신은 `finish()`하는 게 전부다. `MainActivity`는 [[ADR-025]] 구현 그대로(브릿지+8개 플러그인+`#D06100` 폴백 스플래시) 유지 — `SplashActivity`가 브랜드 노출을 이미 마쳤으므로 `MainActivity`의 WebView 로딩 잔여 구간(있다면)은 `#D06100`이 안전망으로 커버한다.

**실기기 검증 (2026-07-16, Xiaomi HyperOS, 다크모드, 화면 녹화 2회 재현)**: `adb shell screenrecord`로 콜드스타트를 녹화해 픽셀 샘플링한 결과, **`(252,128,2)` ≈ `#FC8002`가 약 0.9초간 안정적으로 노출됨을 확인** — 원본 브랜드 `#FB8101`(251,129,1)과 채널당 오차 1(영상 압축 수준)로 사실상 동일하다. 두 번째 녹화에서도 재현(오렌지 첫 노출 시점 ~3.16초). 실제 프레임 이미지로 아이콘+워드마크가 온전히, 이중 로고 없이 깔끔하게 전환되는 것도 확인. **다크모드에서 진짜 브랜드 오렌지가 뜬 것은 이 프로젝트 전체 스플래시 작업(ADR-025~029) 중 최초.**

**트레이드오프**:
- 액티비티가 하나 늘어(SplashActivity/MainActivity 2단 구성) 코드 복잡도가 소폭 증가한다. `SplashActivity`가 `Capacitor`/`WebView`를 전혀 안 건드리므로 [[ADR-003]]/[[ADR-005]] 아키텍처 규칙과 무관.
- `SHOW_MS`(1200ms) 이후에도 `MainActivity`의 WebView가 준비 안 됐으면 `#D06100`(다크) 스플래시가 그 잔여 구간을 메운다 — 완전히 사라지진 않지만 노출 순서상 진짜 브랜드색이 먼저 뜨고 짧게만 보조하는 역할이라 체감이 크게 다르다.
- Android에만 적용(iOS는 [[ADR-025]] 런치 스토리보드가 애초에 force-dark 문제가 없어 그대로 유지).
- `overridePendingTransition`은 최신 API에서 deprecated(`overrideActivityTransition`로 대체 예정) — 컴파일 경고만 있고 동작에는 문제없어 이번엔 그대로 둠.
- 라이트모드는 영향 없음(원래도 `#FB8101` 정상 노출) — 이 변경은 다크모드 전용 문제 해결이 목적.

**이미지 교체 + 가로 눌림 수정 (2026-07-16)**: 사용자가 스플래시 이미지를 새 디자인(캘린더+체크 아이콘 제거, 잎사귀 글리프+워드마크 한 줄 로고타입으로 단순화, 이후 로고 크기를 더 키운 2차 교체도 동일 절차로 반영)으로 iOS·Android 모두 전면 교체 요청. `resources/splash.png`(2732×2732 마스터)를 새 이미지로 교체하고 `npx @capacitor/assets generate`로 Android 밀도별 드로어블 + iOS `Splash.imageset`(@1x/2x/3x) 재생성(아이콘 소스는 안 건드려 `ic_launcher`/`AppIcon`은 무변화 — 앱 런처 아이콘은 이번 교체 범위 밖). 부수적으로 생성된 PWA 매니페스트/아이콘(`public/manifest.webmanifest`, `public/assets/icons/`)은 이 프로젝트가 안 쓰는 산출물이라 삭제. iOS `LaunchScreen.storyboard`는 원래부터 `contentMode="scaleAspectFill"`이라 눌림 문제 자체가 없었음(이미지 교체만으로 충분).

**정정(2026-07-17) — 스플래시 단색을 이미지 배경색 `#F58B0F`로 통일**: 위 이미지 교체 때 새 디자인의 배경색이 구 브랜드 스플래시 주황 `#FB8101`이 아니라 **UI primary `#F58B0F`**(머쉬맘 `--color-primary`와 동일)로 바뀌었는데, 코드의 단색 채움들(웹뷰 배경 `capacitor.config backgroundColor`, `splash_colors.xml` 라이트, iOS 스토리보드 배경, [[ADR-027]] 정정의 플러그인 `backgroundColor`·`#boot-cover`·리로드 오버레이)은 전부 `#FB8101`로 남아 있었다. 이미지가 전면을 덮는 콜드 스타트에선 안 보였지만, 리로드 커버([[ADR-027]] 정정)로 이미지와 단색이 한 화면에 나란히 놓이자 미묘한 색 차이가 이음새로 드러났다(사용자 리포트). 사용자 확인을 거쳐 **이미지(최신 디자인)를 기준으로 단색 6곳을 전부 `#F58B0F`로 통일**. 다크 모드 스플래시 테마 값 `#D06100`(values-night)은 force-dark 통과 상한이라 그대로 둔다. 이 문서 앞부분의 "`#FB8101` = 진짜 브랜드" 서술들은 교체 전 이미지 기준의 기록이다 — 현재 기준색은 `#F58B0F`.

**Android 가로 눌림 수정**: `android:windowBackground=@drawable/splash`(결정 2)가 원인이었다 — `windowBackground`는 `Gravity.FILL`로 화면 실제 비율과 무관하게 드로어블을 늘려 채워서, 정사각형(2732×2732) 원본이 실기기(1080×2400, 훨씬 좁고 긴 비율)에서 가로로 눌려 보였다. `activity_splash.xml`(전체화면 `ImageView`, `android:scaleType="centerCrop"`)로 교체해 비율을 유지한 채 채우도록 수정 — `windowBackground`는 `ImageView`가 인플레이트되기 전 찰나에만 보이는 폴백이라 단색(`@color/splash_background`)으로 낮췄다.

**상태바·제스처 바 색 불일치 수정**: `SplashActivity`는 시스템 바 처리를 전혀 안 해서 상단 상태바·하단 제스처 영역이 기본 검정으로 남아 스플래시 주황과 안 맞았다(사용자 리포트). `MainActivity`의 `SystemBarsPlugin`(edge-to-edge + 투명 바)과 동일한 원리를 브릿지 없는 이 액티비티에 맞게 `SplashActivity.applyEdgeToEdge()`로 재현: `WindowCompat.setDecorFitsSystemWindows(false)` + 상태바/내비게이션 바 `Color.TRANSPARENT` + `setStatusBarContrastEnforced(false)`로 전체화면 `ImageView`가 바 영역까지 그대로 비치게 했다. 아이콘 색(`setAppearanceLightStatusBars`)은 의미상 밝은(흰색) 아이콘으로 설정했으나, **MIUI/HyperOS가 배경 밝기를 자체 판단해 이 설정을 무시하고 항상 어두운 아이콘으로 렌더링함을 확인**(true/false 설정 결과가 실기기에서 동일 — 이 세션 내내 본 force-dark류 OS 레벨 오버라이드와 같은 종류). 배경색 일치가 원래 요청의 핵심이라 아이콘 색은 더 파고들지 않음 — 다른 OEM/AOSP 기본값을 위해 의미상 올바른 값(`false`)은 코드에 남겨둠.
