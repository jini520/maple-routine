# ADR-095 — NEXON Open API Analytics 스크립트 삽입

**날짜**: 2026-08-05
**상태**: **구현 완료** (2026-08-05) — `index.html` 삽입·`dist/index.html` 에 태그 원문 그대로 실려 나가는 것 확인, 테스트 2,314개 통과·lint 신규 경고 없음. **연동 성립은 아직 미확인** — 넥슨 애플리케이션 상세 하단이 "연동 완료"로 바뀌는지 최대 24시간 뒤(2026-08-06) 확인할 것. 개인정보 처리방침 반영(결정 4)도 미착수
**관련**: [[ADR-007]](개인 API 키 인증 — 같은 넥슨 개발자 애플리케이션에서 나온 식별자) · [[ADR-003]](서버 없음 · 로컬 저장) · [[ADR-001]](Capacitor 하이브리드 — 웹뷰 origin 문제) · [[ADR-090]](광고 — 개인정보 처리방침의 존재 이유) · [[ADR-022]](OTA — `index.html` 도 번들에 실린다)

## 맥락

넥슨이 개발자에게 제공하는 **Open API Analytics**(`openapi.nexon.com/ko/guide/analytics-api/`)는
`<head>` 에 스크립트 한 줄을 넣으면 "마이 페이지 > Analytics 대시보드" 에서 사용 지표를 볼 수 있게
해 주는 웹 애널리틱스다. 지금 이 앱에는 **어떤 애널리틱스도 없다** — 사용자가 몇 명인지, 어느 화면을
쓰는지 아는 수단이 하나도 없다.

이 앱이 쓰던 넥슨 것은 데이터 조회용 REST API(`open.api.nexon.com`, [[ADR-007]])뿐이고 Analytics는
성격이 다르다. 호출 도메인도 다르다 — Analytics 스크립트는 **문서 사이트 쪽인 `openapi.nexon.com`**
에서 받는다.

## 결정 1 — 스크립트를 `index.html` `<head>` 에 그대로 넣는다

애플리케이션 상세 하단이 주는 구문 그대로다. `async` 속성 포함:

```html
<script type="text/javascript" src="https://openapi.nexon.com/js/analytics.js?app_id=322698" async></script>
```

**경로가 `/js/analytics.js` 다.** 가이드 본문 예시는 `/analytics.js`(`/js/` 없음)로 적혀 있는데 실제로
발급되는 구문은 이쪽이다 — 가이드를 보고 손으로 옮겨 적으면 틀린다. 반드시 애플리케이션 상세 하단의
구문을 그대로 쓸 것.

`app_id` 는 넥슨 마이 페이지 > 애플리케이션 목록 > 애플리케이션 상세 하단에서 확인한다. **비밀값이
아니다** — 클라이언트에 그대로 실려 나가는 공개 식별자이므로 `index.html` 에 하드코딩하고 환경변수로
빼지 않는다(API 키와 혼동하지 말 것 — 그쪽은 사용자 개인 키이고 기기 보안 영역에만 있다, [[ADR-007]]).

`async` 를 뗄 이유가 없다. 애널리틱스는 첫 페인트를 막을 이유가 전혀 없는 종류의 스크립트고,
이 앱은 부팅 커버(`#boot-cover`)로 첫 페인트 구간을 이미 덮고 있다([[ADR-027]] 정정).

## 결정 2 — 웹뷰에서 연동이 성립하는지는 **확인 대상이지 전제가 아니다**

가이드는 "웹 서비스"를 대상으로 쓰였는데 이 앱은 Capacitor 하이브리드다([[ADR-001]]). 웹뷰 origin이
`https://localhost`(Android) · `capacitor://localhost`(iOS)라, 넥슨이 등록된 서비스 URL·도메인 기준으로
연동을 판정한다면 **매칭이 안 될 수 있다.** 이건 추정이고, 문서에는 origin에 대한 언급이 없다.

확인 방법은 문서가 지정한 그대로다 — 삽입 후 **최대 24시간** 뒤 애플리케이션 상세 하단이
"연동 완료"로 바뀌는지 본다. 안 되면 그때 원인을 좁힌다(브라우저에서 `npm run dev` 로 열었을 때는
되는지 갈라보면 origin 문제인지 아닌지가 나온다).

**추정으로 미리 대응하지 않는다** — origin 우회나 프록시 같은 것을 지금 만들지 않는다.

## 결정 3 — 실패해도 앱은 아무 영향을 받지 않아야 한다

오프라인이거나 넥슨 쪽이 응답하지 않으면 `async` 스크립트는 조용히 실패하고 끝난다. 이 앱의 어떤
코드도 `analytics.js` 가 정의하는 전역을 참조하지 않는다 — 참조하기 시작하면 그 순간 넥슨 도메인
가용성이 앱 동작의 의존성이 된다([[ADR-003]] 의 "기기에서 완결" 성질을 깎는다). **스크립트 한 줄이
전부이고 앱 코드는 이 기능을 모른다.**

## 결정 4 — 개인정보 처리방침에 수집 주체로 넥슨 Analytics를 반영한다

[[ADR-090]] 에서 광고 때문에 개인정보 처리방침을 만들어 게시했다(mapleroutine.store). 제3자 애널리틱스가
하나 늘었으므로 그 문서에도 반영해야 한다. 스토어 데이터 안전성(Play Data safety · Apple 개인정보 라벨)
신고 항목도 같은 이유로 함께 본다. **이건 앱 코드 밖의 후속 작업이고 이 ADR의 범위는 스크립트 삽입까지다.**

## 고정 방법

`src/__tests__/index-html-analytics.test.ts` — `index.html` 을 읽어 스크립트 태그가 **정확한 URL·`async`
속성**으로 살아 있는지 본다. 이 한 줄은 앱 코드가 참조하지 않아 **지워져도 아무것도 깨지지 않고**,
그래서 조용히 사라질 수 있다. 같은 이유로 [[ADR-093]] 이 자산 슬러그 전수 해석 테스트를 세웠다.

## 검토했으나 기각

- ~~`app_id` 를 `.env`(`VITE_*`)로 빼기~~ → 비밀값이 아니고(번들에 그대로 실린다) 이 저장소에는
  `.env` 체계 자체가 없다. 값 하나 때문에 도입하지 않는다.
- ~~웹(`npm run dev`)에서만 로드되게 분기~~ → 알고 싶은 것이 **앱 사용 지표**다. 분기하면 목적이 사라진다.
- ~~넥슨 약관 문제 검토~~ → **해당 없음.** 넥슨이 자사 개발자에게 제공하는 도구를 그 안내대로 쓰는 것이라
  [[ADR-090]] 이 다룬 수익화 조항(제6조⑥·게임IP 가이드)과는 층이 다르다.
