# ADR-307+325 PC 웹 버전

> ⚪ 미구현
> 관련 소스: 아직 없다. `apps/web/`(Next.js)와 `packages/core/` 에 생긴다([[ADR-005]] 결정 8)

## 배경

> 사용자 지정(2026-11-24): 앱의 모든 기능을 웹에서 사용하고 앱과 동기화시켜야 한다. 프레임워크를 둘로 관리할지, UI 컴포넌트와
> 레포지토리는 어떻게 관리할지 정한다.

루트 도메인 `mapleroutine.store` 는 기기 간 동기화(#947) 뒤에 낼 PC 버전이 쓴다([[ADR-016]] 결정 14). 로그인하지 않은 사람에게 무엇을
열지는 앱과 웹이 같고, [[ADR-026]] 결정 10 에 있다.

2026-11-24 의 앱 코드(테스트 제외)는 이렇다.

| 묶음 | 양 | 플랫폼 라이브러리 |
|---|---|---|
| 화면 `src/app` · 공용 UI `src/components` | 3.7만 줄 · 1.7만 줄 | RN 컴포넌트로 그린다 |
| 로직 `features` · `lib` · `storage` · `nexon` · `server` | 파일 244 · 114 · 109 · 21 · 16 | 저장소와 네이티브 기능은 포트로만 부른다([[ADR-004]] 결정 1). RN · Expo 를 직접 가져오는 파일은 `features` 5개(`AppState` · 로그인 창) · `lib` 8개(화면 치수 계산) · `storage` 3개(어댑터)다 |

웹에서 할 수 없는 것도 있다. 배경 실행(`native/background-task.ts`, 새벽의 미완료 스케줄 알림)은 브라우저에서 돌 수 없다. 파티 약속 알림과
공지 푸시는 웹 푸시로 옮길 수 있지만, 아이폰은 사이트를 홈 화면에 추가한 경우에만 받는다.

## 결정

### 결정 1. 웹은 Next.js 로 따로 만들고, 로직은 앱과 함께 쓴다 (사용자 선택 2026-11-24)

- 화면은 `apps/web` 에 React DOM 으로 새로 쓴다. 로직은 `packages/core` 를 앱과 함께 쓴다. 저장소를 어떻게 나누는지는 [[ADR-005]]
  결정 8 에 있다.
- Expo 웹(react-native-web)으로 앱 화면을 그대로 웹에 내는 방법도 검토했다. 화면 코드를 한 벌로 둘 수 있는 대신, 모바일 화면을 PC 에
  늘려 쓰게 되고 첫 로딩이 크다. 화면을 JS 로만 그려 검색 노출도 약하다. Skia 를 쓰는 그래프 둘(`MarketChart` · `SparkLine`)은 웹에서
  CanvasKit(압축 2.9MB)을 따로 받아야 한다. 사용자는 PC 에 맞는 화면을 따로 만드는 쪽을 골랐다.
- 그래서 기능을 더할 때마다 화면을 앱과 웹에 한 번씩 만든다. 디자인 시스템은 글자 역할표만 `packages/tokens` 로 함께 쓰고,
  컴포넌트와 색은 플랫폼마다 따로 둔다. 컴포넌트는 그리는 방식(RN 과 DOM)이 달라 함께 쓸 수 없다. 색은 웹이 앱의 직업 테마를 쓰지 않고
  라이트 · 다크만 두기 때문이다([[ADR-086]] 결정 6).

### 결정 2. 웹은 정적 파일로 내보내 루트 도메인에서 nginx 가 내고, 루트에 남겨 둔 주소를 쓰지 않는다 (사용자 선택 2026-11-24)

- Next.js 의 정적 내보내기(`output: 'export'`)로 HTML 과 JS 파일을 만들고, 앱 박스 nginx 가 `mapleroutine.store` 에서 낸다([[ADR-016]]
  결정 14). 안내 사이트를 내는 방식과 같다.
- Node 서버(`next start`)는 띄우지 않는다. 로그인 뒤 화면의 기록은 브라우저에 있어서(결정 3) 서버가 그릴 데이터가 없다. 서버 렌더링이
  하는 일은 공개 페이지를 다시 빌드하지 않고 최신으로 굽는 것뿐인데, 그에 비해 메모리를 많이 쓴다.
  - 2026-11-24 에 앱 박스에서 쓸 수 있는 메모리는 463MB 였고, Docker 를 걷으면 약 70MB 가 더 빈다(#1206).
  - 같은 날 맥(Node 26)에서 페이지 셋인 최소 Next 서버(16.4.6, standalone)를 쟀다. 띄운 직후 108MB, 요청 400번 뒤 170MB, 동시 요청
    500번 뒤 230MB 였다.
  - 서버 프로세스가 하나 늘면 웹을 배포할 때마다 다시 띄워야 하고, 그 프로세스가 죽으면 웹 전체가 멈춘다.
- 검색 노출이 필요한 공개 페이지(계산기 · MASPI 지수)는 빌드할 때 HTML 로 굽는다. 화면을 JS 로만 그리면 검색엔진이 내용을 읽지 못할 수
  있기 때문이다.
- 날마다 바뀌는 값(MASPI 지수 · 공지)은 페이지가 열릴 때 서버에서 받는다. HTML 에 구운 게임 수치(보스 결정석 가격)는 게임 데이터가
  바뀌면 웹을 다시 빌드해 올려야 최신이 된다. 공지 상세는 검색에 노출하지 않는다.
- 웹 주소는 루트에 남겨 둔 `/v1` · `/assets` · `/ota/files` 와 안내 사이트 주소(`/privacy` · `/support` · `/api-key` ·
  `/app-ads.txt`)를 쓰지 않는다. 이미 나간 바이너리와 스토어 등록정보가 이 주소를 부르기 때문이다([[ADR-016]] 결정 14 · [[ADR-015]]
  결정 11).

### 결정 3. 웹의 기록은 브라우저 안 SQLite 에 두고, 앱과 같은 올리기 · 받기로 맞춘다 (Claude 가 정함 2026-11-24)

- 앱과 같은 표와 트리거를 브라우저 안 SQLite 에 둔다. `packages/core` 의 저장소 코드(`storage/`)와 동기화 코드
  (`features/server-sync/`)를 그대로 쓰고, 웹은 저장소 포트(`storage/ports.ts`)의 어댑터만 따로 둔다.
- 서버를 기록의 원본으로 두고 웹이 화면마다 서버에서 읽는 방법은 고르지 않았다. 지금 서버의 받기 경로는 바뀐 줄만 내준다([[ADR-099]]
  결정 9). 그래서 화면마다 읽기 경로를 새로 만들어야 하고, 앱과 다른 코드가 생기며, 오프라인에서 쓸 수 없다.
- 브라우저 하나를 기기 하나로 센다. [[ADR-099]] 결정 14 (기기에는 지금 로그인한 사람의 기록만 둔다)도 브라우저마다 그대로 따른다.
- 브라우저 SQLite 라이브러리는 시험 빌드에서 첫 로딩 크기와 함께 재고 고른다.

### 결정 4. API 키 사용자는 브라우저에서 넥슨을 직접 부르고, 우리 키가 필요한 조회는 서버가 대신 부른다 (Claude 가 정함 2026-11-24)

- 넥슨 Open API 는 어떤 Origin 이든 허락한다. 2026-11-24 에 `OPTIONS /maplestory/v1/id` 에 아무 Origin 을 보내자
  `access-control-allow-origin` 에 그 Origin 을 그대로 돌려주고 `x-nxopen-api-key` 헤더를 허락했다. 그래서 API 키 사용자는 앱처럼
  자기 키로 넥슨을 직접 부르고, 우리 서버 부하는 늘지 않는다.
- 앱은 넥슨 로그인 사용자의 프렌즈 밖 경로(`character/basic` · 메소 · 공지)를 번들에 든 개발자 키로 부른다([[ADR-025]] 결정 2).
  웹은 이 키를 쓰지 않고 서버가 대신 부른다. 넥슨 가이드가 `API Key는 서버에만 두고, 프론트엔드나 저장소에 넣지 않습니다` 라고 하고,
  웹 번들은 누구나 개발자 도구로 열어 볼 수 있기 때문이다.
- 프렌즈 경로는 앱처럼 서버의 프렌즈 스트림으로 부른다.
- ocid 는 웹 주소에 싣지 않는다. 넥슨 가이드가 식별자를 프론트엔드로 내려 URL 에 싣지 말라고 한다.

### 결정 5. 우리 서버는 웹 주소에서 오는 요청을 받는다 (Claude 가 정함 2026-11-24)

- 웹은 `mapleroutine.store` 에서 `api.mapleroutine.store` 를 부르므로, 서버가 그 Origin 을 CORS 로 허락한다. 지금 서버 응답에는
  CORS 헤더가 없다(2026-11-24 `/v1/market/maspi` 로 확인).
- 넥슨 로그인은 지금 서버 콜백이 앱 스킴(`com.mapleroutine.app://oauth/callback`)으로 돌려보낸다([[ADR-025]] 결정 3). 웹에서
  시작한 로그인은 웹 주소로 돌려보낸다.

## 테스트

구현할 때 적는다. 지킬 것은 이렇다.

- 결정 2: 웹 주소가 `/v1` · `/assets` · `/ota/files` 와 안내 사이트 주소에 겹치지 않는지 본다.
- 결정 3: 웹 어댑터로 연 SQLite 에서 기록을 쓰면 앱과 같은 트리거가 대기 표에 줄을 넣는지 본다.
- 결정 4: 웹 빌드 결과에 개발자 키 값이 들어가지 않는지 본다.

## 열린 질문

- 넥슨 로그인: 지금 넥슨 애플리케이션(iOS · 안드로이드, `client_id` 가 다르다. [[ADR-017]] 결정 1)에 웹을 붙일 수 있는지, 웹
  애플리케이션을 새로 등록하고 프렌즈 승인과 콜백 검수를 다시 받아야 하는지. 사용자가 넥슨 개발자센터에서 확인한다. 새로 받아야 하면
  웹 첫 출시는 API 키 로그인과 비로그인만으로 낼 수 있다.
- PC 화면 구성의 세부. 방향은 W1(위 탭 · 라벨 왼쪽 폼 · 오른쪽 영수증 판)으로 골랐고, 테두리 없이 앱 부품 모양으로 다시 그린 시안으로 정한다([[ADR-086]] 결정 6).
- 첫 출시 범위. 모든 기능을 한 번에 낼지, 차례로 낼지.
- 웹 푸시를 첫 출시에 넣을지.

  내보내기를 골랐다(#1206)
- ADR-325 (2026-11-24): 결정 1 의 함께 쓰는 디자인 시스템에서 테마 색을 뺐다. 웹은 라이트 · 다크만 둔다([[ADR-086]] 결정 6, #1215)
