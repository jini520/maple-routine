### ADR-060: 빈 상태(empty) 디자인 통일 — 공용 `EmptyState` 컴포넌트, 컨텍스트 아이콘 배지, "조회 불가"는 별도 톤 (구현 완료, 이슈 #55)

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**배경**: 앱에서 "비어있음"을 표시하는 곳이 12곳인데 톤이 세 갈래로 갈려 있었다(2026-07-29 전수 조사).

1. **캐릭터 미선택(페이지 전체) 3곳** — `ContentScreen`·`BossScreen`·`BossProfitScreen`. 2026-07-22에 "84px 원형 배지(단풍잎) + 중앙 정렬 + CTA" 패턴으로 이미 개선됐으나 같은 블록이 3개 파일에 복제돼 있었다.
2. **목록 비어있음(인라인) 8곳** — 컨텐츠 일간·주간, 보스 주간·월간(각각 추적 0건 / 필터 결과 없음), 보스 수익 기간, 드롭 시트. 전부 `rounded-[14px] border-dashed border-border p-4 text-sm text-text-muted` 점선 박스 **한 줄**이고 아이콘도 CTA도 없었다. 문구는 `"컨텐츠 관리"에서 추가해주세요`처럼 **행동을 지시하면서 그리로 가는 버튼이 없었다** — 1의 개선이 CTA로 해결한 바로 그 문제가 여기 남아 있었다.
3. **그 외** — 보스 수익 캐릭터 카드 안 "조회 불가"(박스 없는 `<p>` 한 줄), 캐릭터 관리 피커·온보딩의 "표시할 캐릭터가 없어요".

**결정**:

1. **공용 컴포넌트 `components/EmptyState/`** 를 만들고 12곳 중 11곳을 여기로 흡수한다. `size` 는 `'page'`(캐릭터 미선택 3곳) / `'inline'`(목록 비어있음 8곳) 두 변형이고, 배지 크기·타이포·CTA 크기만 다르다(84px/56px, `text-base`/`text-sm`, `py-2.5`/`py-2`). 복제 자체는 관례상 허용돼 있으나([[ADR-018]]) 대상이 11곳이라 복제하면 이후 톤이 또 갈린다는 판단.
2. **배지 안 마크는 자리에 따라 나눈다** — **목록 빈 상태(inline)는 화면별 컨텍스트 아이콘**(lucide: `ListChecks`·`Swords`·`SlidersHorizontal`·`Coins`·`PackageOpen`), **캐릭터 미선택(page)은 브랜드 마크(단풍잎)** 를 유지한다. 시안 4종을 `/debug/empty-states` 비교 페이지에서 검토한 뒤 "세로 배지 · 컨텍스트 아이콘"을 채택했고(사용자 판단), 페이지 빈 상태도 같은 컴포넌트로 흡수하되 마크는 단풍잎으로 되돌렸다(사용자 판단 — 화면 전체를 차지하는 자리는 앱의 얼굴 역할을 겸한다). 컴포넌트는 `icon: LucideIcon | 'leaf'` 한 prop으로 둘을 표현한다.
3. **CTA는 문구가 지시하는 곳으로 실제 이동시킨다** — 수동 모드 컨텐츠 → `/content/manage`, 수동 모드 보스 → `/boss/manage`, 필터 결과 없음 → 필터를 `all`로 초기화. **자동 모드("게임에서 등록해주세요")는 앱 안에 갈 곳이 없으므로 CTA 없이 문구만** 둔다. 보스 수익 "아직 처치한 보스가 없습니다"도 CTA를 달지 않는다(사용자 판단 — 수익은 게임 플레이 결과라 앱 안에 "지금 할 일"이 없고, 억지 목적지는 문구가 지시하는 행동과 어긋난다).
4. **문구는 화면·탭·모드별로 나눈다**. 기존에는 일간/주간, 주간/월간이 같은 문구(`추적할 항목이 없습니다`)를 공유했다. 규칙: 제목은 무엇이 비었는지(`추적할 일간 컨텐츠가 없습니다` / `등록된 주간 보스가 없습니다`), 설명은 다음 행동 한 줄, CTA 라벨은 목적지 이름 그대로(`컨텐츠 관리`·`보스 관리`).
5. **"조회 불가"는 빈 상태가 아니라 별도 컴포넌트 `UnavailableNotice`** 로 분리한다([[ADR-032]] — 롤링 조회 윈도우 밖이라 **확인 자체를 못 한** 상태). 빈 상태와 같은 디자인을 쓰면 "데이터가 없다"로 오해된다. 톤은 **경고(error)가 아니라 정보(`bg-info-tint` + `Info` 아이콘)** 로 한다(사용자 판단). 문구는 "이 기간은 조회할 수 없어요 / 조회 가능한 기간(최근 13일)을 지나 확인할 수 없습니다 — 처치 기록이 없다는 뜻은 아닙니다". 보스 수익 기간 목록과 캐릭터 카드 안(`compact`) 두 곳이 같은 컴포넌트를 쓴다.
6. **캐릭터 관리 피커·온보딩 캐릭터 선택은 건드리지 않는다** — [[ADR-053]]이 로딩/빈/실패 3분기와 문구를 이미 확정했고 `design-system.md`·`onboarding.md`에 명시돼 있다(사용자 판단, 범위 밖).

**이유**:
- 목록 빈 상태에 컨텍스트 아이콘을 고른 이유: 단풍잎은 어디서나 같은 그림이라 "무엇이 비었는지"를 전달하지 못한다. 목록 자리에서는 브랜드 일관성을 배지 색(`bg-primary/15`)·모양이 이미 담당하므로 마크는 의미를 담는 쪽이 낫다. 반대로 화면 전체를 차지하는 캐릭터 미선택 자리는 정보 전달보다 앱의 인상이 앞서 브랜드 마크를 남겼다.
- "조회 불가"를 경고가 아니라 정보 톤으로 둔 이유: 사용자가 고칠 수 있는 실패가 아니라 API의 알려진 제약이다. 빈 상태와 구분만 되면 충분하고, error 색은 과하게 놀라게 한다.
- 자동 모드에 CTA를 만들지 않은 이유: 목적지가 앱 밖(게임 클라이언트)이라 어떤 버튼을 달아도 문구가 약속한 행동을 수행하지 못한다.

**트레이드오프**:
- 배지 아이콘 색은 `text-primary`(교체 대상이던 단풍잎의 `fill-primary` 와 동일 토큰)로 뒀다. 라이트 테마만 보면 `text-primary-text` 가 더 또렷하지만 **레테 테마는 `primary-text` 가 `primary` 보다 어두워** 다크 배지 배경에 아이콘이 묻힌다(4테마 실물 확인). 네 테마를 모두 통과하는 쪽을 택했고, 그 대가로 라이트 테마에서 아이콘 대비가 다소 낮다. 레테의 `primary-text` 토큰 값 자체가 다른 테마와 방향이 반대라는 점은 이 이슈 범위 밖의 별건이다.
- `design-system.md`의 "아이콘을 둥근 배경 박스로 감싸지 않는다"(2026-07-11 확정) 규칙과 충돌한다. 빈 상태 배지는 **아이콘이 아니라 일러스트 자리**로 취급한다는 예외를 문서에 명시했다(이미 2026-07-22 페이지 빈 상태와 드롭 시트 카테고리 헤더가 사실상 예외로 동작하고 있었다).
- 페이지 빈 상태 3곳은 이슈 #55가 "대상 아님"으로 적었던 곳인데 공용 컴포넌트로 흡수했다 — 마크는 단풍잎 그대로라 **시각 변화는 없고** 2026-07-22 결정이 그대로 유효하다. 대신 한 컴포넌트 안에 마크가 두 종류(브랜드/컨텍스트) 공존해, 새 빈 상태를 추가할 때 어느 쪽인지 고르는 판단이 매번 필요하다(기준은 page=브랜드, inline=컨텍스트).
- 문구를 탭·모드별로 나눠 문자열 수가 6개에서 12개로 늘었다. 문구가 갈리는 만큼 이후 수정 시 누락 위험이 있어 규칙(결정 4)을 `design-system.md`에 남겼다.
