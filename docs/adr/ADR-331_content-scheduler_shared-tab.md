# ADR-331 컨텐츠 스케줄러의 공유 탭과 `일일` 이름

> 🟢 유효
> 관련 소스: `app/content-scheduler/ContentScreen.tsx` · `app/content-scheduler/ContentManageScreen.tsx` · `features/content-scheduler/store.ts` · `features/content-scheduler/displayed-contents.ts` · `features/content-scheduler/shared-contents.ts` · `features/content-scheduler/manage-draft.ts` · `features/remaining-schedule/remaining-schedule.ts` · `lib/scheduler/scheduler-content-scope.ts` · `app/today/view-model.ts` · `app/today/widgets/RemainingScheduleWidget.tsx` · `features/schedule-alert/notification-text.ts` · `components/organisms/CharacterPortrait/PortraitRing.tsx`

## 배경

컨텐츠 스케줄러는 캐릭터마다 일간 · 주간 컨텐츠를 보여 준다. 몬스터파크 · 에픽 던전 · 메이플 유니온처럼 진행을 월드나 메이플
ID 가 함께 쓰는 컨텐츠도 캐릭터마다 한 번씩 나와서, 캐릭터가 셋이면 같은 몬스터파크가 세 번 보이고 링도 세 번 센다. today
의 남은 스케줄과 미완료 스케줄 알림은 이미 이런 컨텐츠를 빼고 센다([[ADR-058]] 결정 18). 스케줄러 화면만 캐릭터마다 센다.

사용자가 2026-11-26 에 정했다(#1266). 공유 컨텐츠는 캐릭터 목록에서 빼고 `공유` 탭에서 메이플 ID 단위로 묶는다. 앱의 `일간`
은 모두 `일일` 로 바꾼다. 웹 시안(Figma `Web/컨텐츠 스케줄러`)도 같은 구조다.

## 결정

### 결정 1. 탭은 `일일 · 주간 · 공유` 셋이고, `일간` 이라는 말은 앱에 남기지 않는다

컨텐츠 스케줄러와 컨텐츠 관리의 탭은 `일일 · 주간 · 공유` 다. 탭 값은 `'daily' · 'weekly' · 'shared'` 이고, 처음 값은 지금처럼
일일이다([[ADR-034]] 결정 8).

`일간` 은 앱 문구에서 모두 `일일` 로 바꾼다(사용자 지정). 바꾸는 곳은 다음과 같다.

| 곳 | 바뀌는 글자 |
|---|---|
| 컨텐츠 스케줄러 · 컨텐츠 관리 탭 | `일간` → `일일` |
| 컨텐츠 스케줄러 빈 상태 | `추적할 일일 컨텐츠가 없습니다` · `등록된 일일 컨텐츠가 없습니다` · `캐릭터를 선택하면 일일·주간 컨텐츠를 확인할 수 있습니다` |
| 초상화 링의 스크린 리더 이름 | `일일` |
| today 남은 스케줄 탭 | `일일 · 주간 · 월간` |
| 미완료 스케줄 알림 제목 | `일일 스케줄이 남은 것 같아요` 처럼 주기 이름(`CYCLE_LABEL`) |
| 서버 게임 데이터 | 몬스터파크 짧은 이름 `일일`, 스케줄러 결산 FAQ 답의 `일일, 주간`, 지출 항목 `일일 퀘스트`(key `daily_quest_quick_pass`) |

서버 게임 데이터는 이 앱 버전을 출시하는 날 새 DB 로 옮기기(`move-old-db.ts`) 전에 운영 DB 에서 고친다(사용자 선택
2026-11-26). 옮기기가 게임 데이터 표를 옛 DB 에서 가져오므로 그 전에 고쳐야 새 DB 에도 간다. 미리 고치지 않는 것은 지금
운영 중인 앱이 지출 기록에 품목 이름을 글자로 적기 때문이다. 이름을 바꾸면 옛 기록이 수정 화면에서 품목을 찾지 못한다. 새 버전
부터는 품목을 줄 id 로 가리켜서 이름을 바꿔도 기록이 끊기지 않는다. 테스트 fixture(`src/__fixtures__/game-data/`)는 앱과 함께
이미 고쳤다.

### 결정 2. 공유 범위가 캐릭터가 아닌 컨텐츠는 일일 · 주간 탭과 링에서 뺀다

일일 · 주간 탭은 공유 범위(`shareScope`, [[ADR-032]] 결정 3)가 `character` 인 컨텐츠만 그린다. 지금 표로는 몬스터파크 · 익스트림
몬스터파커 · 에픽 던전 넷 · 메이플 유니온 둘이 빠진다. 이름이나 카테고리로 고르지 않고 공유 범위로 고른다. today 남은
스케줄이 같은 기준으로 빼고 있어서, 기준이 둘이면 링과 남은 스케줄의 숫자가 갈린다.

- 초상화 링도 캐릭터 범위 항목만 센다. 링은 그 캐릭터의 일이고 공유 컨텐츠는 그 캐릭터만의 일이 아니다.
- 병합과 원장은 바꾸지 않는다([[ADR-032]]). 캐릭터의 병합 결과에는 공유 항목이 그대로 남고, 공유 탭과 에픽 던전 주간 한도가
  그 값을 읽는다.

### 결정 3. 공유 탭은 메이플 ID 하나씩 보여 주고, 레일 자리에 메이플 ID 별칭을 놓는다

공유 탭에서는 캐릭터 초상화 레일 대신 추적 캐릭터가 있는 메이플 ID 의 별칭을 같은 자리에 놓는다(사용자 지정). 별칭은 today 의
공유 컨텐츠 위젯과 같은 이름(`mapleIdNameOf`, 바꾼 이름이 없으면 기본 이름)이고, 차례도 같다. 별칭을 고르면 그 메이플 ID 의
공유 컨텐츠를 보여 준다.

- 고른 메이플 ID 는 컨텐츠 스케줄러 스토어가 든다. 처음 값은 지금 고른 캐릭터의 메이플 ID 다. 별칭을 골라도 고른 캐릭터는
  바뀌지 않는다. 일일 · 주간 탭으로 돌아갔을 때 보던 캐릭터가 바뀌면 안 되기 때문이다. 저장하지 않는다.
- 메이플 ID 줄은 캐릭터 레일과 같은 모양이다(사용자 지정). 칸마다 `CharacterPortrait` 의 rail 칸 하나이고, 얼굴은 그 메이플 ID
  의 대표 캐릭터, 둥근 이름은 별칭이다. 대표 캐릭터는 그 메이플 ID 의 추적 캐릭터 가운데 `pickRepresentativeCharacter` 와 같은
  차례(레벨이 높은 순, 같으면 이름 순)의 첫째다. 메이플 ID 드롭다운(`AccountSelect`)과 같은 규칙이라 대개 같은 얼굴이 된다. 추적
  캐릭터 가운데에서 고르는 것은 얼굴 그림이 추적 캐릭터만 스케줄 캐시에 있기 때문이다. 고르지 않은 칸이 흐린 것과 자리 · 여백도
  캐릭터 레일과 같다. 진행 고리와 레벨 글자는 두지 않는다.
- 메이플 ID 가 하나여도 별칭을 그린다. 이 탭의 값이 누구의 것인지 보이게 하려는 것이다.
- 메이플 ID 를 모르는 캐릭터(소속을 아직 받지 못했다)는 공유 탭에 넣지 않는다. 다른 메이플 ID 의 에픽 던전 완료가 섞이면 주
  3회 한도가 틀린다.
- 월드로 나누지 않는다. 넥슨이 월드 공유 항목을 마지막으로 접속한 월드 기준으로 주기 때문이다([[ADR-058]] 결정 18). 월드
  이름을 쓰지 않으면 틀릴 일도 없다.

### 결정 4. 공유 탭의 값은 그 메이플 ID 의 추적 캐릭터 가운데 가장 앞선 값이다

컨텐츠 하나에 타일 하나다. 값은 today 공유 컨텐츠 위젯과 같은 규칙으로 정한다([[ADR-058]] 결정 18). 완료는 캐릭터 가운데
하나라도 완료면 완료이고, 횟수와 퀘스트 상태는 가장 앞선 값이다. 주기 안에서 진행은 줄지 않으므로 가장 큰 값이 최신이다. 여러
벌을 하나로 합치는 함수(`mergeSharedProgress`)는 `features/content-scheduler/shared-contents.ts` 에 두고 today 뷰모델도 그것을
부른다. 두 벌로 두면 같은 컨텐츠가 두 화면에서 다르게 보인다. 공유 탭은 퀘스트 상태만 확인하는 메이플 유니온 드래곤 퇴치 둘도
그린다. today 위젯은 횟수를 확인하는 줄만 그린다([[ADR-058]] 결정 18).

- 묶음은 카테고리이고 차례는 분류 줄의 `sharedSortOrder` 다(몬스터파크 · 메이플 유니온 · 에픽 던전).
- 에픽 던전 주 3회 한도와 `마감` 은 메이플 ID 단위로 센다([[ADR-033]] 결정 7). 한도가 `ID당` 이기 때문이다.
- 카드 모양은 일일 · 주간 탭의 같은 컨텐츠 카드를 그대로 쓴다([[ADR-033]] 결정 3 · 4).
- 시작 기간 전인 컨텐츠는 그리지 않는다.
- 공유 탭은 요구 레벨로 `진행 불가` 를 달지 않는다. 그 메이플 ID 의 어느 캐릭터든 진행할 수 있기 때문이다.

### 결정 5. 어떤 항목을 보일지는 그 메이플 ID 의 캐릭터 가운데 하나라도 그러면 보인다

| 모드 | 보이는 항목 |
|---|---|
| 자동 | 그 메이플 ID 의 추적 캐릭터 가운데 하나라도 게임에 등록한 항목 |
| 수동 | 그 메이플 ID 의 추적 캐릭터 가운데 하나라도 추적 목록에 넣은 항목 |

수동 추적 목록은 지금처럼 캐릭터마다 저장한다(사용자 지정). 기기 키 `manualTrackedContent:{ocid}` 와 서버 `manual_tracked_items`
를 바꾸지 않아서, 다른 기기와 옛 앱과의 동기화도 그대로다.

빈 상태 문구는 수동이 `추적할 공유 컨텐츠가 없습니다` 와 `컨텐츠 관리` 버튼, 자동이 `등록된 공유 컨텐츠가 없습니다` 다. 일일 ·
주간 탭과 같은 짜임이다.

### 결정 6. 컨텐츠 관리의 공유 탭은 메이플 ID 단위로 켜고 끄고, 저장은 그 메이플 ID 의 추적 캐릭터 모두에 적는다

컨텐츠 관리의 공유 탭도 레일 자리에 메이플 ID 별칭을 놓는다. 목록은 공유 범위가 캐릭터가 아닌 컨텐츠 전부를 카테고리로 묶은
체크리스트이고, 일일 · 주간 탭의 체크리스트에서는 이 컨텐츠를 뺀다.

- 행이 켜져 있는 것은 그 메이플 ID 의 추적 캐릭터 가운데 하나라도 추적하는 것이다(결정 5 와 같은 기준).
- `저장` 하면 켠 항목은 그 메이플 ID 의 추적 캐릭터 모두의 목록에 넣고, 끈 항목은 모두에서 뺀다. 한 명에게만 남아 있으면 끈
  항목이 공유 탭에 계속 보이기 때문이다. 항목의 종류(`daily` · `weekly`)는 컨텐츠의 주기다.
- 저장 · 초안 · 확인 창은 일일 · 주간 탭과 같다([[ADR-034]] 결정 10). 다른 별칭을 고를 때 바꾼 것이 있으면 캐릭터를 바꿀 때와
  같은 확인 창이 뜬다. 한 번의 `저장` 이 캐릭터 탭과 공유 탭에서 바꾼 것을 함께 적는다.
- 수동 모드에서 캐릭터를 새로 더하면 그 캐릭터는 지금처럼 게임 등록으로 채운다([[ADR-034]] 결정 5). 공유 항목은 결정 5 의
  `하나라도` 기준이라, 새 캐릭터가 등록하지 않은 공유 항목도 공유 탭에서 사라지지 않는다.

### 결정 7. 머리는 지금 모양 그대로 두고, 탭 셋은 중간 크기 고르기 칸으로 줄인다

컨텐츠 스케줄러 머리는 지금처럼 왼쪽에 제목 · FAQ 물음표와 갱신 시각, 오른쪽에 `관리`(text-xs semibold muted 글자)와 탭이다.
`관리` 는 수동 모드에서만 나온다.

탭이 셋이 되면 폭 360(글자 크기의 기준 폭, [[ADR-063]] 결정 17)에서 제목이 잘린다. 쓸 수 있는 폭 328 에서 `관리` 23, 탭 셋
(`Segment` lg) 166, 사이 간격 12 둘을 빼면 제목 자리가 127 인데, 제목과 물음표에 138 이 든다. 탭을 md(145)로 줄이면 제목
자리가 148 이라 들어간다. 그래서 컨텐츠 스케줄러와 컨텐츠 관리의 탭을 md 로 맞춘다. 화면마다 탭 크기가 다르면 오갈 때 탭이 커졌다
작아진다.

화면은 Figma `App/컨텐츠 스케줄러` 에 테마 여섯으로 있다.
