## 맥락

전체 품질 점검(2026-08-05)에서 초기 로드가 가장 나쁜 지표로 나왔다. `npm run build` 실측:

| 항목 | 값 |
|---|---|
| 메인 JS 청크 | **1,019 kB** (gzip **411 kB**) — 단일 청크 |
| 라우트 지연 로딩 | **0건** (`React.lazy` 없음) |
| dist 총량 | 12 MB (이미지 9.5 MB) |

Vite가 자체 분리한 것은 `jeep-sqlite`(292 kB)와 네이티브 웹 폴백 shim 몇 개뿐이고, **앱 코드는
전부 한 덩어리**다. 8개 라우트 화면 · 모든 store · `src/data/*.json` 이 첫 페인트에 함께 평가된다.

두 가지가 특히 문제다.

**① 디버그 화면이 프로덕션에 실려 나간다.** `/debug/*` 라우트 5개(`BossCardPreview`
`DailyQuestCardPreview` `BossPortraitSizePreview` `LoadingPreview` `ThemeBackgroundPreview`,
합계 **2,033 LOC**)가 게이트 없이 `App.tsx` 에 등록돼 있다. 빌드 산출물에서 라우트 경로 문자열이
그대로 검출된다. 각 파일 주석은 "조정이 끝나면 삭제할 것"이라고 적혀 있지만, 이 도구들은
**일러스트·테마 배경이 추가·교체될 때마다 다시 쓰인다**(2026-07-13 사용자 확인). 즉 삭제가 답이
아니라서 주석대로 정리되지 않은 채 남았다.

**② OTA 다운로드 크기와 직결된다.** [[ADR-022]] 의 Live Update 는 웹 번들을 통째로 내려받으므로
초기 청크 크기가 매 업데이트의 셀룰러 트래픽이 된다([[ADR-027]] 이 셀룰러를 감지해 막는 이유와
같은 축).

## 결정 1 — `/debug/*` 5개를 **삭제한다** (게이팅하지 않는다)

라우트 5개와 컴포넌트 파일 5개(2,033 LOC)를 지운다. 각 파일 주석이 원래 지시하던 바
("조정이 끝나면 삭제할 것")를 그대로 실행하는 것이다.

| 삭제 대상 | LOC |
|---|---|
| `app/LoadingPreview.tsx` (`/debug/loading`, [[ADR-061]]) | 971 |
| `app/content-scheduler/DailyQuestCardPreview.tsx` (`/debug/quest-cards`, [[ADR-020]]) | 396 |
| `app/ThemeBackgroundPreview.tsx` (`/debug/theme-background`, [[ADR-088]]) | 250 |
| `app/boss-profit/BossPortraitSizePreview.tsx` (`/debug/boss-portrait-size`, [[ADR-018]]) | 212 |
| `app/boss-scheduler/BossCardPreview.tsx` (`/debug/boss-cards`, [[ADR-018]]) | 204 |

**사용자 결정(2026-08-05): "제거해. 나중에 필요하면 다시 만들자."** 2026-07-13에는 "일러스트가
추가될 때마다 다시 쓰이므로 지울 수 없다"고 보고 DEV 게이팅을 제안했다가 보류됐던 항목인데,
이번에 **재작성 비용을 감수하고 지우는 쪽**으로 정리됐다. 도구는 조정할 값이 생겼을 때 다시
만든다 — 크롭 조정 UI는 화살표·줌 버튼과 JSON 복사가 전부라 재작성이 어렵지 않고, 그동안
`git log` 로 옛 구현을 참고할 수 있다.

**삭제로 함께 사라지는 것은 `BossCard` 의 `export` 키워드 하나뿐이다.** `BossScreen.tsx` 가
`BossCard` 를 내보낸 것은 `BossCardPreview` 가 실제 카드와 똑같이 그리려고 재사용했기
때문이고(제품 코드·테스트 어디서도 import 하지 않는다), 이제 그 이유가 없어졌으므로 `export` 를
뗀다. 디버그 화면들이 쓰던 나머지 심볼(`getBossPortraitCrop` `getDailyQuestRegionCrop`
`MAPLE_LEAF_PATH` `MapleSweepSpinner` 등)과 데이터 파일(`daily-quest-regions.json`,
`boss-portrait-*-crops.json`)은 **전부 제품 코드가 계속 쓰므로 건드리지 않는다.**

**감수하는 것** — [[ADR-089]] 의 검은마법사 배경 값이 "사용자 확인 대기" 상태인데 그 조정
도구(`/debug/theme-background`)가 사라진다. 값을 다시 만질 일이 생기면 도구부터 복원해야 한다.

## 결정 2 — 라우트 화면 8개를 `React.lazy` 로 분할한다

`App.tsx` 최상단 정적 import를 `lazy(() => import(...))` 로 바꾼다. 대상은 온보딩 · 컨텐츠(+관리) ·
보스(+관리) · 보스 수익 · 드랍 히스토리 · 설정.

Vite는 각 `import()` 를 별도 청크로 떼어내므로, **첫 화면은 자기 화면 하나만 받는다.** 탭 이동
시 나머지가 그때 로드된다 — 네이티브 앱에서 청크는 원격이 아니라 **WebView 로컬 파일**이라
네트워크 지연이 없다.

`AppShell` 은 라우터와 분리돼 있고([[ADR-050]] 시절 테스트 가능성 때문) `MemoryRouter` 로
테스트되므로, 이 변경은 `AppShell` 안쪽에서 끝난다.

## 결정 3 — Suspense 경계는 **최상위 하나 + 중첩 자식 하나**, 자식 것이 부모 안쪽에 있어야 한다

이것이 이 ADR에서 가장 깨지기 쉬운 부분이다.

`<Routes>` 전체를 하나의 `<Suspense>` 로 감싸면 **[[ADR-077]] 의 계약이 깨진다.** 드랍
히스토리(`/profit/drops`)는 형제 라우트가 아니라 보스 수익의 **중첩 라우트**이고, 그 이유는
"이동해도 아래 화면이 언마운트되면 안 되기" 때문이다(형제였을 때 아코디언 펼침·보던 기간·
스크롤을 전부 잃었고, iOS WKWebView에서 stuck sticky 헤더가 빈 화면이 됐다). 최상위 Suspense는
자식 청크가 로드되는 동안 **`BossProfitScreen` 을 포함한 트리 전체를 폴백으로 대체**하므로
정확히 같은 증상을 되살린다.

따라서 중첩 자식은 자기 `element` 만 감싼다:

```tsx
<Route path="drops" element={<Suspense fallback={<RouteFallback />}><DropHistoryScreen /></Suspense>} />
```

이 `element` 는 `BossProfitScreen` 의 `<Outlet />` 자리에 그려지므로 Suspense 경계가 **부모
서브트리 안쪽**에 생기고, 부모는 언마운트되지 않는다.

**최상위 경계는 그대로 둔다** — React 는 서스펜드한 컴포넌트에서 **가장 가까운** 경계를 쓰므로,
자식이 자기 경계를 가지면 그 서스펜드는 바깥 경계까지 올라오지 않는다. 최상위 경계는 탭 간 이동
(화면 전체가 어차피 바뀌는 경우)만 받고, 탭바는 `<Routes>` 밖이라 폴백에 덮이지 않는다. 즉
"라우트마다 하나씩" 8개를 두는 것이 아니라 **경계 2개**로 충분하다.

### 이 결정은 테스트로 고정돼 있다

`src/__tests__/route-splitting.test.tsx` — `DropHistoryScreen` 을 **영원히 서스펜드**시키고
(resolve 되지 않는 프라미스를 throw 하는 React 서스펜스 프로토콜) `/profit/drops` 를 렌더한 뒤,
부모 헤딩 `보스 수익` 이 나타나는지 본다. 최상위 경계 하나뿐이면 자식의 서스펜드가 부모까지
걷어내 그 헤딩이 **영영 나타나지 않는다**.

> 이 테스트가 실제로 판별하는지 확인했다(2026-08-05) — 안쪽 경계를 일부러 지우자 이 테스트만
> 실패하고 나머지 5개는 통과했다. **로드가 끝난 뒤를 보는 테스트로는 이 실수를 못 잡는다**(끝나면
> 어차피 부모가 돌아온다)는 것이 이 형태를 택한 이유다.
>
> 모듈 팩토리 자체를 대기시키는 방식(`vi.mock(path, () => new Promise(() => {}))`)은 쓰면 안 된다 —
> vitest 의 모듈 해석이 통째로 멈춰 테스트가 영영 끝나지 않는다(첫 시도에서 실제로 밟았다).

## 결정 4 — Suspense 폴백은 스플래시 시퀀스를 건드리지 않는다

`AppShell` 은 모듈 평가 시점부터 `MIN_SPLASH_MS`(1000ms) 를 보장한 뒤 네이티브 스플래시를
내린다. 지연 로딩은 이 타이머와 **독립적**이다 — 스플래시가 떠 있는 동안 첫 청크가 로드되므로,
로컬 파일 로딩이 1초 안에 끝나는 한 사용자는 폴백을 보지 못한다.

폴백은 기존 `LoadingState`([[ADR-061]] 로 확정된 표현)를 재사용하되, **스플래시와 겹쳤을 때
이중 로딩으로 보이지 않도록 화면 전체를 채우는 형태로만** 쓴다. 새 로딩 표현을 만들지 않는다.

## 결정 5 — 참조 0건인 `arcanus1.png`(2.65 MB)를 삭제한다

`src/assets/bosses/arcanus1.png` 는 **전체 소스에서 참조가 0건**인데도 번들 최대 파일이다.
`lib/boss-icons.ts` 의 `import.meta.glob('../assets/bosses/*', { eager: true })` 가 디렉터리
전체를 사용 여부와 무관하게 끌어오기 때문이다.

같은 디렉터리의 다른 대용량 파일(`baekyeon` 569 kB · `senya` 418 kB 등)은 참조가 있으므로
**건드리지 않는다.** PNG→WebP 변환은 2단계 과제다([[ADR-093]] 에서 수행).

> 여기 함께 적었던 "eager glob 자체를 lazy 로 바꾼다"는 2단계 계획은 **[[ADR-093]] 결정 3에서
> 철회됐다** — 측정해 보니 `eager` 여부는 dist 크기에도 런타임 다운로드에도 영향이 없었다.

> 게임 애셋 파일 삭제는 [[ADR-006]] 의 "AI 임의 판단 금지" 대상에 가까우므로, 참조 0건을
> 근거로 제시하고 **사용자 확인 후** 지운다(2026-08-05 확인·삭제 완료).
