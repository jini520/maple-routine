### ADR-146: **`today` 는 위젯 격자다** — 4열 좌표 배치 · 크기별로 다르게 그리는 타일 · 데이터는 화면이 한 번 모은다 (설계 완료, 구현 전, 2026-08-17)

**배경**: [[ADR-132]] 결정 7이 첫 화면을 `today` 로 옮겼고, 결정 12가 그 화면을 *«개발 진행중» 빈
화면*으로 두었다. 그 ADR 은 대가에 이렇게 적었다 — *"첫 화면이 빈 대시보드다. 온보딩 직후 착지
지점이기도 해서, 막 캐릭터를 고른 사용자의 첫인상이 «개발 진행중» 이 된다."* 이 ADR 이 그 자리를
채운다.

사용자가 요구한 것은 «대시보드» 가 아니라 **위젯**이다(2026-08-17) — *"위젯 형태로 만들거야 …
실제 위젯처럼 1x1 타일, 2x2 타일, 1x2 타일, 2x4 타일 같은 다양한 형태로 추가될 수 있도록 설계해."*

그 한 문장이 이 ADR 의 전부를 정한다. **화면이 아니라 «판»을 만드는 일**이고, 판을 만든다는 것은
**앞으로 붙을 타일이 지켜야 할 규약을 지금 정한다**는 뜻이다. 지금 붙일 내용 여덟 개를 그리는
것보다 그쪽이 어렵고, 그래서 아래 결정 대부분이 «내용» 이 아니라 «격자와 규약» 에 관한 것이다.

담을 내용은 사용자가 넷을 지정했고(대표 캐릭터 · 캐릭터별 남은 스케줄 · 주간 보스 수익 통계 ·
이번 주 최고가 아이템) 다섯 번째 자리는 제안을 받아 넷을 골랐다(초기화 카운트다운 · 아이템 드롭 가뭄 ·
주간 결정석 한도 · 가격 미입력 알림).

### 결정 1. 격자는 **4열 · 열 폭은 유동 · 행 높이는 고정**이다

사용자 결정(2026-08-17). 표기는 **`가로x세로`(WxH)** 로 고정한다 — 사용자가 쓴 `2x4` 같은 표기가
«폭 2·높이 4» 인지 그 반대인지 갈리므로, 표기 규칙을 결정으로 박아 둔다.

| 값 | 크기 | 근거 |
|---|---|---|
| 열 수 | **4** | 1x1 이 «아이콘 + 숫자 하나» 로 성립하는 최소 단위가 되는 분할. 2열은 1칸이 165dp 라 작은 지표 타일을 만들 수 없고, 6열은 1칸이 52dp 라 «최소 2칸» 규칙이 붙어 결국 4열과 같아지면서 표기만 복잡해진다 |
| 좌우 여백 | **16** (`px-4`) | 앱의 모든 화면이 쓰는 값. 하단바의 14([[ADR-132]] 결정 11)에 맞추는 안을 버렸다 — 바는 **떠 있는 물건**이라 콘텐츠 격자와 다른 자를 써도 되고, 여기서 14 를 쓰면 today 만 다른 좌우 선을 갖는다 |
| 타일 간격 | **12** (제안값) | 화면의 세로 리듬은 `gap-4`(16)이지만 그것은 **서로 다른 블록 사이** 값이다. 격자 안 타일들은 한 판이라 더 붙는다 |
| 열 폭 | **유동** — `(창폭 − 32 − 12×3) / 4` | 360dp 에서 73 |
| 행 높이 | **고정 76** (제안값) | 아래 |

**행 높이를 폭에서 파생하지 않는 것이 이 결정의 핵심이다.** 정사각 셀(행 높이 = 열 폭)로 두면
격자가 화면 폭에 **비례해 길어진다** — Z Flip3 를 펼치면 폭이 ~700dp 라 4x2 타일 하나가 340dp,
즉 화면 절반을 넘는다. 위젯은 *«폭이 늘면 넓어지는»* 물건이지 *«같이 길어지는»* 물건이 아니다.
360dp 에서 열 폭 73 · 행 높이 76 이라 1x1 이 거의 정사각이고, 큰 화면에서는 타일이 옆으로만 넓어진다.

이 값들은 **한 함수가 판다** — `lib/widget-grid-metrics.ts` 의 `resolveWidgetGridMetrics(창폭)`.
[[ADR-132]] 정정 30 이 하단바에서 같은 모양을 이미 했다(*"치수는 계산한다 — 재는 것이 하나도 없다"*).
`onLayout` 실측을 쓰지 않는 이유도 같다: 첫 프레임에 0 이라 타일이 한 프레임 접혀 있다.

### 결정 2. 배치는 **흐름이 아니라 좌표**다 — `{ id, col, row, w, h }`

레이아웃은 **명시적 좌표 배열**이고, 순수 함수가 그 배열을 검증한다.

```ts
export interface WidgetPlacement {
  id: WidgetId
  col: number   // 0..3
  row: number   // 0..
  w: number     // 1..4
  h: number     // 1..
}

/** 겹침·범위·구멍을 잡는다. 반환값이 빈 배열이면 유효한 배치다. */
export function validateWidgetLayout(layout: readonly WidgetPlacement[]): LayoutViolation[]
```

검증 셋: ① **겹치는 타일이 없다** ② `col + w ≤ 4` ③ **통째로 빈 행이 없다**(중간에 빈 행이 나오면
`row` 를 잘못 적은 것이다 — 배치를 손으로 적기로 한 이상 그 실수는 반드시 난다).

렌더는 격자 컨테이너 안 **절대 배치**다. 컨테이너 높이 = `max(row + h) × (행높이 + 간격) − 간격`.

**기각한 둘**:

- **자동 패킹**(순서 배열을 주면 알고리즘이 빈칸을 채운다, iOS 홈 화면 방식) — 결과가 놀랍고,
  위젯 하나의 크기를 바꾸면 아래 전부가 예측 불가능하게 재배열된다. 무엇보다 **검증할 것이 없다**:
  알고리즘이 늘 «어딘가에» 넣으므로 배치 실수가 실수로 드러나지 않는다.
- **행(shelf) 단위 배치**(한 행에 담을 타일 목록을 주고 행 높이는 그 안의 최대값) — 구현이 가장
  싸지만 **`1x2`·`2x2` 같은 «세로로 긴 타일» 이 원리적으로 표현되지 않는다.** 한 행의 높이가 하나라
  옆 칸이 위아래로 갈리지 않기 때문이다. 사용자가 요구한 크기 집합(`1x2` 를 명시했다)이 이미 이 안을
  배제한다.

**v1 에서 이 배열은 코드 상수다**(사용자 결정 — «고정 레이아웃 + 확장 가능한 설계»). 그래서 이번에
**저장 스키마도 마이그레이션도 만들지 않는다.** 나중에 편집이 오면 같은 배열을 저장소로 옮기고
`validateWidgetLayout` 을 그대로 재사용한다 — 그때 새로 필요한 것은 «저장된 배치가 지금 존재하지
않는 위젯 id 를 가리킬 때» 의 참조 무결성뿐이고, 그것은 [[ADR-143]] 결정 4 와 같은 모양이다
(**쓰는 쪽이 지킨다**).

### 결정 3. 위젯은 **크기별로 다른 그림**을 스스로 갖는다

레지스트리 하나가 위젯의 존재를 선언하고, 배치는 그 id 를 가리킬 뿐이다.

```ts
export interface WidgetDefinition {
  id: WidgetId
  /** 이 위젯이 감당하는 크기. 배치가 이 밖의 크기를 주면 검증이 잡는다. */
  sizes: readonly { w: number; h: number }[]
  /** 타일을 누르면 가는 곳. 없으면 누를 수 없는 타일이다. */
  target?: TabRouteName
  Component: React.ComponentType<WidgetProps>
}

export interface WidgetProps {
  w: number
  h: number
  data: TodayViewModel   // 결정 4
}
```

- **위젯 내부가 `w`·`h` 로 갈라 그린다.** 같은 데이터를 다른 밀도로 말하는 것이지, 큰 타일이 작은
  타일을 늘린 것이 아니다(iOS 위젯의 small/medium/large 와 같은 규약). 2x1 짜리 «주간 수익» 은 총액
  하나, 4x2 는 총액 + 캐릭터 top3.
- **타일은 스스로 커지거나 줄지 않는다 — 예외 하나**(아래 정정 1). 크기는 배치가 준다. 위젯이
  *«내용이 많으니 커지겠다»* 를 하면 격자가 무너지고, 그 순간 결정 2의 검증이 거짓말이 된다.
- **넘치면 자르거나 접는다 — 타일 안에서 스크롤하지 않는다.** 타일 안 스크롤은 페이지 스크롤과
  제스처를 두고 싸우고, 위젯이 «작은 화면» 이 되는 순간 격자를 만든 이유가 사라진다. 남은 스케줄이
  캐릭터 6명이면 4x3 타일은 앞의 셋을 그리고 «외 3명» 으로 접는다.
- **`sizes` 는 위젯이 선언하고 배치가 그것을 지킨다.** 검증에 네 번째 규칙이 붙는다: 배치의 `(w,h)`
  가 그 위젯의 `sizes` 에 있어야 한다. 이것이 «크기별로 다르게 그린다» 를 **약속으로 만드는** 자리다 —
  선언 안 한 크기를 받으면 위젯은 그리는 방법을 모른다.

### 결정 4. 데이터는 위젯이 각자 가져오지 않는다 — **화면이 한 번 모아 나눠 준다**

`TodayScreen` 이 기존 스토어 넷(`content-scheduler` · `boss-scheduler` · `boss-profit` ·
`drop-history`)과 `character-basic-cache` 를 읽어 **하나의 뷰모델**(`TodayViewModel`)을 만들고,
위젯에는 그것을 프롭으로 준다. **위젯은 스토어를 모른다.**

이유가 셋이다.

1. **동기화 트리거가 위젯 수만큼 늘어난다.** 위젯 여덟이 각자 `loadTrackedOcids()` 를 부르면
   [[ADR-097]] 게이트를 여덟 번 통과 시도하게 된다. 그 게이트는 «실행당 1회, 화면당이 아니다» 를
   지키려고 만든 것인데([[ADR-101]] 결정 3 과 같은 근거) 위젯이 화면보다 잘게 쪼개진 단위라
   그 규칙이 자동으로 따라오지 않는다.
2. **위젯이 순수 프리젠테이션이 되면 스냅샷 테스트가 값 조합만으로 선다.** 스토어를 목킹하지 않고
   «수익 0 · 캐릭터 없음 · 실패» 같은 상태를 프롭으로 바로 만들 수 있다.
3. **두 위젯이 같은 사실을 다르게 말하는 것을 구조로 막는다.** 결정 6의 위젯 여덟 중 셋이 같은
   드롭 기록을 본다(최고가 아이템 · 아이템 드롭 가뭄 · 가격 미입력). 각자 읽으면 각자의 시점에서 읽는다.

**선행 조건 — `schedule-sync` 단일 비행.** [[ADR-132]] 결정 8 이 기한을 *«`today` 에 내용이 붙는
시점»* 으로 못 박아 둔 구멍이고, 이 ADR 이 그 시점이다.

> 게이트 플래그는 성공이 아니라 **시도**를 기록하고([[ADR-097]] 결정 3, `sync-run-state.ts`) 신선도는
> 호출이 **끝나야** 갱신되므로, `today` 의 동기화가 날아가는 중에 사용자가 스케줄 탭으로 들어가면
> 게이트가 `시도함 = true` · `신선함 = false` 를 보고 **같은 호출을 한 번 더** 낸다. `today` 가
> 첫 화면이라 **실행당 첫 동기화는 대개 이 화면이 낸다** — 즉 이 경로는 예외가 아니라 지배 경로다.

처방은 순서가 아니라 **단일 비행**이다(진행 중인 호출이 있으면 그 프라미스를 함께 기다린다).
자리는 `features/schedule-sync/schedule-sync.ts` 이고, 키는 «ocid 집합» 이 아니라 **회차**다 —
스케줄러 셋과 today 가 같은 추적 목록을 보므로 집합이 같고, 집합을 키로 삼으면 캐릭터 하나가
다른 목록끼리는 여전히 두 번 나간다.

**`prehydrate` 의 순차 루프는 이번 범위에서 바꾸지 않는다.** 그 루프가 순차인 이유가 정확히
*"신선도는 앞 회차가 캐시를 다 쓴 뒤에야 참이 된다"*([[ADR-101]] 결정 3)이므로 단일 비행이 서면
병렬로 돌려도 호출이 늘지 않게 되지만, **고치는 것은 구멍이지 성능이 아니다.** 순차를 푸는 것은
근거가 사라졌다는 사실을 확인한 뒤의 별건이다.

### 결정 5. **위젯은 사라지지 않는다** — 자기 타일 안에서 빈 상태를 말한다

데이터가 없다고 타일을 빼면 격자에 구멍이 나고, 그 구멍은 *«어제 있던 것이 오늘 없다»* 로 읽힌다.
좌표 배치(결정 2)에서는 더 나쁘다 — 아래 타일이 올라오지 않으므로 **빈 사각형**이 남는다.

빈 상태 문구는 `error-resilience.md` 원칙 1을 따른다 — **«없다» 와 «모른다» 를 가른다.** 동기화가
실패해서 모르는 것을 «0 메소» 로 그리지 않는다. 이 화면은 숫자를 크게 그리는 화면이라 그 구분이
특히 중요하다: 큰 `0` 은 사실을 단정하는 그림이다.

~~**예외 하나** — 대표 캐릭터가 지정돼 있지 않으면 그 타일은 **CTA 가 된다**(«대표 캐릭터를
정해주세요» → 설정 → 캐릭터 관리, [[ADR-140]]).~~ → **그 상태가 존재하지 않는다**(정정 2 — 미지정이면
[[ADR-143]] 결정 4의 «임시 대표» 가 선다). 예외 없이 «위젯은 사라지지 않고 자기 타일 안에서 말한다» 만 남는다.

**«없다» 와 «모른다» 를 가르는 규칙에는 예외가 하나 생겼다** — 주간 보스 수익은 기록이 없어도
`0 메소` 를 그린다(정정 4, 사용자 지시). 나머지 위젯은 그대로다.

**타일 탭 이동은 [[ADR-132]] 결정 9 의 광고 게이트를 탄다** — today 에서 어디로 가든 그것은
**그룹 이동**이기 때문이다(today 자신이 그룹이다). 하위 이동·뒤로가기만 게이트 밖이라는 규칙은
그대로이고, 이 화면이 새로 여는 예외는 없다.

```
  (0,7) 2x2 최고가 · (2,7) 2x2 결정석 · (0,9) 2x1 초기화 · (2,9) 2x1 미입력 · (0,10) 4x1 가뭄~~
```

**«새 API 가 필요 없는 것만 골랐다»** 가 5~8번의 선정 기준이었다. 여덟 중 일곱이 이미 기기 안에
있는 값을 다시 배치하는 것뿐이고, 유일한 예외가 결정 7이다.

**「사냥 타이머」 위젯은 만들지 않는다.** 그 화면 자체가 아직 [[ADR-132]] 결정 12 의 «개발 진행중»
넷 중 하나다 — 없는 화면으로 보내는 타일은 «있는 것처럼 보이는 거짓» 이다.

### 결정 7. 대표 캐릭터 카드에서 **전투력은 보류하고, 경험치는 실응답 확인이 선행 조건**이다

사용자 요청은 «닉네임 · 월드 · 레벨 · 길드 · 전투력 · 경험치 %» 였다. 앞 넷은 이미 있고
(`CharacterBasicProfile`), 뒤 둘은 **이 앱이 가진 적 없는 데이터**다.

- **전투력은 `character/basic` 에 없다.** 넥슨 API 에서 전투력은 별도 엔드포인트의 스탯 배열에
  들어 있어, 넣으면 **캐릭터당 호출이 하나 더 느는 축**이 열린다. [[ADR-097]] 이 캐릭터 단위 호출
  예산을 통째로 재편한 결정인 만큼 그 계산을 다시 해야 하고, **이 ADR 은 그 계산을 하지 않는다**
  (사용자 결정 — «경험치만 넣고 전투력은 보류»).
- **경험치는 같은 응답에 편승할 수 있어 추가 호출이 0 이다.** 필드는 **사용자 확인으로 닫혔다**
  (2026-08-17):

  ```
  "character_exp": 1390734270108,      // number — 누적 경험치 절대값
  "character_exp_rate": "80.300"       // string — 현재 레벨 진행률(%), 소수 3자리
  ```

  **`character_exp_rate` 가 숫자가 아니라 문자열인 것이 이 필드의 함정이다** — `access_flag` 와
  같은 모양이고([[ADR-015]] 이래 `normalizeCharacterBasic` 이 `=== 'true'` 로 푸는 그 자리),
  문자열째 비교하면 `"9.500" > "80.300"` 이 참이 되어(사전순) 진행률 바가 **조용히 뒤집힌다.**
  정규화가 `Number()` 로 변환하고 `CharacterBasicProfile.expRate?: number` 로 실어 나른다.
  `character_exp`(누적 절대값)는 **화면에 쓰지 않는다** — 레벨이 오를수록 커지는 값이라 «얼마나
  남았나» 를 말하지 못하고, 카드가 답해야 하는 것은 진행률이다.

**옛 캐시에는 이 필드가 없다.** `world`·`jobClass`·`guildName` 이 이미 그런 것처럼 옵셔널이고,
없으면 카드는 **경험치 줄 자체를 그리지 않는다**(0% 바를 그리지 않는다). 자리를 비워 두거나 빈 바를
그리면 «값이 0» 으로 읽힌다 — [[ADR-057]] 이 길드에서 «미가입» 과 «모름» 을 가른 것과 같은 판단이다.

### 결정 8. 두 화면이 나눠 갖던 판정 둘을 **꺼낸다** — 복제가 아니라 이동이다

위젯 2번(남은 스케줄)이 세는 «남은 것» 은 스케줄러 화면이 보여 주는 것과 **한 글자도 다르면 안
된다.** 그런데 그 판정이 지금 두 자리에 갇혀 있다.

| 판정 | 지금 자리 | 처리 |
|---|---|---|
| 컨텐츠 완료 여부 | `app/content-scheduler/content-completion.ts` | **그 자리에서 import 한다** |
| 표시 대상 보스 목록 | `BossScreen.tsx` 안의 지역 함수 `displayedBossesOf` | **`features/boss-scheduler/` 로 꺼낸다** |

- **`content-completion.ts` 는 옮기지 않는다.** 그 파일이 [[ADR-142]] 결정 4 에서 이미 *"규칙의
  **출처**"* 로 만들어졌고 스스로 *"그때까지 이 파일이 **읽어야 할 한 곳**"* 이라고 선언했다. 다만
  그 파일은 화면 상수(`content-badges` · `WeeklyContentCards` 의 슬러그·이름)에 기대고 있어
  `packages/core` 로 갈 수 없다 — 그래서 `app/today/` 가 `app/content-scheduler/` 를 import 하는
  **화면 사이 의존이 새로 생긴다.** 감수한다: 판정을 두 벌로 만드는 것이 훨씬 나쁘고, 세 번째
  사용처가 생기면 그때 상수와 함께 `core/lib` 으로 승격한다.
- **`displayedBossesOf` 는 꺼낸다.** 그 함수 안에 [[ADR-035]] 수동 모드 멤버십 규칙과 [[ADR-031]]
  결정 5(미등록이어도 완료면 포함)가 함께 들어 있는데, 지금은 `BossScreen.tsx` 지역 함수라
  **화면 밖에서 부를 방법이 없다.** 의존이 코어 모듈과 인자뿐이라(RN 컴포넌트를 안 만진다)
  `packages/core/src/features/boss-scheduler/` 로 그대로 나간다. **시그니처는 안 바꾼다** —
  [[ADR-128]] 원칙 1과 같은 태도로, 꺼내는 작업을 다듬는 작업과 섞지 않는다.

이것이 이 ADR 에서 **기존 코드를 만지는 유일한 부분**이다(그 밖은 전부 새 파일). 두 판정 다
«오늘 남은 것» 의 정의라 today 가 자기 버전을 갖는 순간 두 화면이 서로 다른 수를 말하기 시작한다.

### 결정 9. 「가장 비싼 아이템」은 **시세가 아니라 기록된 판매가** 순위다

앱은 아이템 시세표를 갖고 있지 않다. 아이템 금액의 유일한 출처는 사용자가 입력한 실제 판매가
(`RecordedDrop.priceMeso`, [[ADR-124]])다. 그래서 위젯 4번의 뜻은 정확히 **«이번 주에 기록된 판매가
중 가장 큰 것»** 이고, **가격을 아직 입력하지 않은 드롭은 순위에 들지 않는다.**

- 이것이 위젯 7번(가격 미입력 N건)이 **같은 격자에 있어야 하는 이유**다. 4번이 «없음» 을 말하는
  가장 흔한 이유가 «안 팔았거나 안 적었다» 이므로, 그 답을 옆 타일이 들고 있어야 한다.
- 미입력 건을 «0 메소짜리 후보» 로 순위에 넣지 않는다 — 값을 모르는 것을 가장 싼 것으로 단정하는
  일이다(`lib/drop-price.ts` 가 합산에서 스킵·미입력을 0 으로 접는 것과는 **다른 문제**다. 합산은
  «더할 것이 없다» 이지만 순위는 «비교했다» 를 주장한다).
- 아이템 드롭 판정(`isValuableDrop`)은 **이름 기반이라 가격 없이도 선다.** 그래서 위젯 8번(아이템 드롭 가뭄)은
  4번이 비어 있어도 말할 것이 있다 — 두 위젯이 겹쳐 보이지만 **묻는 것이 다르다**(얼마였나 / 언제
  마지막이었나).

## 시안 검토 중 정정 (2026-08-17, 사용자 지시)

시안(위젯 8종 × 크기별)을 그려 놓고 받은 피드백이다. 넷은 결정을 **뒤집고**, 나머지는 표현을 좁힌다.

### 정정 1. **가로 4칸을 다 쓰는 타일만 `h: 'auto'` 를 선언할 수 있다** — 결정 3의 예외

「남은 스케줄」이 *«외 N명» 없이 선택된 캐릭터를 전부 출력한다*(정정 3)로 바뀌면서 **높이를 미리 알
수 없게** 됐다. 결정 3의 *"타일은 스스로 커지거나 줄지 않는다"* 를 통째로 버리는 대신 조건을 하나 단다.

```
h === 'auto'  →  w === 4    // validateWidgetLayout 의 다섯 번째 규칙
```

**w=4 가 조건인 이유가 이 정정의 전부다.** 가로를 다 쓰면 **옆에 아무도 없으므로**, 늘어난 만큼
아래 전부가 **같은 값으로** 내려가고 겹침이 생길 수 없다. 좁은 타일에 auto 를 허용하면 옆 칸과
아래 칸이 서로 다른 만큼 밀려 좌표가 무너진다 — 결정 2가 자동 패킹을 기각한 것과 같은 이유
(«검증할 것이 없어진다»)가 여기서 되살아난다.

- **배치의 `row` 는 그대로 손으로 적는다.** auto 타일의 `h` 는 **최소 높이**(nominal)이고, 렌더러가
  실측 높이와의 차이만큼 그 아래 전부를 내린다. 즉 `y = 적어 둔 y + Σ(위쪽 auto 타일들의 초과분)`.
  좌표 배열을 읽어서 «몇 번째 띠인가» 를 아는 성질이 유지된다.
- 「남은 스케줄」의 실측: 캐릭터 n명 → `50 + 48n` px(패딩 28 + 헤더 30 + 행 40 · 간격 8).
  2명 146 · 4명 242 · 6명 338. **어느 것도 격자 행(76·164·252)에 안 맞는다** — 그것이 auto 인 이유다.
- **타일 안 스크롤 금지는 그대로다.** 늘어나는 것과 스크롤하는 것은 다르다.

### 정정 2. 대표 캐릭터 — **«대표 없음» 상태는 존재하지 않는다** (결정 5의 예외 삭제)

결정 5는 대표 미지정 시 그 타일을 CTA 로 바꾼다고 적었다. **그 상태가 없다**(사용자 지시) —
[[ADR-143]] 결정 4가 이미 *"미지정이면 목록의 첫 번째가 «임시 대표»"* 로 답을 갖고 있다.

- **today 가 그 값을 읽는 첫 화면이다.** `resolveRepresentative`(`features/character-manage/derivations.ts`)는
  지금 일부러 `null` 을 돌려주고 주석이 그 이유를 *"그 값을 읽는 화면이 아직 하나도 없고"* 로 적어 뒀다.
  그 문장이 이 ADR 로 낡는다.
- **그 함수를 고치지 않고 옆에 하나 더 만든다** — `resolveDisplayRepresentative(orderedOcids, stored)`
  = `stored ?? orderedOcids[0] ?? null`. 둘은 **다른 질문**이다: 기존 함수는 «사용자가 대표라고
  말했는가»(캐릭터 관리의 채워진 별), 새 함수는 «지금 대표 자리에 설 캐릭터는 누구인가»(today 카드).
  기존 함수를 폴백시키면 [[ADR-144]] 결정 4(*대표를 안 고른 화면은 채워진 별이 하나도 없다*)가 깨진다.
- **«임시» 라는 표시는 하지 않는다** — [[ADR-143]] 결정 4의 *"그 규칙도 화면에 그리지 않는다"* 를 잇는다.
- **4x3 은 삭제한다.** 크기는 **4x2(기본) · 4x1 · 2x2** 셋이다.

### 정정 3. 남은 스케줄 — 이름·표기·정렬·범위

| 자리 | 전 | 후 |
|---|---|---|
| 분류 이름 | 일일 컨텐츠 · 주간 컨텐츠 · 주간 보스 · 월간 보스 | **일퀘 · 주간퀘 · 주간 보스 · 검마** |
| 완료 표기 | 「다 했습니다」 | **`CLEAR`** |
| 배지 자리 | 닉네임 **아래** | 닉네임 **오른쪽** — 단 배지 형태 자체를 버린다(정정 9) |
| 강조 | 라벨과 숫자가 같은 무게 | **숫자만 굵게**(정정 9 — 크기·색은 그대로, 테마 색 금지) |
| 범위 | 캐릭터 3명 + 「외 N명」 | **선택된 캐릭터 전부** |
| 전부 완료 | 전용 축하 UI | **없다** — 같은 목록이 전부 `CLEAR` 로 선다 |
| 정렬 | 추적 목록 순서 | **남은 개수 많은 순 → 동수면 캐릭터 관리 순서** |
| 크기 | 2x2·4x2·4x3·4x4 | **`4×auto` 하나** |

- **「검마」는 종류가 하나라서 종류 이름 대신 고유명이 선다.** `weekly-bosses.json` 의 `monthly` 가
  검은마법사 한 항목이므로 «월간 보스 1» 은 «검마 1» 과 같은 말이고 더 짧다. 월간 보스가 둘이 되면
  이 이름이 거짓이 된다 — 참조 데이터에서 파생하지 말고 **그때 다시 정한다**(자동 복수화는 [[ADR-006]]
  태도상 앱이 지어낼 값이 아니다).
- **전부 완료에 축하 UI 를 두지 않는 것이 결정 5와 같은 근거다** — 형태가 안 바뀌어야 «어제와 같은
  화면» 으로 읽힌다. rev 1 시안의 단풍잎 축하 카드는 그 자리에서 격자의 리듬을 깼다.
- **동기화 실패 캐릭터는 남은 개수를 «모른다»** 이므로 정렬에서 0으로 취급해 아래로 간다(열린 질문).

### 정정 4. 주간 보스 수익 — 증감 삭제 · **0을 그린다** · 단위 표기

- **증감 칩을 뺀다.** `rise`/`fall` 토큰과 `previousPeriodTotalMeso` 를 이 화면에서 쓰지 않는다
  ([[ADR-087]] 은 보스 수익 화면에 그대로 산다 — 여기서만 안 쓰는 것이다).
- **기록이 없으면 `0 메소` 로 그린다**(사용자 지시). **결정 5의 «큰 0 을 그리지 않는다» 를 이
  위젯에서 뒤집는 것**이고, 그 결정이 지키려던 것(«없다» 와 «모른다» 를 가른다)은 **옆에 한 줄**로
  남긴다(*아직 이번 주 기록이 없습니다*). 완전히 같은 그림이 되지는 않되 숫자 자리는 0 이다.
  다른 위젯의 빈 상태 규칙은 그대로다.
- **큰 금액 뒤에 `메소`.** 목록 행(top3)에는 안 붙인다 — 머리가 이미 단위를 말했다.

### 정정 5. 최고가 아이템 — top 5 · 이름 한 줄 · 미입력 분리

- 2x2 의 아이템 이름은 **한 줄**(말줄임). 두 줄로 접으면 행 높이가 데이터에 따라 흔들린다.
- 4x2 의 오른쪽은 «그 다음» 둘 → **`top 5`**(2·3·4·5위).
- **«가격 미입력 N건» 칩을 이 타일에서 뺀다** — 그것은 위젯 7의 몫이다. 결정 9가 *"그 답을 옆
  타일이 들고 있어야 한다"* 라고 적었는데, **옆 타일이 들고 있으면 이 타일이 또 들 이유가 없다.**
- 0건 문구는 **«가격이 입력된 아이템이 없습니다»** 한 줄뿐. rev 1의 *"N건이 값을 기다립니다"* 는
  건수를 두 곳에서 말하는 것이라 뺀다.

### 정정 6. 아이템 드롭 가뭄 — **문구가 단계마다 풀이 된다**

지금 `VALUABLE_DROUGHT_TIERS` 는 0~3주가 한 줄 고정이고 마지막 단계만 풀이다. **전 단계를 풀로**
바꾼다(사용자 지시 — *"최근 한국 인터넷 밈을 활용해서 좀 다양하게"*).

```ts
// headline: string  →  headlines: readonly string[]
formatValuableDroughtHeadline(weeksSince, lateIndex)  →  (weeksSince, index)
```

무작위 인덱스는 지금 규칙 그대로 **화면이 마운트당 한 번** 고른다(그 파일이 적어 둔 이유 — 매 렌더마다
고르면 리렌더 때 문구가 깜빡인다).

- **기존 다섯 줄은 지우지 않고 풀에 남긴다.** `drop-history.ts` 주석이 «앞 둘은 사용자 지정» 이라고
  못 박아 뒀다 — 사용자가 고른 문구를 «더 나은 밈» 으로 갈아 치우는 것은 이 정정의 범위가 아니다.
- 2x2 는 잎을 44 → 54 로 키우고 «마지막 기간» 줄을 빼 **세 덩어리를 가운데 한 뭉치로** 모은다.
- **밈은 유통기한이 있다.** 실제 문자열 확정은 사용자 몫이고, 전부 `lib/drop-history.ts` 배열 하나에
  모여 있어 교체 비용이 0이다 — 이 ADR 은 **구조**(단계별 풀)만 정한다.

### 정정 7. 대표 캐릭터 카드는 **월드 엠블럼 + 세 줄**이다 (2차 피드백)

| 자리 | 전 | 후 |
|---|---|---|
| 월드 | 이름 옆 **텍스트 배지** | **닉네임 앞 엠블럼 이미지**(`lib/world-emblem.ts` 의 `worldEmblemUrl`) |
| 줄 구성 | 이름+월드 / `Lv.` + 길드 | **① 이름 ② `Lv. N` + 직업 ③ 길드** |
| 적용 범위 | — | **4x2 · 4x1 · 2x2 셋 모두 같은 구조** |

- **엠블럼은 이미 있다** — `world-emblems.json`(월드명 → basename) + `assets/worlds/*.png` 18종.
  매핑에 없거나 파일이 없으면 `null` 이고 그때는 **엠블럼만 생략**한다(그 함수가 이미 정한 폴백).
- **직업(`jobClass`)이 카드에 처음 선다.** [[ADR-144]] 결정 2가 캐릭터 카드 2줄에 «레벨 + 직업» 을
  올려 둔 것과 **같은 조합**이라 새 규칙이 아니다. 그 값은 `character/basic` 이 아니라 `character/list`
  에서 오므로 **옛 캐시 엔트리에는 없고**, 없으면 그 줄이 레벨만 그린다(그 타입이 이미 정한 규칙).
- **`4x1`(76px)에 세 줄이 들어간다** — 13 / 10.5 / 10px, 행간 1.2~1.25. 초상화 44 ≤ 52(내부 높이).
- **2x2 에서 직업이 잘린다.** 「아크메이지(불,독)」이 158폭의 한계다(열린 질문).

### 정정 8. 대표 캐릭터의 **«EXP 없음» 상태도 없다** (사용자 판정)

정정 2가 «대표 없음» 을 없앤 것과 같은 판정이다. `expRate` 는 타입에서 옵셔널로 두되(옛 캐시
엔트리에 그 필드가 없는 것은 사실이다) **화면이 그 상태를 설계하지 않는다** — 값이 없으면 그 줄을
안 그리는 방어적 기본값만 남고, 시안에서 그 변형을 뺀다.

### 정정 9. 남은 스케줄의 수치는 **배지가 아니라 텍스트**다 (2차 피드백)

정정 3이 «배지를 닉네임 오른쪽에» 로 정했는데, **알약 자체를 없앤다.**

```
야간비행                    일퀘 4 · 주간퀘 1
                       주간 보스 1 · 검마 1
```

- **두 줄로 가른다** — ① 일퀘 · 주간퀘 ② 주간 보스 · 검마. 컨텐츠와 보스가 다른 축이라 줄로 가른다.
- **강조는 굵기 하나뿐이다**(사용자 지시) — 숫자는 **크기도 색도 라벨과 같고** `font-weight` 만
  400 → 800 이다. **테마 색을 쓰지 않는다**: 앞선 시안이 숫자를 `primary-ink` 로 칠했는데, 그러면
  이 타일 하나에 강조색이 캐릭터 수만큼 반복돼 격자에서 «여기가 제일 중요하다» 를 잘못 말한다.
- **배지는 특수 케이스만 진다** — `CLEAR` 와 「동기화 실패」. 둘은 수치가 아니라 **상태**라 다른
  형태를 가질 근거가 있다. 헤더의 합계도 칩 → 텍스트다.
- **둘째 줄이 비어도 자리를 남긴다.** 보스가 0인 캐릭터는 둘째 줄이 비는데, 그때 행을 줄이면 **행
  높이가 데이터마다 달라져** 정정 1의 auto 높이 계산(`50 + 48n`)이 성립하지 않는다.

### 정정 10. 아이템 드롭 가뭄 문구 — **채택안 확정** (사용자 선택 2026-08-17)

정정 6이 연 구조(단계별 풀)에 실제 문자열이 들어왔다. **기존 다섯 줄은 전부 남고**, 제안 중 여섯이
채택됐다.

| 단계 | 기존(유지) | 채택(추가) |
|---|---|---|
| 0주 | 와따리! ㅇㄱㄱㄷ | **완전 럭키비키잖아** · **폼 미쳤다** |
| 1주 | 그래, 그럴 수 있지 | **다음 주엔 되겠지** |
| 2주 | 어?! 슬슬 쫌 그래!? | **슬슬 킹받는데** · **이게 맞나?** |
| 3주 | 선넘네?! | **이게 억까지 뭐야** |
| 4주+ | 다섯 줄 그대로 | — (채택 없음) |

제안 여덟이 떨어졌다(오늘 운 다 씀 · 이게 되네? · 중꺾마 · 아직 실망하긴 이르다 · 이왜진 ·
확률 좀 봐주세요 · 누가 내 드랍률 훔쳐감 + 4주+ 제안 여섯).

**1주와 3주는 풀이 둘뿐이라 «무작위» 가 얕다** — 두 문구가 번갈아 나오는 것처럼 보인다(열린 질문).

### 정정 11. 「메소」는 최고가 아이템에도 붙인다 — **1x1 만 예외** (사용자 확정)

정정 4의 열린 질문이 닫혔다. 두 타일이 나란히 서서 한쪽만 단위가 있으면 버그로 보인다.
**1x1(73×76)은 붙이지 않는다** — 물리적으로 안 들어간다. 2x2 는 아이콘을 48 → 40 으로 줄여
`12.0억 메소` 를 한 줄에 넣는다.

### 정정 12. 남은 스케줄은 **정렬 격자**다 — 「안 A」 채택 (3차 피드백)

정정 9가 «텍스트 두 줄» 로 바꿔 놓고 보니 **숫자가 어디에도 정렬되지 않았다.** 라벨 길이가 제각각
(「일퀘」 2자 · 「주간 보스」 4자)이라 `일퀘 4 · 주간퀘 1` 이 행마다 다른 x 에서 끝나고, 그래서
«어느 캐릭터가 제일 밀렸나» 를 세로로 훑을 수가 없었다. **텍스트로 바꾸면 정렬이 그만큼 더 중요해진다.**

- **라벨 폭을 고정하고 `tabular-nums` 를 건다** → 모든 행의 숫자가 같은 x 에 선다. 2×2 격자
  (col A = 일퀘/주간 보스, col B = 주간퀘/검마).
- **`·` 구분자를 없앤다** — 열이 생기면 구분자가 할 일이 없다.
- **행 사이에 헤어라인**(`border`), 헤더 아래에 `border-strong` 한 줄. 한 행이 두 줄이라 구분이
  없으면 서로 뭉친다.
- **빈 칸은 격자 자리로 남는다**(`grid-auto-rows` 고정) — 정정 9의 «둘째 줄이 비어도 자리를 남긴다» 가
  이제 CSS 한 줄로 성립하고, 행 높이가 데이터에 안 흔들린다.
- **실측이 바뀐다**: `50 + 48n` → **`55 + 45n`** px (2명 145 · 4명 236 · 6명 326).
- **색은 «읽기 2» 로 확정**(사용자 2026-08-17) — 정정 9가 남긴 «같은 색» 의 두 읽기 중,
  **라벨은 `text-muted`, 숫자는 닉네임과 같은 `text`** 다. 「크기·색은 다른 텍스트와 같게」의
  «다른 텍스트» 를 **닉네임**으로 읽은 것이고, 굵기와 명도가 함께 일해 실제로 읽힌다. 라벨까지
  `text-muted` 로 내린 판(읽기 1)은 흐린 글자 위의 굵은 글자라 강조가 약해 기각됐다.
  **여전히 테마 색은 쓰지 않는다** — 그 규칙은 그대로다.
- **동기화 실패 캐릭터는 언제나 맨 아래다**(사용자 확정). 남은 개수를 «모르는» 것이라 정렬에서 0으로
  취급한다 — 위로 올리면 «제일 밀린 캐릭터» 자리를 모르는 값이 거짓으로 차지한다.

**기각 — 「안 B」(라벨을 열 머리글로 올려 한 줄)**. 행에 숫자만 남아 가장 잘 훑히고 6명에서 22px 낮았다.
버린 이유는 **«컨텐츠 / 보스» 라는 묶음이 사라지기 때문**이다 — 두 줄로 가른 것이 공간 문제만은
아니었다(사용자 판정). 22px 이 그 묶음을 잃을 값은 아니다.

### 정정 13. **기본 배치 교체** (사용자 확정 2026-08-17)

```
(0,0)  4x1     대표 캐릭터
(0,1)  2x1     초기화 카운트다운      (2,1) 2x1  주간 결정석 판매 한도
(0,2)  4×auto  캐릭터별 남은 스케줄   ← 아래 전부가 이 타일의 초과분만큼 내려간다
(0,3)  4x3     주간 보스 수익
(0,6)  2x1     이번 주 최고가 아이템  (2,6) 2x1  가격 미입력
(0,7)  4x1     아이템 드롭 가뭄
```

**기본 크기가 여섯 개 바뀐다** — 대표 캐릭터 4x2 → **4x1**, 주간 보스 수익 4x2 → **4x3**,
최고가 아이템 2x2 → **2x1**, 결정석 한도 2x2 → **2x1**, 아이템 드롭 가뭄은 4x1 유지, 초기화는 2x1 유지.

- **총 높이 1010 → 852px**(캐릭터 4명 기준). 대표 카드가 4x2 → 4x1 로 내려온 몫이 가장 크다.
- **읽는 순서가 바뀌었다** — 정체(대표) 다음이 **마감·상한**(초기화 · 결정석 한도)이고, 그 다음이
  할 일(남은 스케줄) → 결과(수익) → 결과의 디테일(최고가 · 미입력) → 정서(가뭄)다. 앞선 배치는
  «할 일» 이 둘째였다.
- **`row` 는 「남은 스케줄」의 nominal `h = 1`**(= 캐릭터 1명, 최소 높이) 기준으로 적는다. 그래서
  좌표가 `(0,3)` 에서 바로 이어지고, 렌더러가 실측 초과분만큼 아래를 민다(정정 1).
- **선언만 남고 아무도 안 쓰는 크기가 생긴다**(대표 4x2·2x2, 수익 4x2·2x2·2x1, 최고가 2x2·4x2·1x1 …).
  배치가 코드 상수인 v1 에서는 쓰이지 않는다. **남긴다**(사용자 확정) — 결정 2가 열어 둔 «나중에 편집이
  오면 배열만 저장소로 옮긴다» 가 성립하려면 그때 고를 크기가 이미 있어야 한다. 대가는 **아무도 안
  부르는 렌더 분기가 스냅샷으로만 검증된다**는 것이다.

### 정정 14. **「물욕」이라는 말을 쓰지 않는다 — 「아이템 드롭」** (사용자 지시)

위젯 이름이 「물욕 가뭄」 → **「아이템 드롭 가뭄」**, 문구도 *«3주째 물욕템 없음»* →
*«3주째 아이템 드롭 없음»* 이다.

**기존 화면을 훑을 필요가 없다** — 실측 결과 **지금 앱의 사용자 노출 문구에 그 말이 한 번도 나오지
않는다**(`packages/core/src/lib/drop-history.ts` 주석 두 줄과 설계 문서에만 있다). 즉 이 규칙은
**today 가 새로 들이지 않으면 되는 것**이다.

- **영문 식별자는 안 바꾼다** — `valuable-drought` · `isValuableDrop` · `summarizeValuableDrought` ·
  `valuable-drops.json`. 규칙은 «화면에 보이는 한국어» 에 대한 것이고, 코어 API 이름을 함께 바꾸면
  [[ADR-038]]·[[ADR-071]] 이 건 계약이 이름만 다른 두 벌이 된다.
- **설계 문서의 「물욕 드랍」은 그대로 둔다**(`features/item-drop.md` 등) — 문서는 화면이 아니고,
  옛 결정을 소급해 고쳐 쓰지 않는 것이 이 저장소의 규칙이다.

### 정정 15. 결정석 링의 분자·분모를 붙인다

`.ring-txt` 가 분자와 분모를 두 줄로 그리는데 사이가 벌어져 **두 값으로 읽혔다**. `line-height: .92`
로 바싹 붙여 **분수**로 읽히게 한다. 값이 바뀐 것이 아니라 읽히는 단위가 바뀐 것이다.
