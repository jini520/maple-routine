# ADR-127 — 캐릭터가 0명인 메이플 ID 는 계정 목록에 아예 서지 않는다

> 🟡 **PARTIALLY SUPERSEDED — 일부 폐기.** 계정 «목록» 자체는 [[ADR-143]] 이 없앴다. 자격 판정 원칙만 남는다.
> 나머지 결정은 유효하다 — 인용 전 본문에서 해당 결정 번호를 확인할 것.

**날짜**: 2026-08-12
**상태**: 구현 완료(2026-08-12) · **실사용 검증 대기**(재현 조건을 가진 기기가 테스터 쪽에만 있다)
**관련**: [[ADR-051]](계정이 1개여도 선택 화면은 보여준다) · [[ADR-068]] 결정 4(전수 프로브 · 전원 조회 불가는
고르기 **전에** 알린다) · [[ADR-086]] 결정 8(고를 수 없는 계정은 잠근다) · [[ADR-113]] 결정 3·4(settle 뒤에
그린다 / settle 은 성공이 아니다) · [[ADR-116]] 결정 3(판정 못 한 계정은 목록에 세우지 않는다) ·
[[ADR-065]] 결정 5(전역 에러 바운더리) · [[ADR-117]](부팅 크래시에서 커버를 걷는 장치) ·
[../trouble/2026-08-12-onboarding-empty-account-crash.md](../trouble/2026-08-12-onboarding-empty-account-crash.md)

## 맥락

테스터 한 명이 API 키를 넣은 뒤 **「화면을 표시하지 못했습니다」에서 더 나아가지 못했다**(갤럭시 S21,
2026-08-12). 앱을 지우고 다시 깔아도 같은 자리에서 멈췄다.

원인은 계정 선택 목록의 렌더 한 줄이다.

```ts
// app/onboarding/AccountSelectionList.tsx
const representative = probe?.representative ?? pickRepresentativeCharacter(account.characters)
```

`pickRepresentativeCharacter` 는 **빈 배열을 받으면 던진다**(`representative-character.ts`). 그 폴백이
`account.characters` 가 비어 있는 경우를 막지 않는다. 사슬은 셋이다.

1. **`normalizeCharacterList` 가 `account_list` 를 그대로 1:1 매핑한다** — `character_list: []` 인 메이플 ID 가
   `characters: []` 로 들어온다.
2. **프로브가 그 계정을 정상으로 판정한다** — 확인된 캐릭터가 0명이라 `representative` 는 `null` 인데,
   `allUnavailable` 판정이 `account.characters.length > 0` 가드에 걸려 `queryable` 로 떨어진다
   (`use-account-probes.ts`). 즉 [[ADR-086]] 결정 8 의 잠금에도 걸리지 않는다.
3. **렌더 폴백이 던진다** — `null` 은 `??` 를 통과하고, 폴백 인자는 빈 배열이다.

**이 크래시는 영구적이다.** `submitApiKey` 는 목록을 그리기 전에 이미 키를 저장하므로, 재시작해도
`deriveResumeTarget` 이 `selectingAccount` 로 재개해 같은 목록을 다시 그린다([[ADR-086]] 결정 1). 앱 안에
탈출구가 없어 사용자가 할 수 있는 일은 앱을 지우는 것뿐이다 — 실제로 테스터가 그렇게 했다.

**한 문장으로: 고를 수 없는 계정을 목록에 세우려다 목록 자체를 그리지 못했다.**

## 결정

### 결정 1 — 걸러내는 자리는 `normalizeCharacterList` 다

`character_list` 가 빈 계정은 도메인 모델로 올라오지 않는다.

```ts
export function normalizeCharacterList(wire: NexonCharacterListResponse): MapleAccount[] {
  return wire.account_list
    .filter((account) => account.character_list.length > 0)
    .map(/* 종전과 같다 */)
}
```

**사슬의 가장 위 고리를 끊는 것이 요점이다.** 아래 두 고리에서 막으면 크래시는 사라지지만 *"캐릭터가
0명인 계정"* 이라는 상태는 그대로 남아, 그것을 아는 코드가 화면·프로브·정규화 세 곳으로 흩어진다.
위에서 접으면 **그 상태가 애초에 존재하지 않는다** — 아래 두 곳은 고칠 것이 없어진다.

기각한 대안 둘:

- **프로브가 0명을 `allUnavailable` 로 판정한다** — [[ADR-068]] 결정 4 의 선례(*"전원 조회 불가는 고른 뒤가
  아니라 고르기 전에 알린다"*)를 따르는 안이고 그래서 진지하게 검토했다. 기각한 이유는 **말할 내용이
  없어서**다. 그 카드가 서려면 대표 캐릭터가 있어야 하는데(월드·이름·레벨·초상화가 카드의 전부다) 0명
  계정에는 하나도 없다 — 조회에 **실패한** 계정과 달리 여기엔 *"조회할 수 없습니다"* 라고 말할 대상조차
  없다. 결정 4 가 카드를 남긴 것은 **보여줄 캐릭터는 있는데 못 쓰는** 경우였다.
- **렌더 폴백만 안전하게 한다** — 크래시는 막지만 대표 자리가 빈 카드가 목록에 남는다. 원인이 아니라
  증상을 막는 것이라 [[ADR-113]] 결정 3 이 없앤 *"고를 수 없는 카드를 보여준다"* 가 되살아난다.

### 결정 2 — 이 판단을 정규화가 하는 것은 층 위반이 아니다

`normalizeCharacterList` 는 와이어→도메인 매퍼이고, 매퍼가 데이터를 버리는 것은 보통 냄새다. 여기서
성립하는 근거는 **`MapleAccount` 의 뜻이 "응답에 있던 계정"이 아니라 "고를 수 있는 계정"** 이기 때문이다 —
`account.characters` 를 소비하는 네 자리(온보딩 스토어 · 설정 계정 변경 · 프로브 · 피커 로스터)가 전부
캐릭터가 있다는 전제로 쓰고 있고, 그 전제가 깨진 것이 이번 크래시다. 전제를 타입 경계에서 지킨다.

### 결정 3 — 전 계정이 0명이면 빈 목록이 된다(지금은 그대로 둔다)

계정이 하나뿐이고 그 계정에 캐릭터가 없으면 `accounts` 가 `[]` 가 되어, 목록에 *"사용할 메이플 ID를
선택해주세요"* 와 비활성 `계속하기` 만 남는다 — 설명도 출구도 없다.

**이 상태는 이 결정이 만든 것이 아니다.** `account_list: []` 응답이면 종전에도 같은 화면이었다. 이 결정이
바꾸는 것은 **도달 경로가 하나 늘어나는 것**뿐이라, 여기서 함께 고치지 않고 열린 질문으로 넘긴다
([features/app-entry.md](../features/app-entry.md)) — 빈 상태 문구·출구를 정하는 것은 크래시를 막는 것과
다른 결정이고, 지금 고칠 것은 **벽돌이 된 사용자**다.

## 대가

- **선택한 계정의 캐릭터가 나중에 전부 삭제되면 오류 문구가 달라진다.** `resolveRegisteredCharacters`
  (`features/schedule-sync/character-roster.ts`)는 `accounts.find(...)` 로 선택 계정을 찾는데, 그 계정이
  이제 목록에서 빠져 **`'선택된 계정을 찾을 수 없습니다'` 로 던진다** — 전에는 빈 로스터를 돌려줘 피커가
  *"표시할 캐릭터가 없어요"* 를 그렸다. 고를 때는 캐릭터가 있었으므로 이 경로는 **고른 뒤 전부 삭제**한
  경우에만 열리고, 출구(설정의 계정 변경)는 양쪽 다 같다. 관측된 적이 없어 지금은 문구 차이만 감수한다.
- **넥슨이 `character_list: []` 를 어떤 조건에서 내는지 모른다.** 응답을 직접 받아 본 적이 없어, 이 결정은
  *"올 수 있다"* 를 전제로 방어하는 것이지 그 조건을 안다고 말하지 않는다
  ([foundation/nexon-api.md](../foundation/nexon-api.md)에 사실만 적는다).

## 함께 드러난 것 — 배포 중인 APK 가 복구 장치를 갖고 있지 않다

같은 크래시가 테스터에게 **두 가지 화면**으로 보였다(에러 폴백 / 브랜드 주황에 갇힘). 갈린 것은 크래시가
`MIN_SPLASH_MS`(1초)를 이겼는가다 — 이기면 [[ADR-065]] 결정 5 의 폴백이 `#boot-cover` **밑에** 깔린다.
[[ADR-117]] 결정 3·6 이 정확히 이것을 고쳤지만, **배포 중인 APK 는 그 수정 이전 빌드다**(versionCode 19,
2026-08-04 — 이후 1.0.1~1.0.4 는 전부 OTA 였다). 새로 설치하는 사용자는 복구 장치가 없는 내장 번들에서
시작한다. **이건 OTA 로 못 고친다** — 네이티브 재빌드가 필요하고, 이 ADR 의 범위 밖으로 남긴다.
