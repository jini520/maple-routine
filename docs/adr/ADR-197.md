# ADR-197: 써드파티 컴포넌트의 `className` 등록은 `lib/nativewind-interop` 한 곳에서 한다

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-09-01
**관련**: [[ADR-128]](RN 전환 · NativeWind) · [[ADR-066]](커스텀 SVG 는 lucide 규격을 지킨다)

## 맥락

NativeWind 가 자동으로 가로채는 것은 `react-native` 의 기본 컴포넌트(`View`·`Text`·`Pressable`)
뿐이다. 그 밖의 컴포넌트에 `className` 을 주면 스타일이 안 붙고 모르는 프롭으로 흘러간다.
실측으로 `<Svg className="text-primary h-5 w-5" />` 의 렌더 트리에 `className` 문자열이 그대로
남아 있었다. 색도 크기도 없었다.

**문제는 그때 에러도 경고도 안 난다는 것이다.** 등록을 빼먹으면 클래스는 썼는데 색과 크기만 없는
상태가 조용히 생긴다. 테마 변수를 못 찾을 때와 같은 실패 모양이라, 화면을 눈으로 보기 전에는
아무도 모른다.

`cssInterop()` 의 성질이 이 문제를 키운다. 그것은 감싼 컴포넌트를 돌려주는 대신 **그 컴포넌트를
등록**한다(실측으로, 등록만 하고 원본을 그대로 렌더해도 클래스가 풀렸다). 등록이 모듈의 부수 효과이므로
**어느 모듈을 거쳐 import 했느냐가 결과를 가른다.**

## 결정

### 결정 1. 등록은 `src/lib/nativewind-interop.ts` 한 파일에서만 한다

등록을 여러 파일에 두면 레지스트리가 갈린다. 그러면 같은 컴포넌트가 import 경로에 따라 클래스가
풀리기도 안 풀리기도 하고, 안 풀려도 에러가 없다. 그래서 그 파일이 원본을 그대로 다시 내보내고,
쓰는 쪽은 거기서만 가져온다.

| 가져올 것 | 원본 | 쓰는 자리 |
|---|---|---|
| `Svg` | `react-native-svg` | SVG 를 그리는 컴포넌트 |
| `LinearGradient` | `expo-linear-gradient` | 그라디언트 배경 |
| `AnimatedView` | `react-native-reanimated` 의 `Animated.View` | 애니메이션이 붙는 상자 |
| `withIconInterop` | 이 파일의 함수 | `lib/icons.ts` 가 아이콘마다 부른다 |

`cssInterop()` 의 반환값을 쓰지 않는 이유는 타입이다. 반환값을 쓰면 `SvgProps` ·
`LinearGradientProps` · `LucideIcon` 이 날아간다.

자식 도형(`Path`·`Circle`·`Defs` 등)은 `className` 을 안 받으므로 `react-native-svg` 에서 직접
가져와도 된다. 등록이 필요한 것은 뿌리인 `Svg` 뿐이다.

### 결정 2. `Svg` 는 색과 크기를 프롭으로 옮긴다

매핑은 `nativeStyleToProp: { width, height, color }` 다.

아이콘과 스피너는 자식 도형을 `stroke="currentColor"` 로 그리고, 색은 호출부가
`className="text-primary"` 로 정한다([[ADR-066]] 이 커스텀 SVG 에 같은 규격을 건다).
`react-native-svg` 에도 `currentColor` 가 있지만 **그 값의 출처는 CSS 상속이 아니라 `Svg` 의
`color` 프롭**이다. 그 둘을 잇는 것이 이 매핑이다.

`width`·`height` 도 같이 옮긴다. `h-5 w-5` 가 SVG 상자 크기가 되고, 호출부 클래스가 `size` 프롭으로
준 기본 크기를 덮는다.

`LinearGradient` 는 크기·여백·모서리를 전부 `style` 로 받으므로 옮길 프롭이 없다. 매핑이 `'style'`
하나인 것은 그래서다.

### 결정 3. 애니메이션이 붙는 상자는 `AnimatedView` 다

Reanimated 의 CSS 애니메이션(`animationName`·`transitionProperty`)은 애니메이션 컴포넌트에만 붙는다.
`createAnimatedComponent` 가 감싸면서 프롭 레지스트리를 달아 주고, UI 스레드가 그 레지스트리를 통해
스타일을 직접 갱신하기 때문이다. 평범한 `View` 에 같은 스타일 키를 주면 RN 이 모르는 키라 조용히
버린다.

매핑은 `'style'` 하나다. 클래스가 만든 스타일과 애니메이션 스타일이 같은 `style` 객체로 합쳐지므로,
`opacity-0`·`opacity-100` 같은 클래스 변화가 그대로 `transitionProperty: 'opacity'` 의 대상이 된다.

### 결정 4. lucide 아이콘은 `lib/icons.ts` 를 거친다

`lucide-react-native` 는 색과 크기를 `color`·`size` 프롭으로 받고 `className` 은 그대로 안쪽 `Svg` 로
흘려보낸다. 그 `Svg` 는 결정 1 로 등록돼 있지만 **그 자리에서는 안 풀린다.** NativeWind 는 JSX 호출
시점에 컴포넌트가 등록됐는지 보는데, 그 `createElement` 가 우리 코드가 아니라 라이브러리 안에 있기
때문이다. 그래서 아이콘 컴포넌트 자체를 등록한다(`withIconInterop`).

매핑이 셋인 것은 lucide 의 프롭 이름과 짝을 맞추기 위해서다.

| 클래스 | 가는 길 |
|---|---|
| `text-*` | `style.color` → `color` 프롭 → `stroke`(아이콘 본체와 자식 도형 모두) |
| `h-*`·`w-*` | `style.height`·`style.width` → `Svg` 의 상자. lucide 가 `size` 로 계산한 값 **뒤에** 나머지 프롭을 펼치므로 클래스가 이긴다 |
| 그 밖(`shrink-0` 등) | `target: 'style'` 로 `style` 프롭에 남아 lucide 의 `...rest` 를 타고 `Svg` 에 닿는다. `target: false` 로 두면 조용히 사라진다(실측) |

**`testID` 는 통하지 않는다.** lucide 의 `Icon` 이 그것을 가로채 `data-testid` 로 바꿔 넘기므로 RNTL
의 `getByTestId` 로 못 찾는다. 아이콘을 테스트에서 지목해야 하면 감싸는 `View` 에 `testID` 를 준다.

`lib/icons.ts` 를 거치는 이유가 하나 더 있다. 배럴 import 는 아이콘 1,900개를 전부 그래프에 넣는데
Metro 는 트리셰이킹을 하지 않는다(전환 당시 실측으로 배럴 3,365 모듈 5.5MB 대 개별 1,626 모듈 3.7MB,
`docs/migration/README.md`). 그 파일이 아이콘별 경로로 가져오고 등록까지 한 자리에서 끝낸다.

## 검증

`src/lib/__tests__/nativewind-interop.test.tsx` 가 배선 자체를 못박는다. `Svg` 의 `text-*` 가 `color`
프롭이 되는 것, `h-5 w-5` 가 상자 크기가 되는 것, `LinearGradient` 의 `className` 이 style 로 풀리는
것 셋이다.

배선이 끊기면 SVG atom 셋(`MapleSpinner`·`MapleSweepSpinner`·`ProfitIcon`)이 크기도 색도 없이 그려진다.
에러가 안 나서 화면을 보기 전에는 모르므로, atom 별 테스트와 별개로 배선을 여기서 본다.

## 트레이드오프

**원본 모듈에서 직접 가져오는 것을 기계가 막지 않는다.** 지금은 이 규칙과 리뷰가 지킨다. 실패가
조용해서 린트 규칙으로 올릴 값이 있지만, 자식 도형은 직접 가져와도 되므로 모듈이 아니라 이름 단위로
걸러야 한다.
