# ADR-279: 앱이 보이는 버전은 도는 번들이 말한다. 스토어 버전과 OTA 버전은 따로 올린다

> 🟢 유효 · 2026-09-14 · **구현 완료**(2026-09-14) · 실기기 미검증 · 사용자 결정
>
> 코드 자리: `native/adapters/rn-live-update.ts` 의 `getCurrentVersion` 이 값을 정하고, 화면은
> `features/live-update/use-running-app-version.ts` 의 `useRunningAppVersion` 으로 읽는다.

**관련**: [[ADR-137]] 결정 5(우리 축의 버전은 매니페스트 `extra.appVersion` 이다. 그대로다)
**문서**: `features/live-update.md` · `foundation/release.md`

## 맥락

스토어에서 1.0.8 을 받은 아이폰의 설정이 `v1.0.7` 을 보였다(사용자 보고 2026-09-14).

버전을 보이는 자리는 넷이다. 더보기 화면 아래쪽 `v1.0.7`(`SettingsScreen`) · 앱 설정의 `앱 정보` 줄
(`AppSettingsScreen`) · `앱 정보` 화면의 `현재 버전`(`AppUpdateSection`) · 개발 노트의 `사용 중` 표식
(`SettingsReleaseNotesScreen`). 앞의 셋 중 `앱 정보` 화면만 번들에게 물었고 나머지 셋은 `package.json` 을
직접 읽었다.

`앱 정보` 화면의 `현재 버전` 은 `rn-live-update.ts` 의 `getCurrentVersion` 이 정한다. 규칙은 **매니페스트
`extra.appVersion`, 없으면 `package.json` 의 `version`** 이었다.

| 도는 번들 | 매니페스트 `extra` | 보인 값 |
|---|---|---|
| OTA 번들 | `publish-rn-ota.mjs` 가 `package.json` 버전을 싣는다 | 맞다 |
| 스토어 바이너리의 내장 번들 | **없다**(빌드가 만드는 `EXUpdates.bundle/app.manifest` 는 `assets` · `commitTime` · `id` 뿐) | `package.json` 버전 |

1.0.8 스토어 릴리스는 `app.json` 의 `expo.version` 만 1.0.8 로 올렸고 `package.json` 은 1.0.7 에
남았다. 바이너리는 1.0.8 인데 내장 번들이 `package.json` 을 읽어 1.0.7 로 보였다.

**화면이 스토어 바이너리의 버전을 `package.json` 에서 읽는다**는 것이 결함이다. `package.json` 은 OTA
매니페스트의 `appVersion` 이 되는 값이라 스토어 바이너리의 버전과 같다는 보장이 없다.

## 결정

### 결정 1. OTA 번들로 돌 때는 매니페스트의 `extra.appVersion` 을 보인다

지금 그대로다. OTA 는 바이너리를 안 바꾸므로 바이너리 버전으로는 OTA 버전을 말할 수 없다.

### 결정 2. 내장 번들로 돌 때는 바이너리에 박힌 버전을 보인다

`expo-constants` 의 `Constants.expoConfig.version` 이다. 빌드가 그때의 `app.json` 을
`EXConstants.bundle/app.config`(안드로이드는 `assets/app.config`)로 굽는다. 1.0.8 스토어 바이너리
안의 값이 `1.0.8` 인 것을 확인했다(2026-09-14, 로컬 Release 빌드 산출물).

**새 네이티브 의존이 아니다.** `expo-constants` 는 `expo` 가 끌어와 이미 바이너리에 들어 있다.
그래서 이 수정은 OTA 로 나갈 수 있다.

`package.json` 버전은 둘 다 못 읽을 때(개발 서버 등)의 마지막 폴백으로만 남는다.

### 결정 3. 버전을 보이는 네 자리가 모두 도는 번들에게 묻는다

세 화면은 `useRunningAppVersion` 을 쓴다. 값은 부팅 때 `checkOnBoot` 가 채운 `useLiveUpdateStore` 의
`currentVersion` 이고(결정 1 · 2 의 규칙), 라이브 업데이트 런타임이 없어 비었으면 `package.json` 이다.
`앱 정보` 화면은 전부터 같은 값을 읽었다.

### 결정 4. 스토어 버전과 OTA 버전은 따로 올리고 둘의 관계를 검사하지 않는다

**OTA 로 발행한 버전은 스토어와 관계가 없어야 한다**(사용자 결정 2026-09-14). 스토어 릴리스는 `app.json` 의
`expo.version` 을, OTA 발행은 `package.json` 의 `version` 을 올린다. `publish-rn-ota.mjs` 가 둘이
같아야 발행하던 검사를 뺀다.

그 검사가 있으면 OTA 버전을 올리려고 `app.json` 도 올려야 했고, `app.json` 은 두 플랫폼 공통 지문 재료라
지문이 바뀌어 스토어 바이너리가 OTA 를 못 받았다. `package.json` 의 `version` 은 **지문 재료가 아니다**
(1.0.7 → 1.0.8 로 바꿔 iOS · 안드로이드 지문이 그대로인 것을 확인, 2026-09-14). 검사가 필요했던 이유는
화면이 스토어 바이너리의 버전을 `package.json` 에서 읽었기 때문이고, 결정 2 · 3 이 그 이유를 없앤다.

관계 검사는 두지 않는다(사용자 결정). **OTA 버전이 스토어 버전보다 낮으면** 버전 번호를 비교하는 판정
(`consumeJustUpdated` 의 `업데이트를 마쳤어요` 등)이 어긋날 수 있고, 이 결정은 그 위험을 받아들인다.

## 대가

- **이미 스토어에 나간 1.0.8 바이너리는 다음 OTA 를 받기 전까지 1.0.7 로 보인다.** 그 바이너리의 내장
  번들이 옛 규칙을 들고 있다. 이 수정이 담긴 OTA 를 받으면 매니페스트 버전이 보인다.
- **`expo-constants` 를 `package.json` 에 직접 적지 않고 `expo` 가 끌어온 것을 쓴다.** 코드가 직접
  import 하는 모듈을 의존성에 적는 관례와 다르다. 적으려고 `npm install expo-constants@~57.0.10` 을
  돌리면 npm 이 범위 안 최신인 57.0.18 로 올려 네이티브 코드가 바뀌고 **iOS · 안드로이드 지문이 둘 다
  바뀐다**(2026-09-14 실측). 스토어 바이너리와 OTA 매칭이 끊긴다. 설치된 57.0.10 을 그대로 두는 것은
  `expo` 의 의존 범위가 정한다. 다음 스토어 바이너리를 구울 때 직접 의존으로 옮긴다.
