# ADR-105 — 검은마법사 테마 재조정: 갈색 제거 · 포인트를 골드로 · 배경 대칭축 보정

**날짜**: 2026-08-06
**상태**: 구현 완료 (색 확정은 사용자 눈 확인 대기)
**관련**: [[ADR-089]](이 테마의 원 결정 — 일부 폐기) · [[ADR-064]](38토큰·파생 규칙·중립 램프) · [[ADR-088]](배경 이미지·틴트 오버라이드 선례) · [[ADR-006]](색 값은 사용자 확인)

## 맥락

[[ADR-089]] 로 넣은 검은마법사 테마를 실제로 쓰면서 사용자가 세 가지를 지적했다.

1. **갈색이 너무 두드러진다** — 보더·비활성 텍스트가 `#654F51`·`#826F71`·`#B69DA0` 처럼 흙빛으로 읽힌다.
2. **포인트 컬러를 연보라 대신 골드로** 바꾼다.
3. **배경 이미지가 오른쪽으로 치우쳐 보인다.**

셋 다 값 문제이고, 셋 다 **왜 그렇게 됐는지가 규칙에 적혀 있다**. 그래서 이 문서는 값을 나열하는
대신 각 증상이 어느 규칙에서 나왔는지와, 규칙을 고칠 자리인지 이 테마만 덮을 자리인지를 남긴다.

## 결정

### 1. 중립 램프의 휴를 이 테마만 `primary` 에서 떼어낸다 (H 10.6 → **340**)

갈색은 값 실수가 아니라 **파생 규칙의 정상 출력**이다. `NEUTRAL_RAMP`([[ADR-064]] 결정 9)은
배경·보더·텍스트를 무채색이 아니라 **`primary` 색상 쪽으로 기울여** 테마 고유 톤을 만든다. 검은마법사의
`primary` 는 카민 `#E0245E`(OKLCH 휴 **10.6**)이고, 휴 10 을 채도 0.02~0.03 까지 낮추면 나오는 색이
정확히 **갈색·토프**다. 붉은 시드를 쓰는 테마는 중립까지 흙빛이 되는 구조다.

두 갈래가 있었다.

| 처방 | 결과 | 판단 |
|---|---|---|
| 중립 **채도**를 낮춘다(×0.35) | `#3F3939`·`#5B5354`·`#ABA2A3` — 갈색은 사라지나 거의 무채색 | 램프가 색조를 주는 **존재 이유**가 사라진다 |
| 중립 **휴**를 옮긴다(340) | `#44363F`·`#614F5B`·`#B29EAB` — 자두빛 차콜 | 채택 |

**휴 340 은 그림에서 왔다.** `blackmage-throne.webp` 의 픽셀을 채도 가중으로 재면 지배 대역이
휴 0~20(52%)과 **330~360(43%)** 둘로 갈리고, 어두운 픽셀(L<0.35)만 보면 평균 휴 359 · 채도 0.052 다.
붉은 쪽은 이미 `primary` 가 맡고 있으니 중립은 남은 자주 대역에서 잡는다 — 아트에서 벗어나지 않으면서
`primary` 카민과도 색이 겹치지 않는다. 골드 포인트(결정 2)와의 거리도 이쪽이 가장 멀다.

**규칙은 안 바꾼다.** `NEUTRAL_RAMP` 이 `primary` 휴를 쓰는 것은 대부분의 테마에서 맞고, 바꾸면
기존 5테마 값이 전부 움직인다. `theme-derive` 에 중립 휴 인자를 새로 뚫지도 않았다 — 지금 필요한 건
**한 테마의 중립 11토큰 override** 하나이고, 그건 [[ADR-064]] 가 이미 가진 `overrides` 로 된다.
같은 요구가 다른 테마에서 또 나오면 그때 시드에 `neutralHue` 를 붙인다.

덮는 토큰은 램프를 쓰는 것 전부다 — `bg`·`surface`·`surface2`·`border`·`borderStrong`·`text`·
`textMuted`·`textDisabled`·`media*` 4개·`scrim`·`shadowColor`. **명도·채도 상수는 램프 값 그대로**
쓰고 휴만 바꿨다(`tone(340, NEUTRAL_RAMP.dark.border)` 식). 톤 계단은 다른 테마와 같은 자리에 남는다.

`track`·틴트류(`primaryTint`·`errorTint`·`infoTint`·`riseTint`·`fallTint`)는 표면에서 파생되므로
따라 움직인다. 손으로 덮지 않는다.

### 2. `secondary` 초월체 라벤더 `#A9A2E8` → 불티 골드 `#E7B758` ([[ADR-089]] 결정 1 일부 폐기)

사용자 결정이다. 값은 **[[ADR-089]] 가 이미 샘플링해 표에 적어 둔 색**을 쓴다 — 일러스트의 불티
`#E7B758`(OKLCH 휴 82). 새로 추정한 색이 아니라 그 문서의 레퍼런스 표에 있던 값이고, 탈락 시안 B
("순정 진홍 + 엠버 금")가 후보로 들고 있던 방향이기도 하다([[ADR-006]]).

고정 휴와의 충돌은 없다 — 골드 휴 82 는 `error`/`rise`(26~27)·`fall`(262)에서 멀다. `secondary` 의
자리가 완료 배지·성공 톤이라 붉은 계열이 오면 안 된다는 [[ADR-089]] 결정 1 의 제약도 그대로 지킨다.
바뀐 것은 "차가운 대비(라벤더)"가 아니라 "따뜻한 대비(골드)"라는 점뿐이고, 자주빛 중립(결정 1) 위에서
보색에 가까운 거리(휴 차 **105°**)를 번다.

**딸려 오는 값 둘.**

- **`onSecondary` 가 아이보리에서 짙은 브론즈 `#573D00` 로 넘어간다.** [[ADR-064]] 결정 1 의 규칙
  그대로다 — 연한 전경(아이보리 `#FFEDEE`)이 밝은 금(L 0.805) 위에서 **가시성 하한 2:1 아래로 사라져**
  짙은 전경으로 넘어가는 경우다. 규칙을 덮지 않았다. 대비는 오히려 **2.06 → 5.46** 으로 올랐다
  ([[ADR-089]] 「받아들인 미달」 표의 첫 줄이 이 변경으로 사라진다).
- **`secondaryTint` 덮개는 유지하되 값이 바뀐다.** [[ADR-089]] 결정 2 와 **같은 실패가 색만 바꿔
  재발한다** — 자주 표면 `#1C1319`(휴 339)에 골드(휴 82) 15% 를 섞으면 `#362824`(휴 **37**, 골드에서
  46° 이탈)로, 두 색 사이 어디도 아닌 **흙색**이 나온다. 갈색을 걷어내는 작업에서 갈색을 다시 만드는
  꼴이다. 처방도 같다 — 골드 휴에서 직접 잡아 `#3B2B07`(L 0.30 · C 0.055 · 휴 이탈 **1°**)로 덮는다.

| | 채도 C | 휴 H | accent(H 82)에서 이탈 | `surface2` 와 휴차 |
|---|---|---|---|---|
| 규칙 파생 `#362824` | 0.022 | 37 | **46°** | 58° |
| 덮은 값 `#3B2B07` | 0.055 | 83 | **1°** | **105°** |

진단을 대비가 아니라 색조로 하는 이유는 [[ADR-089]] 결정 2 와 같다 — `#3B2B07` 과 `surface2`
(`#2E222A`)의 대비는 1.11:1 이라 수치로는 "안 보인다"고 읽히지만, 휴가 105° 벌어져 실제로는 확실히
갈린다. 대비비는 명도만 재므로 이 판단을 못 한다.

다크 테마의 카드 안 완료 배지는 `.media-scope` 에서 틴트가 아니라 **진한 채움**을 쓰므로
([[ADR-064]] 결정 5) 금색 채움 + 브론즈 글자가 된다.

### 3. 배경 `position: center` → **`52% center`**

그림이 오른쪽으로 치우쳐 보이는 이유는 **그림의 대칭축이 그림 한가운데가 아니기 때문**이다.
`blackmage-throne.webp`(800×323)의 좌우 대칭축을 미러 상관으로 재면 **x = 413**(51.6%)이다 — 왕좌·눈이
기하 중심에서 13px 오른쪽에 있다. `cover` 가 세로로 긴 뷰포트에서 이 그림을 2.6배로 확대해 가운데
150px 만 보여주므로, 13px 는 화면에서 **35px(390 폭의 9%)** 로 커진다. 눈으로 바로 잡히는 양이다.

| `position` | 390×844 에서 대칭축 어긋남 |
|---|---|
| `center` (현재) | **+35px** (오른쪽으로) |
| `51.5%` | +10px |
| **`52% center`** | **+1px** |
| `53%` | −16px |

퍼센트가 뷰포트 비율에 따라 흔들리지 않는지 확인했다 — 확대 배율이 커서 `52%` 는 폭 360~430 구간에서
±2px, 태블릿(768·834)에서도 화면 폭의 1.1% 안이다.

**그림을 다시 자르지 않았다.** [[ADR-088]] 결정 3 의 전제가 "그림을 고치는 게 아니라 값을 고친다"이고,
이 증상이 정확히 그 값(`position`)이 있는 이유다. 그림을 자르면 같은 에셋을 쓰는 헤더 조각
(`.theme-header-backdrop`)과 어긋날 위험도 생긴다.

## 남은 미달

[[ADR-064]] 판단 순서대로 색감이 먼저이고 대비는 참고다. 기준선 아래는 **7건에서 6건**으로 줄었다
(`onSecondary` 가 빠졌다). 나머지는 [[ADR-089]] 에서 이미 받아들인 것과 같은 항목이다.

| 항목 | 값 | 판단 |
|---|---|---|
| `onPrimary` / `primary` | 4.06:1 | 아이보리가 카민 위에서 읽힌다 (변동 없음) |
| `primaryInk` / `surface` | 3.96:1 | accent 원색 유지(가시성 하한 2:1 위) |
| `primaryInk` / `primaryTint` | 3.45:1 | 위와 같음 |
| `onThird` / `third` · `onError` / `error` · `errorInk` / `errorTint` | 2.78 / 3.35 / 4.11 | [[ADR-089]] 에서 이미 받아들인 항목 |

`text`·`textMuted` 는 `bg`·`surface` 양쪽에서 AA 위다(15.84 / 7.24 / 14.30 / 7.24).

## 결과

- `src/data/job-themes.json` 의 검은마법사 블록만 바뀐다. 제품 코드·파생 규칙·테스트 **변경 없음** —
  회귀는 `it.each(NAMES)` 라 새 값이 그대로 검사 대상이다([[ADR-064]] 결정 11).
- `buildThemeCss` 가 런타임에 JSON 을 읽어 CSS 변수를 내므로 `index.css` 도 안 건드린다.
- [[ADR-089]] 결정 1 의 `secondary`(라벤더)와 결정 2 의 `secondaryTint` 값, 결정 3 의 `position` 이
  이 문서로 대체된다. 나머지(카민 `primary`·핑크 `third`·`dim` 0.78·기본 다크 테마는 혼테일)는 유효하다.
