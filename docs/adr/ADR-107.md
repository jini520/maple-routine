# ADR-107 — 캐릭터 관리 모달 높이를 안전영역 기준으로 묶고, 스크롤포트를 모달 가장자리까지 넓힌다

**날짜**: 2026-08-06
**상태**: **구현 완료**, 2026-08-06 — 테스트 2,477개 통과 · lint clean · 빌드(타입·CSS 생성 포함) 통과 · 브라우저 하네스로 실측 검증. **미verify: 실기기**
**관련**: [[ADR-015]](캐릭터 카드 그리드) · [[ADR-035]](그리드 분리·온보딩 공유) · [[ADR-053]]·[[ADR-062]](본문 자리 상태 분기·3줄 고정) · [[ADR-099]](스크롤은 화면이 소유) · [[ADR-072]](스크롤 가능한 조상에서 시작한 제스처 무시)

## 맥락

"캐릭터 관리" 모달(`CharacterTrackingPicker`)에서 사용자 보고 2건(2026-08-06).

**① 캐릭터가 많으면 모달이 안전영역을 침범한다.** 지금 카드에는 높이 상한이 없다 — 상한은 본문 안쪽 그리드의 `max-h-[70vh]` 하나뿐이고, 카드 총 높이는 거기에 헤더·버튼·패딩이 더 붙은 값이다.

```
카드 총 높이 = p-6 상하 48 + 테두리 2 + 헤더 72 + mb-4 16 + 본문(≤70vh) + mt-4 16 + 버튼 40
             = 194 + 본문
```

뷰포트 852px 기기에서 본문이 70vh(596)까지 차면 카드는 790px 이 된다. 오버레이는 `items-center` 로 가운데 정렬이므로 위아래로 31px 씩 삐져나오고, 그 자리엔 노치(59)·제스처바(34)가 있다. **`vh` 는 시스템 바를 포함한 화면 전체**라 안전영역이 큰 기기일수록 더 많이 침범한다 — 즉 "기기별 대응"이 아예 없는 값이다.

**② 스크롤 인디케이터가 모달 안쪽으로 24px 들어와 있다.** 인디케이터는 콘텐츠가 아니라 **스크롤포트 위에** 겹쳐 그려지는데([[ADR-099]] 에서 화면 스크롤을 옮길 때 확인한 성질), 그 스크롤포트가 카드 `p-6` **안쪽**의 그리드라 인디케이터도 카드 안쪽 24px 지점에 뜬다.

## 결정

### 결정 1 — 카드 높이는 "화면"이 아니라 "안전영역을 뺀 화면"에서 온다

오버레이가 여백을 만들고, 카드는 그 안에 갇힌다.

```
오버레이: fixed inset-0 z-50 flex items-center justify-center bg-scrim
          px-4 pt-[calc(1rem+var(--sa-top))] pb-[calc(1rem+var(--sa-bottom))]
카드:     flex max-h-full w-full max-w-sm flex-col p-6     ← max-h-full = 오버레이 콘텐츠 박스(=여백 뺀 높이)
헤더·푸터: shrink-0                                        ← 줄어드는 것은 본문 자리뿐
본문 자리: flex min-h-[…결정 2…] flex-col
```

상하 여백 `1rem` 은 안전영역에 **더한** 값이다 — 인셋이 0인 기기(구형 안드로이드·데스크톱 브라우저)에서도 화면에 딱 붙지 않게 하려는 것이고, 인셋이 있는 기기에서는 시스템 바와 카드 사이에 그만큼 숨 쉴 틈이 생긴다.

**flex 로 푸는 이유**: 남는 높이를 본문에 주는 계산을 CSS 가 하게 만든다. 헤더 문구가 몇 줄로 감기는지, 버튼 높이가 얼마인지를 상수로 박아 `calc` 하면 그 값들이 바뀔 때마다 조용히 어긋난다.

그리드가 갖고 있던 `max-h-[70vh]` 는 **없앤다**. 상한은 이제 카드가 정하므로, 남겨두면 두 개의 상한이 경쟁하고 뷰포트가 큰 기기에서는 70vh 가 먼저 걸려 여백만 남는다.

### 결정 2 — 3줄 최소 높이(385px)는 짧은 뷰포트에서 양보한다

본문 자리는 상태(그리드/스피너/실패/빈)가 바뀌어도 아래 버튼이 움직이지 않도록 카드 3줄 높이로 못 박혀 있다(`ROSTER_BODY_MIN_H = min-h-[385px]`, [[ADR-053]]·[[ADR-062]]). 그런데 **CSS 에서 `min-height` 는 `max-height` 를 이긴다** — 385px 를 그대로 두면 결정 1 의 상한이 짧은 기기에서 무효가 되고, 카드는 다시 안전영역을 침범한다.

그래서 모달 안에서만 최소 높이를 클램프한다.

```
min-h-[min(385px,calc(100dvh-var(--sa-top)-var(--sa-bottom)-15rem))]
```

- `15rem`(240px) = 카드 크롬 194 + 오버레이 상하 여백 32 = 226 을 올림한 값이다.
- 이 상수가 실제와 다소 어긋나도 안전하다 — **클램프는 385px 가 애초에 들어가지 않는 기기에서만 발동**한다(대략 뷰포트 625px + 안전영역 미만). 그 위 기기에서는 `min()` 이 항상 385px 를 고르므로 종전 동작 그대로다.
- 온보딩 단계(`ContentCharacterStep`)는 모달이 아니라 페이지라 상한 자체가 없다 — 클램프도 필요 없고 `ROSTER_BODY_MIN_H` 를 그대로 쓴다.

### 결정 3 — 스크롤포트는 그리드가 아니라 호스트가 소유한다

`CharacterTrackingGrid` 에서 `max-h-[70vh] overflow-y-auto` 를 떼어내 **쓰는 쪽**이 자기 자리에 맞는 스크롤포트를 두게 한다. [[ADR-099]] 가 화면 스크롤에 세운 규칙("스크롤포트를 실제로 보이는 영역에 맞춘다")과 같은 것을, 그리드를 공유하는 두 호스트에 적용하는 셈이다.

| 호스트 | 스크롤포트 |
|---|---|
| 모달(`CharacterTrackingPicker`) | `-mr-6 min-h-0 overflow-y-auto pr-6` |
| 온보딩(`ContentCharacterStep`) | `max-h-[70vh] overflow-y-auto` (종전과 동일) |

모달 쪽 `-mr-6` 가 스크롤포트를 카드 패딩 바깥(테두리 안쪽)까지 넓혀 **인디케이터를 모달 오른쪽 끝에 붙이고**, 같은 크기의 `pr-6` 가 콘텐츠 여백을 되돌린다(카드 폭·그리드 열 폭은 그대로다). `min-h-0` 은 flex 아이템의 자동 최소 크기(콘텐츠 높이)를 풀어 결정 1 의 상한 아래로 줄어들 수 있게 한다 — 이게 없으면 스크롤포트가 콘텐츠 높이만큼 버티며 카드 밖으로 넘친다.

스탈 배너([[ADR-062]])는 스크롤포트 **밖**에 그대로 둔다 — 목록을 굴려도 "최신이 아님"은 계속 보여야 한다.

[[ADR-072]] 의 당겨서 새로고침 제외 규칙은 영향받지 않는다 — 스크롤 가능한 조상을 클래스가 아니라 `getComputedStyle().overflowY` 로 찾으므로(`lib/use-pull-to-refresh.ts`), 스크롤포트가 한 단계 위로 옮겨가도 같은 판정이 나온다.

## 반려한 대안

- **그리드에 `className` 프롭을 열어 모달만 다른 클래스를 주기** — 그리드가 스크롤을 계속 소유한 채 호스트가 그 위에 예외를 덮는 구조가 된다. 모달은 `max-h-[70vh]` 를 `max-h-none` 으로 지우는 상쇄 클래스를 넘겨야 하고, 두 상한 중 무엇이 이기는지가 호출부마다 달라진다.
- **그리드 자체를 `-mr-6 pr-6` 로 바꾸기** — 온보딩은 상쇄할 카드 패딩이 없는 페이지라 그리드가 가로로 삐져나온다.
- **카드 전체를 `overflow-y-auto` 로** — 짧은 기기에서 헤더와 "닫기·저장"까지 스크롤 뒤로 숨는다. 모달의 CTA 는 항상 보여야 한다.
- **`max-h-[70vh]` 를 `max-h-[60vh]` 로 낮추기** — 침범 폭만 줄이는 완화책이다. 원인은 비율이 아니라 **안전영역을 계산에 넣지 않은 것**이라 큰 인셋 기기에서 다시 재현된다.

## 검증 (브라우저 하네스, 2026-08-06)

빌드된 CSS(`dist/assets/*.css`)에 실제 모달 마크업을 얹고 `--safe-area-inset-*` 을 주입해 세 경우를 실측했다(뷰포트 1,169px 기준).

| 경우 | 카드 상단 여백 | 카드 하단 여백 | 본문 자리 | 스크롤 |
|---|---|---|---|---|
| 후보 60명 | 인셋 59 + **16** | 인셋 34 + **16** | 850 (카드 상한이 정함) | 내부 스크롤 |
| 후보 3명 | 인셋 59 + 여백 | 인셋 34 + 여백 | **385** (3줄 고정 유지) | 없음 |
| 인셋 300/300 (짧은 화면 흉내) | 인셋 300 + **16** | 인셋 300 + **16** | 343 (클램프 발동) | 내부 스크롤 |

- 세 경우 모두 **카드가 안전영역을 침범하지 않고**, 스크롤포트 오른쪽 끝과 카드 오른쪽 끝의 간격은 **1px**(카드 테두리 두께)이었다 — 인디케이터가 모달 가장자리에 붙는다.
- 실측된 카드 크롬은 **194px** 로 결정 2 의 추정치와 일치했다(15rem 안의 194 + 32).

**미verify**: 실기기(iOS 노치·안드로이드 제스처바)에서의 상하 여백과 인디케이터 위치.
