### ADR-025: 스플래시 스크린 구현 — 네이티브 스플래시 하나로 통일 + MIUI force-dark 대응 (구현 완료)

**배경**: `@capacitor/splash-screen`을 추가하며 안드로이드 12+ 네이티브 SplashScreen API가 활성화됐는데, 기존 `styles.xml`은 옛날 방식(`android:background=@drawable/splash`)이라 우리 스플래시 이미지가 전혀 안 뜨고 시스템 기본 화면만 표시됐다(2026-07-15 발견). 목표는 unboxing(Expo) 앱처럼 **로고가 있는 스플래시 하나**가 실행 시점부터 콘텐츠 준비될 때까지 충분히 떠 있다가 사라지는 것. 흰 화면 깜빡임·이중 스플래시 없이.

**결정**:

1. **스플래시는 네이티브 스플래시 하나로 통일한다(별도 HTML 부트 스플래시를 두지 않는다).**
   - **iOS**: 런치 스토리보드(`LaunchScreen.storyboard`)를 오렌지 배경 + `Splash` 이미지(=오렌지+아이콘+워드마크, `Splash.imageset`)로 두고, `AppDelegate`에서 `window.backgroundColor`도 오렌지로 지정(실행 애니메이션 구간 검정 방지). Capacitor SplashScreen 플러그인이 `launchAutoHide:false`로 스플래시를 유지한다.
   - **Android**: 12+ 테마(`AppTheme.NoActionBarLaunch`←`Theme.SplashScreen`)에 `windowSplashScreenBackground`(색 리소스) + `windowSplashScreenAnimatedIcon`(아이콘+워드마크 락업) + `windowSplashScreenBehavior=icon_preferred`. `MainActivity.onCreate`에서 `installSplashScreen()`(super.onCreate 이전) + `setKeepOnScreenCondition`으로 최소 시간(1s) 유지한다.
   - **유지/해제**: `launchAutoHide:false`라 자동으로 사라지지 않고, `App.tsx`의 `useEffect`가 앱 셸 마운트 후 최소 표시 시간(`MIN_SPLASH_MS`=1s)을 보장한 뒤 `native/splash-screen.ts`의 `SplashScreen.hide()`로 내린다. `capacitor.config`의 `backgroundColor`도 오렌지로 둬 스플래시 해제 직후 WebView 흰 깜빡임을 없앤다.

2. **네이티브 스플래시 아이콘(Android)은 `splash.png`에서 아이콘+워드마크만 오려낸 투명 배경 락업(`res/drawable/splash_icon_lockup.png`)을 쓴다.** 색 유사도 기반 배경 제거는 오렌지 계열이라 잎사귀까지 지워지므로, 가장자리부터 flood-fill로 배경만 투명화한다.

3. **MIUI/HyperOS 다크모드 force-dark 대응 — 다크모드용 스플래시 배경색을 별도로 준다.** MIUI/HyperOS는 다크모드에서 밝은 색 스플래시 배경을 **앱 설정(테마·manifest의 `forceDarkAllowed`, `values-night`, DayNight 앱 테마, `installSplashScreen()` 순서, `icon_preferred` 전부 무효)과 무관하게 luminance 기준으로** 강제로 어둡게 만든다(실기기 검증, [[project_miui_forcedark_splash]] 메모리 참고). 풀 브랜드 주황 `#FB8101`(luminance ~151)은 임계값(~120)을 넘어 `#AD4000`(칙칙한 갈색)으로 깎인다. 아이콘 PNG 비트맵은 force-dark가 안 건드린다. 따라서 배경색을 `@color/splash_background` 리소스로 빼고 `values/`(라이트 `#FB8101`)·`values-night/`(다크 `#D06100` = 강제 다크 변환을 통과하는 가장 밝은 주황, `#D46400`부터 깎임)로 split한다. 라이트/다크 모두 "설정값 == 표시값"이 된다.

**이유 / 구현 중 폐기한 대안**:
- **폐기 (1) — Capacitor 플러그인의 Android 자동 유지**: 플러그인의 `showWithAndroid12API`는 브릿지 로드 시점(첫 콘텐츠 그리기 이후)에 `installSplashScreen()`을 호출해 스플래시를 제대로 hook하지 못한다 → Android에선 스플래시가 유지되지 않고 순식간에 사라진다. 그래서 Android는 `MainActivity`에서 직접 유지한다.
- **폐기 (2) — HTML 부트 스플래시 이원화**: 네이티브 스플래시 위에 `index.html`의 정적 `#boot-splash`(오렌지+로고)를 얹어 유지하려 했으나, **네이티브 스플래시 로고와 HTML 로고가 크기·위치가 달라 로고가 두 번 뜨는(이중 스플래시) 문제**가 생겨 폐기. 네이티브 하나로 통일하는 게 unboxing과 동일하고 더 깔끔하다.
- **force-dark 진단 핵심**: 다크모드를 껐다 켜니 색이 실시간으로 바뀌었고(캐시 아님), Expo의 파란색을 우리 앱에 넣으니 다크모드에서도 안 깎였다(= Expo가 특별한 설정을 한 게 아니라 그 파랑이 원래 임계값 아래라 통과한 것). 이로써 원인이 앱 설정이 아니라 OS의 luminance 기반 force-dark임을 확정했다.

**트레이드오프**:
- 다크모드 Android 네이티브 스플래시는 풀 브랜드 주황(`#FB8101`)이 아니라 살짝 진한 주황(`#D06100`)으로 나온다 — MIUI 제약상 불가피. 라이트모드·iOS는 `#FB8101` 정상 표시.
- 스플래시 유지 방식이 iOS(플러그인)·Android(`MainActivity`)로 갈린다 — 플랫폼별 코드지만 각 플랫폼에서 안정적으로 동작하는 방식을 택했다.
- 네이티브 스플래시 배경색이 색 리소스 참조라, 브랜드 색을 바꾸면 `values/`·`values-night/` 두 곳을 함께 수정해야 한다(다크용은 임계값을 넘기면 다시 깎이니 주의).
- 앱 실행 최초 프레임의 짧은 검정(OS 앱-오픈 줌 애니메이션 구간)은 시뮬레이터/일부 기기에서 남을 수 있다 — 런치 스토리보드/윈도우 배경을 오렌지로 맞춰 최소화했다.
