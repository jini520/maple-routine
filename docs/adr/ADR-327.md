# ADR-327: 가계부 `기타`(수입 · 지출)의 수량을 치는 칸으로 바꾼다

> 🟢 유효 · **구현 완료** 2026-09-29(`app/cashbook/income/EtcForm.tsx` · `app/cashbook/spend/EtcForm.tsx`) · 실기기 미검증 · 이슈 #568 · 사용자 결정 2026-09-29

**관련**: [[ADR-173]](결정 17 `기타` 는 금액 × 수량 · 정정 1 결정 3 아이템 구매 수량은 치는 칸) · [[ADR-202]](결정 3 · 4 수입 `기타` 의 금액 × 수량)
**문서**: `features/cashbook.md` 의 `입력`
**이슈**: #568

## 맥락

수입 `기타` 와 지출 `기타` 의 수량은 `+ / −` 스테퍼(`QuantityStepper`)다. 세는 것이 몇 회라 자릿수가 작다고
보고 스테퍼로 두었다([[ADR-173]] 정정 1 결정 3). 실제로는 수량이 큰 기록이 있어 여러 번 눌러야 했다.
아이템 구매 · 아이템 판매의 수량은 이미 치는 칸이다.

## 결정

### 결정 1. 두 `기타` 폼의 수량을 치는 칸(`AmountInput`)으로 바꾼다

스테퍼를 걷는다. 줄 자리와 `testID`(`income-sheet-quantity` · `spend-sheet-quantity`)는 그대로다.
`QuantityStepper` 컴포넌트는 지출 목록 갈래(`CatalogForm`)와 사냥 계산기가 계속 쓰므로 남는다.

금액 × 수량 계산과, 수정으로 열 때 금액을 `총액 ÷ 수량` 으로 되짚는 것은 그대로다.

### 결정 2. 단위를 안 적는다 (사용자 결정 2026-09-29)

[[ADR-173]] 결정 17 그대로다. `기타` 는 자유 입력이라 무엇을 세는지 앱이 모른다. 아이템 구매의 `개` 는
세는 것이 아이템이라 붙은 것이다.

### 결정 3. 빠른 입력 칩을 안 둔다 (사용자 결정 2026-09-29)

`AmountInput` 은 `chips` 를 안 주면 메소 칩(`MESO_QUICK_ADDS`)을 띄운다. 그래서 빈 배열을 넘겨 칩 줄을 없앤다.
안 넘기면 수량 카드에 `+1억` 같은 메소 칩이 선다.

### 결정 4. 빈 칸 · 0 이면 저장을 막는다 (사용자 결정 2026-09-29)

아이템 구매와 같다. 수량이 0 이면 합계가 0 이라 기존 조건(`금액 × 수량 > 0`)이 그대로 막는다. 1 로 바꿔 읽지 않는다.
사용자가 지운 값을 앱이 다른 수로 채우면 화면과 저장값이 갈린다.

## 대가

- 수량 1 을 2 로 바꾸는 데 한 번 누르던 것이 카드를 열고 치는 것으로 늘어난다.
