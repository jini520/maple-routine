# ADR-102 — 접기 전 사전 스크롤을 걷어낸다: 근본 처방이 들어온 뒤 남은 것은 워크어라운드의 비용뿐이었다

**날짜**: 2026-08-06
**상태**: **구현 완료 · 실기기 검증 완료**, 2026-08-06 — 자동 테스트 2,448개 통과·lint clean, iPhone 17(iOS 26.5) 사이드로딩으로 확인("아주 깔끔해졌어"). **[[ADR-085]] 가 잡았던 옛 증상은 되살아나지 않았다** — 요소 스크롤러([[ADR-100]])가 그 원천을 실제로 없앴음이 이로써 확인됐다
**관련**: [[ADR-085]](이 ADR 이 결정 2를 폐기한다 — 결정 1은 유지) · [[ADR-100]](요소 스크롤러 채택 — "떼는 것은 별도 관측이 필요한 결정"이라 남겨뒀다) · [[ADR-099]] · [[ADR-084]](같은 증상의 실패한 처방, 이미 폐기) · [[ADR-047]](중첩 sticky 카드 헤더) · [[ADR-080]]

## 맥락

사용자 관측(2026-08-06, 연속 프레임 사진): 보스 수익에서 캐릭터 카드를 펼친 채 스크롤을 내리고 그 카드를 접으면 **접히기 직전에 페이지가 엉뚱한 위치로 한 번 튄다.**

| 경우 | 중간 프레임에서 보이는 것 |
|---|---|
| ① 최상단 카드 하나만 펼치고 아래로 스크롤 → 접기 | 최상단으로 튀는데 **본문은 아직 펼쳐져 있어** 그 카드 본문의 맨 위가 한 프레임 보인다 |
| ② 두 개 펼치고 충분히 스크롤 → 아래쪽 카드 접기 | 위쪽 카드 본문 끝으로 튀고, **둘 다 펼쳐진 채** 한 프레임 보인다 |

### 원인 — [[ADR-085]] 결정 2의 두 단계가 두 프레임으로 그려진다

```ts
const collapse = (): void => {
  const removedHeight = shell.height - header.height
  const nextMaxScroll = Math.max(0, scroller.scrollHeight - removedHeight - scroller.clientHeight)
  if (scroller.scrollTop <= nextMaxScroll) { setIsExpanded(false); return }
  scroller.scrollTo(0, nextMaxScroll)                 // ① 먼저 옮기고
  requestAnimationFrame(() => setIsExpanded(false))   // ② 다음 프레임에 접는다
}
```

①과 ② **사이에 한 프레임이 페인트된다.** `setIsExpanded` 가 rAF 콜백 안에서 불리므로 React 18 은 이 업데이트를 Scheduler(MessageChannel)로 넘겨 **다음 매크로태스크**에 렌더한다 — rAF 콜백 → 페인트 → 그 다음 커밋 순서라, 브라우저가 **"스크롤은 이미 옮겨졌는데 본문은 아직 붙어 있는"** 상태를 반드시 한 번 그린다.

추론이 아니다. 기존 테스트가 그 중간 상태를 **의도된 계약으로 단언하고 있었다**:

```ts
// 스크롤이 **먼저** 간다 — 이 시점에는 본문이 아직 붙어 있어야 문서 높이가 유효하다.
expect(scrollTo).toHaveBeenCalledWith(0, 700)
expect(screen.getByText('자쿰')).toBeInTheDocument()
```

튀는 거리는 클램프될 양 전부다. 경우 ①은 접은 목록이 뷰포트에 들어가 `nextMaxScroll = 0` 이라 **최상단까지** 간다.

### 왜 지금 떼는가

[[ADR-085]] 는 iOS **문서** 스크롤 스레드가 접기 전 오프셋을 35~40ms 뒤에 되돌려 보내는 것을 잡은 처방이고, 고리를 두 군데에서 끊었다(결정 1 `fixed` 헤더 · 결정 2 사전 스크롤). 그러면서 **결정 4에서 "목록 전용 스크롤 컨테이너가 근본이긴 하지만" 하고 미뤘다.**

그 근본 처방은 [[ADR-099]]·[[ADR-100]] 이 채택했다. [[ADR-100]] 은 결정 2를 이렇게 남겨뒀다:

> **[[ADR-085]] 결정 2(접기 전 사전 스크롤)를 남겨둔다.** 요소 스크롤러에서도 iOS 스크롤 스레드가 같은 옛 오프셋을 되돌려 보내는지는 모른다. **무해하고** 검증된 코드라 유지하고, 실기기에서 접기가 깨끗하면 그때 떼어볼 수 있다(**떼는 것은 별도 관측이 필요한 결정이다**).

**"무해하다"는 전제가 이번 관측으로 반증됐고, 기다리던 그 "별도 관측"이 이 보고다.** 근본 처방이 들어온 뒤로 이 코드가 하는 일은 워크어라운드의 비용을 내는 것뿐이었다.

## 결정

### 결정 1 — 접기는 상태만 바꾼다. 스크롤을 건드리지 않는다

```ts
onClick={() => setIsExpanded((expanded) => !expanded)}
```

`collapse()` · `shellRef` · 사전 스크롤 계산을 전부 지운다.

**자연 동작이 오히려 옳다.** 접을 때 사라지는 본문은 **탭한 헤더보다 항상 아래에** 있다. 스크롤을 안 건드리면 그 헤더와 위쪽 내용은 제자리에 그대로 남고, 손가락이 있던 자리가 유지된다. 문서가 뷰포트보다 짧아지는 경우에만 브라우저가 한 번 클램프하는데, 그건 [[ADR-100]] 이후 요소 스크롤러의 평범한 동작이다.

### 결정 2 — [[ADR-085]] 결정 1(`fixed` 페이지 헤더)은 유지한다

두 결정은 **서로 다른 고리를 끊는다**([[ADR-085]] 결정 3). 결정 1이 끊는 고리("헤더 위치가 스크롤 오프셋의 함수다")는 지금도 유효하고, 이 화면뿐 아니라 스케줄러 4화면이 [[ADR-098]] 로 같은 형태를 쓴다. 비용도 없다 — 보이는 모습이 `sticky` 와 동일하다.

### 결정 3 — 되살릴 근거는 "실기기에서 옛 오프셋이 되돌아오는가" 하나다

[[ADR-085]] 의 계측 신호는 명확하다: 정상 프레임 **뒤에** 접기 전 오프셋으로 2프레임이 다시 그려지고, 밀린 거리가 잘린 양과 같다. 그 신호가 요소 스크롤러에서 관측되면 되살린다 — 단, 그때는 사전 스크롤을 **같은 커밋에** 태우는 형태(예: `flushSync`)를 먼저 검토한다. 이번 증상의 정체는 사전 스크롤 자체가 아니라 **그것이 별도 프레임으로 그려지는 것**이기 때문이다.

## 트레이드오프

| 얻는 것 | 잃는 것 |
|---|---|
| 접기가 한 커밋에 끝나 중간 프레임이 사라진다 | [[ADR-085]] 가 잡았던 옛 증상이 요소 스크롤러에서도 재발할 가능성이 남는다(관측되면 결정 3) |
| 탭한 헤더가 제자리에 남아 접기 UX 가 예측 가능해진다 | — |
| `collapse()`·`shellRef`·실측 3개가 사라져 화면이 단순해진다 | — |
| 접기 응답이 한 프레임 빨라진다([[ADR-085]] 트레이드오프에 적힌 지연이 없어진다) | — |

곁가지로 `removedHeight = shell − header` 의 **2px 과다 계산**도 함께 사라진다 — 접힘 헤더에는 `border border-border` 가 있고 펼침 헤더에는 없어(코드 주석이 이미 지적한 사실) 접힌 카드가 펼침 헤더보다 2px 높았다.

## 검증

| 항목 | 방법 |
|---|---|
| 접기가 스크롤을 건드리지 않는다 | `BossProfitScreen.test.tsx` — 어떤 오프셋에서 접어도 `scrollTo` 미호출 |
| 접기가 한 커밋에 끝난다(중간 상태 없음) | 같은 파일 — 클릭 직후 동기적으로 본문이 사라진다(`await` 없이) |
| 기간·탭 이동의 최상단 이동([[ADR-080]])은 그대로다 | 기존 테스트 유지 |

**실기기 확인 결과** (2026-08-06, iPhone 17 / iOS 26.5): ① 중간 프레임 **사라짐** ② [[ADR-085]] 의 옛 증상(정상 프레임 뒤에 옛 오프셋으로 2프레임) **재발 없음**.

②가 이 ADR 의 핵심 리스크였고, 재발하지 않았다는 것은 **[[ADR-100]] 의 요소 스크롤러가 원천을 실제로 없앴다**는 뜻이다 — [[ADR-085]] 결정 4가 "근본"이라 부른 판단이 맞았음이 사후 확인됐다. 결정 3(`flushSync` 로 되살리는 안)은 발동 조건이 사라져 당분간 꺼내지 않는다.
