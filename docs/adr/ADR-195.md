# ADR-195: 배지는 컴포넌트 하나다. 테두리·배경·크기를 프롭으로 받는다

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-08-31
**관련**: [[ADR-094]] 결정 3(좁은 `Badge` 를 만든 결정. 이 문서가 그 범위를 넓힌다) · [[ADR-147]] 정정 40(난이도 배지의 크기 둘) · [[ADR-152]] 결정 5(고정칸의 `fixed`) · [[ADR-162]] 결정 3(진행 불가 배지) · [[ADR-172]] 정정 2(한 칸 표기)

## 맥락

배지가 다섯 군데에 흩어져 있었다. 사용자가 화면에 다 띄워 보고(2026-08-31) 통합을 지시했다.

| 컴포넌트 | 살던 곳 | 호출 |
|---|---|---|
| `Badge` | `components/atoms/Badge/` | 톤 3개 |
| `DifficultyBadge` | `components/atoms/DifficultyBadge/` | 10곳 |
| `QuestStateBadge` | `app/content-scheduler/content-badges.tsx` | 8곳 |
| `CategoryBadge` | 같은 파일 | 5곳 |
| `CountLabelBadge` | 같은 파일 | 파일 안 2곳 |

`ADR-094` 결정 3 은 `Badge` 를 토큰 쌍 6곳만 덮게 좁게 만들었다. 그 판단의 근거는 두께나 색이
다른 자리가 각각 1~2곳이라는 실측이었다. 그 수가 늘었다.

## 결정

### 결정 1. 배지는 `components/atoms/Badge/Badge.tsx` 하나다

`DifficultyBadge` 디렉터리와 `content-badges.tsx` 의 배지 셋을 지운다. 스타일을 아는 컴포넌트가
하나뿐이라 같은 자리에 서는 배지들의 상자가 어긋날 수 없다. 어긋나 있던 것이 실제로 있었다
([[ADR-187]] 정정 1 이 마감 배지에만 고친 규칙을 진행 불가 배지가 안 지키고 있었다).

### 결정 2. 색·테두리·글자 그림자는 variant 표가 쥔다

`BADGE_VARIANT` 하나에 13종을 적는다. 평면 배경은 클래스로, 그라디언트 배지는 색 두 개와
테두리와 글자 그림자를 값으로 갖는다. RN 에 배경 그라디언트가 없어 그라디언트 배지만 상자가
`LinearGradient` 가 되고 나머지는 `Text` 하나다.

| 갈래 | variant |
|---|---|
| 토큰 쌍 | `primary` `third` `secondary` |
| 눌린 회색 | `muted`(흐린 글자) `neutral`(보통 글자) |
| 컨텐츠 카테고리 | `epicDungeon` `mapleUnion` `guild` |
| 난이도 | `이지` `노멀` `하드` `카오스` `익스트림` |

카테고리 색은 테마 토큰이 아니라 리터럴 hex 에 `/20` 알파다. 난이도 색은 게임 안의 색을 그대로
옮긴 값이라 테마를 안 탄다([[ADR-147]] 정정 40). 둘 다 표에 그대로 둔다.

### 결정 3. 두께는 variant 의 기본값이고 프롭으로 덮는다

`font-semibold` 가 기본이고 `secondary`(완료)는 `bold`, 난이도는 `extrabold` 다. 같은 색을 다른
두께로 쓰는 자리가 있어서(보스 스케줄러의 마감 배지는 `muted` 인데 `bold` 다) `weight` 프롭으로
덮는다.

**클래스로는 못 덮는다.** NativeWind 는 두께 충돌을 문자열 순서가 아니라 자기 우선순위로 푼다.
`font-semibold font-bold` 와 `font-bold font-semibold` 가 둘 다 600 이다(측정, 2026-08-31). 그래서
호출부가 `className="font-bold"` 를 붙여도 안 먹는다. variant 표에서 두께 클래스를 하나만 고르는
이 구조라야 먹는다.

### 결정 4. 크기 셋 중 둘은 높이가 고정이라 글자 배수를 안 따른다

| size | 상자 | 글자 | 쓰는 곳 |
|---|---|---|---|
| `default` | `px-2.5 py-1` | `text-xs` | 상태·카테고리 배지 |
| `chip` | `h-5 px-2.5` | `text-[10px]` | 난이도 기본 |
| `mini` | `h-4 px-1.5` | `text-[9px]` | 난이도 작은 것 |

`chip` 과 `mini` 는 높이가 `h-5`·`h-4` 로 고정이라 글자만 커지면 잘린다. 그래서 이 둘은 `fixed` 를
자동으로 켠다([[ADR-152]] 결정 5 의 기준이 «상자가 글자를 따라 커지는가» 다). `default` 는 패딩이
높이를 정하므로 호출부가 `fixed` 를 정한다.

이 자동 판정 때문에 `font-scaling-policy.test.ts` 의 고정칸 목록에서 `DifficultyBadge.tsx` 자리를
`Badge.tsx` 가 대신한다.

### 정정 1 (2026-08-31, 사용자 지정) — `chip` 을 없애고 난이도도 `default` 를 쓴다

결정 4 가 크기를 셋으로 두었는데, 화면에서 보니 난이도 배지만 혼자 작았다. 상태 배지와 같은 줄에
서는 자리가 많아서 높이가 어긋난다.

| | 전 | 후 |
|---|---|---|
| 상자 | `h-5 px-2.5` | `px-2.5 py-1` |
| 글자 | 10px | 12px |
| 높이 | 20px 고정 | 패딩이 만든다 |

`size` 는 `default` 와 `mini` 둘만 남는다. 호출부 8곳에서 `size="chip"` 이 사라진다.

**`fixed` 자동 판정도 같이 바뀐다.** 상자가 패딩으로 커지므로 난이도 배지는 글자 배수를 따라간다.
`mini` 만 `h-4` 로 못박혀 있어 자동으로 켜지는 유일한 크기가 된다.

### 정정 2 (2026-08-31, 사용자 지적) — 테두리를 여백 안쪽으로 넣는다

정정 1 로 상자가 패딩 기반이 되자 난이도 배지만 평면 배지보다 커졌다. 사용자가 화면에서 보고
테두리를 의심했고, 실측이 그것을 확인했다.

| 배지 | 테두리 | 바깥 높이 |
|---|---|---|
| 익스트림 | 1.5px | 65px |
| 카오스 | 1px | 63px |
| 완료 | 없음 | 58px |

**RN 의 Yoga 는 테두리를 패딩과 똑같이 바깥 크기에 더한다.** 테두리가 상자 안쪽에 그려지는 것과는
다른 이야기다. 예전에는 난이도 배지의 높이가 `h-5` 로 못박혀 있어 이 차이가 드러나지 않았다.

그래서 그라디언트 배지는 **여백에서 테두리 폭을 뺀다**. 여백과 테두리의 합이 평면 배지의 여백과
같아져 바깥 크기가 맞는다. 익스트림도 카오스도 57px 로 같아졌다(실측).

```
평면      paddingVertical 3
1px 테두리  paddingVertical 2 + borderWidth 1
1.5px     paddingVertical 1.5 + borderWidth 1.5
```

여백을 클래스가 아니라 값으로 쥐는 이유가 이것이다. 뺄셈을 하려면 숫자가 필요하다.

### 정정 3 (2026-09-01, 사용자 지정) — 높이를 못박지 않는다. 여백이 높이를 만든다

결정 4 는 `chip` 과 `mini` 의 높이를 `h-5`·`h-4` 로 박았다. 정정 1 이 `chip` 을 없앴고, 이 정정이
`mini` 의 고정 높이도 걷는다.

**고정 높이가 평면 배지를 깨뜨린다.** 배지 렌더 경로가 둘인데 세로 정렬 방식이 다르다.

| | 구조 | 세로 정렬 |
|---|---|---|
| 그라디언트 배지 | `LinearGradient` + `Text` | `items-center` 가 잡는다 |
| 평면 배지 | `Text` 하나 | 잡아주는 것이 없다 |

`mini` 는 난이도 배지만 쓰다가 today 위젯의 CLEAR 배지가 처음 쓰면서 드러났다. 상자에 높이만 박히니
글자가 위로 쏠렸다. `justify-center` 는 flex 컨테이너 속성이라 `Text` 가 자기 글자에는 못 쓴다.

여백이 높이를 만들면 두 경로가 같아진다. `mini` 는 `padX 6 · padY 2` 다.

**`fixed` 의 근거가 바뀐다.** 결정 4 는 «상자 높이가 고정이라» 였는데, 이제 `mini` 가 글자 배수를
안 따르는 이유는 **놓이는 자리**다. today 위젯의 76px 타일과 가계부의 56px 처치 타일이 고정칸이라
글자가 커지면 넘친다([[ADR-152]] 결정 5). 그래서 `mini` 는 여전히 `fixed` 를 스스로 켠다.

### 결정 5. 라벨은 데이터 상수로 남기고 호출부가 고른다

`DIFFICULTY_SHORT`(익스트림을 `EX` 로) 와 `QUEST_STATE_LABELS`(0 을 `시작 안함` 으로) 는 스타일이
아니라 도메인 데이터다. 컴포넌트가 아니라 상수로 남기고 호출부가 가져다 쓴다.

## 트레이드오프

프롭이 늘었다. `variant` `size` `weight` `fixed` `className` 다섯이고, `ADR-094` 결정 1 이 경계한
«호출부마다 예외» 가 컴포넌트 안으로 들어온 셈이다. 그라디언트·테두리·글자 그림자 축은 난이도
5종만 쓴다.

그 대신 배지 스타일을 아는 파일이 하나가 되어, 같은 자리에 서는 배지의 상자가 어긋나는 종류의
결함이 구조적으로 안 생긴다. 사용자가 그 값을 택했다.
