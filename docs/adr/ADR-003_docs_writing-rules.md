# ADR-003 문서 · 주석 · 앱 문구 쓰는 규칙

> 🟢 유효
> 옛 번호: ADR-158 · ADR-194 · ADR-206
> 관련 소스: `docs/ADR.md` · `src/__tests__/adr-policy.test.ts` · `src/__tests__/comment-style-policy.test.ts`

## 배경

이 저장소의 문서와 주석은 사람 한 명과 AI 에이전트가 같이 읽는다. 지금까지 두 가지 문제가 되풀이됐다.

첫째, 세션이 이미 폐기된 정책을 근거로 코드를 되돌렸다. 폐기 사실이 본문 중간에 묻혀 있었고, ADR 인덱스가
342KB 까지 불어나 인덱스만 열어도 죽은 정책이 같이 읽혔다.

둘째, 문서를 읽어도 무슨 말인지 알기 어려웠다. 원인은 단어보다 문장을 짓는 방식에 있었다. 소스에 없는
비유를 주어로 쓰고, 명사구 하나에 개념을 여러 개 넣고, 규칙만 적고 이유는 적지 않았다. AI 에이전트는
뜻을 잘못 읽어도 아무 신호 없이 그대로 코드에 옮긴다.

## 결정

### 결정 1. ADR 은 기능마다 한 파일이고, 지금 유효한 결정만 남긴다

규칙은 `docs/ADR.md` 에 있다. 요점은 넷이다.

- 한 기능의 결정은 한 파일에 둔다. 결정이 바뀌면 파일 이름 끝에 `+NNN` 을 붙이고 같은 파일에 이어 쓴다.
- 상태는 🟢 유효 · ⚪ 미구현 둘뿐이다. 결정 일부가 뒤집히면 죽은 부분은 본문에서 지운다. 결정이 전부
  죽으면 파일을 지우고, 인덱스 행과 다른 문서의 인용도 함께 지운다. 죽은 정책이 파일에 남아 있으면 다음
  세션이 그것을 읽고 되살리기 때문이다. 옛 내용은 git 히스토리에서 찾는다.
- 인덱스에는 파일 하나에 한 줄만 쓴다. 요약을 쌓으면 인덱스가 다시 불어난다.
- 문서끼리는 경로가 아니라 번호(`[[ADR-NNN]]`)로 가리킨다. 번호가 붙을 때마다 파일 이름이 바뀌어서
  경로로 걸면 링크가 끊긴다.

기능 문서에는 그 기능이 무엇을 하는지만 쓰고, 왜 그렇게 정했는지는 ADR 에 맡긴다. 같은 이유를 두 문서에
쓰면 한쪽만 고쳐지는 일이 생긴다. 문서 하단에 폐기된 정책을 모아 두는 절도 두지 않는다.

### 결정 2. 구현된 것만 쓰고, 열린 질문은 꼭 풀어야 하는 것만 남긴다

문서에 적는 파일 이름 · 함수 이름 · 저장 키 · 화면 문구는 쓰기 전에 `src/` 에서 찾아 실제로 있는지 본다.
문서와 코드가 다르면 코드에 맞춘다. 계획이나 짐작을 사실처럼 적으면 다음 사람이 그것을 사실로 읽는다.

열린 질문에는 반드시 결론을 내야 하는 것만 남긴다. 언젠가 다시 볼 만한 생각까지 모아 두면 정작 풀어야
할 질문이 묻힌다.

ADR 의 테스트 표에는 그 결정을 지키는 테스트만 적는다. 값 하나를 그대로 비교하거나 입력과 출력이 뻔한
테스트는 코드에서 지운다. 남긴 테스트에는 무엇을 지키는지를 표에 적어, 지워도 되는지 다음 사람이 판단할
수 있게 한다.

### 결정 3. 코드에 실제로 있는 이름을 쓴다

`벽지` 대신 테마 배경 이미지, `층` 대신 스택이라고 쓴다. 판단 기준은 간단하다. 그 말로 `src/` 를 검색해서
나오지 않으면 바꾼다. 비유가 이해를 도울 때도 실제 이름을 먼저 쓰고 비유는 뒤에 덧붙인다.

### 결정 4. 결론과 이유를 함께 쓰고, 한 문장에 개념을 셋 넣지 않는다

규칙을 적으면 그 규칙을 어겼을 때 무엇이 깨지는지를 같은 문장이나 바로 다음 문장에 쓴다. 이유가 없으면
다음 사람이 그 규칙을 바꿔도 되는지 판단할 수 없다.

개념이 여러 개면 문장을 나눈다. 짧게 쓰는 것보다 한 번에 읽히는 것이 우선이다. 예를 들어
`테마 배경은 가장 안쪽 불투명 화면이 그린다` 는 개념 셋을 한 명사구에 넣어서 읽히지 않는다.
`테마 배경은 탭 내비게이터가 그린다. 바깥 스택에서 그리면 탭 화면 배경색에 가려진다` 처럼 쓴다.

### 결정 5. 직역투를 쓰지 않는다

한국어 문장은 다른 언어로 옮겼다가 다시 한국어로 돌려 지어서, 영어식 구문이 남지 않게 한다. 다 쓴 뒤에는
한 문장씩 한국 사람이 실제로 그렇게 말하는지 다시 읽는다. 자주 나오는 직역투는 이렇다.

| 직역투 | 고친 문장 |
|---|---|
| 계산기가 나누는 것은 수수료다 | 수수료까지 고르게 나눠지도록 보낼 금액을 역산한다 |
| 그 문제는 단위 칩 다섯이 푼다 | 그래서 단위 칩 다섯 개를 눌러 금액을 더할 수 있게 했다 |
| 애니메이션과 스와이프가 따라온다 | 따로 만들지 않아도 생긴다 |
| 글자를 그리는 유일한 자리다 | 글자는 여기서만 그린다 |

`X 하는 것은 Y 다` 처럼 결론을 뒤로 미루는 구문과, 물건을 주어로 세우는 영어식 문장을 피한다.
`~하는 유일한 N 이다` 는 위치를 지정하는 말이면 `여기서만` 으로 바꾸고, 강조만 하고 있으면 지운다. 개수가
하나라는 사실을 말하는 경우(사냥터 이름이 전역에서 하나뿐이라는 것)는 그대로 둔다. `것이다` 는 정상적인
한국어 표현이라 쓴다.

### 결정 6. 장식 기호를 쓰지 않는다

| 기호 | 대신 쓰는 것 |
|---|---|
| `—` | 앞말이 문장이면 마침표, 라벨이면 콜론, 짧은 덧말이면 괄호 |
| `«»` | 지우고 볼드로 쓴다 |
| `「」` | 앱 문구는 곡선 따옴표 `‘’`, 문서와 주석은 백틱 |

가운뎃점 `·` 은 한국어의 원래 나열 기호라 그대로 쓴다. 표에서 해당 없음을 뜻하는 `| — |` 칸은 문장 부호가
아니라 값이라 남긴다.

곡선 따옴표를 쓰는 이유는 소스 문자열 안에서도 안전하기 때문이다. 홑따옴표는 `text: '...'` 의 구분자와
겹쳐 리터럴을 깨뜨린다.

`comment-style-policy.test.ts` 가 `src/` 를 검사한다. `«»` · `「」` 는 `.ts` · `.tsx` 와 함께 `src/` 안의
`.json` · `.md` 설명 글까지 본다. `—` 는 `.ts` · `.tsx` 에서만 막는다. `.json` 설명 글의 `—` 는 거의 전부 날짜와
설명을 잇는 목록 구분자라서, 마침표로 바꾸면 한 줄로 읽히던 기록이 끊어진다. `—` 를 허용하는 파일은
`lib/boss/boss-profit-period.ts`(표의 빈 칸) 하나다. 허용 목록의 파일에서 `—` 가 사라지면 그 테스트도 실패해서 목록이 낡지 않는다.

### 결정 7. 범위는 문서 · 소스 주석 · 앱 문구 전부다

`docs/**/*.md`, `src/**` 의 주석과 테스트 이름, 그리고 앱 화면에 실제로 보이는 문구(`src/data/feature-guides/*`
· `src/data/release-notes.ts` · 에러 문구)가 모두 이 규칙을 따른다. 앱 문구는 사용자가 보는 것이라 뜻이
조금이라도 바뀌면 안 되므로, 기호만 바꾸고 문장은 그대로 둔다.

### 결정 8. 소스는 ADR 을 인용하지 않는다

`src/**` 의 주석과 문자열에 `[[ADR-NNN]]` 도, 대괄호 없는 `ADR-NNN` 도 쓰지 않는다. 테스트 이름과 에러
문구도 마찬가지다.

참조는 한 방향이다. ADR 에는 파일 경로와 심볼 이름을 적는다. 결정이 코드를 관리하기 때문이다. 반대로
코드가 ADR 번호를 적으면, ADR 을 고칠 때마다 그 번호를 인용한 소스를 전부 다시 봐야 한다. 그리고 번호가
붙어 있으면 이유를 안 적어도 적은 것처럼 보인다.

인용을 지울 때는 셋 중 하나다. 이유가 이미 옆에 있으면 인용만 지운다. 인용이 이유를 대신하고 있었으면
이유를 한 줄로 적고 인용을 지운다. 옮길 이유가 없으면 주석째 지운다.

소스에서 결정을 찾을 때는 `docs/README.md` 에서 기능 → 문서 → 소스 파일 순으로 내려간다.

`adr-policy.test.ts` 가 `src/` 의 `.ts` · `.tsx` 를 검사한다. `scripts/` · `ota/` · `ios/` · `android/` 와
설정 파일(`jest.config.js` · `babel.config.js` · `tailwind-v4-axes.cjs`)은 검사 밖이라 지금도 옛 번호를 인용하는
곳이 남아 있다.

### 결정 9. 주석은 JSDoc 으로 역할만 쓴다

주석은 `/** */` 로 쓰고 파일 머리 · 타입 · 상수 · 함수 · 프롭에 붙인다. `//` 는 선언에 붙지 않아서
호출부에서 마우스를 올려도 보이지 않는다. JSX 속성이나 함수 본문 안의 주석도 한 파일 안에서 형태가
갈리지 않도록 같은 형태로 맞춘다.

태그는 넷만 쓴다.

| 태그 | 붙이는 곳 |
|---|---|
| `@param` | 위치 인자를 받는 함수. 프롭을 구조 분해로 받는 컴포넌트에는 붙이지 않는다 |
| `@example` | 쓰는 법. 실제 호출부에서 가져오고 지어내지 않는다. 없는 조합을 적으면 그것이 다음 사람의 기본값이 된다 |
| `@returns` | 반환값이 자명하지 않을 때만 |
| `@see` | 같은 저장소의 다른 파일 |

`@use` 는 JSDoc 태그가 아니라서 어느 도구도 읽지 않는다.

주석에는 이 코드가 무엇이고 어떻게 쓰는지만 적는다. 경위 · 계측값 · 라이브러리 소스 인용 · `예전에는 이랬다`
는 ADR 과 git 에 맡긴다. 예외는 어기면 버그가 나는 값이다. `adjustResize` 로 바꾸면 시트가 키보드 뒤에 남는
것처럼, 그 한 줄이 없으면 다음 사람이 고치려 드는 값은 이유를 한 줄로 남긴다. 테스트 파일이 아닌 소스의
파일 머리 주석이 JSDoc 인지는 `comment-style-policy.test.ts` 가 검사한다.

### 결정 10. 역할을 적는 주석은 명사로 끝낸다

| 전 | 후 |
|---|---|
| 한 값을 무한 반복시킨다 | 한 값을 무한 반복시키는 훅 |
| 시트 최대 높이를 정한다 | 시트 최대 높이. 화면 높이 × 이 값 |
| 이 값이 바뀌면 스크롤을 되돌린다 | 바뀌면 스크롤을 맨 위로 되돌리는 키 |

파일 머리 · 함수 · 훅 · 프롭 · 테스트 도우미처럼 역할을 적는 주석이 대상이다. 조건 · 제약 · 근거를 적는
주석은 완전한 문장으로 쓴다. `null 이면 레벨 글자를 비운다` 를 명사로 바꾸면 조건이 사라진다.
