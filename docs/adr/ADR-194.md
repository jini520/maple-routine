# ADR-194: 문서와 주석, 앱 문구를 읽히게 쓴다

> 🟢 ACTIVE 유효. 2026-08-31 · 사용자 결정 · 적용 중.

## 맥락

문서가 안 읽힌다는 지적이 나왔다. 원인을 두 번 잘못 짚었다.

**첫 번째 오진: 번역투.** `~에 대한`, `~을 위한`, `~에 의해`, 이중피동 같은 지표로 `docs/` 전체
2.4MB 를 훑으니 275건이었다. 1,000자당 0.1건이라 문제가 아니다.

**두 번째 오진: 비유 어휘.** `갈래`, `든다`, `선다` 같은 말이 3,548건 있어서 치환표를 만들고
`cashbook.md` 에 97곳을 적용했다. 그런데 단어를 바꿔도 문장이 안 읽혔다.

실제 사례다. [[ADR-193]] 제목이 이랬다.

```
벽지는 «가장 안쪽 불투명 화면» 이 든다. 층 스택이 아니라 탭 내비게이터다
```

치환표대로 `벽지`를 테마 배경으로, `든다`를 그린다로 바꾸면 이렇게 된다.

```
테마 배경은 가장 안쪽 불투명 화면이 그린다
```

여전히 무슨 말인지 알 수 없다. 무엇의 안쪽인지, 불투명 화면이 왜 나오는지가 문장 안에 없기
때문이다. **문제는 어휘가 아니라 문장을 짜는 방식이었다.**

원인은 셋이다.

1. **코드에 없는 말을 주어로 쓴다.** `벽지`, `층` 같은 말은 소스 어디에도 없다. 읽는 사람이
   그 말과 실제 코드를 머릿속에서 이어 붙여야 한다.
2. **명사구 하나에 개념을 여러 개 넣는다.** `가장 안쪽 불투명 화면`은 (내비게이터가 여러 겹이다)
   + (화면마다 불투명 배경색을 칠한다) + (그중 가장 안쪽이다) 셋을 합친 말이다.
3. **결론만 쓰고 이유를 안 쓴다.** 규칙은 있는데 그 규칙을 안 지키면 무엇이 깨지는지가 없다.

같은 내용을 이렇게 쓰면 읽힌다.

```
테마 배경은 탭 내비게이터가 그린다. 바깥 스택에서 그리면 탭 화면 배경색에 가려진다
```

## 결정

### 결정 1. 코드에 실제로 있는 것의 이름을 쓴다

`벽지` 대신 테마 배경 이미지, `층` 대신 스택, `갈래` 대신 입력 종류처럼 소스에서 찾을 수 있는
말을 쓴다. 판별법은 간단하다. **그 말로 `src/` 를 검색해서 안 나오면 바꾼다.**

비유가 설명을 도울 때가 있지만, 그때도 실제 이름을 먼저 쓰고 비유를 뒤에 붙인다. 비유만 쓰지
않는다.

### 결정 2. 결론과 함께 이유를 같은 자리에 쓴다

규칙을 적으면 그 규칙을 어겼을 때 무엇이 깨지는지도 한 문장 안이나 바로 다음 문장에 쓴다.
이유가 없으면 다음 사람이 그 규칙을 안전하게 바꿀 수 있는지 판단하지 못한다.

한 문장에 개념을 셋 넣지 말고 문장을 나눈다. 짧게 쓰는 것보다 한 번에 읽히는 것이 우선이다.

### 결정 3. 장식 기호를 쓰지 않는다

세 가지를 없앤다. 사용자 지정(2026-08-31)이다.

| 기호 | 건수 | 대신 쓰는 것 |
|---|---|---|
| `—` (em dash) | 17,472 | 마침표·콜론·괄호. 아래 참조 |
| `«»` | 4,330 | 곡선 따옴표 `‘’` |
| `「」` | 1,839 | 곡선 따옴표 `‘’` |

인용 부호 둘을 **지우지 않고 바꾸는** 이유는, 그것들이 강조가 아니라 인용 기능을 하고 있어서다.
지우면 뒤따르는 조사가 뜬다. `«누가 위인가» 는` 에서 부호만 지우면 `누가 위인가 는` 이 된다.
곡선 따옴표를 쓰는 이유는 소스 문자열 안에서도 안전하기 때문이다. 홑따옴표는 `text: '...'` 의
구분자와 겹쳐 리터럴을 깨뜨린다(실제로 한 번 깨뜨렸다).

가운뎃점 `·` 은 그대로 쓴다. 한국어에서 원래 쓰는 나열 기호다.

`—` 를 무엇으로 바꿀지는 앞말이 정한다.

- 앞말이 **문장으로 끝나면 마침표**로 끊는다. `안 뜬다 — 사전 예약이 떠 있다` → `안 뜬다. 사전 예약이 떠 있다`
- 앞말이 **라벨이면 콜론**을 쓴다. 제목, 표 머리, 다이어그램 주석이 여기 해당한다.
  `## 화면 구조 — 스택 두 겹` → `## 화면 구조: 스택 두 겹`
- 짧게 덧붙이는 말이면 **괄호**에 넣는다. `기능 설명 추가 — 사용법을 분류해 안내` →
  `기능 설명 추가(사용법을 분류해 안내)`

**예외 둘은 그대로 둔다.** 문장부호가 아니라 값이기 때문이다.

- 표의 `| — |` 칸. 해당 없음을 뜻하는 표시다
- 앱이 화면에 그리는 `— 메소`. 금액을 모를 때 `0` 대신 대시를 보여 주기로 한 결정이다
  ([[ADR-087]] 결정 3). `0` 은 '0원 벌었다'로 읽힌다

### 결정 4. 범위는 문서와 소스 주석과 앱 문구 전부다

사용자 지정(2026-08-31)이다. 앞선 판단에서는 소스 주석을 뺐는데 되돌린다.

- `docs/**/*.md`
- `src/**` 의 주석
- **앱에 실제로 보이는 문구**. `src/data/feature-guides/*`(기능 안내), `src/data/release-notes.ts`
  (릴리스 노트), 화면에 뜨는 에러 문구가 여기 해당한다.

앱 문구는 사용자가 보는 것이라 뜻이 조금이라도 바뀌면 안 된다. 기호만 바꾸고 문장은 그대로 둔다.

### 정정 1 (2026-09-01, 사용자 지적) — `~하는 유일한 자리다` 를 안 쓴다

결정 1~3 은 어휘와 기호를 다뤘고 문장 구조는 결정 2 가 개념을 셋 넣지 말라고만 적었다. 그 사이로
구문 하나가 계속 빠져나갔다. `~하는 유일한 N 이다` 다. 소스 주석에만 94곳이었다.

영어 `the only place that ~` 을 그대로 옮긴 말이다. 한국어에서 `유일한` 은 개수가 하나라는 것을
**강조**할 때 쓰는데, 이 구문은 자리를 **지정**하는 데 쓰고 있다. 그래서 읽을 때 한 번 되짚게 된다.

바꾸는 법은 둘이다. **자리를 지정하는 말이면 `여기서만` 으로 돌린다.**

| 전 | 후 |
|---|---|
| 글자를 그리는 유일한 자리다 | 글자는 여기서만 그린다 |
| 화면이 루트 스택을 다루는 유일한 통로 | 화면은 루트 스택을 여기로만 다룬다 |
| 목적지가 없는 유일한 타일이다 | 목적지가 없는 타일은 이것뿐이다 |
| 테스트가 유일한 방어선이다 | 이걸 막는 것은 테스트뿐이다 |

**아예 지우는 쪽이 나을 때가 더 많다.** `유일한` 이 하는 일이 강조뿐이고, 그 강조가 문장에 아무것도
안 더하는 자리가 있다. 그런 자리는 단어를 지우면 문장이 그대로 읽힌다.

개수가 하나라는 **사실 자체**를 말하는 자리는 그대로 둔다. 사냥터 이름이 전역 유일이라는 것,
안내의 `id` 가 문서 안에서 유일해야 한다는 것은 번역투가 아니라 도메인 사실이다.

### 결정 5. 한 번에 하지 않고 나눠서 한다

수십만 자를 한 회차에 바꾸면 diff 를 검토할 수 없고 뜻이 바뀐 곳을 못 찾는다. 이 순서로 한다.

1. 앱 문구 (사용자가 보는 것이라 가장 먼저)
2. `docs/features/*` 와 `docs/foundation/*`
3. 소스 주석
4. ADR 본문 (기록이라 우선순위가 낮다)

## 이유

읽는 쪽이 사람 하나와 AI 에이전트다. 압축한 문장은 쓸 때만 이득이고 읽을 때마다 비용이 든다.
문서는 쓰는 횟수보다 읽는 횟수가 훨씬 많으니 계산이 안 맞는다.

AI 에이전트 쪽이 더 나쁘다. `걷었다` 를 삭제했다로 읽을지 보류했다로 읽을지 자리마다 갈리는데,
틀리게 읽어도 아무 신호가 없다. 그대로 코드에 반영된다.

## 트레이드오프

문서가 길어진다. 개념 셋을 한 명사구에 넣던 것을 세 문장으로 풀면 분량이 두 배가 되는 자리도
있다. 그 대신 다시 읽을 때 해독이 필요 없다.

문체의 개성이 줄어든다. 지금 문체는 읽는 맛이 있었다. 그것을 포기하고 오독을 줄인다.

기계로 못 바꾼다. `선다` 하나가 자리마다 놓인다·표시된다·만들었다로 갈리고, `—` 도 문장을 끊을
자리인지 괄호로 넣을 자리인지 문맥을 봐야 한다. 기호만 일괄 치환하면 문장이 깨진다.

## 열린 질문

- ADR 제목까지 바꿀지. 제목은 인덱스와 커밋 메시지에 박혀 있어 범위가 커진다. 지금은 본문만
  고치고 제목은 그대로 둔다.
- 새 문서가 이 규칙을 지키는지 테스트로 강제할지. 기호 셋은 기계로 검사할 수 있지만 인용문이나
  외부에서 가져온 글까지 걸려 오탐이 난다. 정리가 끝난 뒤에 다시 본다.
