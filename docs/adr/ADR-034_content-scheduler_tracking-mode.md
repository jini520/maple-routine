# ADR-034 자동 · 수동 추적 모드와 컨텐츠 관리

> 🟢 유효
> 옛 번호: ADR-035 · ADR-096 · ADR-086 결정 2 · ADR-140 결정 5 정정
> 관련 소스: `features/tracking-mode/` · `storage/tracking-mode.ts` · `storage/manual-tracked-content.ts` · `lib/scheduler/manual-content-merge.ts` · `features/content-scheduler/displayed-contents.ts` · `features/content-scheduler/store.ts` · `app/content-scheduler/ContentManageScreen.tsx` · `app/settings/TrackingModeModal.tsx` · `app/settings/TrackingModeSelector.tsx`

## 배경

스케줄러 화면은 처음에 게임 안 스케줄러에 등록한 항목만 읽어서 보여 줬다. 그런데 응답의 `registration_flag` 가
실제 게임 상태와 어긋나는 일이 계속 생겼다. 그래서 게임 등록에 기대지 않고 앱에서 직접 추적할 항목을 고르는 수동
모드를 만들었다.

## 결정

### 결정 1. 모드는 앱 전체에 하나다

`trackingMode` 는 `'auto'` 또는 `'manual'` 이고, 컨텐츠 스케줄러와 보스 스케줄러에 똑같이 적용된다. 화면마다,
캐릭터마다 따로 정하지 않는다.

- Preferences 키 `trackingMode` 에 저장한다. 값이 없거나 알 수 없는 값이면 `getTrackingMode` 는 `'auto'` 가 아니라
  `null` 을 돌려준다. 고르지 않은 것과 자동을 고른 것을 같은 값으로 두면, 사용자가 고르지도 않은 자동이 선택된
  것처럼 보이기 때문이다. 동작은 자동이 기본이라 읽는 두 곳(`features/tracking-mode/store` ·
  `features/boss-profit/store`)이 `?? 'auto'` 로 받는다.
- 사용자가 직접 고른 설정이라 데이터 삭제가 지우지 않는다. 데이터를 지웠다고 수동 모드가 말없이 자동으로
  돌아가면 안 된다.
- 모드를 바꿔도 자동 쪽 데이터도 수동 쪽 추적 목록도 지우지 않는다.

### 결정 2. 자동은 게임 등록을, 수동은 추적 목록을 따른다

| 모드 | 화면에 나오는 항목 |
|---|---|
| 자동 | 병합 결과 중 `isRegistered` 가 참인 항목 |
| 수동 | 그 캐릭터의 추적 목록에 있는 항목. 등록 여부는 보지 않는다 |

자동과 수동을 합친 목록은 만들지 않는다. 합치면 수동으로 지운 항목이 게임에 등록돼 있다는 이유로 다음 동기화에서
다시 나타나, 지우기가 무슨 뜻인지 알 수 없게 된다.

스케줄러 API 동기화는 모드와 관계없이 항상 전체 상태를 받는다. 보스 수익 자동 기록도 모드와 관계없이 동기화 결과로
한다. 화면에 무엇을 보여 주는지는 기록에 영향을 주지 않는다.

### 결정 3. 추적 목록에는 무엇을 추적하는지만 저장하고, 값은 보여 줄 때 찾는다

`manualTrackedContent:{ocid}` 에 캐릭터마다 배열 하나를 저장한다.

- 컨텐츠 항목은 `{ contentKey, kind, maxCount? }` 이고 `kind` 는 `'daily'` 또는 `'weekly'` 다. 보스 항목은
  `{ kind: 'boss', bossKey, difficulty }` 다.
- `kind` 는 저장할 때 정한다. 시드는 응답의 일간 · 주간 배열로, 관리 화면은 지금 보는 탭으로 정한다. 보여 줄 때
  추측하면 같은 항목이 일간 · 주간 탭 양쪽에 나온다.
- `nowCount` · `questState` · `isRegistered` 같은 값은 저장하지 않는다. 화면에 그릴 때 그 캐릭터의 동기화 결과에서
  컨텐츠 key 로 찾고(`mergeManualContentList`), 한 번도 동기화된 적 없는 항목은 컨텐츠 표의 기본값을 쓴다. 값을 두
  곳에 두면 모드를 바꿀 때 방금 완료로 보이던 항목이 미완료로 바뀌는 일이 생긴다. 한 곳에서만 읽으면 두 모드가
  언제나 같은 값을 본다.
- `maxCount` 는 사용자가 입력하지 않는다. 추가할 때 컨텐츠 표의 `max_count` 를 복사한다.
- 이 키는 사용자가 추가 · 삭제할 때와 시드할 때만 쓰고, 동기화는 쓰지 않는다. 동시에 쓸 일이 없어서 잠금 없이
  Preferences 로 충분하다.
- 옛 형식(일간 · 주간 구분 없는 `kind: 'content'`, key 대신 이름이 들어 있는 항목)은 읽을 때 컨텐츠 표 · 보스 표로 key 를
  찾아 옮긴다. 찾지 못한 항목은 버린다. 관리 화면은 표에 있는 항목만 보여 주므로, 표에 없는 항목을 남기면 편집할 수
  없는 항목이 된다.

### 결정 4. 추적할 수 있는 컨텐츠는 컨텐츠 표에 있는 것뿐이다

추가는 자유 입력이나 지난 응답 목록이 아니라 컨텐츠 표에서 고른다. 게임 데이터라 사용자가 확인한 항목만 표에
들어간다([[ADR-019]]). 표에서 고르면 한 번도 동기화되지 않아 고를 것이 없는 문제도 생기지 않는다.

표 전체를 자동 모드의 목록으로 쓰지는 않는다. 어떤 퀘스트가 그 캐릭터에게 열리는지는 레벨 · 직업 · 스토리 진행에
따라 다르고, 그 정보는 넥슨 서버에만 있다. 사람이 고를 때는 그런 판단이 필요 없다.

### 결정 5. 수동 모드의 추적 목록은 그때의 게임 등록으로 한 번 채운다

`seedManualTrackedContent` 가 최신 동기화 결과에서 등록된 항목을 추적 목록에 넣는다. 처음 수동 모드를 켰을 때 목록이
비어 있지 않게 하려는 것이다. 부르는 경우는 셋이다.

- 자동에서 수동으로 바꾼 순간, 추적 중인 캐릭터 전원을 시드한다(`useTrackingModeStore.setMode`).
- 이미 수동 모드인데 추적 캐릭터를 새로 더하면 더한 캐릭터만 시드한다(컨텐츠 · 보스 스케줄러 스토어의
  `saveTrackedOcids`).
- 수동 모드에서 처음 캐릭터를 고르면 그 캐릭터들을 시드한다(앱 첫 설정의 `completeCharacterSetup`).

시드 규칙은 이렇다.

- 컨텐츠 표에 없는 컨텐츠, 보스 표에 없는 보스는 넣지 않는다(결정 3 과 같은 이유).
- 캐릭터 여럿을 한 번의 `syncSchedules` 로 처리하고, 결과는 순서가 아니라 ocid 로 찾는다. 캐릭터마다 따로 부르면
  진행 중인 동기화에 서로 합류해 전원이 첫 캐릭터의 스케줄로 채워졌다.
- 결과가 없거나 `state` 가 `null` 이면 예외를 던지고 저장하지 않는다. 빈 배열로 채우면 정말 아무것도 등록하지 않은
  사용자와 구분할 수 없다.
- 이미 있는 목록은 덮어쓴다.

시드가 끝날 때까지는 로딩을 보여 주고 결과를 한 번에 그린다. 컨텐츠 표 기본값은 거의 미등록 · 진행 없음이라, 먼저
그리면 아직 결과가 안 왔을 뿐인데 아무것도 등록하지 않은 것처럼 보인다.

### 결정 6. 두 모드 모두 컨텐츠 관리 화면과 같은 순서로 보여 준다

목록 순서는 추적 목록에 들어간 순서가 아니라 컨텐츠 관리 화면의 순서다. 추가 · 삭제할 때마다 순서가 바뀌던 문제를
고친 것이다. 일간은 컨텐츠 표 순서대로 카테고리를 묶은 순서, 주간은 카테고리 표 순서다. 자동 모드도 같은 순서로
맞춘다(`orderContentsByTemplate`). 화면마다 순서가 다르면 같은 목록으로 보이지 않는다.

컨텐츠 표에 없는 컨텐츠는 자동 모드에서 등록돼 있으면 목록 뒤에 API 이름으로 나오고, 수동 모드에서는 고를 수 없으니
나오지 않는다.

### 결정 7. 추적 항목은 컨텐츠 관리 화면에서만 고친다

스케줄러 화면은 두 모드 모두 읽기만 한다. 카드마다 삭제 버튼을 두거나 목록 끝에 추가 버튼을 두면 진행을 보는
화면이 어수선해진다.

- 수동 모드일 때만 스케줄러 머리 오른쪽에 `컨텐츠 관리` 가 나온다. 누르면 `ContentManage` 를 루트 스택에 push 한다.
  수동 모드의 빈 상태 버튼도 같은 화면을 연다.
- 관리 화면은 수동 모드 전용이다. 자동 모드에서 열려 있으면 바로 뒤로 간다.
- 일간 · 주간 탭으로 컨텐츠 표 전체를 체크리스트로 보여 주고, 추적 중인 항목만 선택 상태(`bg-primary-tint`)로,
  나머지는 카드 바탕(`bg-surface`)으로 그린다. 줄에 테두리는 없다([[ADR-060]] 결정 19). 시작 기간 전인 컨텐츠는 목록에서 뺀다([[ADR-019]]).
- 행을 누르면 바로 저장한다. Preferences 에 쓰는 일이고 되돌리기 쉬워서 확인 버튼을 두지 않는다. 저장에 실패하면
  `추적 목록을 저장하지 못했습니다` 토스트를 띄운다. 누른 행이 그대로 남아 있어 무엇이 실패했는지 알 수 있으므로
  다시 시도 버튼은 두지 않는다.
- 행은 카테고리로 묶는다(`categorizeContentEntries`). 묶음 머리에는 아이콘 · 카테고리 이름 · `추적 수/전체 수` 가
  있고, 행에는 `displayName` 과 같은 아이콘이 있다. 아이콘은 카테고리 key 로 고른다(일일 · 주간 퀘스트 `MapPin`,
  에픽 던전 `Castle`, 메이플 유니온 `LayoutGrid`, 몬스터파크 `Swords`, 아케인리버 지역 퀘스트 `Sparkles`, 무릉도장
  `Medal`, 길드 `Flag`).
- 행 오른쪽의 참고 배지는 `contentCountTag` 가 정한다. 컨텐츠 줄의 `countTag`, 카테고리 줄의 태그, 기본 규칙
  (횟수형이고 상한이 있으면 `최대 n회`) 순서로 본다. 지금 적힌 값은 몬스터파크 `월드 당 최대 14회`, 익스트림
  몬스터파커 `월드 당 2회`, 에픽 던전 `ID당 1회` 이고, 아케인리버 지역 퀘스트는 숨긴다. 리셋 · 제한 규칙이라
  사용자가 확인한 값만 적는다.
- 길드 미가입 캐릭터의 잠금은 [[ADR-033]] 결정 8 이다.

### 결정 8. 일간 · 주간 탭은 스토어에 두고, 관리 화면은 들어올 때 한 번 이어받는다

탭이 화면 안의 상태였을 때는 다른 탭에 다녀오면 일간으로 돌아갔고, 주간을 보다 `컨텐츠 관리` 를 눌러도 일간 목록이
열렸다.

- 탭(`activeTab`)은 `features/content-scheduler/store.ts` 에 있다. 처음 값은 일간이다. 이미 받은 데이터를 나눠
  보여 줄 뿐이라 탭을 바꿔도 조회하지 않는다.
- 관리 화면은 들어올 때의 스케줄러 탭으로 시작한다(`useState(schedulerTab)`). 관리 화면에서 탭을 바꿔도 스케줄러
  탭은 그대로다. 관리 화면에서 잠깐 다른 탭을 본 것 때문에 돌아왔을 때 보던 탭이 바뀌면, 고치려던 문제가 반대
  방향으로 다시 생긴다.
- 저장하지 않는다. 앱을 다시 켜면 일간이다. 앱을 쓰는 동안 보던 탭을 잃는 문제만 고치면 되기 때문이다.
- 고른 캐릭터는 탭과 달리 두 화면이 언제나 같다. 관리 화면에서 고친 추적 목록이 어느 캐릭터의 것인지 헷갈리면 안
  되기 때문이다. 캐릭터 선택은 [[ADR-030]] 이 다룬다.

### 결정 9. 설정에서 모드를 바꿀 때는 고른 뒤 `적용` 을 눌러야 한다

설정의 `스케줄 관리 방법` 모달(`TrackingModeModal`)에서 바꾼다.

- 옵션을 누르면 고르기만 하고, `적용` 을 눌러야 `setMode` 가 한 번 불린다. 누르자마자 저장되면 되돌릴 방법이
  없었다. 버튼은 설정의 다른 확인 모달처럼 `취소` 와 `적용` 이다. 모드 전환은 지우는 동작이 아니라서 `적용` 은
  `primary` 채움 버튼이다.
- 지금 모드와 같은 것을 고르면 `적용` 을 누를 수 없다.
- 적용하는 동안은 `적용` 버튼 안에 스피너가 돌고(`busy`), 옵션 · `취소` 와 바깥 영역 누르기로 닫기가 모두 막힌다.
  시드가 끝나야 닫힌다.
- 적용이 끝나면 `reloadTabStores(['content', 'boss'])` 가 만료된 회차를 한 번 미리 받고(`prefetchSchedules`), 컨텐츠 ·
  보스 스케줄러 스토어의 `reloadLocal` 로 기기 값(수동 추적 목록 `manualTrackedByOcid` · 직접 완료)을 다시 읽힌다.
  수동 모드에서 어떤 항목을 보일지는 저장소가 아니라 스토어 메모리의 추적 목록으로 정하는데, 탭 화면은 띄워진 채
  남아 있어 스스로 다시 읽지 않으므로, 이렇게 하지 않으면 수동으로 바꾼 직후 빈 추적 목록이 보인다. 시드가 끝난
  뒤에 다시 읽어야 옛 목록을 읽지 않는다.
  - 회차는 한 번만 미리 받는다. 두 스토어가 같은 회차 쿼리를 보고([[ADR-142]] 결정 3), 둘 다 부르면 첫 회차가
    실패했을 때 두 번째가 다시 나간다. 수동으로 바꾼 경우는 시드가 방금 동기화를 돌려서 대개 회차가 신선해 조회하지
    않는다. 보스 수익은 회차와 기록 판에 매인 쿼리라 여기서 할 일이 없다.
  - 다시 읽기를 기다리지 않고 모달을 닫는다. 실패해도 알리지 않는다. 그 탭에 들어가면 화면이 다시 조회하고, 그때
    실패하면 그 화면의 실패 처리가 돈다.

옵션 문구는 `features/tracking-mode/copy.ts` 한 곳에 있다. 어느 모드도 추천으로 표시하지 않는다. 옵션마다 아이콘
(자동 `Gamepad2`, 수동 `ListChecks`)과 제목 · 설명이 있고, 그 모드의 한계는 정보 색 상자(`bg-info-tint`)에 따로
적는다. 사용자가 고칠 수 없는 제약이라 오류 색을 쓰지 않는다. 고르기 전에 둘을 견줘 봐야 하므로 설명과
한계는 접지 않는다.

| 모드 | 제목 | 설명 | 한계 |
|---|---|---|---|
| 자동 | 자동 | 게임 내 스케줄러에 등록한 컨텐츠가 그대로 반영돼요. | API 응답에 따라 컨텐츠가 표시되지 않을 수 있어요. |
| 수동 | 수동 | 직접 컨텐츠를 선택하고 관리해요. | 게임 내에 스케줄러를 추가하더라도 앱에는 자동으로 추가되지 않아요. |
