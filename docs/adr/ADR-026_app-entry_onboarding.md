# ADR-026 온보딩 흐름

> 🟢 유효
> 옛 번호: ADR-211 · ADR-308
> 관련 소스: `features/app-entry/` · `app/character-setup/` · `navigation/RootNavigator.tsx` · `app/auth/SignInScreen.tsx` · `app/mvp-grade/MvpGradeOnboarding.tsx` · `storage/mvp-grade-prefs.ts`

## 배경

앱을 처음 켜면 탭을 열기 전에 몇 가지를 받아야 한다. 넥슨 데이터를 읽을 API 키(또는 넥슨 로그인), 앱이
관리할 캐릭터, 그 캐릭터가 속한 메이플 ID 의 MVP 등급이다. 이 문서는 그 화면들을 어떤 순서로 보여 주고,
중간에 앱이 꺼졌을 때 어디서 다시 시작하는지를 정한다. 로그인 화면의 내용은 [[ADR-024]] · [[ADR-025]] 에,
캐릭터를 고르는 본문은 [[ADR-029]] 에, MVP 등급 카드는 [[ADR-050]] 에 있다.

## 결정

### 결정 1. 온보딩에서는 로그인, 캐릭터, MVP 등급만 묻는다

```
로그인 → 캐릭터 설정 → MVP 등급 고르기 → MVP 등급 확인
```

스케줄 관리 방법(자동 · 수동)은 온보딩에서 묻지 않는다. 게임 스케줄러 등록 상태를 따를지 앱에서 직접
체크할지는 앱을 써 본 뒤에야 판단할 수 있는데, 처음 켠 사람에게는 그 판단 재료가 없다. 나중에 설정에서
바꿀 수 있는 값을 시작할 때 억지로 고르게 할 이유가 없다. 관리 방법은 설정의 `TrackingModeSelector`
한 곳에서만 고른다.

그 대신 새 사용자는 수동 모드가 있다는 것을 설정에 들어가야 알게 된다. 이것을 알리는 안내 문구를
온보딩에 넣지는 않는다. 넣으면 단계를 뺀 이유를 문구로 다시 들여오는 셈이기 때문이다.

### 결정 2. 관리 방법을 고른 적이 없으면 아무 값도 저장하지 않는다

온보딩은 `trackingMode` 를 쓰지 않고, `'auto'` 를 미리 넣어 두지도 않는다. 값을 읽는
`features/tracking-mode/store.ts` 와 `features/boss-profit/store.ts` 가 둘 다 `?? 'auto'` 로 읽어서,
저장된 값이 없으면 자동으로 동작한다.

`'auto'` 를 써 넣으면 사용자가 직접 고른 자동과 한 번도 고르지 않은 상태가 저장소에서 똑같아진다. 그러면
나중에 고른 적이 있는지 다시 알고 싶어져도 구분할 방법이 없다.

### 결정 3. 진입 단계는 저장된 값을 보고 정한다

진입 단계(`EntryStage`)는 `signIn → characterSetup → mvpGrade → ready` 넷이다. 부팅과 로그인 직후에
`features/app-entry/stage.ts` 의 `deriveEntryStage` 하나로 단계를 정한다. 두 경로가 함수를 따로 가지면
규칙이 두 벌이 되기 때문이다.

| 저장된 값 | 진입 단계 |
|---|---|
| 인증 설정(`getAuthConfig`)이 없다 | `signIn` |
| 추적 캐릭터가 `null` 이거나 빈 배열이다 | `characterSetup` |
| `mvpOnboardingPending` 이 켜져 있다 | `mvpGrade` |
| 그 밖 | `ready` |

- 진행 상태만 따로 적는 키는 두지 않는다. 각 단계에서 고른 값이 이미 저장돼 있으니, 진행 상태를 또
  적으면 같은 사실이 두 곳에 생긴다. 한쪽만 적힌 채 앱이 꺼지면 둘이 어긋난다. MVP 단계만 예외다
  (결정 9).
- 추적 캐릭터가 빈 배열이어도 캐릭터 설정을 끝내지 않은 것으로 본다. 캐릭터는 최소 하나를 골라야 하므로
  빈 배열은 사용자가 의도한 상태가 아니다.
- `trackingMode` 는 읽지 않는다. 결정 1 에 따라 그 값을 묻는 단계가 없기 때문이다.

### 결정 4. 수동 모드면 캐릭터 설정을 마칠 때 체크리스트를 미리 채운다

온보딩에서 관리 방법을 묻지 않아도, 캐릭터 설정 화면에 수동 모드로 들어오는 경우가 있다. 연결 해제 뒤 다른
넥슨 계정으로 로그인하면, 추적하던 캐릭터가 그 계정에 없어 캐릭터 설정부터 다시 한다(`resolveAfterSignIn`).
`trackingMode` 는 연결 해제도 데이터 삭제도 지우지 않아서, 이때 수동 모드인 채로 캐릭터 설정에 들어온다.

그래서 `completeCharacterSetup` 은 모드가 `manual` 이면 고른 캐릭터를 저장한 뒤
`seedManualTrackedContent` 로 체크리스트를 채우고 나서 다음 단계로 넘어간다. 이 과정을 빼면 수동 모드
사용자의 체크리스트가 빈 채로 앱이 열린다. 시드가 시작되면 화면 전체를 스피너와
`체크리스트를 준비하고 있어요` 로 바꾼다. 캐릭터 수만큼 시간이 걸려서 버튼의 스피너만으로는 멈춘 것처럼
보이기 때문이다.

### 결정 5. 온보딩 화면 넷을 한 스택에 함께 등록한다 (사용자 지정)

`EntryStage` 가 `ready` 가 아니면 루트 스택에 로그인(`SignIn`) · 캐릭터 설정(`CharacterSetup`) ·
MVP 등급 고르기(`MvpGradePick`) · MVP 등급 확인(`MvpGradeConfirm`) 넷을 함께 등록한다. 다음 화면으로 갈
때는 화면을 push 하고, 돌아갈 때는 pop 한다. 그래서 안드로이드 뒤로 버튼과 iOS 밀어서 뒤로 가기가 다른
하위 페이지처럼 동작한다. API 키를 넣은 다음 화면부터는 모두 이전 화면으로 돌아갈 수 있다. 로그인 화면이
맨 아래라 거기서 안드로이드 뒤로 버튼을 누르면 앱이 내려간다.

- 다음 화면은 화면이 직접 push 한다. 로그인이 성공하면 로그인 화면이 `CharacterSetup` 을, 캐릭터 설정이
  `mvpGrade` 를 돌려주면 캐릭터 설정 화면이 `MvpGradePick` 을 push 한다. 진입 단계 값만 보고 화면을
  바꾸면 안 된다. 뒤로 갔다가 다시 앞으로 갈 때는 단계 값이 바뀌지 않아서, 그 값을 기다리면 앞으로 갈 수
  없다.
- 앱을 다시 켰을 때도 같은 스택을 만든다. 부팅이 `characterSetup` 이나 `mvpGrade` 를 찾으면 스토어의
  `resumeTo` 에 적고, 로그인 화면이 그 단계까지 화면을 쌓은 뒤 `consumeResume` 으로 지운다. 이때는
  스플래시가 덮고 있어 화면이 쌓이는 모습이 보이지 않는다.
- `ready` 가 되면 탭과 하위 페이지로 스택 전체가 바뀐다. 앱이 열린 뒤에는 온보딩 화면으로 돌아가지 않는다.

### 결정 6. 캐릭터 설정과 MVP 화면의 머리 줄에는 뒤로가기 버튼만 둔다 (사용자 결정)

세 화면은 `EntryScroll` 에 `onBack` 을 넘겨, 다른 하위 페이지와 같은 `PageHeader` · `BackButton` 을
머리 줄에 둔다. 제목과 설명은 본문에 큰 글자로 쓴다. 로그인 화면은 첫 화면이라 돌아갈 곳이 없어서 버튼이
없다.

### 결정 7. 로그인 화면으로 돌아오면 저장된 키를 입력칸에 채워 둔다 (사용자 결정)

로그인 화면은 `features/auth/saved-key.ts` 의 `loadSavedApiKey` 로 저장된 키를 읽어 `ApiKeyForm` 의
`initialApiKey` 로 넘긴다. 그대로 `확인` 을 누르면 다시 넘어가고, 다른 키로 바꿔 넣을 수도 있다. 앱을
다시 켜서 스택이 다시 쌓인 경우에도 같다. 다른 키로 로그인하면 그 키의 캐릭터로 캐릭터 설정을 다시 하게
되는데, 그 판단은 [[ADR-024]] 에 있다.

### 결정 8. MVP 등급은 캐릭터 설정 다음의 온보딩 화면 둘에서 묻는다 (사용자 결정)

어느 메이플 ID 의 등급을 물을지는 캐릭터를 골라야 알 수 있다. 그래서 캐릭터 설정이 먼저다.

- 캐릭터 설정을 마쳤을 때 추적 캐릭터가 속한 메이플 ID 가운데 등급 이력이 없는 것이 하나라도 있으면
  (`features/mvp-grade/onboarding.ts` 의 `needsMvpOnboarding`) MVP 화면으로 간다. 모두 이력이 있으면
  (캐시를 지운 뒤 다시 온보딩하는 경우) 곧바로 앱을 연다.
- 고르기 화면의 제목은 `MVP 등급을 알려주세요` 이고 아래 버튼은 `다음` 이다. 확인 화면의 제목은
  `이 등급이 맞나요?` 이고 아래 버튼은 `시작하기` 다.
- 확인 화면에는 `수정` 버튼이 없다(사용자 지정). 고르기 화면으로 돌아가려면 뒤로가기를 쓴다.
- `시작하기` 를 누르면 today 위 모달의 확인과 같은 저장을 한 뒤 `finishMvpOnboarding` 으로 앱을 연다.
  카드 구성과 저장 내용은 [[ADR-050]] 에 있다.
- 업데이트로 등급 기능을 처음 만난 기존 사용자, 나중에 추적에 들어온 새 메이플 ID, 주간 확인은 온보딩
  화면이 아니라 today 위 모달(`MvpGradeHost`)로 묻는다.

### 결정 9. MVP 화면에서 앱이 꺼지면 다시 켤 때 그 화면부터 시작한다 (사용자 결정)

캐릭터 설정을 마치고 MVP 화면으로 넘어갈 때 Preferences `mvpOnboardingPending` 을 켜고, `시작하기` 가
끝나면 지운다. 화면을 push 하기 전에 먼저 켜 두므로, 그 사이에 앱이 꺼져도 다음 부팅이 MVP 화면부터
이어 간다.

결정 3 에서 진행 상태만 적는 키를 두지 않는다고 했지만 MVP 단계만은 예외다. 등급 이력이 없다는 사실만으로는
온보딩 중인 사용자와, 업데이트 뒤 아직 등급을 고르지 않은 기존 사용자를 가를 수 없기 때문이다. 이 표시가
없으면 기존 사용자로 보고 today 위 모달로 묻는다.

캐릭터 설정을 마쳤는데 물어볼 메이플 ID 가 없으면 이 표시를 꺼 둔다. MVP 화면에서 로그인 화면까지 돌아가
다른 캐릭터를 고른 경우, 앞서 켜 둔 표시가 남아 있으면 다음 부팅에서 앱 대신 MVP 화면이 열리기 때문이다.
