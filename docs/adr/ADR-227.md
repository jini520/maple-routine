### ADR-227: **서버를 들인다.** 자체 호스팅이고, 저장소는 따로다 (2026-09-07, 사용자 지시)

> ⚪ **NOT IMPLEMENTED.** 결정만 있고 코드가 없다. 서버 저장소도 아직 없다. 착수 전에 이 문서와
> 아래 **열린 질문**을 다시 읽을 것.

**배경**: 사용자가 뒤집기로 한 것은 *"서버리스를 폐기한다"* 이고, 목적은 *"앱 공지 · notification
등 운영자에서 사용자로 가는 기능과 앱과 서버 사이 기능을 추가하는 것"* 이다. 구성도 함께 지정했다.
**사용자 기기 → Oracle 무료 등급(보안 프록시) → 집 미니 PC**. 서버 코드는 **별도 저장소**에 둔다.

같은 날 넷을 더 정했다. **개인 API 키는 백업에 안 넣는다.** **인증은 넥슨 OAuth 승인 뒤에 한다.**
**Oracle 과 미니 PC 는 nginx 로 잇는다.** 그리고 가장 크게 바뀐 것, *"계정관련 데이터를 수집 할
생각은 없음. 이 앱에서 생산한 2차 가공 데이터를 수집할거야"* (예: 고가 아이템 가격 입력 데이터 ·
총 보스 수익 데이터). 앱에서 서버로 가는 방향이 **백업이 아니라 수집**이다.

그런데 이 저장소에서 **서버리스**가 가리키는 것은 하나가 아니라 셋이고, **셋의 처지가 전부 다르다.**
이 문서가 하는 일의 절반은 그 셋을 갈라 각각 어떻게 되는지 못박는 것이다.

|---|---|---|
| `workers/ota-manifest` | Cloudflare Worker · **살아 있고 스토어 바이너리가 주소를 박고 있다** | 1.0.8 유도 발송까지 두고 걷는다(결정 6) |

### 결정 1. [[ADR-003]] 은 **절반만** 죽는다

[[ADR-003]] 한 파일이 서로 다른 둘을 들고 있다.

1. **백엔드 없이 기기 로컬 저장소만 쓴다.** 이것이 죽는다.
2. **`features/*` 는 저장소·네이티브에 직접 못 닿고 `storage/`·`native/` 어댑터를 거친다.**
   이것은 산다.

배지를 ⛔ 가 아니라 🟡 로 내리는 이유가 그것이다. 문서에서 [[ADR-003]] 인용을 세어 보면 30여 곳인데
**대부분이 2번을 근거로 쓴다**(`architecture.md` 의 레이어 규칙 · `persistence/README.md` 의 어댑터
표 · 스토어 액션들이 storage 를 직접 안 부르는 근거). 한 배지로 통째로 내리면 다음 세션이 서버를
붙이면서 그 경계까지 같이 허문다.

**2번은 오히려 서버가 생겨서 더 필요해졌다.** 네트워크가 새 외부 의존성 하나이고, 이 앱이 서버가
죽어도 계속 도는 이유가 그 경계다. 서버 접근은 기존 `nexon/` 이 Nexon API 를 격리하는 것과 같은
모양으로 자기 어댑터를 갖는다. `features/*` 가 서버를 직접 부르면 안 된다.

### 결정 2. 층은 셋이다. 앱 · Oracle 무료 등급 · 집 미니 PC (사용자 지정)

```
  앱 ──▶ Oracle 무료 등급 인스턴스 ──▶ 집 미니 PC
         (공인 IP · TLS 종단 · 프록시)   (실제 처리 · 데이터)
```

프록시가 가운데 있는 이유 셋. **집 IP 를 앱에 안 박는다**(바이너리에 박히면 못 바꾸고, 그 주소가
곧 집 주소다). **가정용 회선 주소가 바뀐다**(고정 IP 가 아니면 앱이 어느 날 아무 데도 못 닿는다).
**TLS 인증서와 도메인이 한 자리에 모인다.**

**두 구간은 nginx 로 잇는다**(사용자 지정). Oracle 쪽이 TLS 를 끝내고 미니 PC 로 넘긴다. 그래서
앱이 아는 주소는 Oracle 하나이고, 미니 PC 를 옮기거나 포트를 바꿔도 앱은 안 바뀐다.

### 결정 3. 서버 코드는 **별도 저장소**에 산다 (사용자 지정)

이 저장소에는 클라이언트만 둔다. 둘을 가르는 경계는 **API 계약**이다.

가르는 이유는 배포 주기가 다르기 때문이다. 서버는 심사를 안 받고 원할 때 배포되지만, 앱은 스토어
심사와 OTA 를 탄다. 한 저장소에 두면 커밋 하나가 두 배포 축을 건드리게 되고, 어느 쪽이 이미 나갔고
어느 쪽이 안 나갔는지가 흐려진다. [[ADR-146]] 이 **네이티브에 적히는 순간 OTA 로 못 고친다** 로 그은
선과 같은 종류의 선이고, 여기서는 한 칸 더 밖이다.

**대신 계약이 두 저장소에 갈라져 산다.** 응답 형태를 한쪽만 바꾸면 타입 검사가 못 잡는다. 그
위험을 어떻게 막을지는 **열린 질문**이다.

### 결정 4. 앱에서 올라가는 것은 **2차 가공 데이터**다. 계정 데이터가 아니고, 백업은 나중이다 (사용자 지정)

사용자가 정한 문장 그대로다. *"계정관련 데이터를 수집 할 생각은 없음. 이 앱에서 생산한 2차 가공
데이터를 수집할거야."* 예로 든 것이 **고가 아이템 가격 입력 데이터**와 **총 보스 수익 데이터**다.

**수집은 백업과 다른 기능이다.** 백업은 이 사람의 기록을 그대로 올려 두었다가 **그대로 돌려주는**
것이라 누구 것인지 알아야 한다. 수집은 여러 사람의 기록에서 뽑은 값을 모으는 것이고 **돌려줄 상대가
없다.** 앞은 계정이 있어야 성립하고 뒤는 없어도 성립한다.

**`ocid` 는 떼지 않는다**(사용자 지정: *"ocid 값은 넥슨 open api에서 누구나 캐릭터 이름만 입력해도
얻을 수 있는 퍼블릭한 키 값이기 때문에 수집해도 문제가 되지 않음"*). 사실 관계가 맞다. 캐릭터
이름 하나로 `/maplestory/v1/id` 가 돌려주는 값이라 **비밀이 아니고 유출로 잃을 것이 없다.** 모으는
쪽에서는 이게 있어야 같은 기록을 두 번 세지 않고 캐릭터가 바뀐 것과 값이 바뀐 것을 가른다.

**그래서 이 문서는 2차 가공을 `식별자를 뗐다` 로 정의하지 않는다.** 대신 데이터셋이 무엇인지 그대로
적는다. 원본이 `boss_drop_records` 의 `(ocid, boss, difficulty, period_key, drop_index)` 와
`boss_profit_records` 의 `(ocid, boss, difficulty, period_key)` 이므로, 서버가 드는 것은
**캐릭터 단위로 이어 붙는 기록**이다. 캐릭터 이름을 아는 사람은 ocid 를 얻어 그 캐릭터의 주차별
수익을 조회할 수 있다. 계정 단위로는 안 이어진다(한 사람의 캐릭터들을 묶는 축이 없다).

**그래도 남는 것 둘.** ① **Play 데이터 안전과 App Store 개인정보 라벨은 `비밀인가` 가 아니라
`저장하는가` 로 신고 대상을 가른다.** 공개값이어도 모으면 신고한다. 무엇으로 분류할지는 **열린
질문**이다. ② 결정 4 의 제목이 `계정 데이터가 아니다` 인 근거는 **계정이 없다는 것**이지 기록이
익명이라는 것이 아니다. 계정 삭제 경로가 안 생기는 근거는 그대로 선다.

**전송은 옵트인이다.** [[ADR-008]] 이 익명 오류 보고를 정할 때 이 모양을 이미 적어 뒀다. 설정에
토글을 두고 **기본값을 OFF** 로 하고 개인 식별 가능 정보를 페이로드에서 뺀다. 그 결정은 **한 줄도
구현되지 않았다**(`Sentry` 도 `익명 오류 보고` 토글도 저장소에 없다). 여기서 처음 실물이 된다.

**계정과 백업은 넥슨 OAuth 승인 뒤로 미룬다**(사용자 지정: *"인증은 추후 nexon oauth가 승인나면 그 때
작업할 것"*). [[ADR-003]] 이 기각 항목에 적어 둔 사정 그대로다. Nexon Open ID 는 메이플스토리
파트너스 승인이 필요한 제한된 기능이고 아직 신청 전이다. **승인 전에는 누가 누구인지 가릴 수단이
없어 백업이 성립하지 않는다.**

**그래서 개인정보 비용이 계정 백업이었을 때보다 훨씬 작다.** 다만 0 은 아니다.

| | 계정 백업이었다면 | 실제(2차 가공 수집) |
|---|---|---|
| 계정·인증 | 필요 | **안 생긴다.** OAuth 승인 뒤로 |
| 계정 삭제 경로 | Play·App Store 둘 다 요구 | **안 생긴다.** 지울 계정이 없다 |
| Play 데이터 안전 신고 | 대폭 개정 | **여전히 필요하다.** 모으면 신고 대상이다 |
| App Store 개인정보 라벨 | 대폭 개정 | **여전히 필요하다** |
| 개인정보 처리방침 개정 | 필요 | **여전히 필요하다** |
| 데이터 보관 기간 정책 | 필요 | 필요 |

**개인 API 키는 어디에도 안 들어간다**(사용자 지정). 백업에도 수집에도 안 실린다. 그래서
`app/auth/ApiKeyForm.tsx` 가 띄우는 `이 기기에만 저장되고 넥슨 외 어디로도 전송되지 않아요` 가
**그대로 참으로 남는다.**

**서버가 죽어도 앱은 돈다.** 수집이라 오히려 쉽다. 못 보내면 안 보내면 되고 사용자가 잃는 것이
없다. 기록·조회는 결정 1 이 살려 둔 어댑터 경계 안쪽에서 계속 로컬로 완결된다.

### 결정 5. 푸시는 **토픽**이다. 개인 알림은 계속 기기가 예약한다 (사용자 선택)

[[ADR-146]] 결정 2 가 정한 성질 넷이 **그대로 산다**. 기기는 토픽을 구독할 뿐이고 등록 토큰은 앱
밖으로 안 나간다. 서버는 자기 키로 넥슨을 부른다. 문구는 서버가 만들어 `notification` 페이로드로
싣는다. 앱은 구독과 해제만 안다.

**바뀌는 것은 발송자가 서 있는 자리 하나뿐이다.** `workers/notice-push` 를 안 만들고 미니 PC 가
보낸다. 서버가 드는 상태(마지막 발송 공지 id)도 KV 키 하나에서 미니 PC 의 저장소로 옮겨 갈 뿐이다.

**[[ADR-146]] 의 기각 근거 둘이 다 살아 있다.** 그 문서는 토큰 방식을 두 근거로 기각했다.
*"토큰 DB · 만료 정리 · 개인정보 분류가 통째로 따라온다"* 와 *"지금 보내려는 알림 셋 중 타겟팅이
필요한 것이 하나도 없다"*. 결정 4 가 계정을 안 만들기로 했으므로 **앞 근거가 온전히 남는다.**
토큰을 들면 그것 하나 때문에 사용자 식별자 저장소가 생기고, 2차 가공 수집이 애써 피한 자리로
곧장 들어간다. 뒷 근거도 그대로다. 개인적인 둘(일간 스케줄 미완료 · 주간 보스 미완료)은
[[ADR-146]] 결정 3 의 하이브리드가 맡는다. 기기가 미리 예약하고 백그라운드가 정확도를 올린다.

대가는 [[ADR-146]] 결정 3 이 이미 적어 둔 것을 그대로 물려받는다는 것이다. iOS 의 백그라운드 재확인은
실행 시각을 보장하지 않아 미완료 알림의 정확도가 기기를 탄다. 서버가 개인별로 판정해 쏘면 그 문제가
사라지지만 그러려면 계정과 개인 기록이 서버에 있어야 하고, 결정 4 가 그 둘을 다 미뤘다. 넥슨 OAuth
승인으로 계정이 생기는 시점에 다시 볼 만한 교환이고, 그때 별도 ADR 로 연다.

### 결정 6. OTA 는 **1.0.8 유도 발송을 마지막으로** Cloudflare 를 떠난다 (사용자 지정)

여기에 이 문서에서 유일한 **물리적 제약**이 있다.

`app.json` 의 `updates.url` 이 `https://maple-routine-ota.dev-jinni520.workers.dev/manifest` 다.
`workers.dev` 는 Cloudflare 도메인이라 **우리가 DNS 로 못 돌린다.** 그리고 이 값은 네이티브 설정이라
**OTA 로 못 바꾼다.** 즉 이미 깔린 바이너리는 무슨 수를 써도 저 주소를 계속 본다.

그래서 순서가 이렇게 고정된다.

1. 새 서버에 매니페스트 엔드포인트를 세운다. [[ADR-137]] 이 실측한 요건은 그대로다. 응답 헤더
   `expo-protocol-version` 이 **없으면 그 자리에서 던진다**. 본문은 평범한 JSON 이어도 된다.
2. `updates.url` 을 새 주소로 바꾼 **1.0.8 을 스토어에 낸다**.
3. 옛 Worker 로 **마지막 OTA** 를 쏜다. 이 번들이 할 수 있는 일은 스토어로 가서 업데이트하라고
   **말하는 것뿐**이다. 주소를 바꾸는 것은 2번이 하고 3번은 못 한다.
4. 그 뒤 옛 Worker 를 걷는다.

**4번의 대가를 적어 둔다.** 3번의 유도 화면을 못 본 사용자는 옛 주소를 계속 보고, Worker 가 없어지면
**그 기기는 OTA 를 영영 못 받는다.** 앱 자체는 계속 돈다. 업데이트만 안 온다. 옛 Worker 를 정적
응답 하나로 남겨 두면(무료 등급이라 비용이 사실상 0) 그 기기들도 유도 화면을 계속 볼 수 있는데,
사용자가 걷기로 정했다. 언제 걷을지는 **열린 질문**이다.

[[ADR-137]] 이 두 층으로 가른 구조(매니페스트는 우리 서버 · 번들과 에셋은 GitHub Releases)는
**그대로 산다**. 옮겨 가는 것은 매니페스트를 내는 자리 하나이고, `launchAsset.url` 은 아무 URL 이나
되므로 번들은 계속 GitHub 에서 받는다. 프로토콜 실측 결과도 전부 유효하다.

- **가용성이 집 회선을 탄다.** 정전·회선 장애·미니 PC 재부팅이 곧 기능 정지다. 결정 4 의 **서버가
  죽어도 앱은 돈다** 를 지키는 것이 이 대가의 유일한 방어선이다.
- **개인정보 의무가 생긴다.** 계정을 안 만들어 삭제 경로는 안 생기지만, **모으는 것 자체가 신고
  대상**이다. 데이터 안전 신고 · App Store 개인정보 라벨 · 처리방침 개정 · 보관 기간이 따라온다.
- **서버가 캐릭터 단위 행동 기록을 든다.** `ocid` 를 떼지 않기로 했으므로(결정 4) 모인 것은 익명
  집계가 아니다. 캐릭터 이름을 아는 사람은 그 캐릭터의 주차별 수익을 조회할 수 있다. `ocid` 자체가
  공개값이라 유출로 새로 잃는 것은 없지만, **보관 기간과 접근 통제가 그만큼 실질적인 문제가 된다.**
- **페이로드에 딸려 나가는 것을 아무도 안 잡는다.** 개인 API 키는 안 싣기로 했는데(결정 4) 그것을
  검사하는 자리가 없다. `ApiKeyForm.test.tsx` 는 안심 문구가 화면에 있는지만 본다.
- **[[ADR-008]] 의 옵트인이 처음 실물이 된다.** 3년간 설계로만 있던 것이라 선례가 없다.
- **Oracle 무료 등급은 우리가 못 정하는 정책 위에 있다.** 무료 등급 축소·유휴 인스턴스 회수 같은
  것이 통보 하나로 온다. 프록시가 죽으면 앱은 미니 PC 에 못 닿는다.
- **저장소가 둘이라 계약이 갈라진다.** 결정 3.
- **[[ADR-137]] 의 무상태 Worker 가 끝난다.** `wrangler.toml` 이 *"바인딩을 더하고 싶어지면 먼저 그
  문서를 읽어라"* 라고 적어 둔 자리인데, 이제 바인딩을 더하는 대신 그 Worker 자체를 걷는다.
- **1.0.8 이전 사용자 일부가 OTA 에서 떨어진다.** 결정 6.

## 기각

- **Cloudflare 에 계속 둔다.** 사용자 결정으로 기각. 옮기는 목적이 **운영자 기능을 우리가 통제하는
  자리에 두는 것** 이라, Worker 옆에 하나 더 두면 목적을 달성하지 못한다.
- **옛 OTA Worker 를 영구 유지한다.** 비용은 사실상 0 이고 1.0.8 미만 사용자를 안 버릴 수 있지만
  사용자가 걷기로 정했다(결정 6).
- **FCM 토큰 등록 + 개별 발송.** 결정 5. 결정 4 가 문턱을 낮췄는데도 타겟팅이 필요한 알림이 없다.
- **서버 코드를 이 저장소에 둔다.** 결정 3.
- **계정 백업·동기화를 지금 만든다.** 결정 4. 인증 수단이 없어 성립하지 않는다. 넥슨 OAuth 승인 뒤로
  미룬다.
- **수집을 기본으로 켜 둔다.** 결정 4. [[ADR-008]] 이 정한 기본값 OFF 를 따른다.
- **`ocid` 를 그대로 실어 보내고 서버에서 지운다.** 나가는 순간 이미 나간 것이라 기기에서 뗀다.

## 열린 질문

**답이 나온 것 셋은 결정 2·4 로 들어갔다.** 개인 API 키는 백업에 안 넣는다. 인증은 넥슨 OAuth
승인 뒤에 한다. Oracle 과 미니 PC 는 nginx 로 잇는다. 남은 것은 아래다.

- **데이터 안전 신고에서 `ocid` 를 무엇으로 분류하는가.** 공개 조회가 되는 값이지만 저장하면
  신고 대상이다. Play 의 분류표에서 어느 칸인지 정해야 하고, 처리방침에도 같은 말로 적어야 한다.
- **모은 가격이 앱으로 되돌아오는가.** 되돌아오면 이 앱에 처음으로 **시세표**가 생긴다.
  **[[ADR-006]] 은 여기 안 걸린다** - 그 문서가 정한 것은 `src/data/` 의 고정 참조표 셋이고, 드롭
  시세는 [[ADR-124]] 가 *"거래소 변동값이라 고정 참조표에도 담기지 않는다"* 며 이미 사용자 직접
  입력으로 빼놨다. 드롭 가격의 권위는 진작 앱 사용자에게 있다. 새로 생기는 질문은 다른 것이다.
  **여러 사람의 입력을 평균한 값을 앱이 보여주면 그것은 `이 사람이 판 값` 이 아니라 `시세` 로
  읽힌다.** [[ADR-124]] 결정 1 이 시세표를 거부한 이유(과거가 흔들린다)가 거기서 다시 걸린다.
- **넥슨 약관이 이 수집을 허용하는가.** 모으는 것이 게임 경제 데이터다. [[ADR-146]] 이 남긴 공지 API
  폴링 질문과 별개이고, 이쪽이 더 무겁다.
- **서버 데이터의 보관 기간.** 계정이 없어 삭제 요청 처리는 안 생기지만 수명은 정해야 한다.
- **옛 OTA Worker 를 언제 걷는가.** 유도 발송 뒤 며칠인지 몇 주인지. 결정 6 의 4번.
- **계약이 갈라지는 것을 어떻게 막는가.** 결정 3.
- **미니 PC 가 꺼져 있을 때 앱이 무엇을 보여주는가.** 수집은 조용히 실패해도 되지만 공지 푸시는
  다르다.
