# ADR-093 — 자산 최적화: PNG → WebP(q95) 변환은 **슬러그 키 디렉터리에만**

**날짜**: 2026-08-05
**상태**: **구현 완료** (2026-08-05) — dist **9.1 MB → 7.3 MB**([[ADR-092]] 전 기준으로는 12 MB → 7.3 MB, -39%). PNG 30개 변환(2.37→0.78 MB) + 고아 5개 삭제(0.23 MB). 테스트 2,253개 통과·lint clean. 변환본 30개 전부 **해상도 일치·필요한 투명도 보존** 확인. **실기기 미검증**
**관련**: [[ADR-092]](1단계 번들 분할 — 이 작업의 2단계) · [[ADR-011]](아이템 아이콘 `iconFile` 매핑) · [[ADR-021]](보스 일러스트에 png 혼재) · [[ADR-006]](게임 데이터·애셋은 사용자 확인) · [[ADR-048]](드랍 연출 프레임) · [[ADR-022]](OTA — dist 크기가 곧 다운로드 크기)

## 맥락

[[ADR-092]] 로 JS 는 갈랐지만 dist 9.1 MB 중 **이미지가 8 MB** 다. Capacitor 앱은 dist 를 통째로
싣고([[ADR-022]] 의 OTA 도 통째로 내려받는다) 이미지가 앱 크기의 대부분이다.

1단계 계획에는 "`import.meta.glob` 의 `eager: true` 를 lazy 로 바꾼다"가 들어 있었는데,
**측정해 보니 틀린 전제였다** — 아래 결정 3.

## 결정 1 — PNG → WebP(q95), 단 **슬러그 키 디렉터리에만**

`import.meta.glob` 로 모은 자산의 조회 키가 디렉터리마다 다르고, 그 차이가 변환 가능 여부를 가른다.

| 디렉터리 | 키 생성 | 변환 |
|---|---|---|
| `bosses/` `maps/` `maps/icons/` `themes/` | 파일명에서 **확장자를 떼어** 슬러그로 | **한다** |
| `items/` `items/rings/` | **확장자를 포함한 전체 파일명** (`urlsByFileName`) | **안 한다** |

`items/` 는 [[ADR-011]] 결정 6이 "이름 → 파일명 계산"이 아니라 "매핑 테이블 조회"로 정한 구조라
`boss-ring-boxes.json` · `item-icons.json` 의 `iconFile` 값(`"Cleansing_Ring.png"`)과
`lib/fixed-drops.ts`(`'sole_200.png'`)가 **확장자까지 박아 두고 있다.** 여기를 변환하려면 게임
레퍼런스 데이터를 함께 고쳐야 하는데([[ADR-006]] 대상), **얻는 것이 43 KB뿐이다.** 하지 않는다.

확장자를 떼는 쪽은 glob 패턴이 이미 `*.{webp,png}` 로 둘 다 받으므로([[ADR-021]] 이 png 를
섞으면서 그렇게 해 뒀다) **파일만 바꾸면 코드 변경이 0이다.**

**품질 q95** — 사용자가 비교 도구에서 직접 보고 정했다(2026-08-05). 각 이미지의 엣지 밀도가 가장
높은 구간(=압축이 가장 티나는 곳)을 잘라 원본과의 차이를 8~40배 증폭해 견줬다. q85 까지 내려도
추가 절감이 0.35 MB뿐이라 위험 대비 이득이 적다.

**대상 30개 파일 · 2.37 MB → 0.78 MB (절감 1.59 MB).** 변환해도 오히려 커지는 파일(작은 아이콘·
월드 엠블럼 등)은 제외한다 — WebP 컨테이너 오버헤드가 이득을 넘는 크기 대다.

## 결정 2 — JPG 애니메이션 프레임(`drop-effect/`)은 변환하지 않는다

0.58 MB 를 더 줄일 수 있지만 **이미 손실 압축이라 재인코딩이 2세대 손실**이다. [[ADR-048]] 이
"최적화본"으로 기록한 프레임들이고, 초당 11.5~15프레임으로 지나가는 연출이라 열화가 눈에 덜
띄는 대신 **검증도 어렵다**(느리게 돌려 한 프레임씩 볼 방법이 없다 — 그 도구가 [[ADR-092]] 에서
삭제된 `/debug/*` 계열이었다). 이득 0.58 MB 는 그 불확실성을 살 만큼 크지 않다.

### 정정(2026-08-05) — `drop-effect/` 도 변환한다 (열화를 실측해 보류를 해제)

보류 이유는 "2세대 손실이 얼마인지 **검증할 방법이 없다**"였다. 그것은 눈으로 볼 방법이 없다는
뜻이었지 손실이 크다는 근거는 아니었으므로, **PSNR 로 재서** 해소했다.

| 디렉터리 | 장수 | 현재 | q95 | 절감 | PSNR 평균 | PSNR 최악 |
|---|---|---|---|---|---|---|
| screen | 16 | 1,280 KB | 998 KB | 282 KB | 50.0 dB | 42.8 dB |
| pre | 8 | 106 KB | 44 KB | 62 KB | 46.0 dB | 42.6 dB |
| loop | 24 | 376 KB | 167 KB | 209 KB | 42.4 dB | 41.8 dB |
| end | 7 | 58 KB | 19 KB | 39 KB | — | 41.4 dB |

**최악 프레임도 41.4 dB** 로 시각적 무손실 기준(40 dB)을 넘는다. 게다가 이 프레임들은 초당
11.5~18장으로 지나가 한 장의 미세 차이가 더 안 보인다.

무손실 WebP 도 재 봤으나 **1.78 → 4.94 MB 로 2.8배** 커져 선택지가 아니다(JPEG 가 이미 버린
정보를 무손실로 다시 담는 셈이라 오히려 불리하다).

`lib/drop-effect-frames.ts` 의 glob 4곳을 `*.{jpg,webp}` 로 넓혔다 — 정렬은 `parseInt` 가 앞의
숫자만 읽어 확장자와 무관하다.

## 결정 3 — `eager: true` glob 을 lazy 로 바꾸는 것은 **효과가 없다** (계획 철회)

[[ADR-092]] 의 "2단계" 목록에 있었고 이 ADR 초안에도 있었으나, **실측으로 반증했다.**

`src/assets/bosses/` 의 35개 파일이 **참조 여부와 무관하게 전부 dist 로 emit**된다(참조 0건인
`mugong.png` 도 emit 됐다 — 세어서 확인). Vite 는 glob 패턴에 걸리는 파일을 **전부 에셋으로
내보내며**, `eager` 는 그 URL 문자열을 JS 에 인라인할지(`eager: true`) 동적 import 함수로
감쌀지(`eager: false`)만 정한다. 즉:

- **dist 크기**: 안 바뀐다 — 어느 쪽이든 전부 emit 된다.
- **런타임 다운로드**: 안 바뀐다 — 이미지는 `<img src>` 가 렌더될 때 받는다. eager glob 이 JS 에
  넣는 것은 **URL 문자열**이지 이미지 바이트가 아니다.
- 줄어드는 것은 URL 문자열 몇십 개뿐이다.

**그래서 자산에서 실제로 듣는 지렛대는 두 가지뿐이다 — 안 쓰는 파일을 지우는 것, 쓰는 파일을
작게 만드는 것.** glob 의 모양은 상관이 없다.

> 교훈: "eager 라서 번들에 다 들어간다"는 **JS 모듈에는 맞고 에셋에는 틀리다.** 에셋은 glob 이
> 참조하는 순간 emit 대상이고, 그 판정은 eager 여부보다 앞선다.

## 결정 4 — 참조 0건 자산 5개를 지운다

| 파일 | 크기 |
|---|---|
| `bosses/firehornDragon.png` | 61 KB |
| `bosses/stunDragon.png` | 54 KB |
| `bosses/sparkyDragon.png` | 52 KB |
| `bosses/hammerDragon.png` | 52 KB |
| `bosses/mugong.png` | 15 KB |

드래곤 4종이 남은 이유는 `ContentScreen.tsx` 의 `MAPLE_UNION_DRAGON_BOSS_SLUG = 'armorDragon'` —
**주간마다 실제 드래곤이 바뀌지만 API 가 어느 드래곤인지 알려주지 않아** 대표 일러스트 하나만
쓴다. 나머지는 후보로 들여왔다 미채택된 것이고, `mugong` 은 어디에도 쓰인 적이 없다.

직전 조사에서 이들이 "참조 1건"으로 잡혔던 것은 [[ADR-092]] 에서 삭제한 `BossCardPreview` 의
후보 슬러그 목록(`NEW_BOSS_PREVIEW_SLUGS`)이었다 — **디버그 도구가 자산을 살려두고 있었던 셈**이고,
그것이 지워지면서 비로소 고아로 드러났다. 사용자 확인 후 삭제([[ADR-006]], 2026-08-05).

## 회귀 방지

변환은 **파일만 바꾸고 코드를 안 바꾸기 때문에** 오히려 조용히 깨질 수 있다 — 슬러그 하나가
해석되지 않아도 화면에는 폴백(일러스트 없는 카드)이 뜰 뿐 에러가 나지 않는다.

그래서 **데이터에 선언된 모든 슬러그가 실제 URL 로 해석되는지**를 테스트로 세운다
(`weekly-bosses.json` 의 `portraitSlug` 전수 · 일일 퀘스트 지역 · 테마 배경). 기존 아이콘
테스트들은 대표 슬러그 한둘만 확인해 이 사고를 못 잡는다.

**투명도 검증** — 변환본 30개를 원본과 대조해 해상도 일치와 알파 보존을 전수 확인했다. `baekyeon`·
`senya` 처럼 RGBA 컨테이너지만 **실제 투명 픽셀이 없던**(alpha 최솟값 255) 파일은 WebP 가 쓸모없는
채널을 떨어뜨려 RGB 가 됐고 — 화면상 차이는 없다 — `arcanus` 처럼 실제 투명도가 있는 파일은
RGBA 로 보존됐다.

**남은 큰 덩어리는 JPG 1.9 MB**(전부 `drop-effect/` 연출 프레임)와 `sql-wasm.wasm` 0.62 MB 다.
전자는 결정 2로 보류, 후자는 SQLite 런타임이라 줄일 수 없다.
