# ADR-129 — 에셋 목록을 빌드 타임 글롭에서 **커밋된 생성물**로 옮긴다

- **상태**: 구현 완료 · 실기기 미검증 (2026-08-12)
- **맥락**: [[ADR-128]] 4단계 step 1 (`packages/app-rn` 화면 재작성의 선행 작업)
- **관련**: [[ADR-088]](테마 배경) · [[ADR-038]](드롭 연출 프레임) · [[ADR-125]](기능 안내 이미지) ·
  [[ADR-011]] 결정 6(`iconFile`) · [[ADR-093]](자산 최적화) · [[ADR-006]](게임 데이터)

## 문제

`packages/core` 는 에셋 목록을 `import.meta.glob` 으로 만든다(7개 모듈 · 275장). 그것은 **Vite 의
컴파일 타임 API** 라 Metro 에 짝이 없고, Expo 가 `import.meta` 자체는 채워 주지만 `glob` 이 없어
모듈을 **평가하는 순간** 죽는다:

```
TypeError: globalThis.__ExpoImportMetaRegistry.glob is not a function
```

3단계는 이것을 **앱 수준 치환표**(`packages/app-rn/core-shims.js`)로 막았다 — 다섯 모듈을 RN 구현으로
갈아끼우고 URL 을 전부 `null` 로 돌려줬다. 컴포넌트는 원본이 정의한 폴백을 타서 **깨지지는 않지만
그림이 없다**(보스 초상 `?` 원 · 아이템 회색 원 · 월드 엠블럼 생략 · 테마 배경 단색 · 드롭 연출 정적).

4단계 화면들은 그 그림이 **실제로 보여야 하는 자리**다. 더 미룰 수 없다.

## 결정

**빌드 타임이 아니라 커밋 타임에 목록을 만든다.** `scripts/generate-asset-manifest.mjs` 가 에셋
디렉터리를 훑어 `packages/core/src/assets/generated/*.ts` 를 쓰고, **웹과 RN 이 그 파일을 함께 쓴다.**
`import.meta.glob` 은 저장소에서 사라져 core 가 번들러 중립이 된다.

### 결정 1 — 생성물은 **한 벌**이다. 플랫폼별로 가르지 않는다

step 지시는 *"웹은 URL 문자열, RN 은 `require()` 결과"* 라며 값을 어떻게 가를지 고르라고 했는데,
**가를 필요가 없다는 것이 이 결정의 요점이다.** 생성물 안에는 평범한 ESM 에셋 import 만 있다:

```ts
import a0 from '../worlds/arcane.png'
export const WORLD_EMBLEM_ASSETS: Record<string, ImageAssetRef> = { "arcane": a0, … }
```

그 한 줄이 Vite 에서는 URL 문자열이 되고 Metro 에서는 에셋 id 가 된다 — **번들러가 이미 가르고
있다.** 파일 분리·플랫폼 확장자·조건부 export 중 무엇을 골라도 그것은 이미 갈린 것을 손으로 한 번
더 가르는 일이고, 목록이 두 벌이 되면 한쪽만 갱신되는 사고가 열린다(금지 사항이기도 하다).

`require()` 대신 ESM `import` 인 것은 Metro 가 둘 다 받기 때문이고(`data/feature-guides/**` 가 이미
그 형태로 이미지를 쓴다), 덤으로 웹 산출물이 옛 glob 전개와 **글자 그대로 같은 모양**이 된다.

### 결정 2 — 갈리는 것은 값이 아니라 **타입 한 줄**이다

조회 함수가 돌려주는 것이 무엇인지는 플랫폼마다 다르다. 그것만 `ImageAssetRef` 로 떼어 가른다:

| 파일 | 값 | 누가 보나 |
|---|---|---|
| `src/types/image-asset.ts` | `string` | 웹(Vite) — `vite/client` 가 에셋 모듈을 `string` 으로 선언 |
| `src/types/image-asset.native.ts` | `number` | RN(Metro) — `AssetRegistry` 에셋 id |

셋이 **같은 규칙**으로 고른다 — Metro·jest 는 원래 `.native.*` 를 먼저 보고, tsc 는
`packages/app-rn/tsconfig.json` 의 `moduleSuffixes: [".native", ""]` 로 맞췄다(그것이 없으면 타입만
웹 것을 믿어 *"타입은 통과하는데 런타임에 죽는"* 어긋남이 생긴다 — 3단계가 `ImportMeta.glob` 선언
때문에 실제로 안고 있던 함정이다).

**함수 시그니처는 그대로다**([[ADR-128]] 결정 4) — 이름·인자·`null` 계약 전부. 웹에서는 반환 타입도
글자 그대로 `string | null` 이라 `app-capacitor` 에서 보이는 변화가 **없다**. RN 에서만
`number | null` 이 되는데, 그건 두 플랫폼에서 *"에셋 참조"* 가 실제로 다른 물건이기 때문이고 그
사실을 타입이 숨기지 않는 편이 낫다.

RN 쪽에는 `packages/app-rn/asset-modules.d.ts`(`*.png`/`*.webp`/`*.jpg` → `number`)가 필요하다.
`vite/client` 를 통째로 들이는 안은 3단계가 이미 기각했다(RN 에서 사실이 아닌 앰비언트 타입이
함께 들어온다).

### 결정 3 — 생성물을 **커밋한다**. 그 대가는 테스트가 갚는다

빌드 시점 생성이 아니라 소스로 커밋한다 — RN 빌드 파이프라인이 저장소 밖(EAS·gradle)에서도 돌고,
생성 단계가 빠진 환경에서 **조용히 빈 목록**이 되는 것이 이 전환에서 가장 비싼 실패다. 생성 파일
머리에는 *"손으로 고치지 마라 · 만드는 법"* 을 박는다.

대가는 명확하다: **커밋한 목록은 반드시 낡는다.** 그림을 넣고 `npm run assets:gen` 을 안 돌리면
목록에 안 들어가고, 그때 화면은 **에러 없이 폴백만** 그린다(자산은 코드를 안 바꿔 조용히 깨진다 —
[[ADR-093]] 이 같은 이유로 슬러그 전수 해석 테스트를 세웠다). 그래서
`src/assets/generated/__tests__/asset-manifest.test.ts` 가 디렉터리를 직접 읽어 **키 집합**을 대조하고,
프레임은 개수와 `0..n-1` 연속성까지 본다. 훑는 규칙은 생성기와 **같은 표**(`src/assets/asset-groups.ts`)를
읽는다 — 규칙을 한 번 더 적으면 그 사본이 낡았을 때 *"검사는 통과하는데 목록은 틀린"* 상태가 된다.

판별력은 실측했다 — 파일을 하나 넣으면 키 검사가, 프레임을 하나 넣으면 개수 검사가 깨진다.

### 결정 4 — 치환 표는 **비우되 지우지 않는다**

다섯이 전부 필요 없어져 `SHIMMED_CORE_MODULES` 가 `[]` 가 됐다. 그래도 파일과 배선(Metro
`resolveRequest` + jest `moduleNameMapper`)은 남긴다 — **벽이 하나 더 있기 때문이다.**
`import.meta.env` 도 Vite 전용이고(`features/live-update/store.ts` 가 모듈 최상위에서 읽는다,
[[ADR-024]]) RN 에서 그 스토어를 값으로 import 하면 그 자리에서 죽는다. OTA 를 이을 때
([[ADR-128]] 결정 7) 이 표가 그 자리를 맡을 가능성이 크고, 배선을 지웠다 다시 만드는 것보다 **비어
있다는 사실을 테스트로 적어 두는** 편이 정직하다.

「core 의 glob 모듈 여덟 개」를 고정하던 테스트는 **「0이어야 한다」로 뒤집었다**(지우지 않았다) —
감시 대상이 사라진 것이 아니라 *"없는 상태가 유지되는가"* 가 감시 대상이 됐다. `ImportMeta.glob`
타입 선언도 함께 지워, 이제 core 에서 글롭을 쓰면 **tsc 가 먼저 막는다**(방어가 두 겹이다).

### 결정 5 — 여덟 번째 모듈은 **오탐이었다**

3단계가 고정한 여덟 목록에 `data/feature-guides/index.ts` 가 있었지만, 그 파일은 글롭을 쓰지 않는다 —
*"쓰지 않는 이유"* 를 적은 **주석**이 문자열 검사에 걸린 것이다(실제 사용처는 `__tests__` 안의
데이터 테스트이고 그쪽은 vitest 전용이라 RN 과 무관하다). 다만 이 파일은 **에셋을 나르는 것이 맞아서**
[[ADR-125]] 결정 4 의 명시적 import 는 그대로 두고 `FeatureGuideImage.src` 의 타입만
`string` → `ImageAssetRef` 로 바꿨다. `assets/guide/` 는 슬러그로 찾는 곳이 아니므로 **생성 목록에
넣지 않는다** — 파일명이 틀리면 조용히 통과하는 대신 빌드가 실패해야 한다는 그 결정이 그대로 산다.

## 기각한 안

**① 에셋 해석을 포트로 뒤집는다**(3단계 주석이 *"제대로 된 답"* 으로 적어 둔 것). core 인터페이스가
늘어난다 — [[ADR-128]] 결정 4 는 어댑터 시그니처를 한 글자도 안 바꾸는 것이 141개 파일 중 117개가
무수정으로 사는 **유일한 조건**이라고 못박았다. 포트를 하나 늘리면 그 조건이 흔들리고, 무엇보다
필요가 없다 — 값을 가르는 일은 이미 번들러가 한다(결정 1).

**② `packages/app-rn` 전용 맵을 둔다**(3단계가 실제로 한 것의 확장판). 목록이 **두 벌**이 되어 한쪽만
갱신하면 조용히 어긋난다. 이 저장소는 같은 형태를 이미 두 번 거부했다 — 테마 토큰([[ADR-064]]
결정 10, *"개별 파일을 손으로 동기화하지 않는다"*)과 라우트 표([[ADR-128]] 3-2단계, *"손으로 적으면
계획서 17행과 화면 목록이 두 벌이 된다"*). 게다가 그 맵을 채우는 순간 [[ADR-011]]·[[ADR-041]] 의
이름→파일 규칙까지 복제하게 된다.

**③ `require.context`**(Metro 의 글롭 짝). Metro 엔 있어도 **jest 에 없다**(실측:
`require.context is not a function`) — *"앱은 도는데 테스트만 죽는"* 형태이고 `core-shims.js` 가
그것을 피하려고 만들어졌다.

**④ RN 에서도 값을 문자열로 맞춘다**(`Image.resolveAssetSource(require(…)).uri`). `ImageAssetRef`
분기가 통째로 사라지지만, core 안에 `react-native` import 가 들어오고 275장을 모듈 로드 시점에 전부
해석해야 하며, [[ADR-048]] 이 필요로 하는 **프레임 비트맵 고유 크기**를 버리게 된다.

## 대가

- **`npm run assets:gen` 을 잊으면 목록이 낡는다.** 결정 3 의 테스트가 그것을 잡지만, 잡는 것은
  *"CI 에서"* 이지 *"넣는 순간"* 이 아니다.
- **RN 에서 반환 타입이 `number` 다.** `<Image source>` 에 그대로 넣어야 하고 원격 URI 처럼
  `{ uri }` 로 감싸면 **조용히 안 뜬다**(`CharacterTrackingGrid` 가 실제로 그 한 줄을 고쳤다 — 같은
  컴포넌트 안에서 얼굴은 원격 URI, 엠블럼은 번들 에셋이라 두 형태가 공존한다).
- **jest 의 값은 숫자가 아니다.** RN 프리셋의 에셋 트랜스포머가 `{ testUri }` 라는 테스트 대역을
  준다 — 타입은 앱이 보는 값을 적고, 테스트는 그 대역의 경로로 *"어느 파일로 해석됐는가"* 를 본다.
- **`moduleSuffixes` 가 RN 프로그램 전체에 걸린다.** 지금은 `image-asset` 한 쌍만 쓰지만 규칙 자체는
  전역이다(RN 표준 설정이라 놀랄 일은 아니다).
- **에셋 폴더에 떨어진 파일은 아무도 안 써도 번들에 실린다** — glob 시절과 같다. 판정 주체가 glob
  에서 생성물의 import 목록으로 바뀌었을 뿐이라 [[ADR-093]] 의 결론(*"지렛대는 안 쓰는 파일 삭제와
  쓰는 파일 축소 둘뿐"*)은 그대로다.

## 폐기하는 것

- **없다.** [[ADR-088]] 결정 3(*"테마 추가는 JSON 한 블록"*)·[[ADR-093]] 결정 1(디렉터리마다 다른
  조회 키)·[[ADR-125]] 결정 4(안내 이미지는 명시적 import)는 전부 그대로 선다. 바뀐 것은 목록을
  **만드는** 방법이지 **묻는** 방법이 아니다.

## 검증

- **웹 산출물이 이전과 같다** — `dist` 의 에셋 126개가 **이름·해시까지 완전히 동일**(shasum 대조).
  JS 청크는 내용이 줄어 해시가 바뀌었다(런타임 경로→슬러그 루프가 사라졌다):
  `screen-profit` 438.40 → 433.29 kB · `screen-boss` 214.66 → 212.83 kB · `index` 246.96 kB 무변화 ·
  dist 총량 7.4 MB 유지.
- vitest **199파일/3046개 → 200파일/3056개**(순증 10 = 이 결정이 더한 낡음 방지 테스트) ·
  jest **693 → 705개** · `tsc` 0 · lint 0 errors/17 warnings(baseline 동일).
- `expo export`(android) 성공. 앱 진입에서 닿는 것은 테마 배경 2장뿐이라(화면이 아직
  자리표시자다) 나머지 여섯 목록은 **임시 진입점으로 확인**했다 — 250장이 전부 번들에 실렸다
  (bosses 30 · drop-effect 55 · items 99 · maps·icons 49 · themes 2 · worlds 15).
- `grep -rn "import.meta.glob" packages/core/src packages/app-capacitor/src | grep -v __tests__` → **0건**.

## 미검증

- **실기기에서 그림이 실제로 뜨는지 본 적이 없다.** `expo export` 는 번들에 들어간 것까지만 말한다.
- **월드 엠블럼 말고는 아직 아무것도 안 그린다.** 보스 초상·드롭 연출 프레임·테마 배경은 값이 왔지만
  CSS 기하(`background-size`/`position`, [[ADR-048]] origin)를 RN 으로 옮기는 일이 남아 있고, 그것은
  화면 작업의 범위다. 각 컴포넌트 주석이 *"무엇이 막고 있는지"* 를 갱신해 두었다.
- **`assets:gen` 을 잊는 사고를 실제로 겪어 보지 않았다** — 테스트의 판별력만 확인했다.
