# ADR-154: 캐패시터 앱의 종료 — 스토어 유도는 버전이 아니라 매니페스트의 «플랫폼 목록» 이 켠다

**날짜**: 2026-08-21
**상태**: 결정 · **1단계 완료**(2026-08-21 — `1.0.6.zip` 업로드, 매니페스트 미발행) · 2·3단계는 스토어 게시 대기
**관련**: [[ADR-128]](RN 전환 — 이 ADR 이 그 5단계의 마지막 고리다) · [[ADR-022]](자체 호스팅 OTA) ·
[[ADR-024]](버전 형식·채널) · [[ADR-026]](관찰용 UI·캐시 우회) · [[ADR-027]](사용자 동의형 UX ·
결정 7 이 `minNativeVersion` 을 만들었다) · [[ADR-119]]·[[ADR-126]](릴리스 노트 원천 한 벌 ·
`highlights`) · [[ADR-137]](RN 쪽 OTA — 이 앱과 프로토콜이 다르다)

## 맥락

RN 전환이 끝났다. 스토어에 올라가는 바이너리는 이제 `app-rn` 이고([[ADR-128]]), 같은
`com.mapleroutine.app` 이라 기존 사용자는 **스토어 업데이트 한 번으로** 새 앱을 받는다.

문제는 스토어 업데이트를 **안 하는 사람**이다. 그들에게 남은 캐패시터 앱은 더 이상 갱신되지 않는데,
부팅마다 도는 OTA 확인은 여전히 매니페스트를 읽고 **「최신 버전입니다」** 라고 답한다. 갱신이 끝난
앱이 스스로를 최신이라 부르는 것은 거짓이고, 그 거짓이 사용자를 옛 앱에 붙잡아 둔다.

그래서 **캐패시터 OTA 를 «업데이트를 나르는 관» 에서 «스토어로 보내는 관» 으로 용도 변경**한다.
이것이 이 앱에 마지막으로 하는 일이고, 그 뒤 `packages/app-capacitor` 는 저장소에서 사라진다.

### 두 플랫폼의 «준비되는 시점» 이 다르다 — 그리고 **둘 다 아직이다** (2026-08-21 실측)

| | 조회 | 결과 | 유도해도 되나 |
|---|---|---|---|
| Android | Play 상세 페이지 | **HTTP 404** — 공개 게시 없음 | **아직** |
| iOS | iTunes Lookup `id6797579391` | `메이플루틴` **1.0.0** (2026-08-06) | **아직** |

**추측이 아니라 조회한 값이다.** 계획 초안은 «Android 는 지금 유도 가능» 을 전제했는데 그 전제가
틀렸다 — 지금 어느 쪽이든 목록에 넣으면 **스토어에 받을 것이 없는 곳으로 보낸다.**

이것이 아래 결정 4 의 단계를 셋으로 가른 이유다. 그리고 그것이 **손해가 아니다** — 게이트를 끈 채
번들만 먼저 내보내면 «읽는 코드를 심는 일» 과 «유도를 켜는 일» 이 갈라져서, **스토어 상태를 하나도
기다리지 않고** 캐패시터 소스를 지울 수 있다.

### 기존 장치(`minNativeVersion`)로는 안 된다 — 이유 둘

[[ADR-027]] 결정 7 이 만든 `minNativeVersion` 이 하는 일이 정확히 「스토어 업데이트 필요」 분기다.
그런데 이번 용도에는 두 군데서 안 맞는다.

**① 플랫폼을 못 가른다.** 매니페스트는 URL 이 **한 개**이고 GitHub Releases 는 정적 호스트라
요청에 따라 다른 파일을 내줄 수 없다(RN 쪽이 `latest-{ios,android}.json` 으로 갈라진 것은 앞에
Cloudflare Worker 가 있어서다 — [[ADR-137]]). `minNativeVersion` 은 필드 하나라 켜는 순간
**양 플랫폼에 동시에** 걸린다.

**② 버전 축을 소비한다.** `check()` 는 `isNewerVersion(bundle.version, manifest.version)` 이
false 면 `minNativeVersion` 을 **보기도 전에** `up-to-date` 로 돌아간다. 즉 게이트를 켜려면 매번
매니페스트 버전을 올려야 하고, **이미 그 버전을 받은 사람에게 다시 켜려면 또 한 칸 올려야 한다.**

이번엔 그 칸이 없다. **iOS 심사 중인 스토어 바이너리가 1.0.6 이라 OTA 버전이 그 위로 올라가면
안 된다**(사용자 결정, 2026-08-21) — 스토어에 없는 버전을 앱이 자기 버전으로 부르게 된다.

## 결정

### 결정 1 — 매니페스트에 `storeRequiredPlatforms?: string[]` 을 둔다

```jsonc
{
  "version": "1.0.6",
  "url": "...", "checksum": "...", "size": 6300000,
  "storeRequiredPlatforms": ["android"],   // ← 이 목록에 든 플랫폼은 스토어로 보낸다
  "highlights": ["..."]
}
```

값은 `Capacitor.getPlatform()` 이 돌려주는 문자열(`'android'` · `'ios'`)이다. 판정은 포함 여부
하나뿐이라 규칙이 매니페스트를 읽는 것만으로 다 드러난다.

**`minNativeVersion` 을 확장하지 않고 새 필드를 둔 이유**는 둘이 답하는 질문이 다르기 때문이다 —
그쪽은 *"이 번들을 적용할 수 있는가"*(번들의 성질)이고, 이쪽은 *"이 플랫폼이 아직 이 앱을 쓰는
것이 맞는가"*(앱의 수명)다. 한 필드에 두 뜻을 얹으면 나중에 읽는 사람이 어느 쪽인지 못 가린다.
`minNativeVersion` 은 **지우지 않는다** — 읽는 코드도 테스트도 그대로 두고, 이번에 쓰지 않을 뿐이다.

### 결정 2 — 판정을 **버전 비교보다 앞에** 둔다

```ts
const { bundle, native } = await CapacitorUpdater.current()

// ① 스토어 유도 — 갱신이 끝난 플랫폼에 「최신입니다」는 거짓이므로 버전 비교보다 앞이다.
if (manifest.storeRequiredPlatforms?.includes(Capacitor.getPlatform())) {
  return { kind: 'store-required', version: manifest.version }
}

// ② 이하 종전
if (!isNewerVersion(bundle.version, manifest.version)) return { kind: 'up-to-date' }
if (manifest.minNativeVersion && isNewerVersion(native, manifest.minNativeVersion)) { ... }
```

순서가 곧 이 결정이다. 두 가지를 한꺼번에 얻는다.

- **거짓을 없앤다.** 갱신이 끝난 플랫폼에 `up-to-date` 를 돌려주지 않는다.
- **버전 축을 안 쓴다.** `manifest.version` 이 사용자의 번들 버전과 **같아도** 게이트가 켜진다.
  그래서 1.0.6 에 고정해 둔 채로 플랫폼만 늘렸다 줄였다 할 수 있다 — 위 「맥락 ②」가 막고 있던
  것이 정확히 이것이다.

`minNativeVersion` 분기는 **그 자리에 그대로 둔다**(②의 마지막 줄). 그것은 버전이 올라갈 때의
판정이라 ① 뒤에 있어도 뜻이 안 바뀐다.

### 결정 3 — 선택 필드다. 필수 검사에 넣지 않는다

`parseLiveUpdateManifest` 의 `version`·`url`·`checksum`·`size` 4종 필수 검사에 **넣지 않는다**.
[[ADR-119]] 결정 5 가 `highlights` 에 대해 말한 것과 **글자 하나 다르지 않은 이유**다 — 매니페스트는
URL 고정·내용 가변이라 «옛 앱이 새 파일을 읽는» 조합이 실재하고, 필수로 만들면 그 순간 기존
설치본 전부가 파싱 실패(`null` → `check-error`)로 떨어진다.

배열이 아니거나 원소가 문자열이 아니면 **필드가 없는 것과 같게** 다룬다(`highlights` 의 빈 배열
처리와 같은 자리, 같은 방식).

### 결정 4 — 번들 배포는 **한 번**, 플랫폼을 늘리는 것은 **매니페스트 한 줄**

| | 하는 일 | 캐패시터 소스 | 사용자에게 보이는 것 | 조건 |
|---|---|---|---|---|
| **1단계** ✅ 완료 | `1.0.6.zip` **업로드만**, `latest.json` 손 안 댐 | **필요** | **없음** | 없음 |
| **2단계** | 초안에 `storeRequiredPlatforms: ["android"]` 넣어 발행 | 불필요 | 유도 | Play 게시 확인 |
| **3단계** | `["android","ios"]` 로 | 불필요 | 유도 | App Store 게시 확인 |

**1단계가 매니페스트를 발행하지 않는 것이 요점이다.** 처음 초안은 «게이트만 끈 정상 배포» 였는데,
그러면 사용자에게 **받을 이유가 없는 6MB 업데이트**를 권하게 된다 — 이 번들의 payload 는 게이트를
읽는 코드와 결정 6 의 링크 수정뿐이라 **화면에 아무것도 안 나타난다**(사용자 지적, 2026-08-21).
동기 없는 업데이트는 안 받히므로 «미리 받아 두게 해서 도달률을 올린다» 는 이득도 환상이었다.

그래서 **zip 만 올리고 매니페스트는 유도가 실제로 필요한 시점에 한 번 발행한다.** 얻는 것 셋:

- **지금 사용자 영향이 0 이다** — `latest.json` 이 1.0.5 그대로라 모달이 안 뜬다.
- **문구 문제가 원인에서 사라진다** — 캐패시터에만 있는 항목을 나열할 자리가 없어지고,
  2·3단계에서는 「스토어에서 업데이트해 주세요」가 **참**이다(결정 7).
- **소스 삭제가 스토어 일정에서 풀린다** — 다시 계산할 수 없는 값(`url`·`checksum`·`size`)이
  이미 `ota/latest.json` 에 적혀 있다.

### `ota/latest.json` — 소스를 지운 뒤 유도를 켜는 유일한 재료

`--bundle-only` 가 이 파일을 저장소에 남긴다. 그 값들은 **그 빌드에서만** 나오므로 캐패시터
소스가 사라진 뒤에는 재생성할 방법이 없고, 이 파일이 깨지면 이미 올라간 `1.0.6.zip` 이
**아무도 못 받는 번들**이 된다. 그래서 형식을 테스트가 지킨다
(`scripts/__tests__/publish-live-update.test.mjs` — 앱 파서 통과 · 게이트가 아직 꺼져 있음 ·
`url`/`checksum`/`size` 형식).

켤 때는 그 파일에 필드 하나를 넣고:

```
gh release upload live-update-latest ota/latest.json --repo jini520/maple-routine --clobber
```

2·3단계가 `gh release upload ... latest.json --clobber` 한 줄인 것이 이 설계의 핵심 이득이다 —
**1단계 직후 `packages/app-capacitor` 를 지워도 나머지를 칠 수 있고, 어느 스토어도 기다리지
않는다.** 종전 계획(`--min-native` 게이트)은 게이트를 켜는 시점에도 빌드가 필요해 «캐패시터를
지우는 것» 과 «유도를 켜는 것» 이 서로를 기다렸다.

### 결정 5 — 되돌릴 수 있다

매니페스트에서 플랫폼을 빼면 원복된다. 종전 계획의 `--min-native 1.0.6` 은 **되돌릴 수 없는
지점**이었다 — 한 번 켜면 그 버전 이하의 모든 설치본이 영구히 게이트에 걸리고, 풀려면 `1.0.7` 번들을
새로 태워야 했다(= 캐패시터 소스를 계속 살려 둬야 했다).

이것이 결정 2 의 순서에서 **공짜로 따라온다**. 판정이 버전이 아니라 목록이라, 목록은 양방향이다.

### 결정 6 — `APP_STORE_ID` placeholder 를 이 번들에서 고친다

`capacitor-live-update.ts:21` 의 `APP_STORE_ID = '0000000000'` 은 스토어 미출시 시절의
placeholder 이고, 그 탓에 **iOS 「스토어로 이동」이 죽은 링크**다(Android 는
`market://details?id=…` 라 무관).

**이 수정은 1단계 번들에 실려야만 한다.** 2단계에서 게이트가 켜지면 새 번들은 다운로드 자체가
안 되므로, 그때 고쳐 봐야 사용자 기기에는 영영 안 닿는다. 실제 값은 `6797579391` 이고 RN 어댑터에
이미 박혀 있다(`rn-live-update.ts:186`).

### 결정 7 — 매니페스트에 실을 `highlights` 는 배포 인자로 덮어쓴다

1.0.6 의 노트는 **RN 의 것**이다 — `today 페이지 추가` · `여러 메이플 ID의 캐릭터를 함께 관리`
셋은 캐패시터 번들에 **없는 기능**이다(`app-capacitor/src/app/` 에 `today/` 가 없고 다계정 UI 도
없다. `보스 「벨로나」 추가` 만 core 게임 데이터라 실제로 들어간다).

- **[[ADR-119]] 결정 1(원천 한 벌)은 안 깨진다.** `release-notes.ts` 는 그대로 두고, 배포 가드
  (노트·핵심 목록이 없으면 중단 — [[ADR-119]] 결정 6 · [[ADR-126]] 결정 8)도 그대로 돈다.
  바뀌는 것은 **매니페스트에 싣는 값** 하나다.
- 이 예외가 정당한 이유는 **한 버전 번호를 두 앱이 나눠 쓰게 된 것**이 이번뿐이기 때문이다.
  그리고 이 앱은 이 배포 이후 존재하지 않는다.
- **1단계는 게이트가 꺼진 정상 배포라 문구도 «스토어로 가라» 가 아니다** — 그 시점엔 스토어에
  받을 것이 없어 그렇게 쓰면 그것이 거짓이 된다. 이 번들이 캐패시터 사용자에게 실제로 주는
  것만 적는다(1.0.5 이후 core 30커밋 중 사용자에게 보이는 것 — 벨로나 · 캐릭터 목록 로딩).
- 2·3단계에서 게이트가 켜지면 모달은 `store-required` 분기로 갈리고 **highlights 를 아예 안
  보여준다** — 그때는 이 문구가 쓰이지 않는다.

### 결정 8 — 캐패시터 전용 진입점을 새로 만들지 않는다

「스토어로 가세요」 전용 화면·배너를 새로 그리지 않는다. `store-required` 모달은 [[ADR-027]] 결정 7
부터 있었고 문구·버튼·스토어 이동이 이미 다 붙어 있다. **지울 코드에 새 UI 를 그리는 것은
투자가 아니다.**

## 대가

- **Android 유도가 즉시가 아니다 — OTA 한 홉이 필요하다.** `storeRequiredPlatforms` 를 읽는
  코드가 1.0.6 번들에 있으므로, 1.0.5 에 있는 사람은 그 번들을 받아야 게이트에 들어온다.
  즉시 걸 수 있는 유일한 장치가 `minNativeVersion` 인데 그것은 「맥락 ①」대로 iOS 까지 함께
  건다. **그래서 이 대가를 고른 것이다.**
  - 홀드아웃이 방치되지는 않는다 — 그들은 부팅마다 `update-available` 모달을 받는다. 받으면
    게이트로 들어오고, 안 받으면 다시 묻는다.
  - **1단계와 2·3단계 사이에는 이 대가가 없다** — 그 구간에 게이트가 꺼져 있어 잃는 것이 없고,
    그 사이 사용자가 1.0.6 을 받아 둘수록 게이트를 켜는 순간의 도달률이 올라간다. **먼저
    내보낼수록 유리하다**는 것이 단계를 셋으로 가른 두 번째 이득이다.
- **iOS 사용자도 1.0.6 번들을 받는다.** 그들에게 이 번들의 실질 내용은 결정 6 의 링크 수정
  하나뿐이다. 그 다운로드를 없앨 방법은 없다 — 매니페스트가 한 벌이라 «iOS 에게만 안 알리기» 가
  프로토콜에 없다.
- **`storeRequiredPlatforms` 를 읽는 코드는 캐패시터 앱에만 생긴다.** RN 은 프로토콜이 달라
  이 필드를 모른다([[ADR-137]]). 곧 지울 앱에 필드를 하나 더하는 셈이지만, 대안이 전부 버전 축을
  쓰거나 빌드를 한 번 더 요구한다.

## 대안과 기각

- **매니페스트를 Cloudflare Worker 뒤로 옮겨 플랫폼별로 가른다** — RN 이 쓰는 구조 그대로다
  (`workers/ota-manifest/`). 기각: **URL 이 사용자 기기의 번들에 박혀 있어** 새 URL 은 1.0.6 을
  받은 사람에게만 유효하다. 즉 이 안도 「OTA 한 홉」을 못 없애면서 워커 엔드포인트·배포 경로를
  더 만든다. **곧 지울 앱을 위해 인프라를 늘리는 것**이라 결정 1 이 하는 일과 이득이 같고 비용만 크다.
- **`--min-native 1.0.6` 을 지금 발행한다**(종전 계획) — 기각: iOS 가 함께 걸린다. 심사 중이라
  보낼 곳이 없고, 결정 6 의 링크 수정이 실리지 않은 상태라 버튼도 죽어 있다.
- **캐패시터 최종분을 1.0.7 로 올린다** — 기각: 사용자 결정(2026-08-21). iOS 스토어 심사 버전이
  1.0.6 이라 OTA 가 그 위로 가면 버전 축이 어긋난다.
- **`highlights` 를 아예 싣지 않는다**(모달이 버전·용량만 표시 — [[ADR-126]] 결정 6) — 거짓말은
  안 하지만 **1.0.5 홀드아웃에게 갈 안내가 사라진다.** 결정 7 이 그 자리를 쓴다.

## 열린 질문

- 2·3단계를 치는 시점 — 각 스토어가 **라이브** 가 된 뒤다. 심사 통과 알림이나 콘솔 상태가 아니라
  **실제 게시를 조회해** 확인하고 친다(위 실측과 같은 방법: Play 상세 페이지 HTTP 코드 ·
  iTunes Lookup 의 `version`).
- 캐패시터 OTA 릴리스(`live-update-latest`)의 zip 정리 — 게이트가 켜진 뒤로는 어떤 번들도
  다운로드되지 않으므로 1.0.6 하나만 남기고 지울 수 있다. 2단계 이후 판단한다.
