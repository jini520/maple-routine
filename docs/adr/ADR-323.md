# ADR-323: 짧은 변이 600 미만인 화면은 세로로 고정한다

> 🟢 유효 · **구현 완료** 2026-09-29(`AndroidManifest.xml` · `AppDelegate.swift`) · 실기기 미검증 · 이슈 #532

**관련**: [[ADR-302]](입력 카드) · [[ADR-194]](읽히게 쓰기)
**문서**: `foundation/design-system.md` 의 레이아웃 절
**이슈**: #532 · 별개로 남는 것 #530(낮은 화면에서 카드 · 모달의 높이 상한)

## 맥락

앱은 가로 회전을 전혀 막지 않았다. `app.json` 은 `"orientation": "default"`, 안드로이드 매니페스트는
`android:screenOrientation="unspecified"`, iOS `Info.plist` 는 방향 넷을 다 연다. 런타임 잠금 코드도 없다.

그런데 `src/` 에는 가로 설계가 없다. 창 폭 · 높이로 분기하는 코드가 없고, 하단바 높이는 창 폭에서만
내며(`lib/bottom-bar-metrics.ts`), today 위젯 격자의 행 높이는 고정이다
(`lib/today/widget-grid-metrics.ts`). 그래서 바형 폰을 눕히면 입력 카드 · 모달 · 팝오버가 잘린다.

막을 곳은 바형 폰이다. 태블릿과 접는 폰의 펼친 화면은 돌 수 있어야 한다. 두 플랫폼 모두 그런
기기를 앱 쪽에서 세로로 묶는 것을 막거나 권하지 않는다.

### 결정 1. 경계는 짧은 변 600 이다

**짧은 변이 600dp / 600pt 이상이면 회전을 허용하고, 아니면 세로로 고정한다.**

600 은 안드로이드 OS 가 이미 쓰는 수다. Android 16 부터 targetSdk 36 앱은 짧은 변이 600dp 이상인
화면에서 `screenOrientation` 을 무시한다. 이 앱은 targetSdk 36 이다(병합된 매니페스트에서 확인).
iOS 도 같은 수를 적어 두 플랫폼의 경계를 맞춘다.

기기 치수를 넣으면 이렇게 갈린다. 폴드 8 인너(약 816×616dp)와 아이폰 듀오 인너(약 626×890pt)는
돌고, 두 커버 화면(약 416dp · 466pt)과 바형 폰(360~410)은 세로로 묶인다. **아이폰 듀오의 pt 와
폴드 8 커버의 DPR 은 발표값이 아니라 픽셀에서 나눈 추정이다.** 실기기나 시뮬레이터로 확인해야 한다.

### 결정 2. 안드로이드는 매니페스트에 `portrait` 하나만 적는다

`MainActivity` 의 `android:screenOrientation` 을 `portrait` 로 바꾼다. 600dp 이상의 화면에서 이 값을
무시하는 것은 OS 가 한다. 앱이 조건을 적을 필요가 없다.

**Android 16 의 임시 opt-out 을 켜지 않는다.** Android 17 이 그 opt-out 을 없앤다. 켜 두면 그때
큰 화면에서 한 번 더 동작이 바뀐다.

### 결정 3. iOS 는 `AppDelegate` 가 좁힌다. `Info.plist` 는 그대로 둔다

`ios/app/AppDelegate.swift` 에서 `application(_:supportedInterfaceOrientationsFor:)` 를 덮어쓴다.
화면의 짧은 변이 600pt 미만이면 `.portrait` 를 돌려주고, 아니면 `ExpoAppDelegate` 의 기본 동작
(`Info.plist` 의 방향 넷)을 돌려준다.

`Info.plist` 로 잠그지 않는 이유는 `~ipad` 접미사가 아이패드만 가르기 때문이다. 접는 아이폰은
phone idiom 이라 plist 로 잠그면 펼친 화면까지 잠긴다. 델리게이트는 plist 가 연 방향 안에서만
좁힐 수 있으므로 **plist 의 방향 넷은 지우면 안 된다.**

짧은 변은 창이 아니라 **화면**에서 잰다. 아이패드 분할 화면에서는 창이 좁아져도 기기는 그대로
돌 수 있어야 한다.

### 결정 4. `app.json` 의 `orientation` 은 안 고친다

그 값은 `expo prebuild` 가 네이티브 파일로 옮기는 재료다. 이 저장소는 prebuild 를 돌리지 않는다.
돌리면 손으로 쓴 안드로이드 파일과 릴리스 서명이 지워진다. 네이티브 파일을 직접 고친다.

## 대가

- 스토어 빌드에 묶인다. 매니페스트 · Swift 는 바이너리 쪽이라 OTA 로 못 나간다
- `app.json` 의 `orientation` 이 네이티브 파일과 다른 값을 들고 있다(결정 4)
- 회전을 허용하는 큰 화면(폴드 인너 · 태블릿)의 가로 레이아웃은 여전히 설계가 없다. 높이 상한은 #530 이 다룬다
- **실기기 미검증**. 바형 폰에서 회전이 막히는지, 큰 화면에서 도는지 확인해야 한다
