### ADR-049: 보스 수익 — 헤더 정렬·유격 4종 정리(새로고침 30px 인라인화, 뱃지 absolute, 셸 `overflow: clip`, 보스 행 높이 고정) (구현 완료, 2026-07-28)

**배경**: 보스 수익 화면의 레이아웃 유격·모서리 아티팩트 4건을 사용자가 실측해 보고했다. 모두 "기능은 멀쩡한데 픽셀이 어긋난다" 부류라 원인을 값으로 특정할 수 있다.

| # | 증상 | 실측 |
|---|---|---|
| 1 | 새로고침 영역이 제목 줄에 따로 있어 세로 공간을 한 줄 더 먹는다 | 새로고침 블록 32px vs 주간/월간 탭 30px |
| 2 | 고가 뱃지 유무로 "OO 총 수익" 라벨행 높이가 튄다 | 라벨 16px vs 뱃지 24px |
| 3 | sticky 카드 헤더의 모서리로 콘텐츠가 지나가고, 카드 끝에서는 모서리가 뾰족해진다 | 헤더 `rounded-t-[14px]`만 있고 하단 라운딩 없음 |
| 4 | 아코디언 보스 행 높이가 제각각 | 91.5px(기본) / 89px(드롭 있음) / 90.5px(마지막 행) |

**결정**:

1. **새로고침 영역을 주간/월간 탭 줄로 이동하고 높이를 30px로 맞춘다.** 제목 줄에서 떼어내 탭 줄 우측(`ml-auto`)에 붙인다. 버튼이 `p-2`(아이콘 16px + 패딩 16px = **32px**)라 그대로 옮기면 탭 줄 높이가 30 → 32px로 커져, **새로고침이 없는 과거 기간**(`isCurrentPeriod === false`)과 2px 어긋난다. 버튼을 `p-2` → `flex h-[30px] w-[30px] items-center justify-center`로 바꿔 활성 탭 pill(`py-[5px]` + `text-sm` 20px = 30px)과 같은 높이로 고정한다. 옆의 동기화 시각 텍스트는 20px라 블록 높이에 영향이 없다.

2. **총 수익 라벨행의 고가 드롭 뱃지를 `absolute`로 띄운다.** 라벨(`text-xs` = 16px)과 뱃지(아이콘 20px + `py-0.5` = 24px)가 같은 flex 줄에 있어 뱃지가 뜨면 줄 높이가 16 → 24px로 뛰었다. 라벨행을 `relative flex items-center`로 두고 뱃지에 `absolute right-0 top-1/2 -translate-y-1/2`를 주어 **레이아웃 흐름에서 뺀다** — 줄 높이는 항상 16px. 뱃지에 **탭 시 확대 애니메이션을 붙일 예정**이라(별도 문서화 예정) 크기 변화가 주변 레이아웃을 밀지 않아야 한다는 요구가 이 선택의 본질적 이유다.

3. **펼침 셸에 `overflow: clip`을 걸어 모서리 클리핑을 되살린다** — [[ADR-047]] 결정 2의 "셸에 `overflow-hidden` 금지"를 **`clip`으로 우회**한다.
   - **문제(상단)**: stuck된 헤더의 `rounded-t-[14px]` 모서리 안쪽은 투명이라, 그 아래를 지나가는 보스 행의 구분선(`border-b`)·`valuable-drop-row` 배경이 모서리 노치로 비친다. 라운딩을 빼면 사각 배경이 카드의 둥근 상단을 덮어 이번엔 카드가 각지게 보인다.
   - **문제(하단)**: 헤더가 **카드 끝에서 릴리스될 때** 헤더 하단 = 카드 하단이 되는데 헤더엔 하단 라운딩이 없어 모서리가 뾰족해진다. 그렇다고 헤더에 `rounded-b-*`를 주면 평상시(카드 최상단) 헤더와 본문 사이가 둥글게 파인다.
   - **해결**: 두 문제 모두 "헤더가 카드 모서리를 넘어 그려지는" 같은 원인이므로 **셸이 자식을 카드 모양대로 잘라내면** 상태별 라운딩 분기 없이 동시에 풀린다. `overflow: hidden`은 스크롤 컨테이너를 만들어 sticky를 죽이지만(ADR-047), **`overflow: clip`은 스크롤 컨테이너를 만들지 않아 sticky가 그대로 살아 있다**(CSS Overflow 3 — "the box is not a scroll container"). 이것이 정확히 "sticky를 지키면서 클리핑하는" 표준 처방이다.
   - **헤더에서 `rounded-t-[14px]`를 뺀다 — 헤더는 사각이어야 한다.** 이게 이 결정의 핵심이고, 처음엔 "미지원 브라우저 폴백"이라며 라운딩을 남겼다가 **증상이 그대로 재현됐다**(사용자 재보고 → 브라우저 hit-test로 원인 확정). 이유: 셸의 클리핑 곡선은 **카드 자신의 상·하단 모서리에만** 존재하는데, stuck된 헤더의 노치는 **카드 한가운데를 따라 내려간다**. 그 위치에서 클리핑은 그냥 직사각형이라 노치를 덮어주지 못한다. 반대로 헤더가 사각이면 — stuck 중엔 불투명해 아무것도 비치지 않고, 카드 최상단(정지 위치)에서는 그 지점이 **클리핑 곡선과 정확히 일치**해 클리핑이 라운딩을 대신 만들어준다. 즉 라운딩의 책임을 "헤더"에서 "카드"로 옮기는 것이 요점이다.
   - **골드 링(`.valuable-drop-card::before`) 보정**: `overflow: clip`은 **패딩 박스**에서 자르므로 `inset: 0`·`border-radius: 14px`인 링의 모서리 바깥쪽 0.42px가 깎인다. 펼침 상태에만 링 반경을 **13px**로 맞춰(`.valuable-drop-card--expanded::before`) 클리핑 곡선과 동심이 되게 한다 — 원래 패딩 박스의 실제 반경이 13px이므로 기하학적으로도 이쪽이 맞다. 글로우(`box-shadow`)는 **요소 자신의 그림자**라 `overflow`에 잘리지 않아 그대로다([[ADR-045]] 유지).
   - 셸 바깥(카드 `isolate` 직속)에 있는 **고가 드롭 배지·경계 페이드는 클리핑 대상이 아니다** — 배지는 의도적으로 모서리 밖으로 나가야 하고, 페이드는 하단에서 이미 거의 투명이다.

4. **보스 행 높이를 89px로 고정한다.** 원인 2개를 각각 없앤다.
   - **이름 줄 높이가 드롭 지시자에 따라 달라진다**: 드롭이 없으면 "＋ 드롭 추가" 칩(`text-[11px]` × line-height 1.5 = 16.5 + `py-1` 8 + 테두리 2 = **26.5px**), 있으면 아이콘 스택(`h-6` = **24px**). → 칩을 `inline-flex h-6 items-center`(패딩 제거)로 **24px에 맞추고**, 이름 줄 버튼 자체에도 `h-6`을 주어 **자식과 무관하게 24px로 고정**한다(난이도 뱃지 20px·보스명 20px 모두 수용). 칩과 아이콘 스택이 같은 슬롯을 쓰므로 드롭을 추가해도 줄 높이가 튀지 않는다는 부수 이점이 있다.
   - **마지막 행만 `last:border-b-0`으로 1px 짧다**: `last:border-b-transparent`로 바꿔 **테두리 박스는 유지하고 색만 지운다**. 배경은 기본 `background-clip: border-box`라 `valuable-drop-row`의 골드 배경도 그 1px을 그대로 채운다(시각 변화 없음).
   - 결과: `p-4`(32) + 이름 줄(24) + `mt-2`(8) + 조작 줄(24) + 테두리(1) = **89px**, 모든 행 동일. 초상화 40px < 56px이라 여전히 콘텐츠 열이 높이를 결정한다.

**이유**: 4건 모두 "값이 우연히 맞아떨어지길 기대하는" 구조가 원인이었다 — 탭과 새로고침이 각자 자기 패딩으로 높이를 만들고, 뱃지가 줄 높이에 참여하고, 라운딩이 상태마다 다른 요소에 흩어져 있고, 행 높이가 가장 큰 자식에 의해 결정됐다. 각 지점을 **명시적 높이 또는 흐름 이탈**로 바꿔 "더 큰 오차가 발생할 수 있는" 여지를 제거한다(사용자 요청 취지).

**트레이드오프**:
- 새로고침 버튼 터치 영역이 32 → 30px로 2px 줄어든다. 최소 권장(44px)에는 원래도 못 미쳤고, 탭 줄 정렬이 우선이라는 사용자 판단.
- 뱃지가 `absolute`라 라벨이 아주 길어지면 겹칠 수 있다. 실제 라벨은 최대 "OO년 O월 총 수익" 수준이라 여유가 크다.
- `overflow: clip` 미지원 브라우저(Chrome 90 / Safari 16 미만)에서는 클리핑이 통째로 무시돼 **펼친 카드의 상·하단 모서리가 사각으로 보인다**. 헤더에 라운딩을 남기는 폴백은 쓸 수 없다 — 그게 바로 고치려는 노치의 원인이기 때문이다(결정 3). 실사용 대상(Android Chromium WebView·iOS 16+ WKWebView)은 모두 지원하고, 접힘 카드는 헤더 자체가 `rounded-[14px]`라 영향이 없다. 순수 장식 열화라 기능 회귀는 아니다.
- 보스 행이 91.5 → 89px로 **2.5px 조밀**해지고 "＋ 드롭 추가" 칩이 2.5px 낮아진다.
- **미verify**: 실기기 육안 확인은 남아 있다(실 데이터 필요 — [[ADR-046]]·[[ADR-047]]과 동일 제약). `clip`과 sticky의 공존 자체는 브라우저에서 실측했다(아래).

**저장소**: 변경 없음(순수 표시 계층).

**구현(2026-07-28)**: TDD로 테스트 먼저(실패 확인) → 구현. `BossProfitScreen.tsx`(4건 전부) · `index.css`(`.valuable-drop-card--expanded::before` 반경 13px). 테스트 4건 신규. **검증**: 전체 테스트 1269건 통과 · lint 경고 0 · build 성공.

**`overflow: clip` × sticky 실측 검증(2026-07-28)**: jsdom엔 레이아웃이 없어 클래스 배선밖에 못 잡으므로, 결정 3의 전제("clip은 sticky를 죽이지 않는다")를 **Chrome에서 최소 재현 페이지로 직접 계측**했다. 페이지 헤더 60px + `overflow` 가변 셸 + 카드 내부 sticky 헤더(`top: 60`) 구조.

| 셸 `overflow` | 스크롤 중간(카드 상단 −140) | 카드 끝(scrollY 1230) |
|---|---|---|
| `clip` | 헤더 top = **60**(오프셋에 정확히 고정) | 헤더 top = **31**, bottom 80 ≤ 카드 바닥 81 — 카드 하단에 밀려 올라가며 카드 안에 머묾 |
| `hidden` | — | 헤더 top = **−909**(정적 위치, 화면 밖) — sticky 사망 |

같은 스크롤 위치에서 `overflow`만 바꿔 비교했으므로 [[ADR-047]] 결정 2가 막으려던 파손이 `clip`에서는 재현되지 않음이 확인됐다.

**모서리 노치 재현·수정 검증(2026-07-28, 사용자 재보고 후)**: 1차 구현에서 헤더의 `rounded-t-[14px]`를 폴백으로 남겼더니 증상이 그대로 남았다. 실제 컴파일된 `dist` CSS + 동일 클래스 문자열로 복제 페이지를 만들고, stuck 헤더 좌상단 12×12px을 `document.elementFromPoint`로 격자 hit-test 해 **무엇이 최상단에 그려지는지**를 직접 읽었다(`H`=헤더, `R`=보스 행, `S`=셸 테두리, `?`=카드 밖).

| 상태 | 좌상단 12×12 hit-test | 판정 |
|---|---|---|
| stuck + 헤더 `rounded-t-[14px]` | `RRRRHH / RRHHHH / RHHHHH / RHHHHH` | **보스 행이 노치로 비침(버그 재현)** |
| stuck + 헤더 사각 | `HHHHHH / HHHHHH / HHHHHH / HHHHHH` | 아무것도 비치지 않음 ✓ |
| 정지(카드 최상단) + 헤더 사각 | `??SHHH / ?SHHHH / SHHHHH / HHHHHH` | 클리핑이 라운딩을 만들어줌 ✓ |

`clip-path: inset(0 round 14px)`로 바꿔도 결과가 같아(같은 격자) 클리핑 방식의 문제가 아니라 **곡선의 위치**가 문제임이 확인됐다. 카드 하단 모서리도 같은 방식으로 확인(`??????/??SRRR/?SRRRR` — 마지막 행이 둥글게 잘림). 행 높이도 같은 페이지에서 12행 전부 **89px**로 계측했다. 실기기 육안 확인은 여전히 남아 있다.
