### ADR-064: 테마 토큰 스케일링 — 17→34토큰, 채움 위 전경색 고정 파기, 값 파생 생성 (설계 확정, 2026-07-30)

**배경**: 캐릭터 대표 컬러로 테마를 **수십 개** 만들 계획인데, 현재 구조는 "사람이 손으로 튜닝한 테마 몇 개" 전제로 짜여 있다. 전수 조사 결과(2026-07-30, 색을 다루는 파일 46개 / 토큰 유틸 호출 약 1,050회) 다음이 확인됐다.

- **채움 위 전경색이 "primary는 충분히 어둡다"를 전제로 세 갈래로 갈라져 있다.** `bg-primary text-bg` 11곳(CTA 버튼 전부) · `bg-primary text-white` 7곳(`BossDropSheet` 6, `BossProfitScreen` 1) · `bg-secondary text-bg` 3곳(완료 배지). 문서에는 네 번째 규칙(`design-system.md` "채움으로 쓸 때 텍스트는 짙은 `#2B1206`")까지 있고 이미 코드와 어긋나 있다. **사용자가 지시한 적 없는 제한이며 파기한다**(2026-07-30) — 라이트 테마의 밝은 파스텔 primary도, 어두운 primary도 모두 성립해야 한다.
- **투명도 합성 틴트가 67곳인데 비율이 4종(`/10`·`/12`·`/15`·`/25`)이고 깔리는 배경이 3종(`bg`·`surface`·`surface-2`)이다.** 합성 결과가 자리마다 달라 대비를 보증할 수 없다. `Toast.tsx:17-18` 주석이 이 문제를 이미 발견해 3곳(`Toast` success/error, `StaleBanner`)만 `color-mix(in oklab, X N%, surface)` 로 우회해 뒀다.
- **그 결과 테마 4개에서 대비 사고가 세 번 났고, 그중 하나는 아직 안 닫혔다.** ① 레테 `info-tint` `#C9D6F2` → `text` 대비 **1.13:1**(2026-07-22 `#262A3A` 로 재수정) · ② 렌 `third` `#C9EEF2` 교체 → `bg-third/15 text-third` 카운트 배지 6곳 텍스트 실종 · ③ 일러스트 카드 안 점수 배지 `bg-third/20 text-third` 가 **레테에서 3.88:1로 AA 미달**([[ADR-021]] 정정 2026-07-14) — "사용자 판단에 맡긴 상태"로 **현재도 미달인 채 남아 있다**. 셋 다 "대표 컬러 밝기가 제각각이라 틴트 대비가 깨진다"는 **같은 실패 모드**이고, 사람이 눈으로 추정하는 한 반복된다.
- **틴트 위 텍스트에 base accent 를 그대로 쓰는 패턴이 35곳**이다(`bg-primary/15 text-primary`). `-text` 토큰은 이 자리를 위해 만들었는데(ADR-009 2026-07-14) 정작 이 레시피가 안 쓴다.
- **`primary-text` 가 두 역할을 겸한다** — 틴트 위 텍스트 7곳 + 일반 표면 위 링크/편집 액션 11곳. 요구 대비가 서로 다른데 값이 하나다. `EmptyState.tsx:45-46` 주석이 *"레테에서만 `primary-text` 가 `primary` 보다 어둡다"* 는 방향 불일치를 이미 기록해 뒀다.
- **텍스트가 없는 채움 12곳**(진행률 fill 8·토글 노브 2·체크박스 2)이 `bg-surface-2` 트랙 위에 놓인다. 파스텔 primary + 라이트 테마면 fill과 track이 둘 다 밝아 진행률이 안 읽히는데, `-text` 계열은 텍스트 대비만 다루므로 이 쌍은 아무 토큰도 보증하지 않는다.
- **테마 밖으로 샌 색이 있다** — 일러스트 카드의 레테 다크 하드코딩 23곳(`ContentScreen` 21·`BossScreen` 2), 스크림·그림자 12곳(`bg-bg/70` 5 + `rgba(0,0,0,*)` 7), 네이티브 브랜드색 3곳.
- **테마 1개 추가에 6개 파일을 수동 수정해야 한다** — `ThemeName` 유니온·타입 가드·`index.css` 오버라이드 블록·`DARK_THEMES` Set·`THEME_OPTIONS` 2곳·회귀 테스트 기댓값.

**결정**:

1. **채움 위 전경색을 `on-*` 토큰으로 분리한다.** `text-white`·`text-bg` 고정을 전부 걷어낸다.
   - `on-primary`(19곳) · `on-secondary`(3곳) · `on-third` · `on-error` 신설.
   - 값은 **후보 집합 {흰색, 검정, 테마 `text`, 테마 `bg`, 해당 accent의 명도 극단} 중 채움색 대비가 가장 높은 것**을 생성 도구가 고른다. 파스텔 primary면 어두운 전경이, 어두운 primary면 밝은 전경이 자동으로 선택된다 — **어느 쪽도 전제하지 않는 것**이 이 결정의 요점이다.

2. **합성 틴트를 `*-tint` 토큰으로 값화한다.** `bg-primary/15` 같은 투명도 접미사 사용을 금지하고 `bg-primary-tint` 로 바꾼다(67곳).
   - 기본 정의는 `color-mix(in oklab, var(--color-X) 15%, var(--color-surface))` — 이미 `Toast`·`StaleBanner` 에서 검증된 방식이라 **테마당 손튜닝 값이 늘지 않는다**. 테마가 다른 농도를 원하면 그 테마만 명시값으로 덮는다.
   - 합성 비율 4종을 **15% 하나로 통일**한다. 자리마다 다른 농도를 쓸 이유가 없었다.
   - **[[ADR-062]]의 "`error-tint` 토큰을 만들지 않는다"를 폐기한다.** 그 결정의 근거는 "4개 테마에 토큰을 추가하는 비용 대비 얻는 게 적다"였는데, `color-mix` 파생이면 추가 비용이 0이고 테마가 수십 개가 되면 `StaleBanner` 의 인라인 `color-mix` 를 매번 복사하는 쪽이 더 비싸다.

3. **accent 계열 텍스트/아이콘을 `*-ink` 로 개명·정리한다.** 기존 `primary-text`/`secondary-text`/`third-text` → `primary-ink`/`secondary-ink`/`third-ink`, 신규 `error-ink`.
   - 이름을 배경이 아니라 **역할**로 붙인다: `on-X` = X 채움 **위**의 전경, `X-ink` = X 계열 **텍스트/아이콘**. ADR-009가 쓰던 "잉크" 어휘를 그대로 잇는다.
   - 요구 대비: `surface` 와 `X-tint` **양쪽 모두** 4.5:1 이상. 두 역할을 겸하는 현 실태를 값 하나로 만족시킬 수 있고, 못 만족하면 생성 도구가 실패로 보고한다.
   - 틴트 위 텍스트에 base accent 를 쓰던 35곳이 `X-ink` 로 수렴한다.

4. **`track` 토큰을 신설한다.** 진행률 바·토글 트랙 전용. 요구: 채움색(`primary`) 대비 **3:1 이상**(비-텍스트 대비 기준). 기본값은 `surface-2` 에서 출발하되 미달이면 생성 도구가 조정한다. 텍스트 대비만 보던 체계의 구멍을 메운다.

5. **일러스트 위 배색을 `media-*` 토큰군 + 미디어 스코프로 승격한다.** 하드코딩 23곳을 걷어낸다.
   - `media-surface`(카드 배경) · `media-border` · `media-ink`(이름) · `media-ink-muted`(보조).
   - 테마마다 값을 갖는다 — 일러스트 페이드·`text-shadow` 가 어두운 배경을 전제하므로 기본값은 테마 색조를 띤 어두운 배색으로 파생하고, 현재 4개 테마는 레테 값(`#1A1720`/`#37323E`/`#E8DFEC`)을 그대로 승계해 회귀를 만들지 않는다.
   - **카드 안에서는 accent 토큰의 기준 배경이 바뀐다.** `X-tint`·`X-ink` 는 `surface` 기준으로 계산한 값인데, 일러스트 카드의 배경은 `media-surface` 다. [[ADR-021]] 정정(2026-07-14)이 이 문제를 이미 기록해 뒀다 — 카드 안 점수 배지 `bg-third/20 text-third` 가 **레테에서 3.88:1로 AA 미달**이고 "사용자 판단에 맡긴 상태"로 미해결이며, 같은 문단이 *"`third-text` 는 애초에 앱의 `surface` 기준이라 이 '항상 어두운 카드' 맥락에는 안 맞다"* 고 원인까지 짚어 뒀다.
   - 해법은 **CSS 스코프**다. 카드 루트에 `.media-scope` 를 두고 그 안에서 기준 토큰을 다시 묶는다.
     ```css
     .media-scope {
       --color-surface: var(--color-media-surface);
       --color-border:  var(--color-media-border);
       --color-text:    var(--color-media-ink);
       --color-text-muted: var(--color-media-ink-muted);
       --color-primary-tint: /* media-surface 기준으로 재계산된 값 */;
       --color-primary-ink:  /* media-surface 기준 AA 통과값 */;
       /* secondary·third·error 동일 */
     }
     ```
     커스텀 프로퍼티는 **선언된 요소에서** `var()` 가 해석되므로, 스코프 안에서 다시 선언해야 새 기준이 반영된다(`:root` 선언을 상속만 받으면 `surface` 기준 값이 그대로 내려온다). 값은 생성 도구가 테마마다 두 벌(일반 / 미디어)을 계산하므로 **사람이 채우는 값은 늘지 않는다**.
   - 이 스코프가 생기면 카드 안 컴포넌트는 `bg-primary-tint text-primary-ink` 같은 **앱 전역과 똑같은 레시피**를 쓰면서 자동으로 어두운 배경 기준을 따른다. [[ADR-021]] 의 미해결 3.88:1도 여기서 닫힌다.

6. **`scrim`·`shadow-color` 를 신설한다.** `bg-bg/70` 스크림 5곳과 `rgba(0,0,0,*)` 그림자 7곳이 검은 그림자·어두운 배경을 전제하고 있다. 밝은 테마에서 스크림이 약하고 파스텔 표면에서 검은 그림자가 탁해진다. 값은 `mode` 와 `bg` 색조에서 파생한다.

7. **`info-tint` 에 짝을 준다.** `info-ink` 를 신설해 그 위 텍스트 대비를 보증한다 — 레테 1.13:1 사고가 정확히 이 자리(짝 없는 틴트 + `text-text`)에서 났다.

8. **테마 데이터에 `mode: 'light' | 'dark'` 필드를 둔다.** `DARK_THEMES` Set(`features/theme/store.ts`) 수동 관리를 없앤다. 이 값이 상태바(`native/status-bar.ts`)·하단 내비 글리프(`native/system-bars.ts`) 명암을 결정한다. **자동 계산하지 않는다** — 파스텔처럼 경계가 애매한 테마에서 의도와 다르게 판정될 수 있어 사람이 박아둔다(사용자 결정 2026-07-30).

9. **값은 파생 생성 도구로 만든다 — 이 확장의 전제 조건이다.** 토큰을 17→34로 늘리면 테마당 손튜닝 값이 2배가 되어, 생성 없이는 이번 확장이 "수십 개 테마" 목표를 **악화시킨다**.
   - **사람이 정하는 값은 4개**: `primary`·`secondary`·`third`(캐릭터 일러스트에서 추출) + `mode`. 나머지 30개는 파생한다.
   - **런타임이 아니라 생성 도구로 한다** — 색 값은 도메인 데이터라 [[ADR-006]] 상 사용자 확인이 필요한데, 런타임 계산은 그 확인 절차를 없앤다. 시드를 넣으면 34토큰 + 대비 검증 리포트를 뱉고, 사람이 확인해 `job-themes.json` 에 커밋한다.
   - 기존 4개 테마를 입력해 **현재 값이 재현되는지**로 도구를 검증한다.

10. **테마 등록을 `job-themes.json` 한 곳으로 모은다.** `ThemeName` 은 JSON 키에서 추론(`keyof typeof`), 타입 가드는 키 존재 확인, `THEME_OPTIONS` 2곳은 키 순회, `DARK_THEMES` 는 결정 8의 `mode` 필드, `index.css` 의 테마별 블록은 CSS 변수 주입으로 대체한다. 테마 추가 = JSON 한 블록.

11. **회귀 테스트를 값 나열에서 스키마·대비 검증으로 바꾼다.** 현재 `job-themes.test.ts` 는 4테마 × 17값을 하드코딩해 비교하는데, 테마가 수십 개가 되면 테스트가 같은 속도로 늘어난다. **모든 테마가 34필드를 갖는가 / 결정 1·3·4·7의 대비 요구를 만족하는가**를 검사하는 형태로 바꾸면 테마가 늘어도 테스트가 늘지 않는다.

**토큰 스키마 (34)**:

| 군 | 토큰 | 수 |
|---|---|---|
| Accent (X ∈ `primary`·`secondary`·`third`·`error`) | `X` · `on-X` · `X-tint` · `X-ink` (+ `primary-hover`) | 17 |
| 표면 | `bg` · `surface` · `surface-2` · `track` · `border` · `border-strong` | 6 |
| 텍스트 | `text` · `text-muted` · `text-disabled` | 3 |
| 정보 | `info-tint` · `info-ink` | 2 |
| 미디어(일러스트 위) | `media-surface` · `media-border` · `media-ink` · `media-ink-muted` | 4 |
| 깊이 | `scrim` · `shadow-color` | 2 |

별도로 `mode: 'light' | 'dark'` 데이터 필드(토큰 아님).

**이름 규칙**: `on-X` = X 채움 **위**의 전경 · `X-ink` = X 계열 텍스트/아이콘 · `X-tint` = X 계열 옅은 배경.

**이유**:

- **결정 1이 이 ADR의 출발점이다.** `text-white` 도 `text-bg` 도 "primary가 어둡다"를 다르게 표현한 것이고, 지시된 적 없이 코드에 굳었다. 후보 집합에서 대비 최댓값을 고르는 방식은 밝은 쪽·어두운 쪽 어느 것도 기본으로 두지 않아, 앞으로 어떤 캐릭터 컬러가 와도 규칙을 다시 정할 필요가 없다.
- **결정 2·3이 사고 2건을 구조적으로 없앤다.** 두 사고 모두 "합성 결과를 사람이 눈으로 추정했다"가 원인이다. 틴트를 값으로 확정하면 그 위 잉크 대비를 **계산할 수 있게** 되고, 계산할 수 있으면 테스트할 수 있다(결정 11).
- **결정 9를 전제로 못 박는 이유**: 결정 1~8을 다 해도 값을 손으로 채우면 테마당 34개를 튜닝하게 된다. 확장과 생성은 한 묶음이어야 의미가 있다.
- **결정 10·11이 없으면 결정 9의 이익이 새어나간다** — 값 생성이 자동이어도 등록이 6파일 수동이면 테마 추가 비용은 그대로다.

**트레이드오프**:

- **[[ADR-062]] 결정 1의 `error-tint` 금지를 뒤집는다**(결정 2). 그 결정은 당시 전제(테마 4개·토큰당 4값 수기 입력)에서는 옳았다. 전제가 바뀌었으므로 뒤집되, `StaleBanner`·`Toast` 의 인라인 `color-mix` 는 새 토큰으로 교체한다.
- **`*-text` → `*-ink` 개명이 28곳을 건드린다.** 기계적 치환이라 위험은 낮지만 문서 레시피도 함께 고쳐야 한다.
- **틴트 농도 통일(15%)이 일부 자리의 미세한 인상을 바꾼다** — `/10`·`/12` 를 쓰던 8곳은 약간 진해지고 `/25` 1곳은 옅어진다. 자리마다 다른 농도를 유지할 근거가 없어 수용한다.
- **`media-*` 를 테마별 값으로 두면 테마마다 4값이 늘어난다.** 전 테마 공통 상수 1벌이 더 쌌지만, 파스텔 테마에서 카드만 어둡게 뜨는 이질감을 피하려면 테마를 따라가야 한다(사용자 결정 2026-07-30). 생성 파생이므로 실입력 비용은 0이다.
- **미디어 스코프는 생성 도구가 테마마다 accent 값을 두 벌 계산하게 만든다**(결정 5). 대신 카드 안팎이 같은 레시피(`bg-primary-tint text-primary-ink`)를 쓰게 되어 컴포넌트 쪽 분기가 사라지고, [[ADR-021]] 의 미해결 AA 미달이 닫힌다. 스코프를 중첩하면(카드 안의 카드) 기준이 한 번 더 바뀌는데 현재 그런 자리는 없다 — 생기면 그때 다룬다.
- **`mode` 를 자동 계산하지 않아 신규 테마마다 한 줄을 사람이 적어야 한다**(결정 8). 자동 판정의 오분류 대신 명시를 택했다.
- **34토큰은 되돌리기 어렵다.** 토큰을 줄이는 변경은 전 테마 데이터와 사용처를 동시에 건드린다. 그래서 이번에 "지금 실사용이 있는 것"만 넣고 투기적 토큰(`success`·`warning` 등 별도 시맨틱 색)은 넣지 않는다 — 현재 성공은 `secondary`, 경고는 `error` 가 담당하고 있고 그 분담을 바꾸지 않는다.

**적용 범위 밖**(의도적으로 테마 토큰을 쓰지 않는 영역, 결정 2026-07-30):

- **`DifficultyBadge`** — 5난이도 × (그라데이션 2색 + 보더 + 텍스트 + 그림자) 하드코딩 20여 값. 게임 고유 난이도 색이라 테마를 따라가면 오히려 의미가 깨진다([[ADR-006]] 도메인 데이터).
- **고가 드롭 골드 연출** — `index.css` 의 `.valuable-drop-*`(`#f7d00d` 계열). 주석에 "전 테마 공통 네온 골드"로 의도가 이미 명시돼 있다.
- **콘텐츠 카테고리 뱃지** — `bg-[#4DD2FF]/20 text-[#4DD2FF]`("에픽 던전"/"길드"). 특정 일러스트(아르카누스 전기빛)에 맞춘 색이라 테마를 따라가면 의미가 깨진다([content-scheduler.md](../features/content-scheduler.md)).
- 두 영역은 코드를 그대로 두되 **"테마 토큰을 의도적으로 쓰지 않는 영역"으로 문서에 명시**해 다음 사람이 헷갈리지 않게 한다.
- **네이티브 브랜드색 3곳**(`capacitor.config.ts` · `index.html` 부트 커버 · `native/splash-screen.ts`, 전부 `#F58B0F`) — 앱 실행 전이라 선택 테마를 모르는 시점이다. 이번 범위에서 건드리지 않는다. 선택 테마를 스플래시에 반영할지는 별도 결정.
- **`/debug/*` 4개 라우트** — `LoadingPreview` 는 `App.tsx` 주석에 "선택이 확정되면 삭제할 것"으로 표시돼 있다. 정규화 대상에서 제외하고, 삭제 시점에 함께 정리한다.

기존 4개 테마(레테·렌·머쉬맘·혼테일)의 신규 17토큰 값은 생성 도구로 뽑되 **커밋 전 사용자 확인을 받는다**([[ADR-006]]).

**1단계 결과(2026-07-30)**: `lib/color.ts`(색 공간·WCAG 대비) + `lib/theme-derive.ts`(파생 규칙) + `scripts/theme-gen.ts`(CLI). 기존 4테마 전부 **필수 대비 항목 통과**. 구현하며 확정한 것 세 가지.

- **가뭄(gamut) 매핑은 채널 클램프가 아니라 채도 축소로 한다.** 머쉬맘 primary(`#F58B0F`, H≈60°)를 어둡게 밀면 그 채도로는 sRGB 밖이라, 채널을 잘라내면 H가 47°로 틀어져 "색상 유지, 명도만 조정"이라는 결정 3이 깨진다. 명도·색상을 고정하고 채도만 이분 탐색으로 낮춘다(CSS Color 4 가뭄 매핑과 같은 방향).
- **대비 검사에 `required`/`advisory` 두 등급을 둔다.** 비활성 텍스트는 WCAG 1.4.3이 대비 요구에서 명시적으로 제외하는 대상이라, 사용자 확정 값(머쉬맘 `text-disabled` = `bg` 대비 **2.78:1**)을 실패로 몰아 억지로 바꾸게 하지 않는다. 권고 미달로만 보고한다.
- **`track` 이 실제로 바뀌는 테마는 머쉬맘 하나뿐이다.** 레테·렌·혼테일은 primary가 이미 `surface-2` 대비 3:1을 넘어 `track` = `surface-2` 그대로다. 머쉬맘만 primary(`#F58B0F`)가 `surface-2`(`#E4E1CE`) 대비 **1.86:1**이라 트랙이 `#585545`(어두운 올리브)로 밀린다 — 진행률 바가 눈에 띄게 어두워지는 유일한 자리다. 이 변경을 받을지는 사용자 확인 대상.
