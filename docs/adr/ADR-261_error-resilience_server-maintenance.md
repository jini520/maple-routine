# ADR-261 서버 점검 잠금

> ⚪ 미구현
> 관련 소스: `server/maintenance.ts` · `features/server-maintenance/` · `app/server-maintenance/ServerMaintenanceLock.tsx` · `app/AppShell.tsx`

## 배경

1.0.15 에서 서버의 표를 한 번에 옮긴다(#947). 옮기는 동안 앱을 쓰지 못하게 하기로 했다(사용자 지정 2026-11-19).
지금 앱에는 서버의 점검으로 앱을 막는 화면이 없다. 점검 표시는 넥슨이 점검 중일 때 머리글 아래에 서는
띠(`NexonMaintenanceBanner`)뿐이고, 그 띠는 화면을 막지 않는다([[ADR-022]] 결정 8).

서버가 답하지 못하는 것만으로는 점검과 장애를 가릴 수 없다. 그래서 운영자가 켜고 끄는 점검 상태를 따로 두고,
앱이 그 상태를 물어 잠근다. 잠금은 1.0.14 의 OTA(1.0.14+1)로 먼저 낸다(#1093).

## 결정

### 결정 1. 점검 중이면 앱 전체를 잠근다

- 잠금 화면(`ServerMaintenanceLock`)은 게임 데이터 잠금(`GameDataLock`)과 같은 곳에 선다. `AppShell` 이 `ReadyShell`
  대신 그린다. 넥슨에서 바로 읽는 화면과 기기의 기록만 쓰는 화면도 함께 막힌다. 서버의 표를 옮기는 동안 앱을 쓰지
  못하게 한다는 것이 정한 기준이다(사용자 지정 2026-11-19).
- `ReadyShell` 을 내리는 것은 화면이 하던 조회와 쓰기를 함께 멈추려는 것이다. 화면을 덮기만 하면 아래에서 요청이 계속
  나간다. 풀리면 `ReadyShell` 이 새로 서고 첫 화면에서 다시 시작한다.
- 게임 데이터 잠금과 겹치면 점검 잠금이 이긴다. 점검 중에는 게임 데이터를 받을 수 없다.
- 잠금 화면 위에 업데이트 모달(`LockedUpdatePrompt`)은 그대로 둔다. 잠금이 풀리지 않는 결함을 OTA 로 고칠 수 있어야
  한다. 스토어 업데이트가 필요하면 그 모달이 잠금 화면 위에 선다.
- 이미 예약된 로컬 알림과 사냥 타이머의 상시 알림은 건드리지 않는다.

### 결정 2. 잠금 화면은 머리 줄과 종료 예정 칸이고 버튼이 없다 (사용자 선택 2026-11-20)

- 껍데기는 게임 데이터 잠금과 같다. 테마 바탕 위에 스크림을 깔고 가운데 패널(`ModalSurface`) 하나를 띄운다.
- 머리 줄(`ModalHeader`)에 렌치 아이콘 · 제목 · 설명을 둔다. 렌치는 넥슨 점검 띠가 쓰는 아이콘이다.

  | 곳 | 문구 |
  |---|---|
  | 제목 | `서버 점검 중입니다` |
  | 설명 | `점검이 끝나면 자동으로 다시 열립니다` |
  | 칸 이름 | `종료 예정` |
  | 칸 값 | `12월 2일 06:00` 꼴. 한국 시각이다 |

- 종료 예정 칸(`InsetRow`)은 점검을 켤 때 시각을 적었을 때만 그린다. 그 시각이 지나면 그리지 않는다. 지난 시각이
  보이면 점검이 끝났는데 앱이 안 풀린 것으로 읽힌다.
- 버튼은 두지 않는다. 버튼은 누르면 실제로 문제가 풀릴 때만 둔다([[ADR-022]] 결정 3). 점검은 기다리는 것 말고 할 일이
  없고, 앱이 스스로 다시 확인한다(결정 5).

### 결정 3. 점검 상태는 앱 박스의 파일 하나이고 nginx 가 낸다 (사용자 선택 2026-11-20)

- 앱 박스의 `/srv/maple-routine-maintenance/maintenance.json` 이 있으면 점검 중이다. 없으면 점검이 아니다.
- 파일의 내용은 `{"maintenance":true,"until":"2026-12-02T06:00:00+09:00"}` 이다. `until` 은 종료 예정 시각이고 `null`
  일 수 있다.
- 앱은 `GET /v1/maintenance` 로 묻는다. nginx 가 파일이 있으면 그 내용을 200 으로, 없으면 204 로 답한다. 서버(NestJS)는
  이 경로를 모른다.
- nginx 가 내는 것은 서버 컨테이너를 내려도 nginx 는 떠 있기 때문이다. 서버가 내는 값이면 서버를 내린 동안 앱이 점검
  중인 것을 알 수 없다.
- 503 응답으로 점검을 알리지 않는다. nginx 는 속도 제한(`limit_req`)에 걸린 요청에도 503 을 낸다.
- 켜고 끄는 것은 맥에서 스크립트로 한다(서버 저장소 `scripts/maintenance.mjs`). `on` 은 종료 예정 시각을 함께 받고,
  `off` 는 파일을 지우고, `status` 는 지금 상태를 보인다. SSH 로 앱 박스의 파일을 쓰고 지운다.
- 관리 화면에는 두지 않는다. 서버가 내려가 있으면 관리 화면도 열리지 않아서, 점검을 끄는 수단이 될 수 없다.

### 결정 4. 점검 중에는 nginx 가 `/v1/` 요청을 서버로 넘기지 않는다

- 점검 파일이 있으면 nginx 가 `/v1/` 아래의 요청에 503 으로 답한다. 두 경로만 예외다. 점검을 묻는 `/v1/maintenance` 와
  OTA 를 확인하는 `/v1/ota/` 다.
- `/admin` · `/assets/` · `/ota/files/` · 안내 사이트는 그대로 연다. 운영자는 점검 중에도 관리 화면을 쓴다.
- 서버 앞에서 막는 것은 잠금 코드가 없는 번들 때문이다. 1.0.14 스토어 바이너리에 든 번들은 점검 화면을 띄우지 못하고
  서버에 계속 요청한다. nginx 에서 막으면 어느 번들이든 점검 중에 서버의 값을 바꾸지 못한다.
- OTA 확인을 열어 두는 것은 그 기기가 잠금이 든 번들을 받고, 스토어 업데이트가 필요한지 판정받게 하려는 것이다
  ([[ADR-011]] 결정 6).

### 결정 5. 앱은 부팅 · 복귀 · 주기로 묻고, 모르면 지금 상태를 둔다

- 묻는 때는 넷이다. 부팅할 때, 백그라운드에서 돌아올 때, 앱을 쓰는 동안 5분마다, 잠긴 동안 30초마다다.
  앱이 화면에 없으면 주기 확인을 건너뛴다.
- 5분은 점검을 켠 뒤 쓰고 있던 앱이 잠길 때까지의 상한이다. 점검을 켜고 서버를 내리기까지 이만큼 기다리면 된다.
  30초는 점검이 끝난 뒤 앱이 풀릴 때까지의 상한이다. nginx 가 파일 하나를 내는 요청이라 서버에 부담이 없다.
- 답은 셋으로 읽는다.

  | 답 | 뜻 | 하는 일 |
  |---|---|---|
  | 200 이고 본문이 `maintenance: true` 인 JSON | 점검 중 | 잠근다 |
  | 204 · 404 | 점검이 아님 | 푼다 |
  | 그 밖(응답 없음 · 5xx · JSON 이 아닌 200) | 모름 | 지금 상태를 둔다 |

- 모르면 지금 상태를 둔다. 켠 뒤 한 번도 답을 못 받았으면 잠그지 않는다. 오프라인에서도 앱을 쓸 수 있어야 한다.
  잠긴 뒤에 답을 못 받으면 그대로 잠가 둔다. 네트워크가 잠깐 끊겼다고 점검 중에 앱이 열리면 안 된다.
- 200 이어도 `maintenance: true` 가 없으면 모름이다. 공용 와이파이의 로그인 페이지는 어느 주소에나 200 을 준다.
- 404 를 점검이 아님으로 읽는 것은 nginx 설정을 넣기 전에는 이 경로가 서버로 넘어가 404 가 오기 때문이다.
- 부팅은 이 확인을 기다리지 않는다. 기다리면 느린 망에서 모든 부팅이 늦어진다. 그래서 점검 중에 앱을 켜면 첫 화면이
  잠깐 보인 뒤 잠길 수 있다.
- 풀리면 게임 데이터를 다시 묻는다. 점검 중에 켜서 게임 데이터 받기가 실패해 있으면 다시 받는다.

### 결정 6. 잠금 코드가 없는 번들의 화면은 잠그지 않는다

- 1.0.14+1 을 받지 않은 기기는 점검 화면을 띄울 수 없다. 그 기기의 서버 요청은 결정 4 가 막고, 넥슨에서 읽는 화면과
  기기의 기록은 평소처럼 쓴다.
- 번들에 없는 화면을 서버가 띄우게 할 수단은 스토어 업데이트 모달 하나다([[ADR-011]] 결정 6). 그 모달은 새 스토어
  버전이 있을 때만 쓸 수 있다. 받을 버전이 없는데 띄우면 사용자가 갈 곳이 없다.
- OTA 번들은 5MB 이하면 묻지 않고 받고, 받아 둔 채 10분 넘게 나갔다 돌아오면 묻지 않고 적용한다([[ADR-012]] 결정 15).
  그래서 1.0.14+1 을 낸 뒤 앱을 연 기기는 대부분 잠금이 든 번들로 넘어간다.
