# ADR-187 서버 아이템 표와 그림 연결 · 관리 화면

> ⚪ 미구현
> 관련 소스: 서버 `database/schema.ts` · `modules/items/` · `modules/drop-items/` · `modules/equipment-items/` · `modules/hunt-loot/` · `modules/assets/` · `modules/game-data/` · `modules/admin/` · 앱 `lib/assets/` · `lib/game-data/sections.ts` · `lib/cashbook/categories.ts` · 이슈 #911 · #912 · #914

## 배경

서버의 아이템은 기능마다 표가 따로 있다. 드롭 아이템(`drop_items`, 109개) · 사냥 전리품(`hunt_loot_items`) · 강화 장비
이름(`equipment_items`, 475개)이다. 같은 아이템이 두 표에 들어 있기도 하다. `거대한 공포` 등 17개는 드롭 아이템과 강화 장비
양쪽에 같은 key 로 있다. 가계부 아이템 구매 · 판매의 그림 목록(#912)과 인벤토리(#911)는 이 아이템들을 함께 써야 하는데,
지금은 거래 아이템을 넣을 표가 없다.

그림은 `assets` 표에 경로 · 해시 · 크기로 있다. 그림을 쓰는 표의 칸은 그림 표의 `id` 가 아니라 파일 이름이나 slug 글자로
그림을 가리킨다(`icon_file` · `portrait_slug` · `emblem` · `background_map` · `background_portrait` · `icon_map`). 그래서 그림 이름을 바꾸면 연결이
소리 없이 끊긴다. 한 그림을 어느 표가 쓰는지 찾을 수 없어서, 아무 데도 안 쓰는 그림을 골라낼 수도 없다. 그림의 분류는
경로의 폴더 14개뿐이다.

이 문서는 아이템을 표 하나로 모으고, 그림을 `id` 로 잇고, 관리 화면을 그 구조에 맞게 바꾸는 방법을 정한다(사용자 지정
2026-11-08). 지금의 그림 목록과 관리 화면 결정은 [[ADR-020]] 에 있다. 이 문서를 구현하면 그 결정 7 · 14 · 15 를 고친다.

## 결정

### 결정 1. 드롭 아이템 · 거래 아이템 · 사냥 전리품 · 강화 장비를 아이템 표 하나(`items`)에 둔다

- 세 표의 줄을 `items` 로 옮기고, 거래 아이템(#912)도 이 표에 더한다. 같은 아이템을 한 줄로 두어야 인벤토리와 거래 목록이
  같은 아이템을 가리킨다.
- key 는 지금 값을 그대로 쓴다. 기기의 드롭 기록 · 서버의 드롭 가격 · 강화 합계가 key 를 들고 있기 때문이다. 두 표에 겹친
  17개는 key 도 같아서 그대로 한 줄이 된다.
- 드롭 아이템 줄의 `id` 는 그대로 옮긴다. 드롭 표 · 상자 · 상자 내용물 · 서버의 드롭 가격(`drop_prices`)이 그 `id` 를 FK 로
  가리키므로, `id` 를 지키면 FK 가 가리키는 표만 바꾸면 된다.
- 아이템 자체의 성질은 `items` 칸이다. 고가(`valuable`) · 월드 귀속(`world_bound`) · 착용 레벨(`level`)이 여기에 든다.
- 한 기능에서만 쓰는 값은 그 기능의 표에 남긴다. 사냥 전리품의 분류 · NPC 가격 · 기간 · 차례는 `hunt_loot_items` 에 두고,
  그 표가 `item_id` 로 아이템을 가리킨다.
- 이름은 띄어 쓴 게임 표기로 둔다. 강화 장비 표는 지금 붙여 쓴 이름이지만, 앱이 넥슨 API 이름과 맞춰 볼 때 양쪽 공백을 지우고
  비교한다([[ADR-019]] 결정 4, 앱 `comparableEquipmentName`). 그래서 띄어 써도 key 찾기는 그대로다.
- 새 아이템의 key 는 영어 snake_case 다. 지금 드롭 아이템 key 와 같은 모양이다. Claude 가 이름에서 지어 목록으로 내고,
  사용자가 훑어보고 고친다(사용자 지정 2026-11-08). 강화 장비 표에 이미 있는 아이템은 그 key 를 쓴다.

### 결정 2. 아이템 분류는 서버 코드에 고정한 트리다 (사용자 지정 2026-11-08)

- 서버 코드의 상수 표가 분류 트리를 든다. 첫 단은 종류(장비 · 소비 · 기타 · 캐시)이고, 둘째 단은 묶음이다. 아이템 줄은
  둘째 단 묶음의 key 하나를 든다.
- 관리 화면에서는 분류를 더하거나 바꾸지 않는다. 바꾸려면 서버를 배포한다.
- DB 칸은 글자이고, 쓰기 검사가 상수 표에 있는 key 인지 본다. ENUM 으로 두면 묶음을 하나 더할 때마다 DB 이관이 필요하다.
- 첫 묶음은 거래 아이템 고르기(#912)에서 쓴 묶음에, 강화 장비 · 드롭 아이템 중 거기에 맞지 않는 것을 위한 묶음을 더한 것이다
  (사용자 지정 2026-11-08). 제네시스 무기 · 데스티니 무기 · 기계 심장(플라즈마 · 페어리 · 리튬 하트)은 장비의 묶음이고, 보스가
  떨구는 재료(변화하는 운명의 파편 · 저주받은 원혼의 잔재 · 남겨진 칼로스의 의지 등 14개)는 기타의 `보스 전리품` 이다. 솔 에르다의
  기운은 솔 에르다 조각과 같은 기타의 `성장 재료` 다.
- 상자 21개(보스 반지 상자 5 · 에테르넬 방어구 상자 10 · 칠흑 장신구 상자 2 · 선택 상자 2 · 솔 에르다 조각 상자 2)는 소비의
  `상자` 로 모은다(사용자 지정 2026-11-08). 게임에서 상자는 소비 탭에 든다.

### 결정 3. 그림을 쓰는 칸은 그림 표의 `id` 를 FK 로 가리킨다

- 그림을 글자로 가리키는 칸을 모두 `assets.id` FK 로 바꾼다. 대상은 아래 표다. FK 면 그림 이름을 바꿔도 연결이 이어지고,
  쓰이는 그림은 지울 수 없고, 한 그림을 어디에서 쓰는지 셀 수 있다.
- 크롭(`image_crops`)도 slug 대신 그림 `id` 를 가리킨다. 크롭은 그림 한 장에 붙는 값이기 때문이다.
- 여러 아이템이 한 그림을 써도 된다. 에테르넬 신발 · 장갑 · 망토 · 어깨는 직업과 상관없이 같은 그림이다(사용자 확인
  2026-11-08).

| 표 | 지금 칸 |
|---|---|
| `bosses` | `portrait_slug` |
| `drop_items`(→ `items`) | `icon_file` |
| `hunt_loot_items`(→ `items`) | `icon_file` |
| `worlds` | `emblem` |
| `cashbook_categories` | `icon_file` |
| `spend_tiles` | `icon_file` · `icon_map` |
| `symbols` | `icon_file` |
| `hexa_core_kinds` · `hexa_job_cores` | `icon_file` |
| `contents` | `background_map` · `background_portrait` |
| `hunting_regions` | `icon_map` |

### 결정 4. 게임 데이터의 그림 칸은 그림 `id` 를 싣고, 옛 글자 칸은 옛 앱이 남는 동안 함께 낸다 (사용자 지정 2026-11-09)

- 그림을 가리키는 방법을 그림 `id` 하나로 통일한다(사용자 지정 2026-11-09). 지금 게임 데이터의 그림 칸은 폴더마다 규칙이
  다르다. 보스 초상은 확장자 없는 이름(`bellona`)을, 아이템은 파일 이름(`meso.webp`)을 싣고 앱이 폴더를 붙여 찾는다. `id` 를
  실으면 서버 DB 의 FK 와 같은 연결고리를 쓰게 되고, 관리 화면에서 그림 경로를 바꿔도 앱이 같은 그림을 찾는다.
- 그림 목록(`assets` 칸)의 줄에 `id` 를 더한다. 앱은 그림 칸의 `id` 로 그 줄을 찾아 기기의 파일을 연다.
- 그림 칸마다 `id` 칸을 새로 더한다. 크롭 줄도 `assetId` 로 그림을 가리킨다.

| 칸 | 옛 글자 칸 | 새 `id` 칸 |
|---|---|---|
| `bosses` | `portraitSlug` | `portraitAssetId` |
| `dropItems` · `huntLoot` | `iconFile` | `iconAssetId` |
| `worlds` | `emblem` | `emblemAssetId` |
| `cashbookCategories` | `iconFile` | `iconAssetId` |
| `spendCatalog` 의 타일 | `iconFile` · `iconMap` | `iconAssetId` |
| `symbolCosts` | `iconFile` | `iconAssetId` |
| `hexaMatrix` 의 코어 종류 · 직업별 코어 | `iconFile` | `iconAssetId` |
| `contents` | `backgroundMap` · `backgroundPortrait` | `backgroundMapAssetId` · `backgroundPortraitAssetId` |
| `huntingGrounds` 의 지역 | `iconMap` | `iconAssetId` |
| `imageCrops` | `slug` | `assetId` |

- 옛 글자 칸은 함께 낸다(사용자 지정 2026-11-09). 이미 깔린 앱(스토어 1.0.13 과 이 일 전의 OTA)은 옛 칸을 읽고, 칸이 없으면
  게임 데이터가 계약을 어겼다며 잠금 화면에서 멈추기 때문이다. 새 앱은 새 칸만 읽는다. 새 앱이 퍼지고 옛 버전을 잠근 뒤에
  옛 칸을 지운다.
- 새 칸을 읽는 앱은 계약 판(`GAME_DATA_CONTRACT`)을 올린다. 옛 사본에는 새 칸이 없어 새 앱이 읽을 수 없기 때문이다. 앱 코드만
  바뀌므로 스토어 출시 없이 OTA 로 낸다. 서버를 먼저 배포하고 OTA 를 낸다.
- 아이템 표는 지금 칸(`dropItems` · `equipmentItems` · `huntLoot`)으로 나눠 낸다. 거래 아이템을 앱에 내는 칸은 #912 를 구현할
  때 정한다.
- 그림 경로는 그대로다. 옛 앱이 경로로 그림 파일을 찾는다.

### 결정 5. 그림의 관리용 분류와 이름은 경로와 따로 둔다 (사용자 지정 2026-11-08)

- 경로는 앱이 그림을 찾는 주소라 바꾸지 않는다. 폴더를 나누면 앱의 폴더 목록과 기존 그림을 함께 옮겨야 한다.
- 아이템이 쓰는 그림은 그 아이템의 분류로 묶인다. 따로 고르지 않는다.
- 아이템이 쓰지 않는 그림(보스 초상 · 지도 · 스킬 · 드롭 연출 프레임 · 월드 엠블럼 · MVP 명패 등)은 그림 분류 하나를 고른다.
  그림 분류도 아이템 분류처럼 서버 코드에 고정한 목록이다. 지금은 폴더 그대로 쓰고 더 나누지 않는다(사용자 지정 2026-11-08).
- 그림에는 관리 화면에서 보이는 이름을 둔다. 파일 이름은 영어 slug 라 화면에서 무엇인지 알기 어렵기 때문이다. 아이템이 쓰는
  그림은 아이템 이름을 보인다.

### 결정 6. 관리 화면은 아이템 · 그림 화면을 새로 짜고, 그림 칸은 그림을 눌러 고른다

- **아이템 화면**: 왼쪽은 분류 트리, 오른쪽은 아이템 그림 격자다. 아이템을 누르면 오른쪽에서 편집 서랍이 열려 이름 · 분류 ·
  그림 · 성질 값을 고친다(사용자 선택 2026-11-08, 시안 아이템 A 의 짜임에 아이템 B 의 서랍). 편집 칸을 늘 세워 두지 않아서
  격자가 넓다.
- **그림 화면**: 왼쪽은 분류 트리, 오른쪽은 한 줄에 그림 하나인 목록이다(사용자 선택 2026-11-08, 시안 그림 B). 줄마다 보이는
  이름 · 경로 · 쓰는 곳 수 · 크기를 보이고, 맨 위 알림 줄이 표가 안 쓰는 그림 수를 알려 준다. 올리기 · 바꾸기 · 크롭은
  지금처럼 이 화면에서 한다.
- **그림 고르개**: 보스 · 월드 · 심볼 · 헥사 매트릭스 · 지출 카탈로그 · 컨텐츠 · 사냥터 · 가계부 분류 화면의 그림 칸을 글자
  입력 대신 그림을 눌러 고르게 한다. [[ADR-020]] 결정 15 의 `기존 화면의 그림 이름 칸은 글자로 둔다` 를 바꾸는 결정이다.
- **왼쪽 메뉴**: 게임데이터 메뉴를 아이템 · 그림 중심으로 다시 묶는다.
- 생김새는 지금 관리 화면의 규칙을 그대로 따른다. 차가운 회색 바탕 · 코발트 강조 · 왼쪽 메뉴이고, 테두리와 구분선 없이 면을
  가른다([[ADR-016]] 결정 13). 시안은 아티팩트 `관리 화면 아이템 · 그림 시안` 이다.

### 결정 7. 가계부 아이템 종류에 캐시를 더한다 (사용자 지정 2026-11-08)

- 가계부 아이템 구매 · 판매의 종류(`cashbook_item_kinds`)는 지금 장비 · 소비 · 기타 셋이다. 여기에 캐시를 더한다. 프라임 큐브 ·
  솔 헤카테 스킨 교환권 같은 캐시 아이템도 경매장에서 사고팔기 때문이다.
- 캐시 종류는 수량을 묻고 구매 관세가 붙는다(사용자 지정 2026-11-08). 종류 표의 단위(`unit`)와 관세 여부(`has_tariff`)를
  그렇게 채운다.
- 이 결정은 앱도 고친다. 앱이 종류 key 를 세 값(`ITEM_KIND_KEYS`)으로 걸러 모르는 종류를 버리기 때문이다. 앱 코드만 바뀌므로
  OTA 로 낸다.

### 결정 8. 앱 코드가 이름으로 쓰던 그림도 게임 데이터 표의 그림 칸으로 받는다 (사용자 지정 2026-11-08)

- 앱이 그림을 쓰는 방법은 지금 셋이다. 게임 데이터 표의 그림 칸을 거치는 방법, 앱 코드에 그림 이름을 직접 적는 방법, 표의 다른
  칸에서 이름을 빌려 다른 폴더를 찾는 방법이다. 뒤의 둘은 서버가 모르는 사용이라, 관리 화면에서 그 그림을 지워도 막을 수 없고
  앱에서 그림만 소리 없이 빠진다. 그래서 방법을 표의 그림 칸 하나로 통일한다.
- 앱 코드가 이름으로 쓰는 그림은 85장이다. 파일 이름으로 쓰는 17장(가계부 줄 표식 · 보스 수익의 메소 주머니와 결정석 칩 · 솔
  에르다 조각 · 솔 에르다의 기운 단위 넷 · 유니온의 부 · 세라자르 주화), 확장자 없는 이름으로 쓰는 주간 컨텐츠 카드 배경 4장
  (`arcanus` · `armorDragon` · `hallOfHeroes` · `flagRace`), 폴더째 쓰는 64장(MVP 명패 · 포스 · 모르는 캐릭터 · 드롭 연출
  프레임)이다.
- 다른 칸에서 이름을 빌리는 곳은 컨텐츠 카드의 지역 아이콘이다. 앱이 배경 지도의 이름으로 `maps/icons/` 의 같은 이름 그림을
  찾는다(`getDailyQuestRegionIconUrl`). 컨텐츠 표에 지역 아이콘 칸(`region_icon_asset_id`, 게임 데이터 `regionIconAssetId`)을
  더하고, 지금 앱이 찾는 그림으로 채운다.
- 그림을 붙일 표가 이미 있으면 그 표의 그림 칸에 두고, 없는 것만 새 표 하나에 둔다(사용자 지정 2026-11-08). 표에 붙어 있어야
  그 줄을 고칠 때 그림도 함께 보이기 때문이다.

| 그림 | 둘 곳 |
|---|---|
| MVP 명패 6 | MVP 등급 표(`mvp_grades`)에 그림 칸(`plate_asset_id`, 게임 데이터 `plateAssetId`)을 더한다. 일반 등급은 그림이 없다 |
| 가계부 줄 표식 중 사냥 · 솔 에르다 조각 · 수입 기타 · 지출 기타 | 가계부 분류 표(`cashbook_categories`)의 그 분류 그림. 지금도 같은 파일이다 |
| 사냥 계산기의 재물 획득의 비약 버프 | 가계부 분류 표의 사냥 그림을 같이 쓴다(사용자 지정 2026-11-09). 지금도 같은 파일이다 |
| 주간 컨텐츠 카드 배경 4 | 컨텐츠 표(`contents`)의 그림 칸. 지하 수로 · 주간 드래곤 퇴치 · PC방 주간 드래곤 퇴치는 보스 초상 칸, 주간 미션 포인트 · 플래그 레이스는 지도 칸이다. 그 다섯 줄은 있고 그림 칸만 비어 있다 |
| 솔 에르다 조각 | 아이템 표(`items`)의 그 아이템 그림 |
| 나머지 72장 | 새 표 `app_images`(역할 key 와 그림 `id`). 게임 데이터 칸은 `appImages` 다 |

- 새 표의 key 는 아래다. 드롭 연출 프레임은 단계와 차례를 key 에 담고, 앱은 같은 단계의 key 를 번호 차례로 모은다. 글자
  차례로 모으면 `10` 이 `2` 앞에 서서 프레임이 뒤섞인다.

- 새 표를 고치는 관리 화면은 S4 의 그림 고르개와 함께 만든다(사용자 지정 2026-11-09). 그 전까지 새 표는 이관이 지금 앱이 쓰는
  그림으로 채운 그대로다.
- 그림 경로는 바꾸지 않는다. 옛 앱은 계속 이름으로 그림을 찾기 때문이다.

### 결정 9. 표도 앱 코드도 쓰지 않는 그림은 하나만 지운다 (사용자 지정 2026-11-08)

2026-11-08 운영 서버의 그림 939장 중 표도 앱 코드도 쓰지 않는 그림은 15장이다(아이템 14 · 지도 1). 서버 작업 때 `items/rings/Tower_Boost_Ring.png`
하나만 지우고 나머지는 남긴다. 플래그 레이스 배경은 길드 플래그 레이스 카드가 쓰고 있어 지우지 않는다. 아이템 14장 중 대부분은 지출 타일이 그림 하나를 함께 쓰느라 남은 주문서 그림이라, 아이템 표에 연결하면
쓰이게 된다.
