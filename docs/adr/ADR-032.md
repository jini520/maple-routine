### ADR-032: 보스 수익 페이지 — 롤링 조회 윈도우 처리, 파티원 수 스냅샷 버그 수정, 미완료 보스 선등록, UI 정리 (구현 완료)

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**배경**: 보스 수익 페이지를 실사용하며 확인된 문제 4건을 함께 정리한다(2026-07-22, 사용자 확인):

1. 스케줄러 API의 `date` 파라미터는 [[ADR-023]]이 확인한 고정 하한선(`MIN_SCHEDULER_DATE`, API 도입 시점) 외에도 **오늘 기준 최근 13일까지만** 조회된다(오늘-14일은 조회 불가, 오늘-13일까지는 조회됨 — 사용자 재실측). 이 롤링 제약은 PRD #6·#7에서 이미 알려져 있었으나([[ADR-023]]이 "고정 하한선과는 무관한 별개"라고만 언급하고 정확한 값은 미확인 상태로 남겨뒀다) 실제 코드에는 전혀 반영되지 않았다 — 캐시도 없고 이 창을 벗어난 과거 기간을 백필하려 하면 매 방문마다 실패할 API를 계속 호출했다.
2. 사용자가 보스 수익 페이지에서 파티원 수를 수정해도 다른 탭으로 이동했다가 돌아오면 값이 파티 관리 기본값으로 되돌아가는 것처럼 보인다는 보고. 재현 결과 실제 원인은 파티 관리 로직이 아니라 `setPartySize`가 화면 상태(`rows`)만 갱신하고 모듈 스코프 캐시 스냅샷(`latestSyncSnapshot`)은 갱신하지 않는 버그였다 — `loadPeriod`의 "현재 기간" 분기가 이 스냅샷에서 슬라이스하므로 탭 전환/기간 이동 왕복이 한 번이라도 끼면 수정한 값이 스냅샷의 낡은 값으로 되돌아갔다.
3. Nexon Open API는 `complete_flag`가 true가 돼야만 보스 수익 페이지에 보스가 등록되는데, 실제로는 인게임에서 처치 직후 물욕템을 바로 입력하고 싶어도 API가 `complete_flag`를 갱신하는 데 시간이 걸려 즉시 입력할 수 없었다(추후 드랍 아이템 입력 기능 확장을 염두에 둔 요구).
4. UI 세부사항 3건: 카드 간격이 컨텐츠/보스 스케줄러와 다름, 난이도 표기가 텍스트("보스명 · 난이도")라 보스 스케줄러의 뱃지 스타일과 불일치, 새로고침 아이콘 옆에 마지막 조회 시각 표시가 없음(컨텐츠/보스 스케줄러에는 있음).

**결정**:

1. **롤링 조회 윈도우 반영**: `lib/boss-profit-period.ts`에 `getMinQueryableDate(now)`(오늘 KST 기준 -13일)와 `isPeriodQueryable(cycle, periodKey, now)`(고정 하한선 `MIN_SCHEDULER_DATE`와 롤링 하한선 중 더 늦은 쪽을 기준으로 판정)를 추가했다. `backfillTarget`(`features/boss-profit/store.ts`)은 기존 `date < MIN_SCHEDULER_DATE` 단일 조건을 `!isPeriodQueryable(...)`로 대체해 두 하한선을 동일하게 처리한다 — 조회 불가면 API를 호출하지 않고 곧바로 `markPeriodChecked`로 확정해 이후 방문에서 재시도하지 않는다. **캐시된 기록이 이미 있으면(롤링 창이 열려있던 시점에 확보) 조회 가능 여부와 무관하게 그 기록을 그대로 보여준다** — `isPeriodQueryable`은 어디까지나 "기록이 없을 때 지금 API를 불러도 되는가"만 판정하고, 기존 기록을 덮어쓰거나 숨기지 않는다.
2. **"조회 불가" 상태 통합**: 기존 `WeeklySubtotalState`의 `'unavailable'`(고정 하한선 이전 주 전용)을 롤링 윈도우 케이스까지 포함하도록 조건을 확장하고(`buildWeeklySubtotalsForMonth`), 표시 문구를 기존 "데이터 없음"에서 **"조회 불가"**로 통일했다(사용자 판단 — 사용자 관점에서 둘 다 "확인할 수 없다"는 같은 의미이고 "조회 불가"가 더 직관적). 월간 탭의 월간 보스(검은마법사) 자체 행과 주간 탭의 빈 목록에도 같은 "조회 불가" 표시를 확장 적용했다(`BossProfitScreen.tsx`) — 이전에는 이 두 곳에 조회 불가 개념 자체가 없어 "아직 처치한 보스가 없습니다"(확정된 빈 상태)와 구분이 안 됐다.
3. **`setPartySize` 스냅샷 동기화 버그 수정**: `setPartySize`가 `get().rows`뿐 아니라 `latestSyncSnapshot.rows`도 같은 매핑 함수로 함께 갱신하도록 수정했다. 재현 테스트(`store.test.ts` "setPartySize 이후 다른 탭으로 이동했다가 돌아와도 수정한 값이 유지된다")로 수정 전 실패·수정 후 통과를 확인했다.
4. **미완료 보스 선등록**: `MatchedBoss.isRegistered`(이미 존재, [[ADR-031]])를 활용해 `refresh()`가 완료된 보스뿐 아니라 "등록됐지만 아직 미완료"인 보스도 `selectDisplayBosses`(boss-scheduler 카드와 동일한 그룹핑 규칙, [[ADR-031]])로 함께 골라 화면에 표시한다. `BossProfitRow`에 `isComplete: boolean`을 추가해 미완료 placeholder는 `payoutMeso: 0`·`partySize: null`로 고정하고 "미완료" 배지를 보여준다(가격 미확정 배지와 동일한 비활성 스타일 재사용). **미완료 placeholder는 절대 `boss_profit_records`에 자동 기록하지 않는다** — 기록해버리면 나중에 실제로 완료됐을 때 "이미 기록 있음"으로 오판해 실제 처치 수익으로 재계산되지 않고 0메소로 영구 고정되는 문제가 생기기 때문이다(`refresh()`의 자동 기록 루프에 `!row.isComplete` 가드 추가). 드랍 아이템 입력 확장(터치해서 물욕템 추가)은 이번 범위에 포함하지 않는다 — placeholder 표시까지만.
5. **파티원 수 스테퍼는 미완료 여부와 무관하게 최소 변경으로 처리**: 스테퍼를 완전히 숨기는 대신 기존 "가격 미확정" 비활성 패턴을 그대로 재사용해 `!row.isComplete`일 때도 같은 방식으로 비활성화했다(사용자 판단 — 스테퍼 노출 여부 자체는 중요하지 않으니 구현 변경이 적은 쪽 선택).
6. **UI 정리 3건**: (a) 캐릭터 아코디언 리스트 간격을 컨텐츠/보스 스케줄러의 카드 리스트와 동일하게 `space-y-4`→`space-y-2`로 변경. (b) 보스 스케줄러 전용이던 `DifficultyBadge`를 `app/boss-scheduler/BossScreen.tsx`에서 `components/DifficultyBadge/DifficultyBadge.tsx`로 이동해(프로젝트 관례상 화면 간 직접 import 지양) `BossProfitBossRow`의 "보스명 · 난이도" 텍스트 표기를 "난이도 뱃지 + 보스명"으로 교체(보스 스케줄러 카드와 동일한 순서). 기존에 `PartyManagementModal.tsx`가 `BossScreen.tsx`에서 직접 import하던 것도 이번에 함께 정리. (c) 스토어에 페이지 전체 기준 `lastSyncedAt`(마지막 성공한 실시간 동기화 시각)을 추가해 새로고침 아이콘 옆에 컨텐츠/보스 스케줄러와 동일한 `formatSyncedAt`로 상대 시간을 표시 — 보스 수익 페이지는 캐릭터를 한 번에 여러 명 보여주는 구조라(컨텐츠/보스 스케줄러의 "선택된 캐릭터 1명" 개념이 없음) 캐릭터별이 아니라 페이지 전체 기준 타임스탬프로 뒀다.
7. **PRD #46 확정**: [[ADR-023]]이 "과거 기간 읽기 전용(스테퍼 비활성)"으로 잠정 설계했던 부분은 실제로는 처음부터 스테퍼가 항상 활성화된 채로 구현돼 있었고(문서만 안 갱신됨) 이 동작이 맞다고 확정했다 — 과거 기록도 파티원 수 편집이 계속 가능하다.

**이유**:
- 롤링 윈도우를 판정 함수 하나(`isPeriodQueryable`)로 통합한 이유: 고정 하한선과 롤링 하한선을 따로 처리하면 "조회 불가"의 두 원인이 코드 곳곳에 흩어져 표시 로직이 갈라진다. 어차피 사용자에게는 "지금 확인할 수 없다"는 같은 결과이므로 하나의 판정으로 합치는 게 단순하다.
- 캐시된 기록이 있으면 조회 가능 여부와 무관하게 그대로 보여주기로 한 이유: 롤링 윈도우는 매일 앞으로 밀리므로, 이미 창이 열려있을 때 확보해둔 기록까지 "조회 불가"로 덮어써 버리면 실제로 존재하는 데이터를 숨기는 퇴행이 된다.
- 미완료 placeholder를 DB에 기록하지 않기로 한 이유: 이 페이지의 기존 핵심 불변식(ADR-014/019) — "기록이 없는 조합만 자동 기록 대상"이 미완료 상태에도 깨지지 않아야, 실제 완료 시점에 정상적으로 자동 기록되는 기존 흐름을 그대로 재사용할 수 있다.
