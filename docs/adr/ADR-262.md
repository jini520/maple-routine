# ADR-262: 지출에 `주문서` 갈래를 더한다. 줄 둘로 항목 하나를 고른다

> 🟢 유효 · 2026-09-12 · **구현 완료** · 실기기 미검증

**관련**: [[ADR-245]] 결정 2(에픽던전은 형태마다 단계를 고른다) · [[ADR-243]](지출 기록도 갈래를
먼저 고른다) · [[ADR-006]](게임 수치는 사용자 확인)
**문서**: `features/cashbook.md`
**이슈**: #360

## 맥락

사용자가 메소로 사는 주문서 19종을 지출로 적게 해 달라고 했다(이슈 #360). 값이 정해져 있으므로
참조표(`spend-catalog.json`)에 항목으로 넣고 선택 목록 폼(`CatalogForm`)을 쓴다. 금액은 `unitPrice` ×
수량이다.

주문서에는 가격이 같고 이름이 비슷한 것이 많다. 사용자는 그런 것을 타일 하나로 묶고, 타일을 고른
뒤 갈래를 고르게 하라고 지정했다. 그중 둘은 고를 줄이 둘이다.

- 매지컬 주문서: `한손무기`/`두손무기` × `공격력`/`마력`. 두손무기 마력 주문서는 없다.
- 귀 장식 주문서: `공격력`/`마력` × `힘`/`민첩`/`운`. 마력 주문서는 스탯이 갈리지 않는다.

지금 폼이 아는 선택은 둘뿐이다. 대표 안의 단계 하나(`tier`)와, 형태마다 단계를 따로 골라 금액을
더하는 에픽던전의 형태(`forms`)다. 줄 둘을 골라 항목 하나를 정하는 방식은 없다.

## 결정

### 결정 1. 갈래 `주문서` 를 선택 목록 넷째로 둔다

`SPEND_CATEGORIES` 가 `컨텐츠 · 이벤트·BM · 버프 · 주문서 · 아이템 구매 · 기타` 가 된다. 앞의 넷이
선택 목록이고 뒤의 둘이 직접 입력이다. 참조표의 `categories` 에도 `주문서` 가 들어간다.

주문서는 전부 메소로 산다. 관세는 없다. 관세는 아이템 구매 갈래의 것이다. 단위는 `개` 이고 수량
상한이 없다.

**갈래 카드 그림은 놀긍이다**(사용자 지정 2026-09-12). 그림이 오기 전에는 `SpendSheet.tsx` 의
`CATEGORY_ICON_FILES` 를 빈 칸을 허락하는 `Partial` 로 풀어 뒀는데, 여섯 갈래가 모두 그림을 갖게
되어 `Record` 로 되돌렸다. 그 타입이 갈래마다 그림 하나를 컴파일 단계에서 지킨다. 없는 파일 이름을
적어 빈 자리를 만들지 않는다. 오타와 구분이 안 되기 때문이다.

**타일 그림은 `ITEM_ICON_BY_LABEL` 이 든다**(`spendIconOf`). 타일 하나에 그림 한 장이라, 항목이
여럿인 타일은 **대표의 그림**을 쓴다(사용자 지정). 일반과 카르마 두 벌이 온 것은 일반 쪽이고,
프리미엄 악세의 대표는 공격력 주문서다(사용자 지정 2026-09-12).

**심볼 강화 갈래는 이번에 안 넣는다.** 비용 표가 아직 없다. 표 없이 갈래만 서면 눌러도 적을 수
없는 칸이 된다.

### 결정 2. 항목이 축 값을 든다. 규칙을 타일마다 코드에 적지 않는다

줄이 둘인 타일의 항목은 `options` 칸에 축 값을 적는다.

```json
{ "category": "주문서", "group": "주문서", "name": "매지컬 한손무기 마력 주문서 100%", "base": "매지컬 주문서", "options": { "무기": "한손무기", "능력치": "마력" }, "currency": "meso", "unitPrice": 60000000, "unit": "개" }
{ "category": "주문서", "group": "주문서", "name": "귀 장식 마력 주문서 10%", "base": "귀 장식 주문서", "options": { "능력치": "마력" }, "currency": "meso", "unitPrice": 100000000, "unit": "개" }
```

줄의 차례와 줄 안 값의 차례는 항목들에 처음 나온 차례다(`optionAxesOf`). 매지컬은 `무기` ·
`능력치`, 귀 장식은 `능력치` · `스탯` 이다.

규칙을 타일 이름으로 코드에 적으면 주문서가 하나 늘 때마다 코드를 고쳐야 한다. 항목에 축 값만
적으면 아래 규칙이 항목 목록에서 나온다.

줄이 하나인 타일(펫장비 주문서 · 프리미엄 악세 · 프리미엄 펫장비 · 놀긍)은 지금의
`base`·`tier` 로 된다. 단계 줄의 글자가 `tier` 그대로다(`공격력`/`마력` · `60%`/`100%`).

**`펫장비 주문서` 는 묶음 이름과 타일 이름이 같다**(사용자 지정 2026-09-12). 펫장비 공격력·마력이
한 타일로 묶이면서 그 이름을 받았다. 같은 날 `펫장비 이노센트`·`펫장비 순백` 의 이름도 줄였다.

### 결정 3. 한 값을 누르면 그 값을 가진 항목만 남긴다

누름 한 번이 넷을 차례로 한다. `lib/cashbook/spend-catalog.ts` 의 `pickSpendOption` 이 이 규칙
하나다.

1. 한 줄의 값을 누르면, 그 값을 가진 항목만 남긴다.
2. 다른 줄에서 지금 고른 값이 남은 항목에 없으면 그 줄의 선택을 지운다.
3. 남은 항목이 다른 줄에 값을 하나만 가지면 그 값을 고른다.
4. 남은 항목이 다른 줄을 아예 안 가지면 그 줄을 흐리게 하고 누를 수 없게 한다.

사용자가 지정한 동작이 모두 이 넷에서 나온다.

- 매지컬에서 마력을 누르면 남는 것은 한손무기 마력 하나라 한손무기가 골라진다(3). 두손무기를 골라
  둔 상태였다면 먼저 지워진다(2).
- 매지컬에서 두손무기를 누르면 능력치가 공격력으로 바뀐다(2 · 3). 매지컬에는 눌리지 않는 칸이 없다.
- 귀 장식에서 능력치를 고르지 않고 힘을 누르면 남는 것은 공격력(힘) 하나라 공격력이 골라진다(3).
- 귀 장식에서 마력을 누르면 스탯 줄이 없는 항목만 남아 그 줄이 잠긴다(4). 공격력으로 돌아오면 줄이
  다시 열리고 **스탯은 비어 있다.** 마력 전에 고른 스탯을 되살리지 않는다(사용자 확인).

처음에는 아무것도 고르지 않았고 두 줄 모두 눌린다. 줄이 잠겼는지는 지금 고른 값에 맞는 항목들로
판정한다(`isOptionAxisOpen`). 잠긴 줄은 세그먼트가 흐려지고 안 눌린다(`Segment` 의 `disabled`).

### 결정 4. 항목 하나가 정해져야 저장이 켜진다

고른 값이 한 항목의 축 값과 꼭 맞을 때만 그 항목이 정해진다(`optionItemOf`). 귀 장식에서
공격력만 골랐으면 맞는 항목이 없어 저장이 꺼져 있다. 에픽던전에서 형태별 단계를 하나도 안 골랐을
때 저장이 꺼져 있는 것과 같다.

기록에 남는 이름(`item`)은 그 항목의 `name` 이다(`귀 장식 공격력(힘) 주문서 10%`). 수정으로 열 때는
그 이름으로 항목을 찾아 두 줄의 값을 되살린다. 에픽던전 기록의 이름을 되읽는 자리와 같다.

### 결정 5. 값이 모두 같은 타일은 가격을 하나만 적는다

타일은 항목 값을 모두 ` | ` 로 잇는다(`tilePriceLabel`). 매지컬은 항목이 셋이라 `6,000만 | 6,000만 |
6,000만 메소` 가 된다. 같은 값을 여러 번 적으면 좁은 타일에서 잘리고, 갈래마다 값이 다르다고 읽힌다.
그래서 값이 모두 같으면 하나만 적는다. 놀긍은 값이 달라 `50만 | 3억 메소` 로 둘을 적는다.

## 대가

- **축 값이 이름과 따로 적힌다.** `options` 는 이름 안에 이미 있는 글자를 한 번 더 적는 것이라 둘이
  어긋날 수 있다. 참조표 테스트는 한 타일 안에서 축 값의 조합이 겹치지 않는지를 본다. 이름과 축 값이
  맞는지는 사람이 본다.
- **항목마다 온 그림을 다 쓰지는 않는다**(사용자 지정 2026-09-12). 타일에 한 장만 서므로 매지컬
  마력·두손무기 · 펫장비 마력 · 프리미엄 펫장비 마력 · 카르마 세 장은 파일로만 남고 번들에 실린다.
  항목 그림을 3단계에 세우는 안은 사용자가 고르지 않았다.
- **줄 이름 `스탯` 은 앱이 지었다.** 이슈 #360 의 예시가 적은 줄 이름은 `무기` · `능력치` 이고,
  힘 · 민첩 · 운 줄은 예시에 없었다. 참조표의 글자라 바꾸려면 JSON 만 고친다.
