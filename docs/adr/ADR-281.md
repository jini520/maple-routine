# ADR-281: 더보기에 문의하기 줄을 두고, 누르면 받는 사람 · 제목 · 기기 정보가 채워진 메일 앱을 연다

> 🟢 유효 · 2026-09-15 · **구현 완료**(2026-09-15) · 실기기 미검증 · 사용자 결정(2026-09-14, 이슈 #439)
>
> 코드 자리: 주소는 `app/settings/contact-mail.ts` 의 `contactMailUrl` · `contactDeviceOf` 가 만들고, 줄은 `SettingsScreen` 의
> 셋째 카드가 `SettingsLinkRow`(열기 실패는 `onOpenFailed`)로 세운다.

**관련**: [[ADR-266]](더보기 셋째 카드 · 앱을 떠나는 줄 `SettingsLinkRow`) · [[ADR-279]](보이는 앱 버전은
`useRunningAppVersion`) · [[ADR-155]](지문이 바뀌면 이미 나간 바이너리가 OTA 를 못 받는다)
**문서**: `features/settings.md`

## 맥락

앱 안에는 문의하는 길이 없다. 메일 주소 `support.mapleroutine@gmail.com` 은 안내 사이트의 문의 페이지
(`site/support.md`)와 `PRIVACY.md` 에만 있다. 문의 페이지는 버그를 신고할 때 앱 버전 · 기기와 OS 버전 · 화면과
동작 · 캡처를 함께 달라고 안내하고, API 키는 가려 달라고 적는다. 사용자가 앱에서 바로 문의할 길을 요청했다
(2026-09-14).

### 결정 1. 메일 앱을 연다. 서버로 보내지 않는다

`Linking.openURL` 에 `mailto:` 주소를 넘긴다. 앱 안 양식으로 서버에 보내면 스토어 설명의 `운영자에게 전송되지
않습니다` 문장과 개인정보 처리방침을 고쳐야 한다. 메일 앱으로 보내면 사용자가 자기 메일로 직접 보내는 것이라 둘 다
그대로다.

- 열 수 있는지 미리 묻지 않고(`canOpenURL`) `openURL` 의 실패로 가른다. `canOpenURL` 은 플랫폼 설정이 있어야
  맞게 답한다. 안드로이드 매니페스트의 `<queries>` 에는 `https` 만 있다.
- 안드로이드의 `openURL` 은 `<queries>` 없이도 메일 앱을 띄운다. RN 의 `IntentModule.openURL` 이 `startActivity`
  를 바로 부르고, 받을 앱이 없으면 그 예외를 거절로 돌려준다. 그래서 매니페스트를 안 고친다. 고치면 지문이 바뀐다.

### 결정 2. 메일 앱이 안 열리면 토스트로 알리기만 한다 (사용자 지정)

주소 복사를 두지 않는다. 메일 앱이 받는 사람을 채운 채 열리면 주소를 옮겨 적을 일이 없고, 복사 수단(RN 코어
`Clipboard`)은 deprecated 경고를 낸다.

- 토스트 문구에 주소를 적는다. `메일 앱을 열지 못했습니다. support.mapleroutine@gmail.com 으로 보내 주세요`.
  복사는 없어도 사용자가 주소를 읽고 다른 기기에서 보낼 수 있다.

### 결정 3. 줄은 더보기 셋째 카드의 `개발자 응원하기(앱 리뷰)` 위다 (사용자 지정)

둘 다 앱을 떠나는 줄이라 같은 카드다. 이름은 `문의하기` 이고 오른쪽은 외부 링크 표식이다(`SettingsLinkRow` 와 같은
모양). 응원은 평생 한 번 누르는 것이라 맨 아래에 두었는데([[ADR-266]]), 문의는 그보다 자주 쓰여 위에 선다.

### 결정 4. 제목은 `[메이플 루틴 문의]` 이고, 본문에 버그 신고 안내와 기기 정보를 미리 넣는다 (사용자 지정)

```
(문의 내용을 적어 주세요)



----
버그를 신고하실 때는 어느 화면에서 무엇을 했는지와
화면 캡처를 함께 보내 주세요.
API 키가 보이면 가려 주세요.

앱 1.0.10 / SM-F711N / Android 15
```

- 안내 두 문장은 문의 페이지의 `버그를 신고하실 때` 를 줄인 것이다.
- **기기 정보 줄에는 앱 버전 · 기기 모델 · OS 버전만 넣는다.** API 키 · 캐릭터 정보는 넣지 않는다.
- **앱 버전은 `useRunningAppVersion` 이다.** 더보기 화면 아래 버전과 같은 값이다([[ADR-279]]). `package.json` 을
  바로 읽으면 OTA 버전이라 스토어 바이너리 버전과 따로 움직인다.
- **OS 버전은 플랫폼마다 읽는 칸이 다르다.** iOS 는 `Platform.Version`(`'18.5'` 같은 문자열)이다. 안드로이드의
  `Platform.Version` 은 API 레벨 숫자라 버전 이름인 `Platform.constants.Release` 를 쓴다.
- 제목과 본문은 `encodeURIComponent` 로 감싼다. 한글 · 줄바꿈 · `&` 가 주소를 깨지 않게 한다.
- 주소를 만드는 일은 순수 함수가 진다(`app/settings/contact-mail.ts` 의 `contactMailUrl`). 화면이 플랫폼 값을 넘긴다.
  플랫폼 분기를 화면에 적으면 두 갈래 중 한쪽만 테스트가 볼 수 있다(`storeReviewUrl` 과 같은 이유).

### 결정 5. 기기 모델은 안드로이드만 이번 OTA 에 넣는다 (사용자 지정)

- 안드로이드는 네이티브 모듈 없이 RN 코어의 `Platform.constants.Model` 로 모델명을 읽는다. 예: `앱 1.0.10 / SM-F711N / Android 15`.
- iOS 에는 그 값이 없어 `expo-device` 가 필요하다. 네이티브 모듈을 더하면 지문이 바뀌어 이미 나간 바이너리가 그 OTA 를
  못 받으므로([[ADR-155]]) 다음 스토어 릴리스에 더한다. 그때까지 iOS 는 `앱 1.0.10 / iOS 18.5` 다.
- 모델을 못 읽으면(빈 글자) 그 칸을 빼고 `앱 1.0.10 / Android 15` 로 적는다.

## 대가

- iOS 문의에는 한동안 기기 모델이 없다.
- 메일 앱마다 `mailto:` 본문을 받는 방식이 다를 수 있다. iOS 기본 메일 · Gmail · 삼성 이메일에서 제목과 본문이 채워지는지
  실기기에서 본다.

## 기각

- **앱 안 양식으로 서버에 보낸다.** 결정 1. 스토어 설명과 개인정보 처리방침을 고쳐야 한다.
- **메일 앱이 안 열릴 때 주소를 복사한다.** 결정 2. 사용자가 필요 없다고 했다.
- **iOS 모델명을 위해 이번에 `expo-device` 를 넣는다.** 결정 5. OTA 가 끊긴다.
