# ADR-125 — 기능 사용법 안내는 기능 카탈로그 한 벌이고, 개발 노트는 거기로 링크만 건다 (이미지는 번들)

- 상태: **결정 완료(결정 1·3 은 같은 날 정정) · 구현 완료(글만) · 스크린샷 대기 · 실기기 미검증** (2026-08-10, 이슈 #198, 마일스톤 v1.0.4). 테스트 3,005개·lint 0 error·프로덕션 빌드 통과. **안내 넷의 이미지가 아직 0장**이고(사용자가 직접 촬영), 화면을 실기기·시뮬레이터에서 눈으로 본 적이 없다
- 관련: [[ADR-119]](릴리스 노트 진실 원천 한 벌 · 항목 단위 표식 · 카테고리 묶음. **이 ADR이 그 위에 얹힌다**) · [[ADR-118]](설정 계층 — 하위 페이지) · [[ADR-120]](스택 스크린 · 2단 스택 선례 · 청크는 탭 단위) · [[ADR-094]](`PageHeader`) · [[ADR-060]](빈 상태 크기) · [[ADR-092]](화면 청크 분할) · [[ADR-018]](탭 토글 스타일)
- 관련 문서: [features/settings.md](../features/settings.md) · [features/live-update.md](../features/live-update.md)

## 맥락

개발 노트([[ADR-119]])는 **무엇이 바뀌었는지 한 줄로 나열만** 한다.

```
v1.0.3                          2026-08-09
 기능
  · 개발 노트 추가 — 버전별 변경 내역 확인   ← 여기서 끝
```

한 줄은 *"바뀐 것이 있다"* 까지만 말하고, **그것이 화면 어디에 있고 어떻게 쓰는지는 말하지 않는다.**
새 기능일수록 이 간극이 크다 — 버그 수정은 한 줄로 충분하지만, 새로 생긴 화면은 한 줄을 읽어도
어디로 가야 하는지 모른다. 이 앱에는 기능 사용법을 설명하는 자리가 **한 군데도 없다.**

## 결정 1 — ~~축은 버전이다~~ → **원천은 기능 카탈로그, 노트는 링크만 건다** (2026-08-10 정정)

### 처음 결정 (같은 날 폐기)

두 안을 놓고 사용자가 골랐다.

| 안 | 성질 | 결과 |
|---|---|---|
| 기능별 상시 가이드 | 앱 기능 전체를 나열한 카탈로그 | 기각 |
| **버전별 새 기능 소개** | 릴리스 노트의 버전 축을 승계 | 채택 → **폐기** |

근거는 *"기능 카탈로그는 릴리스 노트와 **별개의 축을 하나 더** 유지해야 하고, 두 축은 언젠가
반드시 어긋난다"* 였다. 그리고 대가를 이렇게 적어 뒀다 — *"오래된 기능은 옛 버전 카드 안에 묻힌다.
그 요구가 실제로 생기면 그때 카탈로그를 얹는다."*

### 정정 — 그 "실제로 생기면"이 구현 당일에 왔다

사용자 지시(2026-08-10): *"설명 페이지에 기능 설명 탭을 만들고 기능별로 페이지를 만든다. 개발
노트에 링크를 걸고 기능 설명에 있는 동일한 기능 설명으로 링크를 연결한다."*

**두 축을 다 두되 원천을 하나로 못박는 형태**라, 폐기 근거였던 "두 축이 어긋난다"가 성립하지 않는다.

```
src/data/feature-guides.ts     ← 원천 한 벌 (기능 축)
   ├─ /settings/guide          기능 설명 — 그룹 탭으로 전체를 나열
   └─ 개발 노트 항목 guideId   같은 화면으로 링크만 건다 (사본 없음)
```

- **어긋날 수 있었던 것은 "축이 둘"이어서가 아니라 "본문이 둘"일 때다.** 노트가 링크만 걸면 설명은 한 벌로 남는다.
- 그리고 버전 축만으로는 *"지금 이 앱을 어떻게 쓰나"* 에 답할 자리가 없다 — 첫 결정이 스스로 적어 둔 대가가 그것이었고, 이제 그 대가를 치르지 않는다.

### 딸려 오는 규칙 변경 — "고아 안내 금지"를 폐기한다

버전 축이던 시절의 참조 무결성은 **양방향**이었다(모든 `guideId` 에 안내가 있고, 모든 안내가 어느
노트 항목엔가 물려 있다). 뒷방향은 이제 **틀린 규칙**이다 — 원천이 카탈로그이므로 **노트가
가리키지 않는 안내가 정상**이다. 옛 기능은 릴리스 노트가 남아 있지 않아도 사용법은 있어야 하고,
안내는 그 기능이 살아 있는 한 계속 산다. 앞방향(미아 참조 금지)은 그대로 남는다.

### 탭은 하단 탭바와 같은 축이다

그룹은 `컨텐츠 · 보스 · 수익 · 설정 · 공통` 이다. 앞 넷은 **하단 탭바와 글자까지 같다** — 사용자가
이미 아는 구획이라 안내를 찾을 때 새로 배울 것이 없다. `공통` 은 어느 탭에도 속하지 않는 앱 전반의
동작(화면 전환·제스처)이고, 그것을 탭 이름에 억지로 밀어 넣으면 그 탭을 열어 본 사람이 엉뚱한
것을 만난다.

- **비어 있는 그룹은 탭째 감춘다** — 개발 노트의 카테고리 묶음·`ThemeSelector` 와 같은 규칙이다. 지금 `컨텐츠` 에는 안내가 없고, 빈 탭을 열면 아무것도 없는 화면을 만난다.
- **그룹이 하나뿐이면 탭 줄 자체를 그리지 않는다** — 선택지가 둘 이상일 때만 탭이 뜻을 갖는다.
- 스타일은 `design-system.md` 「탭 토글」절 그대로다([[ADR-018]]) — 새 스타일을 만들지 않는다.

## 결정 2 — 가이드 본문은 `release-notes.ts` **밖**에 산다

**항목에 본문을 직접 붙이려던 것을 뒤집는다**(이슈 #198 최초안 정정, 2026-08-10). 이유는 설계
취향이 아니라 **배포 경로가 깨지기 때문**이다.

`scripts/publish-live-update.mjs:33` 이 `src/data/release-notes.ts` 를 **Node 에서 직접 import**
한다(타입 스트리핑, [[ADR-119]] 결정 1 — 스크립트용 사본을 두지 않으려고 원천을 그대로 읽는다).
가이드 본문에는 이미지가 붙고(결정 4), 이미지는 `import img from '../assets/guide/x.webp'` 로
들어온다. **Node 는 `.webp` import 를 해석하지 못한다** — 넣는 순간 `npm run publish` 가 죽는다.

그래서 참조는 **id 문자열**로 끊는다.

```
src/data/release-notes.ts    items[].guideId?: string   ← 순수 데이터 유지, Node 가 읽는다
src/data/feature-guides.ts   FEATURE_GUIDES             ← 이미지 import + 본문. 앱만 읽는다
```

두 파일이 갈라질 위험은 **테스트가 막는다** — 미아 참조 금지(모든 `guideId` 에 안내가 있다) +
id 중복 금지 + 노트 항목의 중복 참조 금지. [[ADR-119]] 가 순서·중복·형식을 데이터 테스트로
강제한 것과 같은 방식이고, 같은 이유다: 런타임에 조용히 통과하는 것을 컴파일이 못 막으면
테스트가 막는다.

> 처음엔 **양방향**이었다(모든 안내가 어느 노트 항목엔가 물려 있어야 한다). 결정 1 정정으로
> 원천이 카탈로그가 되면서 **뒷방향은 틀린 규칙이 됐다** — 노트가 가리키지 않는 안내가 정상이다.

### 부수 효과 둘 — 둘 다 이득이다

1. **매니페스트가 안 커진다.** `latest.json` 의 `notes` 는 노트 텍스트만 나가고 가이드는 안 실린다. 업데이트 모달은 번들을 **받기 전** 에 뜨므로 어차피 이미지를 그릴 수 없다.
2. **개발 노트 목록 화면이 이미지 모듈을 안 건드린다.** `›` 를 그릴지는 `guideId` 문자열 유무로 판정되므로, 목록 화면은 안내 모듈을 import 하지 않는다 — 상세로 들어가야 비로소 이미지가 붙은 모듈이 온다. (기능 설명 목록은 제목을 읽어야 해서 이 이득을 못 받는다.)

## 결정 3 — 상세 하나가 **두 부모 아래 각각 라우팅된다** (2026-08-10 정정)

```
/settings/guide                     기능 설명 (그룹 탭 · 원천)
/settings/guide/:guideId            기능 안내   ← 자식
/settings/release-notes             개발 노트
/settings/release-notes/:guideId    기능 안내   ← 같은 화면·같은 데이터, 자식
```

처음엔 개발 노트 자식 하나뿐이었고, 설정 본화면에 행을 신설하는 안은 *"입구가 둘이 되고
[[ADR-118]] 이 2카드 5행으로 눌러 놓은 설정에 행이 는다"* 로 기각돼 있었다. 결정 1 정정으로 기능
설명이 원천이 되면서 **그 행이 필요해졌다** — 설정은 **2카드 6행**이 되고, `기능 설명` 이
`개발 노트` **위**다(*"이 앱을 어떻게 쓰나"* 가 *"무엇이 바뀌었나"* 보다 자주 묻는 질문이다).

### 왜 한쪽으로 몰지 않았나 — `replace` 로 떨어진다

*"기능 설명 밑에만 두고 개발 노트에서는 그리로 보낸다"* 가 자연스러워 보이지만 **쓸 수 없다.**
`resolveStackDirection`(`src/lib/stack-transition.ts:162`)은 push/pop 을 **경로의 접두 관계**로
판정한다.

| 이동 | 접두 관계 | 판정 |
|---|---|---|
| `/settings/release-notes` → `/settings/release-notes/x` | 접두 | `push` ✅ |
| `/settings/guide` → `/settings/guide/x` | 접두 | `push` ✅ |
| `/settings/release-notes` → `/settings/guide/x` | **서로 접두 아님** | `replace` ❌ |

`replace` 면 **밀려 들어오는 전환이 사라지고** 화면이 그냥 갈린다. 라우트를 둘 두면 양쪽 모두
자기 부모의 자식이라 정상적인 push 다. 화면과 데이터는 **한 벌**이고 경로만 둘이다.

- 그래서 상세는 부모를 상수로 박지 않고 **현재 경로에서 깎아** 쓴다(`resolveParentPath(pathname)`). 어디서 왔든 그리로 돌아가야 하고 — 개발 노트에서 들어왔는데 기능 설명 목록으로 튀면 읽던 자리를 잃는다 — 딥링크 폴백도 같은 값이어야 한다.
- 없는 `:guideId` 로 들어오면 **들어온 쪽 목록**으로 `replace` 한다. 옛 딥링크·오타의 착지점이 빈 화면이 되면 안 되고, 히스토리에 남겨 뒤로가기가 다시 그리로 가게 둘 이유도 없다.
- 화면 청크는 `screen-settings` 하나라([[ADR-120]] 결정 14) 상세로 밀어 넣을 때 **JS 추가 읽기가 없다.** 이미지는 별개 에셋이라 그릴 때 온다.
- `/settings/about/privacy` 에 이어 2단 스택이 셋으로 는다([[ADR-120]] 결정 11).

## 결정 4 — 이미지는 **앱 번들**에 넣고, glob 이 아니라 **명시적 import** 로 건다

원격(사이트·GitHub Pages) 로드는 **기각**(사용자 결정) — 번들은 안 늘지만 **오프라인에서 안내가
통째로 빈다.** 개인정보 처리방침을 `iframe` 으로 실으면서 오프라인을 감수한 것([[ADR-120]] 결정 11)과
판단이 갈리는데, 그쪽은 *"어긋난 법적 문서가 안 보이는 것보다 나쁘다"* 가 이유였다. 사용법 안내는
어긋날 위험이 없고 앱과 함께 버전이 고정되는 편이 맞다.

**`import.meta.glob` 을 쓰지 않는다.** `boss-icons`·`item-icons` 는 데이터(보스명·아이템명)가 파일명을
가리키는 수십 장이라 glob 이 옳지만, 여기는 릴리스마다 몇 장이고 가이드가 **자기 이미지를 직접
지목**한다. glob 조회는 파일명이 틀리면 `undefined` 를 돌려주고 화면에 이미지만 빠진 채 통과하지만,
명시적 import 는 **빌드가 실패한다.** [[ADR-119]] 결정 1 이 JSON 대신 `.ts` 를 고른 것과 같은 판단이다.

### 용량은 재고 기록한다

이미지는 `dist/assets/` 에 별개 파일로 나가지만 **OTA 는 dist 전체를 압축해 내려주므로 zip 이 그만큼
커진다** — 지연 로드가 이 비용을 깎아 주지 않는다. 릴리스마다 누적되는 자산이라 **한 장당·누적
상한을 정하고 넘으면 줄인다.** 상한값은 첫 촬영분 실측 후 확정한다(미결 4).

**기준선 실측 (2026-08-10, 이미지 0장, #185 머지 후)** — `npm run build` 후 `dist` 6.9MB /
zip **5.6MB**, `screen-settings` 청크 52.77kB(gzip 16.88kB). 안내 화면과 가이드 데이터가 이 청크
안에 들어갔고 **이미지가 아직 한 장도 없는 상태의 숫자**다. 다음 실측은 스크린샷을 넣은 뒤
같은 방법으로 잰다.

## 결정 5 — **안내가 있는 항목만** 눌린다

전 항목에 안내를 다는 것이 아니다. 버그 수정 한 줄에 붙일 사용법은 없다.

- `guideId` 를 가진 항목만 버튼이 되고 `›` 가 붙는다. 나머지는 **지금과 DOM 이 같다** — 래퍼도 클래스도 만들지 않는다.
- 안내가 없는 것은 결함이 아니라 정상이므로, 비활성 버튼을 두지 않는다(`error-resilience.md` — 액션이 없는 자리에 액션처럼 보이는 것을 두지 않는다).

## 결정 6 — 본문은 **블록 배열**이다 (이미지 ↔ 문단이 번갈아 선다)

```
‹  드롭 아이템 판매가
   [스크린샷]
   드롭한 아이템에 판매가를 매기면 …
   [스크린샷]
   1. 보스 수익 → 가격 에서 …
```

- 블록은 **이미지만 · 문단만 · 둘 다** 를 모두 허용한다. 사용법은 "그림 한 장에 설명 한 줄"로 떨어지지 않는다 — 맥락 문단이 먼저 오거나, 그림 두 장이 잇따르는 것이 자연스러운 경우가 있다.
- 이미지에는 **대체 텍스트를 필수**로 둔다. 안내 화면에서 이미지가 정보를 나르므로 장식이 아니다.
- 제목은 안내가 자기 것을 갖는다 — 목록 행의 이름이자 상세의 머리말이다. 노트 항목 텍스트(`…를 추가` 같은 완료형 문장)를 그대로 쓰면 화면 제목으로 읽히지 않는다.

- ~~**오래된 기능은 찾기 어렵다.** 버전 축의 대가다(결정 1).~~ → **해소됨**(결정 1 정정) — 기능 설명이 기능 축으로 전체를 나열한다.
- **같은 화면으로 가는 라우트가 둘이다.** 결정 3 정정의 대가다 — 전환 판정이 경로 접두 기반이라 형제로 건너뛰면 `replace` 가 되기 때문이고, 취향이 아니다. 화면·데이터는 한 벌이라 갈라질 것은 없지만 **라우트를 더할 때 둘 다 손대야 한다는 것을 잊기 쉽다.**
- **OTA 번들이 릴리스마다 커진다.** 결정 4의 대가이고, 상한으로 관리한다.
- **원천이 두 파일로 갈린다.** 결정 2는 배포가 강제한 것이지 선호가 아니다 — 방어선은 타입이 아니라 참조 무결성 테스트다.
- **안내를 쓰는 비용이 붙는다.** 스크린샷 촬영이 작업에 들어온다. 그래서 **전 항목이 아니라 필요한 항목만** 이다(결정 5).
- **기능이 늘면 카탈로그를 채워야 한다.** 지금 안내는 v1.0.4 에 손댄 넷뿐이라 `컨텐츠` 탭이 비어 있다(그래서 그 탭이 안 보인다). 카탈로그를 표방한 이상 **옛 기능의 안내가 없는 상태가 눈에 띄는 빈틈**이고, 이건 결정이 아니라 남은 일이다.
