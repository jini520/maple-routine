# ADR-297: 메이플 ID 를 **다시 고른다**. 추적 목록은 메이플 ID 마다 따로 든다

> ⚪ 미구현 · 2026-09-19 · 설계 · 이슈 #491 (#490 이 선행)

> 사용자 지정(2026-09-19): 메이플 ID 를 선택해서 관리하는 방식으로 변경한다. 추적 캐릭터 목록은
> 메이플 ID 마다 따로 든다.

**관련**: [[ADR-143]](이 문서가 뒤집는 결정. 계정 선택을 없앤 문서) · [[ADR-144]](그 화면) ·
[[ADR-296]](메이플 ID 의 출처가 되는 인증 수단) · [[ADR-030]](계정 공유 원장)

## 맥락

[[ADR-143]] 은 2026-08-16 에 계정을 고르는 일 자체를 없앴다. 근거는 사용자가 캐릭터를 여러 메이플
ID 에 나눠 갖고 있는데 한 번에 한 계정만 추적할 수 있어서, 다른 계정 캐릭터를 같이 보려면 설정에서
계정을 바꾸고 추적 목록을 통째로 다시 골라야 한다는 것이었다.

**그 문제는 이 문서에서 다르게 푼다.** [[ADR-296]] 이 넥슨 로그인 하나에 API 키 여러 개를 붙일 수
있게 하면서 고를 수 있는 메이플 ID 수가 크게 늘어난다. 여러 넥슨 계정에 걸친 메이플 ID 를 한 목록에
섞어 놓으면 캐릭터 선택 화면이 읽을 수 없게 된다. 그리고 [[ADR-143]] 이 없앤 것은 선택 단계였지
전환 비용 자체가 아니었다. 전환이 목록을 통째로 다시 고르게 만들던 원인은 커밋이 두 쓰기를 함께
하던 것([[ADR-086]] 결정 6)이고, 메이플 ID 마다 목록을 따로 들면 그 원인이 사라진다.

## 결정

### 결정 1. 메이플 ID 를 고른다. 캐릭터 선택은 고른 ID 안에서만 한다 (사용자 지정)

[[ADR-143]] 결정 1 을 뒤집는다. 고를 수 있는 메이플 ID 목록은 [[ADR-296]] 결정 3 이 만든다.
로그인과 키 여러 개에서 받은 `character/list` 응답의 `account_list` 를 합친 것이다.

- 선택은 새 저장 키 `selectedMapleId` 에 남는다. [[ADR-143]] 결정 7 이 레거시로 내린
  `selectedAccountId` 를 되살리지 않는다. 그 키에는 캐패시터 시절 값이 남아 있는 설치본이 있어,
  되살리면 사용자가 고른 적 없는 값으로 화면이 선다.
- 고르지 않은 상태가 있을 수 있다. 처음 로그인했거나 고른 ID 가 사라졌을 때다. 그때는 캐릭터가
  가장 많은 ID 를 자동으로 고르지 않고 **고르게 한다**([[ADR-051]] 이 자동 확정을 없앤 이유가 여기서도
  그대로다. 앱이 고른 것과 사용자가 고른 것이 구분되지 않는다).

### 결정 2. 추적 목록은 메이플 ID 마다 따로 든다 (사용자 지정)

`trackedCharactersKey()` 가 `trackedCharacters` 하나를 내던 것을 `trackedCharacters:{accountId}` 로
가른다. [[ADR-143]] 결정 2 를 뒤집는다.

- 그래야 전환이 전환이 된다. 목록이 하나면 ID 를 바꿔도 화면이 걸러 보일 뿐이고, 안 보이는
  캐릭터가 계속 동기화된다.
- `representativeCharacter` 도 같이 갈린다. 대표는 추적 목록 안에서 고르는 값이라([[ADR-143]] 결정 4)
  목록이 갈리면 대표도 갈린다. 안 그러면 ID 를 바꿨을 때 대표가 목록 밖 캐릭터를 가리킨다.
- `manualTrackedContent:{ocid}` · `scheduleProbe:{ocid}` · `characterBasicCache:{ocid}` 는 **안 갈린다.**
  ocid 는 메이플 ID 를 넘어 유일하고, 그 값들은 캐릭터에 붙은 사실이지 선택에 붙은 값이 아니다.

### 결정 3. 이관은 첫 `character/list` 응답에서 한 번 한다

기존 설치본의 `trackedCharacters` 는 메이플 ID 를 모르는 평평한 배열이다. ocid 가 어느 ID 에
속하는지는 `character/list` 응답에만 있으므로, 이관은 **그 응답을 처음 받는 시점**에 한다.

- 각 ocid 를 자기 ID 의 목록으로 옮기고, 응답에 없는 ocid 는 버리지 않고 **가장 많이 옮겨 간 ID** 에
  남긴다. 캐릭터 삭제나 이전으로 응답에서 빠진 것을 이관이 지우면 사용자가 고른 목록이 조용히
  줄어든다.
- 이관 직후 `selectedMapleId` 는 **대표 캐릭터가 사는 ID**, 대표가 없으면 옮겨 간 캐릭터가 가장 많은
  ID 다. 이때만 자동으로 고른다. 이관은 사용자가 이미 고른 것을 옮기는 일이라 결정 1 의 자동 확정
  금지와 다르다.
- 평평한 키는 이관 뒤 지운다. 남겨 두면 다음 세션이 두 진실 중 어느 쪽을 읽을지 모른다.

### 결정 4. [[ADR-143]] 의 결정 3 · 4 · 6 · 10 은 그대로 산다

뒤집는 것은 고르는 축 하나다. 나머지는 메이플 ID 축이 돌아와도 그대로 맞다.

| [[ADR-143]] | 상태 | 왜 |
|---|---|---|
| 결정 3 (저장 순서가 표시 순서) | 산다 | 목록이 갈려도 각 목록 안의 순서 규칙은 같다. `orderByTracked` 는 안 바뀐다 |
| 결정 4 (대표는 표식) | 산다 | 값 규칙은 그대로이고 저장 자리만 ID 별로 갈린다(결정 2) |
| 결정 6 (동기화가 캐릭터마다 계정 해석) | 산다 | 오히려 필수다. `accountSharedProgress:{accountId}` 는 그 캐릭터가 사는 ID 로 읽고 써야 한다 |
| 결정 10 (못 고르는 계정 셋) | 산다 | 전원 조회 불가 ID · 일부 조회 불가 · 고를 수 있는 ID 가 없음. 판정 자리가 그대로다 |
| 결정 5 (예열 대신 계정을 열 때 판정) | 산다 | 고른 ID 하나만 훑는 것이 이 문서에서 더 자연스럽다 |
| 결정 8 (`accountScope` 플래그) | 이미 없다 | 캐패시터와 함께 사라졌다([[ADR-155]]). 소스에 `accountScope` 가 없다 |
| 결정 9 (키 재입력의 추적 ocid 대조) | 조정 | 대조 대상이 `trackedCharacters` 하나가 아니라 **그 키가 주인인 ID 들의 목록**이 된다 |

### 결정 5. 전환 자리는 설정이 아니라 캐릭터 관리 화면이다

[[ADR-143]] 이 계정 변경을 설정에서 걷어 캐릭터를 고르는 일 안으로 넣었다. 그 방향은 유지한다.
메이플 ID 를 바꾸는 것은 **무엇을 관리할지 정하는 일**이지 앱 설정이 아니다.

- 인증 수단(로그인 · 키 목록)을 더하고 빼는 것은 설정이다. 그쪽은 계정 자체를 다루기 때문이다.
- 두 화면이 이어져야 한다. 관리 화면에서 원하는 메이플 ID 가 안 보이면 키를 더하러 갈 길이 있어야
  한다.

## 대가

- **ID 를 바꾸면 화면이 통째로 바뀐다.** 오늘 · 스케줄러 · 보스 수익이 모두 고른 ID 의 캐릭터만
  그린다. 여러 ID 에 걸쳐 한눈에 보던 [[ADR-143]] 이후의 화면을 잃는다.
- **이관이 한 번 돈다**(결정 3). 첫 실행에서 목록이 잘못 갈리면 사용자가 고른 순서까지 흐트러진다.
- 가계부와 보스 수익 **기록은 안 갈린다.** 기록은 ocid 에 붙어 있어 ID 를 바꿔도 남아 있고, 화면에
  안 보이는 캐릭터의 기록은 그 ID 로 돌아가야 보인다.

## 성공 기준 (TDD)

- 메이플 ID 를 바꾸면 그 ID 의 추적 목록만 읽힌다. 다른 ID 의 목록은 안 바뀐다.
- 평평한 `trackedCharacters` 를 든 설치본이 첫 `character/list` 응답에서 ID 별로 갈리고, 응답에 없는
  ocid 를 잃지 않는다. 평평한 키는 그 뒤 없다.
- 대표가 사는 ID 가 이관 직후 선택된다. 대표가 없으면 캐릭터가 가장 많은 ID 다.
- 동기화가 각 캐릭터의 자기 ID 로 `accountSharedProgress` 를 읽고 쓴다([[ADR-143]] 결정 6 회귀 가드).
- 고를 수 있는 메이플 ID 가 하나도 없으면 빈 상태와 인증 수단 추가 경로가 선다.
