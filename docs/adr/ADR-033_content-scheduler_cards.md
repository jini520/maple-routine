# ADR-033 컨텐츠 카드와 완료 판정

> 🟢 유효
> 옛 번호: ADR-020 · ADR-021 · ADR-057 · ADR-162 · ADR-271 결정 1 · 2 · 4 · 5
> 관련 소스: `app/content-scheduler/DailyContentCards.tsx` · `app/content-scheduler/WeeklyContentCards.tsx` · `app/content-scheduler/content-badges.tsx` · `app/content-scheduler/content-completion.ts` · `lib/scheduler/required-level.ts` · `lib/scheduler/group-weekly-limit.ts` · `features/content-scheduler/store.ts`

## 배경

넥슨 스케줄러 API 의 일간 · 주간 컨텐츠는 종류마다 진행 상태를 주는 방법이 다르다. 일일 퀘스트는 `now_count` ·
`max_count` 가 항상 0/0 이고 실제 상태는 `quest_state`(0 시작 안함, 1 진행 중, 2 완료)에 들어 있다. 몬스터파크는
횟수로, 길드 지하 수로는 점수로, 무릉도장은 도달한 층수로 온다. 모든 항목을 `이름 · now/max` 와 진행률 바 하나로
그리면 대부분의 카드가 의미 없는 숫자를 보여 준다. 그래서 컨텐츠 종류마다 카드를 나눴다.

## 결정

### 결정 1. 카드 종류는 이름이 아니라 컨텐츠 key 와 카테고리로 고른다

카드를 고를 때 API 이름의 접두어나 글자를 비교하지 않는다. 응답을 정규화할 때 얻은 컨텐츠 key 와, 컨텐츠 표 줄의
`category` · `type` 을 본다([[ADR-019]]). 카드에 보이는 이름은 컨텐츠 표의 `displayName` 이고, 표에 없는 컨텐츠는 API
이름을 그대로 쓴다. 배경 그림도 표 줄의 `backgroundMap`(지도) 이나 `backgroundPortrait`(보스 초상) 으로 정한다.

표에 없는 컨텐츠는 key 가 없어 카테고리를 알 수 없다. 그래서 기본 카드에 API 이름으로 나오고, 이름이
`에픽 던전 : ` 으로 시작해도 에픽 던전 카드나 주간 한도에 들어가지 않는다.

### 결정 2. 카드 틀은 보스 카드와 같다

보스 카드처럼 왼쪽에 이름, 오른쪽에 상태 배지를 두고 배경 그림을 오른쪽으로 갈수록 흐려지게 깐다
(`IllustratedCard` · `FadedIllustration`). 새 디자인을 만들지 않고 이미 검증된 보스 카드를 그대로 쓰면 스케줄러
두 화면이 같은 디자인으로 보인다. 이름 글자에는 그림 위에서도 읽히도록 `ILLUSTRATION_TEXT_SHADOW_STYLE` 그림자를 준다.

카드 높이는 80 이다. 진행률 바가 있는 카드만 112(`h-28`)이고, 위 80 은 다른 카드와 같은 배치로 두고 늘어난 아래에
바를 둔다. 배지와 바는 `third` 색을 쓴다.

### 결정 3. 일간 카드는 세 가지다

`renderDailyContentCard` 가 아래 순서로 고른다.

| 대상 | 카드 | 왼쪽 | 오른쪽 |
|---|---|---|---|
| `type: 'quest'` 인 항목 | `DailyQuestCard`(80) | 지역 아이콘 + 이름. 배경은 지역 지도 | `quest_state` 배지(시작 안함 · 진행 중 · 완료) |
| 컨텐츠 key `monster_park` | `MonsterParkCard`(112) | 아이콘 + 이름. 배경은 몬스터파크 지도 | `now/max` 배지, 아래에 진행률 바 |
| 그 밖 | 기본 카드 | `이름 · now/max` | 진행률 바 |

아이콘과 배경, 자르는 위치는 `lib/assets/asset-lookup` 이 지도 key 로 찾는다. 찾지 못하면 아이콘이나 배경을 그리지
않는다. 표에 없는 일일 퀘스트도 `type` 이 `quest` 라 일일 퀘스트 카드로 나오고, 배경 없이 API 이름으로 보인다.

### 결정 4. 주간 카드는 일곱 가지다

`renderWeeklyContentCard` 가 아래 순서로 고른다. 순서가 바뀌면 같은 항목이 다른 카드로 나오므로 완료 판정(결정 5)도
같은 순서를 따른다.

| 대상 | 카드 | 왼쪽 | 오른쪽 |
|---|---|---|---|
| `guild_underground_waterway` | `GuildUndergroundWaterwayCard`(80, 배경 `arcanus`) | `길드` 배지 + 이름 | `n점` |
| `guild_weekly_mission_points` | `GuildMissionPointsCard`(112, 배경 `hallOfHeroes`) | `길드` 배지 + 이름 | `now/max`, 아래에 진행률 바 |
| `guild_flag_race` | `GuildFlagRaceCard`(80, 배경 `flagRace`) | `길드` 배지 + 이름 | `now_count` 가 1 이상이면 완료, 아니면 시작 안함 |
| 카테고리 `epic_dungeon` | `EpicDungeonCard`(80, 배경은 보스 초상) | `에픽 던전` 배지 + 던전 이름 | `now_count` 가 1 이상이면 완료, 아니면 시작 안함 |
| 카테고리 `monster_park`, 또는 `arcane_river_quest` 이면서 `type: 'contents'` | `WeeklyRegionalContentCard`(80, 배경은 지역 지도) | 지역 아이콘 + 이름 | `now == max` 이고 `max > 0` 이면 완료, 아니면 시작 안함. 익스트림 몬스터파커만 `quest_state` 를 그대로 쓴다 |
| 카테고리 `maple_union` | `MapleUnionDragonCard`(80, 배경 `armorDragon`) | `유니온` 배지 + 이름 | `quest_state` 배지 |
| 카테고리 `weekly_quest` · `mu_lung_dojo`, 또는 `arcane_river_quest` 이면서 `type: 'quest'` | `WeeklyQuestCard`(80, 배경은 지역 지도) | 지역 아이콘 + 이름 | `quest_state` 배지. 무릉도장은 `n층`(참여 전이면 시작 안함), 성실한 조사에 대한 보답은 `quest_state` 가 1 일 때 `n회 완료` 이고 `now == max` 가 되면 완료 |
| 그 밖 | 기본 카드 | `이름 · now/max` | 진행률 바 |

- 길드 셋은 같은 카테고리지만 진행값의 뜻이 달라서 카드를 따로 둔다. 지하 수로는 점수에 상한이 없고, 미션 포인트는
  상한이 있는 횟수이고, 플래그 레이스는 참여했는지만 알 수 있다.
- 에픽 던전의 `max_count` 는 스테이지 수(5)이고 `now_count` 는 깬 스테이지 수다. 한 스테이지라도 깨면 완료로 본다.
- 메이플 유니온 드래곤은 주마다 다른 드래곤이 나오지만 API 가 어떤 드래곤인지 알려 주지 않는다. 그래서 그림 하나로
  고정했다.
- `에픽 던전` · `길드` · `유니온` 배지는 테마 색이 아니라 배지 자체의 고정색(`epicDungeon` · `guild` · `mapleUnion`)
  이다. 배경 그림에 맞춘 색이라 테마를 따르면 그림과 어울리지 않는다.

### 결정 5. 완료 판정은 `content-completion.ts` 한 곳에 둔다

초상화 링의 진행률은 `dailyContentCompletion` · `weeklyContentCompletion` 이 정한다. 카드 렌더러는 완료 · 미완료보다
더 많은 상태(진행 중 · `n층` · `n점` · `n회 완료`)를 그리므로 이 함수를 쓰지 않는다. 대신 이 함수는 카드와 같은
순서로 종류를 나눠서, 카드가 완료로 그리는 항목을 똑같이 완료로 센다.

| 판정 | 대상 |
|---|---|
| `quest_state` 가 2 | 일일 퀘스트, 메이플 유니온, 익스트림 몬스터파커, 그 밖의 주간 퀘스트 |
| `now ≥ max` (`max` 가 0 이면 미완료) | 몬스터파크(일간), 아케인리버 지역 컨텐츠, 길드 미션 포인트, 성실한 조사에 대한 보답, 기본 카드 |
| `now > 0` | 에픽 던전, 길드 플래그 레이스, 길드 지하 수로 |
| 세지 않음 | 무릉도장 |

- 무릉도장은 끝이 정해져 있지 않다. 링 분모에 넣으면 링이 영원히 다 차지 않으므로 분모에서 뺀다.
- 지하 수로는 점수에 상한이 없어서 다 했는지는 알 수 없지만, 그 주에 참여했는지는 알 수 있다. 링은 참여 여부를 센다.
- `max` 가 0 인 항목을 완료로 보지 않는다. 0/0 을 100% 로 읽으면 채울 것이 없는 항목이 다 한 것으로 보인다.

### 결정 6. 요구 레벨에 못 미치는 항목은 `진행 불가` 배지를 달고 집계에서 뺀다

판정은 `lib/scheduler/required-level.ts` 하나가 한다. 컨텐츠 카드, 보스 카드, 초상화 링, today 의 남은 스케줄이 모두
이 함수를 쓴다. 판정이 여러 곳에 흩어지면 같은 항목이 화면마다 다르게 세진다.

- 상태 배지 대신 `진행 불가`(`Badge variant="muted"`)가 보인다. 배지를 하나 더하지 않고 바꾸기만 하므로 좁은
  카드에서 줄이 바뀌지 않는다. 진행률 바가 있는 카드는 바를 그리지 않는다.
- 링과 남은 스케줄의 분모에서 뺀다. 그대로 두면 그 캐릭터의 링이 100% 에 닿지 못하고 남은 개수도 줄지 않는다.
- 캐릭터 레벨을 모르면 진행 가능으로 본다. 컨텐츠 표에 요구 레벨이 없어도 진행 가능으로 본다. 표에는 제한 없음과
  아직 모름을 구분하는 표시가 없어서, 모르는 값을 진행 불가로 단정하지 않는다. 지금 요구 레벨이 없는 컨텐츠는 메이플
  유니온 둘과 길드 셋이다.
- 게임에 등록한 항목이라도 요구 레벨이 모자라면 진행 불가다. 게임이 등록을 허용해도 실제로는 진행할 수 없다(사용자
  확인). 그래서 컨텐츠 표 값이 틀리면 화면도 틀린다. 값은 사용자가 확인한 것만 적는다([[ADR-019]]).
- 고르는 것은 막지 않는다. 표시하고 집계에서 뺄 뿐이고, 수동 추적에서 미달 항목을 고를 수 있다. 흐리게 하거나
  숨기지도 않는다. 흐리면 누를 수 없는 것처럼 보이고, 숨기면 항목이 왜 없는지 알 수 없다.

### 결정 7. 에픽 던전은 주 3회가 한도이고, 한도가 차면 남은 던전은 `마감` 이다

에픽 던전은 네 곳이지만 일주일에 세 번만 돌 수 있다(사용자 확인).

- 한도 3 은 게임 규칙이라 코드에 적지 않고 컨텐츠 표의 카테고리 줄(`epic_dungeon` 의 `weeklyLimit`)에 둔다.
- 판정은 `lib/scheduler/group-weekly-limit.ts` 하나가 한다. 카드, 링, today 의 공유 컨텐츠 위젯이 같은 함수를
  쓴다([[ADR-058]]). 따로 두면 위젯은 `3/3` 인데 카드에는 할 일이 남는 날이 생긴다. 완료 판정은 화면 쪽에 있고
  `lib` 은 `app` 을 가져다 쓰지 않으므로, 호출하는 쪽이 완료 여부를 함께 넘긴다.
- 세는 대상은 등록 여부와 관계없이 그 카테고리에서 완료한 항목 전부다. 한도는 등록 수가 아니라 진행 횟수를 제한하기
  때문이다. 그래서 화면에 보이는 목록이 아니라 그 캐릭터의 병합된 `weeklyContents` 전체를 넘긴다. 등록하지 않은
  던전이 병합 결과에서 빠지지 않는 것은 [[ADR-032]] 결정 6 덕분이다. 같은 컨텐츠가 두 번 들어와도 한 번만 센다.
- 한도가 찼고 아직 완료하지 않은 카드는 상태 배지 대신 `마감`(`Badge variant="muted" weight="bold"`)이 보인다. 보스
  카드가 주간 한도를 채웠을 때 쓰는 말이고 같은 배지다. `완료` 배지와 크기가 같아 카드 오른쪽 끝이 흔들리지 않는다.
- 우선순위는 `진행 불가` → `마감` → `완료` · `시작 안함` 이다. 요구 레벨 290 에 못 미치는 캐릭터의 아우룸 레기스는
  한도가 차도 `진행 불가` 다.
- 링은 `마감` 을 완료로 센다. 네 곳을 추적하면 세 곳을 끝낸 뒤 링이 `4/4` 가 된다. 세지 않으면 `3/4` 에서 멈춘다.
- 에픽 던전 진행은 메이플 ID 공유라 같은 계정의 캐릭터는 같은 수를 본다. 메이플 ID 여러 개를 합쳐 보는 경우는
  다루지 않는다.

### 결정 8. 길드 컨텐츠는 길드에 가입한 캐릭터만 추적할 수 있다

길드에 가입하지 않은 캐릭터는 길드 컨텐츠를 할 수 없는데, 컨텐츠 관리 화면에서 고를 수 있었다.

- 가입 여부는 `character/basic` 의 `character_guild_name` 에서 읽는다. 이미 캐릭터마다 받는 응답이라 호출이 늘지
  않는다. 스토어가 레벨과 함께 캐시에서 꺼내 `ContentCharacterView.guildName` 에 담는다.
- `guildName` 은 세 가지 상태다. 길드 이름이면 가입, `null` 이면 미가입(응답이 알려 준 사실), `undefined` 면
  모름(옛 캐시이거나 응답에 칸이 없음)이다. `null` 일 때만 잠근다. 둘을 같이 다루면 데이터가 불완전할 때 모든
  사용자의 길드 컨텐츠가 잠긴다. 모를 때 잠그지 않으면 기능이 잠시 꺼진 것처럼 보일 뿐이라 이쪽이 안전하다.
- 길드 컨텐츠인지는 컨텐츠 표 줄의 카테고리가 `guild` 인지로 판단한다(`isGuildContent`). 관리 화면의 묶음과 같은
  기준이라 둘이 어긋나지 않는다.
- 막는 곳은 스토어다. `addManualContent` 가 `'guildRequired'` 를 돌려준다. 관리 화면은 그 행을 누를 수 없게 하고, 행
  위를 덮는 반투명 막(`bg-scrim`)에 `길드 가입 시 진행 가능` 을 적는다.
- 이미 추적 중인 항목은 잠그지 않는다. 길드를 나간 뒤에도 추적을 끌 수 있어야 한다.
- 길드 이름은 캐시 값이라 늦게 반영된다. 방금 가입한 캐릭터는 캐시가 갱신될 때까지 고를 수 없다.
- 스케줄러 화면의 카드에는 길드 미가입을 표시하지 않는다.
