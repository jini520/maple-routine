# ADR-217: 알림 모달의 골격을 한 틀이 갖는다. 팝오버의 닫기 층은 내용과 같은 창에 산다

> 🟢 유효 · 2026-09-04 · **구현 완료**

> 사용자 지정(2026-09-04): "내가 확인하려고 했던 건 직전에 만들었던 DevelopmentStageKeyModal 과
> 유사한 디자인의 모달 간의 디자인의 통일성이야. 유사한 디자인의 모달을 템플릿화 해서 title,
> content, description, button, link 등이 동일한 디자인을 유지할 수 있도록 개선해."

**관련**: [[ADR-214]](개발 단계 키 차단) · [[ADR-215]](API 키 화면은 로그인 화면) ·
[[ADR-116]](키 무효화 사슬) · [[ADR-179]](바텀시트 표면) · [[ADR-121]](파티 인원 모달)

## 맥락

앱에서 뜨는 모달 계열을 전수 조사했다. 세 갈래 18개다.

| 갈래 | 수 | 무엇 |
|---|---|---|
| `organisms/Modal` 기반 | 9 | 스크림 + 중앙 패널. 알림 · 확인 · 선택 · 진행률 |
| `organisms/BottomSheet` 기반 | 4 | 보스 드롭 기록 · 판매가 키패드 · 수입 · 지출 |
| `react-native` 의 `Modal` 직접 | 5 | 드롭다운 둘 · 팝오버 둘 · 전체화면 연출 |

갈래 3이 베이스를 안 거치는 것은 게으름이 아니다. 스크림이 없거나(드롭다운 · 팝오버) 전체화면
연출이라 `organisms/Modal` 의 계약(스크림 + 중앙 패널)이 애초에 안 맞는다. 이 ADR은 그 다섯을
베이스로 끌어오지 않는다.

조사에서 문제가 넷 나왔다. 셋은 개별 결함이고 하나는 계열 전체의 물음이다.

### 시트 껍데기가 자기 이름을 하나로 갖고 있다

`BottomSheet.tsx` 가 `accessibilityLabel="드롭 아이템 기록"` 을 고정으로 물고 있는데 이 껍데기를
시트 넷이 공유한다. props 에 라벨 구멍이 없어 호출부가 못 고친다. 수입 시트 · 지출 시트 · 판매가
키패드를 스크린리더가 전부 `드롭 아이템 기록` 으로 읽는다.

### 팝오버의 닫기 층과 내용이 다른 창에 있다

`HeadlineChips` 는 팝오버를 열 때 형제 셋을 세운다. `react-native` 의 `Modal`(안에 닫기용 투명
`Pressable` 하나뿐) · 트리거 칩 · 팝오버 내용(일반 트리에 `absolute z-20`).

RN 의 `Modal` 은 안드로이드에서 `Dialog`, iOS 에서 따로 올라오는 뷰다. **앱 루트 뷰와 다른 창이라
항상 그 위**다. `z-index` 는 같은 트리의 형제끼리만 순서를 정하므로 내용에 `z-20` 이 붙어 있어도
못 이긴다. 화면 전체를 덮는 투명 `Pressable` 이 팝오버 상자 위에 깔린다.

지금 보이는 고장은 없다. 내용이 읽기 전용 텍스트뿐이라 상자를 눌러도 닫힌다가 관찰되는 전부이고
그건 아무 데나 눌러도 닫히는 것으로 보인다. 문제는 다음에 여기 누를 것을 넣을 때다. 그 탭은
조용히 안 먹고 팝오버만 닫히는데, `z-20` 이 붙어 있어 원인이 안 보인다.

같은 문제를 `ItemRevenuePopover` · `AccountSelect` · `SelectField` 셋은 닫기 층과 내용을 **둘 다
`Modal` 안에** 넣고 좌표를 재서 앉히는 것으로 풀었다. 한 화면(보스 수익)에 처방이 둘이다.

### 알림 모달 둘이 골격을 손으로 맞추고 있다

`ApiKeyNoticeModal` 과 `DevelopmentStageKeyModal` 은 같은 물건이다. 56px 아이콘 배지 · 가운데
정렬 제목 · 설명 · 전폭 주 버튼. [[ADR-214]] 가 그것을 못박아 뒀다.

> `ApiKeyNoticeModal` 과 같은 골격이라 두 모달이 한 앱에서 온 것으로 읽힌다(사용자 지정).

그런데 그 골격이 **문장으로만** 있고 코드에는 없다. 두 파일이 각자 `gap-5` · `h-14 w-14` ·
`text-base font-semibold` 를 손으로 적는다. 이미 값이 갈린다.

| | `ApiKeyNoticeModal` | `DevelopmentStageKeyModal` |
|---|---|---|
| 배지 모양 | `rounded-full` | `rounded-[16px]` |
| 배지 색 | `error-tint` / `error-ink` | `primary-tint` / `primary-ink` |
| 아이콘 굵기 | `1.75` | `1.7` |
| 제목 | `text-base font-semibold` | 같음 + `leading-snug` |
| 설명 | `text-sm text-text-muted` | `text-xs text-text-muted` |
| 머리 묶음 | 배지와 제목이 따로 (`gap-5` · `gap-2`) | 배지와 제목이 한 묶음 (`items-center gap-3`) |

배지 모양과 색은 결정이다([[ADR-214]] 가 붉은 원이 아닌 이유를 적었다). 아이콘 굵기 `1.7` 대
`1.75` 와 설명 크기 `text-sm` 대 `text-xs` 는 결정이 아니라 표류다. 셋째 모달이 오면 또 갈린다.

### 알림 모달 하나에 테스트가 없다

계열 18개 중 `DevelopmentStageKeyModal` 만 테스트가 없다. 골격을 틀로 옮기는 작업이 이 파일을
건드리므로 옮기기 전에 그물이 필요하다.

## 결정

### 결정 1. 시트 껍데기는 자기가 무엇인지 모른다. 라벨을 프롭으로 받는다

`BottomSheet` 에 `label: string` 을 **필수**로 둔다. 기본값을 주지 않는 것이 요점이다. 기본값이
있으면 다음 시트도 그것을 물려받아 지금과 같은 상태로 돌아간다. 필수면 시트를 새로 만드는 사람이
자기 시트의 이름을 반드시 한 번 적는다.

| 시트 | 라벨 |
|---|---|
| `BossDropSheet` | 드롭 아이템 기록 |
| `DropPricePad` | 드롭 판매가 입력 |
| `IncomeSheet` | 수입 기록 |
| `SpendSheet` | 지출 기록 |

### 결정 2. 팝오버는 닫기 층과 내용을 같은 창에 둔다

`HeadlineChips` 의 팝오버 내용을 `Modal` 안으로 들인다. 위치는 `useAnchoredPopover` 가 재는
트리거의 윈도우 좌표로 잡는다. 이미 팝오버 셋이 쓰는 훅이라 새 장치가 아니다.

**보이는 자리가 바뀐다.** 지금은 라벨행 왼쪽 변에 맞춰 있는데(`left-0`, 트리 안 절대배치가 그것을
공짜로 줬다) 창을 옮기면 그 기준 상자가 없어진다. 새 기준은 트리거 칩이고, 상자는 칩 왼쪽에 맞춰
화면 가장자리로 clamp 된다. 팝오버가 자기를 연 것 아래에 서는 것이라 나머지 팝오버 셋과 같은
규칙이 된다.

대안 둘을 버렸다.

- **닫기 층을 트리 안으로 내리기.** 칩이 스크롤 뷰 안 헤더에 있어 트리 안 요소로는 화면 전체를
  못 덮고, 덮어도 스크롤을 따라 움직인다.
- **`Modal` 을 없애고 트리거 재탭으로만 닫기.** 바깥 탭으로 닫는 성질을 잃는다.

### 결정 3. 알림 모달의 골격은 `organisms/NoticeModal` 한 곳에 있다

배지 · 제목 · 내용 · 설명 · 주 버튼 · 링크의 **자리와 값**을 이 파일이 갖는다. 호출부는 무엇을
넣을지만 정한다.

```
NoticeModal
  icon      아이콘 컴포넌트
  tone      'primary' | 'error'      배지 바탕·글자색과 모양이 여기서 함께 나온다
  title     제목
  content   제목과 설명 사이의 자유 영역 (선택)
  description  설명 (선택)
  action    { label, onPress }       전폭 주 버튼
  link      { label, onPress }       버튼 아래 인라인 링크 (선택)
  onClose   오버레이 탭·안드로이드 뒤로가기
```

`tone` 이 색과 모양을 함께 정한다. `error` 는 원(`rounded-full`)이고 `primary` 는 네모
(`rounded-[16px]`)다. 둘을 따로 받으면 붉은 네모 같은 조합이 만들어지는데, [[ADR-214]] 가 원과
네모를 가른 근거가 색과 같은 것(실패인가 종류가 다른가)이라 갈라 둘 이유가 없다.

표류하던 값은 한쪽으로 모은다. 아이콘 굵기는 `1.75`, 설명은 `text-xs text-text-muted`. 설명을
작은 쪽으로 고른 것은 사용자 지정이다(2026-09-04, `설명 글자를 DevelopmentStageKeyModal 에 맞춰`).
제목이 할 말을 이미 했고 설명은 그 아래 안내라, 둘이 같은 무게로 서면 제목이 눌린다.

`content` 는 `ReactNode` 다. 개발 단계 키 모달의 두 줄 표가 이 자리에 든다. 표를 틀에 넣지 않는
것은 그것이 그 모달 하나의 물건이기 때문이다. 틀은 그것이 **어디에 서는지**만 정한다.

### 결정 4. 틀이 확인 버튼을 그리는 것이지 확인을 결정하지 않는다

`action` 이 필수라 알림 모달에는 주 버튼이 반드시 하나 있다. 닫을 수 있는가는 `onClose` 가
정하고 틀은 안 본다. `ApiKeyNoticeModal` 은 `onClose` 에 no-op 을 넘겨 못 닫는 채로 남고
([[ADR-116]] 결정 10), `DevelopmentStageKeyModal` 은 확인과 같은 핸들러를 넘겨 닫힌다.

버튼이 둘인 확인 대화상자(`DisconnectConfirm` · `CacheClearConfirm`)는 이 틀에 안 들어온다. 그쪽은
아이콘 배지가 없고 제목이 왼쪽 정렬이며 취소가 있다. 같은 틀로 덮으면 `action` 이 배열이 되고
`tone` 이 정렬까지 정하게 되어, 두 물건을 하나로 부르는 대가만 남는다.

## 무엇이 바뀌어 보이나

값을 한쪽으로 모으기로 했으므로 `ApiKeyNoticeModal` 쪽이 움직인다. 기준을 개발 단계 키 모달로
잡은 것은 그쪽이 나중에 만들어진 데다 사용자가 그것을 기준으로 통일해 달라고 했기 때문이다.

| | 전 | 후 |
|---|---|---|
| 배지와 제목 사이 | 20 (`gap-5`) | 12 (`gap-3`, 한 묶음) |
| 제목과 설명 사이 | 8 (`gap-2`) | 20 (`gap-5`) |
| 설명 글자 | `text-sm` | `text-xs` |
| 아이콘 굵기 | 1.75 | 1.75 (그대로) |

`DevelopmentStageKeyModal` 쪽은 하나도 안 움직인다. 기준이 그쪽이다.

미검증: 두 모달의 새 간격을 눈으로 보지 않았다. 테스트는 문구와 배선만 본다.

## 무엇이 안 바뀌나

- 문구 한 글자도 안 바뀐다. 두 모달의 제목 · 설명 · 버튼 라벨이 그대로다.
- [[ADR-214]] 의 배지 결정(붉은 원이 아니라 `primary` 네모)이 그대로 산다. `tone` 이 그것을 옮겨
  담은 것이지 뒤집은 것이 아니다.
- 갈래 3의 다섯은 그대로 `react-native` 의 `Modal` 을 직접 쓴다. `HeadlineChips` 도 마찬가지다.
  바뀌는 것은 그 창 안에 무엇이 들어가는가뿐이다.
