# ADR-157: 테스트 러너를 jest 하나로 모은다

**날짜**: 2026-08-21
**상태**: 결정 · **구현 완료**(2026-08-21)
**관련**: [[ADR-155]](모노레포 해체 — 러너 둘의 경계를 «경로» 에서 «확장자» 로 옮긴 결정 6, 이
ADR 이 그 경계를 아예 없앤다) · [[ADR-156]](스냅샷 정리) · [[ADR-128]](RN 전환 — jest 를 고른 결정) ·
[[ADR-101]](선하이드레이션이 동적 `import()` 를 쓰는 이유) · [[ADR-129]](에셋 목록을 커밋 시점에)

## 맥락

러너가 둘이었던 것은 **전환기의 산물**이다. RN 쪽은 `jest-expo` 로 시작했고([[ADR-128]]), 웹 시절
로직 테스트는 vitest 위에 있었다. 캐패시터가 걷히고([[ADR-155]] 결정 1) core 가 `src/` 로 녹으면서
두 러너의 테스트가 **같은 `__tests__` 디렉터리에 섞였고**, 그때는 확장자로 갈랐다(`*.spec.*` =
vitest · `*.test.*` = jest).

그 경계는 «지금 무엇을 쓰는가» 가 아니라 «어디서 왔는가» 를 말한다. 러너가 둘이면 매처도 둘,
목 API 도 둘, 설정도 둘이고, **새 테스트를 쓸 때마다 어느 쪽인지 골라야 한다.** 앱이 하나면
러너도 하나여야 하고, 그 하나는 **RN 이 표준으로 쓰는 jest** 다.

### 옮기는 비용을 먼저 쟀다

[[ADR-155]] 결정 6 이 «이번 변경과 같은 커밋에 둘 수 없다» 고 미뤄 둔 이유가 이것이다.

| vitest 것 | 수 | jest 에서 |
|---|---|---|
| `vi.fn`·`vi.mock`·`vi.spyOn`·타이머 | 대부분 | `jest.*` 로 1:1 |
| `vi.hoisted` | 66 | **짝이 없다** — 팩토리가 밖의 값을 끌어오는 방식 자체가 다르다 |
| `vi.stubGlobal`·`vi.unstubAllGlobals` | 29 | 짝이 없다 |
| `vi.waitFor` | 39 | 짝이 없다 |
| `expect(값, '메시지')` | 170 | **jest 는 두 번째 인자를 조용히 버린다** |
| `it.skipIf` · `@vitest-environment` | 8 | 짝이 없다 |
| `import.meta.glob`·`import.meta.url` | 8 | Vite 전용 |
| 동적 `import()` | 91 | jest 의 CJS VM 에서 **던진다** |

## 결정

### 결정 1 — jest 만 남긴다. 실패 모드가 «조용히 덜 검사하는 것» 이라 숫자로 못박는다

이관의 위험은 «깨지는 것» 이 아니라 **«통과하는데 덜 검사하는 것»** 이다. 그래서 판정 기준을
먼저 정했다: **3,860개가 그대로 3,860개여야 한다**(vitest 1,835 + jest 2,025).

결과는 **261스위트 3,860개**로 정확히 같다. 3회 연속 같은 수를 확인했다.

### 결정 2 — 없는 것은 **버리지 않고 만든다**

vitest 에만 있던 것을 그냥 지우면 그 자리가 조용히 약해진다. 셋을 `jest.setup.js` 에 만들었다.

- **`expect(값, '메시지')`** — 실패 메시지 앞에 설명을 붙이는 Proxy 래퍼(약 20줄).
  `it.each` 안에서 «34개 토큰 중 무엇이 빠졌는가» 를 말하는 자리라, 170곳을 버릴 수 없었다.
  패키지(`jest-expect-message`)를 더하지 않은 이유는 하는 일이 그 20줄과 같아서다.
- **`toHaveBeenCalledOnce` · `toHaveBeenCalledExactlyOnceWith`** — 커스텀 매처. 후자를 두 단언으로
  쪼개면 «한 번» 이 빠져도 통과한다.
- **`vi.stubGlobal` 짝** — 원래 값을 기억해 두고 되돌리는 파일 지역 헬퍼(`fetch` 스텁 4파일).

타입도 함께 맞춘다(`jest-extensions.d.ts`) — 런타임만 고치면 `tsc` 가 빨개진다.

### 결정 3 — 목 팩토리는 **jest 의 규칙**으로 다시 쓴다

jest 는 `jest.mock()` 팩토리가 밖의 변수를 끌어오는 것을 막는다(`mock` 접두만 예외). vitest 의
`vi.hoisted` 는 그 자리를 정면으로 해결하던 장치라 **1:1 대응이 없다.** 세 형태로 나눠 옮겼다.

| 원래 모양 | 옮긴 모양 |
|---|---|
| `vi.mock(P, () => ({ x: xMock }))` | `jest.mock(P, () => ({ x: jest.fn() }))` + `const { x: xMock } = jest.requireMock(P)` |
| 팩토리가 **값**을 참조(가변 ref) | 이름을 `mock*` 로 바꾸고 **팩토리 안에서 늦게 채운다** |
| `getState: () => ({ k: kMock })` (중첩) | 팩토리 본문에서 `const k = jest.fn()` 을 만들고 `jest.requireMock(P).store.getState().k` 로 꺼낸다 |

**멱등성이 계약이다.** `jest.resetModules()` 를 쓰는 스펙에서는 팩토리가 다시 불리는데, 그때 새
목을 만들면 테스트가 붙들고 있던 인스턴스와 갈라진다(실제로 그 모양으로 한 번 깨졌다). 그래서
팩토리는 **같은 목을 돌려준다** — `vi.hoisted` 가 공짜로 주던 성질을 손으로 적은 것이다.

### 결정 4 — 동적 `import()` 는 **테스트에서만** CommonJS 로 내린다

`features/prehydrate.ts` 는 **일부러** 동적 import 를 쓴다([[ADR-101]] 결정 5 — 정적으로 바꾸면 세
탭 스토어가 첫 페인트 번들로 딸려 들어간다). 그런데 jest 는 CJS VM 이라 네이티브 `import()` 에서
*"A dynamic import callback was invoked without --experimental-vm-modules"* 로 죽는다.

**소스를 고칠 수 없는 자리라 러너 쪽에서 내린다.** `babel.config.js` 에 15줄짜리 플러그인을 두고
`api.env('test')` 일 때만, 그리고 **`src/` 절대 경로에만** 건다.

- `@babel/plugin-transform-modules-commonjs` 로는 안 됐다 — `babel-preset-expo` 가 caller 에
  `supportsDynamicImport` 를 켜 두어 그 플러그인이 `import()` 를 **일부러 남긴다**(실측).
- 경로를 `/src/` 로 잡으면 `node_modules/react-native/src/…` 까지 걸려 그쪽 프리셋 처리와 겹치고
  `Unexpected token 'export'` 가 난다(실측). 절대 경로로 못박는다.

Metro 는 이 갈래를 타지 않으므로 **앱 번들은 그대로다.**

### 결정 5 — `*.spec.*` 이름은 남긴다

러너가 하나가 됐어도 두 이름을 유지한다. 이제 그것이 말하는 것은 러너가 아니라 **성질**이다 —
`*.spec.*` 는 RN 을 렌더하지 않는 순수 로직·데이터·저장소(빠르다), `*.test.*` 는 RN 을 렌더하거나
RN 모듈을 목하는 것. 한 번에 다 돌리므로 갈라져도 비용이 없고, 이름을 통일하는 것은 **111개
파일을 또 건드리는 일**이라 얻는 것보다 비싸다.

### 결정 6 — 훅 스펙 다섯은 **jsdom 에 남긴다**

`use-count-up`·`use-api-key-notice`·`use-sync-error-toast`·`use-period-error-toast`·
`use-account-probes` 는 `@jest-environment jsdom` + `@testing-library/react` 로 돈다.

RN 도구(`@testing-library/react-native`)로 옮겨 봤고 **되돌렸다.** DOM 표면은 작았지만(`<div>` 둘 ·
`<span>` 하나 · `getByTestId` 하나) RNTL 14 의 `render` 가 비동기라 케이스마다 `await` 이 붙고,
`use-count-up` 은 `requestAnimationFrame` 을 손으로 굴리는 테스트라 그 위에서 값이 안 맞았다.
**러너는 하나** 라는 이 ADR 의 목적은 이미 이뤄졌고, 그 다섯을 위해 `react-dom`·`jsdom` 을 남기는
것이 훅 테스트 55개를 다시 쓰는 것보다 싸다. 옮길 값이 생기면 그때 옮긴다.

## 대가

- **`react-dom`·`jsdom`·`@testing-library/react` 가 devDependency 로 남는다**(결정 6).
- **팩토리가 손으로 적은 멱등성에 기댄다**(결정 3). `vi.hoisted` 가 공짜로 주던 성질이라, 새 목을
  더할 때 그 규칙을 모르면 «resetModules 뒤에 조용히 갈라지는» 실패를 다시 만든다.

### 남은 것 — 드문 워커 크래시 (미해결)

전체 실행 **6회에 한 번쯤** 워커가 `SIGSEGV` 로 죽는다. 매번 다른 스위트가 «Test suite failed to
run» 으로 빨개져 **테스트 실패로 오인하기 쉽다** — 그 줄을 보면 먼저 이것을 의심할 것.

계측한 것(추론이 아니라 값이다):

- 워커 9개(CPU 10) · 워커당 최대 힙 **746MB** · 물리 메모리 24GB → **메모리 여유가 넘친다.**
- 열린 핸들 **0** — 아래 「곁가지로 고친 것」의 누수 둘을 걷은 뒤로 «did not exit» 경고가 사라졌다.
- macOS 크래시 리포트의 폴트 프레임: `__kill ← uv_kill ← node::Kill ← PromiseRejectReactionJob`.
  **메모리 폴트가 아니라 시그널을 보내는 중**이고, 우리 코드에 `process.kill` 은 없다 → jest-worker
  의 종료 경로로 좁혀진다.

`workerIdleMemoryLimit` 으로 덮으면 사라지지만 **그것은 완화책이고 위 계측이 메모리 가설을 이미
반박한다.** 다음에 팔 자리는 jest-worker 의 teardown(워커 수를 줄여 재현률이 바뀌는지, `--detectLeaks`)이다.

### 곁가지로 고친 것 — **제품 코드의 타이머 누수 둘**

러너를 합치자 «jest 가 안 끝난다» 는 신호가 떴고, 그 끝에 **테스트 문제가 아닌 것** 둘이 있었다.
vitest 는 이 상태로도 그냥 끝나서 여태 안 보였다.

- **토스트 자동 소멸 타이머** — 토스트를 띄운 채 끝난 케이스가 2~2.5초짜리 실제 `setTimeout` 을
  남긴다(핸들이 모듈 스코프에 산다). `__resetToastsForTest()` 를 두고 `jest.setup.js` 의 전역
  `afterEach` 가 부른다 — **개별 테스트는 아무것도 안 해도 된다.**
- **SQLite 가드의 경주 타이머** — `Promise.race([쿼리, 타임아웃])` 이 **쿼리가 이겨도 타이머를
  안 껐다.** 조회 한 번에 5초짜리 하나씩 쌓인다. 앱에서도 새던 자리다. `.finally()` 로 끈다.
  같은 코드의 **사본 둘**(`drop-history-store`·`drop-price-store`)도 공유 헬퍼로 모았다 —
  사본이었기에 같은 결함을 세 벌 갖고 있었다.

옮기며 **행동은 한 건도 안 바꿨다.** 단언이 바뀐 자리는 둘뿐이고 둘 다 러너가 강제한 것이다 —
에셋 참조(Vite 는 URL 문자열, jest 는 `{ testUri }` 대역 → `assetUri()` 헬퍼로 통일) ·
`import.meta.glob` 으로 폴더를 훑던 자리(→ `readdirSync`).

## 열린 질문

- **드문 워커 `SIGSEGV`** — 위 「남은 것」. 재현률이 낮아 이분이 비싸다.
- **훅 스펙 다섯을 언제 RN 으로 옮기는가**(결정 6). 신호는 «jsdom 에서만 나는 차이 때문에 버그를
  놓치는 것» 이고, 지금은 그런 일이 없다.
- **`*.spec.*`/`*.test.*` 두 이름을 언젠가 하나로 하는가**(결정 5). 파일을 대량으로 건드릴 다른
  일이 생길 때 묻어서 하는 것이 싸다.
