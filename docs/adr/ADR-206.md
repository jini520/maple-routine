# ADR-206: 주석은 JSDoc 으로 역할만 적고, 소스는 ADR 을 인용하지 않는다

> 🟢 유효 · 2026-09-03 · **결정만 · 적용은 나눠서**(결정 5)

**관련**: [[ADR-194]](문서·주석·앱 문구를 읽히게 쓴다. 결정 2~4 가 그 정정 2 와 정정 1 을 넓힌다)

## 맥락

소스 주석이 ADR 을 **4,359번** 인용한다. `src/` 파일 706개 중 572개가 그렇다(테스트를 뺀 것이 338개).

**그 인용이 이유를 대신하고 있다.** `BottomSheet.tsx` 의 한 줄이 그렇다.

```
android_keyboardInputMode="adjustPan"   // ([[ADR-170]] 정정 11)
```

이 값이 왜 `adjustResize` 가 아닌지는 번호를 따라가야 알 수 있다. [[ADR-194]] 결정 2 가 `결론만 쓰지
말고 이유를 같은 자리에` 를 정했는데 인용이 그 규칙을 우회하는 길이 됐다. 이유를 안 적어도 번호가
붙어 있으면 적은 것처럼 보인다.

**방향도 뒤집혀 있다.** ADR 이 파일 경로와 심볼 이름을 적는 것은 결정이 코드를 가리키는 일이다.
파일이 ADR 번호를 적으면 코드가 결정을 가리킨다. 그러면 ADR 을 손볼 때 그것을 인용하는 소스가 전부
검토 대상이 되고, 실제로 이 저장소는 그 사고를 막으려고 테스트를 하나 두고 있다
(`adr-citation-policy.test.ts` 의 `소스는 완전히 죽은 ADR 을 인용하지 않는다`). 코드에는 결정을
관리할 권한이 없는데 관리 비용만 지고 있다.

## 결정

### 결정 1. 소스는 ADR 을 인용하지 않는다

`src/**` 의 주석에 `[[ADR-NNN]]` 을 안 쓴다. 테스트 파일도 같다.

**참조는 한 방향이다.** `docs/adr/*` 가 파일 경로와 심볼 이름을 적는 것은 그대로 한다. 무엇이
무엇을 가리키는지가 곧 무엇이 무엇을 관리하는지다.

지울 때는 세 갈래다.

| 인용이 하던 일 | 처리 |
| --- | --- |
| 이유가 바로 옆에 이미 있다 | 인용만 지운다 |
| 인용이 이유를 대신하고 있다 | 이유를 한 줄로 적고 인용을 지운다 |
| 옮길 이유가 없다 | 그 주석을 지운다 |

셋째가 가장 많을 것이다. 번호만 있는 주석은 번호를 빼면 남는 것이 없다.

**찾는 길은 반대로 낸다.** 소스에서 결정으로 올라가는 대신 `docs/README.md` 가 기능에서 문서로,
문서에서 소스 파일로 내려간다.

### 결정 2. 주석은 JSDoc 으로 쓰고 역할만 적는다

형태는 [[ADR-194]] 정정 2 그대로다. `/** */` 로 쓰고 파일 머리·타입·상수·함수·프롭에 붙인다.

**태그는 넷이다.**

| 태그 | 붙일 자리 |
| --- | --- |
| `@param` | 위치 인자를 받는 함수. 컴포넌트에는 안 붙인다 |
| `@example` | 쓰는 법. 지어내지 말고 실제 호출부에서 가져온다 |
| `@returns` | 반환값이 자명하지 않을 때만 |
| `@see` | 같은 저장소의 다른 파일 |

`@use` 는 JSDoc 태그가 아니라 어느 도구도 안 읽는다. 쓰는 법은 `@example` 이 받는다.

**내용은 역할만이다.** 경위·계측값·라이브러리 소스 인용·`예전에는 이랬다` 는 안 적는다. 그것은
ADR 과 git 이 갖는다. 주석이 답할 것은 `이것이 무엇이고 어떻게 쓰나` 하나다.

예외는 **어기면 버그가 나는 값**이다. `adjustResize` 로 바꾸면 시트가 키보드 뒤에 남는 것 같은
자리는 한 줄로 남긴다. 그 한 줄이 없으면 다음 사람이 그것을 고치려 든다.

### 결정 3. 문장은 명사로 끝낸다

역할을 적는 자리라 서술문이 필요 없다.

| 전 | 후 |
| --- | --- |
| 한 값을 무한 반복시킨다 | 한 값을 무한 반복시키는 훅 |
| 시트 최대 높이를 정한다 | 시트 최대 높이. 화면 높이 × 이 값 |
| 이 값이 바뀌면 스크롤을 되돌린다 | 바뀌면 스크롤을 맨 위로 되돌리는 키 |

완전한 문장이 필요한 자리는 남긴다. 결정 2 의 예외가 그렇다.

### 결정 4. 번역 말투와 장식 기호를 걷는다

[[ADR-194]] 정정 1 이 `~하는 유일한 자리다` 하나를 잡았는데 그것을 일반화한다.

전형적인 번역투는 이미 거의 없다. 소스 주석 24,217줄에서 `에 의해` 0회 · `필요가 있다` 0회 ·
`제공한다` 1회 · `에 대한` 9회다. 남은 것은 둘이다.

- ~~`것이다` **137회**. 강조가 아니라 습관으로 붙은 자리가 대부분이다.~~ **정정 2 가 이 항목을 뺀다** — 읽어 보니 정상 한국어다.
- `유일한` **45회**. 정정 1 이 94회에서 줄인 나머지다.

새 주석이 그것을 다시 들이지 않게 하는 것이 이 결정의 몫이다.

기호는 [[ADR-194]] 결정 3 그대로다. `—` · `«»` · `「」` 를 안 쓰고 가운뎃점 `·` 은 쓴다.
**지금 소스가 그 결정을 안 지키고 있다**: `—` 615 파일 · `«»` 303 파일 · `「」` 220 파일.

### 결정 5. 적용은 나눠서 하고 테스트는 마지막에 건다

[[ADR-194]] 결정 5 와 같은 이유다. 4,359건을 한 회차에 지우면 diff 를 검토할 수 없고 뜻이 바뀐
자리를 못 찾는다.

감사가 파일에 닿을 때 그 파일을 함께 고친다. 전부 끝난 뒤에 `src/**` 에서 `[[ADR-` 를 막는 테스트를
건다. 지금 걸면 572개가 한꺼번에 빨개져서 아무 작업도 못 한다.

### 정정 1 (2026-09-03) — 범위는 문자열과 생성기까지고, 테스트는 지금 건다

적용하면서 결정 1 의 범위를 세 자리 넓혔다.

**문자열도 같다.** 인용 4,359건 중 **338건이 주석이 아니라 문자열**이었다. 테스트 이름
(`describe('빈 상태 ([[ADR-101]] 결정 1)')`)이 대부분이고, 런타임 에러 문구도 하나 있었다
(`rn-back-gesture.ts` 가 던지는 메시지). 어느 쪽이든 ADR 을 손볼 때 소스가 검토 대상이 되는 것은
같으므로 함께 걷는다. 그 에러 문구를 물던 단언 `toThrow(/ADR-120/)` 은 메시지의 **뜻**을 무는
것으로 바꿨다.

**생성기도 같다.** `scripts/generate-asset-manifest.mjs` 가 `src/assets/generated/*.ts` 머리에
`[[ADR-129]]` 를 박아 넣고 있었다. 생성물만 고치면 다음 `npm run assets:gen` 에서 되살아난다.
`src/assets/asset-groups.ts` 의 `purpose` 문자열이 그 출처라 거기까지 고쳤다.

**테스트를 지금 건다.** 결정 5 는 적용이 끝난 뒤로 미뤘는데, 사용자 지정으로 전수 작업을 한 회차에
했으므로 그 시점이 지금이다. `adr-citation-policy.test.ts` 의 `소스는 완전히 죽은 ADR 을 인용하지
않는다` 를 **`소스는 ADR 을 인용하지 않는다`** 로 갈아 끼웠다. 예외는 그 파일 자신 하나다. 인용을
패턴으로 적어야 검사를 할 수 있다.

딸려서 그 파일의 가드 숫자 둘이 내려갔다. `SRC_CITATIONS > 3000` 은 없어지고
`checked > 1500` 은 문서만 남아 `> 600` 이 된다.

### 정정 2 (2026-09-03) — 결정 4 의 근거 하나가 틀렸고, `—` 는 71% 만 기계로 된다

**`것이다` 는 번역투가 아니다.** 결정 4 는 137회를 두고 `강조가 아니라 습관으로 붙은 자리가
대부분이다` 라고 적었는데, 그것은 숫자만 세고 문장을 안 읽은 판단이었다. 151건을 분류하면 이렇다.

| 갈래 | 건수 | 예 |
| --- | --- | --- |
| 명사화 `~한 것이다` | 58 | `읽히는 단위가 바뀐 것이다` |
| 지시대명사 `그것이다` | 37 | `그 파일이 경계로 있는 이유가 이것이다` |
| 소유 `~의 것이다` | 8 | `종류는 아이템 구매의 것이다` |
| 그 밖 | 48 | |

셋 다 정상 한국어다. 명사화는 영어 `the point is that` 의 계보가 아니라 한국어가 원래 쓰는
구문이고, 나머지 둘은 대명사와 소유격이다. **안 걷는다.** 결정 4 에서 이 항목을 뺀다.

`유일한` 은 [[ADR-194]] 정정 1 대로 갈랐다. 50건 중 **자리를 지정하는 35건**을 고치고
(`~하는 유일한 자리다` → `~하는 것은 여기뿐이다`), **개수가 하나라는 사실 15건**은 남겼다.
`테두리가 유일한 경계다` 나 `하한 34 아래인 유일한 경우다` 는 도메인 사실이다.

**`—` 는 7,291건 중 4,282줄만 기계로 바꿨다.** 앞이 문장 끝(`…다 — `)이거나 닫는 기호
(`` ` `` · `)` · `**`)인 자리만 마침표로 돌렸다. 나머지 3,008건은 구 중간이라 사람이 문장을 다시
써야 한다.

그중 일부는 **절대 못 바꾼다.** `adr-citation-policy.test.ts` 의 정규식이 `docs/ADR.md` 의 집계 줄
(`총 206건 — 🟢 121 · …`)을 문자 그대로 물고 있다. 주석이 아니라 코드다. 기계 치환을 파일 전체에
걸었다면 그 테스트가 깨졌을 것이고, 실제로 `「」` 를 백틱으로 바꿀 때 `db.ts` 의 템플릿 리터럴이
그 자리에서 닫혀 한 번 깨뜨렸다.

### 정정 3 (2026-09-03) — 대괄호 없는 `ADR-NNN` 도 인용이다

결정 1 을 적용하고 금지 테스트까지 건 뒤에도 **848건이 검사망 밖에 남아 있었다.** 대괄호가 없는
`ADR-115 결정 10:` 같은 형태다. 146개 파일에 있었고 대부분 주석 첫머리에서 문장을 여는 자리였다.

```
// ADR-115 결정 10: 저장된 키로는 앞으로 갈 수 없게 된 것을 알리고 확인을 받는 모달.
```

가리키는 대상이 같으므로 같은 규칙을 받는다. 함께 걷고 `adr-citation-policy.test.ts` 의 금지
검사에 `(?<!\[\[)ADR-\d{3}` 를 더했다.

찾는 자리도 넓혔다. 종전 스윕은 줄이 `//` 나 `*` 로 **시작**할 때만 봤는데, 그 밖에 셋이 더 있었다.
JSX 주석의 이어지는 줄 · 테스트 이름 문자열 · **코드 줄 뒤에 달린 꼬리 주석**이다. 마지막 것은
따옴표 밖의 첫 `//` 를 찾아 그 뒤만 고쳤다.

### 정정 4 (2026-09-03) — `—` 를 끝까지 걷고, 문체를 테스트로 못박는다

정정 2 는 `—` 7,291건 중 4,282줄만 바꾸고 나머지는 사람이 봐야 한다고 적었다. 사용자 지정으로
끝까지 갔다. **남은 것은 둘뿐이다.**

| 자리 | 왜 남기나 |
| --- | --- |
| `adr-citation-policy.test.ts` 의 정규식 | `docs/ADR.md` 집계 줄을 글자 그대로 문다. 주석이 아니라 코드다 |
| `boss-profit-period.ts` 의 표 칸 `\| — \|` | 「해당 없음」 이지 문장을 끊는 것이 아니다 |

바꾼 규칙은 둘이다. 앞이 한글·숫자·영문·닫는 기호면 **마침표**, 테스트 이름의 `이름 — 설명` 은
**쌍점**이다. 뒤쪽은 저장소가 이미 쓰던 형태다(`describe('update-available: 자세히 보기')`).

**인용을 걷으며 남긴 자국을 찾아 고쳤다.** 스윕 전후를 대조해 내가 만든 것만 골랐다.

| 자국 | 건수 |
| --- | --- |
| `가드 —.` 처럼 대시 뒤에 구두점만 남은 것 | 56 |
| `(— 사용자 확정)` 처럼 괄호를 열자마자 대시 | 113 |
| `describe(' — 안드로이드…')` 처럼 문자열 첫머리 대시 | 5 |
| 조사만 남아 문장이 깨진 것(`—의 정정 참고`) | 7 |

마지막 갈래는 인용이 문장 한가운데 있던 자리라 기계가 못 고친다. 손으로 다시 썼다.

**`src/__tests__/comment-style-policy.test.ts` 를 새로 둔다.** `«»` 와 `「」` 는 0건이라 그대로
막고, `—` 는 위 표의 둘만 허용한다. 허용 목록이 낡는 것도 함께 막는다. 그 파일에서 `—` 가
사라졌는데 목록에 남아 있으면 실패한다.

### 정정 5 (2026-09-03) — 인용이 문장의 주어였던 자리는 기계가 못 고친다

정정 4 가 자국 넷을 치웠는데 다섯째가 남아 있었다. **인용이 문장의 주어였던 자리**다.

```
([[ADR-173]] 결정 10 이 두 시트를 한 뼈대로 묶은 …)   →   (이 두 시트를 한 뼈대로 묶은 …)
```

`(` 다음에 조사가 바로 오는 형태는 한국어에 없다. 그것을 신호로 삼아 **151건**을 찾았다(스윕 전
같은 형태가 13건 있었고 그것은 원래 문장이다).

갈래로 나눠 고쳤다.

| 조사 | 처리 | 건수 |
| --- | --- | --- |
| 로 · 으로 · 에서 | 조사만 뺀다. 남는 말이 부사구라 문장이 선다 | 106 |
| 의 · 가 · 과 · 와 · 를 · 을 | 괄호째 뺀다. 인용이 머리말이라 남는 것이 없다 | 위와 같은 회차 |
| 이 · 는 · 은 | **스윕 전 원문을 대조해서만** 고친다 | 37 + 손으로 7 |

마지막 갈래가 어려웠다. `(이 …` 는 조사일 수도 있고 `이 화면` 처럼 **지시어**일 수도 있다.
`(이 저장소는 왜 없앴는지를 코드 옆에 적는다)` 는 멀쩡한 문장이다. 그래서 현재 줄만 보지 않고
스윕 전 파일에서 `( 인용 조사` 가 붙어 있었는지를 확인한 뒤에만 고쳤다. 대시가 끼어 있던 것
(`[[ADR-121]] 결정 1 — 이 카드의 …`)은 원래 지시어라 건드리지 않는다.

**교훈은 기계 치환의 검산을 스윕 전 파일로 해야 한다는 것이다.** 현재 문장만 보면 정상과 자국이
안 갈린다.

### 정정 6 (2026-09-03) — 파일 머리를 JSDoc 으로 바꾸고 검사를 붙인다

결정 2 는 형태를 [[ADR-194]] 정정 2 그대로 두기로 했는데, 그 정정은 범위를 `Badge` · `Text` ·
`TextInput` 셋으로 시작해 나머지는 감사가 닿을 때로 미뤄 뒀다. 여기서 끝낸다.

머리 주석이 `//` 이던 **117개 파일**을 `/** */` 로 바꿨다. `//` 는 선언에 안 붙어서 호출부에서
마우스를 올려도 안 보인다. 이제 머리 주석이 있는 파일 261개가 전부 JSDoc 이고, 없는 파일 131개는
규칙 밖이다.

`comment-style-policy.test.ts` 가 그 상태를 지킨다. 테스트 파일은 뺀다.

### 정정 7 (2026-09-03, 사용자 지정) — 결정 2·3 을 저장소 전체에 끝낸다

정정 6 은 결정 2 의 **내용**(역할만)과 결정 3(명사 종결)을 「기계로 안 된다」며 다음 감사로 미뤘다.

### 정정 8 (2026-09-03, 사용자 지정) — 결정 3 은 역할을 적는 자리 전부에 걸린다

정정 7 은 결정 3 을 「값을 이름 짓는 자리에만」 걸어 23곳을 고쳤다고 적었다. 그 범위가 좁았다.

### 정정 9 (2026-09-03) — 인용을 걷은 자리가 60곳에서 문장을 끊고 있었다

결정 1 을 적용한 회차들이 인용만 지우고 문장을 안 고쳤다. 인용이 **주어나 목적어**였던 자리에서
그 자리가 통째로 비었다.

```
// 의 문구 표를 그대로 옮긴 것이다. 이 배열이 계약이다.
// **위 테두리는 가 걷었다.**
//  의 다섯. 목록 셋과 직접 입력 둘.
```

정정 5 가 같은 종류를 한 번 치웠는데 그때 범위가 좁았다. 이번에는 여덟 가지 자국 패턴으로
`src` 를 훑어 274줄을 찾고, 그중 진짜 구멍 60곳을 손으로 메웠다. 나머지는 줄바꿈이 만든 오탐이다.

찾는 패턴은 이렇다. **줄머리 조사**(`// 가 ` · `//  의 `) · **조사 연속**(`은 가 ` · `를 에 `) ·
**문장 뒤 조사**(`. 과 `) · **괄호 잔해**(`(: ` · `(, `) · **주어 실종**(`는 걷었다`) ·
**가리킬 것 실종**(`그 회차에서` · `이 정정의`).

### 기계 치환으로 세 번 깨뜨렸다

적어 둔다. 같은 실수를 세 번 하지 않기 위해서다.

**① 문단을 통째로 다시 흘려 쓰는 스크립트.** 85 파일을 고치고 `types/theme.ts` 를 깨뜨렸다(tsc
에러). 살아 있는 문장도 함께 지웠다. 되돌리고 줄 단위로 다시 했다.

**② 겹공백 정리가 들여쓰기를 먹었다.** `  +` → ` ` 치환이 JSX 주석 줄의 **앞** 공백까지 줄여
14줄이 1칸으로 붙었다. 스윕 전 파일과 대조해 되돌렸다.

**③ 같은 치환이 코드 들여쓰기까지 먹은 것을 늦게 알았다.** ② 를 잡을 때 주석만 봤는데 네 파일의
**코드**도 함께 무너져 있었다(`Main.test.tsx` 164줄 · `db.ts` 111줄 · `font-scaling-policy` 64줄 ·
`sticky-policy` 10줄). tsc 도 eslint 도 잡지 않는다. 이 저장소에는 prettier 설정이 없어
자동 정렬로 되돌릴 수도 없다. 기준 트리의 같은 줄과 대조해 들여쓰기만 되살렸다.

**줄 단위 치환도 안전하지 않다.** 한 파일에 여러 줄을 고칠 때 **위에서 아래로** 적용하면 앞선
편집이 줄 수를 바꿔 뒤 편집이 엉뚱한 줄을 덮는다. 실제로 `SpendSheet.test.tsx` 에서 `it(...)`
한 줄이 주석으로 덮였다. 그 뒤로는 **파일마다 아래에서 위로** 적용하고, 고칠 줄의 내용을 먼저
확인한다.

**생성물만 고치면 되돌아온다.** `src/assets/generated/*.ts` 여덟 개를 고쳤는데 그것을 찍는
`scripts/generate-asset-manifest.mjs` 를 안 고쳤다. 다음 `npm run assets:gen` 이 전부 되돌린다.
생성기를 함께 고치고 다시 찍어 트리가 같은지 확인했다.

교훈은 둘이다. **주석의 뜻을 바꾸는 일은 줄 단위로 아래에서 위로 하고, 검산은 스윕 전 파일로
한다.** 그리고 **주석만 보지 말고 코드가 그대로인지 함께 본다** — 주석을 걷어낸 소스가 같은지
매 커밋 대조하면 이 부류가 전부 잡힌다.
