# ADR-271: 에픽 던전은 주 3회가 한도다. 공유 컨텐츠에 `n/3`, 한도가 차면 남은 던전은 `마감`

> 🟢 유효 · 2026-09-13 · **설계 · 구현 전**

**관련**: [[ADR-006]](게임 수치는 사용자 확인) · [[ADR-030]](에픽 던전 진행은 계정 원장이 든다) ·
[[ADR-147]] 정정 30 · 31 · 45(위젯 9 의 줄 · 계열 · 머리의 수) · [[ADR-182]] 결정 3 · 4(체크박스와 취소선,
오른쪽 카운트) · [[ADR-162]](요구 레벨 미달은 `진행 불가` 이고 분모에서 빠진다) · [[ADR-187]](보스 주간
한도를 채우면 `마감`) · [[ADR-261]] 정정 1(아우룸 레기스의 시작 기간)
**문서**: `features/today.md` · `features/content-scheduler.md` · `foundation/game-data.md`
**이슈**: #413

## 맥락

에픽 던전은 **4종이지만 주당 3회만** 진행할 수 있다(사용자 확인 2026-09-13, [[ADR-006]]). 앱은 이 한도를
모른다. 4종을 각각 따로 할 일로 세서, 3종을 끝낸 뒤에도 남은 1종이 할 일로 남는다.

| 자리 | 지금 |
|---|---|
| today 위젯 9 의 계열 제목 | 글자만 선다. 계열 단위의 수가 없다 |
| 위젯 9 의 줄(`SharedItemRow`, `app/today/widgets/SharedContentsWidget.tsx`) | 취소선과 체크가 **같은 값**(`item.isComplete`) 하나에서 온다. 오른쪽 카운트는 미완료이고 `max > 0` 일 때만 선다 |
| 카드(`EpicDungeonCard`, `app/content-scheduler/WeeklyContentCards.tsx`) | `nowCount > 0` 이면 `완료`, 아니면 `시작 안함`. 요구 레벨 미달이면 같은 자리에 `진행 불가`(`Badge variant="muted"`) |
| 링(`weeklyContentProgress`, `app/content-scheduler/content-completion.ts`) | 요구 레벨 미달은 분모에서 뺀다(`progressible`). 그래서 그 캐릭터의 링이 100% 에 닿는다 |

완료 판정은 `weeklyContentCompletion` 이 에픽 던전을 `byParticipation`(한 스테이지라도 깨면 완료, 사용자
확인 2026-09-11)으로 본다. 한도도 이 완료를 센다.

## 결정

### 결정 1. 한도는 카탈로그가 계열 단위로 든다

`3` 은 게임 규칙이라 코드에 박지 않는다. `scheduler-content-catalog.json` 에 계열 이름을 키로 하는 표를
둔다.

```json
"groupWeeklyLimits": { "에픽던전": 3 }
```

- 키는 줄의 `group` 칸과 같은 글자다. 계열명은 이미 사람이 적는 값이고([[ADR-147]] 정정 31), 이름에서
  `에픽 던전 : ` 접두사로 가르지 않는 것도 그 정정과 같은 이유다.
- 출처는 사용자 확인 2026-09-13 이다. 뜻과 출처는 같은 파일의 `groupWeeklyLimitsNote` 에 적는다.
- `maxCountOverrides` 에 두지 않는다. 그 표는 API 의 알려진 오류를 덮는 자리이고 게임 규칙을 적지
  않는다(그 파일의 `maxCountOverrideNote`).

### 결정 2. 판정은 `lib/scheduler` 의 순수 함수 하나다

위젯 · 카드 · 링이 **같은 함수**를 부른다. 요구 레벨 판정(`lib/scheduler/required-level`)을 두 화면이 한
함수로 보는 것과 같은 이유다. 갈라 두면 위젯은 `3/3` 인데 카드는 할 일이 남는 날이 생긴다.

- **세는 것**: 그 계열에 속한 항목 중 완료인 것의 수 `n`. `n >= 한도` 면 한도가 찼다.
- **완료는 호출부가 넘긴다.** 완료 판정 `weeklyContentCompletion` 은 `app/content-scheduler/` 에 있고
  `lib` 은 `app` 을 부르지 않는다. 그래서 함수는 항목과 그 완료 여부를 받는다.
- **세는 대상은 등록 여부와 무관한 에픽 던전 전부다.** 한도는 등록이 아니라 진행 횟수를 막는다. 자동
  모드에서 2종만 등록하고 등록 안 한 1종까지 3종을 돌았으면 한도가 찬 것이다. 그래서 카드와 링의
  원천은 표시 목록(`displayedWeeklyContents`)이 아니라 **그 캐릭터의 병합된 `weeklyContents` 전체**다.
  위젯의 원천은 뷰모델이 이미 합친 계열의 줄(`buildSharedContents`)이다.
- **한도는 메이플 ID 단위다.** 에픽 던전 진행은 계정 공유라([[ADR-030]] 계정 원장) 한 계정의 캐릭터들은
  같은 `n` 을 본다.

### 결정 3. 위젯 9: 계열 제목에 `n/3`, 한도가 차면 네 줄 모두 취소선

```
에픽던전            3/3
☑ ~~하이마운틴~~
☑ ~~앵글러컴퍼니~~
☐ ~~악몽선경~~
☑ ~~아우룸레기스~~
```

- **계열 제목 옆에 `n/3`** 이 선다(사용자 지정). `n` 은 이번 주에 완료한 에픽 던전 수다. 한도가 있는
  계열에만 선다.
- **취소선은 줄의 완료 또는 계열의 한도 참** 둘 중 하나로 긋는다. 흐린 글자(`text-text-disabled`)는
  취소선과 함께 간다. 둘을 함께 거는 것이 [[ADR-182]] 결정 3 이다.
- **체크박스는 지금처럼 줄의 완료만 본다.** 실제로 진행한 3줄만 채우고 남은 1줄은 비운다(사용자 지정).
- **한도 때문에 취소선만 그어진 줄은 오른쪽 카운트를 안 그린다.** 더 진행할 수 없는 줄의 진행 칸이다.
- 계열 제목의 `n/3` 은 [[ADR-147]] 정정 45 가 걷은 위젯 머리의 수와 다른 수다. 그쪽은 위젯 전체의 남은
  줄을 셌고, 이것은 한 계열의 **게임 한도**를 말한다.

### 결정 4. 카드: 한도가 찼고 미완료면 `마감`

- 상태 배지 자리에 `마감` 이 선다(사용자 지정 2026-09-13). **보스 카드의 `마감` 과 같은 배지다**
  (`Badge variant="muted" weight="bold"`, `BossScreen.tsx`). `완료` 와 같은 상자라 카드 끝이 안 흔들린다.
- 우선순위도 보스와 같다. **`진행 불가`(요구 레벨 미달) → `마감` → `완료`/`시작 안함`**. 요구 레벨 290 에
  못 미치는 캐릭터의 아우룸 레기스는 한도가 차도 `진행 불가` 다.
- `마감` 은 **미완료 카드에만** 선다. 보스의 `isWeeklyLimitClosed` 가 `limitReached && !isComplete` 인 것과
  같다(`features/boss-scheduler/displayed-bosses.ts`).

### 결정 5. 링: `마감` 은 분자에 든다

보스 링의 규칙과 같다(`BossScreen.tsx` 의 `bossRingProgress`). 마감은 이번 주 일이 끝난 것이라 4종을
추적했으면 3종 완료 뒤 링이 `4/4` 다. 안 그러면 3종을 다 해도 `3/4` 에 멈춰 100% 에 절대 못 닿는다.
요구 레벨 미달은 지금처럼 분모에서 빠진다.

링을 세는 `weeklyContentProgress` 는 컨텐츠 스케줄러 화면만 부른다. today 남은 스케줄은 공유 항목을 안
세서 영향이 없다.

## 테스트 (먼저)

- 판정 함수: 완료 3종 → 한도 참, 2종 → 거짓, 등록 안 한 던전의 완료도 센다
- 위젯 뷰모델(`buildSharedContents`): 계열 수 `n/3`, 한도 참이면 네 줄 모두 취소선 · 체크는 완료 3줄만 ·
  막힌 줄은 카운트 없음
- 카드: 한도 참 + 미완료 → `마감`, 한도 참 + 완료 → `완료`, 요구 레벨 미달 + 한도 참 → `진행 불가`
- 링: 4종 추적 · 3종 완료 → `4/4`

## 대가

- **아우룸 레기스 출시 전**([[ADR-261]] 정정 1)에는 에픽 던전이 3종이라 한도가 차도 남는 줄이 없다.
  계열 제목의 `n/3` 만 선다. 한도에 시작 기간을 따로 두지 않아도 동작이 맞는다.
- **다계정일 때 공유 위젯 한 줄이 어느 계정 것인가**(today.md 열린 질문)를 `n/3` 도 물려받는다. 위젯은
  계정을 가리지 않고 줄마다 캐릭터 값을 합치므로, 계정 둘이 서로 다른 던전을 돌면 `n` 이 한 계정의 수가
  아니다.
- **병합이 등록 안 한 에픽 던전을 떨굴 때가 있다**(확인 2026-09-13, 아래 남은 질문). 과거 날짜로 채우는
  `fillMissingSections` 는 네 섹션을 모두 낡은 것으로 두고 다시 병합한다. 그때 공유 항목은 원장에서만
  복원되고, 복원 루프는 `active` 가 거짓인 칸을 건너뛴다. 그래서 오늘 접속하지 않아 일간 섹션이 빈
  캐릭터는 아무도 등록하지 않은 에픽 던전이 `weeklyContents` 에서 빠지고, 그 던전의 완료가 `n` 에 안 든다.
  결정 2 의 `등록 안 한 던전의 완료도 센다` 가 그 캐릭터에서는 성립하지 않는다.

## 남은 질문

- **등록 안 한 에픽 던전이 병합에서 빠지는 틈을 메울지.** 위 대가의 셋째다.
- **계열 제목 `n/3` 의 모양.** 글자 크기 · 색 · 자리를 정하지 않았다.
- **`n` 이 한도를 넘을 때의 표기.** 한 계정에서는 게임이 막지만 다계정이면 넘을 수 있다.
