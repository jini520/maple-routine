# ADR-320: 액세스 토큰은 앱이 든다. 넥슨은 앱이 직접 부르고 서버는 교환·갱신만 한다

> 🟢 유효 · 구현 완료 2026-09-27(서버 · 앱) · 실기기 미검증 · 사용자 지정 · 이슈 #490

**관련**: [[ADR-296]] 결정 4(토큰은 서버가 든다 — **이 결정이 뒤집는다**) · [[ADR-318]](로그인 버튼)

## 맥락

[[ADR-296]] 결정 4 는 토큰을 전부 서버에 두고, 앱은 우리가 발급한 세션 하나만 들고 프렌즈
API 를 **서버 프록시**로 불렀다. U4 가 그 프록시를 만들어 배포했다(`friends-panel` 화이트리스트
6경로).

**부하가 안 맞는다**(사용자 지정 2026-09-26). 강화 내역 조회가 한 회차에 수백 건을 쏜다.

```
planEnhancementHistory:  날짜 31 × 종류 4 = 124 작업
각 작업:                 최대 50 페이지 (MAX_PAGES, PAGE_SIZE 1000)
```

이걸 미니 PC 가 전부 중계하면 사용자 한 명의 한 번 조작이 서버에 수백~수천 요청을 만든다.
넥슨이 감당하는 것을 우리가 가운데서 한 번 더 받는 셈이다.

그리고 로그인 버튼을 처음 눌러 보면서 하나 더 드러났다. 로그인으로는 프렌즈 6경로만 열려서,
나머지 12경로(`character/basic` · 메소 다섯 · 공지 넷 …)는 **어차피 API 키가 있어야 한다.**

## 결정

### 결정 1. 액세스 토큰을 앱에 넘긴다 (사용자 지정)

서버가 code 를 교환한 뒤 **액세스 토큰을 앱에 준다.** 앱은 그것으로 넥슨을 직접 부른다.

```
로그인        앱 → 서버 (code 교환, client_secret 보유) → 앱에 액세스 토큰
프렌즈 6경로   앱 → 넥슨 직접 (Authorization: Bearer <액세스 토큰>)
비프렌즈 12경로 앱 → 넥슨 직접 (x-nxopen-api-key: <개발자 키>)
토큰 갱신      앱 → 서버 (client_secret 이 필요해 서버만 할 수 있다)
```

**`client_secret` 은 안 옮긴다.** 교환도 갱신도 그것을 요구하고(`refreshTokens` 실측), 앱 번들에
넣으면 그대로 뜯긴다. [[ADR-296]] 결정 4 에서 살아남는 것은 이 한 줄이다.

**갱신 토큰(14일)도 서버에 남긴다.** 앱이 드는 것은 수명 30분짜리 액세스 토큰뿐이다.

### 결정 2. 서버의 프렌즈 프록시를 걷는다

`friends-proxy.ts` 와 그 테스트를 없앤다. 앱이 직접 부르므로 쓸 일이 없고, 남겨 두면 다음
세션이 그리로 다시 보낸다.

서버에 남는 일은 **OAuth 교환과 토큰 갱신 둘**이다.

### 결정 3. `credentialOf` 는 로그인이 있으면 로그인을 고른다

종전에는 **API 키만** 골랐다(`config?.apiKeys[0]`). 로그인을 붙이면 같은 계정의 키가 거둬지는데
(#541), 그러면 수단이 0개인 것처럼 읽혀 **앱의 조회가 전부 죽었다**(시뮬레이터 실측 2026-09-26.
화면에는 `네트워크 오류가 발생했습니다` 가 떴지만 네트워크를 탄 적이 없다 - 자격이 `null` 이라
`resolveTrackedCharacterContext` 가 부르기 전에 던졌다).

로그인이 있으면 **액세스 토큰**을 고른다. 프렌즈 밖 경로는 이 자격으로 못 가는데, 그 자리는
`routeOf` 가 개발자 키로 바꿔 단다(결정 4).

**남은 키를 어느 메이플 ID 에 쓸지는 이 결정이 안 정한다.** 로그인이 안 덮는 다른 넥슨 계정의
키가 남을 수 있고, 그 계정 캐릭터는 지금 자격으로 안 보인다. `mergeMapleIds` 가 그 답이 될
자리인데 아직 호출부가 없다(열린 질문).

### 결정 4. 개발자 키는 앱 번들에 넣는다. 둘을 번갈아 쓰고 예비로 둔다 (사용자 지정)

비프렌즈 12경로를 위해 개발자 API 키를 앱에 심는다.

키를 **둘** 둔다(`EXPO_PUBLIC_NEXON_API_KEY_1` · `_2`). **요청마다 번갈아** 써서 한도를 두 배로
쓰고, 무효(400 `OPENAPI00005`)거나 한도 초과(429)인 키는 집합에서 빼 남은 것만 쓴다.

**대가를 적어 둔다.** 번들에서 꺼낼 수 있고, 꺼내 쓰면 우리 한도가 탄다. 넥슨이 그 키를 막으면
로그인 사용자 전원의 비프렌즈 조회가 함께 죽는다. 약관 제6조⑥ 부담도 개발자 쪽이다
([[ADR-296]] 결정 8 이 적어 둔 것). **사용자가 이 대가를 알고 고른 것이다**(2026-09-26).

### 결정 5. 만료는 401 로 알고 그 자리에서 다시 받는다

액세스 토큰이 30분이라 **한 회차 안에서 만료될 수 있다**(강화 내역 수백 건이 30분을 넘길 수
있다). 앱은 프렌즈 경로의 401 을 받으면 서버에 새 액세스 토큰을 받아 **한 번 재시도**한다.

**재시도는 한 번뿐이다.** 두 번째도 같은 실패면 올린다. 그래야 안 도는 것이 보장된다.

받아 오는 함수는 **부팅이 꽂는다**(`setAccessTokenRenewer`). `nexon/` 이 저장소와 우리 서버를
직접 부르면 계층이 거꾸로 서기 때문이고, `native/ports.ts` 와 같은 태도다. 안 꽂혀 있으면
재시도하지 않고 401 을 그대로 올린다.

**키 자격의 401 은 여기 안 온다.** 키가 죽은 것이라 받아 올 토큰이 없다.

두 번째 401 이면 갱신 토큰까지 죽은 것이라 재로그인을 띄운다(로그인 만료 알림 경로 그대로).

## 실측 — 결정 4 의 전제 (2026-09-27)

**개발자 키로 남의 계정 ocid 를 조회할 수 있다.**

```
id?character_name=아델        → ocid 32자
character/basic?ocid=<그것>   → 200
```

키 소유 계정과 무관한 캐릭터다. `character/list` 만 키 소유 계정으로 묶이고
(`docs/foundation/nexon-api.md`), ocid 를 주고 부르는 경로는 안 묶인다.

그래서 로그인 사용자의 비프렌즈 12경로를 개발자 키로 채울 수 있다. 이 값이 400 이었으면
결정 4 가 안 서고 사용자 키를 안 지우는 쪽으로 돌아가야 했다.

## 대가

- **[[ADR-296]] 결정 4 를 뒤집는다.** 그 결정의 근거는 `client_secret` 이었고 그 부분은 그대로
  살아 있다. 옮기는 것은 액세스 토큰뿐이다.
- **U4 의 프록시가 버려진다.** 만들어 배포까지 한 것이다.
- **앱이 평문으로 드는 것이 하나 는다**(액세스 토큰). 다만 수명 30분이라 API 키보다 낫다.
