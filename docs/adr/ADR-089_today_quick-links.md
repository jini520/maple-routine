# ADR-089 today 빠른 이동

> ⚪ 미구현
> 관련 소스: `app/today/widgets/` · `storage/`

## 배경

사용자가 today 에 빠른 이동을 두자고 했다(#613). 자주 가는 화면을 사용자가 직접 골라 today 에서 바로 연다.

today 의 다른 위젯은 요약을 보여 주고, 더 볼 사람만 원래 화면으로 보낸다([[ADR-058]] 결정 11). 빠른 이동은
반대로 누르는 것이 전부인 위젯이다.

## 결정

### 결정 1. 빠른 이동은 today 위젯 하나이고, 칸마다 화면 하나를 연다

위젯 타일 전체는 누를 수 없고 안의 칸을 하나씩 누른다. 칸마다 갈 곳이 다르기 때문이다. 그래서 레지스트리에는
`target` 없이 등록하고, 위젯이 직접 화면을 연다. 다음 파티 스케줄 위젯이 회차마다 다른 곳을 여는 방식과 같다.

### 결정 2. 고를 수 있는 화면은 열다섯이고, 화면마다 아이콘이 하나다

화면과 아이콘은 후보표에서 사용자가 골랐다(사용자 지정). 위젯 칸에는 짧은 이름을 쓴다(결정 7).

| 묶음 | 화면(라우트) | 위젯 이름 | 아이콘 |
|---|---|---|---|
| 탭 | 파티 스케줄(`Appointments`) | 파티 스케줄 | `CalendarClock` |
| 탭 | 컨텐츠(`Content`) | 컨텐츠 | `ListChecks` |
| 탭 | 보스(`Boss`) | 보스 | `Swords` |
| 탭 | 보스 수익(`Profit`) | 보스 수익 | `ProfitIcon` |
| 탭 | 가계부(`Cashbook`) | 가계부 | `Wallet` |
| 탭 | 통계(`Stats`) | 통계 | `TrendingUp` |
| 탭 | 유틸리티(`Utility`) | 유틸리티 | `Hammer` |
| 관리 | 보스 관리(`BossManage`) | 보스 관리 | `SlidersHorizontal` |
| 관리 | 캐릭터 관리(`SettingsCharacters`) | 캐릭터 관리 | `UserRound` |
| 유틸리티 도구 | 판매 분배금 계산기(`UtilityItemSplit`) | 분배금 계산 | `Divide` |
| 유틸리티 도구 | 주간 보스 수익 계산기(`UtilityBossProfitCalculator`) | 보스 계산기 | `Calculator` |
| 더보기 | MVP 등급(`SettingsMvpGrade`) | MVP 등급 | `Crown` |
| 더보기 | 공지 목록(`SettingsNotices`) | 공지 | `Megaphone` |
| 더보기 | 알림 설정(`SettingsNoticeAlerts`) | 알림 설정 | `BellRing` |
| 더보기 | 설정(`AppSettings`) | 설정 | `GearIcon` |

드롭 히스토리 · 아이템 가격 입력 · 컨텐츠 관리 · 기능 설명은 넣지 않는다(사용자 지정). 상세 화면(공지 상세 · 기능 설명
상세 · 등급 이력)도 넣지 않는다. 무엇을 열지 정하는 인자가 있어야 열리는 화면이라 칸 하나로 고정할 수 없다.

### 결정 3. 한 줄(5개)과 두 줄(10개) 가운데 편집 화면에서 고른다

사용자가 편집 화면에서 줄 수를 고른다(사용자 지정). 한 줄에는 칸 다섯이 선다(사용자 지정). 위젯 안에서 가로로
스크롤하지 않는다. 타일 안 스크롤은 페이지 스크롤과 제스처를 두고 싸운다([[ADR-058]] 결정 4).

두 줄에 여섯 개 이상 골라 둔 채 `한 줄` 로 바꾸면 트레이 순서로 여섯 번째부터의 칸을 선택에서 뺀다(사용자 지정).
뺀 칸은 다시 `두 줄` 로 바꿔도 돌아오지 않는다. 가로 스크롤로 넘치는 칸을 남기는 방법은 기각했다(사용자 지정).

### 결정 4. 구성은 위젯 안에서 연 편집 화면에서 고친다

더보기 설정에는 두지 않는다(사용자 지정). 고치고 싶은 순간 사용자가 보고 있는 것이 이 위젯이기 때문이다.

편집 화면은 위젯 제목 줄 오른쪽의 `편집` 을 눌러 연다(시안 B5-1, 사용자 지정). 다른 위젯의 `파티 스케줄 ›` 처럼
제목 줄 오른쪽 글자가 누르는 곳이라는 약속을 그대로 쓴다. 마지막 칸을 편집 칸으로 쓰면 바로 가기가 한 칸 줄고,
길게 누르기는 화면에 단서가 없다.

### 결정 5. 처음에는 자주 쓸 만한 화면으로 한 줄이 채워져 있다

빈 위젯으로 시작하면 사용자가 편집 화면을 찾아 들어가기 전까지 쓸모가 없다(사용자 지정).

처음 구성은 한 줄이고, 순서대로 보스 수익(`Profit`) · 통계(`Stats`) · 보스 관리(`BossManage`) · 판매 분배금 계산기
(`UtilityItemSplit`) · 설정(`AppSettings`) 이다(사용자 지정).

### 결정 6. 구성은 `storage/` 어댑터를 거쳐 저장한다

`features/` 와 `app/` 은 저장소에 직접 닿지 않는다(CLAUDE.md 아키텍처 규칙).

### 결정 7. 칸은 테마색을 옅게 깐 원 안의 옅은 테마색 아이콘이고, 이름은 작고 흐리게 적는다

시안 B 를 골랐다(사용자 지정). 칸 바탕을 칠하지 않고 원 하나만 둔다. 원 바탕은 테마의 `primary` 를 따르되
`primary-tint` 보다 옅게 깐다(사용자 지정). `primary-tint` 는 아이콘 열 개가 모이면 너무 진하다. 아이콘도 같은
이유로 `primary` 그대로가 아니라 옅게 그린다(사용자 지정). 둘 다 `primary` 의 투명도로 내므로 테마를 바꾸면 따라간다.

| 테마 모드 | 원 바탕 | 아이콘 |
|---|---|---|
| 밝게 | `primary` 6% | `primary` 55% |
| 어둡게 | `primary` 8% | `primary` 70% |

어둡게 모드의 값이 더 큰 것은 어두운 바탕에서는 같은 투명도가 더 흐려 보이기 때문이다(사용자 지정).
화면 이름은 원 아래에 작고 흐리게 적는다(사용자 지정). 아이콘만으로는 무엇인지 알기 어렵고, 크고 진하게 적으면
아이콘보다 글자가 먼저 읽힌다. 한 줄에 다섯 칸이면 칸 폭이 60px 안팎이라 10px 를 넘으면 `드롭 히스토리` 가 한 줄에
들어가지 않는다. 글자는 9px · `text-muted` 다(시안 N4, 사용자 지정). 그래서 위젯에는 짧은 이름(`분배금 계산` · `가격 입력` · `보스 계산기`)을 쓰고, 접근성 이름
(`accessibilityLabel`)은 전체 이름으로 단다.

### 결정 8. 편집 시트는 보스 선택 시트와 같은 구조이고, 트레이가 위젯의 미리보기다

시안 E2 를 골랐다(사용자 지정). 주간 보스 수익 계산기의 보스 선택 시트(`BossPickerBody` · `BossPickerTray`)와 같은
구조다. 앱에 이미 있는 고르는 방식을 따르면 사용자가 새로 익힐 것이 없다.

- **본문**: 결정 2 의 묶음마다 둥근 카드를 두고, 카드 안에 타일을 한 줄에 다섯씩 세운다. 타일은 위젯과 같은 원 아래에
  화면 이름을 적는다. 위젯에는 이름이 없으므로 이 시트가 이름을 알려 주는 유일한 곳이다.
- **고른 타일**: 원 오른쪽 아래에 `primary` 체크가 붙고 이름이 굵어진다. 칸이 다 차면 고르지 않은 타일을 흐리게 한다.
- **바닥 트레이**: 개수 배지(`7 / 10`)와 줄 수 세그먼트(`한 줄` · `두 줄`)가 한 줄에 서고, 그 아래에 위젯과 같은
  5열 칸이 빈 칸까지 그대로 선다. 저장될 모습을 시트를 닫기 전에 보여 주기 위해서다. 맨 아래는 `적용` 버튼이다.
- 트레이의 칸을 누르면 빠지고, 길게 누르면 끌어서 순서를 바꾼다. 보스 선택 시트의 트레이와 같은 동작이다.
