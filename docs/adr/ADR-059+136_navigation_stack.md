# ADR-059+136 화면 스택과 하단바

> 🟢 유효
> 옛 번호: ADR-077 · ADR-098 · ADR-120 결정 1 · 4 · 9 · 18 · ADR-132 결정 1 · 2 · 3 · 7 · 11 · ADR-167 · ADR-209 · ADR-210 · ADR-234
> 관련 소스: `navigation/` · `components/organisms/BottomBar/` · `lib/bottom-bar-metrics.ts` · `hooks/useOpenTab.ts` · `hooks/useScreenNavigation.ts` · `hooks/useScrollToTop.ts` · `hooks/useRootBackToBackground.ts` · `native/haptics.ts`

## 배경

앱의 탭 화면은 아홉 개다. 이것을 하단바 한 줄에 모두 놓으면 칸이 좁아져 라벨부터 깨진다. 그래서 하단바에는
그룹 다섯 개만 두고, 하위 화면이 있는 그룹을 누르면 바가 그 그룹의 하위 행으로 바뀌게 했다.

탭 화면 위에서 여는 하위 페이지(보스 관리, 드롭 히스토리, 설정의 하위 화면 등)는 열아홉 개다. 이 페이지들과
하단바의 하위 행이 같은 방식으로 열려야 한다. 같은 방식이란 오른쪽에서 밀려 들어오고, iOS 에서 화면 왼쪽 끝을
밀면 돌아가는 것이다. 이 문서는 그 구조를 react-navigation 스택으로 어떻게 짰는지를 정한다.

## 결정

### 결정 1. 하위 페이지는 루트 스택에 push 하고, 아래 화면은 그대로 둔다

하위 페이지는 `RootNavigator` 의 루트 스택에 쌓는다. 전환 애니메이션과 iOS 가장자리 스와이프는
`@react-navigation/native-stack` 에 들어 있어서 앱이 따로 만들지 않는다.

push 로 열면 아래 화면이 언마운트되지 않는다. 그래서 하위 페이지에서 돌아와도 펼쳐 둔 아코디언, 보던 기간,
스크롤 위치가 그대로 남는다. 뒤로 가기는 `goBack()` 한 번이다. 딥링크를 두지 않아서 스택은 앱이 push 한 만큼만
깊고, 하위 페이지가 떠 있으면 그것을 연 화면이 반드시 아래에 있다. 그래서 화면마다 부모 경로를 갖고 있을
필요가 없다. 딥링크 설정(`linking`)을 넣으면 없던 진입 경로가 생기므로 두지 않는다.

하위 페이지에는 하단바가 없다. 바는 `LayerStack` 안에 있고(결정 2), 하위 페이지는 `LayerStack` 전체를 옆으로
밀어내므로 바도 아래 화면과 함께 밀려 나간다. 바를 앱 맨 위로 올리면 하위 페이지 위에서 언제 숨길지를 따로
판정해야 하고, 밀려 나가는 대신 사라지게 된다.

하위 페이지 목록은 `routes.ts` 의 `ROUTE_TABLE` 에서 뽑는다. `RootNavigator` 의 `STACK_SCREENS` 는
`Record<StackRouteName, …>` 이어서, 표에 행을 더하고 화면을 빠뜨리면 컴파일이 안 된다.

### 결정 2. 하단바의 그룹 행과 하위 행은 스택 한 단씩이다

```
RootStack
├─ Main (LayerStack)
│   ├─ Groups        Today · Utility · Settings
│   ├─ ScheduleSubs  Appointments · Content · Boss
│   ├─ LedgerSubs    Profit · Cashbook · Stats
│   └─ BottomBar     layout 이 그린다
└─ 하위 페이지 열아홉
```

하위가 있는 그룹을 누르면 `LayerStack` 에 그 그룹의 레이어 화면(`ScheduleSubs` · `LedgerSubs`)이 push 된다.
하위 행으로 내려가는 것도 진짜 push 라서, 하위 페이지와 같은 전환과 가장자리 스와이프가 생긴다. 두 스택은
`PUSH_SCREEN_OPTIONS` 상수 하나를 함께 쓴다. 각자 값을 적어 두면 한쪽만 고쳤을 때 열리는 방식이 조용히 달라진다.

각 레이어 화면 안은 탭 내비게이터다. 그래서 같은 그룹 안에서 하위끼리 옮겨 갈 때(컨텐츠에서 보스로)는 스택이
늘어나지 않고 전환도 없다. 이때 ← 를 누르면 그 그룹에 들어오기 전 화면으로 나간다. 탭 내비게이터는
`backBehavior="none"` 이다. `"history"` 로 두면 모든 탭 전환이 쌓여 유틸리티에서 설정으로 옮긴 것까지 뒤로 가기로
되돌아온다. 하위끼리 옮겨도 탭이라 서로 언마운트하지 않으므로 스크롤 위치도 남는다.

바는 `LayerStack` 의 `layout` 이 레이어 화면들 뒤에 형제로 그린다. 레이어가 밀려도 바는 움직이지 않는다.
라우트 이름 `Main` 은 화면들이 `navigate('Main', …)` 으로 쓰고 있어서 컴포넌트 이름이 `LayerStack` 으로 바뀐
뒤에도 그대로 둔다.

### 결정 3. 그룹은 다섯이고, 어느 행을 보여 줄지는 지금 페이지로 정한다

| 그룹 | 라벨 | 하위 |
|---|---|---|
| `today` | today | 없음 |
| `schedule` | 스케줄러 | 파티 스케줄 · 컨텐츠 · 보스 |
| `ledger` | 수익·지출 | 보스 수익 · 가계부 · 통계 |
| `utility` | 유틸리티 | 없음 |
| `settings` | 더보기 | 없음 |

표는 `bar-groups.ts` 의 `BAR_GROUPS` 하나다. 그룹은 하위가 있으면 레이어 화면(`layer`)을, 없으면 자기
페이지(`page`)를 가진다. 둘 중 하나만 가져야 하고, 둘 다 가지거나 둘 다 없으면 어느 행을 그릴지 정할 수 없다.

지금 페이지의 그룹이 하위를 가지면 하위 행을, 아니면 그룹 행을 그린다(`barLayer`). 그룹 행을 보여 주라는 상태를
따로 두지 않는다. 따로 두면 가계부에 있는데 그룹 행이 떠 있는 상태가 생기고, 그 상태에서 뒤로 가기가 어디로
가야 하는지 답할 수 없다.

← 는 하위 행에만 나온다. 그룹 행에서는 다섯 그룹이 이미 다 보여서 나갈 버튼이 필요 없다. 하위 행에 있으면
스택이 반드시 두 단 이상이므로 ← 를 눌렀을 때 돌아갈 곳이 없는 경우는 없다.

### 결정 4. 레이어 상태는 react-navigation 이 관리하고, 바는 마지막 하위 하나만 기억한다

지금 페이지는 react-navigation 상태에서 읽는다(`pageFromLayerState`). 바가 사본을 따로 가지면 탭은 가계부인데 바는
스케줄러를 그리는 프레임이 생긴다. 중첩 내비게이터는 첫 프레임에 아직 상태가 없어서, 그때는 이동할 때 넘긴
`params.screen` 을 읽고, 그것도 없으면 그 레이어의 첫 화면으로 정한다. 모르는 이름이 오면 첫 화면으로 떨어진다.
바가 예외를 던지면 앱 전체가 멈추기 때문이다.

바가 직접 갖는 값은 `lastSub` 하나다(`bar-store.ts`). 그룹을 나가면 그 레이어 화면이 언마운트되므로, 다시
들어갈 때 어느 하위를 열지는 앱이 기억해야 한다. 하위를 가진 그룹을 다시 누르면 마지막으로 보던 하위가 열린다.

`bar-groups.ts` 의 함수들은 새 상태가 아니라 해야 할 이동(`BarIntent`)을 돌려준다. 상태가 react-navigation
쪽에 있어서 새 상태를 돌려줄 수 없기 때문이다. 이동은 `openSubs` · `switchSub` · `switchGroupPage` · `back` ·
`none` 다섯 가지이고, 실제로 이동시키는 일은 `BottomBar` 가 `BarNavigation`(`openLayer` · `goBack`)으로 한다.
판정이 순수 함수라 렌더 없이 테스트할 수 있다.

### 결정 5. 같은 레이어 화면은 스택에 두 번 쌓지 않는다

이미 아래 단에 있는 레이어로 가면 새로 쌓지 않고 그 단까지 되돌아간다. react-navigation 7 의 `navigate` 는
되돌아가지 않고 한 단 더 쌓기 때문에, 바는 `StackActions.popTo` 를 먼저 보낸 뒤 안쪽 탭을 정한다. 이렇게 하지
않으면 하위 행에서 그룹 페이지로 갈 때 바닥에 있는 `Groups` 가 한 번 더 쌓인다. 그러면 바에는 ← 가 없는데
가장자리 스와이프로는 뒤로 갈 수 있는 상태가 된다.

화면에서 탭을 여는 `useOpenTab` 도 같은 규칙을 따른다. 그룹 페이지(Today · Utility · Settings)로 갈 때는 먼저
`popToTop` 으로 `Groups` 까지 되돌아간다. 다만 `LayerStack` 이 한 단뿐이면 보내지 않는다. 뺄 단이 없을 때
`POP_TO_TOP` 을 보내면 처리하는 내비게이터가 없어 개발 모드 경고가 뜬다. 단 수는 `getParent(LAYER_STACK_ID)` 로
`LayerStack` 을 직접 찾아서 센다. `canGoBack()` 은 탭 내비게이터의 뒤로 가기까지 세어서 바닥에서도 참이 될 수
있다.

그래서 스케줄러, 가계부, 스케줄러 순으로 옮긴 뒤 ← 를 누르면 가계부가 아니라 스케줄러에 들어오기 전 화면으로
나간다. 스택 깊이가 끝없이 늘어나지 않게 하려고 이렇게 정했다.

### 결정 6. 화면은 페이지 이름만 알고, 레이어 구조로 바꾸는 일은 `navigation/` 이 한다

탭으로 가려면 `navigate('Main', { screen: 레이어, params: { screen: 페이지 } })` 처럼 두 단을 적어야 한다.
이것을 화면마다 적으면 어느 페이지가 어느 레이어에 있는지가 화면 수만큼 복사된다. 그래서 이 변환은
`tab-navigate.ts` 의 `tabNavigateArgs` 하나에서만 하고, 화면은 `useOpenTab()` 에 페이지 이름만 넘긴다. 파라미터는
가장 안쪽 화면에 붙인다. 한 단 위에 붙이면 레이어 화면이 받고 목적지 화면은 못 받는다.

하위 페이지를 열 때는 `useScreenNavigation()` 을 쓴다. `useSettingsNavigation` 은 같은 훅의 별칭이다.

`navigation/` 에는 내비게이터와 페이지 표만 둔다. 하단바를 그리는 코드는 `components/organisms/BottomBar/` 에,
훅은 `hooks/` 에 둔다. `bar-groups.ts` 는 바만 쓰는 것이 아니라 `tab-navigate.ts` 와 `page-from-layer-state.ts` 도
읽는 페이지 표라서 `navigation/` 에 남긴다.

### 결정 7. 앱은 today 에서 시작하고, `ROUTE_TABLE` 의 `/` 행은 컨텐츠를 그대로 가리킨다

`INITIAL_TAB_ROUTE` 는 `Today` 다. 타입이 `keyof GroupLayerParamList` 여서 하위 페이지를 첫 화면으로 적을 수
없다. 적을 수 있으면 앱을 켜자마자 스택이 두 단인 상태가 생긴다.

`ROUTE_TABLE` 의 `/` 행은 옛 웹 앱이 `/` 에서 무엇을 보여 줬는지 적어 둔 기록이라 `Content` 그대로 둔다. 첫
화면과 이 행이 다른 것은 의도한 것이다. 둘이 어긋나 보인다고 `/` 를 `Today` 로 고치지 않도록 테스트가 두 값을
한 번에 확인한다.

### 결정 8. 안드로이드에서 더 뺄 화면이 없으면 뒤로 가기는 앱을 백그라운드로 보낸다

하위 페이지나 하위 행이 떠 있으면 react-navigation 이 뒤로 가기를 받아 한 단 뺀다. 레이어도 진짜 스택이라
`canGoBack()` 하나로 판정할 수 있다. 더 뺄 것이 없을 때의 기본 동작은 액티비티 종료인데, 그러면 다음 실행이 콜드
스타트가 되어 스플래시부터 다시 본다. 그래서 `useRootBackToBackground` 가 그때만 뒤로 가기를 받아
`moveAppToBackground()` 를 부른다. 다시 열면 보던 화면 그대로다. 종료할지 묻는 창은 띄우지 않는다. 홈 버튼과 같은
동작이라 잃는 것이 없다.

`BackHandler` 리스너는 나중에 등록된 것부터 불린다. 이 훅은 pop 할 것이 있으면 `false` 를 돌려주고 react-navigation
에 넘기므로, 어느 쪽이 먼저 불려도 결과가 같다. 컨테이너가 아직 준비되지 않았으면 판정하지 않는다.

### 결정 9. 활성 탭을 두 번 누르면 그 화면이 맨 위로 스크롤된다

300ms 안에 같은 항목을 두 번 누르면 더블탭으로 본다(`double-tap.ts` 의 `isSecondTap`). 두 플랫폼의 시스템 더블탭
간격과 같은 값이다. 더 늘리면 한참 떨어진 두 번의 누름이 더블탭으로 잡혀, 탭을 확인하려고 두 번 누른 사용자가 맨 위로
튕긴다. 더블탭으로 잡히면 기록을 지워서 세 번째 누름은 다시 첫 누름이 된다. 다른 탭에서 옮겨 온 직후의 누름도
더블탭의 첫 누름으로 세지 않는다.

바는 화면 밖에 있어서 화면의 `ScrollView` 를 직접 잡을 수 없다. 그래서 `scroll-to-top.ts` 에 라우트 이름별로
맨 위로 올리는 함수를 등록해 두고, 바는 지금 페이지 이름으로 그 함수를 부른다. 함수 하나만 등록하는 방식은 안
된다. 같은 레이어의 탭 화면들은 서로 언마운트하지 않아서 마지막에 등록한 화면만 남기 때문이다. 등록은
`ScreenScroll` 이 `useScrollToTopTarget` 으로 하고, 화면 안에 버튼을 달 때는 `useScrollToTop()` 을 쓴다. 두 훅은
`useRoute()` 대신 `NavigationRouteContext` 를 읽는다. 컴포넌트 테스트가 내비게이터 없이 렌더하는데 `useRoute()`
는 그때 예외를 던진다. 해제할 때는 이름이 아니라 등록한 함수가 같은지를 보고 지운다. 이펙트가 다시 돌면
새 등록이 옛 해제보다 먼저 일어나서, 이름만 보면 방금 등록한 함수가 지워진다.

### 결정 10. 누른 결과로 무언가 바뀌면 햅틱을 낸다

햅틱은 두 종류다.

| 함수 | 뜻 | iOS | 안드로이드 |
|---|---|---|---|
| `tapFeedback()` | 눌러서 어딘가로 갔다 | `impactAsync(Light)` | `performAndroidHapticsAsync(Virtual_Key)` |
| `selectionFeedback()` | 고른 값이 바뀌었다 | `selectionAsync()` | `performAndroidHapticsAsync(Clock_Tick)` |

하단바의 탭 이동과 ← 는 `tapFeedback()` 을 낸다. 활성 탭을 다시 누를 때와 맨 위로 스크롤할 때는 내지 않는다.
화면은 그대로인데 손끝에 무언가 바뀌었다고 알리면 거짓 신호가 되기 때문이다. ← 도 화면이 바뀌는 이동이라 탭
이동과 같은 햅틱을 낸다. 같은 바 안에서 누름마다 촉감이 다르면 헷갈린다.

같은 기준을 앱 전체에 쓴다. 페이지 뒤로(`BackButton`), 기간 이동 화살표, 떠 있는 버튼(`SpeedDial` ·
`DropPriceFab`)은 `tapFeedback()` 을, `Segment` · 난이도 고르개(`DifficultyExpander`)와 `Switch` ·
`CalendarGrid` · `CharacterRail` · 캐릭터 카드 순서 바꾸기와 `Stepper` 의 `−` · `+` 는 `selectionFeedback()` 을 낸다.
이미 고른 값을 다시 누르면 내지 않는다. `Stepper` 가 최솟값 · 최댓값에 닿으면 그쪽 버튼이 막혀 누름이 없으므로
햅틱도 없다. 값이 바뀌지 않았는데 울리면 거짓 신호가 된다. 가능하면 부품 안에서 부른다. 호출하는 화면마다 적어 두면 새 화면에서 빠뜨리기 쉽다.

안드로이드에서 `impactAsync` · `selectionAsync` 를 쓰지 않는다. 그쪽 구현은 진동 모터를 직접 돌려서, 사용자가
시스템 설정에서 촉각 피드백을 꺼도 울린다. `Segment_Tick` 대신 `Clock_Tick` 을 쓰는 것은 `Segment_Tick` 이
API 34 이상에만 있기 때문이다. 기기에 진동 장치가 없거나 촉각 피드백이 꺼져 있어 거절되면 그 오류는 무시한다.
햅틱 때문에 이동이 막히면 안 된다. 포트가 주입되지 않은 것은 배선 실수라서 그대로 예외를 던진다.

### 결정 11. 바는 화면 위에 떠 있고, 치수는 창 폭으로 계산한다

바는 `position: absolute` 로 띄운다. 콘텐츠는 바 아래로 지나가고, 끝에 남길 여백은 `ScreenScroll` 이 바 높이로
계산한다([[ADR-063]]).

| 값 | 계산 |
|---|---|
| 폭 | `min(창 폭 − 14 × 2, 420)`. 상한에 걸리면 남는 폭을 좌우로 나눠 가운데에 둔다 |
| 높이 | `round(폭 × 72 / 374)`, 최소 64 |
| 아래 위치 | 하단 안전영역 바로 위(`BAR_LIFT` 0). 안드로이드는 안전영역 최소 34 |
| 안쪽 여백 | 3. 알약 높이는 바 높이 − 6 |
| 칸 폭 | `(폭 − 3 × 2 − 23) ÷ 5`. 알약은 칸보다 23 넓다 |

높이를 폭에 비례시킨 것은 칸 폭이 이미 바 폭에 따라 달라지기 때문이다. 높이를 고정하면 기기마다 알약의 가로세로
비가 달라진다. 비례 상수는 402pt 기기에서 쓰던 값(폭 374, 높이 72)에서 거꾸로 구했다. 최소 높이 64 는 아이콘,
간격, 라벨이 들어가는 최소 높이다. 폭에 상한을 두면 높이도 함께 멈춘다. 높이 상한을 따로 적으면 폭은 멈췄는데
높이만 커지는 조합이 생긴다.

치수를 측정하지 않고 계산하는 이유는 측정값이 첫 프레임에 0 이어서 알약이 한 프레임 접혀 보이기 때문이다.
같은 함수(`resolveBottomBarMetrics`)를 바와 `ScreenScroll` 이 함께 써서 두 값이 어긋나지 않는다.

키보드가 떠 있으면 바를 그리지 않는다(`useKeyboardShown`).

### 결정 12. 활성 표시는 알약과 아이콘으로 하고, 유리 재질은 iOS 26 이상에서만 쓴다

iOS 26 이상에서는 바와 알약, ← 원판을 `expo-glass-effect` 의 `GlassView` 로 그린다. 바는 `regular`, 알약과
원판은 `clear` 재질이다. `colorScheme` 은 OS 설정이 아니라 앱 테마의 `mode` 를 따른다. 기본값 `auto` 로 두면
라이트 OS 에서 다크 테마를 켰을 때 어두운 페이지 위에 밝은 유리판이 뜬다. 유리가 없는 iOS 26 미만과
안드로이드는 불투명한 캡슐이고, 블러로 유리를 흉내 내지 않는다.

← 원판은 `Pressable` 밖에 둔다. 안에 두면 iOS 가 그 `GlassView` 를 그리지 않는다. 원판은 `opacity: 0` 으로
마운트하지 않고 ← 가 필요할 때만 마운트한다. 투명한 상태로 마운트하면 iOS 가 유리 효과를 꺼 버리고 다시 켜지 않는다.

색은 `bar-colors.ts` 의 `resolveBarColors` 가 테마에서 계산한다.

- 바의 바탕은 그 모드에서 가장 밝은 표면이다(라이트 `surface` · 다크 `surface2`). 페이지와 바는 색이 아니라
  그림자로 구분한다. 바를 어둡게 해서 구분하면 그 위의 글자가 안 읽힌다.
- 바와 활성 알약 둘레에 선(헤어라인)을 긋지 않는다(사용자 지정 2026-10-30, [[ADR-060]] 결정 19). 유리 재질 위에서도 같다.
  선이 하던 일은 바의 그림자를 조금 진하게 해서 맡긴다.
- 활성 아이콘과 라벨은 같은 색이고, 그 테마의 메인 컬러(`primaryInk`)다. 다크에서는 메인 컬러가 비활성보다
  어두워질 수 있어서 명도만 올린다. `text` 쪽으로 섞으면 채도까지 빠져 주황이 갈색이 된다.
- 비활성 아이콘과 라벨은 `textMuted` 에서 채도를 뺀 색이다. 바 안에서 색을 가진 것은 활성 항목 하나뿐이어야
  한다. 이 처리는 바 안에서만 하고, 테마 토큰은 그대로 둔다.
- 안쪽에 의미 있는 선이 없는 아이콘(대시보드 · 렌치 · 검 · 수익)은 활성일 때 면을 채운다. 나머지는 채우면 안쪽
  선이 사라지므로 대신 획을 굵게 한다(1.5 에서 2.2, 달력과 시계는 1.8). 채우기와 굵히기는 함께 하지 않는다.

그림자는 `boxShadowOf` 로 `boxShadow` 에 적는다. `shadowOpacity` 같은 iOS 전용 속성은 안드로이드에 전달되지 않는다.
라벨에는 `includeFontPadding: false` 를 준다. 안드로이드는 글자 상자에 여백을 더해서 아이콘이 3px 위로 밀린다.

### 결정 13. 같은 행 안에서는 알약이 미끄러지고, 행이 바뀌면 두 행이 차례로 교차한다

같은 행 안에서 탭을 옮기면 알약이 240ms 동안 미끄러진다. 화면 전환(340ms)보다 짧은 것은 움직이는 거리가 짧아서다.
그룹 행과 하위 행이 바뀔 때는 알약을 미끄러뜨리지 않는다. 두 행의 항목이 달라서 이어지는 위치가 없기 때문이다.

행이 바뀌면 280ms 동안 나가는 행이 먼저 사라지고 들어오는 행이 나타난다. 두 행을 같은 구간에 겹쳐 흐리면 항목 수가
다른 두 줄이 포개져 글자가 이중으로 보인다. 하위 행은 첫 칸을 ← 에 내주고 둘째 칸부터 시작한다. 그래서 그룹 행과
칸 위치가 같다. 폭을 바꾸는 애니메이션은 없고, 이동 · 투명도 · 크기만 네이티브 드라이버로 움직인다. 그래서 탭을 누른 직후
화면 마운트로 JS 가 막혀도 전환이 끊기지 않는다.
