# ADR-100 강화 내역을 계산한 합계로 저장하고, 다시 매길 기간은 환경 변수로 건다

> ⚪ 미구현
> 관련 소스: `storage/enhancement-history.ts` · `features/enhancement-history/collect.ts` · `features/enhancement-history/spending.ts` · `storage/sqlite/migrations.ts`

## 배경

가계부는 강화 API(큐브 · 스타포스 · 잠재능력 · 소울 잠재)의 응답 줄을 `enhancement_history.payload` 로 통째로 들고,
읽을 때마다 비용을 계산한다([[ADR-047]] 결정 10). 이것을 계산이 끝난 합계로 저장하게 바꾼다(#614, 사용자 2026-10-06).
합계는 #507 이 서버로 보낼 최종값이 된다([[ADR-099]]).

합계를 저장하면 계산 코드나 비용 표를 고쳐도 지난 합계가 저절로 바뀌지 않는다. 그래서 그 기간을 넥슨 API 에서 다시
받아 매기는 요청 장치를 함께 둔다(#615).

## 결정

### 결정 1. 저장 단위는 날짜 · 캐릭터 · 분류 · 장비별 합계이고, 응답 원본은 버린다

가계부의 분류 줄과 장비별 펼침이 그대로 남는다([[ADR-047]] 결정 12). 값을 못 매기는 줄은 지금처럼 버린다. 장비 레벨은
`equipment-items.json` 에서만 찾고, 같은 이름의 큐브 · 잠재 기록에서 레벨을 빌리던 `loadObservedItemLevels` 는 걷는다.
캐릭터 소속을 모르다가 나중에 알게 되는 경우는 예외로 둔다. 없어진 캐릭터가 다시 생기면 새로 만든 캐릭터다(사용자 지정).

### 결정 2. 합계는 MVP 할인 전 비용으로 저장하고, 할인은 화면에 보일 때 앱이 붙인다

MVP 등급 기간을 고쳐도 강화 내역을 다시 받지 않기 위해서다(사용자 지정 2026-10-26). 넥슨 로그인 계정의 강화 내역은 서버
스트림을 거쳐 받으므로, 다시 받으면 서버 부하가 크다.

- 합계 한 줄은 칸 둘로 비용을 든다. `attempt_cost_meso` 는 MVP 할인을 받는 시도 비용이고, `destroy_defence_cost_meso` 는
  할인을 받지 않는 파괴 방지 추가 비용이다([[ADR-050]] 결정 5). 큐브 · 잠재 · 소울은 MVP 와 무관해 시도 비용 칸만 쓴다.
- 이벤트 할인(샤이닝 스타포스 등)은 그 시도에 실제로 붙은 할인이라 시도 비용에 이미 넣는다.
- 화면은 그 날짜 · 그 캐릭터의 MVP 할인을 시도 비용 합계에 한 번 붙이고 내림한 뒤 파괴 방지 비용을 더한다. 등급을 찾는
  규칙은 지금과 같다([[ADR-050]] 결정 2 ~ 4).
- 시도마다 내림하던 것이 합계에 한 번 내림하는 것으로 바뀌어, 시도당 1 메소 이하의 차이가 생긴다. 사용자가 받아들인
  오차다.
- MVP 할인이 붙은 금액은 서버로 보내지 않는다([[ADR-099]] 결정 7). 기기가 할인 전 합계를 들고 있으므로 등급을 고쳐도
  서버에 물을 것이 없다.

### 결정 3. 기존 기기는 DB 이관이 원본으로 합계를 만들고, 원본 표는 v1.0.14 에서 지운다

이관은 #507 의 다음 DB 버전이다. 옛 `enhancement_history` 는 v1.0.13 에서 읽지 않은 채 두고 v1.0.14 에서 지운다(사용자 선택, #685).
[[ADR-078]] 결정 9 와 같은 이유다.

### 결정 4. 다시 매길 기간은 `EXPO_PUBLIC_*` 환경 변수로 걸고, 끝나면 완료 표에 적는다

- 요청 하나는 `id` · 기간(`from` · `to`) · 종류(빼면 넷 다)다. API 가 아니라 번들에 박히는 환경 변수라 OTA 로 나간다
  ([[ADR-014]] 결정 6).
- 수집기는 끝나지 않은 요청의 날짜를 굳음(`settled`)과 상관없이 다시 받아 합계를 갈아 끼우고, 진행 바 분모에도 넣는다.
- 요청의 날짜를 모두 받으면 완료 표에 `id` 를 적고, 적힌 요청은 다시 안 돈다. 하나라도 실패하면 안 적는다.
- 조회 하한 밖은 받을 수 없어 건너뛰고, 기간이 통째로 하한 밖이면 바로 완료로 적는다. 형식이 틀린 값은 무시한다.
- 다시 매길 때는 지금 비용 표의 값으로 매긴다.
- 넥슨 로그인 계정은 한 회차에 7일치만 다시 받는다(사용자 선택 2026-10-26, 날 수는 구현 때 정한 처음 값). 그 계정의 강화
  내역은 서버 스트림을 거치므로, 요청을 걸면 모든 로그인 사용자가 그 기간을 한꺼번에 서버로 받게 된다. 나눠 받으면 부하가
  여러 날로 흩어진다. 남은 날은 다음 회차가 이어 받고, 모든 날을 받은 회차에 완료를 적는다. 진행 바 분모에도 그 회차에
  받을 날만 넣는다. API 키 계정은 앱이 넥슨을 직접 부르므로 나누지 않는다.
