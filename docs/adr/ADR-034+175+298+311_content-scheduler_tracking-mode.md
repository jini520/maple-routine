# ADR-034+175+298+311 자동 · 수동 추적 모드와 컨텐츠 관리

> 🟢 유효
> 옛 번호: ADR-035 · ADR-096 · ADR-086 결정 2 · ADR-140 결정 5 정정
> 관련 소스: `features/tracking-mode/` · `storage/tracking-mode.ts` · `storage/manual-tracked-content.ts` · `lib/scheduler/manual-content-merge.ts` · `features/content-scheduler/displayed-contents.ts` · `features/content-scheduler/store.ts` · `features/content-scheduler/manage-draft.ts` · `app/content-scheduler/ContentManageScreen.tsx` · `app/boss-scheduler/BossManageScreen.tsx` · `hooks/useUnsavedChangesGuard.ts` · `app/settings/SettingsActionBar.tsx` · `components/organisms/NoticeModal/` · `storage/record-revision-batch.ts` · `app/settings/TrackingModeModal.tsx` · `app/settings/TrackingModeSelector.tsx` · `storage/preferences-conversion.ts`

## 배경

스케줄러 화면은 처음에 게임 안 스케줄러에 등록한 항목만 읽어서 보여 줬다. 그런데 응답의 `registration_flag` 가
실제 게임 상태와 어긋나는 일이 계속 생겼다. 그래서 게임 등록에 기대지 않고 앱에서 직접 추적할 항목을 고르는 수동
모드를 만들었다.

## 결정

### 결정 1. 모드는 앱 전체에 하나다

`trackingMode` 는 `'auto'` 또는 `'manual'` 이고, 컨텐츠 스케줄러와 보스 스케줄러에 똑같이 적용된다. 화면마다,
캐릭터마다 따로 정하지 않는다.

- Preferences 키 `trackingType` 에 저장한다. 서버 칸 이름과 같다([[ADR-099]] 결정 57). 값이 없거나 알 수 없는 값이면 `getTrackingMode` 는 `'auto'` 가 아니라
  `null` 을 돌려준다. 고르지 않은 것과 자동을 고른 것을 같은 값으로 두면, 사용자가 고르지도 않은 자동이 선택된
  것처럼 보이기 때문이다. 동작은 자동이 기본이라 읽는 두 곳(`features/tracking-mode/store` ·
  `features/boss-profit/store`)이 `?? 'auto'` 로 받는다.
- 사용자가 직접 고른 설정이라 데이터 삭제가 지우지 않는다. 데이터를 지웠다고 수동 모드가 말없이 자동으로
  돌아가면 안 된다.
- 모드를 바꿔도 자동 쪽 데이터도 수동 쪽 추적 목록도 지우지 않는다.

### 결정 2. 자동은 게임 등록을, 수동은 추적 목록을 따른다

| 모드 | 화면에 나오는 항목 |
|---|---|
| 자동 | 병합 결과 중 `isRegistered` 가 참인 항목 |
| 수동 | 그 캐릭터의 추적 목록에 있는 항목. 등록 여부는 보지 않는다 |

자동과 수동을 합친 목록은 만들지 않는다. 합치면 수동으로 지운 항목이 게임에 등록돼 있다는 이유로 다음 동기화에서
다시 나타나, 지우기가 무슨 뜻인지 알 수 없게 된다.

스케줄러 API 동기화는 모드와 관계없이 항상 전체 상태를 받는다. 보스 수익 자동 기록도 모드와 관계없이 동기화 결과로
한다. 화면에 무엇을 보여 주는지는 기록에 영향을 주지 않는다.

### 결정 3. 추적 목록에는 무엇을 추적하는지만 저장하고, 값은 보여 줄 때 찾는다

`manualTrackedContent:{ocid}` 에 캐릭터마다 배열 하나를 저장한다.

- 저장하는 항목은 서버 `manual_tracked_items` 와 같은 `{ type, targetId }` 다([[ADR-099]] 결정 47). `type` 은 `'daily'` ·
  `'weekly'` · `'boss'` 이고, `targetId` 는 일일 · 주간이면 컨텐츠 줄 id, 보스면 난이도 줄 id 다.
- 화면과 병합이 드는 항목은 컨텐츠면 `{ contentKey, kind }`, 보스면 `{ kind: 'boss', bossKey, difficulty }` 다. 저장소
  (`storage/manual-tracked-content.ts`)가 줄 id 와 key 를 오간다. 게임 데이터에 없는 줄 id 의 항목은 읽을 때 건너뛰고, 표에 없는
  key 를 적으려 하면 던진다.
- `kind` 는 저장할 때 정한다. 시드는 응답의 일일 · 주간 배열로, 관리 화면은 지금 보는 탭으로 정한다. 보여 줄 때
  추측하면 같은 항목이 일일 · 주간 탭 양쪽에 나온다.
- `nowCount` · `questState` · `isRegistered` 같은 값은 저장하지 않는다. 화면에 그릴 때 그 캐릭터의 동기화 결과에서
  컨텐츠 key 로 찾고(`mergeManualContentList`), 한 번도 동기화된 적 없는 항목은 컨텐츠 표의 기본값을 쓴다. 값을 두
  곳에 두면 모드를 바꿀 때 방금 완료로 보이던 항목이 미완료로 바뀌는 일이 생긴다. 한 곳에서만 읽으면 두 모드가
  언제나 같은 값을 본다.
- 이 키는 사용자가 관리 화면에서 저장할 때와 시드할 때 쓴다. 넥슨 스케줄 동기화는 쓰지 않는다. 서버 동기화의
  받기는 다른 기기에서 바꾼 항목을 이 키에 쓰고 두 스케줄러 스토어를 다시 읽힌다(`refreshAfterServerSync`, [[ADR-099]]).
  그래서 관리 화면을 연 동안에도 저장된 목록이 바뀔 수 있다(결정 10).
- 최대 횟수는 저장하지 않는다. 카드는 넥슨이 준 값이나 컨텐츠 표의 값을 써서 읽는 곳이 없다([[ADR-099]] 결정 52).
- 1.0.15 전의 형식(일일 · 주간 구분 없는 `kind: 'content'`, key 대신 이름이 들어 있는 항목, key 로 적은 항목)은 기기 변환이 한 번
  컨텐츠 표 · 보스 표로 줄 id 를 찾아 옮겼다([[ADR-286]] 결정 7). 찾지 못한 항목은 버렸다. 관리 화면은 표에 있는 항목만 보여
  주므로, 표에 없는 항목을 남기면 편집할 수 없는 항목이 된다.

### 결정 4. 추적할 수 있는 컨텐츠는 컨텐츠 표에 있는 것뿐이다

추가는 자유 입력이나 지난 응답 목록이 아니라 컨텐츠 표에서 고른다. 게임 데이터라 사용자가 확인한 항목만 표에
들어간다([[ADR-019]]). 표에서 고르면 한 번도 동기화되지 않아 고를 것이 없는 문제도 생기지 않는다.

표 전체를 자동 모드의 목록으로 쓰지는 않는다. 어떤 퀘스트가 그 캐릭터에게 열리는지는 레벨 · 직업 · 스토리 진행에
따라 다르고, 그 정보는 넥슨 서버에만 있다. 사람이 고를 때는 그런 판단이 필요 없다.

### 결정 5. 수동 모드의 추적 목록은 그때의 게임 등록으로 한 번 채운다

`seedManualTrackedContent` 가 최신 동기화 결과에서 등록된 항목을 추적 목록에 넣는다. 처음 수동 모드를 켰을 때 목록이
비어 있지 않게 하려는 것이다. 부르는 경우는 셋이다.

- 자동에서 수동으로 바꾼 순간, 추적 중인 캐릭터 전원을 시드한다(`useTrackingModeStore.setMode`).
- 이미 수동 모드인데 추적 캐릭터를 새로 더하면 더한 캐릭터만 시드한다(컨텐츠 · 보스 스케줄러 스토어의
  `saveTrackedOcids`).
- 수동 모드에서 처음 캐릭터를 고르면 그 캐릭터들을 시드한다(앱 첫 설정의 `completeCharacterSetup`).

시드 규칙은 이렇다.

- 컨텐츠 표에 없는 컨텐츠, 보스 표에 없는 보스는 넣지 않는다(결정 3 과 같은 이유).
- 캐릭터 여럿을 한 번의 `syncSchedules` 로 처리하고, 결과는 순서가 아니라 ocid 로 찾는다. 캐릭터마다 따로 부르면
  진행 중인 동기화에 서로 합류해 전원이 첫 캐릭터의 스케줄로 채워졌다.
- 결과가 없거나 `state` 가 `null` 이면 예외를 던지고 저장하지 않는다. 빈 배열로 채우면 정말 아무것도 등록하지 않은
  사용자와 구분할 수 없다.
- 이미 있는 목록은 덮어쓴다.

자동에서 수동으로 바꿀 때의 시드(`seedManualTrackedContentOnModeSwitch`)는 두 가지가 다르다. 이때는 추적 중인
캐릭터 전원을 채운다. 조회 불가 캐릭터는 추적 목록에서 지우지 않으므로([[ADR-028]] 결정 9) 그 캐릭터도 함께 들어온다.
캐릭터를 새로 더할 때와 첫 설정의 시드는 위 규칙 그대로다.

- 조회 불가 캐릭터는 건너뛰고, 그 캐릭터의 목록은 건드리지 않는다(사용자 지정 2026-11-05). 동기화 결과가 없는
  캐릭터(넥슨 캐릭터 목록에서 빠졌다)와 결과의 에러가 `characterUnavailable` 인 캐릭터가 조회 불가다. 채울 게임
  등록이 없고, 스케줄러가 이미 조회 불가 안내를 보여 준다. 예외를 던지면 조회되는 캐릭터까지 수동으로 바꾸지 못한다.
- 다른 이유로 못 채운 캐릭터가 있어도 나머지 캐릭터는 끝까지 채운 뒤 예외를 던진다(사용자 지정 2026-11-05). 못 채운
  캐릭터의 목록도 건드리지 않는다. 그 캐릭터는 사용자가 컨텐츠 관리에서 더한다. 실패를 알리는 방법은 결정 9 에 있다.

시드가 끝날 때까지는 로딩을 보여 주고 결과를 한 번에 그린다. 컨텐츠 표 기본값은 거의 미등록 · 진행 없음이라, 먼저
그리면 아직 결과가 안 왔을 뿐인데 아무것도 등록하지 않은 것처럼 보인다.

### 결정 6. 두 모드 모두 컨텐츠 관리 화면과 같은 순서로 보여 준다

목록 순서는 추적 목록에 들어간 순서가 아니라 컨텐츠 관리 화면의 순서다. 추가 · 삭제할 때마다 순서가 바뀌던 문제를
고친 것이다. 일일은 컨텐츠 표 순서대로 카테고리를 묶은 순서, 주간은 카테고리 표 순서다. 자동 모드도 같은 순서로
맞춘다(`orderContentsByTemplate`). 화면마다 순서가 다르면 같은 목록으로 보이지 않는다.

컨텐츠 표에 없는 컨텐츠는 자동 모드에서 등록돼 있으면 목록 뒤에 API 이름으로 나오고, 수동 모드에서는 고를 수 없으니
나오지 않는다.

### 결정 7. 추적 항목은 컨텐츠 관리 화면에서만 고친다

스케줄러 화면은 두 모드 모두 읽기만 한다. 카드마다 삭제 버튼을 두거나 목록 끝에 추가 버튼을 두면 진행을 보는
화면이 어수선해진다.

- 수동 모드일 때만 스케줄러 머리 오른쪽에 `관리` 가 나온다(사용자 지정 2026-11-03). 누르면 `ContentManage` 를 루트 스택에 push 한다.
  스크린 리더 이름은 `컨텐츠 관리` 다. 화면에서는 컨텐츠 스케줄러 머리 안이라 무엇의 관리인지 보이지만, 스크린 리더는 버튼 이름만 읽는다.
  수동 모드의 빈 상태 버튼도 같은 화면을 연다.
- 관리 화면은 수동 모드 전용이다. 자동 모드에서 열려 있으면 바로 뒤로 간다.
- 일일 · 주간 · 공유 탭으로 컨텐츠 표 전체를 체크리스트로 보여 주고([[ADR-331]] 결정 6), 추적 중인 항목만 선택 상태(`bg-primary-tint`)로,
  나머지는 카드 바탕(`bg-surface`)으로 그린다. 줄에 테두리는 없다([[ADR-060]] 결정 19). 시작 기간 전인 컨텐츠는 목록에서 뺀다([[ADR-019]]).
- 행을 누르면 추적을 켜고 끈다. 누른 것은 초안에 들고, 화면 아래 `저장` 을 눌러야 저장된다(결정 10).
- 행은 카테고리로 묶는다(`categorizeContentEntries`). 묶음 머리에는 아이콘 · 카테고리 이름 · `추적 수/전체 수` 가
  있고, 행에는 `displayName` 과 같은 아이콘이 있다. 아이콘은 카테고리 key 로 고른다(일일 · 주간 퀘스트 `MapPin`,
  에픽 던전 `Castle`, 메이플 유니온 `LayoutGrid`, 몬스터파크 `Swords`, 아케인리버 지역 퀘스트 `Sparkles`, 무릉도장
  `Medal`, 길드 `Flag`).
- 행 오른쪽의 참고 배지는 `contentCountTag` 가 정한다. 컨텐츠 줄의 `countTag`, 카테고리 줄의 태그, 기본 규칙
  (횟수형이고 상한이 있으면 `최대 n회`) 순서로 본다. 지금 적힌 값은 몬스터파크 `월드 당 최대 14회`, 익스트림
  몬스터파커 `월드 당 2회`, 에픽 던전 `ID당 1회` 이고, 아케인리버 지역 퀘스트는 숨긴다. 리셋 · 제한 규칙이라
  사용자가 확인한 값만 적는다.
- 길드 미가입 캐릭터의 잠금은 [[ADR-033]] 결정 8 이다.

### 결정 8. 컨텐츠 탭은 스토어에 두고, 관리 화면은 들어올 때 한 번 이어받는다

탭이 화면 안의 상태였을 때는 다른 탭에 다녀오면 일일로 돌아갔고, 주간을 보다 `컨텐츠 관리` 를 눌러도 일일 목록이
열렸다.

- 탭(`activeTab`)은 `features/content-scheduler/store.ts` 에 있다. 처음 값은 일일이다. 이미 받은 데이터를 나눠
  보여 줄 뿐이라 탭을 바꿔도 조회하지 않는다.
- 관리 화면은 들어올 때의 스케줄러 탭으로 시작한다(`useState(schedulerTab)`). 관리 화면에서 탭을 바꿔도 스케줄러
  탭은 그대로다. 관리 화면에서 잠깐 다른 탭을 본 것 때문에 돌아왔을 때 보던 탭이 바뀌면, 고치려던 문제가 반대
  방향으로 다시 생긴다.
- 저장하지 않는다. 앱을 다시 켜면 일일이다. 앱을 쓰는 동안 보던 탭을 잃는 문제만 고치면 되기 때문이다.
- 고른 캐릭터는 탭과 달리 두 화면이 언제나 같다. 관리 화면에서 고친 추적 목록이 어느 캐릭터의 것인지 헷갈리면 안
  되기 때문이다. 캐릭터 선택은 [[ADR-030]] 이 다룬다.

### 결정 9. 설정에서 모드를 바꿀 때는 고른 뒤 `적용` 을 눌러야 한다

설정의 `스케줄 관리 방법` 모달(`TrackingModeModal`)에서 바꾼다.

- 옵션을 누르면 고르기만 하고, `적용` 을 눌러야 `setMode` 가 한 번 불린다. 누르자마자 저장되면 되돌릴 방법이
  없었다. 버튼은 설정의 다른 확인 모달처럼 `취소` 와 `적용` 이다. 모드 전환은 지우는 동작이 아니라서 `적용` 은
  `primary` 채움 버튼이다.
- 지금 모드와 같은 것을 고르면 `적용` 을 누를 수 없다.
- 적용하는 동안은 `적용` 버튼 안에 스피너가 돌고(`busy`), 옵션 · `취소` 와 바깥 영역 누르기로 닫기가 모두 막힌다.
  시드가 끝나야 닫힌다.
- `setMode` 가 실패하면 스피너를 멈추고 모달을 닫은 뒤 `컨텐츠를 불러오지 못한 캐릭터가 있습니다` 토스트를 띄운다
  (사용자 지정 2026-11-05). 모드는 수동 그대로다. `setMode` 가 시드보다 먼저 모드를 저장하고, 채운 캐릭터는 수동으로
  쓸 수 있기 때문이다. 아래 다시 읽기도 성공했을 때처럼 한다. 토스트를 닫은 뒤에 띄우는 것은 모달이 열려 있으면
  토스트가 모달 뒤에 가려서다.
- 적용이 끝나면 `reloadTabStores(['content', 'boss'])` 가 만료된 회차를 한 번 미리 받고(`prefetchSchedules`), 컨텐츠 ·
  보스 스케줄러 스토어의 `reloadLocal` 로 기기 값(수동 추적 목록 `manualTrackedByOcid` · 직접 완료)을 다시 읽힌다.
  수동 모드에서 어떤 항목을 보일지는 저장소가 아니라 스토어 메모리의 추적 목록으로 정하는데, 탭 화면은 띄워진 채
  남아 있어 스스로 다시 읽지 않으므로, 이렇게 하지 않으면 수동으로 바꾼 직후 빈 추적 목록이 보인다. 시드가 끝난
  뒤에 다시 읽어야 옛 목록을 읽지 않는다.
  - 회차는 한 번만 미리 받는다. 두 스토어가 같은 회차 쿼리를 보고([[ADR-142]] 결정 3), 둘 다 부르면 첫 회차가
    실패했을 때 두 번째가 다시 나간다. 수동으로 바꾼 경우는 시드가 방금 동기화를 돌려서 대개 회차가 신선해 조회하지
    않는다. 보스 수익은 회차와 기록 판에 매인 쿼리라 여기서 할 일이 없다.
  - 다시 읽기를 기다리지 않고 모달을 닫는다. 실패해도 알리지 않는다. 그 탭에 들어가면 화면이 다시 조회하고, 그때
    실패하면 그 화면의 실패 처리가 돈다.

옵션 문구는 `features/tracking-mode/copy.ts` 한 곳에 있다. 어느 모드도 추천으로 표시하지 않는다. 옵션마다 아이콘
(자동 `Gamepad2`, 수동 `ListChecks`)과 제목 · 설명이 있고, 그 모드의 한계는 정보 색 상자(`bg-info-tint`)에 따로
적는다. 사용자가 고칠 수 없는 제약이라 오류 색을 쓰지 않는다. 고르기 전에 둘을 견줘 봐야 하므로 설명과
한계는 접지 않는다.

| 모드 | 제목 | 설명 | 한계 |
|---|---|---|---|
| 자동 | 자동 | 게임 내 스케줄러에 등록한 컨텐츠가 그대로 반영돼요. | API 응답에 따라 컨텐츠가 표시되지 않을 수 있어요. |
| 수동 | 수동 | 직접 컨텐츠를 선택하고 관리해요. | 게임 내에 스케줄러를 추가하더라도 앱에는 자동으로 추가되지 않아요. |

### 결정 10. 두 관리 화면은 아래 `저장` 을 눌러야 저장한다

컨텐츠 관리와 보스 관리는 누를 때마다 바로 저장했다. 저장할 때마다 기록을 썼다는 알림(`noteRecordsWritten`)이 서버
동기화를 깨워서(`features/server-sync/after-write.ts` → `kickServerSync`), 몇 번 누르면 그만큼 API 호출과 동기화가
이어졌다. 그래서 바꾼 것을 모아 두었다가 한 번에 저장한다(사용자 선택 2026-11-24, #1211).

사용자가 정한 것은 넷이다.

1. 컨텐츠 관리와 보스 관리 둘 다 저장 버튼을 둔다.
2. 화면 아래에 `저장` 하나를 둔다. 캐릭터 설정 화면의 `계속하기` 와 같은 버튼이다. 바꾼 것이 있을 때만 누를 수 있다.
   누르면 바꾼 것을 한 번에 저장하고, 서버 동기화도 한 번만 돈다.
3. 저장하지 않고 나갈 때와 화면의 캐릭터를 다른 캐릭터로 바꿀 때 확인 창을 띄운다. 제목은 `저장하지 않은 변경이 있어요`,
   본문은 `바꾼 내용을 저장할까요?`, 버튼은 `버리기` · `저장` 이다.
4. 보스 관리의 파티 설정(파티 인원 · 분배)도 `저장` 으로 모은다. 파티 모달의 `적용` 은 초안에 넣기만 한다([[ADR-036]]
   결정 14 · [[ADR-038]] 결정 4).

아래는 사용자가 정하지 않은 세부라 Claude 가 정했다(2026-11-24). 이유를 함께 적는다. 새 문구는 위 확인 창의 문구 말고는 없다.

**부품.** 새 생김새를 만들지 않는다.

- `저장` 은 캐릭터 관리의 저장 바와 같다. 화면 아래에 고정한 `SettingsActionBar` 안에 전체 폭 `Button` `primary` 를
  둔다([[ADR-029]] 결정 8). 캐릭터 설정의 `계속하기` 가 서는 `EntryScroll` 의 고정 바와 같은 한 벌이다. 누를 수 없으면
  `opacity-50` 이고, 저장하는 동안은 `busy` 로 버튼 안에 스피너가 돈다. 바 높이는 재서 그만큼 목록 아래를 비운다. 글자는
  역할표의 주 버튼(`text-base font-bold`)이다. 화면에 고정되는 것은 이 바 하나이고, 화면 아래 액션 바만 고정하는 예외에
  든다([[ADR-063]] 결정 1).
- 확인 창은 `NoticeModal` 이다. `icon` 을 비워 배지 없이 제목과 설명(`description`)만 세운다. 사용자가 아이콘을 정하지
  않았고, 시킨 것만 넣는다는 디자인 원칙을 따른다. 큰 버튼(`action`)이 `저장`, 그 아래 글자 버튼(`secondaryAction`)이
  `버리기` 다. 바꾼 것을 지키는 쪽이 안전한 기본값이라 큰 버튼에 둔다. `버리기` 는 되돌릴 수 없는 동작이라 `danger` 로
  글자만 `error-ink` 로 칠한다([[ADR-062]] 결정 8). 글자는 모두 그 부품이 정한 역할표 값이다. 제목은 `text-base font-bold`,
  설명은 `text-xs`, 글자 버튼은 `text-xs font-semibold` 다.

**나가는 경우.** 이 화면을 스택에서 빼는 이동은 모두 나가는 것으로 본다.

- `←`, iOS 가장자리 스와이프, 안드로이드 뒤로 가기, 조회 불가 안내의 캐릭터 관리 버튼(`useOpenTab` 이 이 화면을 빼고
  탭을 연다), 자동 모드가 되어 컨텐츠 관리가 스스로 뒤로 가는 것(결정 7)이 여기에 든다. 모드는 서버 동기화가 다른 기기의
  값을 받아 바꿀 수 있다.
- 바꾼 것이 있는 동안 React Navigation 의 `usePreventRemove` 로 이 빼기를 한 곳에서 막고 확인 창을 띄운다. 이동마다 따로
  막으면 새 이동이 생길 때 빠진다. native-stack 은 이 훅이 켜져 있으면 iOS 스와이프도 멈추고 같은 처리를 부른다
  (`preventNativeDismiss`). 두 화면이 같은 훅(`useUnsavedChangesGuard`)으로 막고 같은 창을 띄운다.
- 하단바의 탭 바꾸기는 생기지 않는다. 두 화면은 루트 스택의 하위 페이지라, 열리면 하단바가 아래 화면과 함께 밀려
  나간다(`docs/foundation/navigation.md`).
- 앱을 닫는 것은 막지 않는다. 배경으로 가면 화면과 초안이 메모리에 남아, 돌아와서 이어 고친다. OS 가 앱을 끝내거나 OTA
  로 다시 읽으면 초안은 사라진다. 끝나는 순간에는 창을 띄울 수 없다. 배경으로 갈 때 저장하면 누르지 않은 저장과 동기화가
  다시 생기고, 초안을 기기에 적어 두려면 저장소가 하나 더 필요하다.

**확인 창의 버튼.**

- `저장` 은 아래 `저장` 과 같은 저장을 한다. 끝나면 막아 둔 이동(나가기 · 캐릭터 바꾸기)을 잇는다. 저장하는 동안 `저장`
  안에 스피너가 돌고 두 버튼을 누를 수 없다.
- 그 저장이 실패하면 창을 닫고 실패 토스트를 띄운 뒤 그 화면과 그 캐릭터에 남는다. 실패한 채 이동하면 바꾼 것이 말없이
  사라진다. 창을 먼저 닫는 것은 창이 열려 있으면 토스트가 그 뒤에 가리기 때문이다(결정 9 와 같다).
- `버리기` 는 초안을 버리고 막아 둔 이동을 잇는다.
- 바깥을 누르거나 창이 떠 있는 동안 안드로이드 뒤로 가기를 누르면(`onClose`) 창만 닫는다. 화면 · 캐릭터 · 초안은
  그대로다. 두 버튼 중 아무것도 고르지 않았으니 아무것도 하지 않는 쪽이 안전하다.

**캐릭터 바꾸기.** 레일에서 다른 캐릭터를 누를 때 바꾼 것이 있으면, 고른 캐릭터를 바꾸기(`select`) 전에 확인 창을 띄운다.
바꾼 것이 없으면 지금처럼 바로 바꾼다. 고른 캐릭터는 앱 전체가 함께 쓰므로([[ADR-030]]), 답을 받기 전에 바꾸면
스케줄러까지 다른 캐릭터로 넘어간다.

**초안.**

- 초안은 화면의 상태(`useState`)로 둔다. 스토어와 기기 저장소에는 두지 않는다. 이 화면만 읽고, 스케줄러와 today 는
  저장된 값만 그려야 하기 때문이다. 화면을 나가면 함께 사라지는 것도 `버리기` 의 뜻과 맞다.
- 초안에는 바꾼 항목만 든다. 컨텐츠는 `kind` 와 컨텐츠 key 마다 추적 여부, 보스는 보스 key 마다 추적 난이도 또는 추적
  안 함, 파티는 보스 · 난이도마다 인원과 분배다. 화면은 저장된 값 위에 초안을 얹어 그린다. 관리 화면을 연 동안에도 받기가
  저장된 목록을 바꿀 수 있어서다(결정 3). 목록 전체를 복사해 두면 사용자가 만지지 않은 항목까지 옛 값으로 덮게 된다.
- 저장된 값과 같아진 항목은 바꾼 것으로 치지 않는다. 켰다가 다시 끄면 `저장` 도 다시 꺼진다. 캐릭터 관리의 저장 버튼과
  같은 규칙이다([[ADR-029]] 결정 8).
- 초안은 주인 캐릭터(ocid)를 함께 든다. 고른 캐릭터가 주인과 다르면 초안을 쓰지 않는다. 받기가 추적 캐릭터를 바꿔 고른
  캐릭터가 다른 캐릭터로 넘어가도, 앞 캐릭터의 초안이 새 캐릭터의 행에 얹히지 않는다. 자동 모드 보스 관리의 난이도
  편집(`difficultyEdit`)과 같은 방법이다([[ADR-038]] 결정 11).
- 컨텐츠 관리에서 일일 · 주간 탭을 바꿔도 초안은 남는다. 탭은 같은 캐릭터의 목록을 나눠 보여 줄 뿐이다.

**저장.**

- 저장은 화면마다 `features/` 스토어의 저장 함수 하나가 한다. 그 함수는 쓰기 전부를 `batchRecordWrites` 로 감싼다. 안에서
  난 쓰기 알림은 감싼 일이 끝날 때 한 번만 나가므로(`notifyAfterBatch`), 동기화를 깨우는 것도 한 번이다. 감싸지 않으면 첫
  쓰기의 알림이 동기화를 시작하고, 도는 동안 난 다음 알림이 끝난 뒤 한 번 더 돌린다(`features/server-sync/kick.ts`).
- 추적 목록은 저장소의 지금 배열을 읽어 초안을 얹고 `setManualTrackedContent` 한 번으로 쓴다. 지금의 추가 · 삭제 함수처럼
  읽기 → 계산 → 쓰기 한 번이다. 그래서 받은 항목을 덮지 않고, 쓰는 사이에 항목이 빠진 상태가 저장되지 않는다.
- 저장 함수(`saveManualContentDraft` · `saveBossManageDraft`)도 예전의 추가 함수처럼 주간 보스 한도([[ADR-037]] 결정 7)와
  길드 잠금([[ADR-033]] 결정 8)을 확인한다. 막는 곳은 스토어라는 규칙을 따른다.
- 길드 잠금에 걸린 컨텐츠는 켜지 않고 나머지만 저장한다. 화면은 잠긴 행을 누를 수 없게 하므로, 화면을 연 동안 받은 기본
  정보가 미가입으로 바뀐 경우에만 생긴다. 켜지 않은 항목도 저장한 것과 함께 초안에서 빠진다. 그러면 그 행이 꺼진 채
  `길드 가입 시 진행 가능` 을 덮어 보여 왜 켜지지 않았는지 보인다.
- 화면은 저장된 값에 초안을 얹어 그리고, 저장 함수는 저장소의 지금 배열에 같은 함수(`manage-draft.ts`)로 초안을 얹어 쓴다.
  두 곳이 같은 함수를 써야 화면에 보인 목록이 그대로 저장된다.
- 저장한 항목은 초안에서 뺀다. 남겨 두면 나중에 받은 값이 그 항목을 바꿨을 때 옛 초안이 바꾼 것으로 다시 잡힌다.

**실패.** 추적 목록을 쓰지 못하면 지금 문구 `추적 목록을 저장하지 못했습니다` 토스트를 띄운다([[ADR-022]] 결정 7). 초안은
남고 `저장` 을 다시 누를 수 있다. 다시 시도 버튼은 두지 않는다. 바꾼 행이 화면에 그대로 있어 무엇이 저장되지 않았는지
보인다. 보스 관리의 파티 설정 실패는 [[ADR-036]] 결정 14 에 있다.

**저장 뒤.** 성공을 알리는 문구는 없다. `저장` 이 누를 수 없는 상태로 돌아가는 것으로 끝나고, 화면에 남는다. 레일로 다른
캐릭터를 이어서 고치는 화면이기 때문이다.
