# ADR-308: 온보딩은 뒤로 갈 수 있는 한 스택이고, MVP 등급 선택은 캐릭터 설정 다음 화면이다

> 🟢 유효 · 2026-09-22 · 구현 완료(2026-09-23, 브랜치 `feat/mvp-grade`, 실기기 미검증) · 사용자 지정 · 시안 https://claude.ai/artifact/EmnT9Fk5j5nvEa2iooGGik (11번째 줄, 온보딩 가)

> 사용자 지정(2026-09-22): 최초 사용자는 **온보딩 단계에서** MVP 등급을 고르고, 기존 사용자는 업데이트 뒤 모달로 고른다(처음 요청).
> 온보딩은 지금까지 화면으로 진행했으니 MVP 등급도 화면이어야 한다. API 키 입력 이후의 화면은 전부 뒤로 갈 수 있어야 하고,
> 기기 뒤로가기(안드로이드 뒤로 버튼 · iOS 밀어서 뒤로)가 되어야 하며, 헤더에 다른 페이지와 같은 뒤로가기 버튼이 선다.

**관련**: [[ADR-306]](결정 11 의 온보딩 부분을 이 문서가 뒤집는다) · [[ADR-215]](결정 2 · 3 의 진입 단계와 화면 목록을 이 문서가 바꾼다)

## 맥락

[[ADR-306]] 결정 11 은 온보딩 · 기존 사용자 · 새 메이플 ID 를 규칙 하나로 덮으며 **진입 단계를 늘리지 않았다**. 그래서 온보딩에서도
캐릭터 설정의 `계속하기` 로 앱이 열린 뒤 today 위에 모달이 떴다. 처음 요청은 온보딩과 기존 사용자를 나눴는데, 설계가 그 구분을 묻지
않고 합쳤다.

온보딩 화면은 뒤로 갈 수 없었다. [[ADR-215]] 결정 3 이 `EntryStage` 로 화면 목록을 통째로 갈아 끼워, 로그인과 캐릭터 설정이 한 스택에
함께 서지 않는다(`RootNavigator` 주석: 둘을 나란히 두면 되돌아갈 곳이 없다).

## 결정

### 결정 1. 온보딩 화면 넷이 한 스택에 쌓인다 (사용자 지정)

앱이 열리기 전(`EntryStage` 가 `ready` 가 아닐 때) 루트 스택에 **로그인 · 캐릭터 설정 · MVP 등급 고르기 · MVP 등급 확인** 넷을 함께
등록한다. 앞으로 가는 것은 화면을 밀고(push), 뒤로 가는 것은 빼낸다(pop). 그래서 **기기 뒤로가기**(안드로이드 뒤로 버튼 · iOS 밀어서
뒤로)가 하위 페이지와 같이 된다. 로그인 화면이 맨 아래라 거기서 안드로이드 뒤로 버튼은 앱을 내린다.

- **API 키 입력 이후 화면은 전부 뒤로 간다**(사용자 지정). 캐릭터 설정 → 로그인, MVP 고르기 → 캐릭터 설정, MVP 확인 → MVP 고르기.
- **앱을 다시 켰을 때도 같은 스택이다.** 저장된 값이 캐릭터 설정 단계면 스택은 `로그인 · 캐릭터 설정`, MVP 단계면
  `로그인 · 캐릭터 설정 · MVP 고르기` 로 선다. 부팅 때 한 번 이 스택으로 다시 놓는다(스플래시가 덮고 있어 안 보인다).
- **앞으로 가는 것은 화면이 한다.** 로그인이 성공하면 로그인 화면이, `계속하기` 가 끝나면 캐릭터 설정 화면이 다음 화면을 민다.
  진입 단계는 **어디까지 끝냈는가**만 들고 화면을 고르지 않는다. 뒤로 갔다가 다시 앞으로 가도 단계 값이 안 바뀌어서, 단계가 바뀌길
  기다리면 앞으로 못 간다.
- `ready` 가 되면 지금처럼 탭과 하위 페이지로 통째로 바뀐다. 앱이 열린 뒤 온보딩으로 뒤로 가지 않는다.

### 결정 2. 헤더에는 뒤로가기 버튼만 선다 (사용자 결정)

캐릭터 설정 · MVP 고르기 · MVP 확인 화면의 머리 줄에 다른 하위 페이지와 같은 뒤로가기 버튼(`BackButton`)이 선다. 제목과 설명은 지금처럼
본문의 큰 글자로 둔다. 로그인 화면에는 없다(첫 화면이라 돌아갈 곳이 없다).

### 결정 3. 로그인 화면으로 돌아가면 저장된 키가 입력칸에 채워져 있다 (사용자 결정)

그대로 `확인` 을 누르면 다시 넘어가고, 다른 키로 바꿀 수도 있다. 앱을 다시 켜 스택이 `로그인 · 캐릭터 설정` 으로 선 경우에도 로그인
화면이 저장된 키를 읽어 채운다.

### 결정 4. MVP 등급 선택은 캐릭터 설정 다음의 온보딩 화면 둘이다 (사용자 결정, 시안 온보딩 가)

진입 단계에 `mvpGrade` 를 더한다(`signIn → characterSetup → mvpGrade → ready`). [[ADR-306]] 결정 11 의 `진입 단계는 늘리지 않는다` 를
뒤집는다.

- **고르기 화면**: 제목 `MVP 등급을 알려주세요` · 설명(모달과 같은 문구) · 메이플 ID 마다 모달의 ID 카드(시안 C) · 바닥 줄 `다음`.
- **확인 화면**: 제목 `이 등급이 맞나요?` · 설명 · 확인-나 카드 · `앞으로 등급은 직접 바꿀게요` 체크박스 · 바닥 줄 **`시작하기`**.
  **`수정` 이 없다**(사용자 지정). 고르기로 돌아가는 길은 뒤로가기다.
- `시작하기` 는 모달의 `맞아요` 와 같이 이력을 적고 자동 수수료를 다시 세는 작업을 돌린 뒤 앱을 연다.
- **묻는 조건은 모달과 같다.** 캐릭터 설정을 마쳤을 때 추적 캐릭터가 속한 메이플 ID 가운데 등급 이력이 없는 것이 있으면 이 화면으로 간다.
  다 있으면(캐시를 지운 뒤 다시 온보딩하는 경우) 곧장 앱을 연다.
- 모달은 **기존 사용자의 업데이트 뒤 1회 · 새 메이플 ID · 주간 확인**에만 남는다.

### 결정 5. MVP 화면에서 앱이 꺼지면 다시 켤 때 그 화면부터다 (사용자 결정)

캐릭터 설정을 마치고 MVP 화면으로 갈 때 preferences `mvpOnboardingPending` 을 적고, `시작하기` 가 끝나면 지운다. 부팅이 이 표시를 보고
진입 단계를 `mvpGrade` 로 둔다.

진입 단계는 원래 **진행 상태 전용 키를 두지 않는다**(`features/app-entry/stage.ts`, 각 단계의 산출물이 이미 영속화돼 있어서다). MVP 단계는
예외다. 산출물(등급 이력)이 없는 것만으로는 **온보딩 중인 사용자**와 **업데이트한 기존 사용자**를 가를 수 없어서다. 표시가 없으면 기존
사용자로 보고 today 위 모달로 묻는다.

## 구현 (2026-09-23)

| 자리 | 파일 |
|---|---|
| 진입 단계 | `features/app-entry/stage.ts`(`mvpGrade`) · `features/app-entry/store.ts`(`resumeTo` · `consumeResume` · `finishMvpOnboarding`, `completeCharacterSetup` 이 다음 단계를 돌려준다) |
| 표시 | `storage/mvp-grade-prefs.ts` 의 `getMvpOnboardingPending` · `setMvpOnboardingPending`(키 `mvpOnboardingPending`) |
| 묻는 조건 | `features/mvp-grade/onboarding.ts` 의 `needsMvpOnboarding` |
| 스택 | `navigation/RootNavigator.tsx`(`ready` 가 아니면 온보딩 화면 넷을 한 그룹으로 등록) · 라우트 `MvpGradePick` · `MvpGradeConfirm`(`navigation/routes.ts`) |
| 앞으로 가기 | `app/auth/SignInScreen.tsx`(로그인 성공 뒤 `CharacterSetup`, 부팅 때 `resumeTo` 까지 다시 쌓기) · `app/character-setup/CharacterSetupScreen.tsx`(`mvpGrade` 면 `MvpGradePick`) |
| 머리 줄 | `components/templates/EntryScroll` 의 `onBack`. 하위 페이지와 같은 `PageHeader` · `BackButton` 이다 |
| 저장된 키 | `features/auth/saved-key.ts` 의 `loadSavedApiKey` · `ApiKeyForm` 의 `initialApiKey` |
| MVP 화면 | `app/mvp-grade/MvpGradeOnboarding.tsx`(`MvpGradePickScreen` · `MvpGradeConfirmScreen`) · 고른 값 `features/mvp-grade/onboarding-draft.ts` · 카드는 모달과 같은 `app/mvp-grade/MvpGradeCards.tsx` |

- `auth` 스토어의 `signIn` 은 앞으로 갈 수 있으면 `true` 를 돌려준다. 실패하면 로그인 화면이 아무것도 안 민다.
- 로그인으로 돌아가 다시 들어오면 캐릭터 설정까지만 민다. MVP 화면은 캐릭터 설정의 `계속하기` 가 다시 민다.
- 캐릭터 설정을 마쳤는데 물을 ID 가 없으면 `mvpOnboardingPending` 을 지운다. MVP 화면에서 로그인까지 되돌아가 다른 캐릭터를 고른
  경우에 앞서 적은 표시가 남아, 다음 부팅이 열린 앱 대신 MVP 화면을 세우지 않게 하려는 것이다.
- 시드 대기 중에도 기기 뒤로가기는 막지 않는다. 다른 하위 페이지의 저장 대기와 같다.

## 대가

- 온보딩 화면 넷이 늘 함께 등록된다. 앱이 열리기 전에는 무엇이 스택에 있는지를 진입 단계가 아니라 화면 이동이 정한다.
- 진입 단계에 전용 키 하나가 생긴다(결정 5).
- 로그인 화면으로 돌아가 다른 키로 로그인하면 그 키의 캐릭터로 캐릭터 설정을 다시 한다([[ADR-215]] 의 가드 그대로).
