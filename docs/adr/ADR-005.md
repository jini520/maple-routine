# ADR-005: 사냥 타이머는 상시 표시 알림 + 주기적 사운드로 구현 (폐기 · DEPRECATED)

> ⛔ **DEPRECATED — 폐기.** 사냥 타이머 계획을 접었다(2026-08-30, 사용자 결정). 이 결정은 3년간
> **한 줄도 구현되지 않았고**(Android Foreground Service·iOS Live Activity 커스텀 플러그인 0건,
> 소비자 0건), 남아 있던 포트·어댑터·웹 폴백도 함께 지웠다.
> **새 구현의 근거로 인용하지 말 것.** 본문은 아래 요약으로 줄였다 — 죽은 정책이 컨텍스트에
> 실리지 않게 하기 위해서다.
>
> 🔗 **지금도 코드가 따르는 것** — **`native/` 어댑터 경계 하나뿐이다**(«`features/*` 는 네이티브 API 를 직접 만지지 않고 어댑터를 거친다»). 이 결정이 그 레이어를 처음 세웠고, CLAUDE.md 의 CRITICAL 규칙과 `native/ports.ts`·`storage/ports.ts`·`native/ads.ts`·`hooks/useKeyboardVisible.ts`·`features/cashbook/records.ts`·`features/cashbook/meso-rate.ts`·`features/settings/cache-data.ts` 가 [[ADR-003]] 과 짝지어 지금도 인용한다([[ADR-128]] 은 이 경계를 RN 전환을 가능하게 만든 원인으로 적었다). **타이머 쪽 결정은 전부 죽었다.**

## 무엇을 결정했었나 (요약)

30분 카운트다운 동안 «네이티브 타이머 앱처럼» 경과 시간이 표시되는 **상시 알림**을 띄우고 지정 주기마다 알림음을 재생하기로 했다. 플랫폼별로 **Android** 는 Foreground Service + `Notification.Builder.setUsesChronometer(true)`, **iOS** 는 Live Activity(ActivityKit, 16.1+)로 가르고, 기성 플러그인이 없으니 Swift/Kotlin **커스텀 네이티브 모듈**을 직접 써서 `native/hunting-timer` 포트 뒤로 노출하기로 했다.

## 왜 접었나

**설계만 있고 구현이 없는 채로 3년을 버텼다.** 저장소 전체에서 `HuntingTimer` 를 담은 `.java`/`.kt`/`.swift` 가 0건이었고, 상시 알림도 주기 사운드도 `soundIntervalMinutes` 를 소비하는 코드도 존재한 적이 없다. 화면(`app/hunting-timer/`)도 상태(`features/hunting-timer/`)도 디렉터리 자체가 없었다. 남아 있던 것은 **호출하면 거부하는 어댑터**(`rn-hunting-timer.ts`)와 브라우저에서만 도는 인메모리 폴백뿐이라, 되살릴 때 필요한 것은 그 파일들이 아니라 **결정** 이었다 — 그 결정을 접는 쪽으로 냈다.
