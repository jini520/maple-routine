### ADR-047: 보스 수익 — 펼친 캐릭터 카드의 헤더(초상화·이름·총액)를 sticky로 고정 (구현 완료, 2026-07-28)

**배경**: 캐릭터 카드를 펼치면 보스 행이 길게 늘어나(주간 최대 10+행, 월간은 주차별 합계+월간 보스) 스크롤하는 동안 **지금 보고 있는 행이 누구 것인지** 사라진다. 펼친 카드의 헤더(아바타 + 캐릭터명 + 총액)를 카드 범위 안에서 상단에 고정해 달라는 사용자 요청. 헤더는 이미 펼침/접힘 셸이 분리돼 있어([[ADR-023]]) 펼침 상태에만 sticky를 걸 수 있다.

**결정**:
1. **펼침 헤더만 sticky**: 펼쳤을 때 헤더 버튼에 `sticky` + 오프셋 + `bg-surface`를 준다. 접힘 상태는 단독 카드라 고정할 대상이 없어 그대로.
2. **펼침 셸의 `overflow-hidden` 제거** — [[ADR-023]]의 펼침 셸 결정 중 이 속성만 반전. `overflow: hidden` 조상은 **스크롤포트를 만들어 sticky를 무력화**한다(sticky는 가장 가까운 스크롤 조상 기준으로 붙고, 그 조상이 스크롤되지 않으면 고정이 일어나지 않는다). 원래 `overflow-hidden`이 맡던 **하단 모서리 클리핑은 `AccordionFooter`에 `rounded-b-[14px]`** 로 대체한다(footer만 `bg-surface-2`로 셸 모서리에 닿는 유일한 요소 — 보스 행·서브섹션 라벨은 카드 중간이라 무관).
3. **sticky 오프셋 = 페이지 sticky 헤더의 실측 높이**: 이 화면의 스크롤 컨테이너는 문서 전체이고 페이지 헤더가 `sticky top-0 z-10 bg-bg`로 **불투명하게** 덮으므로, 카드 헤더를 `top-0`으로 두면 페이지 헤더 뒤에 가려 보이지 않는다. 헤더 높이는 상태에 따라 가변이라(주간/월간 탭·기간 라벨·동기화 실패 경고·에러 문구·총 수익 헤드라인 유무) 상수로 둘 수 없어 **`ResizeObserver`로 실측**해 `CharacterAccordion`에 내려주고 인라인 `style={{ top }}`으로 적용한다. 프로젝트 첫 중첩 sticky 사례 — 기존 sticky는 모두 페이지 헤더(`top-0`)나 시트 푸터(`bottom-0`)였다.
4. **z-index 층 정리(카드 `isolate` 안)** — `드롭 아이콘 1~3 < sticky 헤더 5 < 골드 회전 샤인 링 6 < 고가 드롭 배지 10`:
   - 헤더 `z-[5]` — 보스 행 드롭 아이콘 스택이 `relative` + 인라인 `zIndex: 1~3`이라 z-index 없이는 **아이콘이 sticky 헤더를 뚫고 비친다**.
   - `.valuable-drop-card::before`(골드 링)를 `z-index: 0 → 6`으로 올린다. 헤더가 sticky가 되며 불투명 `bg-surface`를 갖게 돼, 링이 헤더보다 낮으면 **테두리 상단·좌우 2px가 헤더 배경에 덮여 끊겨 보인다**([[ADR-045]] 결정 4 "펼침에도 회전 샤인 유지"가 깨진다). 테두리는 콘텐츠 위에 그려야 맞다. 접힘 상태에선 이미 링이 헤더 배경 위였으므로(비positioned 배경 → positioned 링 순서) 접힘/펼침 동작이 이로써 일치한다.
   - 배지(`z-10`, [[ADR-045]])는 그대로 최상단.
   - [[ADR-045]]의 `isolate` 덕에 이 값들은 카드 안에 갇혀 페이지 헤더·하단 nav와 경쟁하지 않는다.
5. **헤더에 `bg-surface` 명시**: 기존 펼침 헤더는 배경 없이 셸의 `bg-surface`를 노출했다. sticky가 되면 그 아래로 보스 행이 지나가므로 자기 배경이 없으면 내용이 겹쳐 보인다.
6. **헤더-목록 경계 페이드 오버레이를 이 화면에서 제거**(공용 레시피 미사용): 페이드는 페이지 헤더(`z-10`) 안의 `absolute top-full h-8` 오버레이로, 헤더 바로 아래 32px 밴드를 `bg-bg`로 덮는다. 그런데 stuck된 캐릭터 헤더가 멈추는 위치가 **정확히 그 밴드**(`top` = 페이지 헤더 높이)이고, 카드는 [[ADR-045]]의 `isolate`로 `z-10`보다 아래라 **페이드가 stuck 헤더 상단을 덮어 흐리게 가린다**. 블러(`backdrop-blur-sm`)를 먼저 뺐지만 색 그라데이션만으로도 같은 가림이 남아 오버레이 자체를 없앤다(사용자 확인). 경계는 [[ADR-046]] 총 수익 헤드라인 하단의 `h-px bg-border` 헤어라인이 대신한다 — 페이드(부드러운 소멸)보다 선명한 선이지만, 중첩 sticky 구조에서는 경계가 또렷한 편이 오히려 2단 헤더를 읽기 쉽다.

**이유**: 스크롤 중 컨텍스트(누구의 수익인지) 유지가 목적이고, 헤더에는 이미 캐릭터 총액이 있어 고정 시 "그 캐릭터 합계"를 계속 볼 수 있다는 부수 이점이 있다. 페이지 헤더 아래에 딱 붙게 두면 헤더 2단(전역 요약 + 캐릭터) 구조가 자연히 만들어진다.

**트레이드오프**:
- **여러 카드 동시 펼침**: 각 헤더는 자기 카드(containing block) 안에서만 고정되므로, 스크롤하면 카드1 헤더가 카드1 바닥과 함께 밀려 올라가고 카드2 헤더가 같은 자리를 이어받는다(그룹 헤더 스택의 자연스러운 동작). 별도 처리 없음.
- **`ResizeObserver` 폴백**: 미지원 환경에선 측정값이 0으로 남아 `top: 0` = 페이지 헤더 뒤에 가려진다(고정 자체는 동작). 실사용 대상(Android Chromium WebView·iOS 13.4+)은 모두 지원하고, 테스트 환경엔 이미 no-op 폴리필이 있다(`vitest.setup.ts`).
- **모서리 클리핑 안전망 상실**: `overflow-hidden`을 뺐으므로 앞으로 셸 하단에 닿는 배경 요소를 추가하면 각진 모서리가 드러난다. 현재는 footer 하나뿐이고 `rounded-b-[14px]`로 처리 — 회귀 가드 테스트를 둔다.
- **미verify**: 실제 스크롤 감각(페이지 헤더 아래 정확히 붙는지, 카드 전환 시 이어받는 모양)은 실 데이터가 필요해 육안 확인이 남아 있다([[ADR-046]]과 동일 제약).

**저장소**: 변경 없음(순수 표시 계층).

**후속(2026-07-28) — stuck 헤더 하단 경계 페이드 + 배지 동반 고정**(사용자 요청):
1. **경계 페이드가 페이지 헤더 → 카드 헤더로 이동**: 결정 6에서 페이지 헤더의 페이드를 없앴는데, 중첩 sticky 구조에선 **콘텐츠가 지나가는 경계가 카드 헤더 아래로 옮겨졌다**. 그래서 같은 레시피(`bg-gradient-to-b` + `backdrop-blur-sm` + mask)를 stuck 헤더 하단에 붙인다 — 배경색만 카드 표면에 맞춰 `from-surface`. 헤더 버튼 안에 `absolute inset-x-0 top-full h-8` **`<span>`**(버튼 자식은 phrasing content여야 하므로 div 불가)으로 넣어 헤더와 함께 움직이게 한다. 헤더가 `z-[5]` 스택 컨텍스트라 페이드도 그 안에 들어가 보스 행(`zIndex 1~3`) 위에 그려지고, 골드 링(`z-6`)보다는 아래라 테두리를 가리지 않는다.
   - **한계**: CSS로는 stuck 여부를 알 수 없어 **평상시에도 페이드가 존재**한다(첫 보스 행 상단이 약간 흐려짐). 페이지 헤더 페이드도 같은 성질이었다. 거슬리면 sentinel + `IntersectionObserver`로 stuck 상태를 감지해 켜고 끄는 방식으로 바꿀 수 있다.
2. **고가 드롭 배지도 헤더와 함께 고정 — 단 펼침 상태에만**: 배지를 헤더 **안**에 넣으면 헤더의 `z-[5]` 컨텍스트에 갇혀 골드 링(`z-6`)이 배지 위를 지나간다(배지는 카드 우상단 모서리 = 링 위치라 정확히 겹친다). 그래서 배지는 셸 **바깥**(카드 `isolate` 직속, `z-10`)에 남기고, **높이 0 sticky 레일**(`sticky z-10 h-0`)에 얹어 헤더와 같은 오프셋으로 고정한다. `h-0` + 자식은 `absolute`라 레이아웃엔 영향이 없다. 레일의 `top`은 `stickyTop + 8`(배지의 `-top-2` 만큼) — 그래야 stuck 시 `-8px`로 올라간 배지가 헤더 상단선에 정확히 걸리고, 페이지 헤더 뒤로 숨지 않는다. 평상시엔 레일이 자연 위치(카드 최상단)라 배지 위치가 기존과 동일하다.
   - **레일의 고정 범위를 헤더와 일치시킨다**(시안 B 채택, 브라우저 프리뷰로 4안 비교 후 사용자 확정): sticky는 containing block 아래 끝에서 밀려 올라가는데, 레일은 **높이 0**이라 카드 맨 아래까지 붙어 있고 헤더는 **자기 높이(~64px)만큼 일찍** 떨어진다. 그래서 카드 끝부분에서 헤더만 올라가고 **배지가 남아 어긋난다**. 레일을 `absolute inset-x-0 top-0` + `bottom = 헤더 높이`인 제약 박스 안에 넣어 범위를 헤더와 맞춘다 — `absolute`라 레이아웃 영향이 없고 배지 모양·위치는 그대로다. 헤더 높이는 시스템 글꼴 확대 시 달라질 수 있어 **`ResizeObserver`로 실측**한다(상수 64px는 프리뷰용). 제약 박스는 `pointer-events-none`, 배지만 `pointer-events-auto`로 되살린다.
   - **접힘 상태에서는 레일을 쓰지 않는다**(사용자 요청): 접힌 카드의 containing block은 헤더 높이(~56px)뿐이라 그 짧은 구간에서 배지만 떠서 카드와 어긋나 보인다. 고정할 헤더도 없으므로 접힘일 때는 [[ADR-045]]의 원래 구조(`absolute -right-1.5 -top-2 z-10`, 기준은 카드 wrapper)를 그대로 쓴다. `z-10`은 상태마다 위치가 다르다 — 펼침은 **레일**이(sticky는 z-index 없이도 스택 컨텍스트를 만들므로 레일에 `z-10`이 있어야 골드 링 `z-6` 위로 간다), 접힘은 **배지 자신**이 가진다(레일이 없어 정적 요소엔 z-index가 먹지 않는다).
