### ADR-062: 실패 상태 UI 통일 — 공용 `ErrorState`(원인 + 행동), 스탈 배너, 에러 문구 어미 `~습니다` (설계 확정, 2026-07-30)

> 🟡 **PARTIALLY SUPERSEDED — 일부 폐기.** 결정 3의 일부는 [[ADR-114]]·[[ADR-115]] 가 폐기했다.
> 나머지 결정은 유효하다 — 인용 전 본문에서 해당 결정 번호를 확인할 것.

**배경**: 앱이 사용자에게 내보내는 실패·에러 텍스트를 전수 조사했다(2026-07-30). [[ADR-060]]이 빈 상태에서, [[ADR-061]]이 로딩에서 정리한 것과 같은 문제가 **실패**에만 남아 있었다.

- **공용 컴포넌트가 없다.** 로딩은 `LoadingState`, 빈 상태는 `EmptyState`, 조회 불가는 `UnavailableNotice` 가 있는데 실패에만 없다. 그래서 화면마다 `<p className="text-sm text-error">` 한 줄을 각자 갖고 있다(스케줄러 3화면·피커·온보딩 스텝이 서로 복사본).
- **원인을 말하지 않는다.** 피커·온보딩 스텝은 `loadFailed: boolean` 만 내려받아, 401이든 429든 네트워크든 같은 한 문구를 띄운다.
- **행동을 주지 못한다.** 401은 재시도로 절대 풀리지 않는데 "닫고 다시 열어주세요"라고 안내한다. 키를 고치러 갈 경로가 화면에 없다.
- **어미가 섞였다.** 인라인 문구는 `~습니다`, 에러 토스트는 `~어요`. `UnavailableNotice` 는 한 컴포넌트 안에서 제목 `~어요` / 설명 `~습니다` 로 갈렸다.
- **가장 흔한 실패가 무음이다.** 피커는 `getCharacterPickerRoster` 가 네트워크 전에 캐시 stub을 먼저 방출하므로(`schedule-sync.ts:106-130`, [[ADR-017]] 결정 6), 그 뒤 실패해도 `entries.length > 0` 분기가 이겨 `loadFailed` 가 화면에 쓰이지 않는다. 온보딩 예열([[ADR-016]])이 캐시를 채워두는 정상 경로에서는 **이쪽이 기본값**이라, 낡은 목록을 최신처럼 보여주고 사용자가 그대로 저장한다.

**결정**:

1. **공용 `components/ErrorState` 를 신설한다.** 아이콘(`AlertTriangle`) + 제목 + 설명 + 액션 버튼, 중앙 정렬. `LoadingState`·`EmptyState`·`UnavailableNotice` 와 같은 계열로 두어 실패에도 공용 껍데기를 준다.
   - **아이콘을 배지로 감싸지 않는다.** design-system.md "아이콘 절"의 *배경 없이 단독* 규칙을 그대로 따르고 예외를 늘리지 않는다([[ADR-060]]이 빈 상태 배지를 예외로 둔 것과 반대 방향). 그 결과 **배지 유무만으로 빈 상태와 즉시 구분**되므로, 규칙 준수와 상태 구분이 같은 선택으로 해결된다.
   - **`error-tint` 토큰을 새로 만들지 않는다.** 색은 아이콘에만 `error` 를 쓰고 배경은 투명(자리를 감싸는 쪽이 이미 카드)이다. 스탈 배너의 옅은 틴트는 `Toast` 의 error 톤과 같은 `color-mix(in oklab, var(--color-error) 9%, var(--color-surface))` 를 재사용한다 — 4개 테마에 토큰을 추가하는 비용 대비 얻는 게 적다.
   - **자체 카드를 두지 않는다.** 적용처 두 곳이 모두 이미 껍데기 안이다(피커는 모달 카드, 온보딩은 페이지) — [[ADR-061]]이 `LoadingState` 를 이 두 자리에 씌우지 않기로 한 것과 같은 판단이다.
   - **크기 변형(size)을 두지 않는다.** 두 자리가 같은 크기를 쓰므로 지금 필요 없다(사용자 결정 2026-07-30). 카드가 필요하거나 크기가 갈리는 자리가 생기면 그때 추가한다.

2. **원인을 화면까지 전달한다.** 피커·온보딩 스텝의 `loadFailed: boolean` 을 `loadError: ScheduleSyncError | null` 로 바꾸고 `onRetry` 를 함께 받는다. `toScheduleSyncError` 를 export해 호출부가 reject를 종류로 변환한다.

3. **원인별로 문구와 행동이 다르다.** 같은 원인이라도 **자리에 따라 줄 수 있는 행동이 다르다** — 피커는 설정으로 보낼 수 있지만 온보딩 중에는 설정 화면 자체가 없다.

   | 원인 | 제목 | 피커 | 온보딩 |
   |---|---|---|---|
   | `invalidApiKey` | API 키가 유효하지 않습니다 | "설정에서 키를 다시 등록해주세요" + **설정 열기** | "API 키를 다시 확인해주세요" + 다시 시도 |
   | `rateLimited` | 요청이 너무 많습니다 | "잠시 후 다시 시도해주세요" + 다시 시도 | 동일 |
   | `network` | 캐릭터 목록을 불러오지 못했습니다 | "네트워크 연결을 확인해주세요" + 다시 시도 | 동일 |

   429의 재시도 버튼은 **비활성화하지 않는다**(사용자 결정 2026-07-30) — 즉시 누르면 또 429지만, 잠글 시각을 추적하는 상태를 새로 만들 만큼의 이익이 없다.

4. **보여줄 항목이 있는 채로 실패하면 스탈 배너를 얹는다.** `loadError !== null` 일 때 항목 유무로 갈린다 — 없으면 자리 전체에 `ErrorState`, 있으면 목록 위에 한 줄 배너("목록이 최신이 아닙니다" + 다시 시도). 목록을 가리지 않으면서 실패를 숨기지 않는다.

4-1. **본문 자리 높이를 카드 3줄로 못 박는다**(사용자 보고 2026-07-30 후속). `ROSTER_BODY_MIN_H` = `min-h-[385px]`(실측: 카드 123px × 3 + `gap-2` 8px × 2)를 슬롯에 주고, 중앙 정렬 분기(스피너·실패·빈 상태)는 `flex-1` 로 그 높이를 채운다.
   - **이유**: 상태마다 높이가 달라 아래 CTA가 위아래로 움직였다. 특히 실패 상태에서 `ErrorState` 의 액션 버튼(다시 시도)과 온보딩 CTA(계속하기)가 20px 남짓 떨어져 붙어 보였다 — 같은 모양의 버튼 둘이 나란히 있어 어느 쪽이 이 화면의 주 동작인지 흐려진다.
   - 자리의 높이를 **콘텐츠가 우연히 정하게 두지 않는다**는 처방은 [[ADR-054]] 정정 4(보스 수익 라벨행을 `h-6` 으로 명시 고정)와 같다.
   - 트레이드오프: 캐릭터가 3명(1줄)뿐이어도 385px를 차지해 아래쪽에 빈 공간이 남는다. CTA가 흔들리지 않는 값이라 수용한다. 모달 총 높이는 약 559px로, 세로 600px 미만 뷰포트에서는 위아래가 잘릴 수 있다(현실적인 대상 기기 범위 밖으로 본다).

5. **에러 문구의 어미는 `~습니다` 로 통일한다**(사용자 결정 2026-07-30).

   | 구분 | 어미 | 예 |
   |---|---|---|
   | 실패·에러·불가 | **`~습니다`** | "네트워크 오류가 발생했습니다" · "저장하지 못했습니다" · "이 기간은 조회할 수 없습니다" |
   | 성공·안내 | `~어요` | "캐릭터 정보를 모두 불러왔어요" · "주간 12개를 모두 선택했어요" |
   | 진행 중 | `~하고 있어요` | [[ADR-061]] 결정 9 그대로 |

   `UnavailableNotice` 는 실패가 아니지만 이 규칙을 따른다 — 정보 톤은 **색(info-tint)이 담당하지 어미가 담당하지 않는다**. 한 컴포넌트 안에서 제목·설명의 어미가 갈려 있던 것을 없앤다.

**이유**:

- **결정 1의 "배지 없음"**: 세 상태(조회 중 / 확정된 빈 상태 / 확인 불가·실패)는 항상 구분 가능해야 한다([[ADR-060]]·[[ADR-061]], error-resilience.md 원칙 2). 배지를 쓰면 `EmptyState` 와 첫인상이 같아져 그 요구가 깨지고, 동시에 아이콘 규칙의 예외를 셋으로 늘려야 한다. 배지를 빼면 두 문제가 한 번에 없어진다.
- **결정 3의 "설정 열기"**: 401에 재시도 버튼을 주는 것은 눌러도 실패하는 버튼을 주는 것이다. 앞선 조사에서 미구현으로 남아 있던 error-resilience.md의 *"전역 `apiKeyInvalid` → 설정 진입 유도"* 가 **배너를 새로 만들지 않고** 이 액션으로 해결된다.
- **결정 4가 결정 1~3과 묶여야 하는 이유**: 스탈 분기를 빼면 새 `ErrorState` 는 재설치·캐시 삭제 직후 콜드 스타트에서만 보인다. 정상 사용자에게는 아무것도 바뀌지 않는다. 배관(`loadError` 전달·재시도 배선)이 같으므로 나눠 하면 같은 파일을 두 번 건드린다.
- **결정 5**: 실패 문구에 `~어요` 를 쓰면 사과하듯 읽힌다. 반대로 성공·진행에 `~습니다` 를 쓰면 딱딱하다. 어미를 톤 신호로 쓰되 **에러/비-에러 두 갈래로만** 나눠, 규칙을 외우지 않아도 판단할 수 있게 한다.

**트레이드오프**:

- **[[ADR-053]] 결정 3의 "재시도 버튼 없음"을 폐기한다.** 그 결정은 "모달을 닫았다 다시 열면 재조회되므로 그 경로를 문구로 안내한다"였다. 닫았다 여는 것으로 풀리지 않는 실패(401)가 있고, 원인을 못 보여주는 상태에서 그 안내는 사용자를 헛수고시킨다. 재조회 경로 자체는 그대로 재사용한다 — 여는 순간의 초기화를 `reloadRoster()` 로 뽑고 재시도가 같은 경로를 타게 해, 열기와 재시도가 한 코드로 수렴한다.
- **스탈 배너는 피커를 열 때마다 뜰 수 있다.** 캐시 폴백이 계속되는 상황에서는 매번 보인다. 억제(세션 1회 등)는 두지 않는다 — 낡은 목록을 최신으로 오인해 저장하는 것이 반복 노출보다 나쁘다.
- **문구 어미 변경이 기존 토스트 3종을 건드린다**("저장하지 못했어요" · "파티원 수를 저장하지 못했어요" · "API 키를 확인하지 못했어요"). 문구만 바뀌므로 위험은 낮지만 테스트 기대값을 함께 고친다.
- **`~습니다` 통일이 `UnavailableNotice` 의 정보 톤을 약화시킬 수 있다.** 색·아이콘·정렬은 그대로 두어 실패와 계속 구분되게 한다.

**적용 범위 밖**(별도 진행):

- 비활성 캐릭터(`access_flag: false`) 처리 — 이슈 #78 A. 응답 계측이 선행이다.
- 설정 계정 모달의 `다시 시도` 가 재조회하지 않고 모달을 닫는 버그 — 이슈 #78 D.
- 인라인 실패 문구를 토스트로 옮기는 작업(스케줄러 3화면·보스 수익) — 이 ADR의 결정 5(어미)만 공유하고 나머지는 독립적이다.
