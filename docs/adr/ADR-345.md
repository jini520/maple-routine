# ADR-345: 넥슨 로그인을 가이드라인대로 다시 세운다

> ⛔ 폐기 · 2026-10-14 · [[ADR-347]] 이 흡수했다

**무엇을 결정했었나.** 넥슨 개발 가이드(`service` · `oAuthSecurity` 탭)에서 거꾸로 풀어 로그인
설계를 세웠다. 액세스 토큰은 서버에서만 관리·사용하고, `state` 는 Redirect URI 에서 서버가
확인하며, 그러므로 `redirect_uri` 가 서버의 https 주소여야 한다는 것. 콜백을 서버가 받고 커스텀
스킴에는 값을 안 싣고, 세션 원본을 짝에 봉해 두고 짧은 창 안에 꺼내 가며, 간격 고리가 짝과 고아
세션을 치운다.

**왜 폐기했나.** 서버 코드를 완전히 다시 쓰기로 했고(사용자 지정 2026-10-14) DB 도 이어 가지
않기로 했다. 이 문서는 **기존 코드를 고칠 것**으로 쓰여 있어서 - 결정 하나가 사라질 함수 두 줄에
걸려 있고, 스키마 결정이 마이그레이션을 전제로 했다 - 다시 쓰는 서버의 설계서로는 경계가 어긋났다.

**결정은 [[ADR-347]] 로 옮겼다.** 실측(PKCE 두 갈래가 막힌 것 · https 콜백이 동작하는 것 · 갱신
토큰 회전)도 그 문서가 든다. 기기 SQLite 쪽 소견 넷은 서버와 무관해 그 문서의 「이 문서 밖에 남는
것」에 목록만 남겼다.

전문은 git 히스토리에 있다.
