# ADR-088 — 혼테일 테마 재작업: 얼음 동굴 포인트 + 테마 배경 이미지

> 🟡 **PARTIALLY SUPERSEDED — 일부 폐기.** 결정 5-1은 [[ADR-133]] 이 폐기, 배경 그림은 [[ADR-109]] 가 교체했다.
> 나머지 결정은 유효하다 — 인용 전 본문에서 해당 결정 번호를 확인할 것.

**날짜**: 2026-08-03
**상태**: 구현 완료
**관련**: [[ADR-064]](38토큰·파생 규칙) · [[ADR-009]](테마 등록·기본 다크) · [[ADR-006]](색 값은 사용자 확인) · [[ADR-021]](일러스트 카드 배경 크롭)

## 맥락

혼테일 테마는 보스 스프라이트 하나만 보고 만든 팔레트였다. 그 결과 `secondary` 가 무채색
회색(`#7B777A`), `third` 가 탁한 갈색(`#936E68`)이라 **완료 배지·진행 칩이 색으로 아무 말도
하지 않았다**. 혼테일은 [[ADR-009]] 이후 **기본 다크 테마**라 저장된 선택이 없는 다크 모드
사용자가 처음 보는 화면이기도 하다.

사용자가 레퍼런스 3장을 줬다 — 보스 스프라이트 · 보스 입장 맵 · 보스 필드 맵. 이미지에서
실제로 뽑힌 색은 이랬다([[ADR-006]] 도메인 데이터라 추정이 아니라 샘플링).

| 출처 | 색 | 비고 |
|---|---|---|
| 보스 몸통 | `#201010` 흑갈색 · 비늘 `#886860` | 채도 거의 없음 |
| 보스 뿔 | H 4~16 완전 채도, 최고 `#A02800` | 스프라이트에서 **유일한** 채도 |
| 맵(양쪽) | H 205~225 얼음 블루가 화면의 절반, 하이라이트 `#90D0F0` | |
| 맵(양쪽) | 마젠타 수정 `#A81088` · 보라 발광 `#9810D8` | 면적은 작지만 시선이 가는 점 |

즉 현행 팔레트에는 **맵의 색이 하나도 들어가 있지 않았다**.

## 결정

### 1. 시드는 현행 유지, 회색 포인트만 얼음 동굴로

표면 톤이 통째로 갈리는 안(primary 를 얼음 블루로 돌려 앱 전체를 심야 네이비로)까지 시안을
만들어 견줬고, **사용자가 현행 유지를 택했다**. 바뀌는 것은 `secondary` 계열 4토큰뿐이다.

| 토큰 | 전 | 후 |
|---|---|---|
| `secondary` | `#7B777A` 무채색 회색 | `#6BB4E8` 얼음 발광 |
| `onSecondary` | `#FFEEE6` | `#1B4663` (파생 — 밝은 채움이라 짙은 전경) |
| `secondaryTint` | `#301F1E` | `#203343` (**오버라이드**, 결정 2) |
| `secondaryInk` | `#7B777A` | `#6BB4E8` |

`primary`(용암 주황 `#E86A16`)·`third`·표면·텍스트는 **전부 그대로**다. 뿔의 주홍이 이미
`primary` 로 들어가 있어 보스의 점은 유지된다.

### 2. `secondaryTint` 만 파생 규칙을 덮는다 — 갈색 표면 + 얼음 15% = 다시 회색

[[ADR-064]] 의 틴트 규칙은 `color-mix(accent 15%, surface)` 다. 그런데 혼테일 표면은
갈색(`#241110`)이라 얼음 `#6BB4E8` 을 15% 섞으면 **`#31272B`** — 바꾸기 전 회색 틴트
`#301F1E` 와 육안으로 구분되지 않는다. 즉 규칙을 그대로 따르면 **이 작업의 목적인 "회색 →
얼음"이 배지에서 일어나지 않는다**(보색에 가까운 시드를 소량 섞으면 채도가 서로 상쇄되기
때문이고, 규칙의 결함이 아니라 규칙이 전제한 조건 — 시드와 표면의 색상이 가깝다 — 밖이다).

그래서 이 한 토큰만 **차가운 베이스(`#101820`)에 얼음을 20% 섞은 `#203343`** 으로 덮는다.
[[ADR-064]] 가 마련해 둔 `overrides` 장치를 쓰는 것이고, 규칙 자체는 바꾸지 않는다 — 다른
테마는 여전히 15% 혼합이다.

측정치: 잉크(`#6BB4E8`) 대비 **5.77:1**, 표면 대비 1.39:1(틴트는 표면과 붙어 있어야 칩으로
읽힌다). 대안이던 15%/25%/35% 단순 증량은 각각 회색(#31272B)·회보라(#3A363F)·과하게
밝음(#414553)이라 전부 기각.

카드 안(`.media-scope`) 완료 배지는 [[ADR-064]] 결정 5대로 다크 모드에서 `secondary` **통짜
채움**이라 이 오버라이드와 무관하게 얼음 블루로 나온다.

### 3. 테마에 **배경 이미지**를 선택 필드로 추가한다

사용자 요청은 "필드 맵(밤 수정 동굴)을 배경으로". 지금 테마 스키마는 색 38토큰뿐이라 필드를
신설한다. 적용 범위는 **혼테일 하나**지만, 구조는 "필요할 때 다른 테마에도 값 한 블록으로
붙는" 형태로 만든다(사용자 지시).

```jsonc
"background": {
  "image": "hontail-cave",   // src/assets/themes/<slug>.webp
  "size": "cover",           // background-size
  "position": "center",      // background-position
  "dim": 0.82                // 이미지 위에 덮는 검정 불투명도
}
```

- **에셋 해석은 슬러그 → URL 맵**으로 한다. `import.meta.glob` + NFC 정규화로, 일일 퀘스트
  지역 배경(`lib/daily-quest-backgrounds.ts`)이 쓰는 방식 그대로다. JSON 이 번들 경로를 알
  필요가 없고, 파일을 넣고 슬러그만 적으면 붙는다.
- **크기·위치·어둡기는 값으로 조절**한다(사용자 지시). 코드를 고치지 않고 JSON 한 줄로
  "더 어둡게 / 아래쪽을 보이게 / 확대" 를 바꾼다. 지역 배경 크롭 데이터
  (`daily-quest-region-crops.json` 의 `{size, position}`)와 같은 모양이라 낯설지 않다.
- `buildThemeCss` 가 `--theme-bg-image`·`--theme-bg-size`·`--theme-bg-position`·
  `--theme-bg-dim` 네 프로퍼티를 낸다. **배경이 없는 테마는 아예 선언하지 않는다** — CSS 쪽
  기본값(`none`)이 그대로 살아 다른 네 테마의 그림은 한 픽셀도 안 바뀐다.

### 4. 배경은 `position: fixed` 백드롭 한 장으로 깐다 — `background-attachment: fixed` 는 쓰지 않는다

벽지처럼 보이려면 배경이 **뷰포트에 고정**돼야 한다(문서에 붙으면 `cover` 가 문서 높이만큼
확대돼 그림이 깨진다). 그 방법이 둘인데:

- `background-attachment: fixed` — iOS WKWebView 에서 동작이 불안정한 것으로 알려져 있고,
  이 프로젝트는 이미 iOS 페인트·스크롤 결함으로 [[ADR-077]]·[[ADR-079]]·[[ADR-085]] 를
  겪었다. 같은 계열의 위험을 새로 들이지 않는다.
- **`position: fixed` 요소 한 장** — 어디서나 예측 가능하다. 이쪽을 쓴다.

`App.tsx` 루트의 첫 자식으로 `<div class="theme-backdrop">` 를 넣고 `z-index: -1` 을 준다.

**루트의 `bg-bg` 는 배경이 있는 테마에서 뺀다.** 음수 z-index 가 부모 배경 **위**에 오는 것은
부모가 스태킹 컨텍스트일 때뿐인데, 앱 루트(`div.min-h-screen`)는 스태킹 컨텍스트가 아니다.
그래서 처음 구현대로 `bg-bg` 를 남겼더니 **이미지가 통째로 사라졌다**(브라우저에서 확인,
2026-08-03 — 어둡게 깔린 게 아니라 아예 안 보였고, `dim` 을 0으로 낮춰도 그대로여서 "덮였다"로
가려냈다). 바탕색은 `body` 가 같은 `--color-bg` 로 이미 칠하고 그 색이 캔버스로 전파되므로,
루트에서 빼도 배경 없는 상태의 그림은 그대로다. 이 계약을 회귀 테스트로 잡는다.

### 5. 상단 sticky 헤더의 이음매는 **위쪽 페이드**로 없앤다

페이지 배경을 덮는 `bg-bg` 불투명 면이 8곳 있다(각 화면 sticky 헤더·드롭 히스토리
오버레이·바텀시트). 이들은 백드롭 위에 **평평한 단색 사각형**으로 얹혀, 그 아래 이미지와
경계선이 생긴다.

8곳을 전부 고치는 대신(`fixed` 배경 정렬 트릭이 필요해지고, 위험은 결정 4가 피한 바로 그
것이다) **백드롭 자신이 위쪽에서 `--color-bg` 로 페이드**하게 한다. 헤더가 덮는 띠에서는
이미지가 이미 배경색과 같아 이음매가 생길 자리가 없고, 아래로 내려가며 동굴이 드러난다.
페이드 높이도 `dim` 과 같이 값(`fadeTop`)으로 조절한다.

### 5-1. 정정 — 헤더에 **정렬된 배경 조각**을 넣는다 (페이드·반투명 모두 폐기)

결정 5는 이음매를 **없애는** 대신 헤더 띠에서 배경을 포기했다. 사용자가 "sticky 영역에도 배경이
보이게" 요청해 방향을 바꿨는데, 먼저 시도한 **헤더 반투명(`headerFill`)은 사용자가 반려했다** —
헤더가 투명해지면 배경만이 아니라 **그 밑으로 스크롤된 카드도 함께 비친다**. 불투명도로는
"배경만 통과시키고 콘텐츠는 막는다"를 표현할 수 없다(둘 다 헤더 뒤에 있다).

그래서 헤더를 **불투명하게 유지하되, 헤더가 자기 자리에 해당하는 배경 조각을 직접 그린다**.
백드롭과 **같은 기하**로 그리면 이어붙인 티가 나지 않는다.

```
헤더(sticky/fixed, z-10)
 └ .theme-header-backdrop   position:absolute; inset:0; overflow:hidden; z-index:-1
    └ ::before              position:absolute; top:0; left:0; width:100vw; height:100dvh
                            ← 백드롭과 똑같은 레이어·크기·위치. 넘치는 부분은 부모가 잘라낸다
```

정렬이 보장되는 이유는 **조각이 뷰포트와 같은 상자에 그려지기** 때문이다. `cover` 는 그리는
상자를 기준으로 계산되므로, 헤더 상자(예: 390×120)에 `cover` 를 주면 배율이 달라져 어긋난다.
그래서 조각은 뷰포트 크기(`100vw × 100dvh`)로 그리고 **부모가 헤더 높이만큼만 잘라낸다**. 헤더는
문서 최상단 요소라 stuck 여부와 무관하게 항상 뷰포트 상단에 있고, 그래서 조각의 좌상단이 백드롭의
좌상단과 같은 점이다.

- `overflow: hidden` 은 **헤더가 아니라 조각 래퍼**에 건다 — 헤더에 걸면 그 안의 캐릭터 드롭다운
  팝오버가 잘린다.
- `z-index: -1` 은 헤더 **자신의 배경 위, 헤더 콘텐츠 아래**다(헤더가 `z-10` 스태킹 컨텍스트라
  이번엔 전제가 성립한다). 헤더 전체는 여전히 `z-10` 이라 **스크롤된 카드는 조각이 가린다** —
  조각이 불투명하기 때문이고, 그래서 조각에는 이미지·어둡기와 함께 `--color-bg` 바탕색도 넣는다.
- 백드롭과 조각은 **같은 CSS 선언을 공유**한다(선택자 둘, 규칙 하나). 한쪽만 고치면 어긋나므로.
- 적용은 **페이지 상단 헤더 5곳**(컨텐츠·컨텐츠 관리·보스·보스 관리·보스 수익)이다. 드롭 히스토리
  오버레이·바텀시트·에러 화면은 아래를 **가리는 것이 일**이라 손대지 않는다.

**페이드(`fadeTop`)는 0으로 내린다.** 헤더가 같은 그림을 이어 그리므로 이음매가 구조적으로 없다 —
페이드는 그 이음매를 감추려던 장치였다. 값은 남겨둔다(다른 테마가 원하면 쓸 수 있다).

### 5-2. 값은 디버그 라우트에서 눈으로 맞춘다

`size`·`position`·`dim`·`fadeTop` 은 수치로 고를 수 있는 값이 아니라 **보고 정하는** 값이다
(어느 크롭에서 수정·달이 보이는지는 뷰포트 비율까지 걸린다). 그래서 `/debug/theme-background` 를
둔다 — `/debug/boss-cards`·`/debug/quest-cards`·`/debug/boss-portrait-size` 와 같은 임시 도구
패턴이고, 조정이 끝나면 라우트와 파일을 지운다.

슬라이더는 **진짜 백드롭과 헤더 조각의 커스텀 프로퍼티**(`document.documentElement` 인라인 스타일)
를 바꾼다. 별도 프리뷰 상자를 만들면 뷰포트 기준으로 계산되는 `cover` 를 재현할 수 없어 실제와
어긋나기 때문이다 — 화면 자체가 프리뷰다. 페이지에는 실제 헤더와 같은 클래스의 sticky 헤더와 채움
카드가 있어 **헤더 조각 정렬과 스크롤 가림**을 그 자리에서 확인한다.

배경이 없는 테마에서는 백드롭 자체가 렌더되지 않아 조절할 대상이 없으므로, 그 경우 안내와 함께
**배경을 가진 테마로 전환하는 버튼**을 보여준다(실제 `selectTheme` 경로라 프리뷰가 앱과 같다).

### 5-3. 표면을 두 단계 어둡게 (사용자 요청)

배경 이미지가 들어오면서 카드가 상대적으로 밝아 보였다. `surface` 를 **색조는 그대로 두고 명도만**
내린다(사용자가 4단계 시안 중 "두 단계" 선택).

| 토큰 | 전 | 후 |
|---|---|---|
| `surface` | `#241110` | `#190707` |
| `surface2`·`track` | `#362120` | `#2A1616` |

`surface2` 를 같은 폭으로 함께 내린 이유는 둘의 단차가 카드 안 pill·진행률 트랙을 카드에서
띄우는 유일한 장치라서다. 틴트 6종은 **규칙(`accent 15% + surface`)대로 다시 파생**해 따라
내려간다 — `primaryTint` `#3D1D15`→`#33130C`, `thirdTint` `#331D1C`→`#291413`,
`errorTint` `#3D1B18`→`#33110F`, `riseTint` `#3E1E1C`→`#341413`, `fallTint` `#30242F`→`#271B25`.

**예외 둘.**
- `infoTint`(`#3A3235`)는 **규칙 파생값이 아니라 옛 손값**이다([[ADR-009]] 2026-07-22 정정으로
  들어온 값). 규칙값(`#21191E`)으로 갈아끼우면 요청하지 않은 변경이 함께 들어가므로, **같은 폭만큼만
  내려** 관계를 보존한다(`#2F272A`). 잉크 대비 11.24:1 유지.
- 얼음 `secondaryTint`(`#203343`)는 표면이 아니라 차가운 베이스에서 만든 명시 오버라이드라
  (결정 2) 그대로 둔다. 표면이 내려간 만큼 완료 배지가 오히려 더 또렷해진다(1.39→1.50).

**카드는 이제 밝기가 아니라 보더로 정의된다.** 원래도 `surface`/`bg` 대비는 1.09:1 뿐이라 카드는
따뜻한 색조와 보더로 구분되고 있었고, 두 단계 내리면 밝기는 사실상 같아진다(1.01:1) — 대신 보더
대비가 1.93→2.09 로 올라 경계를 보더가 맡는다. 배경 이미지 위에서는 이쪽이 그림을 더 살린다.

`primary`(용암 주황 `#E86A16`)·텍스트·`media-*`(일러스트 카드)는 건드리지 않았다.

### 6. 적용 범위

- 배경 이미지를 갖는 테마는 **혼테일 하나**. 나머지 넷은 값이 없어 CSS 도 안 나간다.
- 카드는 **불투명 유지**(시안 ⑥ 반투명 카드는 기각 — 카드 안 텍스트 대비가 배경 위치마다
  달라져 [[ADR-064]] 가 세운 대비 계측이 무의미해진다).
- 스플래시·부트 커버·네이티브 브랜드색은 범위 밖([[ADR-064]] 와 동일).

## 근거로 삼지 않은 것

- **대비 수치로 색을 고르지 않았다** — [[ADR-064]] 판단 순서대로 색감이 먼저다. 얼음
  `#6BB4E8` 은 갈색 표면 위에서 `secondary` 채움으로 4.43:1 인데, 이 수치가 아니라 "맵의
  얼음이 그 색인가"로 골랐다. 수치는 참고로 기록만 한다.
- **third(탁한 갈색)는 건드리지 않았다** — 사용자 지시가 "회색 → 얼음"이었다. 마젠타 수정을
  third 로 올리는 안이 시안에 있었지만 채택되지 않았다.
