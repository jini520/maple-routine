# ADR-307: 오래 걸리는 데이터 작업은 조각마다 저장하고, 앱이 중간에 닫히면 다시 열 때 이어서 한다

> ⚪ 미구현 · 2026-09-22 · 설계 · 사용자 지정 · 시안 https://claude.ai/artifact/EmnT9Fk5j5nvEa2iooGGik (9 · 10번째 줄)

> 사용자 지정(2026-09-22): 기존 데이터를 바꾸는 작업은 진행률 모달을 띄운다. 작업이 정상으로 끝났는지 확인하는 장치를
> 두어, 앱이 비정상으로 닫혀도 다시 열 때 이어서 진행한다. 이번에만 쓰고 말 장치가 아니라 범용이어야 한다.

**관련**: [[ADR-306]](첫 사용처. 일괄 적용과 자동 수수료 다시 계산) · [[ADR-063]](실패를 어디에 띄우는가) ·
[[ADR-115]](닫을 수 없는 모달)

## 맥락

[[ADR-306]] 의 두 작업이 기존 기록을 다시 쓴다. 기존 사용자의 첫 확인 화면에서 켜는 **지난 기록 수수료 적용**과, 등급 기록을 바꿀 때마다
도는 **자동 수수료 다시 계산**이다. 처음 구현은 네 가지가 틀렸다.

- **기록마다 따로 `UPDATE` 하고 트랜잭션이 없다.** 중간에 앱이 닫히면 일부만 바뀐 채 굳는다. 일괄 적용은 물었다는 표시
  (`mvpBulkApplyAsked`)를 적용보다 먼저 적어, 닫히면 다시 묻지도 않는다.
- **행마다 커밋이라 기록이 많으면 느리다.**
- **그동안 화면이 `맞아요` 버튼의 스피너뿐이다.** 진행률도 건수도 없다.
- **가계부가 수입 기록이 바뀐 것을 모른다.** `cashbookDataRevision` 이 드롭과 결정석의 판만 더해서, 드롭이 안 바뀌면 옛 금액을 계속 보인다.

값을 옮기는 장치는 이미 하나 있다(`storage/sqlite/migrations.ts`). DB 를 열 때 버전마다 트랜잭션 하나로 조용히 돈다. 그 장치는 스키마
버전에 묶여 있어 사용자가 고른 때에 도는 작업(체크박스를 켠 일괄 적용, 등급을 고친 뒤의 다시 계산)을 담지 못한다.

## 결정

### 결정 1. 작업은 **남은 일을 스스로 찾는** 단계들로 짓는다 (사용자 지정)

작업 하나는 이름 · 배지 아이콘 · 진행 제목 · 단위 · 단계 목록 · 완료 문구를 갖는다. 단계는 함수 둘이다.

- `remaining()` 은 **남은 일의 수**를 센다.
- `runChunk(limit)` 는 남은 일의 앞쪽 `limit` 개를 처리하고 처리한 수를 돌려준다. **조각 하나가 SQLite 트랜잭션 하나다**(200개).

처리한 일은 다시 남은 일로 잡히지 않는다. 일괄 적용은 수수료가 빈 행을 찾는데 처리하면 수수료가 들어가고, 다시 계산은 요율이 틀린 자동 행을
찾는데 처리하면 요율이 맞는다. 그래서 **멈춘 자리를 따로 적지 않아도** 다시 돌리면 남은 것부터 한다. 앱이 조각 도중에 닫히면 그 조각만
되돌아가고 앞 조각은 남는다.

이렇게 셀 수 없는 작업(한 번 읽고 끝나는 계산)은 이 장치에 못 붙는다.

### 결정 2. 시작하기 전에 **끝나지 않은 작업 표시**를 적고, 남은 일이 0 이 되면 지운다

표시는 preferences `pendingTasks` 한 칸이다. 작업마다 `id` 와 **시작할 때 단계마다 남아 있던 수**(`totals`)를 적는다. 진행률의 분모가
이 값이고, 분자는 `totals − remaining()` 이다.

- **작업을 시작하기 전에 적는다.** 적은 뒤에 첫 조각이 돈다.
- **모든 단계의 남은 일이 0 이 되면 지운다.**
- 작업 정의는 `id` 로 찾는다(등록부). 모르는 `id` 는 표시를 지운다. 앱 버전이 내려가 정의가 없어진 경우다.
- **캐시 삭제에서 보존한다**(`KEEP_KEYS`). 지워지면 반쯤 바뀐 기록이 그대로 굳는다. 기록을 지운 뒤라면 남은 일이 0 이라 다음에 열 때
  묻지 않고 지워진다(결정 4).

### 결정 3. 진행률 모달은 **범용 부품 다**다 (사용자 결정)

- 머리는 **배지 아이콘과 제목**이고 둘 다 작업이 준다. 설명 줄은 없다. `앱을 닫아도 다음에 열 때 이어서 적용해요` 를 두었다가 뺐다(사용자 지시).
- **단계 목록**은 단계가 둘 이상인 작업에만 선다. 끝난 단계는 체크와 건수, 도는 단계는 스피너와 `N / M건`, 남은 단계는 `대기` 다.
- 맨 아래가 **막대 · 건수 · 퍼센트**이고 모든 작업이 같이 쓴다. 단위는 작업이 준다(기본 `건`).
- 닫는 버튼이 없고 바깥 탭 · 뒤로가기로 안 닫힌다. 끝나면 스스로 닫힌다.
- **0.3초 넘게 걸릴 때만 뜬다**(사용자 결정). 등급 하나를 고친 뒤 몇 건만 다시 세는 일에 모달이 한 프레임 번쩍이지 않게 한다.

### 결정 4. 앱을 다시 열 때 끝나지 않은 작업이 있으면 **재진행 확인 모달 다**를 띄운다 (사용자 결정)

- 제목 `끝나지 않은 작업이 있어요` 와 설명 `앱이 중간에 닫혀 멈춘 작업이에요. 멈춘 곳부터 이어서 진행해요.` 는 모든 작업이 같이 쓴다.
  작업 이름을 제목에 넣지 않는 것은 이름마다 조사(이/가)가 갈려서다.
- 작업마다 줄 하나가 선다. 작업 이름 · 멈춘 자리의 막대 · `N / M건` 이고, 앞 작업 뒤에 기다리는 작업은 `대기` 다.
- 버튼은 **`이어서 진행하기` 하나**다. **`나중에` 는 없다**(사용자 결정). 미루면 그동안 일부 기록만 바뀐 채로 계산된다.
  바깥 탭 · 뒤로가기로 안 닫힌다.
- 누르면 같은 막대가 진행률 모달(결정 3)로 이어진다. 이때는 0.3초 규칙 없이 곧바로 선다. 사용자가 누른 일이라서다.
- **뜨는 때는 진입 단계가 `ready` 가 된 뒤다.** 남은 일이 0 인 작업(표시를 지우기 전에 닫힌 경우)은 묻지 않고 표시만 지운다.
- **MVP 등급 모달보다 먼저다.** 끝나지 않은 작업이 있거나 도는 동안 등급 모달을 띄우지 않는다. 등급 모달의 답이 새 작업을 만들어
  줄이 꼬이기 때문이다.

### 결정 5. 끝나면 **완료 토스트**를 띄운다 (사용자 결정)

문구는 작업이 준다. 처리한 수가 0 이면 안 띄운다.

### 결정 6. 실패하면 **알리고 닫는다**. 표시는 남는다

작업이 던지면(저장소 오류) 그 조각만 되돌아가고 표시는 그대로다. 토스트 `작업을 마치지 못했어요` 를 띄우고 모달을 닫는다. 다음에 앱을
열 때 재진행 확인이 다시 뜬다.

실패한 자리에서 재진행 확인을 곧바로 다시 띄우지 않는 것은 `나중에` 가 없어서다. 같은 실패가 되풀이되면 사용자가 앱을 못 쓰게 된다.

### 결정 7. 작업이 바꾼 표는 **판(revision)을 올린다**

`income_records` 에 판을 새로 두고 `cashbookDataRevision` 에 더한다. 가계부가 수입 기록이 바뀐 것을 알고 다음 포커스에 다시 읽는다.
드롭과 결정석은 이미 판이 있다.

### 결정 8. 첫 사용처는 [[ADR-306]] 의 두 작업이다

| 작업 | 단계 | 완료 토스트 |
|---|---|---|
| `지난 기록 수수료 적용` | 판매 기록(아이템 판매 · 조각 정산 · 사냥의 조각 몫) · 드롭 판매가 | `지난 기록 N건에 수수료를 적용했어요` |
| `자동 수수료 다시 계산` | 판매 기록 · 드롭 판매가 · 결정석 분배 | `자동 수수료 기록 N건을 다시 계산했어요`([[ADR-306]] 결정 6 그대로) |

- 배지 아이콘은 둘 다 왕관이다(등급 모달과 같다).
- 등급 확인 모달은 `맞아요` 에서 이력을 적고 닫힌다. 그 뒤에 작업이 돈다. 일괄 적용을 켰으면 적용이 먼저이고 다시 계산이 뒤다.
- **일괄 적용은 표시를 적은 뒤에 `mvpBulkApplyAsked` 를 적는다.** 반대 순서면 그 사이에 닫힐 때 다시 묻지도 않고 적용도 안 된다.
- 설정의 등급 변경 · 기록 고치기 · 기록 추가 · 지우기도 저장 뒤 다시 계산 작업을 돌린다.

### 결정 9. 캐릭터 관리 저장의 진행률도 이 부품으로 그린다 (사용자 결정)

모양만 바꾼다. 제목 `캐릭터 정보를 저장하고 있어요`, 단위 `개`, 배지 아이콘은 사람 둘(`UsersIcon`)이다. 저장은 네트워크 조회라 남은 일을
셀 수 없어 표시 · 재진행에는 안 든다. 0.3초 규칙도 안 들고 지금처럼 저장하는 동안 늘 선다. 옛 `ProgressModal` 은 지운다.

## 대가

- 새 작업은 남은 일을 셀 수 있게 지어야 한다. 한 번 읽고 끝내는 작업은 못 붙는다(결정 1).
- 표시(preferences)와 조각(SQLite)이 한 트랜잭션이 아니다. 표시를 지우기 전에 닫히면 할 일이 0 인 표시가 남는데, 다음에 열 때 묻지 않고
  지운다(결정 4).
- 작업이 도는 동안 앱의 다른 화면을 못 만진다.
- 같은 실패가 되풀이되면 앱을 열 때마다 재진행 확인이 뜨고 실패 토스트로 끝난다(결정 6).

## 열린 질문

- **구현 때 정한 문구 둘이 사용자 확인 전이다**: 실패 토스트 `작업을 마치지 못했어요` · 일괄 적용 완료 토스트 `지난 기록 N건에 수수료를 적용했어요`.
