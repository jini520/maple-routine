# ADR-161+202 가계부 메이플 ID 기록

> 🟢 유효
> 관련 소스: `app/cashbook/character-options.ts` · `app/cashbook/sheet-fields.tsx` · `app/cashbook/income/EtcForm.tsx` · `app/cashbook/spend/CatalogForm.tsx` · `app/cashbook/spend/SymbolForm.tsx` · `app/cashbook/spend/ItemBuyForm.tsx` · `app/cashbook/spend/EtcForm.tsx` · `features/cashbook/account-names.ts` · `lib/maple-id-name.ts` · `features/cashbook/legacy-entry-accounts.ts` · `features/cashbook/records.ts` · `lib/cashbook/categories.ts` · `storage/cashbook-entries.ts` · `storage/income.ts` · `storage/spend.ts` · `storage/sqlite/migrations.ts` · `features/mvp-grade/character-list.ts` · `features/stats/aggregate.ts` · `app/stats/CharacterSection.tsx` · `app/today/view-model.ts`

## 배경

가계부의 수입 · 지출 가운데 몇 분류는 캐릭터를 고르지 않아도 저장됐고, 그 기록은 계정 단위(`ocid = null`)였다. 이 기록은
하루 목록에 제목만 섰고, 통계의 캐릭터별 카드에서는 빠졌다. 사용자가 그 분류들에서 기록을 붙일 곳을 고르게 했다(2026-11-04, #851).

> 모든 항목에 캐릭터 항목을 필수로 바꿀거야.
>
> 계정으로 입력할 수 있게하고 통계에도 캐릭터가 아니라 계정 단위 기록으로 표시되도록 정책을 수정할게.
>
> 계정(maple id단위)이 여러개 일 수 있어. 목록에서 골라야하는 것은 맞는데 이것 끼리 구분할 수가 있어야해.
>
> 근데 이번 수정이 기존에 캐릭터가 필수 였던 곳까지 영향을 미치면 안돼. 기존에 캐릭터 필수 정책이 없던 곳에 들어가는거야.

여기서 계정은 메이플 ID 다. 메이플스토리의 계정 단위는 `넥슨 계정 > 메이플 ID > 캐릭터` 이다([[ADR-101]]). 메이플 ID 는
넥슨 `character/list` 의 `account_id` 이고, 기기 표 `character_accounts` 의 `account_id` 와 같은 값이다. 이 값은 사람이 읽을 수
없는 글자라 화면에는 이름을 따로 만들어 보여 준다(결정 3).

## 결정

### 결정 1. 캐릭터 없이 저장되던 분류는 캐릭터나 메이플 ID 를, 또는 캐릭터만 골라야 저장된다

이 결정은 캐릭터 없이 저장되던 분류에만 들어간다(사용자 지정 2026-11-04). 사냥 · 솔 에르다 조각 · 사냥 전리품 판매 · 아이템
판매 · 헥사 매트릭스는 이미 캐릭터가 필수라 이 결정 밖이고, 지금 규칙 그대로다([[ADR-048]] 결정 7 · [[ADR-137]]).

분류마다 무엇을 고르는지는 사용자가 하나씩 정했다(2026-11-04).

| 시트 | 분류 | 고르는 것 |
|---|---|---|
| 수입 | 기타 (`etc`) | 캐릭터나 메이플 ID |
| 지출 | 이벤트·BM (`event_bm`) | 캐릭터나 메이플 ID |
| 지출 | 기타 (`etc`) | 캐릭터나 메이플 ID |
| 지출 | 컨텐츠 (`content`) | 캐릭터나 메이플 ID([[ADR-101]] 결정 29) |
| 지출 | 버프 (`buff`) | 캐릭터만 |
| 지출 | 주문서 (`scroll`) | 캐릭터만 |
| 지출 | 심볼 강화 (`symbol`) | 캐릭터만 |
| 지출 | 아이템 구매 (`item_purchase`) | 캐릭터만 |

- 이 여덟 분류의 목록에는 `선택 안함` 이 없다. 새 기록은 빈 칸으로 열리고, 고르기 전에는 저장이 꺼진다.
- 폼마다 저장 조건(`canSave`)이 고른 것이 있는지 본다. 보기에서 `선택 안함` 을 빼기만 하면 모자란다. 수정으로 연 옛 기록은
  칸이 비어 있어서, 저장 조건이 보지 않으면 그대로 다시 저장된다.
- 컨텐츠 · 이벤트·BM · 버프 · 주문서는 한 폼(`CatalogForm`)을 함께 쓴다. 메이플 ID 보기는 그 폼이 분류를 보고 컨텐츠 ·
  이벤트·BM 에만 붙인다(`ACCOUNT_SPEND_CATEGORY_KEYS`).
- 심볼 강화는 캐릭터를 골라야 하므로, 늘 착용 레벨로 거른 목록과 그 캐릭터가 기억한 레벨에서 시작한다. 심볼은 캐릭터마다
  레벨이 따로다.
- 고를 보기가 하나도 없으면 저장할 수 없고, 따로 알리지 않는다(사용자 지정 2026-11-04). 지금 사냥 · 아이템 판매와 같다.
  온보딩과 캐릭터 관리가 추적 캐릭터를 하나 이상 요구하므로, 이렇게 되는 것은 캐시에 이름이 아직 없거나 추적 목록을 못
  읽었을 때뿐이다.

### 결정 2. 메이플 ID 보기는 캐릭터 뒤 맨 끝에 서고, 추적 캐릭터가 속한 ID 만 선다

- 목록은 추적 캐릭터가 지금 차례대로 서고, 그 뒤에 메이플 ID 가 선다(사용자 지정 2026-11-04). 자주 고르는 캐릭터가 위에
  남는다.
- 추적 캐릭터가 속한 ID 만 선다. 소속은 기기 표 `character_accounts` 에서 찾는다. MVP 등급이 등급을 묻는 ID 와 같은
  기준이다([[ADR-050]] 결정 12). 소속을 모르는 캐릭터의 ID 는 서지 않는다.
- ID 끼리는 대표 캐릭터의 레벨이 높은 ID 가 먼저이고, 같으면 대표 이름순이다. 대표 캐릭터는 그 ID 에서 레벨이 가장 높은
  캐릭터다(`pickRepresentativeCharacter`). 넥슨 `character/list` 응답을 담아 기기에 저장한 쿼리 `characterList(credentialKey)`
  에서 고르고([[ADR-142]] 결정 2), 그 응답에 ID 가 없으면 그 ID 의 추적 캐릭터 가운데 레벨이 가장 높은 캐릭터를 쓴다. 레벨은
  쿼리 캐시 `characterBasic(ocid)` 의 값이다. 대표를 못 찾은 ID 는 맨 끝이다. 가계부는 저장된 응답을 읽기만 하고 넥슨을 따로
  부르지 않는다.
- 메이플 ID 보기는 글자만 선다. 캐릭터 보기의 월드 엠블럼 같은 그림을 붙이지 않는다(사용자 지정 2026-11-04).

### 결정 3. 메이플 ID 의 이름은 [[ADR-101]] 결정 8 의 이름이다

- 기본 이름은 `메이플ID-` 뒤에 그 메이플 ID 값의 앞 8자를 붙인 것이다(`메이플ID-da9b2f21`). 앱 전체가 메이플 ID 를 이 이름으로
  부른다([[ADR-101]] 결정 8, 사용자 지정 2026-11-11). 같은 ID 가 화면마다 다른 이름이면 같은 ID 로 읽히지 않는다.
- 이름은 ID 값에서 바로 만들어서, 대표 캐릭터나 저장된 `character/list` 응답이 없어도 늘 선다. 그래서 이름을 못 만드는 ID 가
  없고, 서로 다른 ID 가 같은 이름으로 서지 않는다.
- 가계부의 메이플 ID 보기와 하루 목록 줄은 이름만 적고 대표 캐릭터를 붙이지 않는다. 이름 아래에 대표 캐릭터를 두는 것은 계정
  관리 화면과 캐릭터 관리 드롭다운뿐이다([[ADR-101]] 결정 8).
- 기록에는 ID 만 저장하고 이름은 그릴 때 만든다. 이름을 저장하면 같은 ID 의 기록이 이름마다 갈린다.

### 결정 4. 기록은 `ocid` 나 `account_id` 하나만 채우고, 넥슨 계정 id 는 주인을 모르는 옛 기록에만 남는다

- `cashbook_entries` 에 `account_id` 칸을 더한다. 캐릭터 기록은 `ocid` 만, 메이플 ID 기록은 `account_id` 만 채운다(사용자 지정
  2026-11-04). 어느 기록인지는 어느 칸이 찼는지로 가른다. 같은 사실을 한 번만 적으므로 두 칸이 어긋날 일이 없다.
- 캐릭터 기록의 메이플 ID 가 필요하면 `character_accounts` 에서 그 캐릭터의 소속을 찾는다. 기록에 함께 적지 않는다.
- 칸 이름은 `character_accounts` 의 메이플 ID 칸과 같은 `account_id` 다. 같은 값을 두 표가 다른 이름으로 부르면 두 표를 이어
  읽을 때 같은 값인지 알기 어렵다.
- **새 기록에는 `nexon_account_id` 를 적지 않는다**(사용자 지정 2026-11-04). 넥슨 계정은 `ocid` 나 메이플 ID 에서
  `character_accounts` 를 거쳐 찾는다. 메인 계정 id 를 적어 두면, 다계정이 생긴 뒤 부계정 메이플 ID 의 기록에 메인 계정이 붙어
  틀린 값이 된다.
- 칸은 지우지 않는다. 주인을 모르는 옛 기록(`ocid` 와 `account_id` 가 모두 `NULL`)에는 이 값 말고 단서가 없다. 옛 기록을
  메이플 ID 로 옮기거나(결정 5) 수정해서 캐릭터 · 메이플 ID 를 고르면 이 칸을 비운다. 그래서 이 칸이 찬 행은 늘 주인을 모르는
  옛 기록이다.

### 결정 5. 캐릭터 없이 적힌 옛 기록은 그 넥슨 계정의 메이플 ID 가 하나뿐이면 그 ID 로, 아니면 대표 캐릭터에게 붙인다

- 옛 기록(`ocid` 와 `account_id` 가 모두 `NULL`)에는 넥슨 계정 id(`nexon_account_id`)만 있다. 그 넥슨 계정에 메이플 ID 가
  하나뿐이면 어느 ID 의 기록인지 분명하므로 그 ID 를 적는다(사용자 지정 2026-11-04). 넥슨 계정의 메이플 ID 는
  `character_accounts` 에서 센다. 옮긴 행은 `nexon_account_id` 를 비운다(결정 4). 메이플 ID 를 고를 수 있는 분류(결정 1)의
  기록만 이렇게 옮긴다.
- 그래도 남은 옛 기록은 그 기기의 지금 대표 캐릭터에게 붙인다([[ADR-101]] 결정 28, 사용자 지정 2026-11-09). 지금까지 앱은 넥슨
  계정을 하나만 두어 고르지 않고 적은 기록도 그 계정의 것이고, 사용자가 직접 적은 기록이라 사용자의 책임으로 본다.
  - 메이플 ID 도 고를 수 있는 분류의 기록은 대표 캐릭터의 메이플 ID 에 붙인다.
  - 캐릭터만 고르는 분류의 기록은 대표 캐릭터(그 `ocid`)에 붙인다. 캐릭터 기록은 `ocid` 로 메이플 ID 를 찾으므로(결정 4)
    메이플 ID 칸은 채우지 않는다.
  - 대표 캐릭터는 화면이 대표로 세우는 캐릭터다(`resolveDisplayRepresentative`). 대표를 고르지 않았으면 추적 목록의 첫
    캐릭터다. 대표가 없거나 그 캐릭터의 메이플 ID 를 아직 모르면 붙이지 않는다.
- 옮기는 것은 앱을 켤 때의 부팅 단계(`assignLegacyEntryAccounts`)이고, `fillLegacyAccountIds` 뒤에 돈다. 그 단계가 끝나기 전에는
  옛 기록의 `nexon_account_id` 가 빈 글자일 수 있어 계정을 셀 수 없다([[ADR-098]] 결정 6). 소속은 `character/list` 를 받아야
  생기므로, 붙일 기록이 남아 있으면 켤 때마다 다시 본다.

### 결정 6. 메이플 ID 기록은 이름을 붙여 보여 주고, 그림이 서는 자리에는 세우지 않는다

| 자리 | 메이플 ID 기록 | 캐릭터도 메이플 ID 도 없는 옛 기록 |
|---|---|---|
| 가계부 하루 목록 줄의 첫 줄 | `메이플 ID 이름 · 제목`(`메이플ID-da9b2f21 · 제목`). 캐릭터 기록의 `이름 · 제목` 과 같은 형식이다 | 제목만 |
| 통계 `캐릭터별` 카드의 막대 | ID 마다 한 줄. 금액 순서대로 캐릭터 줄 사이에 선다 | 빠진다 |
| 통계 `캐릭터별` 카드의 단상 | 서지 않는다. 메이플 ID 줄을 뺀 캐릭터 줄의 상위 셋이 선다 | 빠진다 |
| today `이번 주 수익` 의 순위 | 서지 않는다 | 빠진다 |

- 단상과 today 순위는 전신 그림 · 얼굴이 서는 자리다. 메이플 ID 에는 그림을 두지 않으므로(결정 2) 이 두 자리에는 세우지
  않는다(사용자 지정 2026-11-04).
- 통계 카드 제목은 `캐릭터별` 그대로다(사용자 지정 2026-11-04). 메이플 ID 줄도 결정 3 의 이름만 쓰고, 캐릭터 줄과 가르는
  표시를 따로 붙이지 않는다([[ADR-101]] 결정 8, 사용자 지정 2026-11-09).
- 순 수익 · 수입 내역 · 지출 내역 같은 다른 카드와 today 의 합계 · 도넛은 지금처럼 모든 기록을 센다.

## 번호 기록

- ADR-161 (2026-11-04): 캐릭터 없이 저장되던 가계부 분류에 캐릭터나 메이플 ID 를 고르게 하고, 메이플 ID 기록을 이름과 함께 보여 주는 결정을 처음 작성했다(#851)
- ADR-202 (2026-11-11): 메이플 ID 의 이름을 `메이플 ID · 대표 캐릭터` 에서 [[ADR-101]] 결정 8 의 이름(`메이플ID-` 와 ID 앞 8자)으로 바꿨다. 대표 캐릭터는 ID 의 차례를 정하는 데만 쓴다(#928)
