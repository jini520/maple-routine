### ADR-031: 보스 스케줄러 처치 카운트 자체 계산 · 등록/처치 난이도 불일치 보정 · 챌린저스 시즌 보스 표시 · 파티 관리 모달 필터 (구현 완료)

**배경**: 보스 스케줄러 화면([[ADR-019]])을 실사용하면서 Open API 응답 자체의 정확성 문제와 UX 개선 필요성이 추가로 확인됨(2026-07-22, 사용자 실측):

1. `weekly_boss_clear_count`/`weekly_boss_clear_limit_count` 필드 값이 실제와 다르게 오는 경우가 있다. 특히 `weekly_boss_clear_limit_count`는 캐릭터가 인게임에서 정보 갱신을 하지 않으면 `0`으로 오는 경우가 확인됨 — 게임 규칙상 이 값은 항상 12([[ADR-007]] `weeklyBossSelectionLimit`)로 고정이라 API 값을 신뢰할 수 없다.
2. `registration_flag`가 표시하는 난이도와 실제로 처치한 난이도가 다른 경우가 있다(예: 이지로 등록해두고 실제로는 노멀을 처치). 이 경우 등록된 난이도 항목의 `complete_flag`는 그대로 `false`로 남고, 실제로 처치한 다른 난이도 항목에 `complete_flag: true`가 대신 찍힌다. 더 나아가 아예 어떤 난이도도 등록하지 않은 채로 처치한 경우도 있다 — 이때는 등록된 항목 자체가 없어 화면에서 완전히 누락된다.
3. 챌린저스 월드에는 "시즌 보스"(현재 메이린, `content_name: "시즌 보스 메이린"`, [[ADR-006]] `weekly-bosses.json`의 `eventWeekly`)라는 특수 콘텐츠가 있다 — 주간 보스 12마리 처치 제한에 포함되지 않는다는 게임 규칙은 이미 알려져 있었으나([[ADR-007]] 109행), 화면에서 이걸 시각적으로 구분해 보여주는 기능은 아직 없었다. **정정(2026-07-22)**: 이 `content_name` 항목 자체는 챌린저스가 아닌 월드의 API 응답에도 존재한다(사용자 실측) — 응답에 있는지 여부로는 챌린저스 월드인지 판별할 수 없다.
4. 파티 관리 모달([[ADR-019]])의 보스 드롭다운이 항상 전체 보스 목록(24종+시즌+월간)을 보여줘, 실제로 스케줄러에 등록해둔 소수의 보스를 찾기 번거롭다는 피드백.

**결정**:

1. **주간 보스 처치 카운트를 API 값 대신 직접 계산**: `weekly_boss_clear_count`/`weekly_boss_clear_limit_count`를 domain 상태(`SchedulerCharacterState`)에 더 이상 실어 나르지 않는다. 대신 매칭된 보스 목록(`bossContents`, cycle이 `weekly`인 것들)에서 시즌 보스를 제외한 `content_name` 그룹 중 그 그룹의 **어떤 난이도든 하나라도 완료(`complete_flag: true`, 아래 2번 보정 반영)** 인 그룹 수를 세어 처치 카운트로 쓴다. **`registration_flag`는 이 카운트에 영향을 주지 않는다(사용자 확정, 2026-07-22)** — 스케줄러에 등록하지 않고 잡은 보스도(아래 5번) 시즌 보스가 아닌 이상 그대로 카운트에 포함된다. 상한은 항상 `weekly-bosses.json`의 `weeklyBossSelectionLimit`(12, 이미 [[ADR-007]]에서 사용자 확정)을 그대로 쓰고 API 응답 값은 무시한다. 이 계산은 [[ADR-030]] 병합(stale 시 이전 캐시로 폴백, 진행값만 초기화) 이후의 "실효 상태"(`bossContents`) 위에서 수행되므로, 주간 리셋(목요일 0시 KST) 이후 캐릭터가 접속하지 않아 API가 빈 배열을 주는 경우에도 [[ADR-030]] 폴백이 그대로 적용되어 보스 목록은 유지되고 카운트만 0으로 자연히 초기화된다 — 이번 변경을 위한 별도 캐시 처리가 필요하지 않다.
2. **등록 난이도 ≠ 처치 난이도 보정 (등록된 항목 한정)**: Open API wire → domain 변환 단계(`nexon/schedule/normalize.ts`)에서 각 항목의 `isComplete`는 기본적으로 자기 자신의 `complete_flag`를 그대로 따르되, 예외로 "**등록된**(`registration_flag: true`) 항목인데 자기 자신은 미완료라도, 같은 `content_name`을 가진 다른 난이도 항목 중 하나라도 `complete_flag: true`"면 그 등록된 항목도 완료로 승격시킨다. 이 승격은 등록된 항목에만 적용한다 — 미등록 항목들끼리는 서로의 완료 여부를 전파하지 않는다(각자의 원본 `complete_flag`를 그대로 유지, 아래 5번에서 개별적으로 쓰인다).
3. **챌린저스 시즌 보스 표시**: 시즌 보스 표시 여부는 API 응답에 그 항목이 있는지가 아니라 **선택된 캐릭터의 월드**로 판정한다 — `world-emblems.json`에서 `challengers` 엠블럼으로 매핑되는 월드(챌린저스/챌린저스2/챌린저스3/챌린저스4)면 챌린저스 월드로 간주한다(신규 헬퍼 `isChallengersWorld`, `lib/world-emblem.ts`에 추가). 챌린저스 월드 캐릭터를 보고 있으면 **`registration_flag`와 무관하게** 주간 탭 헤더의 `n/12` 카운터 배지 옆에 `season` 배지를 표시하고, 시즌 보스(`eventWeekly` 소속, 난이도 무관하게 하나라도 `complete_flag: true`면 완료)의 완료/미완료 상태를 함께 보여준다.
4. **파티 관리 모달 — "스케줄러에 등록된 보스만 보기" 토글**: 기본값 ON. ON이면 드롭다운은 선택된 캐릭터가 게임 내 스케줄러에 등록해둔 보스만 보여준다. 단, 등록된 보스가 하나도 없으면(신규 캐릭터 등) 토글이 켜져 있어도 전체 목록으로 자동 대체한다 — 모달의 원래 목적("아직 등록 안 한 보스도 미리 파티 인원 설정 가능", 위 [[ADR-019]] 연계 코드 주석)이 완전히 막히지 않도록 하기 위함.
5. **미등록이어도 완료된 보스는 카드로 표시**: 화면의 보스 카드 목록(주간·월간 공통)은 `content_name` 그룹별로 다음 우선순위로 구성한다 — (a) 그 그룹에 등록된(`registration_flag: true`) 항목이 하나라도 있으면 그 항목만 카드로 보여준다(2번 보정이 적용된 `isComplete` 그대로). (b) 등록된 항목이 하나도 없으면, 그 그룹에서 `complete_flag: true`인 난이도가 있는지 찾아 있으면 그 난이도를 완료 카드로 추가한다. (c) 등록도 안 됐고 완료도 없으면 카드를 만들지 않는다(기존 동작). 즉 "아예 스케줄러에 등록하지 않고 잡은 보스"도 처치한 난이도 그대로 카드에 나타나되, 등록된 난이도가 있을 땐 그 등록 항목만 보여줘 중복 카드가 생기지 않는다.

**트레이드오프**:
- 처치 카운트는 `content_name` 그룹 단위로 "그룹에 완료된 난이도가 있는가"만 보고 1로 센다 — 같은 보스를 여러 난이도로 동시에 완료한 드문 경우에도 중복 카운트되지 않는다. 반대로 이 계산은 등록 여부와 무관하므로, 극단적으로 한 주에 시즌 보스를 제외한 서로 다른 보스를 12종보다 많이 클리어하면(등록 없이 잡은 것 포함) 표시되는 `n`이 상한 12를 넘어설 수 있다 — 실사용에서 흔치 않은 경우라 이번 설계에서는 그대로 둔다.
- 시즌 보스 판정이 `world-emblems.json` 매핑에 의존한다 — 향후 새 챌린저스 월드(챌린저스5 등)가 생기면 그 파일을 먼저 갱신해야 이 판정도 함께 갱신된다([[ADR-006]] 정책과 일관).
- ~~5번으로 인해, 등록 없이 여러 난이도를 동시에 완료한 드문 경우(예: 등록 없이 노멀·하드 둘 다 처치) 카드가 두 장 이상 뜰 수 있다 — 데이터를 숨기지 않는 쪽을 택했다.~~ → **정정(2026-07-22, 사용자 확인, [[ADR-032]])**: 같은 content_name·같은 cycle(weekly/monthly)에서는 게임 룰상 한 캐릭터가 여러 난이도를 동시에 완료하는 게 애초에 불가능하다 — 위에서 우려했던 "카드 두 장" 현상이 실제로 관찰됐다면 진짜 동시 완료가 아니라 bossDaily/bossWeekly content_name 교차 오염 버그([[ADR-032]] 참고)가 원인이었을 가능성이 높다.

**정정(2026-07-22) — 메이린 표시명을 API content_name과 통일**: 메이린 카드/드롭다운 표시명을 기존 `weekly-bosses.json`의 `boss: "메이린"`에서 Nexon 스케줄러 Open API의 실제 `content_name`인 `"시즌 보스 메이린"`으로 변경(사용자 확정 — 식별키 자체를 전체 교체하는 범위로 선택). `boss`가 이제 API `content_name`과 정확히 같아 `apiAlias` 매핑이 더 이상 필요 없어 해당 entry에서 제거했다. 이 boss 이름은 `boss-crystal-prices.json`(가격/최대 파티인원 조인 키)과 `item-drop-table.json`(드랍표 조인 키)에서도 동일한 문자열로 조인하므로 두 파일의 `"boss": "메이린"`도 함께 `"시즌 보스 메이린"`으로 갱신했다(아이템명 `"메이린의 ○○ 상자"` 등은 보스 식별자가 아니라 그대로 둠). 또한 이 이름은 SQLite `boss_party_settings`/`boss_profit_records`의 `boss` 컬럼에 파티 인원 설정·수익 기록의 저장 키로도 쓰이므로, 기존에 저장된 `boss = '메이린'` 행이 새 키를 못 찾는 고아 데이터가 되지 않도록 `storage/sqlite/db.ts`의 `openBossProfitDb()`가 매번 여는 시점에 `UPDATE ... SET boss = '시즌 보스 메이린' WHERE boss = '메이린'`을 두 테이블에 실행해 이관한다(이미 이관됐으면 WHERE절에 걸리는 행이 없어 no-op).
