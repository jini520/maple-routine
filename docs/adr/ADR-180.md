# ADR-180 — 떠 있는 것의 층은 **형제 순서**가 정한다 — 화면이 소유한 오버레이는 «바 위 슬롯» 에 그린다

> 🟢 유효 · 2026-08-30 · **구현 완료** · 실기기 미검증

## 맥락

사용자 보고(2026-08-30): **펼침판(＋)을 펴면 화면은 어두워지는데 하단바만 그대로 밝다.**
백드롭이 바를 안 덮는다.

### 지금 그려지는 순서

RN 은 **형제 순서가 곧 그리는 순서**다(이 저장소가 이미 두 곳에서 그렇게 적어 뒀다 —
`AppShell.tsx` 의 벽지 주석, `docs/features/theme.md`). `ThemeProvider` 의 화면 채움 View 직속
형제를 뒤에서부터 세면 층이 그대로 나온다:

| 층 | 무엇 | 어디서 그리나 |
|---|---|---|
| ⑥ 맨 위 | **시트 + 시트 스크림** | `PortalProvider` 의 루트 호스트 |
| ⑤ | 토스트 | `AppShell` |
| ④ | API 키 안내 | `AppShell` |
| ③ | `AppNavigation` — 화면들 → **그 위에 하단바** | `Main` 의 `layout` |
| ② | 테마 벽지 | `AppShell` |
| ① 맨 아래 | 시트 호스팅 컨테이너(빈 측정 상자) | `BottomSheetModalProvider` |

**시트는 이미 바 위다.** `@gorhom/portal` 의 `PortalProvider` 가 `{children}` 을 그린 **뒤에**
루트 호스트를 붙이기 때문이다(`{children}{shouldAddRootHost && <PortalHost/>}`) — 시트는 앱 트리
전체의 **다음 형제**다. `BottomSheet.tsx` 파일 머리가 *"웹의 `fixed … z-[60]` 이 하던 일을
프로바이더의 호스트가 대신한다"* 고 적어 둔 것이 실제로 그렇게 서 있다.

**펼침판만 바 아래다.** 스크림도 FAB 도 `CashbookScreen` **안**에서 그려지는데, 바는 그 화면들
**뒤에** 그려진다(`Main` 의 `layout`).

### `zIndex` 로는 못 고친다

RN 의 `zIndex` 는 **같은 부모 안에서만** 겨룬다. 바와 화면 컨테이너는 형제지만 스크림은 화면
**안**이라 바와 겨룰 자리가 없다. 화면 컨테이너를 통째로 바 위로 올리면 — 화면은 불투명하므로 —
바가 **흐려지는 것이 아니라 사라진다**.

그러므로 스크림이 바를 덮으려면 **펼침판이 화면 밖으로 나가야** 한다. 그리고 스크림만 내보낼 수는
없다: FAB·줄은 스크림 **위**여야 하고 스크림은 바 위여야 하므로, FAB 도 바 위다.

## 결정

### 1. 바 **뒤에** 슬롯을 하나 둔다 — `AboveBar`

`Main` 의 `layout` 이 그리는 순서가 «화면들 → 바» 였는데 여기에 하나가 붙는다:

```
<View className="flex-1">
  {children}                 ← 층 스택(화면들)
  <ConnectedBottomBar />     ← 떠 있는 캡슐
  <AboveBarHost />           ← 바 위 슬롯 ([[ADR-180]])
</View>
```

기구는 **새로 만들지 않는다** — 시트가 이미 쓰는 `@gorhom/portal` 이다. 호스트를 하나 더 두고
(`above-bar`), 화면이 소유한 오버레이는 `<AboveBar>` 로 감싸 그 호스트에 그린다. 이 앱에서
«바 위에 그린다» 는 이미 포털이고, 두 벌을 만들 이유가 없다.

**왜 `Main` 의 `layout` 인가 — 바와 같은 상자여야 한다.** `AppShell` 에 두면(토스트가 있는 자리)
하위 페이지가 `Main` 을 밀어낼 때 바는 함께 나가는데 FAB 만 남는다([[ADR-120]] 결정 4 ·
[[ADR-167]]). 바 바로 뒤에 두면 «바가 나가면 함께 나간다» 가 구조로 성립한다.

### 2. 펼침판은 **통째로** 올라간다

스크림만 올리면 FAB 가 그 밑에 깔린다(맥락의 마지막 문단). `SpeedDial` 의 반환 전체를
`<AboveBar>` 로 감싼다 — 스크림·줄 둘·FAB 가 한 덩어리로 바 위에 선다.

**공짜로 따라오는 것 하나**: 열린 상태에서 바를 누르면 이제 스크림이 그 탭을 받아 **닫힌다**.
종전에는 바가 스크림 위라 «펼친 채로 다른 탭으로 이동» 이 됐다.

### 3. 슬롯은 **자기 화면이 초점을 잃으면 안 그린다**

포털로 나간 그림은 **화면이 숨어도 안 숨는다.** 층 안의 화면들은 탭이라 서로 언마운트되지 않고
([[ADR-167]] 결정 3) 네이티브가 화면 뷰를 숨길 뿐인데, 포털 내용은 그 뷰 **밖**에 있다 — 가만
두면 FAB 가 보스·오늘 화면 위에까지 떠 있게 된다.

그래서 판정을 **슬롯 자신이** 든다(`AboveBar` 안). 이 규칙은 펼침판의 것이 아니라 **바 위에
그리는 모든 것의 전제**이므로 슬롯이 갖는 것이 맞다.

**`useIsFocused` 를 그대로 못 쓴다** — 그 훅은 내비게이터 밖에서 **던지고**, 이 저장소의 컴포넌트
테스트는 내비게이터 없이 렌더한다(`render-atom.tsx`). `NavigationContext` 를 **옵션으로** 읽어,
없으면 «보인다» 로 둔다(테스트·독립 렌더). 있으면 `isFocused()` + `focus`/`blur` 구독으로
react-navigation 의 `useIsFocused` 와 같은 일을 한다.

**대가 — 층 전환에서 FAB 가 화면과 함께 미끄러지지 않고 즉시 사라진다**(사용자 선택, 2026-08-30).
갈래는 셋이고 그중 하나만 갈린다:

| 이동 | 종전 | 지금 |
|---|---|---|
| 탭 전환(가계부 ↔ 수익) | 즉시 사라짐(전환 자체가 없다) | 같다 |
| 하위 페이지(`Main` 통째로 밀림) | 화면과 함께 미끄러짐 | 같다(슬롯이 바와 같은 상자에 있다) |
| **층 전환(가계부 → 오늘)** | 화면과 함께 미끄러짐 | **즉시 사라짐** |

### 4. 시트는 안 건드린다

이미 바 위이고(맥락의 표 ⑥), 이 결정이 만드는 슬롯은 그보다 **아래**다 — 시트가 열리면 시트
스크림이 펼침판까지 덮는다. 순서가 «화면 < 바 < 펼침판 < 안내·토스트 < 시트» 로 한 줄에 선다.

## 결과

- `components/organisms/AboveBar/AboveBar.tsx` — 호스트(`AboveBarHost`)와 슬롯(`AboveBar`) 둘.
- `Main.tsx` 의 `layout` 이 바 **뒤에** 호스트를 그린다. 순서가 곧 층이라 이 한 줄이 결정 전부다.
- `SpeedDial` 은 반환을 `<AboveBar>` 로 감싸는 것 말고 **한 줄도 안 고친다** — 자리 계산
  (`dialBottomPx`)은 창 기준 절대 배치라 부모가 바뀌어도 같은 자리다.
- `render-atom.tsx` 의 `renderOverlay` 가 `PortalProvider` + 호스트를 함께 세운다. 둘 다 **뷰를
  하나도 안 그리므로** 기존 오버레이 테스트의 트리는 그대로다.
- 회귀는 두 자리에서 잡는다 — `Main.test.tsx` 가 «가계부에서 스크림이 바보다 **뒤에** 그려진다» 를
  실제 트리로 물고, `AboveBar.test.tsx` 가 호스트·초점 규칙을 문다.

## 폐기한 것

없다. [[ADR-170]] 결정 5~9(펼침판)의 모양·움직임·아이콘은 그대로이고, 이 결정은 그것이 **어느
층에 서는가**만 정한다.
