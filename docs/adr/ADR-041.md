### ADR-041: 보스 반지 상자 결과 선택 개편 — 백옥 기준 목록·저가치 반지 '기타' 묶음·반지→레벨 선택 순서·연마석 레벨 없음 (구현 완료, 2026-07-26)

**배경**: [[ADR-038]]/[[ADR-040]]이 만든 반지 상자 드릴다운(`BoxDrillDown`, `BossDropSheet.tsx`)은 상자의 **모든 반지를 그대로 나열**한다. 그런데 녹옥·홍옥 상자는 31종이나 되고 그중 실제 가치 있는 건 **리스트레인트 링·컨티뉴어스 링** 정도다. 또 현재 UI는 **등급(레벨)을 먼저** 고른 뒤 반지를 고르는데, 생명 상자의 **생명의 연마석은 레벨 개념이 없어** 현재 흐름으로는 레벨을 강제당해 기록 흐름이 어색하다. 사용자 요청(2026-07-26) 2건 반영. 게임 수치 데이터는 읽기만 하고 추정하지 않는다([[ADR-006]]).

**결정**:
1. **백옥 기준 목록 + 저가치 반지 '기타' 묶음(사용자 요청 1)**:
   - **명명 반지 = 백옥의 보스 반지 상자 반지 집합(11종)** 을 기준(baseline)으로 삼는다. 각 상자에서 이 집합에 속한 반지만 개별 타일로 노출한다. baseline은 `boss-ring-boxes.json`의 백옥 항목 `itemProbabilities`에서 **동적 산출**(데이터 변경 시 자동 동기화, 하드코딩·추정 없음 [[ADR-006]]).
   - baseline 밖 반지(녹옥·홍옥의 +20종)는 **단일 '기타' 타일 하나**로 묶고, **레벨퍼프 링 아이콘(`rings/Level_Jump_Ring.png`)** 을 쓴다. '기타' 선택 시 `itemName='기타'`, `ringLevel`은 유지(3/4)로 기록한다.
   - **연마석**(이름에 `연마석` 포함, 실질 `생명의 연마석`)은 '기타'에 넣지 **않고** 별도 특수 항목으로 둔다(레벨 없음, 결정 2).
   - 결과: 백옥·흑옥 = **11 명명, 기타 없음** / 녹옥·홍옥 = **11 명명 + 기타** / 생명 = **9 명명 + 생명의 연마석**.
   - 타일 정렬(사용자 확정): **명명 반지(상자 순서) → 연마석 → 기타**.
   - '기타' 아이콘: `lib/item-icons`의 **런타임 매핑에만** `'기타' → Level_Jump_Ring.png`를 추가한다([[ADR-011]] 조회 규칙). 정합성 테스트가 검사하는 `item-icons.json`(매핑명이 드랍테이블에 실재해야 함)은 **건드리지 않는다** — '기타'는 실재 아이템명이 아닌 UI 전용 묶음.
   - '기타'의 시세/가치: **관리 안 함**(priceMeso 없음). 저가치 반지 묶음이라 수익 계산에 잡히지 않는 게 의도.
2. **반지→레벨 선택 순서 + 연마석 레벨 없음(사용자 요청 2)**:
   - 드릴다운 선택 순서를 **반지 먼저, 레벨 나중**으로 바꾼다. 레벨('등급') 섹션을 반지 섹션 **아래**로 옮긴다. 레벨 섹션은 **항상 보이되**, **연마석(무레벨) 선택 시에만** 레벨 버튼을 `disabled`로 흐리게 한다(사용자 확정 — 반지 미선택·명명 반지·기타는 레벨 활성).
   - **연마석(레벨 없음) 선택 시**: 레벨 선택을 `disabled`하고 **'이 결과로 기록' 버튼을 활성화**한다(레벨 없이 기록, `ringLevel=undefined`).
   - `canConfirm = 반지 선택됨 && (무레벨 항목이면 true, 레벨 항목이면 레벨 선택됨)`. 레벨 항목→연마석으로 선택을 바꾸면 남은 레벨 상태는 무시(기록 시 미포함).

**데이터**: 신규 수치 데이터 없음(`boss-ring-boxes.json` 읽기만). '기타'는 UI 파생 항목이라 데이터 파일에 추가하지 않는다.

**이유**: 저가치 반지 20종을 개별 나열하면 목록만 길고 실사용 의미가 없다 → 가치 있는 건 개별, 나머지는 '기타' 한 칸. 백옥이 목록이 가장 짧고 가치 반지를 포함해 baseline으로 적합. 연마석은 레벨 개념 자체가 없어 레벨 강제는 잘못된 기록을 유도한다.

**트레이드오프**: '기타'로 묶으면 나중에 어떤 저가치 반지였는지 구분 불가(현재 요구 아님·가치 없음). baseline을 백옥으로 고정하므로, 백옥엔 없지만 다른 상자엔 있는 반지는 전부 '기타'로 접힘(의도된 동작). '기타'를 런타임 아이콘 맵에 특수 매핑하는 건 일반 규칙([[ADR-011]] 매핑 테이블)의 예외라 주석으로 명시.

**성공 기준(TDD, [[ADR-006]]·CLAUDE.md)**: 테스트 먼저 → 구현. (1) `lib/boss-drops`: `getRingBoxContents`가 백옥 기준으로 **명명 반지 + (extras 있으면) '기타' + (연마석 있으면) 연마석**을 반환하고 각 항목에 `hasLevel`을 붙임, `levels=[3,4]`. 케이스: 백옥(11 명명·기타 없음), 녹옥('기타' 포함·`hasLevel=true`), 생명(연마석 `hasLevel=false`·기타 없음). (2) `lib/item-icons`: `getItemIconUrl('기타')`가 `Level_Jump_Ring` 포함. (3) `BossDropSheet`: 반지 선택 전 레벨 `disabled`, 연마석 선택 시 레벨 `disabled`·기록 버튼 활성·`ringLevel` 없이 기록, '기타' 기록(`itemName='기타'`+레벨). 기존 드릴다운 테스트(레벨→반지 순서)를 **반지→레벨 순서**로 갱신. 전체 `test`·`lint`·`build` 통과.

**리뷰 확정(2026-07-26)**: ① '기타' 이름 = 그대로 **`'기타'`**. ② 타일 정렬 = **명명 반지 → 연마석 → 기타**. ③ 레벨 섹션 = **항상 보임**, **연마석 선택 시에만** `disabled`. baseline 밖 반지는 전 상자에서 '기타'로 접힘·'기타'는 수익 계산 대상 아님(가치 없음)도 확정. 실기기 육안 검증은 [[ADR-038]]/[[ADR-039]]/[[ADR-040]]와 함께.

**개정(2026-07-30, 구현 완료)**: '기타' 아이콘을 **레벨퍼프 링 → 리밋 링(`rings/Limit_Ring.webp`)** 으로 교체(사용자 요청). 결정 1의 나머지(런타임 맵 전용 매핑·`item-icons.json` 무변경·수익 계산 제외)는 그대로다. 리밋 링도 레벨퍼프와 마찬가지로 **백옥 baseline 밖 = '기타' 묶음에 실제로 포함된 반지**라 명명 타일과 아이콘이 겹치지 않는다(중복 회피 근거 동일). 변경 지점은 `lib/boss-drops`의 `OTHER_RING_ICON`과 `lib/item-icons`의 런타임 특수 매핑 2곳뿐. 아래 '구현' 문단의 `Level_Jump_Ring.png` 언급은 2026-07-26 시점 기록으로 남긴다.

**구현(2026-07-26, 구현 완료)**: TDD로 테스트 먼저 → 구현. `lib/boss-drops`(`RingOption{name,iconFile,hasLevel}` 신규, `getRingBoxContents`가 백옥 baseline으로 명명 반지 개별 + baseline 밖 반지 단일 `'기타'`(레벨퍼프 아이콘) + 연마석 별도(`hasLevel:false`)로 그룹핑, 정렬 명명→연마석→기타, 상자별 `levels`는 원본 유지), `lib/item-icons`(런타임 맵에만 `'기타'→Level_Jump_Ring.png` 특수 매핑 — `item-icons.json` 무변경으로 정합성 테스트 표면 불변), `BossDropSheet`의 `BoxDrillDown`(반지 섹션을 위로·등급 섹션을 아래로 재배치, `selectedOption.hasLevel` 기반 `needsLevel`/`levelDisabled` 도출 — 연마석 선택 시 등급 버튼 `disabled`·하이라이트 억제·레벨 없이 기록 활성, `canConfirm`/`onConfirm`이 무레벨 항목은 `ringLevel` 미포함). **검증**: 전체 1185 tests(신규 4 — `getRingBoxContents` 백옥/홍옥/생명 그룹핑·`getItemIconUrl('기타')`·`BossDropSheet` '기타' 기록·연마석 레벨 없음)·lint(경고 0)·build 통과. 기존 드릴다운 2개 테스트는 등급 항상 활성이라 클릭 순서 무관하게 통과 유지. **미verify**: 실 데이터로 시트 드릴다운 육안 확인([[ADR-038]]/[[ADR-039]]/[[ADR-040]]와 동일 — 등록 캐릭터·동기화 데이터 필요).
