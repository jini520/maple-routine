# ADR-150: app-rn 에서 전면광고를 걷는다 — 인벤토리를 인라인으로 옮기기 위한 첫 걸음

**날짜**: 2026-08-19
**상태**: **(구현 완료, 2026-08-19)** — app-rn 한정. 인라인 광고는 **아직 없다**(후속 ADR).
**관련**: [[ADR-090]](탭 전환 전면광고 + 3중 게이트 — **app-rn 에서만 폐기**, app-capacitor 에서는 그대로 선다) · [[ADR-128]](RN 전환 — 이 결정의 동인을 적어 둔 문서) · [[ADR-132]] 결정 9(광고 게이트를 그룹 이동에만 — **app-rn 폐기**) · [[ADR-005]](네이티브 어댑터 레이어 — 포트는 남는다)

## 맥락

[[ADR-128]] 이 RN 으로 가기로 한 **동인 자체가 광고 인벤토리**였다.

> 웹뷰가 하나의 거대한 네이티브 뷰라 DOM 카드 *사이*에 광고 뷰를 넣을 자리가 원리적으로 없고,
> 그래서 전면광고를 걷어내고 인라인으로 가는 **선택지 자체가 없다**.

즉 [[ADR-090]] 의 탭 전환 전면광고는 «가장 좋은 포맷» 이어서 고른 것이 아니라 **웹뷰에서 가능한
유일한 포맷**이어서 고른 것이다. 그 제약은 RN 에서 사라졌고, 사용자 지시(2026-08-19)로 첫 걸음을
뗀다 — *"우선 지금 앱에 붙어있는 전면 광고는 제거해줘"*.

**적용 범위는 app-rn 뿐이다.** app-capacitor 는 지금 App Store 에 나가 있는 앱이고 패리티까지
계속 OTA 로 배포한다([[ADR-128]] 결정 3) — 거기서 광고를 걷으면 «전환이 끝날 때까지 수익 0» 이
된다. 게다가 AdMob 플러그인은 네이티브라 **OTA 로는 제거되지도 않는다**(새 바이너리가 필요하다).

## 결정

### 결정 1 — 노출 지점 셋만 지운다

| 자리 | 하던 일 |
|---|---|
| `app/AppShell.tsx` | 부팅 시 `startAds()` — SDK 초기화 + 첫 광고 사전 로드 |
| `navigation/BottomBar.tsx` | 그룹 이동에서 `shouldGateAd` 판정 후 `maybeShowTabSwitchAd()` |
| `app/today/WidgetGrid.tsx` | 위젯으로 그룹을 넘을 때 같은 호출([[ADR-132]] 결정 9 의 바 밖 갈래) |

**사전 로드도 함께 지운다.** 표시만 막고 `startAds()` 를 남기면 실행마다 **뜨지 않을 광고를
요청**하게 되고, 그건 AdMob 에서 임프레션 없는 요청 — 즉 매치율 0 — 으로 쌓인다. 지금 걷는 것은
「광고를 띄우는 일」이 아니라 「전면광고라는 인벤토리」다.

### 결정 2 — SDK·포트·앱 ID 는 **남긴다**

인라인 광고가 그대로 물려받을 자산이라 여기서 걷으면 두 번 세워야 한다. **무변경**:

`react-native-google-mobile-ads` 의존성 · `native/adapters/rn-ads.ts` · `ads-env.ts` ·
`boot.ts` 의 `setAdsPort(rnAdsPort)` · `app.json` 의 config plugin 앱 ID · `app-ads.txt` ·
`EXPO_PUBLIC_ADS_TEST` 배선.

특히 **`ads-env.ts` 의 테스트 광고 강제**는 인라인 광고에도 그대로 필요하다 — 실 ID 로 자기 광고를
누르면 계정이 정지되는 위험은 포맷과 무관하다(`features/ads.md`).

### 결정 3 — `shouldGateAd`·`BarAction` 은 고아라 함께 지운다

[[ADR-132]] 결정 9 가 만든 판정 함수이고 **광고 게이트 말고는 부르는 곳이 없다**(그 타입이 생긴
이유도 *"광고 게이트가 무엇을 눌렀는가까지 봐야 해서"* 였다). 인라인 광고는 화면에 그려지는
것이라 **이동 시점 판정이 필요 없다** — 되살아날 여지가 없는 코드다.

`BottomBar` 의 `apply(next, action)` 에서 두 번째 인자가 사라지고, 부르는 네 자리가 함께 줄어든다.

### 결정 4 — 「없기로 한 것」을 가드로 지킨다

`src/__tests__/interstitial-policy.test.ts` 가 **app-rn 소스에 `features/ads/tab-switch-ad`
import 가 0건**임을 본다. [[ADR-131]] sticky 가드·[[ADR-129]] 글롭 가드와 같은 형태다 — 회귀가
«기능이 깨지는» 모양이 아니라 **«없기로 한 것이 슬그머니 돌아오는»** 모양으로 오기 때문이다.

가드는 `@core/native/ads` 는 잡지 않는다 — 어댑터가 `resolveInterstitialAdId`·`shouldUseTestAds`
를 계속 부르고(결정 2), 그 둘은 인라인 광고도 쓸 함수다.

### 결정 5 — `packages/core` 는 한 글자도 안 건드린다

`features/ads/policy.ts`·`tab-switch-ad.ts`·`native/ads.ts`·`storage/ads.ts` 와 그 테스트는
**app-capacitor 가 지금도 쓰고 있다**. 여기서 지우면 출시본이 깨진다.

## 트레이드오프

- **app-rn 은 이 시점부터 수익이 0이다.** 미출시라 지금 잃는 것은 없지만, **인라인 광고 없이 전환
  릴리스가 나가면 그 순간부터 실제 손실**이다 — 즉 이 결정이 인라인 광고를 [[ADR-128]] 5단계의
  **선행 조건**으로 만든다.
- **SDK 가 초기화되지 않는다.** `startAds()` 가 초기화와 사전 로드를 함께 했으므로(결정 1), 인라인
  광고를 붙일 때 **초기화를 부를 자리를 새로 정해야 한다**. `mobileAds().initialize()` 자체는
  `rn-ads.ts` 에 그대로 남아 있다.
- **두 앱의 광고 동작이 갈린다.** [[ADR-128]] 이 이식의 잣대로 삼은 *"예전과 같은가"* 로 대조할 수
  없는 항목이 하나 늘었다 — 다만 이것은 실수가 아니라 **의도된 차이**다.
- **[[ADR-090]] 의 3중 게이트 설계가 app-rn 에서 사용처를 잃는다.** core 에 코드로는 남지만
  (app-capacitor 가 쓴다) RN 쪽에서는 검증되지 않은 채 방치된다.

## 기각안

- **인라인 광고가 준비될 때까지 전면광고를 둔다** — 미출시 앱이라 지금 지키고 있는 수익이 없고,
  화면 작업이 계속되는 동안 노출 지점이 늘어날 뿐이다(`WidgetGrid` 가 실제로 그렇게 늘어난
  두 번째 지점이다).
- **광고 스택 통째로 제거**(SDK·앱 ID·`app-ads.txt`·환경변수) — 인라인 광고가 그대로 쓸 자산이라
  다시 세워야 하고, `app-ads.txt` 는 게시 후 크롤링까지 시간이 걸려 되돌리는 비용이 특히 크다.
- **app-capacitor 도 함께 걷기** — 출시본의 수익이 즉시 0이 되고, 네이티브 플러그인이라 OTA 로는
  제거되지도 않는다(새 바이너리 필요).
- **`shouldGateAd` 만 남겨 두기** — 부르는 곳이 없는 export 와 그 테스트 넷이 남는다. 인라인
  광고에는 이동 시점 판정이 필요 없으므로 되살아날 여지도 없다.
