# ADR-191+230 태블릿과 접는 폰 외부 화면의 배치

> 🟢 유효
> 관련 소스: `lib/screen-layout.ts` · `components/templates/ScreenScroll/ScreenScroll.tsx` · `components/templates/ScreenScroll/bottom-inset.ts` · `components/templates/EntryScroll/EntryScroll.tsx` · `components/organisms/BottomBar/BottomBar.tsx` · `components/organisms/BottomSheet/BottomSheet.tsx` · `components/organisms/Modal/Modal.tsx` · `components/organisms/InputCard/InputCard.tsx` · `components/organisms/Toast/ToastStack.tsx` · `lib/bottom-bar-metrics.ts` · `lib/fab-metrics.ts` · `lib/safe-area.ts` · `theme/text-scale.ts`

## 배경

앱은 폭 360 ~ 430 인 바형 폰의 세로 화면에 맞춰 만들어져 있다. 이 문서는 그 기준을 벗어나는 세 화면의 배치를 정한다(#945).

| 화면 | 앱이 쓰는 크기 | 바형 폰과 다른 점 |
|---|---|---|
| 태블릿 · 접는 폰의 안쪽 화면 | 짧은 변 600 이상 | 폭이 훨씬 넓고, 돌아간다 |
| 갤럭시 Z 폴드8 외부 화면 | 약 447×706dp | 폭이 조금 넓고 높이가 낮다 |
| 아이폰 듀오 외부 화면 | 466×678pt | 폭이 조금 넓고 높이가 낮다. 오른쪽에 폭 약 84pt 의 세로 레일이 있다 |
| 아이폰 듀오 안쪽 화면 | 가로 951×669pt | 짧은 변이 600 을 넘지만 외부 화면과 같은 폭 84pt 의 레일이 오른쪽에 있다 |

두 외부 화면의 크기는 `docs/foundation/design-system.md` 의 `시안` 표에서 옮겼다.

아이폰 듀오 외부 화면은 iOS 27.1 시뮬레이터에서 쟀다(2026-11-10). OS 는 앱 창을 466×678 그대로 주고, 레일을
오른쪽 안전영역 84 로 넘긴다. 위쪽 안전영역은 0, 아래쪽은 34 다. 레일 위쪽(약 x 391 ~ 445, y 20 ~ 152)에는 OS 가
반투명한 세로 막대와 시계 · 와이파이를 앱 화면 위에 그린다. 좌우 안전영역을 읽지 않던 앱은 콘텐츠를 창 폭 466 에
펼쳐서, `파티 스케줄` 화면의 `보드` 세그먼트와 기간 이동 줄의 `>` 버튼이 이 막대에 가려졌다. 위쪽 안전영역이 0 이라
헤더도 화면 위 끝에 붙었다.

안쪽 화면은 같은 시뮬레이터에서 가로로 쟀다(2026-11-15). 창은 951×669 이고 안전영역은 오른쪽 84 · 위 0 · 아래 34 로
외부 화면과 같다. 시계 · 와이파이도 오른쪽 위에서 앱 위에 그려진다. 세로로 돌린 안쪽 화면은 아직 재지 않았다.
결정 3 ~ 7 이 이 두 화면을 다룬다.

듀오 외부 화면의 모양은 시안 캔버스(https://claude.ai/artifact/FnJZDibxSZiks8ygq83M8N)에서 골랐다(2026-11-15).
막대는 A1, ＋ 자리는 F2, 위아래 여백은 P24 다.

## 결정

### 결정 1. 태블릿과 접는 폰의 안쪽 화면은 전용 배치를 두지 않고 바형 폰 배치를 그대로 쓴다 (사용자 지정)

짧은 변이 600 이상인 화면도 바형 폰과 같은 배치를 쓴다(사용자 지정 2026-11-15). 다만 오른쪽 안전영역이 있는 화면(아이폰
듀오의 안쪽 화면)은 결정 3 을 따른다. 하단바는 지금처럼 가운데에 뜨고
폭 420 에서 멈춘다([[ADR-059]] 결정 11). 넥슨 로그인 버튼도 같은 폭에서 멈춘다([[ADR-025]] 결정 5). today 격자는 4열이고([[ADR-058]] 결정 1), 콘텐츠는 창 폭만큼 늘어난다.
가로로 돌려도 같은 배치다. 화면이 도는 것 자체는 그대로다([[ADR-010]] 결정 1).

태블릿 전용 내비게이션과 배치를 시안으로 두 차례 그려 보고 정했다. 내비게이션은 왼쪽 세로 막대 · 사이드바 · 위쪽 탭 바 ·
펼치는 하단 독 · 두 줄 하단바를, 배치는 today 와 파티 스케줄을 기둥과 패널로 나눈 안을 그렸다
(https://claude.ai/artifact/QiHBaeSW1asX7DrzcR38ZL). 고를 안이 없어서 태블릿 전용 UI 는 만들지 않는다.

### 결정 2. 갤럭시 Z 폴드8 외부 화면은 바형 폰 배치를 그대로 쓴다 (사용자 지정)

외부 화면 전용 배치를 두지 않는다. 폭 447 은 바형 폰(360 ~ 430)보다 조금 넓을 뿐이고, 짧은 변이 600 미만이라 세로로
고정되는 것도 바형 폰과 같다([[ADR-010]] 결정 1). 높이가 낮아 넘치는 곳이 나오면 바형 폰 배치에서 고친다.

### 결정 3. 아이폰 듀오는 외부 화면과 안쪽 화면 모두 오른쪽 안전영역에 콘텐츠를 넣지 않는다 (사용자 지정)

콘텐츠는 오른쪽 안전영역 84 를 뺀 폭 안에 놓는다. 외부 화면은 382, 가로 안쪽 화면은 867 이다. 레일 위쪽에 OS 가 그리는
막대와 시계 · 와이파이가 앱 위에 겹쳐서, 그 자리에 놓인 버튼과 글자가 가려지기 때문이다.

이 화면은 기기 이름이 아니라 오른쪽 안전영역으로 알아본다(사용자 지정 2026-11-14). 화면 크기와 상관없이 오른쪽
안전영역이 0 보다 크면 이 배치를 쓴다(사용자 지정 2026-11-15). 처음에는 세로로 고정된 화면(짧은 변 600 미만)으로 범위를
좁혔는데, 그러면 안쪽 화면이 태블릿처럼 바형 폰 배치를 써서 콘텐츠가 시계 밑으로 들어가고 헤더가 위 끝에 붙었다.
기기 이름으로 가르면 같은 모양의 다음 기기가 나올 때마다 목록을 고쳐야 한다. 안전영역으로 가르면 목록이 없고, 레일이
있는 다음 기기도 함께 잡힌다. 아래에서는 이 배치를 `오른쪽 레일 화면` 이라 부른다.

이 판정은 iOS 에서만 쓴다(사용자 지정 2026-11-15, #1028). 안드로이드는 옆 안전영역을 판정에 쓰지 않는다. 폴드8 안쪽 화면
에뮬레이터를 세로로 돌리니 화면 구멍(카메라 컷아웃) 자리가 오른쪽 안전영역 약 52dp 로 와서 레일 배치가 켜졌다. 그 레일은 폭 64 인
세로 막대보다 좁아 막대가 콘텐츠와 겹친다.

### 결정 4. 오른쪽 레일 화면은 하단바를 세로 막대로 바꿔 오른쪽 안전영역에 놓는다 (사용자 지정)

콘텐츠가 비운 오른쪽 안전영역에 하단바를 세로로 세운다. 하단바와 그 아래 여백은 화면 아래 약 115pt 를 썼다(높이
678 의 17%). 바를 옆으로 옮기면 그 높이를 콘텐츠가 쓴다.

막대는 하단바의 칸을 그대로 세운다(사용자 지정 2026-11-15, 시안 A1). 아이콘 아래 라벨도 그대로 둔다. 가로 바의
왼쪽에서 오른쪽 순서가 막대의 위에서 아래 순서다.

| 값 | 계산 |
|---|---|
| 폭 | 64 |
| 칸 | 높이 56, 다섯 칸. 막대 높이는 56 × 5 + 3 × 2 = 286 |
| 가로 위치 | 오른쪽 안전영역의 가운데 |
| 세로 위치 | 아래쪽 안전영역 바로 위. 막대 아래 끝이 거기 닿는다 |
| 안쪽 여백 · 알약 | 여백 3. 알약은 막대 폭 − 6 = 58, 높이는 칸과 같은 56 |
| ← 원 | 알약 폭 × 48 / 66 = 42. 가로 바와 같은 비율이다 |
| 아이콘 · 라벨 | 가로 바와 같다. 아이콘 25, 간격 4, 라벨 10px |

폭 64 는 가장 긴 라벨인 `파티 스케줄` 이 알약 58 안에 들어가는 폭이다. 칸 56 은 아이콘 · 간격 · 라벨(44)에 위아래 6 씩을
더한 높이다. 가로 바는 창 폭에 비례해 치수가 바뀌지만 막대는 고정값이다. 막대가 서는 자리는 OS 가 정한 레일 폭이라
창 크기를 따라 늘어날 이유가 없다.

가로 위치를 안전영역의 가운데로 둔 것은 OS 막대의 위치가 앱에 주어지지 않기 때문이다. 앱이 아는 것은 오른쪽 안전영역의
폭뿐이다. 그래서 막대 가운데는 x 424 다. 시안은 OS 막대 가운데(x 418)에 맞춰 그렸다.

아래쪽 안전영역 바로 위에 두는 것은 가로 바와 같은 높이다. 막대 위 끝은 외부 화면에서 y 358, 가로 안쪽 화면에서 y 349 라
OS 가 그리는 시계 · 와이파이(외부 화면 y 152 까지)와 겹치지 않는다.

하위 행은 첫 칸이 ← 이고 하위가 그 아래에 선다(사용자 지정 2026-11-15, 시안 ②). 하위가 셋인 스케줄러는 다섯째 칸이
빈다. 알약이 미끄러지는 방향과 행이 바뀌는 움직임([[ADR-059]] 결정 13)은 가로 대신 세로로 움직인다. 재질과 색은 가로
바와 같다([[ADR-059]] 결정 12).

막대는 가로 바처럼 `LayerStack` 의 `layout` 이 그린다. 그래서 하위 페이지가 열리면 막대도 아래 화면과 함께 밀려 나간다.
키보드가 떠 있으면 그리지 않는 것도 같다.

### 결정 5. 오른쪽 레일 화면은 콘텐츠 위아래에 24 를 더 띄운다 (사용자 지정)

위쪽 안전영역이 0 이라 그대로 두면 헤더가 화면 위 끝에 붙는다. 아래도 하단바가 옆으로 빠지면 콘텐츠가 아래쪽 안전영역
바로 위에서 끝난다. 그래서 위아래에 24 를 더해 콘텐츠가 기기 끝에 붙지 않게 한다(사용자 지정 2026-11-15, 시안 P24).

위는 `resolveTopSafeAreaPx` 가 위쪽 안전영역에 24 를 더한 값을 낸다. 헤더 패딩, 위쪽 안전영역 페이드, 위에서 내려오는
시트(`TopSheet`)가 모두 이 값을 읽으므로 한 곳에서 더하면 함께 내려간다. 아래에서 올라오는 시트(`BottomSheet`)는 높이 상한을
인셋으로 정하는 자리라 같은 24 를 따로 더한다(사용자 지정 2026-11-15). 더하지 않으면 시트가 화면 위 끝까지 차올라 핸들이
위 끝에 붙는다. 모달은 인셋 위에 자기 여백(`MODAL_TOP_GAP_PX`)을 이미 둔다.

아래는 화면 틀(`ScreenScroll` · `EntryScroll`)만 24 를 더한다. 콘텐츠 끝 여백이 아래쪽 안전영역 + 24 이고, 콘텐츠는 그
선에서 투명해진다. 세로 막대 · ＋ · 토스트는 더하지 않는다. 시안에서 고른 자리가 아래쪽 안전영역을 기준으로 그린 자리라서다.
`resolveBottomSafeAreaPx` 에 더하면 이것들까지 24 만큼 올라간다.

### 결정 6. 오른쪽 레일 화면은 ＋ 를 콘텐츠 오른쪽 아래에 둔다 (사용자 지정)

＋ 는 레일에 넣지 않고 바형 폰처럼 콘텐츠 위에 띄운다(사용자 지정 2026-11-15, 시안 F2). 오른쪽은 콘텐츠 오른쪽 끝에서 16,
아래는 아래쪽 안전영역 + 12 다. 위치 계산(`useFabPlacement`)은 아래쪽 안전영역 + 하단바 몫 + 12 이고, 오른쪽 레일
화면에서는 하단바 몫이 0 이 된다. ＋ 를 누르면 펼쳐지는 `SpeedDial` 항목도 그 위로 쌓인다.

### 결정 7. 화면 배치 구간은 `lib/screen-layout.ts` 하나가 정하고, 앱은 창 폭 대신 콘텐츠 폭을 쓴다

`resolveScreenLayout` 이 창 폭 · 창 높이 · 오른쪽 안전영역 · 플랫폼을 받아 배치 구간과 콘텐츠 폭을 낸다. 화면마다 따로 판정하면
기준이 갈리기 때문이다. 화면은 훅 `useScreenLayout` 으로 받는다.

| 구간 | 조건 | 콘텐츠 폭 |
|---|---|---|
| `phone` | 아래에 들지 않는다. 바형 폰 · 태블릿 · 안드로이드 전부(폴드8 외부 · 안쪽 화면 포함) | 창 폭 |
| `side-rail` | iOS 이고 오른쪽 안전영역이 0 보다 크다. 아이폰 듀오의 외부 · 안쪽 화면 | 창 폭 − 오른쪽 안전영역 |

창 폭으로 치수를 계산하던 곳은 콘텐츠 폭을 쓴다. today 격자 · 인벤토리 격자 · 통계 · 모달 상한 · 입력 카드 · 팝오버와
드롭다운 위치 · 토스트가 그렇다. 창 폭을 그대로 읽으면 콘텐츠가 382 인데 466 으로 계산해 오른쪽이 레일로 넘친다.
창 전체를 덮는 것만 창 폭을 쓴다. 테마 배경 그림(`ThemeBackdrop`) · 부트 스플래시(`BootSplash`) · 드롭 연출
(`DropEffectOverlay`) · 하단바다.

시트 · 모달 · 입력 카드도 본문은 콘텐츠 폭 안에 서고, 스크림만 창 전체를 덮는다. 본문이 레일로 넘어가면 높은 시트의 오른쪽 위가
OS 막대에 가린다. 스크림이 레일을 덮지 않으면 시트가 열린 채로 세로 막대를 눌러 다른 화면으로 갈 수 있다.

앱 루트를 382 로 좁히지 않고 화면 틀마다 콘텐츠 폭을 쓴다. 세로 막대가 `LayerStack` 안에 있어야 하위 페이지와 함께
밀려 나가는데(결정 4), 루트를 좁히면 막대도 그 안에 갇힌다.

글자 배수의 상한([[ADR-063]] 결정 17)도 화면 폭 대신 콘텐츠 폭 ÷ 360 이다. 상한은 한 줄 라벨이 넘치지 않게 하려고 두었고,
글자가 놓이는 폭은 콘텐츠 폭이기 때문이다. 듀오 외부 화면의 상한은 382 ÷ 360 = 1.06 이라 글자 크기 설정 1.1 · 1.2 가 1.06
으로 들어간다.
