# ADR-050: iOS 탭 동시 탭 → 문서 리로드 → 데이터 유실 (폐기 · DEPRECATED)

> ⛔ **DEPRECATED — 폐기.** 웹뷰가 없어 «탭 동시 탭 → 문서 전체 리로드» 라는 계기 자체가 사라졌다.
> **새 구현의 근거로 인용하지 말 것.** 본문은 아래 요약으로 줄였다 — 죽은 정책이 컨텍스트에
> 실리지 않게 하기 위해서다.
>
> 🔗 **지금도 코드가 따르는 것** — 결정 2(stale SQLite 커넥션 자가복구) · 3(리로드가 죽이던 것을 닫는 경로) — `storage/sqlite/db.ts`·`storage/adapters/rn-sqlite.ts`·`storage/ports.ts`·`features/boss-profit/auto-record.ts` 가 지금도 이 방어를 건다.

## 무엇을 결정했었나 (요약)

iOS 웹뷰에서 하단 탭 두 개를 동시에 누르면 합성된 클릭이 `<a href>` 의 기본 동작을 흘려 **문서가 통째로 리로드**되고, 그 리로드가 SQLite 커넥션을 stale 하게 만들어 보스 수익 데이터가 비어 보였다. 처방 셋 — 탭바 클릭을 네이티브 캡처로 가로채기 · 커넥션 열기에 타임아웃을 걸어 자가복구 · 조회 실패를 「기록 없음」으로 오인하지 않기.
