# ADR-025+068+083+105 넥슨 로그인

> 🟢 유효
> 옛 번호: ADR-296 · ADR-318 · ADR-320 결정 3 · 4 · ADR-321 · ADR-334 결정 1 · 2 · 3 · 4
> 관련 소스: `features/auth/nexon-login.ts` · `features/auth/prune-covered-keys.ts` · `features/auth/nexon-login-enabled.ts` · `app/auth/SignInScreen.tsx` · `app/auth/ApiKeyWarningModal.tsx` · `app/auth/ApiKeySheet.tsx` · `components/molecules/NexonLoginButton/` · `native/browser.ts` · `lib/nexon-credential.ts` · `lib/covered-keys.ts` · `nexon/developer-keys.ts` · `server/nexon-auth.ts` · `storage/api-key.ts`

## 배경

넥슨 프렌즈 프로그램에 들어가면서 넥슨 Open ID 로그인(`게임 데이터 활용 로그인`)을 쓸 수 있게 됐다.
로그인하면 사용자가 API 키를 직접 발급받지 않아도 된다. 다만 Open ID 로 부를 수 있는 것은 프렌즈 경로
몇 개뿐이다. `character/basic` · 메소 · 공지 같은 나머지 경로는 여전히 API 키가 있어야 한다. 그래서
로그인이 API 키를 대신하지 않고, 두 수단을 함께 둔다.

넥슨 애플리케이션은 아직 프로덕션 승인을 받지 못한 테스트 단계다. 이 단계에서는 등록된 테스트 사용자만
로그인할 수 있다. 그래서 로그인 기능은 앱에 모두 넣어 두되, 승인이 날 때까지 화면에는 보이지 않게 꺼 둔다.

## 결정

### 결정 1. 넥슨 로그인과 API 키를 함께 둔다

기기에는 인증 수단의 목록을 저장한다(`storage/api-key.ts`). 넥슨 로그인은 0 개나 1 개, API 키는 0 개
이상이다. 둘 중 하나라도 있으면 앱이 열리고, 하나도 없으면 로그인 화면이 나온다.

- 로그인을 하나만 두는 이유는 로그인이 앱 사용자를 구분하는 기준이고, 키는 그 사용자가 쓰는 자원이기
  때문이다. 다시 로그인하면 있던 로그인을 바꾼다.
- 키는 이름(`label`)과 함께 저장한다. 키 값은 서로 비슷해 보여서 이름이 없으면 목록에서 구분하기 어렵다.
  사용자가 이름을 붙이지 않으면 빈 문자열로 두고, 앱이 이름을 지어 넣지 않는다. 같은 키를 다시 넣으면
  목록에 더하지 않는다.
- 옛 설치본이 `apiKey` 칸에 저장한 키는 새 목록이 비어 있을 때 읽어 와 목록에 올린다. 옛 칸은 지우지
  않는다. 앱을 옛 버전으로 되돌려도 키를 잃지 않게 하려는 것이다. 옛 칸은 연결 해제 때만 함께 지운다.

넥슨을 부를 때 어떤 자격을 쓸지는 `lib/nexon-credential.ts` 의 `credentialOf` 가 정한다. 로그인이 있으면
로그인을 쓰고, 없으면 첫 번째 키를 쓴다. 로그인을 붙이면 같은 계정의 키는 지워지므로(결정 4) 보통은
둘 중 하나만 남는다.

### 결정 2. 넥슨 토큰은 서버가 갖고, 앱은 서버 세션만 갖는다

`client_secret` · 액세스 토큰 · 갱신 토큰은 모두 우리 서버에 둔다. 토큰 교환에는 `client_secret` 이
필요하고, 넥슨 보안 가이드라인이 액세스 토큰을 서버에서만 다루라고 정하고 있다. 앱이 저장하는 것은 서버가
발급한 세션 하나(`NexonLoginMethod.session`)뿐이다. 옛 설치본에 남아 있는 액세스 토큰 칸은 읽을 때 버린다.

로그인 사용자의 조회는 경로에 따라 두 가지로 나뉜다. 나누는 곳은 `nexon/http.ts` 의 `routeOf` 하나다.

| 경로 | 보내는 곳 | 싣는 것 |
|---|---|---|
| 프렌즈 경로 | 우리 서버의 프렌즈 스트림. 서버가 세션으로 사용자를 확인하고 넥슨을 대신 부른다 | 세션 |
| 그 밖의 경로 | 넥슨에 직접 | 앱에 들어 있는 개발자 키 |

서버 쪽 스트림의 동작은 [[ADR-016]] 에 있다.

개발자 키는 둘이다(`EXPO_PUBLIC_NEXON_API_KEY_1` · `_2`, `nexon/developer-keys.ts`). 요청마다 번갈아 써서
한도를 두 배로 쓰고, 무효(401 · 403 · 400 `OPENAPI00005`)나 한도 초과(429)가 난 키는 그 실행 동안 빼고 남은 키만
쓴다. 앱을 다시 켜면 다시 시도한다. 키가 앱 번들에 들어 있어 꺼내 쓸 수 있고, 그러면 우리 한도가 줄어든다.
넥슨이 그 키를 막으면 로그인 사용자 모두의 프렌즈 밖 조회가 함께 멈춘다. 사용자가 이 위험을 알고 고른
방식이다.

개발자 키로 난 키 실패는 사용자의 키 탓으로 보지 않는다. `toScheduleSyncError` 는 실패에 `developerKey` 가 실려
있으면 무효와 한도 초과를 `invalidApiKey` · `rateLimited` 가 아니라 `network` 로 바꾼다. 사용자가 고칠 수 없는
실패이기 때문이다. 키 탓으로 보내면 키 재입력 안내의 확인이 어느 키를 지울지 몰라 사용자의 API 키를 모두 지운다.

### 결정 3. 로그인 창은 `openAuthSessionAsync` 로 열고, 세션은 열쇠 둘로 받는다

`features/auth/nexon-login.ts` 의 `signInWithNexon` 이 다음 순서로 진행한다.

```
앱     서버에 시작을 요청한다(POST /auth/nexon/login). 서버가 authorizeUrl 과 redeemKey 를 준다
앱     openAuthSessionAsync 로 authorizeUrl 을 연다
넥슨   로그인 · 동의
넥슨   서버의 콜백으로 code 와 state 를 보낸다
서버   토큰을 교환해 세션을 보관하고 com.mapleroutine.app://oauth/callback?receipt= 로 앱에 돌려보낸다
앱     redeemKey 와 receipt 를 서버에 넘겨 세션을 받는다(POST /auth/nexon/session)
앱     세션을 인증 수단 목록에 저장한다
```

- `redeemKey` 는 로그인을 시작한 앱만 갖고 콜백 URL 에는 실리지 않는다. `receipt` 는 앱으로 돌아올 때만
  실린다. 그래서 돌아오는 요청을 가로챈 앱도, 로그인 시작을 흉내 낸 앱도 둘 중 하나만 가지게 되어 세션을
  받을 수 없다. `state` 는 콜백을 받는 서버가 확인한다. 서버 쪽 규칙은 [[ADR-016]] 에 있다.
- 서버가 아직 콜백을 처리하는 중(`pending`)이면 1초 뒤에 다시 묻고, 30번(`REDEEM_MAX_TRIES`)까지 묻는다.
  끝까지 `pending` 이면 실패다. `gone`(404)이면 바로 실패다.
- `openAuthSessionAsync` 를 쓰는 이유는 iOS 에서 이 함수가 ASWebAuthenticationSession 을 열어, 콜백 URL 이 그
  세션으로만 돌아오기 때문이다. `Linking.openURL` 로 Safari 를 열면 같은 스킴을 등록한 다른 앱이 콜백을 받을 수 있다.
  앱 안 웹뷰로도 열지 않는다. 주소창이 보이지 않으면 사용자는 자기가 어디에 비밀번호를 넣는지 확인할 수 없다.
- 스킴 `com.mapleroutine.app` 은 iOS 의 `Info.plist`(`CFBundleURLSchemes`)와 안드로이드의
  `AndroidManifest.xml`(`intent-filter`)에 등록되어 있다.
- 사용자가 창을 닫으면 `cancelled` 이고, 아무 일도 일어나지 않는다. 안내를 띄우면 사용자는 자기가 닫았는데도
  무엇이 잘못됐는지 찾게 된다.
- 세션 저장에 실패하면 `failed` 다. 다음에 앱을 켰을 때 로그인 상태가 아니므로 성공이라고 하면 안 된다.
- 이 함수는 예외를 던지지 않고 `signedIn` · `cancelled` · `failed` 중 하나를 돌려준다. 부르는 쪽이
  화면이라서, 예외를 던지면 버튼마다 `try` 를 둬야 한다.

### 결정 4. 로그인하면 같은 계정의 API 키를 지운다

세션을 저장한 뒤 `pruneCoveredApiKeys` 가 로그인과 각 키로 `character/list` 를 불러 ocid 집합을 비교한다.
로그인의 ocid 가 키의 ocid 를 모두 포함하면 그 키를 지운다(`lib/covered-keys.ts` 의
`apiKeysCoveredByLogin`).

- 같은 계정을 두 수단으로 갖고 있을 필요가 없고, 키는 기기에 평문으로 저장되어 있어 지우는 편이 안전하다.
- 다른 넥슨 계정의 키는 지우지 않는다. 지우면 그 계정의 캐릭터를 볼 수 없게 된다.
- 어느 한쪽이 캐릭터를 하나도 주지 않았으면 지우지 않는다. 조회가 실패했을 수 있어서, 빈 집합을 모두
  포함한다고 읽으면 멀쩡한 키가 지워진다.
- 키를 지우지 못해도 로그인은 성공이다. 쓸모없는 키가 남을 뿐이고 다음 로그인 때 다시 시도한다.

### 결정 5. 로그인 버튼은 넥슨이 준 이미지 한 장을 비율 그대로 늘려 쓴다

넥슨 Open ID 검수에서 로그인 버튼 화면을 확인한다. 그래서 버튼은 이 앱의 디자인 시스템이 아니라 넥슨의
`로그인 버튼 사용 가이드` 를 따른다. 가이드는 색(`#0077FF`) · 모서리(`6px`) · 심볼 · 글꼴을 정해 두고,
글자를 일그러뜨리거나 가이드에 없는 비율로 쓰는 것을 금지한다.

- `wide-center` 이미지를 쓴다. `narrow` 는 폭이 고정이라, 폭이 꽉 찬 다른 버튼과 나란히 두면 폭이 맞지 않는다.
- `Image` 하나로 폭만 `100%` 로 정하고 높이는 정하지 않는다. 종횡비는 `naturalAspectStyle` 이 이미지의 원래
  크기에서 읽는다. 높이까지 정하면 그림이 일그러져 가이드를 어기게 된다. 712 · 96 같은 크기를 코드에 직접
  적지 않는 이유는 이미지를 바꿀 때 두 곳이 어긋나지 않게 하기 위해서다.
- 가이드는 비율을 지킨 확대와 축소를 허용한다. 그래서 넓은 화면에서 버튼이 함께 커져도 규정 위반이 아니다.
- 이미지는 `src/assets/nexon/login-button-wide-center.png`(sizeL, 712×96) 한 장이다. 받은 sizeM(356×52)은
  sizeL 의 절반 크기가 아니라 비율이 다른 버튼이어서 RN 의 `@2x` 규칙으로 묶을 수 없다. 둘 중 해상도가
  높은 sizeL 을 쓴다.
- 부품은 `components/molecules/NexonLoginButton/` 에 둔다. 넥슨의 규정을 따라야 하는 부품이라 일반 기본
  부품을 모아 둔 `atoms` 와 성격이 다르다. 스크린리더가 읽는 이름(`넥슨ID 로그인`)은 `Pressable` 에 두고
  그림은 읽지 않게 한다.

### 결정 6. 버튼은 로그인 화면과 더보기 탭 맨 위에 둔다

API 키로 이미 들어온 사용자는 로그인 화면을 다시 볼 일이 없다. `SignInScreen` 은 저장된 수단이 하나도 없을
때만 나오기 때문이다. 그래서 더보기 탭(`app/settings/SettingsScreen.tsx`) 제목 아래에도 버튼을 둔다.
설정 화면은 톱니바퀴를 한 번 더 눌러야 들어가고, 더보기 탭의 소식 아래에 두면 배너 때문에 첫 화면에서
보이지 않는다.

- 더보기 탭의 버튼은 넥슨 로그인이 없을 때만 보인다(`hasNexonLogin()`). 화면에 들어올 때마다 다시 확인하고,
  확인하기 전에는 보이지 않는다. 보였다가 사라지면 아래 소식이 한 칸 튀어 오르기 때문이다. 로그인하면
  버튼이 사라지고 소식이 다시 맨 위로 온다.
- 로그인 화면에도 둔다. 로그아웃해서 수단이 하나도 남지 않으면 로그인 화면만 보이고 탭은 보이지 않는다.
  여기에 버튼이 없으면 그 사용자는 다시 로그인할 수 없다.
- 두 버튼은 같은 스토어 동작(`signInWithNexonAccount`)을 부른다. 이 동작이 로그인 뒤에 `character/list` 를
  받아 진입 단계를 다시 판정하고(`resolveAfterSignIn`) 토스트까지 띄운다. 화면은 버튼을 숨길지만
  정한다.
- 성공하면 `넥슨 계정을 연결했어요` 토스트가 뜬다. 실패하면 `넥슨 로그인에 실패했습니다` 토스트가 뜨고,
  취소하면 아무 일도 없다. 로그인은 됐는데 캐릭터 목록을 받지 못하면 토스트 없이 앱을 열지 않는다. 로그인
  자체는 성공했으므로 실패라고 하면 사실과 다르고, 앱을 열면 캐릭터가 없는 화면이 나온다.

### 결정 7. 로그인 화면은 넥슨 로그인 하나를 앞에 세우고, API 키는 경고를 거쳐 상단 시트에서 받는다

넥슨 로그인이 주 경로이고, API 키는 되도록 쓰지 않게 한다(사용자 지정 2026-10-27, #757). 앞으로 일부 기능은
넥슨 로그인으로만 쓸 수 있게 되기 때문이다. 그래서 첫 화면에서 API 키의 비중을 최대한 낮추고, 키로 가려는
사용자에게는 경고를 먼저 보여 준다.

```
첫 화면    앱 아이콘 96px · 가운데 · 그림자
           메이플 루틴                                 24px bold
           내 메이플 스토리 스케줄 정보 조회를 위해서
           넥슨 로그인이 필요해요.                       14px · text-muted
           [ 넥슨ID 로그인 ]
           게임 데이터 활용 로그인이란? ↗                13px · primary-ink · 링크
           (화면 맨 아래) API 키로 시작하기               12px · text-muted · 글자 버튼
경고 모달  ⚠ API 키로 시작할까요?
           [🔒 일부 기능은 넥슨 로그인으로만 쓸 수 있어요]   card-inset 칸
           [앞으로 나오는 기능도 넥슨 로그인을 기준으로 만들어요.]   card-inset 칸 · text-muted
           [ 넥슨ID 로그인 ]
           그래도 API 키로 시작하기                       13px · text-muted · 글자 버튼
상단 시트  🔑 API 키로 시작하기            ⚠ 일부 기능 제한
           Nexon Open API 키           openapi.nexon.com에서 확인 ↗
           [ 입력칸 ]
           (     확인     )
           API 키 발급 방법 보기 ↗
```

첫 화면은 이렇게 둔다.

- 첫 화면에는 넥슨 로그인 하나만 크게 둔다. 아이콘 · 이름 · 설명 · 넥슨 버튼 · 소개 링크를 한 덩어리로 화면 세로
  가운데에 모은다. `API 키로 시작하기` 는 화면 맨 아래의 작은 흐린 글자 버튼이다. 키 입력칸을 첫 화면에 두면 키가
  넥슨 로그인과 같은 무게의 방법으로 보인다.
- 머리에 앱 이름 `메이플 루틴` 을 쓴다. 이름 줄이 제목이 되고 설명 두 줄은 그 아래 보조 글이 된다. 첫 화면에
  입력칸이 없어져 설명이 밀려날 자리가 없다.
- 아이콘은 96px 이고 모서리는 크기의 22.4%(22px)다. iOS 앱 아이콘과 같은 비율이라 앱 아이콘으로 보인다.
  테두리 대신 그림자로 바탕과 가른다. 아이콘 바탕과 페이지 색의 밝기가 거의 같아 경계가 필요하고, 앱은 카드 ·
  칸에 테두리를 두지 않는다([[ADR-060]] 결정 16).
- 넥슨의 `게임 데이터 활용 로그인` 소개 다섯 문장은 앱에 싣지 않는다. 넥슨 버튼이 설명 아래로 밀려나기 때문이다.
  `게임 데이터 활용 로그인이란?` 링크가 넥슨의 소개 페이지(`openapi.nexon.com/ko/data-util/introduction/`)를 연다.
  넥슨이 문구를 고쳐도 앱을 고칠 필요가 없다. 링크는 글자 폭만큼만 누를 수 있고 굵기는 `normal` 이다.

`API 키로 시작하기` 를 누르면 경고 모달(`ApiKeyWarningModal`)이 뜬다.

- 모달은 `Modal` 의 가운데 정렬 패널이다. 패널은 테두리가 없고, 다크에서는 시트처럼 표면을 한 단 올려 스크림과
  가른다(`buildSheetScopeVariables`). 게임 데이터 잠금 화면의 패널과 같은 모양이다.
- 머리 줄은 `error-tint` 원 안의 경고 삼각형과 제목 `API 키로 시작할까요?` 다. 그 아래 두 문장을 `card-inset`
  칸에 하나씩 넣는다. 첫 칸은 자물쇠 아이콘과 `일부 기능은 넥슨 로그인으로만 쓸 수 있어요` 이고, 둘째 칸은
  흐린 글자 `앞으로 나오는 기능도 넥슨 로그인을 기준으로 만들어요.` 다. 첫 칸이 자물쇠인 것은 머리 줄의 경고
  삼각형과 겹치지 않게 하려는 것이다.
- 어떤 기능을 못 쓰는지는 적지 않는다. 넥슨 로그인 전용 기능 목록이 아직 정해지지 않았고, 정해지지 않은 것을
  단정하면 거짓이 된다.
- 큰 버튼은 넥슨 로그인 버튼이다. API 키로 가려는 사용자에게도 넥슨 로그인을 한 번 더 권한다. 키로 가는 길은 그
  아래 흐린 글자 버튼 `그래도 API 키로 시작하기` 다.
- 두 버튼 모두 모달을 닫는다. 넥슨 로그인은 모달을 닫고 로그인 창을 연다. `그래도 API 키로 시작하기` 는 모달을
  닫고 상단 시트를 연다. 스크림이나 뒤로가기로 닫으면 첫 화면으로 돌아간다.

키는 상단 시트(`ApiKeySheet`. 껍데기는 `TopSheet`, [[ADR-062]] 결정 15)에서 받는다.

- 바텀시트는 키보드를 보지 않아 시트 안에 입력칸을 둘 수 없다([[ADR-062]] 결정 4). 위에서 내려오는 시트는
  키보드와 자리를 다투지 않는다.
- 머리 줄은 32px `primary-tint` 원 안의 열쇠, 제목 `API 키로 시작하기`, 오른쪽 끝의 `error-tint` 배지
  `일부 기능 제한` 이다. 경고 모달을 지나온 뒤에도 키 경로가 제한된 경로라는 것을 한 줄로 남긴다. 화면 높이와
  상관없이 같은 머리를 쓴다.
- 본문은 `ApiKeyForm` 이다. 라벨 `Nexon Open API 키` 와 같은 줄 오른쪽에 `openapi.nexon.com에서 확인` 링크를 둔다.
  입력칸은 테두리 없이 `card-inset` 으로 칠하고, 오른쪽 눈 아이콘으로 가린 키를 보이게 한다. 그 아래 `확인` 과,
  맨 아래 가운데에 `API 키 발급 방법 보기` 링크를 둔다. 발급 링크는 낮은 화면에서도 남긴다. 키가 없는 사용자에게는
  그것이 유일한 다음 걸음이다.
- `확인` 은 채운 버튼이 아니라 `tint` 다. 키 경로를 넥슨 버튼과 같은 무게로 보이지 않게 하려는 것이다.
- 키가 어디에 저장되는지 알리던 문장(`입력한 키는 이 기기에만 저장되고…`)은 걷었다(사용자 지정).
- 시트가 열리면 입력칸에 초점을 주어 키보드를 함께 올린다. 시트를 연 이유가 키를 치는 것 하나이기 때문이다.
- 저장된 키가 있으면(온보딩 중간에서 로그인 화면으로 돌아온 경우) 입력칸에 채워 둔다.
- 검증에 실패하면 시트는 그대로 두고 토스트로 알린다([[ADR-024]] 결정 10). 개발 단계 키로 막히면 개발 단계 키 모달이
  시트 위에 뜨고, 닫으면 시트로 돌아온다([[ADR-024]] 결정 4).
- 시트를 닫으면 친 키는 버린다. 키 검증이 성공하면 다음 화면으로 넘어가므로 시트를 따로 닫지 않는다.

### 결정 8. 앱이 여는 웹 주소는 인앱 브라우저로 연다 (사용자 지정)

웹 주소(`https://`)를 여는 링크는 모두 `native/browser.ts` 의 `openInAppBrowser` 로 연다. 그 안에서
`expo-web-browser` 의 `openBrowserAsync` 를 부른다. iOS 는 SFSafariViewController, 안드로이드는 Chrome Custom
Tabs 다. 같은 크기와 색의 링크 가운데 어떤 것은 앱을 떠나고 어떤 것은 떠나지 않으면, 누르기 전에는 어느 쪽인지
알 수 없다. 그래서 앱 전체에서 같은 방식으로 연다.

| 링크 | 파일 |
|---|---|
| `게임 데이터 활용 로그인이란?` | `app/auth/SignInScreen.tsx` |
| `openapi.nexon.com에서 확인` · `API 키 발급 방법 보기` | `app/auth/ApiKeyForm.tsx` |
| `발급 방법 자세히 보기` | `app/auth/DevelopmentStageKeyModal.tsx` |
| 개인정보 처리방침 | `app/settings/SettingsAboutScreen.tsx` |
| 공지의 `자세히 보기` · 공지 본문 안 링크 | `app/settings/SettingsNoticeDetailScreen.tsx` · `NoticeBlocks.tsx` |

- 웹 주소가 아닌 것은 인앱 브라우저가 열 수 없어 그대로 `Linking` 으로 연다. `문의하기`(`mailto:`) ·
  `개발자 응원하기(앱 리뷰)`(스토어 앱) · 알림 설정의 앱 설정 이동(`Linking.openSettings()`) · 스토어 업데이트
  이동이다.
- 인앱 브라우저를 못 열면 시스템 브라우저(`Linking.openURL`)로 넘긴다. 안드로이드에 Custom Tabs 를 받는 브라우저가
  없으면 `openBrowserAsync` 가 거절하는데, 그대로 삼키면 눌러도 아무 일이 안 일어난다. 시스템 브라우저도 못 열면
  조용히 끝난다. 화면은 그대로 서 있어야 해서다.
- iOS 에서 창이 이미 떠 있으면 `openBrowserAsync` 는 거절하지 않고 `locked` 로 끝난다. 그래서 두 번 눌러도 Safari 가
  따로 열리지 않는다.
- iOS 에서는 창을 카드 시트(`presentationStyle: pageSheet`)로 띄운다(사용자 지정). 넥슨 로그인 창
  (`ASWebAuthenticationSession`)이 카드 시트로 뜨므로, 같은 앱에서 웹 문서를 여는 창 둘의 모양을 맞춘다.
  라이브러리 기본값은 화면 전체를 덮는 `overFullScreen` 이다. 로그인 창의 확인 창과 인앱 브라우저 아래의 버튼
  막대는 시스템이 정해 맞출 수 없다. 안드로이드는 둘 다 Custom Tabs 라 따로 할 것이 없다.
- 창의 상단 막대는 지금 테마의 `bg`(`toolbarColor`), 버튼은 `primaryInk`(`controlsColor`)로 칠한다. 앱 머리와 같은
  바탕이라 창이 앱의 하위 화면처럼 이어져 보인다. 테마는 누를 때의 것을 쓴다.
- 안드로이드는 상단 막대 색이 바뀌지 않는다. `expo-web-browser` 57.0.3 의 안드로이드 코드가 `toolbarColor` 를 상단
  막대가 아니라 보조 막대 색(`setSecondaryToolbarColor`)으로 넣기 때문이다. 패치는 하지 않았다(사용자 지정). 라이브러리를
  고치면 네이티브 지문이 바뀌어 OTA 로 낼 수 없다.
- 창이 열리지 않았을 때의 오류 화면은 우리가 그리지 않는다. 오프라인이면 인앱 브라우저가 자기 오류 페이지를 띄운다.
- `app/` 에서 `expo-web-browser` 를 직접 부르지 않고 `native/` 어댑터를 거친다([[ADR-004]]).
- 바깥 화살표 아이콘(`ExternalLinkIcon`)은 그대로 둔다. 없으면 링크라는 표시가 색 하나만 남는데,
  `primary-ink` 는 밝은 테마에서 바탕과의 대비가 낮아 누를 수 있다는 것이 잘 보이지 않는다.
- 링크에는 `role="link"` 를 준다. 인앱 브라우저로 열어도 목적지는 웹 문서라서 스크린리더가 링크로 읽어야 한다.

### 결정 9. 넥슨 로그인 입구는 상수 하나로 끄고 켠다. 지금은 켜져 있다

프로덕션 승인 전에는 등록된 테스트 사용자만 로그인할 수 있다. 입구를 켜 둔 채 내보내면 나머지 사용자가 화면에서
가장 큰 버튼을 눌러 실패한다. 그래서 승인 전에는 `features/auth/nexon-login-enabled.ts` 의 `NEXON_LOGIN_ENABLED`
를 `false` 로 두었다. 승인이 나서 지금은 `true` 다. 환경 변수(`EXPO_PUBLIC_*`)로 두지 않는 이유는 OTA 번들을 만드는 셸 환경에 따라 값이 바뀔 수
있기 때문이다.

꺼져 있으면 다음과 같다.

- 로그인 화면에서 넥슨 버튼과 소개 링크, 맨 아래 `API 키로 시작하기` 를 모두 빼고, 머리 둘째 줄은
  `API 키 입력이 필요해요.` 로 바꾼다. 로그인을 언급하면 사용자가 없는 방법을 찾게 된다.
- 더보기 탭 맨 위 버튼도 보이지 않는다.
- 키 입력(`ApiKeyForm`)은 경고 모달과 상단 시트를 거치지 않고 첫 화면 머리 아래에 펼쳐 둔다. 경고와 시트는 넥슨
  로그인이 있을 때 키 경로를 낮추려고 둔 것이다. 넥슨 로그인이 없으면 키가 유일한 방법이라 낮출 이유가 없다.
- 이미 로그인한 기기에서만 보이는 것(계정 및 데이터 화면의 `넥슨 로그아웃`, 로그인 만료 모달)은 그대로 둔다.
  꺼진 빌드에서는 새로 로그인할 수 없으므로 일반 사용자에게는 보이지 않는다.

켤 때는 이 상수만 `true` 로 바꾸는 OTA 를 낸다. OTA 는 같은 지문의 바이너리에만 적용되므로, 켤 때 필요한 네이티브
설정은 바이너리에서 빼지 않는다. iOS `CFBundleURLSchemes` · 안드로이드 `intent-filter` · `expo-web-browser` ·
`SceneDelegate` 가 콜백 URL 을 `RCTLinkingManager` 로 넘기는 코드가 그것이다. 로그인 흐름 코드
(`nexon-login.ts` · `server/nexon-auth.ts` · `NexonLoginButton`)도 번들에 그대로 둔다.

### 결정 10. 로그아웃은 넥슨 로그인만 지우고, 연결 해제와 따로 둔다

계정 및 데이터 화면(`SettingsAccountDataScreen`)의 `넥슨 로그아웃` 은 넥슨 로그인이 있을 때만 보인다. 누르면
확인 모달(`SignOutConfirm`)을 띄우고, 확인하면 `signOutNexonLogin` 이 다음 순서로 진행한다.

1. 서버 세션을 거둔다(`revokeNexonSession`). 기기에서 지우기 전에 해야 세션 값을 아직 갖고 있다. 실패해도
   계속한다. 기기에서 지우는 일이 더 중요하고, 서버 쪽은 갱신 토큰 수명이 지나면 정리된다.
2. 기기에서 넥슨 로그인을 지운다(`clearNexonLogin`). API 키와 추적 목록 · 기록 · 설정은 남는다.
3. 남은 수단이 없으면 로그인 화면으로 보낸다. 다른 넥슨 계정의 API 키가 남아 있으면 앱은 그 키로 계속 쓴다.
   [[ADR-024]] 결정 7 과 같은 규칙이다.

| | 지우는 것 | 남기는 것 |
|---|---|---|
| 로그아웃 | 넥슨 로그인(서버 세션 포함) | API 키 · 앱 데이터 |
| 연결 해제 | 인증 수단 전부(`clearAuthConfig`) | 앱 데이터 |

- 로그아웃은 되돌릴 수 있지만 확인을 한 번 받는다. 다시 로그인하려면 창을 열고 넥슨을 거쳐야 해서, 실수로
  눌렀을 때 드는 수고가 작지 않다.
- 확인 모달의 주 버튼은 `로그아웃` 이고 제목은 `로그아웃할까요?` 다. 되돌릴 수 없는 연결 해제 모달은 `취소` 가
  주 버튼이라 이 점이 다르다. 두 항목이 같은 화면에 있어서 문구도 다르게 해야 무엇을 눌렀는지 알 수 있다.
- 로그아웃 줄은 따로 카드 하나에 둔다. `캐시 데이터 삭제` · `연결 해제` 처럼 빨간 글자로 표시하는 위험한
  항목의 카드에는 넣지 않는다. 로그아웃은 되돌릴 수 있기 때문이다.
- 둘을 하나로 합치지 않는다(사용자 지정). 지금은 다른 넥슨 계정의 키가 남는지만 다르지만, 나중에 붙일 기능을
  위해 나눠 둔 것이다.

## 번호 기록

- ADR-025 (2026-10-19): 옛 ADR-296 · 318 · 320 · 321 · 334 를 합쳐 처음 작성

  테마에 맞춘다. iOS 는 로그인 창처럼 카드 시트로 띄운다(#634)
