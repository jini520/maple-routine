# ADR-343: 서버로 못 보낸 것은 대기 표 하나가 든다. 종류마다 다른 것은 함수 둘이다

> ⚪ 미구현 · 2026-10-08 · 설계 · 사용자 지정

**관련**: [[ADR-299]](결정 1 이 올라갈 범위를 적었고 대가가 재전송 대기열을 요구했다) ·
[[ADR-342]](첫 종류가 드롭 가격이다. 그 문서가 이 장치를 쓴다) · [[ADR-340]](서버 쪽 사람 표) ·
[[ADR-003]](`features/*` 는 저장소에 직접 닿지 않는다)

## 맥락

### 올라갈 것이 여러 종류다

[[ADR-299]] 결정 1 이 범위를 적었다.

> 넥슨 API 로 받아 앱이 가공한 데이터는 전부 대상이다. **보스 일간·주간·월간 기록과 가계부**가
> 여기 든다.

드롭 가격([[ADR-342]])은 그중 첫 종류다. #507 과 #611 도 같은 통로를 쓴다. 종류마다 대기 장치를
따로 만들면 같은 코드가 여러 벌이 된다.

### 전송은 사용자 동작 자리에서 한 건이다

훑어서 보내지 않는다([[ADR-342]] 결정 4). 사용자가 값을 저장하는 순간 그 한 건이 나간다. 그래서
**대기 표가 드는 것은 못 보낸 것뿐**이고 평소에 비어 있다.

### 기록 표에 전송 상태를 두면 안 된다

처음에는 기록 행에 `sent_at` · `attempts` 를 두려 했다. 사용자가 거뒀다(2026-10-08).

> 드롭 기록 데이터의 관점에서 서버에 전송 시간과, 시도 횟수는 불필요한 값이잖아

서버 `notices` 는 `sent_at` 을 행에 들지만 **공지는 보내기 위해 존재한다.** 드롭 기록은 사용자 자기
기록을 위해 존재하고 전송은 거기 얹힌 일이다. 실무로도 `RecordedDrop` 에 칸이 둘 늘면 그것을 만드는
다섯 자리가 다 들고 다녀야 한다([[ADR-342]] 대가).

## 결정

### 결정 1. 표 하나가 할 일만 든다. 성공하면 행을 지운다

```sql
CREATE TABLE IF NOT EXISTS server_sync_queue (
  id          TEXT    NOT NULL,          -- uuid. SQLite 가 만든다([[ADR-342]] 결정 1)
  kind        TEXT    NOT NULL,          -- 어느 종류의 기록인가
  record_id   TEXT    NOT NULL UNIQUE,   -- 그 기록의 uuid
  attempts    INTEGER NOT NULL DEFAULT 0,
  last_error  TEXT,
  created_at  TEXT    NOT NULL,
  PRIMARY KEY (id)
)
```

할 일만 들어서 표 자체가 목록이 된다. 부분 인덱스가 필요 없다.

**`UNIQUE` 는 `record_id` 한 칸이다.** uuid 는 표를 가로질러 유일하므로 `kind` 를 엮으면 유일성이
안 늘고, 같은 기록에 행이 둘 생길 수 있는 상태만 만든다.

**한 기록에 대기 행은 하나다.** 같은 기록을 여러 번 고쳐도 행 하나이고, 보낼 때 현재 값을 읽으므로
마지막 값이 간다(결정 4).

### 결정 2. 작업 종류는 적지 않는다. 원본의 유무로 파생한다

`'upsert' | 'delete'` 를 칸으로 두지 않는다. **원본이 있으면 올리기이고 없으면 지우기**이므로 적을
이유가 없다. 적으면 지워진 기록에 올리기가 남는 상태가 표현 가능해지고, 제약으로는 못 막는다.

`kind` 는 다르다. **파생되지 않는다.** uuid 만 보고는 어느 표를 열어야 하는지 알 수 없다.

### 결정 3. 종류마다 함수 둘을 등록한다

```
kind 마다
  읽기   (recordId) => 보낼 값 | null      null 이면 서버에서 지운다
  보내기 (값 또는 지우기) => Promise<void>
```

훑는 고리는 종류를 모른다.

```
표의 행마다
  그 kind 의 읽기 함수를 부른다
    값이 오면  → 보내기
    null 이면  → 삭제 요청
  성공 → 행을 지운다
  실패 → attempts += 1, 5 가 되면 행을 지운다
```

**삭제 판정이 종류 안에 있다.** 드롭 가격은 `원본이 없거나 price_state 가 'entered' 가 아니다` 를
`null` 로 답한다. 다음 종류가 다른 조건을 써도 고리는 안 바뀐다.

레지스트리 모양은 `app/today/widgets/registry.ts` 가 선례다. 위젯마다 존재 · 크기 · 목적지를 한
자리에 모은다.

### 결정 4. 값은 표에 담지 않는다

`record_id` 만 담고 보낼 때 원본에서 현재 값을 읽는다. 담으면 그 사이에 또 고친 경우 **중간 값이
서버로 간다.** 서버는 마지막 값만 두므로 의미가 없다.

### 결정 5. 앱을 켤 때 백그라운드로 훑고 5회까지다. 네트워크가 없으면 세지 않는다 (사용자 지정)

첫 화면을 막지 않는다. `attempts` 가 5 가 되면 그 행을 버린다. 안 버리면 못 보내는 건이 영원히
재시도된다.

버려도 되는 근거는 사용자가 적었다(2026-10-08). **서버가 값을 모으는 목적이 통계라 한두 건이 빠지는
것은 문제가 아니다.** 기기의 기록은 그대로 남는다.

**네트워크가 없을 때는 `attempts` 를 올리지 않는다**(사용자 지정 2026-10-08). 올리면 비행기 모드로
앱을 다섯 번 켠 사용자가 그동안 쌓인 것을 **전부** 잃는다. 그것은 한두 건이 아니라 오프라인이던
기간의 전부다.

가르는 기준은 **응답이 왔는가**다.

| | 센다 |
|---|---|
| `fetch` 가 던졌다 (연결 실패 · 타임아웃) | 안 센다. 다음 회차에 그대로 다시 시도 |
| 응답이 왔다 (상태 코드가 무엇이든) | 센다. 서버가 답했으니 요청 자체에 문제가 있을 수 있다 |

**기존 `src/server/*.ts` 의 모양을 베끼면 안 된다.** `settlement.ts` · `notices.ts` 는 `catch` 와
비-200 을 **둘 다 `null` 로** 합친다. 조회에서는 앱이 둘에 같은 일을 하므로 맞는 선택이지만, 여기서는
그 구분이 유일한 판정 재료다.

### 결정 6. 고리와 레지스트리는 `features/` 에 있고 원본은 `storage/` 를 거친다

[[ADR-003]] 의 경계다. 고리가 SQLite 를 직접 열면 계층이 거꾸로 선다. 읽기 함수는 그 종류의
`storage/` 어댑터를 부른다.

## 대가

- **서버에 없는 것에 삭제 요청이 한 번 나갈 수 있다.** 전송이 실패한 상태에서 그 기록을 지우면, 훑을
  때 원본이 없어 삭제로 읽힌다. 서버는 그 `record_id` 를 못 찾고 아무것도 안 한다. 요청 하나가
  낭비되고 그걸 막으려면 결정 2 를 되돌려야 한다.
- **종류를 레지스트리에 안 더하면 그 종류는 조용히 안 나간다.** 표에 행은 쌓이고 읽기 함수가 없어서
  처리되지 않는다. `app/today/widgets/registry.ts` 와 같은 함정이고, 그쪽은 테스트가 지킨다
  (`lib/today/widget-layout.ts` 의 검증). 여기도 같은 테스트가 필요하다.
- **부팅에 작업이 하나 는다.** 지금 `boot.ts` 가 하는 일은 포트 꽂기뿐이다.
- **네트워크가 끝까지 없으면 행이 영원히 남는다.** 결정 5 가 그때 `attempts` 를 안 세기 때문이다.
  표가 무한히 커지지는 않는다 - 한 기록에 행 하나이고 기록이 지워지면 다음 회차가 삭제로 처리해
  비운다. 다만 영구 오프라인 기기에서는 그 삭제도 못 나간다.
- **표가 기록 표와 끊어져 있다.** FK 가 없으므로 기록을 지운 뒤 대기 행이 남는 것이 정상 동작이고
  (그게 삭제 신호다), 반대로 **다 처리된 기록의 대기 행이 남아 있으면 그것을 알아낼 길이 없다.**
  행을 지우는 자리를 한 곳에 모아야 한다.

## 기각

- **기록 표마다 전송 상태 칸을 둔다.** 전송 시각과 시도 횟수는 그 기록의 값이 아니다. 사용자 지정으로
  기각했다(맥락).
- **값을 표에 담는다.** 중간 값이 서버로 간다(결정 4).
- **작업 종류를 칸으로 적는다.** 파생되는 값이고, 적으면 잘못된 조합이 표현 가능해진다(결정 2).
- **종류마다 대기 표를 따로 둔다.** 같은 코드가 여러 벌이 된다(맥락).

## 열린 질문

착수 전에 답한다.

- **버린 것을 사용자에게 알리는가.** 알리면 사용자가 할 수 있는 일이 없고, 안 알리면 조용히 사라진다.
- **다음 종류가 무엇인가.** [[ADR-299]] 가 보스 기록과 가계부를 적었지만 순서는 #507 이 정한다.
- **훑는 중에 앱이 꺼지면.** `attempts` 가 오른 채 남는다. 그 회차를 시도로 셀지.
