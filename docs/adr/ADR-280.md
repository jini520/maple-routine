## 맥락

이슈 #430(지출 줄 표식을 시트 타일의 그림으로)을 설계하다 드러났다. 기록에서 시트 타일을 되짚는 길이 이름
글자 비교뿐이었다. 기록에도 카탈로그에도 항목을 가리키는 id 가 없다. 사용자가 이름으로 찾는 곳을 **모두**
key 로 바꾸고, v1.0.10 2단계보다 먼저 하기로 정했다(2026-09-15).

조사한 지금 모양이다(2026-09-15, 커밋 `b6bfd858`).

이 모양이 낳는 문제는 넷이다.

- **이름을 바꾸면 옛 기록이 그림과 되짚기를 잃는다.** 그래서 이름을 바꿀 때마다 기록을 옮기는 SQL 을 더해
  왔다. 지출 다섯(`MIGRATE_SHOP_CATEGORY_RENAME` 등)과 메이린 보스 둘(`MIGRATE_MEIRIN_*`)이고, 버전 없이
  부팅마다 돈다.
- **같은 이름을 곳마다 다르게 비교한다.** 완전 일치, 공백 제거, NFC 정규화, 접두어를 뗀 앞부분 일치가 섞여
  있다. `scheduler-merge.ts` 는 한 흐름 안에서 공유 범위는 공백을 무시하고 원장 키는 원문으로 써서, 띄어쓰기가
  다르면 같은 컨텐츠가 두 번 들어갈 수 있다.
- **앱이 만든 이름을 거꾸로 읽는다.** 에픽던전 리워드 기록 `하이마운틴 EXP 2단계, 솔 1단계` 는 카탈로그의 어떤
  항목 이름과도 같지 않아 `parseSpendRewardName` 이 문법을 풀어야 한다.
- **보이는 글자와 열쇠가 한 칸을 같이 쓴다.** 지출 기록의 `item` 은 가계부 줄 제목이면서 카탈로그 조회 열쇠다.

### 결정 1. key 는 영문 snake_case 다

예: `black_mage`, `high_mountain`, `magical_one_hand_attack_scroll`. 장비 레벨 표의 `key` 467개가 이미 이
모양이라 그대로 쓴다.

보스 `portraitSlug` · 사냥 지역 `slug` · 퀘스트 `backgroundSlug` 는 **그림 열쇠로 남기고** 신원 key 를 따로
적는다. 그림 열쇠는 여러 신원이 같이 쓸 수 있어서다. 예를 들어 `roadOfVanishing` 을 세 컨텐츠가 쓴다.

### 결정 2. 묶음마다 마스터 표 하나가 key · 이름 · 그림을 든다

이름과 그림 파일 이름은 마스터 표에만 적는다. 다른 데이터 파일(드롭 표 · 고가 목록 · 상자 파일 · 가격표 ·
카탈로그 · 지역 표)은 key 로 가리킨다. 코드 안의 이름 표(`ITEM_ICON_BY_LABEL` · `CASHBOOK_ROW_ICON_BY_KEY`
· `EPIC_DUNGEON_BACKGROUND_SLUGS` 등)도 마스터 표로 옮긴다.

- 이유: 이름 하나를 바꾸는 일이 한 줄이 되고, 파일끼리 이름이 어긋날 자리가 없어진다. 지금은 드롭 아이템 이름
  77개가 파일 다섯에 반복해 적혀 있다.
- 대가: 사용자가 패치 때 드롭 표 같은 파일을 손으로 고칠 때 이름 대신 key 를 읽고 적는다. 모든 참조 key 가
  마스터 표에 있는지는 테스트가 지킨다.
- key 는 [[ADR-006]] 이 말하는 게임 수치가 아니다. 그래도 이름과 key 의 짝을 새로 적을 때는 사용자에게 보여
  확인받는다.

### 결정 3. 기록은 key 칸을 더하고, 화면은 key 로 찾은 표의 이름을 보인다

SQLite 기록과 Preferences 값에 key 칸을 더한다. 기존 이름 칸은 **그때의 이름**으로 남긴다. 화면은 key 로
마스터 표를 찾아 지금 이름을 보이고, 표에 없는 key 면 저장된 이름을 보인다.

- 예: 카탈로그에서 `미호로이드 교환권` 을 `미호로이드` 로 바꾸면 옛 기록도 `미호로이드` 로 보인다. 이름을 바꿀
  때 기록을 옮기는 SQL 이 더는 필요 없다.
- 기본키에 이름이 든 보스 표 셋은 기본키를 key 로 다시 짠다. SQLite 는 기본키를 바꿀 수 없어 표를 다시 만든다.
  `rebuildIncomeRecords`(`storage/sqlite/db.ts`)가 선례다.

### 결정 4. key 를 못 얻으면 key 는 비우고 원문 이름을 지킨다

경우는 셋이고 셋 다 같게 다룬다.

- 마스터 표에서 못 찾는 옛 기록. 예: 슬롯이 없는 옛 이름 `익셉셔널 해머`, 표에서 빠진 `루인 포스실드` 드롭,
  이름이 사라진 사냥터
- 넥슨 API 가 준 모르는 이름. 예: 새 보스 · 새 컨텐츠가 나온 직후 데이터를 아직 못 고쳤을 때
- 사용자가 직접 친 이름. 예: 아이템 구매 · 기타 · 아이템 판매

key 는 `null` 이고 화면에는 원문 이름이 선다. 그림은 없고, key 가 필요한 판정(가격 · 드롭 후보 · 고가 등)에서는
빠진다. 이관 때 못 찾았다고 지우지 않는다.

### 결정 5. 이관은 DB 버전 번호로 한 번씩 돈다

SQLite 는 `PRAGMA user_version`, Preferences 는 버전 키에 이관 단계를 적는다. 아직 안 돈 단계만 차례로 한 번
돌린다.

- 이유: 순서가 보장된다. 드롭 기록은 key 를 채운 뒤에야 획득 판정(`pruneUnobtainableDrops`)을 돌려야 한다. 먼저
  돌면 못 찾은 이름을 거짓 기록으로 지울 수 있다.
- 이유: key 를 못 찾아 `null` 로 둔 행을 부팅마다 다시 찾지 않는다.

### 결정 6. 다시 받을 수 있는 캐시는 옮기지 않고 비운다

`schedulerCache:{ocid}` 와 `scheduleProbe:{ocid}` 는 key 로 옮기지 않고 비운다. 업데이트 뒤 첫 실행이 스케줄을
다시 조회하고, 조회 원장은 14일 창을 다시 채운다.

- 대가: 그 첫 실행은 API 호출이 한 번 늘고, 캐시로 먼저 그리던 화면이 비어 있다가 선다.
- 수동 추적(`manualTrackedContent`)과 공유 진행(`worldSharedProgress` · `accountSharedProgress`)은 key 로 옮긴다.

### 결정 7. 넥슨 API 이름은 한 규칙으로, 한 자리에서 key 로 맞춘다

마스터 표가 API 이름(과 별칭)을 든다. 모든 묶음이 **NFC 정규화 뒤 공백을 지우고 완전히 같은지** 하나로 key 를
얻는다. 맞추는 자리는 응답을 앱 모양으로 바꾸는 곳(`nexon/*/normalize.ts` 쪽)이고, 그 뒤로는 key 만 쓴다.

- 지금은 보스는 공백 제거(API `검은 마법사` / 데이터 `검은마법사`), 드롭은 NFC, 컨텐츠는 완전 일치 · 공백
  제거 · 앞부분 일치가 섞였고, 장비는 공백 제거, 월드는 완전 일치다.
- 퀘스트 지역처럼 접두어를 뗀 앞부분 일치로 여러 컨텐츠를 묶던 것은 컨텐츠마다 마스터 표에 줄을 두어 푼다.

### 결정 8. 순서는 손입력 가계부, 보스 드롭 아이템, 보스, 컨텐츠 · 강화 · 월드 다

묶음마다 문서, 테스트, 구현, PR 하나다.

- 앞의 둘이 먼저인 것은 v1.0.10 2단계가 기다려서다. #430(지출 줄 그림)은 가계부 묶음에, #429(판매 줄을 펼친
  판의 아이템 그림)는 드롭 묶음에 기댄다.
- 대가: `boss_drop_records` 는 기본키에 보스 이름이 들어 있어 보스 묶음이 표를 다시 만든다. 기본키는
  `(ocid, boss, difficulty, period_key, drop_index)` 이고 아이템 이름은 안 든다(2026-09-15 드롭 묶음 조사로 정정.
  처음에는 아이템 이름도 든다고 적어 두 번 다시 만든다고 했다). 그래서 드롭 묶음은 칸만 더한다.

### 결정 9. key 는 한글 이름을 영어로 번역해 만든다 (2026-09-15, 사용자 결정)

예: `지하 선로1` 은 `underground_track_1`, `놀라운 긍정의 혼돈 주문서 60%` 는 `amazing_positive_chaos_scroll_60`.
Claude 가 초안을 만들고 사용자가 확인한다. 묶음 #443 은 검토 페이지에서 확인한다.

- 이유: key 만 보고도 무엇인지 알 수 있다. 로마자 표기(`jiha_seollo_1`)는 기계적으로 만들 수 있지만 길고 읽기 어렵다.
- 대가: 게임 공식 영문 표기와 다를 수 있다. key 는 화면에 안 보이는 신원이라, 정확한 번역보다 한 번 정한 뒤 바뀌지
  않는 것이 중요하다.
- 다른 상위에서 이름이 겹칠 수 있는 하위는 상위 key 를 앞에 붙인다. 사냥터는 `지역 key` + `_` + 번역이다(예:
  `reverse_city_underground_track_1`). 사냥 지역 key 는 지금의 지역 `slug` 를 snake_case 로 옮기고 앞의 `the_` 를 뺀
  것이다.

### 결정 10. 손입력 가계부 묶음은 이렇게 옮긴다 (이슈 #443)

사용자가 정한 것은 둘이다(2026-09-15). 에픽던전 리워드 기록은 **한 줄을 그대로 두고 형태별 항목 key 를 한 칸에**
담는다. 사냥터 key 는 **이름을 번역**해 만든다(결정 9). 나머지는 결정 1 ~ 7 을 이 묶음에 적용한 설계다.

**마스터 표**

| 대상 | 자리 | 드는 것 |
|---|---|---|
| 지출 갈래 6 · 수익 갈래 3 · 아이템 구매 종류 3 · 에픽던전 형태 2 | 코드 표(`src/lib/cashbook/categories.ts`) | key · 이름 · 시트 카드 그림 · 형태의 짧은 이름(`EXP` · `솔`) |
| 지출 묶음 11 · 타일 32 · 항목 45 | `src/data/spend-catalog.json` | `groups`: key 마다 이름 · `active`. `tiles`(새 칸): key 마다 이름 · 그림(아이템 그림 파일 또는 지역 아이콘). `items`: key · 이름 · 타일 key · 묶음 key · 갈래 key 와 지금의 가격 칸 |
| 사냥 지역 21 · 사냥터 408 | `src/data/hunting-grounds.json` | 지역과 사냥터마다 `key` |

- 갈래 · 종류 · 형태를 코드 표에 두는 것은 코드가 이 값으로 폼을 가르는 고정 목록이라서다. TS 표면 key 가 타입이
  되어, 없는 갈래를 적으면 타입 검사가 잡는다.
- 코드 안의 이름 표를 옮기고 지운다. `ITEM_ICON_BY_LABEL` · `MAP_ICON_BY_LABEL` 은 `tiles` 로, 두 시트의
  `CATEGORY_ICON_FILES` 는 갈래 표로, `FORM_SHORT_NAMES` 는 형태 표로 간다.
- `CASHBOOK_ROW_ICON_BY_KEY` 의 손입력 줄 열쇠는 기록 종류와 갈래 key 로 나눈다(`income:hunting` · `spend:buff`). 수익
  `기타` 와 지출 `기타` 는 갈래 key 가 둘 다 `etc` 라서 기록 종류를 앞에 붙인다. 보스 · 강화 줄의 열쇠는 그 묶음이 옮길 때까지 그대로 둔다.
- 단계(`tier`)와 축 값(`options`)은 key 를 두지 않는다. 카탈로그 항목마다 이미 적혀 있어 항목 key 하나로 되찾기
  때문이다. 기록은 고른 항목 key 만 저장한다.
  - 수정 시트는 항목 key 로 카탈로그 항목을 찾아 그 항목의 타일 · `tier` · `options` 로 선택을 되살린다. 예:
    `premium_accessory_attack_scroll_100` 이면 타일 `프리미엄 악세` 가 열리고 `공격력` 이 골라진다. 에픽던전 리워드는
    `form_item_keys` 의 항목마다 `tier` 를 꺼내 형태별 단계를 고른다.
  - 지금 `restoreChoice`(`CatalogForm.tsx`)도 같은 길이다. 항목을 찾는 열쇠가 이름에서 key 로 바뀔 뿐이다. 그래서
    `공격력` 이라는 단계 글자를 카탈로그에서 바꿔도 옛 기록의 선택이 되살아난다.

**기록 칸**

| 표 | 더하는 칸 | 뜻 |
|---|---|---|
| `spend_records` | `category_key` | 갈래 key |

  `legacySpendKeysOf` 는 이관만 쓴다.
- `lastHuntSelection` 은 `{ ocid, groundKey }` 로 바꾼다. 이관은 이름으로 사냥터를 찾아 key 로 옮기고, 못 찾으면
  지운다. 사냥 기록을 한 번 더 적으면 다시 생기는 값이라서다. 옮기는 자리는 `getLastHuntSelection` 이 옛 모양을
  읽을 때다. 옮긴 값을 새 모양으로 다시 적고 못 찾은 값은 지우므로 한 번만 돈다.

- 버전 1: 부팅마다 돌던 이름 이관 SQL 일곱(지출 다섯 · 메이린 보스 둘)을 한 번 돌리고, 부팅마다 도는 자리에서 뺀다.

이름 그대로 둔다.

### 결정 11. 보스 드롭 아이템 묶음은 이렇게 옮긴다 (이슈 #444)

사용자가 정한 것은 넷이다(2026-09-15).

- **같은 아이템은 key 하나다.** 루시드 하드에서 직접 고른 `몽환의 벨트`(slot `벨트`)와 칠흑 장신구 상자에서 나온
  `몽환의 벨트`(slot 없음)가 같은 key 다. `slot` 과 `ring_level` 은 key 에 넣지 않고 지금 칸에 둔다. 그림과 고가 판정이
  지금도 이름만 보고 slot 을 안 봐서 결과가 같다.
- **반지 31종과 `기타` 도 마스터 표 하나에 넣는다.** `기타`(백옥 상자 11종 밖의 반지를 묶어 적는 칸)도 key 를 갖는다.
  key 가 없으면 결정 4 대로 그림이 사라져서다.
- **key 를 못 찾은 드롭 기록은 획득 판정 없이 남긴다.** 결정 4 의 `못 찾았다고 지우지 않는다` 를 드롭에도 그대로 쓴다.
- **코드에 박힌 이름 판정 넷은 코드에 두고 key 로 적는다.** 데이터 파일 모양이 늘지 않는다.

**마스터 표**: 새 파일 `src/data/drop-items.json` 이다. `item-icons.json` 을 대신한다.

| 칸 | 드는 것 |
|---|---|
| `items` | key · 이름 · 그림 파일(`iconFile`, 없을 수 있다). 드롭 표의 이름 77(`misc` 의 `태초의 정수` 포함) · 반지 31 · 기타 1 |
| `sets` | key · 이름. 드롭 표의 `set` 값 넷(`칠흑의 보스 세트` 등) |

- 다른 파일은 key 로 가리킨다.
  - `item-drop-table.json`: 줄의 `name` 이 `item`(아이템 key)이 되고 `set` 이 세트 key 가 된다. `slot` · `note` ·
    `amount` · `from` · `until` 은 그대로다.
  - `boss-ring-boxes.json` · `accessory-boxes.json`: 상자의 `name` 과 내용물의 `name` 이 `item`(아이템 key)이 된다.
    반지 그림(`iconFile`)은 마스터 표로 옮긴다.
  - `valuable-drops.json`: `items` 가 아이템 key 목록, `sets` 가 세트 key 목록이 된다.
  - `item-icons.json` 은 지운다. 반지 그림 표(`boss-ring-boxes.json` 의 `iconFile`)와 코드의 `iconByName['기타']`
    (`asset-lookup.ts`)도 마스터 표로 옮긴다. 그림을 찾는 표가 셋에서 하나가 된다.
- `slot` 은 key 를 두지 않는다. 기록이 드롭 표의 글자를 복사해 두는 칸이고 어떤 판정도 안 읽는다. slot 별 그림
  (`iconFileBySlot`)을 받던 길은 데이터가 0건이라 걷는다.
- 코드의 이름 상수는 key 가 된다.
  - `DROP_PRICE_FAB_ITEMS`(가격 입력 버튼의 그림 셋) · `SOL_ERDA_ENERGY_NAME`(솔 에르다의 기운 그림 나누기) ·
    `'백옥의 보스 반지 상자'`(이름을 붙이는 반지의 기준 상자)는 key 로 적는다.
  - `includes('연마석')`(레벨이 없는 상자 내용물)은 연마석 key 둘(`생명의 연마석` · `신념의 연마석`)의 목록이 된다.
    이름 일부로 가르면 key 로 바꾼 뒤에 판정할 글자가 없다.

**기록 칸**

| 표 | 더하는 칸 | 뜻 |
|---|---|---|
| `boss_drop_records` | `item_key` | 아이템 key |
| | `box_origin_key` | 상자 결과면 상자의 아이템 key. 아니면 `null` |

- 이름 칸(`item_name` · `box_origin`)에는 새 기록에도 그때 이름을 함께 쓴다(결정 3).
- 기본키에 아이템 이름이 없어 칸만 더한다(`ensureColumn`). 표를 다시 만들지 않는다.

**화면과 판정**

- 보이는 이름은 key 로 찾은 마스터 표의 이름이고, 못 찾으면 저장된 이름이다. 드롭 시트 · 획득 히스토리 문장 · 가격
  입력 · 수익 팝오버 · 고가 배지 · today 위젯이 한 함수로 이름을 얻는다.
- 그림 · 고가 판정 · 상자 판정(드릴다운을 여나)은 key 로 한다. key 가 없으면 그림이 없고 고가가 아니고 상자가 아니다.
- 획득 판정(`isObtainableDrop`)은 **타일 key** 로 한다. 상자 결과면 `box_origin_key`, 아니면 `item_key` 다. 타일 key 가
  없으면 판정하지 않고 획득 가능으로 본다(사용자 결정). 그래서 `pruneUnobtainableDrops` · 난이도 확정 이관 · 히스토리
  거르기가 그 기록을 지우거나 숨기지 않는다.
- 같은 타일인지(한 카드에 같은 타일 하나, 난이도 확정 이관의 겹침)는 타일 key 로 가르고, key 가 없으면 타일 이름으로
  가른다.
- React key 는 아이템 key 를 쓰고, key 가 없으면 이름을 쓴다. `aria-label` 은 이름 그대로다.

**이관 (결정 5)**

- 버전 3: `boss_drop_records` 의 `item_name` · `box_origin` 을 마스터 표에서 찾아 두 key 칸을 채운다. 이름은 NFC 로
  맞춘다. 드롭 이름을 비교하던 코드 셋(`boss-drops.ts` · `valuable-drops.ts` · `asset-lookup.ts`)이 NFC 로 비교해 왔기
  때문이다. `기타` 는 기타의 key 가 된다. 못 찾으면 `null` 이다(결정 4).
- 못 찾는 이름으로 알려진 것은 둘이다. 슬롯이 나뉘기 전의 `익셉셔널 해머` 와 드롭 표에서 빠진 `루인 포스실드` 다.
  지금까지는 그 주를 열거나 난이도가 확정될 때 `pruneUnobtainableDrops` 가 지웠고, 이 묶음 뒤로는 남아서 이름으로 선다.
- Preferences 에는 드롭 아이템 이름이 없어 옮길 것이 없다.

### 결정 12. 보스 묶음은 이렇게 옮긴다 (이슈 #445)

사용자가 정한 것은 넷이다(2026-09-15).

- **난이도는 보스 key 와 따로 두고 API 영문 값을 key 로 쓴다.** `easy` · `normal` · `hard` · `chaos` · `extreme` 이다.
  한글(`카오스`)은 표시 표에서 찾는다. 지금은 `normalize.ts` 의 `DIFFICULTY_MAP` 이 영문을 한글로 바꾸고 그 한글이 기본키 ·
  원장 · 데이터 파일 · 배지 색까지 신원으로 쓰인다.
- **API 이름이 표에 없는 보스는 기록하지 않는다.** 새 보스가 나왔는데 데이터를 아직 못 고친 경우다. 스케줄러 화면에는 API
  원문 이름으로 서지만 수익 기록 · 파티 설정 · 드롭 기록 · 수동 추적 · 원장에는 안 들어간다. 기본키를 보스 key 로 짜면 key 가
  없는 보스는 기본키를 못 채우기 때문이다. 패치 데이터를 패치 전에 넣어 왔으므로 드문 경우다.
- **보이는 보스 이름은 API 표기다.** 마스터 표의 이름이 곧 API 이름이라 매칭용 칸을 따로 두지 않는다. 보스 수익 · 가계부의
  `검은마법사` 가 `검은 마법사` 로 보인다.

| `boss_drop_records` | `(ocid, boss_key, difficulty, period_key, drop_index)` |

- `boss` 칸은 그때 이름으로 남긴다. `difficulty` 칸은 영문 key 를 든다.
- 행을 잇는 key(`rowKey` · `dropRowKey` · `partySizeKey` · 가계부 `bossRowKey` · `confirmedDropKey` 등)와 testID 는 보스 key 와
  난이도 key 로 짠다.

**이관 (결정 5)**

- 버전 4: 세 표를 다시 만든다(`rebuildIncomeRecords` 가 선례다). 옛 행의 `boss` 를 결정 7 규칙으로 표에서 찾아 `boss_key` 를
  채우고, 한글 난이도를 영문 key 로 옮긴다.
- **보스를 못 찾는 행은 옮기지 않는다.** 기본키를 못 채우기 때문이고, 모르는 보스는 기록하지 않는다는 결정과 같다. 그런 행이
  남을 길은 거의 없다. 자동 기록은 결정석 가격을 모르는 보스를 건너뛰었고(`auto-record.ts`), 드롭 시트는 드롭 표에 없는
  보스에 후보가 없다. 남을 수 있는 것은 모르는 보스에 적은 파티 설정 정도다. 결정 4 의 `원문 이름을 지킨다` 는 이 묶음에서
  이 한 경우만 따르지 않는다.
- Preferences `manualTrackedContent:{ocid}` 의 보스 항목은 `{ kind: 'boss', bossKey, difficulty }` 가 된다. 읽을 때 옛
  모양(`contentName` 에 보스 이름, 한글 난이도)을 key 로 옮기고 못 찾는 보스는 뺀다. 지금 레거시 `content` 항목을 읽을 때
  옮기는 방식(`migrateLegacyKinds`)과 같다. 일간 · 주간 항목은 컨텐츠 묶음이 옮길 때까지 그대로다.
- `schedulerCache:{ocid}` · `scheduleProbe:{ocid}` 는 옮기지 않고 비운다(결정 6). 값에 모양 번호(`version: 2`)를 넣고, 번호가
  다른 옛 값은 없는 것으로 읽는다. 지우는 쓰기는 따로 두지 않고 다음 저장이 새 모양으로 덮어쓴다. 원장은 읽고-고치고-쓰는
  잠금 안에서 쓰여, 읽는 쪽이 지우면 방금 쓴 새 값을 지울 수 있어서다. 원장의 `bosses` 는 `보스 key|난이도 key` 이고 key 가 없는 보스는 안 적는다.

**표시**: 보스 이름은 보스 표의 이름, 난이도는 난이도 표의 한글이다. 드롭 히스토리 문장 · 가계부 · today · 배지가 모두 같은
표를 읽는다.

### 결정 13. 컨텐츠 묶음은 이렇게 옮긴다 (이슈 #446 의 첫 PR)

사용자가 정한 것은 넷이다(2026-09-15).

- **컨텐츠 · 강화 · 월드를 PR 셋으로 나눈다.** 결정 8 은 묶음마다 PR 하나였지만 세 영역이 서로 거의 안 얽혀서다. 차례는
  컨텐츠 → 강화 → 월드이고, 강화 · 월드의 질문은 그 PR 을 시작할 때 묻는다. 이슈 #446 은 마지막 PR 이 닫는다.
- **템플릿(`scheduler-content-template.json`)이 마스터 표다.** 컨텐츠마다 한 줄이 이미 있다(41줄). 여기에 key · 갈래 · 그림 ·
  보이는 이름 칸을 더하고, 퀘스트 지역 표 셋과 코드 표 셋은 이 칸으로 흡수해 지운다. 카탈로그는 key 로 가리킨다.
- **카테고리 라벨과 카탈로그 계열을 갈래 key 하나로 합친다.** 지금 관리 화면 · 카드의 `에픽 던전`(이름을 정규식으로 갈라
  만든 글자)과 주간 한도 · today 위젯의 `에픽던전`(카탈로그 `group`)이 따로 산다. 갈래 key `epic_dungeon` 하나가 둘을 맡고
  보이는 글자는 갈래 표에서 찾는다.
- **API 이름을 아직 대조하지 못한 줄(아우룸 레기스)에 표식을 두지 않는다.** 지금처럼 데이터 note 에 적고 첫 응답과 대조한다.
  표식이 있어도 못 찾는 일을 막지 못한다.

**API 경계 (결정 7)**: 스케줄 응답을 정규화하는 자리에서 일간 · 주간 컨텐츠의 `content_name` 으로 컨텐츠 key 를 얻는다. 규칙은
보스와 같다(NFC 뒤 공백 제거 · 완전 일치). 매칭 함수는 부르는 쪽이 넘긴다. 보스 매칭 함수와 함께 한 인자로 묶는다.

- 컨텐츠 항목(`DailyContent` · `WeeklyContent`)은 `contentKey`(못 찾으면 `null`)와 `apiName`(원문)을 든다.
- 이름으로 비교하던 곳(공유 범위 · 계열 한도 · 카드 고르기 · 완료 판정 · 수동 병합 · 요구 레벨 · 캐시 병합의 원장 key)은 컨텐츠
  key 와 갈래 key 로 가른다. `scheduler-merge.ts` 가 공유 범위는 공백을 지우고 원장 key 는 원문으로 쓰던 어긋남이 이것으로 풀린다.
- **표에 없는 컨텐츠(key 가 없다)**는 보스와 같게 다룬다. 스케줄러 화면(자동 모드)에 API 원문 이름과 갈래 없는 기본 카드로
  서고, 수동 추적 · 공유 원장 · 계열 한도에는 안 들어간다. 관리 화면은 마스터 표만 그리므로 바뀌지 않는다.

**Preferences (결정 6)**

- `manualTrackedContent:{ocid}` 의 컨텐츠 항목은 `{ kind, contentKey, maxCount? }` 가 된다. 읽을 때 옛 모양(`contentName`)을 이름으로
  찾아 key 로 옮기고, 못 찾으면 뺀다. 지금도 템플릿에 없는 항목은 읽을 때 빠진다(`migrateLegacyKinds`).
- `worldSharedProgress:{world}` · `accountSharedProgress:{accountId}` 의 값은 컨텐츠 key 를 열쇠로 든다. 이 원장은 한 번이라도 활성으로
  본 적이 있는지를 쌓은 값이라 다시 받을 수 없어 옮긴다. 읽을 때 이름 열쇠를 key 로 바꾸고 못 찾는 이름은 버린다. 키의 `{world}`
  부분은 월드 PR 이 다룬다.
- `schedulerCache:{ocid}` 는 모양 번호를 3 으로 올려 옛 값을 버린다. 컨텐츠 항목에 key 칸이 생겨서다.

**SQLite**: 컨텐츠 이름을 저장하는 표가 없어 이 PR 은 DB 버전을 올리지 않는다.
