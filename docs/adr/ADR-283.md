## 맥락

사냥 수익 시트는 솔 에르다 조각 개수와 개당 가격을 한 줄에서 받고, 합계 `획득 메소 + 조각 × 조각 가격` 을 사냥한 날 금액으로 적는다.
조각을 아직 안 팔았으면 제대로 적을 길이 없다. 가격을 0 으로 두면 나중에 판 돈이 들어갈 자리가 없고, 짐작한 값을 치면 실제로 판
값과 다른 돈이 사냥한 날에 선다. 사용자가 조각을 나중에 팔기로 적고 판 날에 정산하게 해 달라고 했다(2026-09-14).

결정은 두 번에 걸쳐 모았다. 2026-09-14 에 이슈 본문의 결정을 정했고, 2026-09-16 에 착수 전 질문의 답으로 보관을 캐릭터별로 바꾸고
사냥 기록의 캐릭터를 필수로 했다.

## 사냥 시트 (#440)

### 결정 1. 사냥 기록마다 `조각 가격 나중에 입력` 을 고른다 (사용자 지정)

사냥 시트의 `획득 메소 직접 입력` 체크박스 옆에 `조각 가격 나중에 입력` 체크박스를 둔다. 계산기 · 수동 입력 두 폼에 다 선다.

```
□ 획득 메소 직접 입력   □ 조각 가격 나중에 입력     ← 수정으로 열면 왼쪽은 없고 오른쪽만 선다
캐릭터        [선택 ▾]                             ← 필수(결정 4)
…
[조각 그림] [  80 ] 개 ··· [      ] 메소            ← 켜면 가격 칸이 꺼진다(editable=false)
                          12억 메소                 ← 켜면 조각 값이 빠진 합계
```

- **켜면 조각 가격 칸이 꺼지고 비고, 조각 값이 합계에서 빠진다.** 합계는 획득 메소만이다. 조각 개수는 그대로 받아 저장한다.
  꺼진 가격 칸은 글자와 단위가 함께 흐려진다(`opacity-40`, 날짜 화살촉의 못 누르는 모양과 같은 값).
- **끄면 가격 칸이 다시 켜진다.** 켜기 전에 친 가격은 되살리지 않는다.
- **수정으로 열면 저장된 값으로 켜진 채 열린다**([[ADR-171]] 결정 2). 이 값이 빠지면 나중에 입력 기록을 열어 저장만 해도 지금 판매로
  바뀌고 보관에서 빠진다. `획득 메소 직접 입력` 은 수정에서 안 서지만(모드를 못 바꾼다) 이 체크박스는 선다.
- **체크 상태는 시트 셸이 든다.** `획득 메소 직접 입력` 을 바꾸면 폼이 새로 심기므로(`key` 가 모드를 담는다), 폼 안에 두면 모드를 옮길
  때 풀린다.

### 결정 2. 나중에 입력은 새 칸 `hunt_fragments_deferred` 에 적는다

`income_records` 에 `hunt_fragments_deferred INTEGER` 를 더한다. `1` 이 나중에 입력이고 `NULL` · `0` 은 지금 판매다.

- **가격 0 이나 `NULL` 로 나타내지 않는다.** 가격이 0 인 옛 기록은 지금 판매이고(이슈 #440 결정 4), 계산기 이전 행은 사냥 칸이 전부
  `NULL` 이다. 둘 다와 갈리는 칸이 따로 있어야 한다.
- 칸은 `CREATE` 본문과 `ensureColumn` 두 자리에 더한다(`persistence/sqlite.md`). 옛 행은 `NULL` 이라 옮길 값이 없어 `DB_VERSION` 은
  안 올린다.
- 타입은 `HuntingCalculatorDetail` · `HuntingManualDetail` 에 `fragmentsDeferred: boolean` 이다. 저장할 때 나중에 입력이면 가격은 0 이다.

### 결정 3. 합계 식은 한 함수다

`lib/cashbook/hunting-meso.ts` 의 합계가 `fragmentsDeferred` 를 받아 켜져 있으면 조각 값을 뺀다. 수동 폼도 같은 함수를 부른다. 지금
수동 폼은 `typedMeso + fragments * fragmentPrice` 를 폼 안에서 따로 세서, 한쪽만 고치면 두 폼의 합계가 갈린다.

### 결정 4. 사냥 기록은 캐릭터를 골라야 저장된다 (사용자 지정 2026-09-16)

사냥 두 폼의 캐릭터 고르개에서 `선택 안함` 을 빼고, 캐릭터를 고르기 전에는 저장이 꺼진다. 보관이 캐릭터별이라(결정 5) 캐릭터 없는
사냥 기록의 조각은 갈 곳이 없다. 사용자가 캐릭터 없는 보관 칸을 두는 대신 캐릭터를 필수로 했다.

- 처음 고른 캐릭터는 지금처럼 마지막 사냥 선택을 따른다. 그것이 없으면 비어 있고 저장이 꺼져 있다.
- **캐릭터 없이 저장된 옛 사냥 기록은 그대로 둔다.** 수정으로 열면 캐릭터가 비어 있고, 캐릭터를 골라야 다시 저장된다.
- 아이템 판매 · 기타 폼의 `선택 안함` 은 그대로다.

## 보관 (#440)

### 결정 5. 보관은 캐릭터별이고 기록에서 센다 (사용자 지정 2026-09-16)

한 캐릭터의 보관 개수는 **그 캐릭터의 나중에 입력 사냥 기록의 조각 합에서, 그 캐릭터의 정산 기록이 판 개수 합을 뺀 값**이다. 보관을
따로 저장하지 않는다(이슈 #440 결정 3).

- 예: 아델 9월 1일 80개 보관 · 제논 9월 3일 40개 보관 → 아델 80개 · 제논 40개. 아델로 9월 10일에 50개를 정산하면 아델 30개.
- **고른 날까지 쌓인 것만 센다**(사용자 지정). 날짜가 `earned_on ≤ 고른 날` 인 기록만 더한다. 9월 10일에 보관한 조각을 9월 5일 날짜로는
  못 판다.
- **보관이 모자라게 되는 수정 · 삭제를 막지 않는다**(이슈 #440 결정 5). 가계부라서 사용자가 만든 오차는 사용자 몫이다.
- **마이너스도 계산값 그대로 보인다**(이슈 #440 결정 6). 0 으로 맞추지 않아 오차가 드러난다.
- **지금 판매 기록과 옛 기록은 안 든다**(이슈 #440 결정 4). 보관에 넣고 싶으면 사용자가 그 기록을 열어 나중에 입력을 켠다.
- **보관 개수는 정산 폼에만 보인다**(사용자 지정). 가계부 하루 목록의 사냥 줄에는 보관한 조각을 안 적는다(사용자 지정).
- 세는 자리는 `storage/income.ts` 의 한 SQL 조회다(캐릭터 · 날짜 · 뺄 기록 id). 가계부 층(`features/cashbook/records.ts`)이 감싸고
  `CashbookScreen` 이 수익 시트에 콜백으로 넘긴다. 시트는 저장소를 모른다.

## 정산 (#441)

### 결정 6. 수익 시트에 `솔 에르다 조각` 갈래를 더한다 (사용자 지정)

갈래 차례는 `사냥 · 솔 에르다 조각 · 아이템 판매 · 기타` 다. 아이템 판매 폼 안에 넣지 않는다.

- key 는 `sol_erda_fragment`, 이름은 `솔 에르다 조각` 이다. 이름이 기록에 글자로 박혀 나중에 바꾸면 기존 기록을 옮겨야 해 착수 때
  확정했다(사용자 지정).
- 카드 그림은 사냥 폼이 쓰는 `sol_erda_fragment.webp` 다. 카드가 넷이라 첫 화면이 두 줄(3+1)이 된다.
- 기본 갈래(`[0]`)는 여전히 사냥이다.

### 결정 7. 정산 폼은 캐릭터 · 보관 · 판 개수 · 개당 가격이다 (사용자 지정)

```
캐릭터                 [선택 ▾]   ← 필수. `선택 안함` 이 없다
보관 중 120개   판 개수 [    ] 개   ← 보관은 고른 캐릭터 · 고른 날까지(마이너스도 그대로). 판 개수는 1 ~ 보관
개당 가격             [     ] 메소
                       4억 메소   ← 판 개수 × 개당 가격
[저장]
```

- **보관 중과 판 개수는 한 줄이다**(사용자 지정 2026-09-16). 판 개수를 치면서 상한인 보관을 같은 줄에서 본다.
  `보관 중인 조각이 없습니다` 는 그 줄 아래 왼쪽에 선다.

- **금액은 판 날 칸에 선다**(이슈 #441 결정 2). 시트 머리에서 고른 날이다. 사냥한 날 칸은 안 바뀐다.
- **일부만 팔 수 있다**(결정 3). 판 개수는 1 부터 보관까지 친다. 넘기면 저장이 꺼진다.
- **수수료 줄이 없다**(결정 4). 금액은 `판 개수 × 개당 가격` 이다. 수수료를 뗀 값을 원하면 개당 가격에 뗀 값을 친다.
- **보관이 0 이하면 저장이 꺼진다**(결정 5). 보관 줄 아래에 `보관 중인 조각이 없습니다` 를 적는다.
- **보관을 못 읽으면 개수 자리가 `-` 이고 저장이 꺼진다.** 캐릭터를 고르기 전 · 읽는 중과 같은 모양이다. 없다는 문구는 안 적는다.
  못 읽은 것을 0 으로 읽으면 보관이 있는데도 없다고 말하게 된다.
- **캐릭터가 필수다.** 보관이 캐릭터별이라 캐릭터 없는 정산은 뺄 보관이 없다. 사용자가 정산 폼에 캐릭터 고르개를 두고 캐릭터별로
  세라고 했다.
- **날짜 · 캐릭터를 바꾸면 보관을 다시 센다.**
- 저장값: `category_key` `sol_erda_fragment` · `mesoAmount` 총액 · `quantity` 판 개수 · `item` · `hunt` 없음. `quantity` 는 지금
  `기타` 만 쓰는 `몇 회` 칸인데, 금액 칸에 곱한 총액이 들고 `금액 ÷ 수량` 으로 단가를 되짚는 뜻이 같아 같은 칸을 쓴다. 칸의 뜻이
  `기록 하나가 담는 몇 회 · 몇 개` 로 넓어진다.

### 결정 8. 수정으로 연 정산의 상한은 자기 몫을 뺀 보관이다

수정 시트에서 판 개수 상한은 **이 기록을 뺀 보관**이다. 지금 보관만 보면 보관을 다 판 기록은 열어서 저장만 해도 막힌다. 단가는
`금액 ÷ 판 개수` 로 되짚는다(`기타` 와 같다).

### 결정 9. 가계부 하루 목록의 정산 줄 (사용자 지정)

| 자리 | 값 |
|---|---|
| 제목 | `캐릭터 · 솔 에르다 조각` |
| 개수 | `50개`(사냥 줄의 `12재획` 이 서는 자리) |
| 금액 | `+4억` |
| 줄 그림 | `sol_erda_fragment.webp`(`income:sol_erda_fragment`) |

- 금액은 `mesoAmount` 라 그날 합계 · 기간 합계 · 열지도에 그대로 든다.

## 대가

- **캐릭터 없는 사냥 기록을 새로 못 적는다.** 옛 기록도 수정해 저장하려면 캐릭터를 골라야 한다.
- **수익 시트 첫 화면이 두 줄이 된다.**
- **보관 오차는 사용자가 고친다.** 수정 · 삭제로 모자라져도 막지 않고 마이너스로 보일 뿐이다.

## 기각

- **보관을 메이플 ID 전체로 하나 둔다.** 이슈 #440 의 처음 결정 2 였다. 정산 폼에 캐릭터를 두고 캐릭터별로 세라는 답으로 바뀌었다.
- **캐릭터 없는 사냥 기록끼리 따로 보관한다 · 나중에 입력을 캐릭터가 있을 때만 켠다.** 결정 4. 사용자가 사냥 기록의 캐릭터를 필수로 했다.
- **나중에 입력을 조각 가격 0 이나 `NULL` 로 나타낸다.** 결정 2. 옛 기록과 못 가른다.
- **정산을 아이템 판매 폼 안에 둔다 · 수수료 줄을 둔다.** 결정 6 · 7. 사용자가 새 갈래와 수수료 없음을 골랐다.
- **보관을 날짜와 상관없이 센다.** 결정 5. 사용자가 고른 날까지 쌓인 보관만 세라고 했다.
- **사냥 줄에 보관한 조각을 적는다 · 보관을 정산 폼 밖에도 보인다.** 결정 5. 사용자가 둘 다 안 한다고 했다.

## 정정

### 정정 1. `보관 중인 조각이 없습니다` 를 걷는다 (사용자 지정 2026-09-16)

결정 5 · 결정 7 이 보관 줄 아래에 세웠던 문구다. 그 줄이 `보관 중 0개` 를 이미 적고 있어 같은
말이 두 번 선다. 보관이 마이너스인 오차도 `-5개` 로 그대로 보이므로 무엇이 막고 있는지는 그 수가
말한다([[ADR-288]] 결정 3).

**저장이 꺼지는 규칙은 그대로다.** 보관이 0 이하면 안 켜지고, 못 읽었을 때 `-` 가 서는 것도 같다.

### 정정 2. 사냥 시트의 `조각 가격 나중에 입력` 은 마지막에 저장한 값으로 열린다 (사용자 지정 2026-09-16)

결정 1 은 이 체크가 **언제나 꺼진 채** 열린다고 적었다. 같은 사냥을 반복해 적는 자리라 매번 다시
켜게 돼서, 저장에 성공한 값을 기억해 **새 기록의 첫 값**으로 세운다([[ADR-288]] 결정 2).
수정으로 열 때 기록에 박힌 값이 이기는 것은 그대로다.
