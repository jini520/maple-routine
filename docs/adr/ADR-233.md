### ADR-233: **헤더의 경계를 못박는다.** 제목 · 기준 시각 · 다른 페이지로 가는 것 셋뿐이다 (2026-09-08, 사용자 지시)

> 🟢 **구현 완료 · 실기기 미검증** (2026-09-08). iOS 시뮬레이터로 확인했다. 화면 일곱이 바뀌었다.

**배경**: 사용자 지적.

> `페이지 마다 헤더가 왜 다 다른거야? header는 title과 데이터 기준시간, 다른 페이지로 이동 탭,`
> `정도로 경계를 명확하게 해. 캐릭터 레일, 기간 이동, 주간·월간 이동 탭 같은건 header가 아니잖아.`

헤더 셸(`PageHeader` 와 그 상자를 베낀 화면 셋)이 **화면마다 다른 것을 담고 있었다**. 담긴 것이
화면마다 다르니 헤더라는 말이 화면마다 다른 것을 가리켰고, 그래서 [[ADR-231]] 정정 4 에서
`높이를 맞춘다` 가 무엇을 맞추는 일인지부터 갈렸다.

| 화면 | 헤더에 담겨 있던 것 |
|---|---|
| today · 유틸리티 · 설정 계열 · 가격 기록 | 제목 · 기준 시각 · 뒤로 |
| 컨텐츠 스케줄러 | + 캐릭터 레일 · 일간/주간 탭 |
| 보스 스케줄러 | + 캐릭터 레일 · 솔로/파티 필터 · 로딩 카드 |
| 보스 관리 | + 캐릭터 레일 · 모든 보스 보기 토글 |
| 컨텐츠 관리 | + 캐릭터 레일 · 일간/주간 탭 |
| 가계부 | + 주간/월간 탭(제목 줄 안) |
| 보스 수익 | + 기간 이동(`← 이번 주 →`) |
| 히스토리 | + 가뭄 요약 카드 |

### 결정 1. 헤더에 담는 것은 셋뿐이다

1. **제목**
2. **데이터 기준 시각** (제목 줄 바로 아래, [[ADR-231]] 정정 4)
3. **다른 페이지로 가는 것** - 뒤로(`←`) · 페이지 이동 링크

그 밖은 전부 콘텐츠다. **이 화면에서 무엇을 보는가를 고르는 것**은 헤더가 아니다. 캐릭터 레일 ·
기간 이동 · 주간/월간 탭 · 일간/주간 탭 · 솔로/파티 필터 · 모든 보스 보기 토글이 그렇다.

가르는 기준은 **여기를 떠나는가**다. 떠나면 헤더, 여기 머무르며 보는 것을 바꾸면 콘텐츠다.
그래서 보스 수익의 `아이템 가격` · `히스토리` 와 컨텐츠 스케줄러의 `관리` 는 헤더에 남는다.
같은 줄에 있어도 성질이 다르다.

### 결정 2. 내려보낸 것은 콘텐츠의 첫 자식이 된다

`ScreenScroll` 의 콘텐츠 컨테이너가 이미 `gap-4` 로 블록을 잇는다. 헤더 안쪽 간격도 같은
`gap-4` 였으므로 **자리를 옮겨도 보이는 간격은 그대로다**. 헤더가 스크롤 뷰의 첫 자식이라
같이 굴러가던 성질도 그대로다.

**캐릭터 레일의 음수 마진이 사라진다.** 그 값(`marginHorizontal: -16`)은 헤더 상자의 `px-4` 를
뚫으려고 있었다. 콘텐츠의 직계 자식이 되면 뚫을 여백이 없다. 안쪽 스크롤의
`paddingHorizontal: 16` 만 남으면 첫 칸과 마지막 칸은 제자리에 서고 스크롤은 화면 끝까지 간다.

### 결정 3. 경계를 테스트가 지킨다

문서에만 두면 다음 화면에서 조용히 어긋난다. 새 화면을 만드는 사람은 옆 화면을 복붙하고, 그때
복붙되는 것이 하필 레일을 헤더에 넣은 화면일 수 있다. `<PageHeader>` 블록 안에 제목 줄 말고
다른 것이 있으면 실패하는 가드를 둔다. 이 저장소가 제목 줄 정책에서 쓴 방식과 같다.

### 딸려 온 것

- **가계부의 주간/월간을 왼쪽 정렬로 바꿨다.** 제목 줄 우측에 있던 것을 내리자 형제 탭인 보스
  수익의 같은 자리(왼쪽)와 좌우로 갈렸다. 두 화면이 같은 `periodKey` 로 기간을 말하는데
  컨트롤이 갈리면 다른 것으로 읽힌다.

### 열린 질문

- **`PageHeader` 의 `below` 프롭은 죽어 있다.** 아무도 안 쓴다. 이 결정으로 헤더가 제목 줄
  하나만 담게 되면 그 프롭의 쓸 자리가 더 줄어든다. 걷을지는 따로 정한다.
