### ADR-009: 직업(전직) 기반 테마 시스템 도입
**결정**: 캐릭터 직업 고유 컬러를 Primary 색상으로 쓰는 다중 테마 시스템을 도입한다. `docs/UI_GUIDE.md`의 색상 파생 규칙(Hover/Active/Subtle/Border 계산, 라이트/다크 배경별 텍스트 대비 기준)은 모든 테마에 공통 적용하고, 테마마다 색상 값을 교체한다.
**정정(2026-07-10)**: ~~테마마다 바뀌는 건 Primary 색상 값 하나뿐~~ — 사용자가 실제 예시 테마("레테": primary `#452951`(진보라)·secondary `#A7446A`(로즈)·third `#FBFB8A`(연노랑))를 주면서 확인됨: 직업 테마는 **3색 세트**(Primary/Secondary/Third)로 온다. 3색 각각의 역할은 색상마다 다르게 매핑한다(와이어프레임 적용 사례 참고): Primary는 채움 배경 + 텍스트/아이콘 잉크 겸용(밝기가 충분히 낮으면 별도 잉크 보정 불필요), Secondary는 hover/눌림 상태 + 보더, Third는 옅은 강조 배경(subtle) + 채움 위 텍스트색. 이 매핑은 테마별 밝기 구성에 따라 달라질 수 있어 고정 공식이 아니라 색상마다 판단이 필요하다.
**이유**: 메이플스토리 직업 고유 컬러를 활용하면 사용자가 자신의 캐릭터/직업에 애착을 느끼는 개인화 경험을 제공할 수 있다.
**구현 방향(뼈대, 2026-07-09)**:
- 컬러 값은 `src/data/job-themes.json`에 직업별 참조 테이블로 저장한다. 다른 게임 레퍼런스 데이터와 동일하게 [[ADR-006]] CRITICAL 규칙이 적용되어, 실제 컬러 값은 AI가 임의로 채우지 않고 사용자(도메인 전문가) 확정 후 반영한다 — 현재 미작성
- 선택된 테마는 다른 전역 클라이언트 상태와 동일하게 Zustand로 관리하고 `storage/`에 영속화한다
- Tailwind는 정적 유틸리티 클래스 기반이라 런타임에 값이 바뀌는 다중 테마와 궁합이 안 맞는다 — Primary 관련 값은 CSS 커스텀 프로퍼티(예: `--color-primary`)로 노출하고, 선택된 테마 값을 `:root`에 주입하는 방식을 제안(구현 시 확정)
**트레이드오프**: Tailwind arbitrary value(`bg-[#...]`)를 그대로 못 쓰고 `bg-[var(--color-primary)]` 형태의 간접 참조가 필요해진다. `UI_GUIDE.md`에 정의한 정적 색상값(기본 테마)도 테마 적용 시점에는 CSS 변수 참조로 바뀌어야 한다.
**미확정 — 추후 확정 필요**:
- 직업별 실제 컬러 값(hex) — "레테" 예시는 검증용 테스트 팔레트로 와이어프레임에만 적용했고, `src/data/job-themes.json`에는 아직 반영하지 않았다(실제 직업 매핑인지 사용자 확인 전까지 [[ADR-006]] CRITICAL 규칙 적용)
- `job-themes.json` 스키마를 `{ primary, secondary, third }` 3필드로 확정할지, 색상 역할 매핑(어떤 색이 채움/보더/텍스트인지)을 테마마다 수동 지정할지 자동 규칙(예: 가장 어두운 색 = 채움)으로 계산할지
- 테마 단위: 직업 대분류(전사/마법사/궁수/도적/해적/초보자 등)인지 5차 전직 세부 단위인지
- 테마 전환 UX: 설정에서 수동 선택인지, 등록된 캐릭터의 직업에 따라 자동 적용인지
- **정정(2026-07-09)**: ~~테마 미선택 시 기본값 유지 여부~~ — 확정: 기본값은 계속 오렌지(#FF7033, `UI_GUIDE.md` "기본 테마")를 쓰되, 배경 팔레트는 다크에서 **라이트로 전환**했다(게임 앱다운 캐주얼한 톤을 위해, PRD "디자인" 섹션 참고). 다크는 폐기하지 않고 보조 팔레트로 유지
- 다크 모드를 사용자가 설정에서 직접 켤 수 있게 할지 여부는 여전히 미정

**정정(2026-07-12)**: 아래 항목이 사용자 확인을 거쳐 확정됨.
- ~~3색 세트(Primary/Secondary/Third) + 파생 공식~~ → **폐기, 13개 시맨틱 토큰을 테마 데이터에 직접 값으로 저장하는 방식으로 교체**: `bg`/`surface`/`surface-2`/`border`/`border-strong`/`primary`/`primary-hover`/`primary-deep`/`secondary`/`info`/`error`/`text`/`text-muted`/`text-disabled`. Hover/Deep 등을 공식으로 파생하지 않는다 — 사용자가 두 번째 테마("렌")를 이 13토큰 형태로 직접 제공하면서 파생 공식 대신 명시값 방식으로 전환.
- ~~테마 단위(직업 대분류 vs 세부 전직) 미정~~ → `job-themes.json`에 테마 이름을 키로 저장하는 구조로 확정. 첫 두 항목은 `"레테"`(현재 `src/index.css` 값을 그대로 확정), `"렌"`(신규 제공)이다. **단, 이 이름이 실제 어떤 전직에 대응하는지는 여전히 미정** — 현재는 이름 자체를 테마 식별자로만 쓴다.
- ~~직업별 실제 컬러 값(hex) 미정~~ → "레테"·"렌" 두 테마의 13토큰 값 확정(표는 `docs/UI_GUIDE.md` "테마 시스템" 참고). 레테의 `primary-hover`/`secondary`/`info`/`error`/`text-disabled` 5개는 기존 `src/index.css`에 대응값이 없어, 사용자 위임 하에 기존 팔레트와 어울리게 보간·재활용해 채웠다(`secondary`는 기존 `gold` #D1C093 재활용, `error`는 기존 `magenta` #D8608F 재활용).
- ~~CSS 적용 방식 "제안(구현 시 확정)"~~ → 확정: Tailwind v4 `@theme` 블록(`src/index.css`)은 레테 값을 기본값으로 유지하고, `:root[data-theme="렌"] { --color-*: ...; }` 형태로 오버라이드한다. Tailwind v4 유틸리티 클래스(`bg-primary`, `text-text` 등)는 내부적으로 이미 `var(--color-*)`를 참조하므로 기존 컴포넌트 코드 변경 없이 테마 전환이 적용된다.
- **신규 확정**: 기존 `--color-gold`/`--color-gold-bright`/`--color-magenta`/`--color-neutral-warm` 4개 토큰은 13토큰 스키마에 없어 폐기한다. 마이그레이션 — `gold`→`secondary`로 개명(`BossScreen.tsx` 즐겨찾기 배지), `magenta`→`error`로 개명(8개 파일의 에러 메시지 텍스트), `neutral-warm`→`text-muted`로 통합(`App.tsx`/`ApiKeyForm.tsx`/`BossPortrait.tsx`/`CharacterTrackingPicker.tsx`), `gold-bright`는 실사용처 없어 그대로 폐기.

**여전히 미확정 — 추후 확인 필요**:
- 테마 이름("레테"/"렌")과 실제 캐릭터 전직의 매핑, 테마 단위(대분류/세부 전직)
- `docs/PRD.md`·`docs/UI_GUIDE.md`의 "라이트가 기본 테마"(2026-07-09 확정) 방향과, 지금 확정한 레테(다크 팔레트)가 사실상 코드의 기본값으로 쓰이고 있는 현재 상태가 서로 불일치한다. 이번 변경은 이 불일치를 해소하지 않으며, 라이트 기본 트랙 자체는 아직 코드화되지 않았다 — 별도 확인 필요.

**정정 — 구현 범위 축소(2026-07-12)**: ~~전환 UX(임시 토글 vs 정식 설정 화면) 미정~~ → **당장은 만들지 않는다.** 설정 화면·토글 UI, `job-themes.json` 데이터 파일, Zustand 스토어, `storage/theme.ts`, `:root[data-theme]` 런타임 오버라이드는 모두 보류하고, "렌" 13토큰 값을 `src/index.css`의 `@theme` 블록에 정적으로 반영해 현재 활성 팔레트를 레테→렌으로 교체하는 것까지만 이번 구현 범위로 한다. 런타임 다중 테마 인프라는 실제로 전환 기능이 필요해지는 시점에 다시 착수한다.

**정정 — 렌 팔레트 재수정(2026-07-12)**: 렌이 다크(잉크블랙)에서 라이트(실버/아이보리)로 전면 교체됨. 토큰 이름 2개 변경(스키마 전체에 소급 적용, 레테 값 자체는 불변): ~~`primary-deep`~~→`primary-text`(빨강 텍스트·링크 전용), ~~`info`~~→`info-tint`(배경 틴트 전용). `error`는 이번엔 신규 보간 대신 `docs/UI_GUIDE.md`에 이미 있던 라이트 배경용 부정/에러 값(`#B91C1C`)을 재사용 — 위에서 "미해소"로 남겨뒀던 라이트 기본 방향과의 불일치도 렌이 라이트가 되면서 자연 해소됨(브랜드 컬러가 오렌지가 아니라 블러드레드라는 차이는 남음). 정확한 값·컴포넌트 마이그레이션 상세는 `docs/UI_GUIDE.md` "테마 시스템" 참고.

**구현 완료(2026-07-12, 커밋 `dbe890d`)**: 위 "구현 범위 축소"에서 정한 범위 그대로 `src/index.css`의 `@theme` 블록 값이 렌 13토큰으로 정적 교체됐다. `job-themes.json`·Zustand 테마 스토어·`storage/theme.ts`·`:root[data-theme]` 오버라이드·설정 화면 토글은 결정대로 만들지 않았다 — 런타임 다중 테마 전환은 여전히 미구현이며, 전환 기능이 실제로 필요해지는 시점에 별도로 착수한다.

**재개(2026-07-12, 설정 화면 task 범위 포함)**: 위 "구현 범위 축소"에서 보류했던 런타임 다중 테마 전환 인프라 착수를 재개한다 — 신규 "설정 화면"(핵심 기능 6, `docs/PRD.md` 참고) 구현 범위에 "레테/렌 수동 테마 선택"이 포함되기로 확정되면서다. `src/data/job-themes.json`(레테·렌 13토큰 값 — `docs/UI_GUIDE.md` "테마 시스템" 표에 이미 확정된 값을 그대로 옮기는 것이며 신규 컬러 확정이 아님), `storage/theme.ts`(기존 `api-key.ts`와 동일한 Preferences 기반 영속화 패턴), Zustand 테마 스토어, `:root[data-theme]` 런타임 오버라이드를 이번에 구현한다. 테마 이름과 실제 캐릭터 직업(전직)의 매핑은 여전히 미정이므로(위 "여전히 미확정" 참고), 이번 범위는 직업 기반 자동 적용이 아니라 사용자가 레테/렌 중 하나를 직접 고르는 수동 선택 UI로 한정한다.

**정정 — 렌 팔레트 3차 수정(2026-07-14)**: 사용자가 `third`/`info-tint`/`error` 3개 토큰 값을 다시 제공해 교체했다. `third`: `#525475`→`#C9EEF2`, `info-tint`: `#C9EEF2`→`#E4F6F8`, `error`: `#B91C1C`→`#A31118`. 나머지 10개 토큰은 불변. `job-themes.json`·`src/index.css`·`docs/UI_GUIDE.md` "테마 시스템" 표에 반영 완료.

**버그 수정(2026-07-14)**: 위 렌 팔레트 3차 수정으로 `third`가 아주 옅은 하늘색(`#C9EEF2`)이 되면서, `bg-third/15 text-third` 패턴으로 구현돼 있던 카운트 배지 6곳(보스 스케줄러 n/12, 몬스터파크 카드, 길드 지하수로/미션 포인트 카드, 보스 수익 "가격 미확정" 배지 — 진행률 바 2곳 포함)의 텍스트가 사실상 안 보이는 문제가 발견됨. 확인해보니 이 배지들은 애초에 `docs/UI_GUIDE.md`(카운트 배지 레시피)와 이전 ADR 결정([[ADR-020]] 결정 11, [[ADR-021]])에 `bg-primary/15 text-primary`(배지)·`bg-white/15`+`bg-white/80`(진행률 바 트랙/채움)로 이미 명시돼 있었다 — 코드가 그 스펙과 다르게(`third`로) 구현된 상태였던 구현 버그였다. 신규 디자인 결정이 아니라 기존 문서 스펙대로 코드를 고친 것.

**정정(2026-07-14, 아래 [[ADR-020]] 결정과 충돌 해소)**: 위 "버그 수정"에서 6곳 전부를 `primary`/흰색으로 되돌렸지만, 이후 몬스터파크·길드 지하수로·길드 미션 포인트 3곳(카드 내부 배지)은 사용자 지시로 다시 `third`로 재변경됐다(상세는 이 문서의 "카드 내부 점수 배지·진행률 바를 `third`로" 항목 참고, `docs/UI_GUIDE.md` "카운트 배지 레시피"도 그 상태로 반영됨). 보스 스케줄러 n/12·보스 수익 "가격 미확정" 2곳은 이 "버그 수정" 그대로 `primary` 유지. 즉 최종 상태는 "카드 내부 배지=third, 전역 헤더 카운트 배지=primary"로 갈린다 — 위 "버그 수정" 문단만 읽으면 6곳 전부 primary로 오해할 수 있어 이 정정을 남긴다.

**정정 — `-text` 계열 토큰 추가(2026-07-14)**: 사용자가 "캐릭터 대표 컬러를 추출하다 보면 라이트/다크에 따라 대비가 안 좋은 경우가 계속 생길 것"이라며 테마 스키마 자체를 확장해달라고 요청. `primary`/`primary-text`(채움용과 텍스트용을 분리하는 기존 선례)와 동일한 원칙을 `secondary`/`third`에도 적용해 `secondary-text`/`third-text` 2개 토큰을 신설(스키마 15→17필드). 값은 원래 색의 Hue를 유지한 채 `bg-X/15` 틴트 배경(surface 위에 15% 합성) 대비 WCAG AA(4.5:1) 이상이 되도록 AI가 계산한 제안값 — 레테: `secondary-text` = `secondary` 그대로(이미 대비 충분, 7.19:1), `third-text` = `#DA6995`(4.51:1). 렌: `secondary-text` = `#3E7369`(4.51:1), `third-text` = `#21808A`(4.51:1). 정확한 계산 방식·최종 확인 여부는 `docs/UI_GUIDE.md` "테마 시스템" 참고 — **사용자가 이 값을 직접 검토·확정하기 전까지는 잠정치**로 취급한다.

**정정 — 테마 이름 한글화 + 4번째 테마 "혼테일" 추가 + 시스템 다크 모드 연동(2026-07-14)**: 사용자가 `mushmom` 표기를 다른 테마와 동일하게 한글 "머쉬맘"으로 정정 요청 — `ThemeName` 타입·`job-themes.json` 키·`ThemeSelector.tsx`·`storage/theme.ts`·`features/theme/store.ts`·테스트 전체에서 `'mushmom'`을 `'머쉬맘'`으로 개명한다(값 자체는 불변). 동시에 4번째 테마 "혼테일"(다크)을 17토큰 값과 함께 추가했다(값은 `docs/UI_GUIDE.md` "테마 시스템" 표 참고, [[ADR-006]] 확인 완료). "혼테일"을 **기본 다크 테마**로 지정하면서, "시스템 컬러로 자동으로 라이트/다크 테마가 바뀌는" 동작을 요청 — 기존에는 저장된 테마가 없으면 무조건 "머쉬맘"이었는데, 이제 `restoreFromStorage()`에서 `window.matchMedia('(prefers-color-scheme: dark)')`로 OS 설정을 확인해 라이트면 "머쉬맘", 다크면 "혼테일"을 기본값으로 쓴다. 앱 실행(정확히는 `restoreFromStorage` 호출) 시점에 1회만 판정하고 실시간으로 OS 설정 변경을 감지해 앱 실행 중 전환하지는 않는다(스코프 축소 — 필요해지면 추후 `matchMedia` change 리스너를 추가). 사용자가 설정 화면에서 테마를 한 번이라도 명시적으로 선택하면 그 값이 영속화되어 이후에는 시스템 설정과 무관하게 그 값을 쓴다(기존 수동 선택 동작과 동일). `src/index.css`의 `@theme` 기본 블록은 계속 "머쉬맘" 값이고, "혼테일"은 "레테"·"렌"과 동일하게 `:root[data-theme='혼테일']` 오버라이드 블록을 갖는다. jsdom 테스트 환경은 `window.matchMedia`를 기본 제공하지 않아, `resolveSystemTheme()`은 `window.matchMedia`가 없으면 라이트("머쉬맘")로 안전하게 폴백한다.
