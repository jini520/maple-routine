# ADR-260: 스위치 손잡이가 미끄러진다

> 🟢 유효 · 2026-09-12 · **구현 완료** · 실기기 미검증

**관련**: [[ADR-255]](스위치는 부품 하나다. 그 대가에 손잡이가 순간이동한다고 적었다) ·
[[ADR-250]] 결정 1(세그먼트의 선택 배경이 미끄러진다. 시간과 곡선을 거기서 가져온다)
**문서**: `foundation/design-system.md`

## 맥락

`atoms/Switch` 의 손잡이는 `on` 이 바뀌면 그 자리로 **순간이동했다**. 트랙 색과 손잡이 자리가
한 프레임에 함께 바뀌어서, 무엇이 어디로 갔는지가 안 보인다. 사용자가 애니메이션을 지시했다.

스위치를 쓰는 세 자리(알림 설정 · 보스 관리의 `모든 보스 보기` · 드롭 연출)가 모두 이 부품을
쓰므로 한 곳만 고치면 셋이 함께 바뀐다([[ADR-255]] 결정 1).

## 결정

### 결정 1. 손잡이는 CSS 트랜지션으로 미끄러진다

손잡이를 `AnimatedView` 로 두고 `transform` 에 트랜지션을 건다. `ProgressBar` 의 폭 트랜지션과
같은 방식이다. 값이 바뀌면 Reanimated 가 옛 자리에서 새 자리로 옮긴다.

시간은 **200ms**, 곡선은 `cubicBezier(0.32, 0.72, 0, 1)` 이다. 세그먼트의 미끄러지는 상자
(`useSlidingThumb`)와 같은 값이라, 앱 안에서 무엇이 미끄러지든 같은 움직임으로 읽힌다.

NativeWind 의 `transition-*` 클래스로는 쓰지 않는다. RN 스타일로 옮겨지지 않아 에러 없이 안
움직인다(`ProgressBar` 의 `WIDTH_TRANSITION` 과 같은 이유).

### 결정 2. 처음 서는 자리에서는 안 미끄러진다

CSS 트랜지션은 값이 **바뀔 때만** 돈다. 화면이 열리며 스위치가 처음 그려질 때는 이미 제자리에
서 있다. 열자마자 손잡이가 달려오면 사용자는 누르지 않은 이동을 보게 된다([[ADR-250]] 결정 1 과
같은 원칙).

### 결정 3. 움직임 줄이기를 켜면 트랜지션을 안 건다

`useReducedMotion` 이 참이면 트랜지션 키를 아예 안 준다. 손잡이가 곧바로 선다.

### 결정 4. 트랙 색은 따라 흐르지 않는다

누르는 즉시 `bg-surface-2` 와 `bg-primary` 가 바뀐다. 색까지 200ms 에 걸쳐 바뀌면 그동안 누른
스위치가 안 눌린 것처럼 보인다. 세그먼트의 글자색이 상자를 안 기다리는 것과 같은 이유다
([[ADR-250]] 결정 1).

## 대가

- **값이 되돌아갈 때도 미끄러진다.** 알림 설정에서 구독이 실패하면 스위치가 미끄러져 제자리로
  간다([[ADR-259]] 결정 4). 되돌아간 것이 눈에 보이므로 오히려 낫다.
- **화면이 열린 뒤 값이 늦게 바뀌어도 미끄러진다.** 누르지 않은 이동이다. 트랜지션은 누가
  바꿨는지 모르고 값이 바뀐 것만 본다.
