### ADR-070: 주문서 교환권 3종 — 죽은 `scroll` 카테고리를 `consumable` 로 흡수, 이름 통일, 위치 보정 (구현 완료, 2026-07-31)

**배경**: `item-drop-table.json` 에는 최초 전사 시점부터 `scroll` 카테고리가 있고, 25개 보스×난이도 엔트리에 "프리미엄 악세서리 …교환권 / 프리미엄 펫장비 …교환권 / 매지컬 무기 주문서 교환권" 3종이 들어 있다. 그런데 **이 데이터를 읽는 코드가 없다** — `types/drops.ts` 의 `DROP_CATEGORIES` 는 `fixed`·`equipment`·`consumable` 뿐이고, 드롭 후보(`SELECTABLE_DROP_CATEGORIES`)·고정 드롭·고가 판별(`lib/valuable-drops`) 어디도 `scroll` 을 순회하지 않는다. 즉 이 3종은 **데이터에는 있으나 화면에 한 번도 나온 적이 없고, 따라서 기록된 적도 없다**. 사용자가 이 3종의 실제 아이콘을 제공하면서 드롭 위치 목록을 함께 준 것이 계기다.

데이터에는 네 가지 문제가 함께 있었다.
- **이름이 갈려 있다**: 듄켈(하드)만 "프리미엄 악세서리 **스크롤** 교환권"·"프리미엄 펫장비 **스크롤** 교환권"이고 나머지 24개 엔트리는 "…**주문서** 교환권"이다. 같은 아이템이 두 이름으로 존재하면 `name` 으로 dedupe·조인하는 계층(드롭 후보 통합, `item-icons` 매핑, 기록 키)이 전부 둘로 갈린다.
- **빠진 위치가 있다**: 찬란한 흉성(노멀)에 3종이 없었다.
- **`note` 도 갈려 있다**: 카링(노멀·익스트림)만 `교환 불가`, 나머지는 `교환 불가, 7일`.
- **아이콘이 없다**: 매핑도 파일도 없어 노출해도 플레이스홀더가 된다.

**결정**

1. **`scroll` 카테고리를 폐지하고 3종을 `consumable` 로 옮긴다.** 대안은 `DROP_CATEGORIES`·`SELECTABLE_DROP_CATEGORIES` 에 `scroll` 을 추가해 시트에 "주문서" 섹션과 헤더 아이콘([[ADR-040]] 결정 4)을 신설하는 것이었으나, **이 3종은 인게임에서도 소비 아이템**이고 별도 섹션이 사용자에게 주는 구분이 없다. 카테고리를 늘리면 타입·시트 섹션·헤더 아이콘·`RecordedDrop.category` 의 허용값이 함께 늘고, 기록에 새 카테고리 값이 섞이기 시작한다 — 얻는 것 없이 되돌리기 어려운 쪽이다. 사용자 확인(2026-07-31).

2. **이름은 사용자가 준 표기로 통일한다** — `프리미엄 악세서리 스크롤 교환권` · `프리미엄 펫장비 스크롤 교환권` · `매지컬 무기 주문서 교환권`. 즉 앞 둘은 "주문서 교환권" → "스크롤 교환권"으로 바꾸고(듄켈 하드가 이미 쓰던 표기가 정답이었다), 셋째는 그대로 둔다. `악세사리`/`악세서리` 중에서는 **`악세서리`** 를 쓴다 — 기존 데이터·사용자가 준 이미지 파일명이 모두 이 표기다.

3. **`note` 는 "교환 불가, 7일"로 맞춘다.** 카링(노멀·익스트림)만 `교환 불가`(기간 없음)였고 나머지 24엔트리는 `교환 불가, 7일`이었다 — 같은 아이템이 보스에 따라 다른 조건일 이유가 없다는 사용자 확인(2026-07-31)에 따라 카링도 7일을 붙인다. 새로 넣은 찬란한 흉성(노멀)도 같은 값이다.

4. **드롭 위치는 추가·보정만 한다(전체 교체 아님).** 사용자가 준 목록은 정답 전체가 아니라 보정 목록이다(사용자 확인, 2026-07-31). 목록에만 있는 **찬란한 흉성(노멀)** 을 추가하고, 목록에 없는 기존 엔트리 — 최초의 대적자(4난이도)·발드릭스(2)·시즌 보스 메이린(하드), 그리고 선택받은 세렌(하드)·감시자 칼로스(카오스·익스트림)·카링(하드·익스트림)·림보(하드) — 는 **그대로 둔다**. 게임 수치 데이터를 코드/AI 판단으로 지우지 않는다는 [[ADR-006]] 의 방향과 같다: 확인되지 않은 삭제보다 보존이 안전하다.

5. **기록 마이그레이션은 필요 없다.** 이 3종은 선택 후보로 노출된 적이 없어 `boss_drop_records` 에 옛 이름으로 저장된 행이 존재할 수 없다. 이름 변경(결정 2)이 기존 기록을 고아로 만들지 않는 유일한 이유가 이것이므로, 앞으로 이름을 바꿀 땐 같은 조건을 먼저 확인해야 한다([[ADR-069]] 결정 4가 다루는 문제와 같은 종류다).

6. **파풀라투스 마크의 실제 아이콘을 반영한다.** `papulatus_mark.png` 는 1×1 투명 플레이스홀더였다(2026-07-11 메모 "실제 아이콘 파일 필요"). 사용자가 제공한 실제 이미지로 교체한다.

7. **새 아이콘 파일은 기존 명명·여백 규칙을 따른다.** 파일명은 영문 스네이크 케이스(`item-icons.json` 이 "한글 아이템명 → 영문 파일명" 매핑 전용이라는 전제를 유지), 캔버스는 **아트워크가 약 90%** 가 되도록 투명 테두리만 덧댄다(리샘플링 없음, item-drop.md 2026-07-30 규칙). 사용자가 준 4장은 전부 여백 0의 타이트 크롭이라 그대로 넣으면 옆 아이콘보다 커 보인다.

**트레이드오프**

- **`misc` 카테고리는 죽은 데이터로 남긴다(사용자 확인, 2026-07-31).** 감시자 칼로스(카오스)·카링(이지)의 "태초의 정수" 1건씩은 흡수도 삭제도 하지 않는다 — `scroll` 과 같은 처리를 하지 않기로 명시적으로 정한 것이라, 나중에 "빠뜨렸다"고 읽히면 안 된다. 데이터 정합성 테스트가 `misc` 를 허용 목록에 두어 이 상태를 고정한다.
- **결정 4 때문에 데이터가 사용자의 목록보다 넓다.** 사용자 목록이 실제로 "전체 정답"이었다면 최초의 대적자·발드릭스·메이린 등에 나오지 않는 아이템이 타일로 보이게 된다. 삭제는 되돌릴 때 원본이 없지만 과다 노출은 언제든 좁힐 수 있어, 확인 전까지는 보존 쪽을 택했다.
- **소비 섹션이 길어진다.** 상위 난이도 보스는 소비 타일이 3~6개에서 6~9개로 늘어난다.

**상태**: **(구현 완료, 2026-07-31)** — `src/data/item-drop-table.json`(scroll→consumable 25엔트리·이름 통일·찬란한 흉성 노멀 추가), `src/data/item-icons.json`(3종 매핑 추가·파풀라투스 마크 메모 갱신), `src/assets/items/`(신규 3종 + `papulatus_mark.png` 교체). 코드·타입·저장소 무변경(순수 데이터).
