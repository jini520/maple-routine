# ADR-324: iOS 는 UIScene 으로 창을 연다. 창은 하나다

> 🟢 유효 · **구현 완료** 2026-09-29(`ios/app/SceneDelegate.swift` · `AppDelegate.swift` · `Info.plist`) · 실기기 미검증 · 이슈 #494

**관련**: [[ADR-323]](회전 잠금이 씬의 화면에서 짧은 변을 잰다) · [[ADR-320]](넥슨 로그인) · [[ADR-194]](읽히게 쓰기)
**문서**: `foundation/release.md` 의 `다음 스토어 릴리스에서 같이 할 일`
**이슈**: #494

## 맥락

이 Mac 의 Xcode 는 27.0 뿐이라 빌드가 iOS 27 SDK 로 나간다. 그 SDK 로 만든 앱은 UIScene 생명주기를
채택하지 않으면 iOS 27 에서 UIKit 이 실행을 막는다(`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`).
앱은 Expo SDK 57 템플릿 그대로 `AppDelegate` 가 `UIWindow` 를 직접 만들었고 `Info.plist` 에 씬 매니페스트가
없었다. 그래서 다음 스토어 빌드를 그대로 구우면 iOS 27 사용자 전부가 켜자마자 죽는다.

Expo SDK 57 에는 씬 쪽 짝(`ExpoSceneDelegate` 같은 것)이 없다. 씬 대리자는 이 저장소가 직접 쓴다.

## 결정

### 결정 1. 창 만들기와 리액트 네이티브 시작을 씬 대리자로 옮긴다

`AppDelegate.didFinishLaunchingWithOptions` 는 팩토리를 만들고 Firebase 를 켜고 `launchOptions` 를 들고만
있는다. 창은 `SceneDelegate.scene(_:willConnectTo:options:)` 가 그 씬으로 만들고, 거기서
`startReactNative` 를 부른다.

### 결정 2. 씬이 만든 창을 `AppDelegate.window` 에도 건다

광고(`react-native-google-mobile-ads` 의 전면 광고 · 동의 창 · 광고 검사기)와 Firebase Messaging 이 창을
`UIApplication.shared.delegate.window` 로 찾는다. 씬을 채택하면 그 자리가 비어, **앱은 켜지는데 광고와
동의 창만 조용히 안 뜬다.** 그래서 씬 대리자가 만든 창을 앱 대리자의 `window` 에도 넣는다.

### 결정 3. 창은 하나다 (사용자 결정 2026-09-29)

`UIApplicationSupportsMultipleScenes` 는 `false` 다. 결정 2 가 창 하나를 전제로 한다. 창이 둘이면
광고가 어느 창에 뜰지 정할 수 없다. iPad 분할 화면(Split View)은 창 하나로도 되므로 지금처럼 된다.

### 결정 4. URL 은 씬 콜백에서 받아 `RCTLinkingManager` 에 넘긴다

씬을 채택하면 `application(_:open:options:)` 와 `application(_:continue:restorationHandler:)` 가 안 불린다.
같은 일을 `scene(_:openURLContexts:)` 와 `scene(_:continue:)` 가 한다. 앱을 새로 켠 URL 은
`launchOptions` 가 아니라 `connectionOptions` 로 오므로, 그 URL 을 `launchOptions` 의 `.url` 자리에 넣어
`Linking.getInitialURL()` 이 계속 읽게 한다.

지금 앱은 들어오는 URL 을 소비하지 않는다. 넥슨 로그인은 `openAuthSessionAsync`(ASWebAuthenticationSession)라
콜백이 세션으로 돌아오고 이 길을 안 탄다. 옮기는 것은 종전 앱 대리자가 하던 일을 끊지 않으려는 것이다.

## 옮기지 않아도 되는 것 (소스로 확인)

- **스플래시**(`expo-splash-screen`): 앱 대리자 구독자의 `customizeRootView` 로 루트 뷰에 붙는다. 창과 무관하다
- **알림을 눌러 열기**(notifee · Firebase Messaging): `UNUserNotificationCenter` 대리자로 받는다. 씬과 무관하다.
  푸시 토큰 등록도 앱 대리자에 남는다
- **앱 대리자의 생명주기 콜백**(`applicationDidBecomeActive` 등): 씬을 채택하면 안 불리지만, 설치된
  모듈 중 그것을 구현한 것이 없다. RN 의 `AppState` 는 `UIApplication` 알림을 들으므로 그대로 온다
- **expo-web-browser**: `keyWindow` 로 창을 찾는다. 씬의 창이 key 가 되므로 그대로 된다

## 대가

- 스토어 빌드에 묶인다. OTA 로 못 나간다
- Expo 템플릿에서 더 멀어진다. SDK 를 올릴 때 Expo 가 씬 대리자를 내놓으면 그쪽으로 옮길지 다시 본다
- 창이 하나라 iPad 에서 앱을 두 창으로 못 연다(결정 3)
- **실기기 미검증**
