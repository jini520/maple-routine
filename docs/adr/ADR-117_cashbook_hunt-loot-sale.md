# ADR-117 사냥 전리품 판매

> ⚪ 미구현
> 관련 소스: `app/cashbook/income/` · `lib/cashbook/categories.ts`

## 배경

가계부 수입에서 솔 에르다 조각 말고도 사냥에서 얻어 파는 전리품을 적고 싶다(#747, 사용자 2026-10-27). 전리품 목록은
서버에서 관리한다. 앱 업데이트 없이 더하고 빼기 위해서다.

판매 폼은 수입 · 지출 시트의 새 디자인(#746) 위에 그린다.

## 결정

### 결정 1. 수입 갈래 `사냥 전리품 판매` 를 더하고, 솔 에르다 조각 갈래는 그대로 둔다

조각 정산은 지금 갈래와 기록을 그대로 쓴다(사용자 선택 2026-10-28). 조각만 사냥 기록에서 보관 개수를 세기 때문에 흐름이
다르고, 갈래를 합치지 않으면 이미 적힌 정산 기록을 옮길 일도 없다. 통계에서도 두 갈래는 따로 선다.

### 결정 2. 전리품은 순록의 우유 · 황혼의 이슬 · 사냥 이벤트 아이템 셋이고, 목록은 서버 표에 둔다

- 주문의 흔적은 넣지 않는다. 보스 전리품이기도 해서 사냥 판매로 묶기 애매하다(사용자 2026-10-28).
- 사냥 이벤트 아이템은 이벤트마다 줄을 더하지 않고 항목 **하나**로 둔다. 아이템 이름은 판매 때 사용자가 친다.
- 표에는 이름 · 그림 · 순서 · 판매처 · NPC 개당 가격을 둔다. 판매처는 경매장 · NPC 둘이다. 서버 관리 화면에서 고치고,
  앱은 다른 게임 데이터처럼 받아서 기기에 저장한다([[ADR-020]]).

### 결정 3. 보관 개수는 세지 않고, 판 날에 개수만 적는다

사냥 폼에 전리품 칸을 더하지 않는다. 보관 개수를 세는 것은 솔 에르다 조각뿐이다.

### 결정 4. NPC 판매는 수수료가 없고 단가를 앱이 채우며, 경매장 판매는 지금 수수료 규칙을 쓴다

- NPC 판매 전리품은 가격이 정해져 있다. 사용자는 개수만 치고, 금액은 `개수 × NPC 개당 가격` 이다. 가격은 사용자가 준
  값이다. 순록의 우유 2,750 메소 · 황혼의 이슬 5,100 메소(사용자 2026-10-28).
- 경매장 판매(사냥 이벤트 아이템)는 사용자가 단가를 친다. 수수료는 아이템 판매와 같이 떼고 받은 돈과 뗀 몫을 함께
  저장한다([[ADR-047]] 결정 7). 요율은 MVP 등급에서 고른다([[ADR-050]]).

## 테스트

구현할 때 적는다.
