### ADR-039: 바텀시트 자체구현 → vaul(Drawer) 라이브러리 교체 (구현 완료 2026-07-26)

**배경**: [[ADR-038]] 결정 7에서 `components/BottomSheet`를 `createPortal(document.body)` 기반으로 직접 구현했다(Modal 패턴 미러, 62줄). 실사용 후 자체구현의 상호작용 한계가 드러났다 — (1) 드래그 닫기가 `onTouchStart/Move/End` **터치 이벤트 전용**이라 데스크톱 마우스로는 시트를 끌어 못 닫음, (2) 핸들을 임계값(90px) 미만으로 끌었다 놓으면 부드러운 스냅 복귀 없이 **뚝** 되돌아옴, (3) 열림/닫힘 **진입·이탈 애니메이션 없음**(즉시 등장/소멸, 오버레이 페이드 없음), (4) 속도 기반 닫기(**fling**) 없음. 스킨은 동일하게 두고 동작만 라이브러리로 바꾼 비교 프로토타입을 나란히 검증한 뒤, 사용자가 라이브러리 교체를 결정(2026-07-26).

**결정**:
1. **vaul(Drawer) 채택**: `components/BottomSheet`의 내부를 vaul `Drawer`로 교체한다. 진입/닫힘 spring 애니메이션, 속도 기반 fling, 놓을 때 부드러운 스냅 복귀, 포커스 트랩·`Esc`·`aria`(Radix 기반), body 스크롤 잠금을 라이브러리가 내장 제공한다. 마우스·터치 양쪽 드래그 지원.
2. **공개 API·스킨 불변 → 사용처 무변경**: `BottomSheet`의 props(`onClose`/`children`/`testId`)와 시각 스킨(오버레이 `bg-bg/70`, 시트 `rounded-t-[20px] border-t border-border bg-bg`, `z-[60]`, 그랩 핸들 `h-1 w-9 bg-border-strong`, `max-h-[82vh] w-full max-w-md`, `pb-[calc(1rem+env(safe-area-inset-bottom))]`, `shadow-[0_-8px_30px_rgba(0,0,0,0.3)]`)을 그대로 유지한다. 유일 사용처인 `BossDropSheet`는 손대지 않는다.
3. **부모 조건부 마운트 패턴 유지**: 현재 `BossProfitScreen`이 시트를 조건부로 마운트하고 `onClose`로 언마운트한다. vaul의 닫힘 애니메이션을 살리려면 언마운트를 애니메이션 종료까지 지연해야 하므로, `BottomSheet` 내부에 `open` 상태(초기 `true`)를 두고 `onOpenChange(false)` → `open=false` → vaul 이탈 애니메이션 → `onAnimationEnd(isOpen=false)`에서 `props.onClose()`로 부모에 언마운트를 알린다. `추가 완료` 버튼처럼 콘텐츠가 직접 `onClose`를 부르는 경로는 종전대로 즉시 닫힘(버튼 닫힘은 애니메이션 불필요).
4. **자체 `useBodyScrollLock` 의존 제거**: vaul이 스크롤 잠금을 내장하므로 `BottomSheet`에서 이 훅 호출을 뺀다. 단 훅 파일(`lib/use-body-scroll-lock.ts`)은 Modal·DisconnectConfirm·CharacterTrackingPicker가 계속 쓰므로 **삭제하지 않는다**([[ADR-003]] 어댑터 레이어 유지).
5. **jsdom 폴리필**: 전역 test env가 `node`이고 컴포넌트 테스트만 파일 주석으로 jsdom을 켠다(셋업 파일 없음). vaul(Radix)이 요구하는 `Element.hasPointerCapture/setPointerCapture/releasePointerCapture`·`scrollIntoView`·`window.matchMedia`·`ResizeObserver`를 `setupFiles` 하나로 폴리필하되, node-env 테스트에서도 로드되므로 `typeof window`/`typeof Element` 가드를 둔다. `vite.config.ts`의 `test.setupFiles`에 연결.

**이유**:
- 자체구현 62줄로는 spring·fling·스냅 복귀·마우스 드래그를 다시 만들어야 하고, 그 품질은 검증된 라이브러리에 못 미친다. 스킨/공개 API를 그대로 두면 교체 비용이 시트 컴포넌트 1개에 국한된다(사용처·테스트 표면 최소).
- 부모 조건부 마운트는 이미 자리잡은 패턴이라, 언마운트 지연만 `onAnimationEnd`로 흡수하면 UX(이탈 애니메이션)를 얻으면서 상위 구조를 안 바꾼다.

**트레이드오프**:
- 런타임 의존성 1개(vaul) 추가 — 번들 증가(빌드로 측정해 기록). 단 네이티브 변경 없는 JS라 스토어 심사 없이 OTA로 배포 가능([[ADR-022]]).
- jsdom 폴리필 셋업 파일이 새로 생김(테스트 인프라 표면 소폭 증가). 이후 다른 Radix 계열 도입에도 재사용 가능.
- [[ADR-038]] 결정 7의 "자체 `createPortal`" 부분을 이 ADR이 대체(supersede)한다 — `DropEffectOverlay`는 계속 자체 `createPortal` 유지(시트가 아니라 전체화면 연출이라 vaul 부적합).

**성공 기준(TDD)**: 기존 `BossDropSheet` jsdom 테스트(시트 존재 `getByTestId('boss-drop-sheet')`, 토글→`추가 완료`→`onSave`+`onClose`, 드릴다운 기록, 고가 연출 트리거)가 **수정 없이 그대로 통과**하는 것을 성공 기준으로 삼는다. 폴리필 추가 후 `npm run test`·`npm run lint`·`npm run build` 전부 통과 확인.

**구현(2026-07-26, 구현 완료)**: `vaul@1.1.2` 추가, `vitest.setup.ts`(pointer capture·`scrollIntoView`·`matchMedia`·`ResizeObserver` 폴리필, `typeof window`/`typeof Element` 가드) 신설 + `vite.config.ts` `test.setupFiles` 연결, `components/BottomSheet/BottomSheet.tsx`를 vaul `Drawer`로 전면 교체(공개 API·스킨·`testId` 불변, 내부 `open` 상태 + `onAnimationEnd`로 닫힘 애니메이션 후 `onClose`, 자체 `useBodyScrollLock` 호출 제거). 유일 사용처 `BossDropSheet`·훅 파일은 무변경. **검증**: `BossDropSheet` 테스트 4개 무수정 통과 → 전체 1158 tests·lint·build 통과, vaul 번들 증가 gzip **+20.3kB**(main chunk, tree-shake 대조 측정), 실제 앱(`npm run dev`) 부팅 콘솔 에러 없음. 스킨·상호작용 자체는 별도 비교 프로토타입에서 실 브라우저로 선검증.

**정정(2026-07-26) — DropEffectOverlay 클릭 간섭**: 교체 후 사용자 보고 — 고가 드롭 연출 화면을 탭해도 연출이 안 닫히고 **탭이 뒤 시트 타일로 통과**되는 회귀. 원인은 vaul가 쓰는 `@radix-ui/react-dismissable-layer`가 modal 시트가 열린 동안 `document.body.style.pointerEvents = 'none'`을 걸고 Drawer 콘텐츠만 `auto`로 되살리는 것 — `DropEffectOverlay`는 Drawer 바깥 별도 `createPortal(body)`라 `pointer-events:none`을 **상속**받아 hit-target에서 빠지고, `z-[70]`으로 시트 위에 있어도 탭이 아래 시트로 떨어졌다(자체구현 시트는 body를 안 건드려 없던 문제). **fix**: `DropEffectOverlay` 루트에 `pointer-events-auto` 추가(상속된 none을 명시적으로 되살림) — 한 클래스. 비교 프로토타입에 축소 재현(연출 오버레이 + fix on/off 토글)해 실 브라우저로 **버그 재현→수정 확인**(off: 탭이 뒤 타일 토글·연출 유지 / on: 탭→연출 닫힘·통과 없음). jsdom은 실제 hit-testing을 못 하므로 오버레이 루트가 `pointer-events-auto`를 유지하는지 구조 테스트로 회귀 고정(`DropEffectOverlay.test.tsx`).

**정정 2(2026-07-26) — 연출 탭이 시트까지 닫음**: 위 `pointer-events-auto`로 오버레이가 탭을 받게 되자 새 증상이 드러났다(사용자 보고) — 연출을 탭해 닫으면 **뒤 바텀시트까지 함께 닫힘**. 원인은 Radix `dismissable-layer`가 시트 콘텐츠 **바깥**의 pointerdown을 dismiss 신호로 보는 것. 핵심은 Radix가 레이어 노드에 **React 합성 캡처**(`onPointerDownCapture`)를 달아 "안/밖"을 판정하는데, **React 포털 이벤트는 DOM이 아니라 React 트리로 전파**된다는 점이다 — `DropEffectOverlay`는 [[ADR-038]] 구조상 `BossDropSheet`에서 `BottomSheet`의 **형제**로 렌더돼(시트 children이 아님) Radix가 '바깥'으로 판정, 오버레이 탭 → 시트 dismiss(`onOpenChange(false)` → 내 `onAnimationEnd` → `onClose`)로 이어졌다. (비교 프로토타입 1차판이 오버레이를 시트 children 안에 뒀을 땐 React 합성 캡처가 '안'으로 판정해 이 버그가 안 났던 것이 방증.) **fix**: `BottomSheet`의 `Drawer.Content`에 `onPointerDownOutside` 가드를 달아, pointerdown 타깃이 `[data-sheet-keep-open]`(오버레이가 다는 마커) 안이면 `event.preventDefault()`로 dismiss를 취소한다(vaul가 이 prop을 Radix로 포워딩하고 `defaultPrevented`를 존중함을 소스로 확인). 시트를 children으로 옮기지 않은 이유 — 그러면 오버레이 pointer 이벤트가 vaul 드래그 핸들러로 흘러 시트가 끌려갈 위험이 있어, 형제 유지 + 명시 가드가 더 안전. 비교 프로토타입을 실제 앱과 동일 구조(오버레이=시트 형제)로 맞추고 가드 on/off 토글로 실 브라우저 **재현(off: 연출 탭→시트까지 닫힘) → 수정(on: 연출만 닫히고 시트 유지)** 확인. 오버레이가 마커를 유지하는지 구조 테스트 추가. **미verify**: 실 데이터로 보스 수익 주간 화면에서 시트/연출 제스처·애니메이션 육안 확인(등록 캐릭터·동기화 데이터 필요 — 실기기/실계정 검증 대상).
