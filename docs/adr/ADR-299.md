# ADR-299: 앱이 만든 값 중 변하지 않는 것은 서버가 든다. 로우 데이터는 기기에 남는다

> ⚪ 미구현 · 2026-09-19 · 설계 · 넥슨 로그인([[ADR-296]])을 완성한 뒤 착수

> 사용자 지정(2026-09-19): 원본 데이터는 사용자 기기에 저장하지만, 변경되지 않는 총액과 2차 생산
> 목록 등은 서버에서 관리한다. 사용자 기기의 데이터를 완전히 옮기려는 게 아니다. 화면을 그리는
> 데이터는 남겨 둔다.

**관련**: [[ADR-227]](결정 4 를 이 문서가 뒤집는다) · [[ADR-296]](넥슨 로그인. 열린 질문 하나를 결정 5
가 닫는다) · [[ADR-003]](어댑터 경계는 그대로 산다) · [[ADR-277]](서버가 기준이고 기기는 사본을 드는
선례) · [[ADR-214]](API 키 한도)

## 맥락

### 서버로 옮기려는 이유는 셋이다

**여러 사용자의 데이터로 통계를 낸다.** 넥슨 로그인이 붙으면 프렌즈 API 호출이 서버를 거치고
([[ADR-296]] 결정 4), 서버가 누가 누구인지 가릴 수 있게 된다.

**기기 이관을 줄인다.** 기기 DB 는 지금 버전 9 이다(`src/storage/sqlite/migrations.ts` 의
`DB_VERSION`). 버전이 오를 때마다 이관 코드가 사용자 기기마다 따로 돌고, 그 결과를 확인할 길이
없다. 버전 7·8 은 09-17 패치 가격이 `boss_profit_records.price_meso` 에 잘못 굳은 것을 고쳤다. 계산한
값이 원본 행에 들어 있어서 생긴 이관이다. 서버에서 돌리면 한 번 돌리고 바로 확인할 수 있다.

**같은 계산을 매번 되풀이하지 않는다.** 지금은 금액 일부를 읽을 때마다 다시 센다. 가계부의 조각
보관은 저장하지 않고 센다(`features/cashbook.md`). 드롭 금액은 `payout_meso` 에 넣지 않고 읽는 시점에
더한다(`features/boss-profit.md`). 변하지 않는 과거 값을 최종값으로 들면 이 계산이 한 번으로 끝난다.

### API 키가 필요한 조회는 서버가 개발자 키로 부를 수 있다

`character/basic` 같은 조회는 공개 데이터다. 어느 키로든 ocid 만 있으면 부를 수 있다(사용자 확인
2026-09-19). 서비스 단계 키의 한도는 초당 500건, 하루 2,000만 건이다([[ADR-214]]). 2026-09-17 새벽
2시부터 오후 3시까지 앱의 고유 IP 가 114 개였으므로, 키 하나로 충분하다.

### [[ADR-227]] 결정 4 의 전제가 사라졌다

그 결정은 식별자를 뗀 2차 가공 데이터만 옵트인으로 모으고, 계정과 백업은 넥슨 OAuth 승인 뒤로
미뤘다. 근거는 승인 전에는 누가 누구인지 가릴 수단이 없다는 것이었다. 프렌즈 승인이 났고
(2026-09-19) [[ADR-296]] 이 넥슨 로그인을 들인다.

## 결정

### 결정 1. 넥슨 API 로 받아 앱이 가공한 데이터는 전부 대상이다 (사용자 지정)

넥슨이 준 값이어도 앱이 무엇을 더했으면 앱이 만든 데이터로 본다.

| 데이터 | 넥슨이 준 것 | 앱이 더한 것 | 지금 자리 |
|---|---|---|---|
| 보스 일간·주간·월간 기록 | 스케줄러의 처치 관측 | 결정석 가격 · 파티 인원 · 드롭 기록 | `boss_profit_records` · `boss_drop_records` |
| 가계부 | 강화 사용 내역(큐브 · 스타포스 · 잠재) | 가계부 줄과 금액 · 손으로 적은 수입과 지출 | `enhancement_history` · `income_records` · `spend_records` |
| 그 밖에 가공한 데이터 전부 | | | 착수할 때 목록을 만든다 |

### 결정 2. 과거 값 중 변하지 않는 것은 계산해 서버에 적는다. 로우 데이터는 앱이 든다 (사용자 지정)

서버로 가는 것은 **계산이 끝난 최종값**이다. 사용자가 적은 행과 넥슨에서 받은 원본은 기기에 남는다.
화면을 그리는 데이터도 기기에 남는다. 그래서 서버가 죽어도 앱은 선다.

### 결정 3. 서버는 넥슨 로그인 uid 로 사용자를 가른다. uid 가 없으면 API 키의 해시로 가른다 (사용자 지정)

키 원문은 서버로 가지 않는다. 해시는 되돌릴 수 없어 서버가 키를 얻을 수 없다. 서버가 넥슨을 부를
때는 자기 키를 쓴다(결정 5).

### 결정 4. 전송은 무조건이다 (사용자 지정)

설정에 끄는 토글을 두지 않는다. [[ADR-227]] 결정 4 는 [[ADR-008]] 의 옵트인(기본값 OFF)을 따랐는데,
여기서는 따르지 않는다. 결정 2 가 서버를 최종값의 자리로 정했으므로, 끄는 사용자가 있으면 그 사람의
과거 값이 서버에 없다.

### 결정 5. 로그인만 한 사용자의 공개 조회는 서버가 개발자 키로 대신 부른다 (사용자 지정)

[[ADR-296]] 의 열린 질문(로그인만 한 사용자는 today 의 캐릭터 기본 정보와 메소 획득량을 못 본다)의
답이다. `character/basic` · `item-equipment` · `symbol-equipment` · `union-raider` 가 공개 조회라 이
길이 열린다(맥락).

### 결정 6. 착수는 넥슨 로그인을 완성한 뒤다 (사용자 지정)

결정 3 의 첫째 열쇠가 로그인 uid 이므로 [[ADR-296]] 이 먼저 서야 한다.

## 대가

- **못 보낸 값을 버릴 수 없다.** [[ADR-227]] 은 수집이라 못 보내면 안 보내면 됐다. 이제는 서버가
  최종값의 자리라, 서버가 꺼져 있던 동안의 값을 다시 보내는 대기열이 필요하다.
- **미니 PC 디스크 하나에 모든 사용자의 최종값이 있다.** 백업과 복구를 운영해야 한다.
- **개인정보 의무가 커진다.** 끌 수 없는 수집이라 Play 데이터 안전에 선택 항목으로 신고할 수 없다.
  uid 와 해시에 묶인 기록이라 [[ADR-227]] 이 계정 백업이면 생긴다고 적은 항목(계정 삭제 경로 ·
  처리방침 개정 · App Store 개인정보 라벨)이 다시 걸린다(`foundation/release.md`).
- **모든 사용자의 공개 조회가 개발자 키 하나의 한도를 쓴다.** 약관 부담도 개발자에게 온다(결정 5).
- **기기 이관은 남는다.** 로우 데이터와 화면 데이터가 기기에 남기 때문이다. 서버로 옮겨 가는 것은
  최종값의 이관뿐이다.

## 기각

- **기기 데이터를 서버로 통째로 옮긴다.** 사용자 지정으로 기각했다(결정 2). 화면을 기기 데이터로
  그리므로 서버가 죽어도 앱이 선다.
- **옵트인으로 보낸다(기본값 OFF).** 결정 4.
- **식별자를 떼고 집계만 모은다.** [[ADR-227]] 결정 4 의 모양이다. 결정 3 이 uid 와 해시로 묶기로 해
  기각했다. 식별자가 없으면 서버 값을 그 사용자에게 돌려줄 수 없다.

## 열린 질문

착수 전에 답한다.

- **무엇이 변하지 않는가.** 과거 값도 바뀐다. 가계부는 날짜를 골라 적으므로 지난 달 합계가 언제든
  바뀐다. 드롭은 지난 기간을 다시 편집할 수 있고(`features/item-drop.md`), 드롭 가격을 고칠 수 있어서
  `payout_meso` 에 넣지 않는다(`features/boss-profit.md`). DB 버전 7·8 은 이미 닫힌 09-17 주의 가격을
  고쳤다. 데이터마다 굳는 시점과, 굳은 뒤에 바뀌면 다시 보내는 규칙이 필요하다.
- **서버에 두는 단위.** 합계만 두면 서버는 버전 7·8 같은 수정을 할 수 없다. 어느 보스를 몇 번
  잡았는지 모르기 때문이다. 그러면 수정이 다시 기기 이관이 된다. 행 단위 최종값(보스 · 난이도 · 기간 ·
  파티 인원 · 분배금)을 두면 서버에서 한 번에 고친다. 맥락의 둘째 이유가 이 선택에 달려 있다.
- **누가 계산하는가.** 로우 데이터가 기기에 있으므로 기기가 계산해 보내는 것이 자연스럽다. 그러면
  계산 코드의 버그를 고치는 일도 기기에 남는다.
- **화면은 최종값을 어디서 읽는가.** 계산을 줄이려면 기기도 최종값을 들어야 한다. 기기가 스스로 굳힌
  값을 드는 길이 있고, 서버 값의 사본을 받는 길이 있다. 뒤쪽은 [[ADR-277]] 의 선례다. 기준은 서버이고
  기기에는 마지막 응답의 사본만 둔다. 사본은 이관하지 않고 버린 뒤 다시 받는다.
- **API 키 해시를 열쇠로 쓰면 끊기는 자리.** 키를 다시 발급하면 해시가 바뀌어 서버 기록과 끊긴다.
  키를 여럿 둔 사용자([[ADR-296]] 결정 2)는 해시도 여럿이다. 키 사용자가 로그인하면 해시에 묶인
  기록을 uid 로 옮겨야 하고, [[ADR-296]] 결정 6 이 그때 키를 지우므로 옮기는 일이 먼저다. 앱이 보낸
  해시는 서버 기록을 여는 값이기도 하다. 서버가 받은 해시를 그대로 저장하면 DB 가 새어 나갈 때 남의
  기록을 열 수 있다.
- **API 키 안내 문구를 고치는가.** `app/auth/ApiKeyForm.tsx` 가 `입력한 키는 이 기기에만 저장되고
  넥슨 외 어디로도 전송되지 않아요` 라고 적는다. 키 원문은 여전히 안 나가지만 키에서 만든 값이 나간다.
- **넥슨 약관이 이 수집을 허용하는가.** [[ADR-227]] 에서 넘어온 질문이다. 모든 사용자에게 끌 수 없이
  적용되므로 더 무겁다.
