# ADR-101 다계정: 넥슨 계정 여러 개를 등록한다

> ⚪ 미구현
> 관련 소스: `storage/api-key.ts` · `lib/nexon-credential.ts`

## 배경

넥슨 계정을 여러 개 쓰는 사용자가 계정을 모두 등록할 수 있게 한다(사용자 지정 2026-10-26). 기능은 아직 만들지 않는다.
지금 다시 짜는 기기 · 서버 스키마가 이 기능을 막지 않도록 계정의 자리부터 연다([[ADR-098]] 결정 5 · 6, [[ADR-099]] 결정 5).

메이플스토리의 계정 단위는 이 순서다.

```
넥슨 계정(넥슨 로그인 또는 API 키 하나) > 메이플 ID > 캐릭터
```

## 결정

### 결정 1. 넥슨 계정 하나가 인증 수단 하나이고, 다계정은 넥슨 로그인 사용자만 쓴다

- 메인 계정은 넥슨 로그인이다. 부계정은 모두 API 키로 등록한다(사용자 지정).
- 넥슨 로그인을 하지 않은 사용자는 계정을 하나만 쓴다. 그 계정이 API 키여도 된다.
- 지금 인증 수단 목록이 이미 `넥슨 로그인 0~1개 + API 키 여러 개` 를 들고 있어서([[ADR-025]] 결정 1), 이 목록에 계정 id 를
  붙여 그대로 쓴다.

### 결정 2. 메인 계정은 서버를 거쳐 넥슨을 부르고, 부계정은 앱이 직접 부른다

메인 계정은 넥슨 로그인이라 넥슨 토큰이 서버에 있다([[ADR-025]] 결정 2). 부계정은 API 키라 앱이 그 키로 직접 부른다.

### 결정 3. 서버로 보내는 기록은 계정 종류와 상관없이 모두 보낸다

부계정의 기록도 서버로 간다(사용자 지정). 메인 계정의 신원으로 보내고, 어느 계정의 기록인지는 계정 id 로 적는다
([[ADR-099]] 결정 5).

### 결정 4. 캐릭터는 계정과 상관없이 등록하고, 개수 제한이 있는 컨텐츠 화면에서만 계정을 바꿔 본다

- 캐릭터 관리는 지금처럼 계정 · 메이플 ID 와 상관없이 캐릭터를 등록한다(사용자 지정).
- 계정당 · 메이플 ID 당 개수 제한이 있는 컨텐츠는 그 제한을 계정별로 보여 줘야 한다. 그래서 그 컨텐츠를 보여 주는 곳에
  계정을 바꾸는 세그먼트를 둔다(사용자 구상). 어느 화면 · 어느 컨텐츠인지는 기능을 만들 때 정한다.
