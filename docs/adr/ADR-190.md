# ADR-190 — 발행 지문을 **못박는다**. 트리 계산값이 아니라 «스토어 바이너리가 묻는 값» 으로 낸다

> 🟢 유효 · 2026-08-30 · **구현 완료** · 1.0.7 발행에 적용
>
> [[ADR-137]] 결정 3 의 «`runtimeVersion` 을 우리가 안 적는다» 를 **한 가지 경우에만** 뒤집는다 —
> 트리가 스토어 바이너리의 지문을 **재현하지 못할 때**.

## 맥락

RN OTA 는 버전이 아니라 **`runtimeVersion`(네이티브 트리의 fingerprint 해시)** 으로 매칭된다
([[ADR-137]] 결정 3). 그 값은 빌드 시각에 바이너리 안에 박히고, `publish-rn-ota.mjs` 는
**발행 시점 트리의 계산값**을 쓴다. 둘이 갈리면 매니페스트는 아무도 묻지 않는 이름으로 남는다
(`docs/trouble/2026-08-19-rn-runtimeversion-drift.md`).

**그 격차가 1.0.6 에서 영구화됐다.**

| | 지문 |
|---|---|
| App Store 1.0.6 | `d304704ee9eeedd73d61383372e00849f830f8fb` |
| Play 1.0.6 (versionCode 21) | `3df849c014ea95bb7b0b9dd506094148b0fdc508` |
| **지금 트리** (2026-08-30 실측) | ios `a52ce256dea7a8316d27c3c5e07466c751abc440` · android `7e2fec5dcde4539a077aa014b8cba5eeef456267` |

두 가지가 겹쳤다. ① 그때의 아카이브가 GUI 로 구워져 **어떤 트리 상태로도 재현되지 않고**
(트러블 문서 원인 ⑤) ② [[ADR-155]] 가 `android/`·`ios/`·`modules/` 를 루트로 옮겨 경로 자체가
지문 재료에서 바뀌었다. `c9ce4697` 을 워크트리로 꺼내 `npm ci` 해도 값이 또 다르다 — 커밋 내용이
아니라 그때의 `node_modules` 상태에 딸린 값이다.

**그래서 «다시 계산해서 맞춘다» 는 길이 없다.** 다음 스토어 바이너리를 굽기 전까지, 트리는
스토어 사용자가 묻는 이름을 영원히 못 만든다.

### 그대로 발행하면 무슨 일이 일어나나

`latest-<platform>.json` 은 **배달 파일이 아니라 판정 파일**이다([[ADR-137]] 결정 4). 앱의 경로는:

```
/manifest (내 runtimeVersion) → 204 → checkStoreRequired()
  → /latest.runtimeVersion === Updates.runtimeVersion ? 최신 : 「스토어 업데이트가 필요해요」
```

발행 스크립트는 매니페스트와 **`latest-*.json` 을 함께** 쓴다. 못박지 않고 1.0.7 을 발행하면
`latest-*.json` 의 `runtimeVersion` 이 트리 계산값(`a52ce256…`/`7e2fec5d…`)으로 덮이고, 스토어
사용자는 매니페스트도 못 받고(이름이 다르다) 판정도 어긋나 **부팅할 때마다 「스토어 업데이트가
필요해요 · v1.0.7」 거짓 모달**을 보게 된다. 스토어에 가도 받을 것이 없는 채로.

## 결정

### 1. 지문을 **못박는 자리**를 스크립트에 둔다 — 임시 편집이 아니라 커밋되는 상수로

```js
const PINNED_RUNTIME_VERSIONS = {
  ios: { runtimeVersion: 'd304704e…', binaryAppVersion: '1.0.6' },
  android: { runtimeVersion: '3df849c0…', binaryAppVersion: '1.0.6' },
}
```

2026-08-25 의 안드로이드 단독 발행은 **워크트리 안에서 스크립트를 세 줄 고쳐** 했고 커밋하지
않았다. 그 방식의 대가가 셋이다 — 무엇을 발행했는지 저장소에 **기록이 남지 않고**, 다음 사람이
같은 편집을 다시 만들어야 하고, 값이 틀려도 **아무것도 막지 않는다**.

격차가 «일회성 사고» 가 아니라 **다음 스토어 빌드까지 이어지는 상태**이므로, 그 상태는 코드에
적혀 있어야 한다. `binaryAppVersion` 을 함께 드는 것은 «이 지문이 어느 바이너리의 것인가» 가
값만 봐서는 안 읽히기 때문이다.

### 2. 못박은 값이 **지금 발행돼 있는 판정값과 같은지** 발행 전에 확인한다

```
/latest?platform=<p> 의 runtimeVersion === PINNED[p].runtimeVersion  →  진행
그 밖                                                              →  중단
```

이 한 줄이 이 ADR 이 지키려는 것을 **그대로** 검사한다. 판정 파일과 다른 값을 못박는 순간
「스토어 업데이트가 필요해요」가 살아나므로, 사람이 값을 잘못 베끼는 경로를 여기서 끊는다.
`export` 앞에 두어 몇 분짜리 빌드를 태우기 전에 걸린다(노트 가드가 같은 자리에 있는 이유와 같다).

- 발행된 `latest-*.json` 이 아직 없으면(첫 발행) 이 검사는 **건너뛴다** — 비교할 대상이 없는
  것이지 어긋난 것이 아니다.
- 못박지 않은 플랫폼에는 적용하지 않는다.

### 3. 못박은 채로 발행해도 **`latest-*.json` 의 `runtimeVersion` 은 안 바뀐다**

같은 값을 다시 쓰므로 판정은 그대로고, `appVersion` 만 1.0.7 로 오른다. 스토어 사용자는
매니페스트를 **받고**(이름이 자기 지문이다) 판정에서도 걸리지 않는다.

옛 사이드로딩 빌드(08-14 지문)를 든 기기는 여전히 스토어로 가라는 모달을 받는다 — 그쪽은 실제로
옛 바이너리라 **맞는 안내**다.

### 4. 못박은 값은 **다음 스토어 바이너리가 나오면 지운다**

새 바이너리를 [[ADR-155]] 이후의 트리에서 구우면 그때부터는 트리 계산값이 곧 바이너리의 값이다
(`release.md` 규칙 1·2 를 지키는 한). 그 시점에 이 상수를 비우는 것이 정상 상태로의 복귀다.

스크립트는 못박은 플랫폼마다 **줄을 찍어** 그 사실을 발행자에게 알린다. 조용히 못박으면 다음
사람이 트리 계산값으로 나가고 있다고 믿는다.

## 무엇이 안 바뀌나

- **[[ADR-137]] 결정 3 의 정신은 남는다** — 지문은 여전히 «계산되는 값» 이고, 우리가 적는 것은
  트리가 그 값을 못 만들 때뿐이다. 상수는 «우리가 정한 새 규칙» 이 아니라 **바이너리에서 읽어 온
  사실**이다.
- `latest-*.json` 이 판정 파일이라는 것([[ADR-137]] 결정 4), 매니페스트 이름이
  `manifest-<platform>-<runtimeVersion>.json` 이라는 것, Worker 가 상태를 안 든다는 것.
- `release.md` 규칙 1~4. 이 결정은 그 규칙들이 **이미 어긋난 뒤** 무엇을 하느냐이지, 규칙을
  느슨하게 하지 않는다.

## 정정 1 (2026-08-30) — 못박기는 **혼자 쓰이면 안 된다**

이 문서대로 1.0.7 을 못박아 내보냈더니 **안드로이드 앱 이미지 273개가 전부 빈칸**이 됐다
([[ADR-191]]). 원인은 지문이 아니라 **에셋의 소스 경로**였다 — 안드로이드는 APK 에 박힌 이미지를
드로어블 리소스로 들고 그 이름을 `httpServerLocation` 에서 파생하는데, [[ADR-155]] 가 그 경로를
바꿨다.

**지문 불일치는 이름 문제가 아니라 «트리가 다르다» 는 정확성 신호였다.** 결정 1 은 그 신호를
못박아 지나갈 수 있게 만들었고, 그것이 이 사고의 문을 열었다.

그래서 못박기의 뜻을 바꾼다 — **발행을 가능하게 하는 장치가 아니라, 추가 조건을 강제하는 표식**이다.
`PINNED_RUNTIME_VERSIONS` 가 비어 있지 않으면 발행 스크립트는 **에셋 이름표를 요구**하고 export 뒤
전수 대조에 실패하면 **중단**한다([[ADR-191]] 결정 3). 결정 2 의 판정값 대조는 그대로 살아 있고,
그 위에 이 관문이 하나 더 선다.

결정 4(다음 스토어 바이너리가 나오면 비운다)는 그대로다 — 이제 **이름표와 플러그인도 함께** 치운다.

## 대가

- **다음 스토어 빌드까지 트리 계산값이 죽은 값이 된다.** 그 사이에 네이티브를 고치면 OTA 로는
  못 나가는데 스크립트는 그것을 모른다 — 못박은 지문은 «옛 네이티브» 를 가리키기 때문이다.
  그래서 이 상수가 살아 있는 동안 **네이티브 변경은 스토어 빌드로만** 나간다(규칙 5 에 적었다).
- 1.0.7 의 JS 가 1.0.6 바이너리에서 도는 근거는 **지문이 아니라 사람이 확인한 사실**이다 —
  네이티브 의존성·로컬 모듈·`app.json` 이 1.0.6 과 같다는 것을 발행 전에 확인했다(아래).
