# ADR-096 가계부 기록 테이블 재설계

> ⚪ 미구현
> 관련 소스: `storage/sqlite/db.ts` · `storage/sqlite/migrations.ts` · `storage/spend.ts` · `storage/income.ts` · `features/cashbook/records.ts` · `lib/cashbook/categories.ts` · `lib/cashbook/spend-catalog.ts`

## 배경

손으로 적는 가계부 기록은 테이블 둘에 있다. `spend_records`(지출)와 `income_records`(수입)다.

세 가지가 문제다.

- **카드 이름을 기록 칸을 이어 붙여 만든다.** 하루 목록 카드의 이름은 `manualLabelOf` 가 화면을 그릴 때 심볼 · 항목 key ·
  형태 key · 직접 친 글자 · 갈래 이름 순서로 찾아 한 줄로 잇는다. 그래서 `지내우시 · 악몽선경 EXP 1단계` 처럼 제목과
  품목이 한 줄에 섞이고, 품목마다 원하는 이름을 따로 정할 수 없다.
- **한 기록에 품목이 여럿이어도 칸 하나에 담는다.** 에픽던전 추가 리워드의 두 형태는 `form_item_keys` 한 칸에 들어간다.
- **id 가 `시각 + 난수` 다**(`newRecordId`). 앱의 기본키는 uuid 한 칸이다([[ADR-077]] 결정 8).

카드는 두 줄로 바꾼다(사용자 지정 2026-10-24).

```
캐릭터이름 · 에픽던전        지내우시 · 심볼강화       지내우시 · 주문서                 지내우시 · 사냥
악몽선경 EXP 1단계, 솔에르다 1단계   세르니움 7 -> 10        매지컬 한손무기 공격력 주문서      8소재
```

이 결정은 #670 과 함께 정했고(2026-10-25), v1.0.13 스토어 바이너리로 낸다. #631 · #507 · #614 는 이 작업에 넣지 않는다(사용자 선택).

## 결정

### 결정 1. 수입과 지출을 테이블 하나로 합치고, 수입과 지출은 `flow` 칸으로 가른다

```
cashbook_records         id · ocid · flow · category_key · group_key · entry_date · memo · created_at · updated_at
  ├ cashbook_record_lines  id · record_id · position · item_key · custom_name · form_key · item_kind_key
  │                        · quantity · level_from · level_to · 금액 칸
  └ cashbook_hunt_inputs   id · record_id · 사냥 계산기 입력
```

- `flow` 는 `income` · `spend` 둘이다. 하루 목록과 기간 합계를 테이블 하나에서 읽으려고 합쳤다(사용자 선택).
- `category_key` 는 `flow` 와 함께 읽는다. 기타(`etc`)가 수입과 지출 양쪽에 있기 때문이다.
- `entry_date` 는 돈이 오간 날(KST `YYYY-MM-DD`)이고, 시트에서 고르며 고칠 수 있다. 달력 칸 · 하루 목록 · 기간 합계가
  이 값으로 기록을 놓는다. `created_at` 은 저장한 시각이라 사용자가 못 고치고, 같은 날 안의 차례를 정한다. 이름은 서버의
  날짜 칸 규칙(`from_date` 처럼 `_date`)을 따랐다. 옛 `spent_on` · `earned_on` 을 옮긴다(사용자 지정).
- 사냥 계산기 입력은 수입 사냥에만 있어서 `cashbook_hunt_inputs` 로 뺀다. 기록 하나에 0개나 1개다. 합친 테이블에 두면
  지출 행마다 빈 칸이 열 개 넘게 붙는다.
- 보스 결정석 · 보스 드롭 판매 · 강화 지출은 원천 테이블(보스 기록 테이블 · `enhancement_history`)에 그대로 둔다. 카드는
  같은 두 줄 규칙으로 그린다.

### 결정 2. 금액 · 수수료 · 관세는 품목 줄마다 둔다

기록 한 건의 금액은 그 기록에 딸린 줄의 금액을 더한 값이다. 기록 행에는 금액 칸을 두지 않는다. 두 곳에 두면 줄 합계와
기록 금액이 어긋날 수 있기 때문이다. 줄마다 두면 품목별 금액 표시나 품목별 통계를 나중에 더할 수 있다(사용자 선택).

메소 · 포인트 · 포인트 시세 · 캐시 금액과 판매 수수료(`sale_fee_*`) · 구매 관세(`tariff_meso`)가 모두 줄의 칸이다.
수수료와 관세는 품목의 금액에 붙는 값이라, 금액과 같은 줄에 있어야 줄 금액을 그 줄만으로 셀 수 있다(사용자 선택).

### 결정 3. 카드 이름은 서버 참조표에 두고, 기록은 key 와 숫자만 갖는다

- 첫 줄 제목은 묶음의 `card_title` 이다. 묶음이 없는 갈래(심볼 강화 · 아이템 구매 · 기타 · 사냥 등)는 갈래의 제목을 쓴다.
- 둘째 줄은 줄마다 항목의 `name`(직접 친 품목이면 `custom_name`)에 형태 · 단계 · 레벨 · 수량을 이어 적는다.
- 항목의 `name` 은 원본 이름이다. 화면 자리가 좁아 줄여 쓰던 이름은 새 칸 `short_name` 에 따로 두고, 시트 타일처럼 좁은
  곳에서만 쓴다. 비어 있으면 `name` 을 쓴다. 카드 이름 칸을 따로 두지 않는 이유는 원본 이름이 곧 카드 이름이라 칸이
  겹치기 때문이다(사용자 지정 2026-10-25). 예를 들어 `블루베리 농장 입장권` 이 `name`, `블루베리 농장` 이 `short_name` 이다.
  확률이 하나뿐인 주문서도 확률을 이름에 남긴다(`매지컬 한손무기 공격력 주문서 100%` · `귀 장식 마력 주문서 10%`).
- 에픽던전 리워드 형태도 같은 규칙이다. 원본 이름 `경험치` · `솔 에르다` 를 카드에도 쓴다
  (`악몽선경 경험치 1단계, 솔 에르다 1단계`, 사용자 지정).
- 이름을 서버에 두는 이유는 관리 화면에서 고치면 앱 업데이트 없이 바뀌기 때문이다(사용자 선택). 서버 작업을 함께 한다.
- 갈래와 에픽던전 리워드 형태도 서버로 옮긴다(사용자 선택). 지금 서버에는 둘 다 enum(`spend_category` 넷 · `spend_form`
  둘)뿐이고 이름은 앱 상수(`SPEND_CATEGORIES` · `INCOME_CATEGORIES` · `SPEND_FORMS`)가 든다. 그래서 묶음이 없는 갈래의
  제목과 형태의 카드 이름을 둘 자리가 서버에 없다. 서버에 갈래 표(수입 · 지출 갈래 열하나)와 형태 표를 만들고, 앱
  상수는 다른 게임 데이터처럼 서버 데이터의 번들 사본이 된다([[ADR-020]]).
- 갈래는 `GET /v1/game-data` 의 새 칸 `cashbookCategories` 로 내려준다(사용자 선택). 수입 갈래까지 담으므로 지출 목록 칸
  (`spendCatalog`)에 넣지 않는다. 형태는 지출 목록 칸에 남는다.
- 관리 화면에서 갈래의 이름 · 카드 제목 · 그림 · 설명 · 차례를 고치고, 새 갈래도 더한다(사용자 선택).
- 앱은 갈래 key 마다 입력 폼이 코드로 정해져 있다. 그래서 관리 화면에서 새로 더한 갈래는 앱에 그 폼이 생길 때까지 갈래
  목록에 이름만 서고, 못 고르게 막아 둔다(사용자 지정). 운영자가 앱 작업을 마칠 때까지의 상태다.
- 갈래 key 는 서버에서 ENUM 이 아니라 글자다. 관리 화면에서 더하기 때문이다. 구현할 때 [[ADR-020]] 결정 9 의 ENUM 목록에서
  지출 분류 · 형태를 빼고, 이름을 앱 상수에 둔다는 문장도 함께 고친다.
- 심볼 강화의 둘째 줄은 심볼 이름(`symbols.name`)을 그대로 쓰고, 사냥은 수량과 단위만 적는다. 두 표에는 칸을
  더하지 않는다(사용자 선택).
- [[ADR-078]] 결정 6 과 같은 이유로 서버 게임 데이터의 key 는 지우지 않는다. 기록이 key 만 가지므로 key 가 사라지면
  그 기록의 이름을 찾을 수 없다.

### 결정 4. 둘째 줄의 수량에는 단위를 붙인다

`8소재` · `3회` 처럼 수량 뒤에 그 항목의 단위를 붙인다(사용자 지정). 단위는 서버 항목의 `unit` 이 든다.

### 결정 5. 기록 id 는 uuid 이고, 옛 기록의 id 도 uuid 로 바꾼다

새 기록은 `expo-crypto` 의 `randomUUID()` 로 만든다. 옛 `시각 + 난수` id 는 이관할 때 uuid 로 바꾼다(사용자 선택). 지금
옛 id 를 가리키는 곳은 없다. 서버 동기화 대기 표(`server_sync_queue`)는 드롭 가격만 가리킨다.

### 결정 6. v1.0.13 스토어 바이너리로 내고, 옛 테이블 둘은 v1.0.14 에서 지운다

[[ADR-078]] 결정 9 와 같은 이유다. OTA 가 실패해 옛 코드로 돌아가도 DB 가 열려야 하므로 v1.0.13 에서는 옛 테이블을
지우지 않는다.
