### ADR-065: 무음 실패 5곳 처리 — 실패했는데 신호가 없던 자리들 (구현 완료, 2026-07-30)

> 🟡 **PARTIALLY SUPERSEDED — 일부 폐기.** 캐시 삭제 실패 토스트 하나는 RN 에 이식되지 않았다([[ADR-128]]).
> 나머지 결정은 유효하다 — 인용 전 본문에서 해당 결정 번호를 확인할 것.

**배경**: 실패·에러 텍스트 전수 조사(2026-07-30)에서 [[ADR-062]]·[[ADR-063]]이 표시 방식과 배치 기준을 정했다. 남은 것은 **아예 신호가 없던 자리**들이다 — error-resilience.md 원칙 1("실패는 숨기지 않는다") 위반이 5곳 있었다.

각 자리의 배치는 [[ADR-063]] 원칙 4로 판정했다 — *그 문구가 사라진 자리에 남는 것이 있는가.*

| 자리 | 남는 것 | 판정 |
|---|---|---|
| A 온보딩 API 키 | 폼 | 토스트 |
| B OTA 다운로드 | 없음(모달이 사라진다) | 모달 안 분기 |
| C 캐시 삭제 | 모달 — 단 리로드가 파괴한다 | 리로드 후 토스트 |
| D 관리 화면 토글 | 체크박스 | 토스트 |
| E 렌더 예외 | 없음(화면이 죽었다) | 전체 화면 폴백 |

선택지는 `/debug/silent-failures`(`feat-debug-silent-failures` 브랜치)에서 실물과 나란히 비교해 골랐다.

**결정**:

1. **A — 온보딩 API 키 실패는 원인별 문구로 알린다.** 새 UI는 없다.
   - `submitApiKey` 에는 **이미 토스트가 있었다** — 문제는 문구가 `'API 키를 확인하지 못했습니다'` 하드코딩이라 원인을 잃는 것이었다. 바로 아래에서 `toOnboardingError(error)` 로 원인을 계산해 state에 넣는데 토스트는 그 값을 쓰지 않았다. [[ADR-063]] 결정 2(스토어가 원인을 버리던 문제)와 같은 종류다.
   - `hydrate` 실패(저장된 키로 재실행했다가 조회 실패)에는 토스트가 **아예 없었다** — 아무 설명 없이 API 키 입력 화면으로 되돌아갔다.
   - `setApiKey`(키 저장) 실패는 `try` 밖이라 미처리 rejection이었다 — 아무 일도 안 일어난 것처럼 보였다. 감싸서 `storageWriteFailed` 로 알린다. `formatOnboardingError` 의 그 문구가 **처음으로 도달 가능해진다**.
   - 액션은 두지 않는다 — 온보딩 중에는 설정 화면이 없고, 재시도는 사용자가 폼에서 어차피 다시 누른다.
   - `formatOnboardingError` 를 `app/onboarding/` 에서 `features/onboarding/` 으로 옮긴다. 스토어(features)가 그 함수를 쓰는데 `app/` 에 있으면 레이어가 거꾸로다 — `features/schedule-sync/format.ts` 와 같은 자리로 맞춘다.

2. **B — OTA 다운로드 실패에 모달 분기를 추가한다.** `MODAL_STATUSES` 에 `'error'` 가 없어 모달이 소리 없이 닫히던 것을 고친다. 기존 5분기와 같은 골격(아이콘 배지 + 제목 + 설명 + 버튼)을 쓰되 배지 톤만 error다.
   - **매니페스트 조회 실패(자동 확인)는 모달을 띄우지 않는다.** 사용자가 시작하지 않은 실패라 조용히 넘긴다 — 다운로드 실패만 모달이다. 그래서 스토어가 두 실패를 구분해야 한다(`error` → `download-error`).
   - **부 동작(`나중에`)의 크기를 줄인다**(사용자 지적) — 주 동작과 같은 `px-5 py-2.5 text-sm` 이라 비중이 너무 컸다. `px-4 py-1.5 text-xs` + 버튼 간격 `space-y-1`, 모달 하단 패딩 `pb-4`.
   - 이 버튼은 `GHOST_BTN` 상수이고 **4개 분기가 공유**한다(update-available·confirm-cellular·ready-to-apply·store-required). error 분기만 다르게 두면 한 모달 안에서 부 동작 크기가 갈리므로 **상수를 줄여 전부 바꾼다**.

3. **C — 캐시 삭제 실패는 리로드 뒤에 토스트로 알린다.** 실패해도 리로드가 실행되므로(`clearCacheData` → 스플래시 → `closeBossProfitDb` → `reload`) 화면 신호가 전부 파괴된다. 그 흐름은 **그대로 두고** 알리기만 한다.
   - 리로드를 막거나(실패 시 모달 유지) 타임아웃과 실패를 구분하는 안은 **채택하지 않았다**(사용자 결정) — 부분 삭제 상태를 되돌리는 조치도 하지 않는다.
   - 배관: `sessionStorage` 에 플래그를 남기고 부팅 후 읽어 띄운다. **`Preferences`(영속)를 쓰지 않는 이유**는 앱을 다시 켜도 남아 한참 뒤에 엉뚱하게 뜨기 때문이다 — 리로드는 넘기고 앱 종료와 함께 사라지는 `sessionStorage` 가 의미에 맞다.
   - CLAUDE.md 아키텍처 규칙상 `features/`·`app/` 이 저장소를 직접 만지지 않으므로 `storage/pending-notice.ts` 어댑터를 둔다.
   - 타임아웃(응답 없음)도 실패와 같이 알린다 — 둘을 구분하는 게 (c)안이었고 채택하지 않았다. 어디까지 지워졌는지 알 수 없으므로 문구는 **"캐시를 일부만 삭제했습니다"** 다.

4. **D — 관리 화면 토글 저장 실패를 토스트로 알린다.** `ContentManageScreen` 이 `void` 로 프로미스를 버리고(2곳), `BossManageScreen` 의 보스 추가/제거·난이도 교체에 `try/catch` 가 없어 체크가 조용히 되돌아가는 것 외에 설명이 없었다.
   - 문구는 **"추적 목록을 저장하지 못했습니다" 하나로 통일**한다 — 같은 화면 안에서 무엇을 토글했는지는 사용자가 알고 있어 컨텐츠/보스를 구분할 이유가 없다.
   - 재시도 액션은 두지 않는다 — 다시 탭하면 되는 일이라 액션이 중복이다.

5. **E — 전역 에러 바운더리를 두되, 폴백은 최소로 한다.** 렌더 중 예외가 나면 아무 문구 없는 흰 화면이 남던 것을 고친다. 아이콘 + 제목 + 짧은 설명 + **`다시 시작` 하나**뿐이다.
   - `설정 열기`(캐시 삭제로 가는 길)도 `자세한 내용`(스택트레이스)도 **넣지 않는다**(사용자 결정). 브랜드 마크도 없다.
   - 근거: 이 화면의 목적은 복구 도구를 주는 게 아니라 **흰 화면을 없애는 것**이다. 리로드로 안 풀리는 반복 크래시라면 앱 안에서 할 수 있는 게 없고, 그때의 탈출구(OS 설정의 앱 데이터 삭제·재설치)는 앱 밖에 이미 있다. 선택지를 하나로 줄이면 그 하나가 분명해진다.
   - **크래시 리포팅은 이 결정에 포함하지 않는다.** opt-in 토글·전송 항목(원칙 7)을 정해야 하므로 바운더리만 먼저 넣는다. `lib/error-reporting` 은 여전히 없다.

**트레이드오프**:

- **C의 토스트는 리로드 뒤에 뜨므로 삭제 모달과 시간이 떨어진다.** 사용자가 맥락을 잃을 수 있지만, 리로드를 막는 쪽이 부분 삭제 상태로 앱을 계속 돌리는 위험을 만든다고 봤다.
- **C는 `sessionStorage` 를 새로 쓴다.** 앱의 다른 저장은 전부 Capacitor `Preferences` 다 — 저장 매체가 하나 늘지만, "리로드는 넘기되 앱 종료와 함께 사라진다"는 의미를 Preferences로는 표현할 수 없다.
- **B의 `GHOST_BTN` 축소가 4개 분기에 파급된다.** 의도한 것이다(한 모달 안 일관성). 다만 error 분기만을 위한 변경이 기존 화면 4곳의 모양을 바꾼다.
- **E는 스택트레이스를 남기지 않아 사용자 문의 시 붙일 정보가 없다.** 프로덕션 번들이 난독화돼 정보량이 적고, 이 상황이 실제로 거의 발생하지 않을 것으로 봤다(사용자 판단).
- **E의 폴백은 리로드로 안 풀리는 크래시에서 무한 반복이 된다.** 앱 안 탈출구를 의도적으로 두지 않은 결과다.

**적용 범위 밖**: 429 새로고침 disabled · 에러 매퍼 3중 복제 · 참조 무결성 표기 3종 · 설정 계정 모달의 `다시 시도` 버그(이슈 #78 D) · `refreshAccounts` 의 원인 오분류.
