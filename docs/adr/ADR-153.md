# ADR-153: today 는 «보고 있는 기간» 이 아니라 «지금 기간» 을 읽는다 — 보스 수익 스토어가 둘을 갈라 낸다

**날짜**: 2026-08-19
**상태**: **(구현 완료, 2026-08-19 · 실기기 미검증)** — `app-rn` 한정(today 는 RN 에만 있다).
스토어 변경은 `packages/core` 라 두 앱이 함께 받지만, `currentPeriodRows` 를 읽는 화면은 today 하나다.
**관련**: [[ADR-147]](today 설계 — 위젯 3·5 의 원천) · [[ADR-023]](주간/월간 탭·기간 네비게이션) ·
[[ADR-054]](월드별 결정석 한도) · [[ADR-124]](아이템 수익 합산) · [[ADR-111]](`latestSyncSnapshot` 과
기록 합집합) · [[ADR-096]](탭 상태를 스토어가 소유한다)

## 맥락

사용자 보고(2026-08-19):

> 위젯의 값이 보스 수익 페이지에서 주간 → 월간으로 이동시킨 후에 today 화면으로 이동하면 주간
> 결정석 판매 개수, 보스 수익 같은 주간 보스 수익 관련 데이터를 참고하는 위젯에서 값이 없어져.

재현 경로가 짧고 **결정적**이다. 보스 수익 화면에서 탭을 옮기는 것만으로 today 의 숫자가 사라진다.

### 원인 — 한 값의 뜻이 두 화면에서 다르다

보스 수익 스토어의 `rows` 는 «사용자가 보고 있는 (탭, 기간)» 한 조각이다:

```ts
// rows.ts
filterRowsForTab(rows, tab, periodKey) // row.cycle === tab && row.periodKey === periodKey
```

`cycle` 을 함께 거르므로 **월간 탭에서는 주간 행이 한 줄도 남지 않는다.** `loadPeriod` 는
`dropsByRowKey` 도 그 조각 기준으로 다시 채우므로 이번 주 드롭 항목도 같이 사라진다.

today 는 그 둘을 그대로 받아 **자기 자를 한 번 더** 댄다(`view-model.ts` 의 `buildProfit` —
`row.cycle === 'weekly' && row.periodKey === 이번 주`). 두 자가 겹칠 때만 값이 남고, 월간 탭에서는
교집합이 공집합이다 → 위젯 3(주간 보스 수익)과 위젯 5(주간 결정석 판매 한도)가 **동시에** 빈다.

위젯 4·7·8(최고가·미입력·가뭄)이 멀쩡한 것도 같은 설명이다 — 그쪽 원천은 `drop-history` 스토어라
보스 수익 화면의 네비게이션과 무관하다. 사용자가 *"주간 보스 수익 관련 데이터를 참고하는 위젯"* 이라고
가른 경계가 정확히 이 경계다.

### 이것은 «적어 둔 대가» 였다

`docs/features/today.md` 는 이미 *"스토어가 다른 탭·기간을 보고 있으면 그 행은 세지 않는다"* 고
적어 두었다. **적어 두는 것으로는 부족했다** — 화면 둘이 한 값을 공유하는데 그 값의 뜻이 한쪽(보스
수익 화면)에서는 «보고 있는 것», 다른 쪽(today)에서는 «지금» 이다. 뜻이 둘이면 한쪽은 반드시 틀린다.

## 결정

1. **스토어가 두 값을 낸다.** `rows`·`dropsByRowKey` 는 그대로 «화면이 보고 있는 것» 이고,
   **`currentPeriodRows`** 를 새로 낸다 — «지금 기간의 행 전부»(주간·월간 두 주기가 함께 들어 있고,
   today 는 종전대로 자기가 주간만 거른다). today 는 `rows` 대신 이 값을 읽는다.
2. **새 원천이 아니라 이미 있는 것을 노출한다.** `currentPeriodRows` 의 내용은 모듈 스코프
   `latestSyncSnapshot.rows` 와 **같다**([[ADR-111]] 이 만든 그 스냅샷이 이미 «지금 기간 전부» 다).
   그것을 **커밋 자체에 얹는다** — 스토어의 `set` 을 한 겹 감싸 어느 커밋이든 그 시점의 스냅샷을
   함께 싣는다. 사본이 둘인 것 자체보다 «갱신 자리가 흩어지는 것» 이 위험이고, 그 위험은
   `setPartySize` 에서 실제로 한 번 터진 적이 있다(2026-07-22, 그 함수의 주석).

   **처음엔 «스냅샷을 바꾸는 자리마다 `set` 을 한 번씩 더 부르는» 모양으로 갔고, 기존 테스트가
   그것을 막았다** — [[ADR-097]] 결정 5 정정 3 의 *"건너뛴 진입의 커밋은 1회"* 는 로딩이 한 프레임
   번쩍이는 것을 막는 계약이라, 커밋을 늘리는 방식은 그 계약을 깬다. `set` 래퍼는 **커밋 수를 그대로
   두고** 같은 불변식을 세운다. 대신 조건이 하나 붙는다: 스냅샷 대입은 **그것을 화면에 반영할 `set`
   보다 앞**에 와야 한다(`setPartySize` 의 두 줄 순서를 그래서 뒤집었다).
3. **드롭은 사본을 만들지 않는다.** `dropsByRowKey` 를 «보고 있는 기간 **∪** 지금 기간» 의
   상위집합으로 둔다. 키(`dropRowKey`)에 `periodKey` 가 들어 있어 두 기간이 한 맵에 있어도 충돌이
   없고, 사본을 두면 드롭 편집 경로(`setBossDrops`·`applyExternalDropEdit`)가 **둘로 갈려** 같은
   결함이 아이템 수익 쪽에서 되풀이된다.
4. **기간 이동은 `currentPeriodRows` 를 건드리지 않는다.** `loadPeriod`(탭 전환·‹ ›)는 화면의 조각만
   바꾼다 — 그래야 today 가 사용자의 네비게이션에 흔들리지 않는다는 이 ADR 의 문장이 구조로 선다.

## 기각한 안

- **보스 수익 화면을 떠날 때 스토어를 주간·현재 기간으로 되돌린다** — [[ADR-096]] 결정 1·2(탭 상태를
  스토어가 소유하고 화면 복귀에도 유지한다)를 뒤집는다. 사용자는 월간을 보다 today 를 들렀다 돌아오면
  주간에 서 있게 된다. 게다가 소유권이 거꾸로다 — today 를 고치려고 **남의 화면 상태를 되돌리는**
  일이고, «지금» 을 요구하는 소비자가 하나 더 생기면 그때 다시 깨진다.
- **today 가 SQLite 에서 이번 주를 직접 읽는다** — 합산 판정이 두 벌이 된다([[ADR-147]] 결정 8:
  *"두 벌이 되면 today 와 원래 화면이 다른 수를 말한다"*). 지금 today 의 수익은 보스 수익 화면과
  **같은 함수**(`groupTotalMeso`·`summarizeWorldCrystals`)로 계산되고 그 성질을 잃을 이유가 없다.
- **위젯이 각자 스토어를 구독한다** — [[ADR-147]] 결정 4 가 이미 기각한 안이다(트리거가 위젯 수만큼
  늘고, 같은 기록을 보는 셋이 각자의 시점에서 읽는다).

## 대가

- **스토어 상태에 사본이 하나 는다.** 주간 탭·현재 기간에서 `rows` 와 `currentPeriodRows` 는 같은
  내용이다. 근거는 «둘의 뜻이 다르다» 이고, 어긋남을 막는 것은 결정 2 의 `set` 래퍼다.
- **그 래퍼는 커밋마다 한 필드를 더 쓴다** — 값이 안 바뀌어도 같은 배열 참조를 다시 실을 뿐이라
  구독자의 렌더가 늘지 않는다(zustand 는 상태 객체의 동일성으로 알리고, 그 객체는 어차피 새로 만들어진다).
- **`dropsByRowKey` 가 조금 커진다** — 보고 있는 기간과 지금 기간 **둘뿐**이고 방문한 모든 기간이
  아니다. 조회는 종전과 같이 한 번이다(`loadDropsByRowKey` 가 기간 키를 모아 한 번에 읽는다).
