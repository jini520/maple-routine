## 배경

넥슨 프렌즈 프로그램에 들어가면서 넥슨 Open ID 로그인(`게임 데이터 활용 로그인`)을 쓸 수 있게 됐다.
로그인하면 사용자가 API 키를 직접 발급받지 않아도 된다. 다만 Open ID 로 부를 수 있는 것은 프렌즈 경로
몇 개뿐이다. `character/basic` · 메소 · 공지 같은 나머지 경로는 여전히 API 키가 있어야 한다. 그래서
로그인이 API 키를 대신하지 않고, 두 수단을 함께 둔다.

넥슨 애플리케이션은 프로덕션 승인을 받았고, 콜백 주소 검수도 2026-11-05 에 승인됐다. 승인 전에는 등록된 테스트
사용자만 로그인할 수 있어서, 로그인 기능을 앱에 넣어 두고 화면에서는 꺼 두었다(결정 9).

## 결정

### 결정 1. 넥슨 로그인과 API 키를 함께 둔다

기기에는 인증 수단의 목록을 저장한다(`storage/api-key.ts`). 넥슨 로그인은 0 개나 1 개, API 키는 0 개
이상이다. 둘 중 하나라도 있으면 앱이 열리고, 하나도 없으면 로그인 화면이 나온다.

- 로그인을 하나만 두는 이유는 로그인이 앱 사용자를 구분하는 기준이고, 키는 그 사용자가 쓰는 자원이기
  때문이다. 다시 로그인하면 있던 로그인을 바꾼다.
- 키는 이름(`label`)과 함께 저장한다. 키 값은 서로 비슷해 보여서 이름이 없으면 목록에서 구분하기 어렵다.
  사용자가 이름을 붙이지 않으면 빈 문자열로 두고, 앱이 이름을 지어 넣지 않는다. 같은 키를 다시 넣으면
  목록에 더하지 않는다.
- 옛 설치본이 `apiKey` 칸에 저장한 키는 새 목록이 비어 있을 때 읽어 와 목록에 올린다. 옛 칸은 지우지
  않는다. 앱을 옛 버전으로 되돌려도 키를 잃지 않게 하려는 것이다. 옛 칸은 로그아웃 때만 함께 지운다([[ADR-017]] 결정 7).

메인 계정의 자격은 `lib/nexon-credential.ts` 의 `credentialOf` 가 정한다. 로그인이 있으면 로그인이고, 없으면
로그인 없이 쓰는 메인 키다(`mainKeyId`, [[ADR-101]] 결정 5). 로그인을 붙이면 같은 메이플 ID 의 키는 지워지므로(결정 4) 남은 키는 다른
넥슨 계정의 키다. 캐릭터마다 어느 계정의 자격으로 부르는지는 [[ADR-101]] 결정 4 에 있다.

### 결정 2. 넥슨 토큰은 서버가 갖고, 앱은 서버 세션만 갖는다

`client_secret` · 액세스 토큰 · 갱신 토큰은 모두 우리 서버에 둔다. 토큰 교환에는 `client_secret` 이
필요하고, 넥슨 보안 가이드라인이 액세스 토큰을 서버에서만 다루라고 정하고 있다. 앱이 저장하는 것은 서버가
발급한 세션 하나(`NexonLoginMethod.session`)뿐이다. 옛 설치본에 남아 있는 액세스 토큰 칸은 읽을 때 버린다.

로그인 사용자의 조회는 경로에 따라 두 가지로 나뉜다. 나누는 곳은 `nexon/http.ts` 의 `routeOf` 하나다.

| 경로 | 보내는 곳 | 싣는 것 |
|---|---|---|
| 프렌즈 경로 | 우리 서버의 프렌즈 스트림. 서버가 세션으로 사용자를 확인하고 넥슨을 대신 부른다 | 세션 |
| 그 밖의 경로 | 넥슨에 직접 | 앱에 들어 있는 개발자 키 |

서버 쪽 스트림의 동작은 [[ADR-016]] 에 있다.

개발자 키는 둘이다(`EXPO_PUBLIC_NEXON_API_KEY_1` · `_2`, `nexon/developer-keys.ts`). 요청마다 번갈아 써서
한도를 두 배로 쓰고, 무효(401 · 403 · 400 `OPENAPI00005`)나 한도 초과(429)가 난 키는 그 실행 동안 빼고 남은 키만
쓴다. 앱을 다시 켜면 다시 시도한다. 키가 앱 번들에 들어 있어 꺼내 쓸 수 있고, 그러면 우리 한도가 줄어든다.
넥슨이 그 키를 막으면 로그인 사용자 모두의 프렌즈 밖 조회가 함께 멈춘다. 사용자가 이 위험을 알고 고른
방식이다.

개발자 키로 난 키 실패는 사용자의 키 탓으로 보지 않는다. `toScheduleSyncError` 는 실패에 `developerKey` 가 실려
있으면 무효와 한도 초과를 `invalidApiKey` · `rateLimited` 가 아니라 `network` 로 바꾼다. 사용자가 고칠 수 없는
실패이기 때문이다. 키 탓으로 보내면 키 재입력 안내의 확인이 어느 키를 지울지 몰라 사용자의 API 키를 모두 지운다.

### 결정 3. 로그인 창은 `openAuthSessionAsync` 로 열고, 세션은 열쇠 둘로 받는다

`features/auth/nexon-login.ts` 의 `signInWithNexon` 이 다음 순서로 진행한다.

```
앱     서버에 시작을 요청한다(POST /auth/nexon/login). 서버가 authorizeUrl 과 redeemKey 를 준다
앱     openAuthSessionAsync 로 authorizeUrl 을 연다
넥슨   로그인 · 동의
넥슨   서버의 콜백으로 code 와 state 를 보낸다
서버   토큰을 교환해 세션을 보관하고 com.mapleroutine.app://oauth/callback?receipt= 로 앱에 돌려보낸다
앱     redeemKey 와 receipt 를 서버에 넘겨 세션을 받는다(POST /auth/nexon/session)
앱     그 세션으로 character/list 를 받는다. 메이플 ID 가 없으면 여기서 멈춘다(결정 10)
앱     세션을 인증 수단 목록에 저장한다
```

- `redeemKey` 는 로그인을 시작한 앱만 갖고 콜백 URL 에는 실리지 않는다. `receipt` 는 앱으로 돌아올 때만
  실린다. 그래서 돌아오는 요청을 가로챈 앱도, 로그인 시작을 흉내 낸 앱도 둘 중 하나만 가지게 되어 세션을
  받을 수 없다. `state` 는 콜백을 받는 서버가 확인한다. 서버 쪽 규칙은 [[ADR-016]] 에 있다.
- 서버가 아직 콜백을 처리하는 중(`pending`)이면 1초 뒤에 다시 묻고, 30번(`REDEEM_MAX_TRIES`)까지 묻는다.
  끝까지 `pending` 이면 실패다. `gone`(404)이면 바로 실패다.
- `openAuthSessionAsync` 를 쓰는 이유는 iOS 에서 이 함수가 ASWebAuthenticationSession 을 열어, 콜백 URL 이 그
  세션으로만 돌아오기 때문이다. `Linking.openURL` 로 Safari 를 열면 같은 스킴을 등록한 다른 앱이 콜백을 받을 수 있다.
  앱 안 웹뷰로도 열지 않는다. 주소창이 보이지 않으면 사용자는 자기가 어디에 비밀번호를 넣는지 확인할 수 없다.
- iOS 에서는 창을 `preferEphemeralSession` 으로 연다. 이 창은 Safari 나 다른 앱의 로그인 창과 쿠키를 나누지 않고,
  닫히면 쿠키를 버린다. 넥슨 로그인 창에서 네이버 · 구글 같은 소셜 계정으로 로그인하면, 그 서비스는 로그인 쿠키가
  남아 있는 동안 묻지 않고 같은 계정으로 넥슨에 돌려보낸다. 2026-11-12 에 아이폰에서 잘못 고른 네이버 계정으로 계속
  들어가 다른 계정을 고를 수 없었다. 그때 Safari 에는 네이버 로그인이 없었다. 로그인 창은 만료일이 있는 쿠키만 Safari 와
  나누고 세션 쿠키는 로그인 창끼리 남긴다는 개발자 보고가 있어, 사용자가 이 쿠키를 지울 곳이 없다. 넥슨 자체 로그인은
  원래 매번 ID 입력 화면을 띄우므로(2026-11-10 실측) 이 옵션으로 잃는 것이 없다.
- 안드로이드는 Chrome Custom Tabs 라 기본 브라우저와 쿠키를 나눈다. `expo-web-browser` 가 쓰는 androidx.browser 1.6.0 에는
  같은 옵션이 없어 지금은 그대로다. 사용자가 기본 브라우저에서 그 서비스에 로그아웃하면 다른 계정을 고를 수 있다.
- 스킴 `com.mapleroutine.app` 은 iOS 의 `Info.plist`(`CFBundleURLSchemes`)와 안드로이드의
  `AndroidManifest.xml`(`intent-filter`)에 등록되어 있다.
- 사용자가 창을 닫으면 `cancelled` 이고, 아무 일도 일어나지 않는다. 안내를 띄우면 사용자는 자기가 닫았는데도
  무엇이 잘못됐는지 찾게 된다.
- 넥슨 동의 화면에서 `취소` 를 눌러도 `cancelled` 다. 창을 닫은 것과 같이 사용자가 스스로 그만둔 것이기 때문이다.
  이때 넥슨은 콜백에 `error_name=user_cancel_consent` 를 보내고, 서버가 그 값을 돌아오는 주소에 그대로 싣는다.
  앱은 `receipt` 가 없고 `error_name` 이 `user_cancel_consent` 일 때만 `cancelled` 로 본다. 다른 `error_name` 은
  `failed` 다. 넥슨 동의 화면에는 거절 버튼이 따로 없고, 항목을 골라 일부만 동의하는 화면도 없다.
- 세션 저장에 실패하면 `failed` 다. 다음에 앱을 켰을 때 로그인 상태가 아니므로 성공이라고 하면 안 된다.
- 이 함수는 예외를 던지지 않고 `signedIn` · `noMapleId` · `cancelled` · `failed` 중 하나를 돌려준다. 부르는 쪽이
  화면이라서, 예외를 던지면 버튼마다 `try` 를 둬야 한다.

### 결정 4. 로그인하면 같은 메이플 ID 의 API 키를 서버에서 잇고, 로그인이 그 키의 계정 id 를 이어받는다

세션을 받으면 **저장하기 전에** `linkSameMapleIdKeys` 가 로그인과 각 키로 `character/list` 를 불러 메이플 ID(`account_id`)
집합을 견준다. 두 집합이 같은 키를 고른다(`lib/covered-keys.ts` 의 `apiKeysCoveredByLogin`). 캐릭터(ocid)가 아니라 메이플 ID 로
견준다(사용자 지정). 캐릭터가 하나도 없는 메이플 ID 도 견줄 수 있다.

고른 키마다 그 키의 해시를 서버에 보내 로그인한 사람과 잇는다(`POST /v1/me/api-key-links`, [[ADR-017]] 결정 9). 그다음
로그인을 저장하면서 서버가 받은 키를 같은 저장에서 빼고, 로그인은 첫 키의 넥슨 계정 id 를 이어받는다([[ADR-098]] 결정 5).

- 키를 지우면 해시를 다시 만들 수 없다. 그래서 잇기 전에 지우면 그 키로 보낸 기록이 서버에서 다른 사람으로 계속 남는다.
- 저장하기 전에 하는 이유는 로그인이 새 id 로 먼저 저장되면 강화 수집기가 그 id 로 키 시절 날짜를 다시 받기 때문이다. 강화
  합계는 계정을 가리지 않고 더하므로 같은 지출이 두 번 세어진다.
- 같은 넥슨 계정의 키를 두 수단으로 갖고 있을 필요가 없고, 키는 기기에 평문으로 저장되어 있어 지우는 편이 안전하다.
- 메이플 ID 가 다른 키는 잇지도 지우지도 않는다. 지우면 그 계정의 캐릭터를 볼 수 없게 된다.
- 어느 한쪽이 메이플 ID 를 하나도 주지 않았으면 고르지 않는다. 조회가 실패했을 수 있어서, 빈 집합을 같다고 읽으면 멀쩡한
  키가 지워진다.
- 서버가 받지 못한 키(응답 없음 · 거절)는 지우지 않는다. 로그인한 채 앱을 켤 때(`restoreFromStorage`) `pruneCoveredApiKeys` 가
  같은 일을 다시 한다(사용자 선택). 다음 로그인까지 미루면 로그인이 유지되는 동안 키가 기기에 평문으로 남는다. 그래서 로그인과
  메이플 ID 가 다른 키를 함께 둔 기기는 앱을 켤 때마다 `character/list` 를 수단 수만큼 더 부른다.
- 앱을 켤 때 다시 할 때는 로그인이 이미 자기 id 로 기록을 썼을 수 있다. 그 id 의 기기 기록을 이어받은 id 로 옮긴 뒤 저장한다.
- 잇거나 고르지 못해도 로그인은 성공이다. 거둔 키가 없으면 로그인은 그 메이플 ID 가 속했던 옛 계정 id 를 잇고, 없으면 자기
  id 로 저장된다([[ADR-098]] 결정 5). 남은 키는 다음에 앱을 켤 때 다시 다룬다.

### 결정 5. 로그인 버튼은 넥슨이 준 이미지 한 장을 비율 그대로 늘려 쓴다

넥슨 Open ID 검수에서 로그인 버튼 화면을 확인한다. 그래서 버튼은 이 앱의 디자인 시스템이 아니라 넥슨의
`로그인 버튼 사용 가이드` 를 따른다. 가이드는 색(`#0077FF`) · 모서리(`6px`) · 심볼 · 글꼴을 정해 두고,
글자를 일그러뜨리거나 가이드에 없는 비율로 쓰는 것을 금지한다.

- `wide-center` 이미지를 쓴다. `narrow` 는 폭이 고정이라, 폭이 꽉 찬 다른 버튼과 나란히 두면 폭이 맞지 않는다.
- `Image` 하나로 폭만 `100%` 로 정하고 높이는 정하지 않는다. 종횡비는 `naturalAspectStyle` 이 이미지의 원래
  크기에서 읽는다. 높이까지 정하면 그림이 일그러져 가이드를 어기게 된다. 712 · 96 같은 크기를 코드에 직접
  적지 않는 이유는 이미지를 바꿀 때 두 곳이 어긋나지 않게 하기 위해서다.
- 가이드는 비율을 지킨 확대와 축소를 허용한다. 그래서 넓은 화면에서 버튼이 함께 커져도 규정 위반이 아니다.
- 이미지는 `src/assets/nexon/login-button-wide-center.png`(sizeL, 712×96) 한 장이다. 받은 sizeM(356×52)은
  sizeL 의 절반 크기가 아니라 비율이 다른 버튼이어서 RN 의 `@2x` 규칙으로 묶을 수 없다. 둘 중 해상도가
  높은 sizeL 을 쓴다.
- 부품은 `components/molecules/NexonLoginButton/` 에 둔다. 넥슨의 규정을 따라야 하는 부품이라 일반 기본
  부품을 모아 둔 `atoms` 와 성격이 다르다. 스크린리더가 읽는 이름(`넥슨ID 로그인`)은 `Pressable` 에 두고
  그림은 읽지 않게 한다.

### 결정 6. 버튼은 로그인 화면과, today 머리의 `넥슨 ID 연동하기` 가 여는 시트에 둔다

API 키로 이미 들어온 사용자는 로그인 화면을 다시 볼 일이 없다. `SignInScreen` 은 저장된 수단이 하나도 없을
때만 나오기 때문이다. 그래서 앱 안에도 입구를 하나 둔다. 자리는 today 머리의 캐릭터 관리 버튼 왼쪽이다
(사용자 지정). today 는 앱을 켜면 처음 보이는 화면이라, 탭을 옮기지 않아도 입구가 보인다.

머리에는 넥슨 버튼을 바로 두지 않는다. 글자 버튼 `넥슨 ID 연동하기` 를 두고, 누르면 바텀시트
(`app/auth/NexonLinkSheet.tsx`)가 열린다. 넥슨 버튼은 결정 5 대로 넥슨의 그림을 폭에 맞춰 늘려 쓰므로
머리 한 줄에 들어가지 않는다.

- 머리 버튼(`app/today/NexonLinkButton.tsx`)은 바탕 없는 글자 버튼이다. 글자는 `text-xs font-semibold
  text-primary-ink` 다. 시안의 모양 다섯 가운데 사용자가 골랐다.
- 시트는 왼쪽 정렬이다. 위에서부터 제목 `넥슨 ID 연동하기`, 설명 두 줄, 넥슨 버튼, `게임 데이터 활용 로그인이란?`
  링크가 선다(사용자 지정). 설명은 API 키 경고 모달과 같은 문장이다(`일부 기능은 넥슨 로그인으로만 쓸 수 있어요.` ·
  `앞으로 나오는 기능도 넥슨 로그인을 기준으로 만들어요.`). 설명은 줄바꿈이 생기지 않게 시트 제목 아래 설명의
  크기(`text-xs`)로 쓴다.
- 제목은 시트 머리(`header`)에 두고, 설명 · 넥슨 버튼 · 링크는 스크롤 안에 둔다(사용자 지정). 머리 없이 제목까지
  스크롤 안에 두면 내용을 끌어 올릴 때 핸들 띠 뒤로 내용이 비친다(실기기). 머리는 핸들 띠까지 시트 바탕색으로
  칠해져 있어 그 뒤가 가려진다.
- 시트에 닫기 버튼은 없다. 다른 바텀시트처럼 끌어 내리거나 바깥을 눌러 닫는다.
- 시트의 넥슨 버튼을 누르면 시트를 닫고 로그인을 시작한다. 경고 모달의 넥슨 버튼과 같다. 시트는 토스트보다
  위에 그려진다. 시트를 연 채로 로그인하면 실패 토스트가 시트에 가려진다.
- 머리 버튼은 넥슨 로그인이 없을 때만 보인다(`hasNexonLogin()`). 화면에 들어올 때마다 다시 확인한다.
  확인하기 전에는 보이지 않는다. 로그인한 사용자에게 보였다가 사라지면 버튼이 깜빡이기 때문이다.
  로그인하면 버튼이 사라진다. 로그인이 만료돼 지워지면 다음에 화면에 들어올 때 다시 보인다.
- 로그인 화면에도 둔다. 로그아웃해서 수단이 하나도 남지 않으면 로그인 화면만 보이고 탭은 보이지 않는다.
  여기에 버튼이 없으면 그 사용자는 다시 로그인할 수 없다.
- 두 버튼은 같은 스토어 동작(`signInWithNexonAccount`)을 부른다. 이 동작이 로그인이 받아 온 `character/list`
  로 진입 단계를 다시 판정하고(`resolveAfterSignIn`) 토스트까지 띄운다. 연동 시트는 버튼을 숨길지만 정한다.
- 로그인 화면의 버튼만 `{ fresh: true }` 를 넘긴다. 세션을 받은 뒤 저장하기 전에 추적 목록을 비워 캐릭터를 새로 고르게
  한다([[ADR-101]] 결정 14). 연동 시트는 키로 쓰던 사람이 로그인을 붙이는 것이라 비우지 않는다. 비우는 것은 메이플 ID 를
  확인한 뒤다(결정 10). 메이플 ID 가 없는 넥슨 ID 면 앞 로그인의 추적 목록이 그대로 남는다.
- 로그인 화면은 성공하면 다음 온보딩 화면(`CharacterSetup`)을 민다. API 키로 로그인할 때와 같다. 진입 단계가
  `ready` 가 되면 스택 전체가 탭으로 바뀌어 밀 것이 없다. 처음 쓰는 사용자는 고른 캐릭터가 없어 `ready` 가 아니다.
  밀지 않으면 로그인이 됐는데도 로그인 화면에 머문다.
- 로그인이 진행 중이면 다시 눌러도 새로 시작하지 않는다. 로그인 창은 한 번에 하나만 열 수 있어서, 두 번째 시작은
  창을 열지 못하고 실패 토스트를 낸다. 그사이 첫 로그인은 그대로 끝나므로, 사용자는 로그인이 됐는데도 실패했다는
  말을 듣는다.
- 성공하면 `넥슨 계정을 연결했어요` 토스트가 뜬다. 실패하면 `넥슨 로그인에 실패했습니다` 토스트가 뜨고,
  취소하면 아무 일도 없다. 캐릭터 목록을 받지 못해도 실패다. 목록은 로그인을 저장하기 전에 받으므로(결정 10)
  그때 로그인은 저장되지 않았다.

### 결정 7. 로그인 화면은 넥슨 로그인 하나를 앞에 세우고, API 키는 경고를 거쳐 상단 시트에서 받는다

넥슨 로그인이 주 경로이고, API 키는 되도록 쓰지 않게 한다(사용자 지정 2026-10-27, #757). 앞으로 일부 기능은
넥슨 로그인으로만 쓸 수 있게 되기 때문이다. 그래서 첫 화면에서 API 키의 비중을 최대한 낮추고, 키로 가려는
사용자에게는 경고를 먼저 보여 준다.

```
첫 화면    (왼쪽 위) 자주 묻는 질문                       14px · text-muted · 글자 버튼 · [[ADR-150]] 결정 8
           🍁 메이플 루틴                               스플래시의 잎(primary) + 메이플스토리 서체 글자(text) · 글자 34
                                                       ↕ 64
           넥슨 Open API의 메이플스토리 스케줄러와 강화 기록을
           불러오려면 넥슨 로그인이 필요해요.             14px · text-muted
           [ 넥슨ID 로그인 ]
           게임 데이터 활용 로그인이란? ↗                12px · primary-ink · 링크
           (화면 맨 아래) API 키로 시작하기               12px · text-muted · 글자 버튼
경고 모달  ⚠ API 키로 시작할까요?
           [🔒 일부 기능은 넥슨 로그인으로만 쓸 수 있어요]   card-inset 칸
           [앞으로 나오는 기능도 넥슨 로그인을 기준으로 만들어요.]   card-inset 칸 · text-muted
           [ 넥슨ID 로그인 ]
           그래도 API 키로 시작하기                       12px · text-muted · 글자 버튼
상단 시트  🔑 API 키로 시작하기            ⚠ 일부 기능 제한
           Nexon Open API 키           openapi.nexon.com에서 확인 ↗
           [ 입력칸 ]
           (     확인     )
           API 키 발급 방법 보기 ↗
```

첫 화면은 이렇게 둔다.

- 첫 화면에는 넥슨 로그인 하나만 크게 둔다. 이름 · 설명 · 넥슨 버튼 · 소개 링크를 한 덩어리로 화면 세로
  가운데에 모은다. `API 키로 시작하기` 는 화면 맨 아래의 작은 흐린 글자 버튼이다. 키 입력칸을 첫 화면에 두면 키가
  넥슨 로그인과 같은 무게의 방법으로 보인다.
- 머리는 스플래시의 잎과 이름 묶음이다(사용자 선택 2026-11-04). 앱 아이콘은 두지 않는다. 시안에서 아이콘 아래 이름만
  바꾼 안과 견줘, 아이콘을 빼고 그 자리에 묶음을 둔 안을 골랐다. 잎은 스플래시의 둥근 잎 경로를 테마 `primary` 로,
  이름은 스플래시의 메이플스토리 서체 글자 윤곽을 테마 `text` 로 그린다([[ADR-013]] 결정 14 · 15). 배치도 스플래시와
  같아서 잎이 왼쪽, 이름이 오른쪽이고 세로 가운데를 맞춘다. 이름 글자는 34, 잎은 그 117%(40), 둘 사이는 6 이다. 시안에서
  28 · 34 · 40 을 견줘 골랐다.
- 이름과 설명 사이는 64 다. 이름을 설명 · 넥슨 버튼 덩어리와 떨어뜨려 따로 읽히게 하려는 것이다(사용자 지정). 시안에서
  8 부터 96 까지 견줘 골랐다.
- 설명은 두 줄 `넥슨 Open API의 메이플스토리 스케줄러와 강화 기록을` · `불러오려면 넥슨 로그인이 필요해요.` 다(사용자 선택
  2026-11-04). 무엇을 불러오려고 로그인하는지를 말한다. 줄은 손으로 나눈다. 자동 줄바꿈에 맡기면 폭에 따라 말 가운데서
  꺾인다. 긴 줄도 Pretendard 14 로 306px 라 아이폰 SE 2 의 글자 폭(327)에 들어간다. 넥슨 로그인 입구가 꺼진 빌드는 둘째
  줄이 `불러오려면 API 키 입력이 필요해요.` 다.
- 넥슨의 `게임 데이터 활용 로그인` 소개 다섯 문장은 첫 화면 본문에 싣지 않는다. 넥슨 버튼이 설명 아래로 밀려나기 때문이다.
  `게임 데이터 활용 로그인이란?` 링크가 넥슨의 소개 페이지(`openapi.nexon.com/ko/data-util/introduction/`)를 연다.
  넥슨이 문구를 고쳐도 앱을 고칠 필요가 없다. 링크는 글자 폭만큼만 누를 수 있고 굵기는 `normal` 이다. 요약한 설명은
  왼쪽 위 `자주 묻는 질문` 이 여는 FAQ 시트에 있다. 시트는 버튼을 밀어내지 않고, 문구는 서버에 있어 앱을 다시 내지 않고
  고친다([[ADR-150]] 결정 5 · 8).

`API 키로 시작하기` 를 누르면 경고 모달(`ApiKeyWarningModal`)이 뜬다.

- 모달은 가운데 정렬이고, 패널 · 머리 줄 · 칸은 다른 가운데 모달과 같다([[ADR-062]] 결정 8).
- 머리 줄은 `error` 배지 안의 경고 삼각형과 제목 `API 키로 시작할까요?` 다. 그 아래 두 문장을 `card-inset`
  칸에 하나씩 넣는다. 첫 칸은 자물쇠 아이콘과 `일부 기능은 넥슨 로그인으로만 쓸 수 있어요` 이고, 둘째 칸은
  흐린 글자 `앞으로 나오는 기능도 넥슨 로그인을 기준으로 만들어요.` 다. 첫 칸이 자물쇠인 것은 머리 줄의 경고
  삼각형과 겹치지 않게 하려는 것이다.
- 두 칸의 문장은 단어 가운데서 줄이 바뀌지 않게 묶는다(`lib/keep-words.ts`). RN 은 한글을 글자 사이에서도 줄을 바꿔
  `만들어요` 가 `만` / `들어요` 로 나뉘었다. 안드로이드에는 iOS 의 `hangul-word` 같은 옵션이 없어, 두 플랫폼이 함께 지키는
  단어 결합자(U+2060)를 단어 안 글자 사이에 넣는다.
- 어떤 기능을 못 쓰는지는 적지 않는다. 넥슨 로그인 전용 기능 목록이 아직 정해지지 않았고, 정해지지 않은 것을
  단정하면 거짓이 된다.
- 큰 버튼은 넥슨 로그인 버튼이다. API 키로 가려는 사용자에게도 넥슨 로그인을 한 번 더 권한다. 키로 가는 길은 그
  아래 흐린 글자 버튼 `그래도 API 키로 시작하기` 다.
- 두 버튼 모두 모달을 닫는다. 넥슨 로그인은 모달을 닫고 로그인 창을 연다. `그래도 API 키로 시작하기` 는 모달을
  닫고 상단 시트를 연다. 스크림이나 뒤로가기로 닫으면 첫 화면으로 돌아간다.

키는 상단 시트(`ApiKeySheet`. 껍데기는 `TopSheet`, [[ADR-062]] 결정 15)에서 받는다.

- 바텀시트는 키보드를 보지 않아 시트 안에 입력칸을 둘 수 없다([[ADR-062]] 결정 4). 위에서 내려오는 시트는
  키보드와 자리를 다투지 않는다.
- 머리 줄은 32px `primary-tint` 원 안의 열쇠, 제목 `API 키로 시작하기`, 오른쪽 끝의 `error-tint` 알약
  `⚠ 일부 기능 제한` 이다. 경고 모달을 지나온 뒤에도 키 경로가 제한된 경로라는 것을 한 줄로 남긴다. 화면 높이와
  상관없이 같은 머리를 쓴다. 넥슨 로그인 입구가 꺼져 있으면 알약을 달지 않는다(결정 9).
- 본문은 `ApiKeyForm` 이다. 라벨 `Nexon Open API 키` 와 같은 줄 오른쪽에 `openapi.nexon.com에서 확인` 링크를 둔다.
  입력칸은 테두리 없이 `card-inset` 으로 칠하고, 오른쪽 눈 아이콘으로 가린 키를 보이게 한다. 그 아래 `확인` 과,
  맨 아래 가운데에 `API 키 발급 방법 보기` 링크를 둔다. 발급 링크는 낮은 화면에서도 남긴다. 키가 없는 사용자에게는
  그것이 유일한 다음 걸음이다.
- `확인` 은 채운 버튼이 아니라 `tint` 다. 키 경로를 넥슨 버튼과 같은 무게로 보이지 않게 하려는 것이다.
- 키가 어디에 저장되는지 알리던 문장(`입력한 키는 이 기기에만 저장되고…`)은 걷었다(사용자 지정).
- 시트가 열려도 입력칸에 초점을 주지 않는다(사용자 지정). 키보드는 사용자가 입력칸을 누를 때 올라온다.
- 저장된 키가 있으면(온보딩 중간에서 로그인 화면으로 돌아온 경우) 입력칸에 채워 둔다.
- 검증에 실패하면 시트는 그대로 두고 토스트로 알린다([[ADR-024]] 결정 10). 개발 단계 키로 막히면 개발 단계 키 모달이
  시트 위에 뜨고, 닫으면 시트로 돌아온다([[ADR-024]] 결정 4).
- 시트를 닫으면 친 키는 버린다. 키 검증이 성공하면 다음 화면으로 넘어가므로 시트를 따로 닫지 않는다.

### 결정 8. 앱이 여는 웹 주소는 인앱 브라우저로 연다 (사용자 지정)

웹 주소(`https://`)를 여는 링크는 모두 `native/browser.ts` 의 `openInAppBrowser` 로 연다. 그 안에서
`expo-web-browser` 의 `openBrowserAsync` 를 부른다. iOS 는 SFSafariViewController, 안드로이드는 Chrome Custom
Tabs 다. 같은 크기와 색의 링크 가운데 어떤 것은 앱을 떠나고 어떤 것은 떠나지 않으면, 누르기 전에는 어느 쪽인지
알 수 없다. 그래서 앱 전체에서 같은 방식으로 연다.

| 링크 | 파일 |
|---|---|
| `게임 데이터 활용 로그인이란?` | `app/auth/DataUtilLoginLink.tsx`. 로그인 화면과 연동 시트가 함께 쓴다 |

  이동이다.
- 인앱 브라우저를 못 열면 시스템 브라우저(`Linking.openURL`)로 넘긴다. 안드로이드에 Custom Tabs 를 받는 브라우저가
  없으면 `openBrowserAsync` 가 거절하는데, 그대로 삼키면 눌러도 아무 일이 안 일어난다. 시스템 브라우저도 못 열면
  조용히 끝난다. 화면은 그대로 서 있어야 해서다.

  따로 열리지 않는다.
- iOS 에서는 창을 카드 시트(`presentationStyle: pageSheet`)로 띄운다(사용자 지정). 넥슨 로그인 창

  라이브러리 기본값은 화면 전체를 덮는 `overFullScreen` 이다. 로그인 창의 확인 창과 인앱 브라우저 아래의 버튼
  막대는 시스템이 정해 맞출 수 없다. 안드로이드는 둘 다 Custom Tabs 라 따로 할 것이 없다.

- 안드로이드는 상단 막대 색이 바뀌지 않는다. `expo-web-browser` 57.0.3 의 안드로이드 코드가 `toolbarColor` 를 상단
  막대가 아니라 보조 막대 색(`setSecondaryToolbarColor`)으로 넣기 때문이다. 패치는 하지 않았다(사용자 지정). 라이브러리를
  고치면 네이티브 지문이 바뀌어 OTA 로 낼 수 없다.
- 창이 열리지 않았을 때의 오류 화면은 우리가 그리지 않는다. 오프라인이면 인앱 브라우저가 자기 오류 페이지를 띄운다.
- `app/` 에서 `expo-web-browser` 를 직접 부르지 않고 `native/` 어댑터를 거친다([[ADR-004]]).

  `primary-ink` 는 밝은 테마에서 바탕과의 대비가 낮아 누를 수 있다는 것이 잘 보이지 않는다.

### 결정 9. 넥슨 로그인 입구는 상수 하나로 끄고 켠다. 지금은 켜져 있다

넥슨이 허락하지 않은 사용자는 로그인할 수 없다. 입구를 켜 둔 채 내보내면 그 사용자가 화면에서 가장 큰 버튼을 눌러
실패한다. 그래서 `features/auth/nexon-login-enabled.ts` 의 `NEXON_LOGIN_ENABLED` 로 입구를 끄고 켠다. 프로덕션
승인 뒤 `true` 로 켰다가, 콜백 주소 검수를 기다리며 다시 `false` 로 두었다. 검수가 승인돼(2026-11-05) 1.0.13 스토어
바이너리에서 다시 켠다(사용자 결정). 입구를 켜는 번들에는 키를 서버에서 잇는 일(결정 4)이 함께 있어야 한다. 없으면 로그인한
키 사용자의 키가 잇지 않은 채 지워져, 그 키로 보낸 기록이 서버에서 다른 사람으로 계속 남는다. 환경 변수(`EXPO_PUBLIC_*`)로 두지 않는
이유는 OTA 번들을 만드는 셸 환경에 따라 값이 바뀔 수 있기 때문이다.

꺼져 있으면 다음과 같다.

- 로그인 화면에서 넥슨 버튼과 소개 링크, 맨 아래 `API 키로 시작하기` 를 모두 빼고, 머리 둘째 줄은
  `불러오려면 API 키 입력이 필요해요.` 로 바꾼다. 로그인을 언급하면 사용자가 없는 방법을 찾게 된다.
- 넥슨 버튼이 있던 자리에 `API 키로 로그인` 버튼(`components/molecules/ApiKeyLoginButton/`)을 둔다. 첫 화면의
  배치는 입구가 켜져 있을 때와 같다. 나중에 입구를 켜도 같은 자리에 같은 모양의 버튼이 서서, 사용자가 화면이
  달라졌다고 느끼지 않게 하려는 것이다(사용자 지정 2026-11-05).
- 이 버튼은 넥슨 버튼과 같은 모양이다. 앱의 `Button` 은 알약 모양이라 넥슨 버튼 자리에 두면 모양이 달라 보여서 따로
  만든다(사용자 지정).
  - 높이는 넥슨 버튼 그림의 비율(`naturalAspectStyle`)을 그대로 읽는다. 폭이 같으면 높이도 같고, 그림을 바꾸면 두
    버튼이 함께 바뀐다.
  - 모서리는 넥슨 가이드와 같은 6 이다.
  - 가운데에 열쇠 아이콘(19)과 `API 키로 로그인` 을 6 띄워 둔다. 넥슨 버튼의 심볼 자리에 열쇠를 둔 것이다. 시안에서
    글자만 둔 안과 견줘 골랐다(사용자 선택). 글자는 주 버튼 역할인 `text-base font-bold` 다.
  - 바탕은 테마의 `primary`, 글자와 아이콘은 `on-primary` 다(사용자 지정). 넥슨의 파랑을 쓰면 넥슨 로그인 버튼으로
    오해한다.
- 버튼을 누르면 경고 모달 없이 키 입력 상단 시트가 바로 열린다. 경고 모달은 넥슨 로그인을 한 번 더 권하는 창이라,
  넥슨 로그인이 없으면 권할 것이 없다.
- 시트 머리에 `⚠ 일부 기능 제한` 알약을 달지 않는다. 알약은 키 경로가 넥슨 로그인보다 제한된 경로라는 표시라,
  넥슨 로그인이 없으면 무엇에 비해 제한된다는 것인지 말이 되지 않는다(사용자 지정).
- today 머리의 `넥슨 ID 연동하기` 도 보이지 않는다.
- 이미 로그인한 기기에서만 보이는 로그인 만료 모달은 그대로 둔다.
  꺼진 빌드에서는 새로 로그인할 수 없으므로 일반 사용자에게는 보이지 않는다.

다시 끄거나 켤 때는 이 상수만 바꾸는 OTA 를 낸다. OTA 는 같은 지문의 바이너리에만 적용되므로, 로그인에 필요한 네이티브
설정은 바이너리에서 빼지 않는다. iOS `CFBundleURLSchemes` · 안드로이드 `intent-filter` · `expo-web-browser` ·
`SceneDelegate` 가 콜백 URL 을 `RCTLinkingManager` 로 넘기는 코드가 그것이다. 로그인 흐름 코드
(`nexon-login.ts` · `server/nexon-auth.ts` · `NexonLoginButton`)도 번들에 그대로 둔다.

### 결정 10. 메이플 ID 가 없는 넥슨 로그인은 저장하지 않는다

넥슨 ID 를 여럿 가진 사용자가 메이플 ID 가 없는 넥슨 ID 로 먼저 들어오는 일이 있다. 넥슨은 그 ID 의 `character/list` 에
200 과 빈 `account_list` 를 준다. 2026-11-07 ~ 11-09 운영 로그에서 5명이 그랬고, 2명은 넘어가지 못했다.

전에는 세션을 먼저 저장하고 목록을 받았다. 목록이 비어도 로그인이 남았고, 조회는 로그인이 있으면 늘 로그인으로 한다(결정 1).
그래서 화면의 어느 출구로도 그 로그인을 지우지 못했다.

- 캐릭터 관리 본문의 `API 키 다시 입력` 은 `확인` 에서 API 키만 지우고 로그인은 남겨, 같은 화면에 머물렀다.
- 뒤로 가서 API 키로 시작해도 목록을 빈 로그인으로 불러 다시 빈 화면이었다.
- 앱 안 연동 시트로 빈 넥슨 ID 에 들어온 API 키 사용자는 쓰던 키가 빈 로그인에 가려졌다.

이렇게 정한다.

- `signInWithNexon` 은 세션을 받은 뒤 **저장하기 전에** 그 세션으로 `character/list` 를 받는다. 목록이 비면 저장하지 않고,
  서버 세션을 거둔 뒤(`revokeNexonSession`) `noMapleId` 를 돌려준다. 기기의 저장소는 그대로다.
- 그때 토스트 `이 넥슨 ID 에 연결된 메이플 ID 를 찾지 못했어요` 를 띄운다(사용자 선택 2026-11-12). 로그인 화면에서 했으면
  로그인 화면에 남고, 연동 시트에서 했으면 앱과 API 키가 그대로다.
- 목록을 받지 못하면 저장하지 않고 `failed` 다. 메이플 ID 가 있는지 모르는 로그인을 저장하면 같은 일이 생길 수 있다.
- 받은 목록의 메이플 ID 소속은 로그인을 저장해 계정 id 가 정해진 뒤 적는다(`recordCharacterList`). 먼저 적으면 계정 칸이 빈
  채로 남는다. 스토어는 이 목록으로 진입 단계를 판정하고 목록을 다시 받지 않는다.
- 받은 목록을 그 로그인의 캐릭터 목록 캐시에 넣는다. 로그인을 갈아끼우면 새 로그인이 앞 로그인의 계정 id 를 이어받아
  (`setNexonLogin`) 캐시 열쇠가 같다. 넣지 않으면 캐릭터 설정이 5분 동안 앞 로그인의 빈 목록을 보여 준다.

이 결정 전에 빈 로그인이 저장된 기기도 빠져나와야 한다.

- 캐릭터 관리 본문(`CharacterManageBody`)은 넥슨 로그인으로 부른 목록에 메이플 ID 가 하나도 없으면, 제목
  `조회되는 캐릭터가 없어요` 는 그대로 두고 설명 `이 넥슨 ID 에 연결된 메이플 ID 를 찾지 못했어요` 와 버튼 `다른 넥슨 ID 로
  로그인` 을 보인다(사용자 선택 2026-11-10 · 11-12). API 키로 불렀으면 지금 문구 그대로다([[ADR-024]] 결정 6).
- 어느 수단으로 불렀는지는 목록을 받는 훅(`useAccountRosters`)이 그때 쓴 자격의 종류를 목록과 함께 넘겨 가른다. 화면이
  저장소를 따로 읽으면 목록을 부른 때와 다른 때의 자격을 보게 된다.
- 버튼을 누르면 서버 세션을 거두고 넥슨 로그인만 뗀다(`leaveEmptyNexonLogin`). API 키는 지우지 않는다. 남은 수단이 있으면
  그 수단으로 목록을 다시 받고, 없으면 로그인 화면으로 간다. 다시 로그인하면 새 계정 id 로 저장돼 빈 목록 캐시를 보지 않는다.
- 캐릭터 설정 화면에서 로그인 화면으로 갈 때는 그 화면이 스택에서 빠진다. 진입 단계만 되돌리면 같은 온보딩 스택이라 캐릭터
  설정이 로그인 화면 위에 남는다. 설정의 캐릭터 관리에서는 진입 단계가 바뀌며 스택 전체가 로그인 화면으로 바뀐다.

## 번호 기록

- ADR-025 (2026-10-19): 옛 ADR-296 · 318 · 320 · 321 · 334 를 합쳐 처음 작성
- ADR-068 (2026-10-19): 결정 2 에 401 · 403 을 받은 개발자 키도 빼는 것과, 개발자 키의 키 실패를 `network` 로
  보는 규칙을 더했다
- ADR-083 (2026-10-23): 결정 8 을 로그인 화면에서 앱 전체의 웹 주소로 넓혔다. 못 열면 시스템 브라우저로 넘기고, 창 색을
  테마에 맞춘다. iOS 는 로그인 창처럼 카드 시트로 띄운다(#634)
- ADR-105 (2026-10-27): 결정 7 을 다시 썼다. 첫 화면에는 넥슨 로그인만 두고, API 키는 경고 모달을 거쳐 상단 시트에서
  받는다. 결정 9 의 입구를 껐을 때 화면도 그에 맞췄다(#757)
- (2026-11-04) 결정 8 의 링크 목록에 문의 모달의 오픈채팅을 더했다([[ADR-052]] 결정 9)
- ADR-166 (2026-11-04): 결정 3 에 넥슨 동의 화면의 `취소` 를 더했다. 창을 닫은 것처럼 `cancelled` 로 보고 토스트를 띄우지 않는다(#853)
- ADR-169 (2026-11-05): 결정 6 을 다시 썼다. 앱 안의 입구를 더보기 탭 맨 위에서 today 머리의 `넥슨 ID 연동하기` 와
  그것이 여는 시트로 옮겼다. 결정 9 도 그에 맞췄다
- ADR-170 (2026-11-05): 결정 9 의 입구를 다시 껐다. 1.0.13 스토어 바이너리를 잠근 채로 낸다. 껐을 때의 로그인 화면도
  바꿨다. 키 입력을 첫 화면에 펼치지 않고, 넥슨 버튼 자리에 같은 모양의 `API 키로 로그인` 버튼을 둔다. 누르면 경고
  모달 없이 상단 시트가 열리고, 시트 머리에 `일부 기능 제한` 알약이 없다. 결정 7 의 시트 머리도 그에 맞췄다
- ADR-171 (2026-11-05): 결정 4 를 다시 썼다. 키를 고르는 기준을 캐릭터에서 메이플 ID 로 바꾸고, 지우기 전에 서버에서
  로그인한 사람과 잇는다([[ADR-017]] 결정 9, #607). 로그인은 저장하기 전에 잇고, 이은 키의 계정 id 를 이어받는다
  ([[ADR-098]] 결정 5). 잇지 못한 키는 남기고 앱을 켤 때 다시 한다. 결정 9 의 입구를 다시 켰다.
  콜백 주소 검수가 승인돼 1.0.13 스토어 바이너리에서 연다
- (2026-11-05) 결정 6 에 로그인 화면이 성공하면 다음 온보딩 화면을 미는 것과, 진행 중인 로그인을 다시 시작하지 않는
  것을 적었다. 둘 다 처음 설치한 시뮬레이터에서 넥슨으로 로그인해 보고 찾은 결함이다
- ADR-192 (2026-11-10): 결정 10 을 새로 썼다. 넥슨 로그인으로 캐릭터 없는 넥슨 ID 에 들어오면 빈 화면이 API 키 문구 대신
  다른 넥슨 ID 로 바로 다시 로그인하는 버튼을 보인다(#948)
- ADR-207 (2026-11-12): 결정 3 에 iOS 로그인 창을 쿠키를 나누지 않는 창으로 여는 것을 더했다. 결정 10 을 다시 썼다. 메이플
  ID 가 없는 넥슨 로그인은 저장하지 않고, 이미 저장된 기기는 빈 화면의 `다른 넥슨 ID 로 로그인` 으로 로그인을 떼고 로그인
  화면으로 간다. 결정 6 의 목록을 못 받을 때도 그에 맞췄다. ADR-192 의 그 자리에서 다시 로그인하는 버튼과, 로그인 창
  옵션을 쓰지 않는다는 줄은 걷었다(#948, OTA 1.0.13+7)
