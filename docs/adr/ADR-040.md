### ADR-040: 보스 드롭 입력 시트 개편 — 난이도 무관 통합 표시·간소화 난이도 뱃지·고정 드롭 읽기 전용·카테고리 아이콘·고가 리스트 확장(익셉셔널 해머)·연출 끄기 토글 (구현 완료, 2026-07-26)

**배경**: [[ADR-038]]이 구현한 보스 드롭 입력 바텀시트(`BossDropSheet`)를 실사용 관점으로 다듬는다. 현재 시트는 보스 행의 **단일 난이도**(`boss`+`difficulty`) 드롭만 보여주고([[ADR-038]] 결정 1), `고정`도 다른 카테고리와 똑같이 토글 타일이며, 카테고리 헤더는 `bg-primary` 노란 점, 고가 연출은 항상 발동한다(끌 수 없음). 사용자 요청(2026-07-26) 6건을 반영한다. 설계 질문 3건은 사용자 확정: ① 고정 드롭은 **난이도별 그룹**으로 표시(값이 난이도마다 달라 통합 불가), ② 아이템 타일 난이도 표시는 **약자 컬러 칩**(노/하/익, 난이도색), ③ 연출 끄기 토글은 **바텀시트 안**에 두되 값은 **전역 공유**(영구 저장). 게임 수치 데이터는 읽기만 하고 추정하지 않는다([[ADR-006]]).

**결정**:
1. **난이도 무관 통합 표시(선택 대상=장비·소비)**: 시트가 보스의 **모든 난이도** 드롭을 한 번에 보여준다(사용자 요청 1). `lib/boss-drops.ts`의 `getBossDropCandidates`를 `(boss)` 단일 인자로 바꿔, 그 보스의 전 난이도 `equipment`+`consumable` 후보를 **`category`+`name`+`slot` 기준으로 dedupe**해 합치고, 각 후보에 그것이 등장하는 난이도 목록 `difficulties: BossDifficulty[]`([[ADR-007]] `BOSS_DIFFICULTIES` 정규 순서)를 붙인다. (한 보스 안에서 같은 이름의 slot은 일관됨을 데이터로 확인 — dedupe가 자연히 1타일로 접힘.) 카테고리 범위는 종전대로 `장비`/`소비`/`고정` 3분류(스크롤·misc는 종전처럼 미표시, 사용자 요청 4가 이 3분류를 지목해 재확인). 기록(`RecordedDrop`)은 종전대로 아이템 정체성(이름·카테고리·slot)만 담고 **난이도 tier는 저장하지 않는다** — 시트는 보스 행의 난이도로 파일링되며 DB 스키마·`boss_drop_records`는 무변경.
2. **간소화 난이도 뱃지(약자 컬러 칩)**: `DifficultyBadge.tsx`에 `DIFFICULTY_ABBR`(이지→이, 노멀→노, 하드→하, 카오스→카, 익스트림→익)와 컴팩트 `DifficultyChip`을 신규 추가하고 기존 `DIFFICULTY_BADGE_STYLES` 색을 재사용한다(사용자 요청 2). 각 선택 타일(장비·소비/상자)에 그 후보의 `difficulties`를 칩 줄로 렌더한다. 칩은 장식 정보라 `aria-hidden`(약자만으론 스크린리더에 무의미) — 타일 접근명은 아이템명 그대로 유지해 기존 `getByRole` 테스트 표면 불변.
3. **고정 드롭 읽기 전용·난이도별 그룹**: `고정`은 토글/기록 대상에서 빼고(사용자 요청 3), 신규 `getBossFixedDrops(boss): { difficulty, items:[{name, amount, slot}] }[]`로 **난이도별 그룹**(정규 순서)을 만들어 각 난이도 뱃지 아래 `이름 값`을 나열하는 **읽기 전용** 섹션으로 렌더한다(사용자 확정 — 고정 값이 난이도마다 달라 통합 불가). `고정` 후보는 `getBossDropCandidates`(선택 대상)에서 제외되고 `selected`에 추가되지 않는다. 과거에 기록된 `fixed` 레코드가 `initialDrops`에 있으면 값은 보존하되(무손실) 새 UI엔 노출/편집 불가 — record-only 베타라 허용(마이그레이션 없음).
4. **카테고리 라벨 아이콘(노란 점 대체)**: 카테고리 헤더의 `bg-primary` 점(`<span className="h-1.5 w-1.5 rounded-full bg-primary" />`)을 lucide 아이콘으로 교체(사용자 요청 4) — `장비`=`Sword`, `소비`=`FlaskConical`, `고정`=`Pin`. `text-text-muted` 색·크기(≈14px)로 라벨과 톤을 맞춘다. lucide-react는 이미 의존성(App 등에서 사용).
5. **고가 리스트에 익셉셔널 해머 추가**: `valuable-drops.json`의 `items`에 `"익셉셔널 해머"`를 추가한다(사용자 요청 5, [[ADR-038]] 결정 10 "이름 추가만으로 대상 변경"). 정확한 데이터상 아이템명은 `익셉셔널 해머`(구어 "해머류"의 실제 단일 이름, 5개 보스에서 slot별 아이콘). `updatedAt`/`source` 갱신. 정합성 테스트(`data/__tests__/valuable-drops.test.ts`)가 실재 아이템명임을 이미 강제하므로 별도 실패 없음(추가 검증만 보강).
6. **연출 끄기 토글(바텀시트 내, 전역 공유·영구 저장)**: 고가 아이템 연출을 끌 수 있는 토글을 **시트 헤더**에 둔다(사용자 확정). 값은 **전역**이라 [[ADR-003]] 어댑터 패턴(테마·트래킹 모드 미러)으로 저장 — `STORAGE_KEYS.dropEffect` 신규, `storage/drop-effect.ts`(`getDropEffectEnabled`/`setDropEffectEnabled`, 기본 **true=연출 표시**), `features/drop-effect/store.ts`(`useDropEffectStore`: `enabled`, `restoreFromStorage`, `setEnabled`), `App.tsx`에서 부팅 시 `restoreFromStorage`(테마와 동일 패턴). 시트의 두 `setEffect(...)` 호출(`toggleNormal`·`applyBoxResult`)을 `enabled`로 게이트한다. 토글이 꺼지면 고가 드롭을 새로 추가해도 연출이 뜨지 않는다. `features/*`는 storage 직접 접근 금지·어댑터만 사용([[ADR-003]]).

**데이터**: `valuable-drops.json`에 `익셉셔널 해머` 추가 외 신규 수치 데이터 없음(전부 기존 `item-drop-table.json`을 읽기만). `priceMeso`·시세 분리 정책은 [[ADR-038]] 그대로.

**이유**:
- 난이도 무관 통합: 한 보스의 드롭이 난이도마다 갈려도 사용자는 "이 보스에서 뭐가 뜨나"를 한눈에 보고 싶어 함(요청). 선택 대상은 dedupe로 접고 난이도는 칩으로 부기(附記)해 목록을 짧게 유지한다.
- 고정 분리: 고정 드롭은 "선택 기록"의 의미가 없고(항상 나옴) 값이 난이도마다 달라 통합 타일 하나에 담을 수 없다 → 읽기 전용 난이도별 그룹이 정보 손실 없이 가장 정확.
- 전역 연출 토글: 연출 선호는 시트 단위가 아니라 사용자 단위 취향이라 전역·영구가 맞다. 어댑터 레이어 경유는 [[ADR-003]] 준수이자 테마/트래킹과 동일 검증 패턴 재사용.

**트레이드오프**:
- `getBossDropCandidates` 시그니처 변경(`(boss,difficulty)`→`(boss)`)으로 유일 사용처 `BossDropSheet`와 `lib/__tests__/boss-drops.test.ts`를 갱신해야 함(사용처 좁아 국소적).
- 통합 표시로 캐릭터가 실제로 잡지 않은 상위 난이도 전용 드롭(예: 익스 전용)도 타일에 노출됨 — 칩으로 난이도를 명시해 오인 방지(요청된 동작).
- 난이도 tier를 기록에 안 담으므로, 훗날 "어느 난이도에서 나온 드롭인가"를 되짚는 분석은 불가(현재 요구 아님).

(2) `DifficultyBadge`: `DifficultyChip` 약자·색. (3) `storage/drop-effect`·`features/drop-effect/store`: 기본 true, get/set 왕복. (4) `data/valuable-drops`: `익셉셔널 해머` 포함 + `isValuableDrop('익셉셔널 해머')` true. **정정(2026-07-26) — 토글 의미 반전 + 헤더 난이도 뱃지 제거(사용자 보고)**: (1) 1차 구현이 결정 6의 원 스펙("**연출 끄기** 토글 — **활성 시** 연출이 안 뜸")을 뒤집어 "연출"(ON=표시) 토글로 만들어, 사용자가 켜면 연출이 오히려 뜨는 반대 동작이 됐다. 라벨을 "연출 끄기"로 바꾸고 스위치 활성(`aria-checked` true) = 연출 끔(내부 `enabled=false`)이 되도록 바로잡았다(스토어의 positive 모델 `enabled`는 유지, UI만 `off={!enabled}`로 표현). 반전 회귀를 막는 구조 테스트 추가('연출 끄기'가 `enabled=true`일 때 미체크·`false`일 때 체크). (2) 시트 헤더의 보스 이름 옆 행-난이도 뱃지(`<DifficultyBadge difficulty={props.difficulty}/>`)는 이제 각 아이템이 난이도 칩으로 등장 난이도를 표기하므로 중복이라 제거(사용자 요청). `difficulty` prop 자체는 부모의 레코드 필링 맥락이라 유지. (3) 토글 스위치 디자인 버그(사용자 보고 — 흰 knob이 트랙 밖으로 삐져나감): 트랙 `<span>`이 기본 `display:inline`이라 `w-7 h-4`(너비·높이)가 인라인 요소에 적용되지 않아 트랙이 0크기로 붕괴하고, `absolute` knob이 밖으로 떨어져 나온 게 원인. 트랙을 `inline-flex items-center`로, knob을 비-absolute `inline-block`(`translate-x-0.5`↔`translate-x-3.5`)로 바꿔 트랙이 실제 28×16px로 렌더되고 knob이 대칭 여백으로 담기게 수정. 별도 HTML 미리보기(6배 확대)를 실 브라우저로 스크린샷해 knob 담김 육안 확인. 전체 1179 tests·lint·build 통과.

**정정 3(2026-07-26) — 드롭 리스트에서 공용 소모품 제거 + 상자 재탭 제거(사용자 요청)**: (1) '소형 경험 축적의 비약'·'소형 고농축 경험 축적의 비약'(공용 소모품)을 `item-drop-table.json` 전 보스 consumable에서 제거(총 46건, 전부 first/middle 위치라 후행 콤마 균일 — node 텍스트 필터로 순수 삭제 184줄, 다른 항목·포맷 무변화). 파일 `updatedAt`·`note`에 제거 이력 기록([[ADR-006]] 도메인 전문가 지시). 제거로 스우 consumable이 전부 반지 상자만 남아 비고가 테스트가 참조할 일반 아이템이 사라져 `BossDropSheet` test #4를 `데이브레이크 펜던트`(여명 세트·비고가·비박스, 진 힐라)로 교체. (2) '탭하여 결과 ›' 상자(반지 상자·칠흑 장신구 상자)가 **이미 지정돼 있으면 타일 재탭 시 드릴다운을 열지 않고 선택을 제거**하도록 `handleTileTap`을 변경(일반 아이템 토글과 동일한 재탭=제거 UX). 드릴다운은 이제 항상 새 선택 전용이라 `BoxDrillDown`의 **제거 버튼과 `existing`/`onRemove` prop을 삭제**(pre-fill·제거는 재탭으로 대체). 회귀 테스트 2건 추가(재탭 제거·드릴다운에 제거 버튼 없음). 전체 1180 tests·lint·build 통과.
