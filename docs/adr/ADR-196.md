# ADR-196: 글꼴과 글자 계단을 앱이 쥔다. 두 플랫폼이 같은 값을 본다

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-09-01
**관련**: [[ADR-152]] 결정 4·5(글자는 atom 한 곳에서 나오고, 칸에 묶인 자리는 `fixed` 다) · [[ADR-195]](배지 크기) · [[ADR-128]] 3단계(NativeWind)

## 맥락

같은 코드가 두 플랫폼에서 다른 높이로 그려졌다. 사용자가 배지에서 발견했고, 재 보니 글자를 쓰는
자리 전부의 문제였다.

**실측 (2026-09-01, 시뮬레이터 · `lineHeight` 없이 `한글Ag` 의 줄 상자 높이)**

| fontSize | iOS | 안드로이드 | 차이 |
|---|---|---|---|
| 9px | 11.0 | 13.3 | +2.3 |
| 10px | 12.0 | 15.2 | +3.2 |
| 12px | 14.3 | 18.3 | +4.0 |
| 16px | 19.3 | 23.6 | +4.3 |

원인이 둘이었다.

1. **글꼴이 달랐다.** 앱에 `fontFamily` 설정이 없어 각 플랫폼 시스템 글꼴을 썼다. iOS 는
   San Francisco + Apple SD Gothic Neo, 안드로이드는 Roboto + Noto Sans CJK KR 이다. 한글이 라틴보다
   큰지 작은지조차 **부호가 반대**였다(iOS 는 −2.3, 안드로이드는 +1.5).
2. **줄 높이가 없는 자리가 있었다.** Tailwind 기본 계단(`text-xs`)은 줄 높이를 함께 갖지만
   **임의값(`text-[10px]`)은 안 갖는다**. 없으면 RN 이 플랫폼 글꼴 메트릭으로 줄 상자를 잡는다.
   앱에 임의값이 169곳 있었다.

굵기는 원인이 아니었다. 400·500·600·700·800 이 모든 크기에서 줄 상자 높이가 같았다.

## 결정

### 결정 1. Pretendard 를 네이티브에 심는다

두 플랫폼이 같은 글꼴을 본다. OFL-1.1 이라 임베드와 상업 사용에 제약이 없다. `expo-font` 설정
플러그인으로 빌드 시점에 심는다. 런타임 로드(`useFonts`)를 안 쓰는 이유는 안드로이드가 굵기를
합성하지 않아 굵기마다 패밀리 이름이 갈리기 때문이다.

### 결정 2. 파일은 플랫폼마다 다르게 넣는다

| | 파일 | `fontFamily` 로 쓰는 이름 |
|---|---|---|
| iOS | `PretendardVariable.ttf` 하나 | `Pretendard Variable` |
| 안드로이드 | 정적 5개(400·500·600·700·800) | `Pretendard` |

**둘 다 정적으로도, 둘 다 가변으로도 안 된다.** 세 번 시도해 갈렸다.

| 시도 | iOS | 안드로이드 | 왜 |
|---|---|---|---|
| 정적 5개 | ✗ | ✓ | 파일마다 Family 이름이 다르다(`Pretendard Medium` 등). iOS 는 Family 로 찾으므로 굵기 매칭에 실패하고 **조용히 시스템 글꼴로 떨어진다** |
| 가변 1개 | ✓ | ✗ | `expo-font` 가 만드는 `res/font/*.xml` 이 같은 파일을 굵기마다 가리키는데 `fontVariationSettings` 를 못 넣는다. 굵기가 전부 400 으로 붕괴한다 |
| **혼합** | ✓ | ✓ | |

이름이 갈리는 것도 그래서다. iOS 는 **글꼴 파일 안의 Family 이름**으로 찾고, 안드로이드는
`res/font/xml_pretendard.xml` 이라는 **리소스 이름**으로 찾는다.

### 결정 3. 글자 계단은 `typography.cjs` 한 표가 쥔다

크기·줄 높이·굵기를 값으로 적는다. Tailwind 기본 계단을 `extend` 가 아니라 **교체**한다. 더하면
표에 없는 이름이 살아남아 줄 높이 없는 자리가 다시 생긴다.

`rem` 이 아니라 px 인 이유는, `rem` 이 `INLINE_REM`(16)을 거쳐 접히기 때문이다. 그 배수를 건드리면
계단 전체가 조용히 따라 움직인다.

비율은 본문 1.45 다. 받침 있는 한글이 눌리지 않을 만큼이다. 큰 글자는 그만큼 띄우면 헐렁해서
20px 부터 1.4 · 22px 부터 1.3 · 30px 부터 1.2 로 좁힌다.

### 결정 4. 칩은 자기 계단을 쓴다

배지는 한 줄짜리 라벨이라 본문 줄 높이를 쓰면 상자가 헐렁하다. `chip`(12px/14) ·
`chip-sm`(10px/14) · `chip-xs`(9px/11) 셋을 따로 둔다.

`chip` 과 `chip-sm` 은 **줄 높이가 같다**. 난이도 배지가 10px 인데 12px 짜리 상태 배지와 나란히
서기 때문에, 글자 크기가 달라도 배지 높이는 안 갈려야 한다([[ADR-195]] 결정 1).

### 결정 5. 글자 배수 정책은 그대로다

이 결정은 **크기를 고정하지 않는다**. 시스템 글자 크기를 따르는 것은 여전히 기본이고, 칸에 묶여
못 커지는 자리만 `fixed` 로 끈다([[ADR-152]] 결정 5). 계단이 바뀌어도 그 축은 안 건드린다.

## 검증

`src/__tests__/typography-policy.test.ts` 가 넷을 본다. 표에 없는 `text-<이름>`, 임의값
`text-[Npx]`, 표에 없는 `font-<굵기>`, 줄 높이 빠진 표 항목. 셋 다 **화면에서만 드러나는** 종류의
실패라 테스트가 필요하다.

## 트레이드오프

**앱 용량이 는다.** iOS 6.4MB · 안드로이드 12.7MB. 서브셋으로 줄일 수 있지만 넥슨 API 가 주는
임의 한글(캐릭터·보스·아이템 이름)이 두부로 깨질 위험이 있어 쓰지 않는다.

**OTA 지문이 달라진다.** `runtimeVersion` 정책이 `fingerprint` 라, 네이티브가 바뀌면 스토어에 올라간
바이너리는 이 빌드 라인의 업데이트를 못 받는다.

**`prebuild` 를 돌릴 때마다 릴리스 서명 설정이 날아간다.** `expo prebuild` 는 `android`·`ios` 를
비우고 다시 만든다. [[ADR-091]] 의 키스토어 블록이 템플릿 기본값(`signingConfig signingConfigs.debug`)
으로 덮이므로 **매번 되살려야 한다**. 모르고 릴리스를 만들면 디버그 키로 서명되어 Play 가 거부한다.
