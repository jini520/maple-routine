# ADR-109 — 혼테일 배경을 얼음 동굴 프레임으로 교체하고, 죽은 에셋을 전부 정리한다

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-08-07
**상태**: 구현 완료 (배치 값은 사용자가 눈으로 확정)
**관련**: [[ADR-108]](검은마법사 배경 — 같은 방식) · [[ADR-106]](배경 0건 상태·죽은 에셋의 정상 종료) · [[ADR-088]](배경 이미지 구조) · [[ADR-006]]

## 맥락

[[ADR-106]] 에서 뗀 혼테일 배경의 새 그림이 들어왔다(`hontail-background`, 1408×790, 투명 50%).
이로써 배경을 뗀 두 테마가 **둘 다 채워졌고**, [[ADR-106]] 이 만든 임시 상태가 완전히 닫힌다.

## 결정

### 1. `size: cover` — 늘리지 않는다

이 그림은 **프레임/비네트**다(고드름이 네 변을 두르고 가운데가 통째로 투명). 검은마법사의
**하단 앵커 장면**([[ADR-108]])과 성격이 달라서, 프레임을 화면 네 변에 붙이는 `100% 100%`(늘리기)가
후보였다. 실제로 그려 보니 고드름이 세로 형태라 왜곡이 잘 안 읽혀 그림 자체는 좋았다.

**채택하지 않았다** — 사용자 지시가 "왜곡시키지 마, height만 꽉 채워"다. 결과적으로 두 테마 모두
`cover` 를 쓴다. 그림 종류는 `size` 를 가르지 않고, **크롭이 얼마나 아픈지**와 `position` 을 어떻게
고르는지를 가른다.

### 2. 프레임은 크롭이 장면보다 더 아프다 — 대가를 적어 둔다

| | 검은마법사 | 혼테일 |
|---|---|---|
| 구성 | 하단 앵커 장면 | 프레임/비네트 |
| 종횡비 | 2.475 | 1.782 |
| 폰(0.462)에서 `cover` 가로 노출 | 19% | **26%** |
| 잘려 나가는 것 | 양쪽 사슬·블레이드 | **좌우 고드름 기둥** |

**프레임은 가장자리가 곧 내용이다.** 장면은 중심부가 남으면 인상이 얼마간 살지만, 프레임은 양 끝이
정의상 서로 반대편에 있어 26% 안에 둘 다 담을 방법이 **원리적으로** 없다. `position` 으로 고를 수
있는 건 "어느 26%"뿐이다(사용자가 `45% bottom` 으로 잡았다).

값으로 풀 수 있는 문제가 아니다 — **캔버스를 폰 비율(종횡비 ≤ 0.46)로 다시 뽑는 것이 답**이고,
그때는 자르지도 늘리지도 않고 네 변이 다 붙는다. [[ADR-108]] 결정 4 와 같은 결론이다.

**`auto 100%` 와 `cover` 는 이 뷰포트에서 결과가 같지만 뜻이 다르다** — 화면이 그림보다 가로로
길어지면 `cover` 는 가로를 채우려 더 확대하고 `auto 100%` 는 세로만 채운 채 좌우에 `bg` 를 남긴다.
지금은 `cover` 로 통일했고, 태블릿 가로처럼 넓은 화면에서 프레임을 남기고 싶어지면 그때 갈린다.

### 3. `dim` 은 그림마다 다르다 — 혼테일 0.8, 검은마법사 0.65

혼테일이 더 높은 이유는 **상단 고드름이 헤더 텍스트와 겹치기 때문**이다("컨텐츠 스케줄러"·
"캐릭터 관리"가 놓이는 자리에 밝은 파란 얼음이 온다). 검은마법사는 아래쪽에 모여 있어 헤더와
안 겹친다.

옛 값(혼테일 0.82 · 검은마법사 0.78)과 비슷해 보이지만 **물려받은 값이 아니라 새로 잡은 값**이다.
둘 다 알파를 크게 써서(투명 50% / 36%) `dim` 이 실제로 누르는 면적이 옛 불투명 그림보다 작다.

### 4. 죽은 에셋을 **전부** 지운다 — `hontail-cave.webp` 포함

[[ADR-106]] 결정 2 가 "새 그림을 넣는 커밋에서 같이 지운다"고 정한 조건이 이제 둘 다 충족됐다.
`src/assets/themes/` 에는 **실제로 쓰이는 두 장만** 남는다.

지우자 **테스트 2건이 깨졌다** — 배경 경로 테스트가 `hontail-cave` 를 "실재하는 슬러그"로 쓰고
있었다. [[ADR-106]] 결정 2 가 예고한 바로 그 결합이다("파일이 0개면 검사 방법 자체가 사라진다").

**픽스처를 진짜 슬러그로 옮겨 결합을 끊었다.** 이제 테스트가 가리키는 슬러그는 실제 테마가 쓰는
것이라, 앞으로 "안 쓰는 파일인데 테스트 때문에 못 지운다"가 생기지 않는다.

### 5. 슬러그 이름은 `hontail-` 로 맞춘다

받은 파일명은 `hantail-background.png` 였다. 테마는 혼테일이고 기존 에셋도 `hontail-cave` 였으므로
슬러그를 `hontail-background` 로 정규화했다 — 오타 슬러그는 JSON·테스트·파일명에 영구히 남는다.

## 결과

- `job-themes.json` 혼테일에 `background` 블록(`cover` · `45% bottom` · `dim` 0.8) +
  `src/assets/themes/hontail-background.webp`(500 → 156KB, 알파 유지).
- `hontail-cave.webp` 삭제. 에셋 폴더에 죽은 파일 **0개**([[ADR-106]] 임시 상태 종료).
- 테스트 픽스처 2건이 죽은 슬러그 → 실제 슬러그로 이동. 제품 코드·타입·CSS 변경은 여전히 **0**.
- 배경을 가진 테마가 **둘**이 됐다 — [[ADR-088]] 시절과 같은 수이지만 그림이 둘 다 바뀌었고
  값은 그림마다 새로 잡았다.
