# ADR-285: 설명이 필요한 자리는 **FAQ 바텀시트** 하나로 연다. 답은 **블록 배열**이다

> 🟡 **부분 폐기 — 결정 3 의 상한 값이 바뀌었다**([[ADR-316]] 결정 1, 2026-09-25). 「껍데기가
> 든 상한을 그대로 쓰고 FAQ 전용 상한을 안 둔다」는 결정은 그대로 살아 있고, 그 껍데기의 상한이
> 화면의 82% 에서 **상단 안전영역 아래까지**로 바뀌었다. 나머지 결정은 그대로다.

**날짜**: 2026-09-16
**상태**: **(구현 완료, 2026-09-16 · 실기기 미검증)** — 이슈 #458. 사용자 요청 2026-09-16.
**정정 1**(2026-09-25, 사용자 결정): 결산 FAQ 의 시각을 실측 `00:00 ~ 02:00` 으로 바꾼다.
**관련**: [[ADR-284]] 결정 8(결산 안내 줄을 탭하면 이 시트가 열린다 — 첫 사용처) · [[ADR-226]]
결정 5(불러오는 중은 모달이 말한다 — 시트와 모달을 가르는 자리)

## 맥락

화면이나 기능에 설명이 필요한 자리가 생겼다. 첫 자리는 결산 안내 줄이다 — 그 줄은 **무슨 일이
일어나는 중인지**만 말하고, 결산이 무엇인지까지 말하면 한 줄이 아니게 된다.

같은 자리가 앞으로 더 생긴다. 파티 인원과 수익이 어떻게 나뉘는지, 수동 모드가 무엇인지 같은 것들이
지금은 설명할 자리가 없어 화면 문구로 밀려들거나 아예 없다.

그래서 **화면마다 설명 UI 를 따로 만들지 않고 부품 하나**를 둔다.

### 결정 1. 바텀시트다. 모달이 아니다

`BottomSheet` 껍데기를 그대로 쓴다(`src/components/organisms/BottomSheet/BottomSheet.tsx`).
새 껍데기를 만들지 않는다.

모달이 아닌 이유는 **설명이 화면을 대신하는 것이 아니라 덧붙는 것**이기 때문이다. 시트는 뒤 화면을
남겨 두므로 방금 본 것 위에 설명이 얹힌다. [[ADR-226]] 결정 5 가 모달에 맡긴 것은 **아무것도 못
하는 동안**이고, 여기는 그 상황이 아니다.

### 결정 2. 질문과 답을 **전부 펼친 채** 싣는다

접고 펴는 장치를 두지 않는다. 위에서 아래로 읽는다.

아코디언을 안 쓰는 이유는 **여는 사람이 이미 질문을 들고 왔기 때문**이다. 결산 줄을 탭한 사람은
결산이 무엇인지 물은 것이고, 그 사람에게 목차부터 보이면 답까지 한 번 더 눌러야 한다.

### 결정 3. 높이는 **내용이 정하고 껍데기의 상한에서 멈춘다**

껍데기가 이미 그 상한을 든다 - `maxDynamicContentSize` 가 그 값이다(2026-09-16 당시 `frame.height ×
0.82`, 지금은 상단 안전영역 아래까지 · [[ADR-316]] 결정 1).
**FAQ 전용 상한을 새로 두지 않는다.** 시트마다 상한이 다르면 같은 자리에서 올라오는 것들이 저마다
다른 높이에서 멈춘다.

내용이 상한을 넘으면 시트 안에서 스크롤한다. 그것도 껍데기가 이미 갖고 있다.

**더 있다는 신호를 따로 만들지 않는다.** 마지막 줄이 아래 가장자리에서 잘려 보이는 것이 신호다.
페이드를 얹으면 읽히는 줄을 일부러 흐리게 만드는 일이 된다.

**상한에 매번 닿는 FAQ 가 생기면** 높이를 올릴 일이 아니라 그 FAQ 가 너무 길다는 신호다. 그때
그 FAQ 만 접는 안을 다시 꺼낸다.

### 결정 4. 답은 글자 한 덩어리가 아니라 **블록 배열**이다

FAQ 마다 필요한 것이 다르다. 어떤 답은 문단 하나면 되고, 어떤 답은 그림이 있어야 한다. 답을
문자열 하나로 두면 그림이 필요해지는 날 시트를 고쳐야 한다.

```ts
type FaqBlock = { kind: 'paragraph'; text: string }

interface FaqItem {
  question: string
  answer: FaqBlock[]
}

interface FaqSheetProps {
  /** 머리에 서는 이름. 그 화면의 말로 쓴다. */
  title: string
  items: FaqItem[]
  onClose: () => void
}
```

**종류는 `paragraph` 하나로 시작한다.** 결산 FAQ 가 쓰는 것이 그것뿐이다. 강조 상자 · 이미지 ·
목록 · 단계는 모양만 정해 두고(아래 표) 쓸 FAQ 가 생길 때 더한다. 안 쓰는 블록을 미리 만들면
쓰는 자리가 없어 틀린 채로 굳는다.

배열 모양을 지금부터 두는 것이 늘릴 자리다. 종류가 늘어도 호출부는 안 고친다.

| 블록 | 모양 | 언제 |
|---|---|---|
| `paragraph` | `text-13` · `text-text-muted` | 기본 |
| `callout` | `bg-info-tint` 상자 · 아이콘 14px | 한 답에 하나까지 |
| `figure` | 시트 폭에 맞춘 그림 + `text-11` 설명 | 그림이 말이 더 빠를 때 |
| `list` | 점 목록 · 점은 `primary-ink` | 나열이 문장보다 짧을 때 |
| `steps` | 번호 원 17px + 글 | 순서가 **정말 있을 때** |

`steps` 에 단서가 붙는 이유는 순서가 없는데 번호를 붙이면 없는 순서를 지어내기 때문이다.

### 결정 5. 시트 안의 모양

| 자리 | 값 |
|---|---|
| 제목 | `text-base` 700. 그 화면의 말로 쓴다. `자주 묻는 질문` 이라고 안 쓴다 |
| 질문 | `text-sm` 600 · 앞에 `Q` 표식 `primary-ink` |
| 답 | `text-13` · `text-text-muted` · 왼쪽 20 들여쓰기(질문 글자와 맞는다) |
| 구분 | 문답 사이 `border-border` 한 줄 |

제목이 `자주 묻는 질문` 이 아닌 이유는 그 말이 **무엇에 대한 설명인지를 안 말하기 때문**이다.
결산 줄에서 열면 `스케줄러 결산` 이다.

### 결정 6. 닫는 길은 **기존 시트와 같다**

스크림을 누르거나 아래로 끌어 닫는다. 바닥에 닫기 버튼 줄을 두지 않는다 — 그 줄의 높이만큼 시트가
짧아지는데, 읽기만 하는 시트에 그 값을 쓸 이유가 없다.

### 결정 7. 내용은 **데이터로 둔다**

FAQ 내용은 화면 코드가 아니라 데이터다. 그래야 새 FAQ 를 다는 일이 시트를 고치는 일이 아니게 된다.

두는 자리는 `src/data/` 가 **아니라** 그 기능 폴더다. `src/data/` 는 게임 레퍼런스 수치가 사는
자리이고([[ADR-006]]), FAQ 는 게임 수치가 아니라 앱 설명이다.

## 첫 사용처: 결산 FAQ

제목은 `스케줄러 결산` 이고 세 문답이다(문구는 사용자 확정 2026-09-16).

| 질문 | 답 |
|---|---|
| 결산이 무엇인가요? | 넥슨이 일간, 주간 스케줄러 기록을 모아 확정하는 작업입니다. 22:00 ~ (익일) 04:00 사이에 진행되며, 결산 중에는 기록이 조회되지 않습니다. |
| 왜 보스가 완료 처리되지 않나요? | 결산 시간이 아닐 때 보스를 처치하더라도 결산 시간 전에 앱에서 기록을 호출하지 않으면 완료로 처리되지 않을 수 있습니다. |
| 어떻게 해야 하나요? | 결산이 완료되면 다음 조회 시 앱이 알아서 데이터를 동기화합니다. 기다려주세요. |

**`22:00 ~ (익일) 04:00` 은 사용자가 준 값이다.** 앱이 이 시각으로 판정하지 않는다 — 판정은 서버가
하고([[ADR-284]] 결정 1) 이 문장은 설명이다. 서버가 도는 창은 20:00 ~ 06:00 으로 더 넓은데, 사용자에게
말하는 대략의 구간과 서버가 살펴보는 구간이 같을 이유가 없어서다.

세 문답의 높이는 약 410 이라 상한에 안 닿는다.

## 대가

- **부품 하나에 화면 여럿이 매달린다.** 시트 모양을 고치면 모든 FAQ 가 함께 바뀐다. 그것이 목적이지만,
  한 화면만 다르게 하고 싶을 때 쓸 손잡이가 없다.
- **블록 종류가 하나라 지금은 배열이 과해 보인다.** 문자열 배열로 두면 더 짧다. 그 짧음을 안 고르는
  것은 그림이 들어가는 FAQ 가 이미 예정돼 있기 때문이고, 그때 계약을 바꾸면 호출부를 전부 고쳐야 한다.
- **설명이 시트로 들어가면 화면에서는 안 보인다.** 열어야 읽힌다. 화면에 늘 떠 있어야 하는 말은
  이 시트가 아니라 화면 문구로 남아야 한다.

## 정정 1. 결산 FAQ 의 시각을 실측으로 바꾼다 (2026-09-25, 사용자 결정 · 이슈 #458)

### 맥락

위 표의 `22:00 ~ (익일) 04:00` 은 사용자가 어림으로 준 값이었다. 서버가 여섯 밤을 재고 나니
실제 구간은 **00:00 ~ 02:00**(KST)이었다([[ADR-284]] 정정 1).

**표와 코드가 이미 갈라져 있었다.** OTA 1.0.10(`eb454425`)이 문구를 `00:00 ~ 04:00` 으로 고치고
`기록이` 를 `일부 기록이` 로 바꿨는데 이 ADR 은 안 따라왔다. 이 정정이 둘을 다시 맞춘다.

### 정정

첫 문답의 답이 이렇게 된다.

> 넥슨이 일간, 주간 스케줄러 기록을 모아 확정하는 작업입니다. 00:00 ~ 02:00 사이에 진행되며,
> 결산 중에는 일부 기록이 조회되지 않습니다.

나머지 두 문답은 그대로다. **시각은 여전히 설명이지 판정이 아니다.** 앱은 이 시각으로 가르지
않고 서버가 응답으로 판정한다([[ADR-284]] 결정 1). 서버가 도는 창이 06:00 까지인 것은 끝을 못 본
밤에도 언젠가는 끄기 위해서다.

### 대가

- **넥슨이 구간을 옮기면 문구가 틀린다.** 어림값일 때보다 좁아서 더 잘 틀린다. 판정은 안 흔들리고
  설명만 낡는다.
- **문구를 고치려면 앱을 새로 내야 한다.** 서버가 주는 값이 아니라 앱이 든 글자라서다.
