# ADR-198: 버튼 atom 은 외형만 갖고, 스타일 표는 `variants.ts` 로 가른다

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-09-01
**관련**: [[ADR-094]](atoms 는 `design-system.md` 가 규정한 것만 만든다) · [[ADR-128]](RN 전환) · [[ADR-195]](배지도 같은 모양의 변형 표를 쓴다)

## 맥락

`design-system.md` 의 `기본 컴포넌트` 절이 버튼을 클래스 문자열로 규정하고 있었고, [[ADR-094]]
결정 3 이 그 규정을 atom 으로 승격했다. 문서에 없던 `danger`(파괴적 동작)와 `outline`(부 동작)은
이미 화면에서 쓰이고 있던 것을 코드로 올린 것이다.

웹에서 RN 으로 오면서 `<button>` 태그가 공짜로 주던 것 셋이 사라졌다. 버튼 시맨틱, 글자 스타일
상속, 폼 submit 방지다. 그 셋을 어떻게 메울지가 이 atom 의 모양을 정했다.

## 결정

### 결정 1. 외형만 갖고 레이아웃은 호출부에 남긴다

변형 표에 있는 것은 배경·테두리·여백·라운딩과 글자색·크기·굵기뿐이다. 폭·정렬·간격은 없다.

근거는 실측이다(2026-08-05). `primary` 를 쓰는 9곳에서 공통으로 나온 토큰은 변형 표의 것뿐이었고
`w-full`·`gap-2` 는 5~6곳에서만 쓰였다. 그것들은 이 버튼이 어떻게 생겼나가 아니라 이 자리에
어떻게 놓이나에 속한다. atom 이 그것까지 쥐면 호출부마다 예외 프롭이 생기는데, [[ADR-094]]
결정 1 이 경계한 것이 그 모양이다.

라운딩만 예외로 atom 이 못박는다. `design-system.md` 의 디자인 원칙 2 가 컴포넌트 성격별로
라운딩을 다르게 주기 때문이다(카드 14px · 버튼 pill · 인풋 10px). 프롭으로 열면 그 원칙이
호출부에서 무너진다.

### 결정 2. 상자 클래스와 글자 클래스를 두 벌로 나눈다

웹은 `<button>` 하나에 배경·여백과 글자색·굵기를 함께 걸었다. RN 에서는 그것이 안 된다. **글자
스타일이 상자에서 자식 `Text` 로 상속되지 않는다.** 실측으로 `Pressable` 의 `className` 에 넣은
`text-*`·`font-*` 는 그 View 의 style 에 들어가 앉아 있기만 하고 안쪽 `Text` 는 못 받았다.

그래서 같은 규정을 `BUTTON_VARIANT_CLASS`(상자)와 `BUTTON_VARIANT_TEXT_CLASS`(글자) 두 벌로
나눈다. 값은 웹 문자열을 그대로 쪼갠 것이고 새로 만든 값이 없다.

**이 실패는 조용하다.** 한 벌로 되돌려도 에러가 없고, 라벨이 색도 굵기도 없이 그려질 뿐이다.
그래서 테스트가 상자 표에 `text-`·`font-` 로 시작하는 클래스가 없는지 본다.

호출부에 남는 결과가 하나 있다. 글자 유틸은 `className` 이 아니라 `textClassName` 으로 준다.
상자에 주면 무시되는데, 그때도 에러가 없다.

### 결정 3. 스타일 표는 `variants.ts` 로 가른다

`Button.tsx` 는 **어떻게 그리는지**만 갖고, `variants.ts` 는 **무엇으로 그리는지**만 갖는다.

표를 컴포넌트 파일 안에 넣어 보고 되돌렸다(2026-09-01). 두 가지가 걸렸다.

**컴포넌트 코드가 표에 묻힌다.** 버튼은 표 20줄에 코드 20줄이라 견딜 만했지만, 같은 구조인 배지는
표가 90줄이고 코드가 60줄이다. 파일을 열었을 때 먼저 보이는 것이 클래스 문자열이면 그 컴포넌트가
무엇을 하는지 읽는 데 스크롤이 든다.

**fast refresh 가 깨진다.** 컴포넌트 파일이 컴포넌트 아닌 값을 export 하면
`react-refresh/only-export-components` 가 걸리고, 그 파일을 고칠 때 상태 보존 대신 전체 리로드가
돈다. 실제로 표를 넣은 동안 경고가 2건 늘었다.

타입은 표에서 파생되므로 `variants.ts` 가 갖는다. 호출부가 쓰는 타입은 컴포넌트 파일이 다시
내보내서(`export type { BadgeVariant } from './variants'`) import 경로를 하나로 유지한다. 타입은
지워지는 값이라 fast refresh 규칙에 안 걸린다.

같은 판단을 따르는 자리가 이미 여럿이다. `settings/row-class.ts` · `Toast/timer-animation.ts` ·
`DropEffectOverlay/float-animation.ts` · `AccountSelect/place-dropdown.ts` 가 그렇다. 배지도 같은
규칙을 따른다([[ADR-195]] 정정 5). `ProgressBar/width-transition.ts` 는 이 목록에 있었으나 해당하지
않았고(정정 1), `FadedIllustration/faded-illustration.ts` 는 해당했다가 벗어났다(정정 2).

### 결정 4. 웹에서 안 넘어온 것 둘, 명시로 바꾼 것 하나

**`hover:` 는 뺐다.** 터치 기기에 hover 가 없고 NativeWind 도 네이티브에서 그 클래스를 조용히
버린다(실측으로 렌더 결과에 흔적이 없다). 남겨 두면 있는데 안 도는 코드가 된다. 눌림 피드백은
`active:` 라는 다른 축이고, 웹에 없던 것을 여기서 새로 만들지 않았다.

**`type` 프롭은 없앴다.** 웹에서 기본값을 `button` 으로 둔 이유가 폼 안에서 실수로 submit 되는
사고였는데, RN 에는 폼도 submit 도 없다. 남기면 아무 일도 안 하는 프롭이 된다.

**`primary` 의 `text-base` 는 더한 것이 아니라 적어 준 것이다.** 웹 `<button>` 은 Tailwind preflight
의 `font: inherit` 로 본문 크기 16px 를 물려받았고, 그래서 primary 만 크기 클래스가 없었다. RN 의
`Text` 기본값은 14px 라 그대로 두면 그 자리만 웹보다 작아진다. 문자열이 아니라 그려지는 크기를
맞춘다.

## 검증

`src/components/atoms/Button/__tests__/Button.test.tsx` 가 변형 넷의 **풀린 스타일**을 본다. 클래스
문자열은 렌더 트리에 남지 않으므로 값으로 확인해야 하고, 그래서 클래스 이름이 바뀌어도 그려지는
모습이 같으면 통과한다.

그중 한 케이스가 결정 2 의 회귀를 막는다. 상자 표에 글자 유틸이 도로 들어가면 실패한다.

## 트레이드오프

**파일이 하나 더 늘어난다**(결정 3). 변형 하나를 더할 때 두 파일을 오간다. atom 하나에 파일 둘은
디렉터리를 열었을 때 무엇이 컴포넌트인지 덜 분명하다.

**라운딩을 프롭으로 못 연다**(결정 1). 디자인 원칙을 코드가 지키는 대신, 예외가 필요한 자리가
생기면 이 ADR 을 다시 열어야 한다.

## 정정 1 (2026-09-02, 실측). 이 규칙은 **export 하는 값**에만 걸린다

결정 3 의 선례 목록에 `ProgressBar/width-transition.ts` 가 있었는데 그 자리는 해당하지 않았다.
`WIDTH_TRANSITION` 은 소비자가 같은 디렉터리의 `ProgressBar.tsx` 하나뿐이라 **export 할 이유가
없었고**, export 하지 않는 값은 `react-refresh/only-export-components` 에 걸리지 않는다. 값을
`ProgressBar.tsx` 안 지역 상수로 옮긴 뒤 eslint 를 돌려 확인했다(경고 0). 파일은 지웠다.

그래서 결정 3 을 쓸 때 물을 것은 «값인가» 가 아니라 **«그 값을 모듈 밖에서 쓰는가»** 다. 남은 선례
다섯은 전부 여기에 해당한다. `variants.ts` 둘은 호출부가 타입을 쓰고, 나머지 셋은 다른 파일이
값을 import 한다.

값이 커서 컴포넌트를 묻는 경우는 별개의 이유로 여전히 가른다(결정 3 의 첫 근거 — 배지 표 90줄 대
코드 60줄). `WIDTH_TRANSITION` 은 5줄이라 그쪽에도 안 걸렸다.

## 정정 2 (2026-09-02, 실측). `faded-illustration.ts` 도 지웠다

정정 1 과 **같은 판정이 한 자리 더** 나왔다. 결정 3 의 선례 목록에 있던
`FadedIllustration/faded-illustration.ts` 가 사라졌다.

그 파일이 200줄이던 동안은 두 근거에 다 걸렸다. 그런데 크롭 기하 여섯이 `lib/image-crop.ts` 로
빠지면서(조회 쪽인 `lib/boss-icons` 와 그리기 쪽인 `components/` 가 **둘 다 쓰는 값**이라 `lib/` 이
맞는 자리였다) 남은 것이 필터·베일 **값 8줄**이 됐다. 첫 근거(값이 커서 코드를 묻는다)에 안 걸린다.

두 번째 근거도 안 걸렸다. 그 값을 모듈 밖에서 쓰던 것은 **테스트 둘뿐**이었다. 둘 다 «RN 상수가 웹
원본과 같은가» 를 상수끼리 비교하고 있었는데, 그 비교를 **그려진 결과**로 옮겼다. 렌더한
`LinearGradient` 의 `locations`·`colors` 와 감싸는 `View` 의 `filter` 를 `lib/media-card` 의 웹
문자열에서 뽑은 값과 견준다. 선언이 아니라 화면에 나가는 값을 보므로 이쪽이 더 낫고, 값을 내보낼
이유가 없어졌다.

값을 `FadedIllustration.tsx` 안 지역 상수로 옮기고 eslint 를 돌려 확인했다(경고 15건 그대로).
타입 `IllustrationVariant` 만 내보내는데, 타입은 지워지는 값이라 이 규칙에 안 걸린다(결정 3).
