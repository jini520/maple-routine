# ADR-167: 하단바의 «층» 을 **진짜 스택**으로 만든다 — 제스처와 전환은 구조에서 나온다

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-08-23
**상태**: **구현 완료**(2026-08-23, 사용자 결정 3건) — **실기기 미검증**(아래 「검증」 절).
**관련**: [[ADR-132]](두 층 바 — **이 결정이 그 층 모델의 소유자를 바꾼다**) · [[ADR-120]] 결정 4(탭바가
아래 화면과 한 덩어리로 밀려 나간다) · [[ADR-120]] 결정 5·6(전환 애니메이션 · 가장자리 스와이프) ·
[[ADR-120]] 결정 18(스택이 비면 백그라운드로) · [[ADR-130]](새 제스처 계층은 «옮기기» 가 아니라
«다시 만들기») · [[ADR-145]] 결정 1(보스 관리가 셋째 하위) · [[ADR-150]](전면광고 철거로 바의 판정이
하나 줄었다)

## 맥락

사용자 보고 — *"하단바 **하위 탭**에서 iOS 뒤로가기 제스처(가장자리 스와이프)가 동작하지 않는다.
다른 하위 페이지처럼 열리도록 고친다."*

### 안드로이드는 되는데 iOS 만 안 되는 것은 우연이 아니다

하위 페이지 열하나는 **루트 스택 push** 라 제스처가 공짜로 붙어 있다(`RootNavigator.tsx` —
`animation: 'ios_from_right'` · `gestureEnabled: true`). 그런데 하단바의 하위 행은 **스택이 아니다** —
화면 아홉이 `TabNavigator` 안에 전부 형제로 있고 그 사이에는 스택도 애니메이션도 없다.

그래서 **되돌아갈 단이 없고**, 뒤로가기는 바가 손으로 만들어 낸다:

- `bar-model.ts` — `history`(한 층 내려올 때 적은 «온 자리») · `showGroups` · `canGoBack()`
- `bar-store.ts` — 그 기록의 보관소
- `use-root-back.ts` — 안드로이드 하드웨어 백이 그 규칙을 탄다

안드로이드 백은 `BackHandler` 를 우리가 가로채 `barGoBack()` 을 부르기 때문에 된다. iOS 가장자리
스와이프는 **가로챌 자리가 없다** — UIKit 인식기는 `UINavigationController` 가 갖고 있고, 탭 전환에는
그 컨트롤러가 없다.

### 이슈의 비용 추정 둘이 틀렸다 (2026-08-23 코드 확인)

이슈는 A안(그룹 진입을 스택 push 로)의 대가를 *"층 상태의 진실 원천이 둘이 된다"* 로 봤다.
`bar-store.ts:13` 의 경고를 인용하면서다 — *"두 벌이 되면 «탭은 가계부인데 바는 스케줄» 같은 프레임이
반드시 생긴다"*.

**틀렸다. 방향이 반대다.** 스택이 층을 지면 `history` 와 `showGroups` 는 **합쳐지는 것이 아니라 죽는다** —
스택 깊이가 곧 층이고, 그러면 «기록이 없는데 하위 행에 있다» 는 상태가 **성립할 수 없다**(결정 5 의
안전망이 존재 이유를 잃는다). 진실 원천은 둘이 되는 게 아니라 **하나로 줄어든다.**

두 번째: 바가 탭 내비게이터에 묶인 곳이 **856줄 중 두 줄뿐이다.**

```
BottomBar.tsx:396   const page = state.routes[state.index].name as TabRouteName
BottomBar.tsx:539   if (next.page !== before.page) navigation.navigate(next.page)
```

나머지(층 판정 · 색 · 치수 · 알약 애니메이션 · 접근성)는 내비게이터를 **묻지 않는다**.

### 잃는 것도 재 봤다

하위 화면의 로컬 상태: `ContentScreen` **0개** · `BossScreen` 1개(파티 모달) · `BossProfitScreen` 2개.
데이터는 전부 zustand 라 언마운트로 잃는 것은 **스크롤 위치 정도**다.

## 결정

### 결정 1. 층은 **스택 한 단**이다 — 바가 아니라 react-navigation 이 든다

그룹 행 → 하위 행이 **진짜 push** 가 된다. 그러면 전환 애니메이션과 가장자리 스와이프가 **둘 다 공짜로**
붙는다(사용자 결정: *"전환 애니메이션 + 스와이프 백 둘 다"*). [[ADR-120]] 결정 5·6 이 하위 페이지
열하나에 준 것과 **같은 값**이 같은 경로로 온다 — 새 제스처 계층을 만들지 않으므로 [[ADR-130]] 이
경고한 비용이 발생하지 않는다.

### 결정 2. 바는 **스택의 형제**다 — 층은 밀리고 바는 안 밀린다

새 구조:

```
RootStack  (ios_from_right · gestureEnabled)
├─ Main                                 ← 「탭 레이어」를 대신하는 화면 하나
│   └─ <View>
│        ├─ LayerStack (ios_from_right · gestureEnabled)   ← 층을 이것이 진다
│        │    ├─ Groups        = 그룹 층 (Today · Utility · Settings, tabBar 없음)
│        │    ├─ ScheduleSubs  = 스케줄러 하위 (Content · Boss · BossManage)
│        │    └─ LedgerSubs    = 수익·지출 하위 (Profit · HuntingProfit · Spend)
│        └─ <BottomBar />      ← 형제. 절대배치. 층이 밀려도 **안 움직인다**
└─ 하위 페이지 열하나          ← 지금 그대로
```

**이 자리가 [[ADR-120]] 결정 4 를 지킨다.** 그 결정은 *"탭바가 아래 화면과 한 덩어리로 밀려 나간다"* 인데,
하위 페이지 열하나는 `Main` **통째**를 밀어내므로 바가 함께 나간다 — 지금과 한 프레임도 다르지 않다.

바를 앱 층(`AppNavigation`)으로 끌어올리는 판은 **버린다.** 그러면 바가 하위 페이지 위에도 그려져
«언제 숨기나» 라는 새 판정이 생기고, 밀려 나가는 대신 사라지게 되어 결정 4 가 깨진다.

### 결정 3. 하위끼리는 **같은 스택 단 안의 형제**다 — 안 쌓인다

사용자 결정: *"지금처럼 옆걸음 — 안 쌓는다."* 컨텐츠 → 보스는 `ScheduleSubs` 안의 탭 전환이라 스택이
자라지 않고, 거기서 ← 는 **그룹에 들어오기 전 자리**로 나간다. [[ADR-132]] 결정 4 가 `backBehavior="history"`
를 거절한 근거(*"모든 탭 전환이 쌓인다"*)를 그대로 지킨다.

하위 여섯을 **평평한 스택 화면 여섯**으로 두고 `replace` 로 옆걸음하는 판도 있었다(구조가 더 얇다).
버린 이유는 `replace` 가 언마운트라 **컨텐츠에서 스크롤을 내렸다가 보스에 갔다 오면 맨 위**가 되기
때문이다. 지금은 탭이라 유지된다 — 고치러 온 일이 아닌 것을 망가뜨리지 않는다.

### 결정 4. `history` 와 `showGroups` 를 **지운다**

- `history` → 스택이 든다.
- `showGroups`(기록 없는 ← 로 페이지는 그대로 둔 채 그룹 행만 올린 상태, [[ADR-132]] 결정 5) →
  **없앤다.** 하위 층에 있다는 것이 곧 스택 깊이 ≥ 1 이라, 그 상태가 만들어질 길이 사라진다.
- `lastSub` → **남는다.** 그룹을 나가면 그 스택 단이 언마운트되므로, 다시 들어갈 때 어느 하위로 갈지는
  여전히 우리가 기억해야 한다.

`bar-store.ts` 가 드는 것은 이제 `lastSub` 하나다.

### 결정 5. `bar-model.ts` 는 **상태가 아니라 «이동 의도»** 를 돌려준다

지금 `pressGroup`/`pressSub`/`pressBack` 은 새 `BarState` 를 만들고 `BottomBar` 가 그것을 적용한다.
층을 스택이 들면 그 반환값이 갈 곳이 없다 — 상태는 react-navigation 것이다.

그래서 같은 함수들이 **무엇을 할지**를 돌려준다:

```ts
type BarIntent =
  | { kind: 'openSubs'; group: GroupId; page: TabRouteName }  // push
  | { kind: 'switchSub'; page: TabRouteName }                 // 같은 단 안 옆걸음
  | { kind: 'switchGroupPage'; page: TabRouteName }           // 그룹 층 안 옆걸음(+ popToTop)
  | { kind: 'back' }                                          // pop
  | { kind: 'none' }
```

**규칙은 여전히 순수 함수로 테스트된다** — `bar-model.ts` 머리말이 적어 둔 존재 이유(*"판정을 물으려면
렌더가 필요해지면 안 된다"*)가 그대로 산다. 사용자가 준 예시 셋도 그대로 명세로 남는다.

### 결정 6. `openPage`(위젯 타일)의 **특수 케이스가 사라진다**

[[ADR-132]] 결정 4 의 구멍을 메우려고 만든 함수다 — today 위젯으로 보스 수익에 가면 기록이 빈 채로
하위 행에 도착해, ← 가 «가계부가 활성인 채 그룹 행만 열림» 으로 떨어졌다.

스택에서는 위젯 타일이 그냥 `push` 다. 기록을 «누가 적었는가» 라는 물음 자체가 없어지므로
**그 결함의 원인이 구조에서 제거된다.** 함수는 남되(목적지를 지목하는 진입점은 여전히 필요하다)
`pressGroup` 과 다른 규칙을 갖지 않는다.

### 결정 7. 안드로이드 하드웨어 백의 **바 전용 분기를 걷는다**

`use-root-back.ts` 는 «화면 스택 → 바 기록 → 백그라운드» 세 단계였다. 층이 진짜 스택이 되면
`navigation.canGoBack()` 이 **하위 층까지 포함해 참**이 되므로 react-navigation 이 알아서 pop 한다.
남는 것은 원래의 두 단계다 — 스택이 비면 백그라운드([[ADR-120]] 결정 18).

`barCanGoBack`/`barGoBack`/`registerBarBackHandler` 가 함께 사라진다.

### 결정 8. 같은 층이 스택에 **두 번 서지 않는다**

이미 아래 단에 있는 층으로 가면 **되돌아간다**(push 가 아니라 pop).

이 결정은 구현 중에 강제됐다 — **react-navigation 7 의 `navigate` 는 더 이상 되돌아가지 않는다**
(그 몫이 `popTo` 로 갈라졌다). 그대로 두면 하위 층에서 화면 CTA 로 설정에 갈 때 스택 바닥에 있는
그룹 층이 **한 번 더 쌓이고**, 그러면 바는 ← 를 안 그리는데(층 판정은 «지금 페이지» 에서 나온다)
가장자리 스와이프는 뒤로 가는 **어긋난 프레임**이 된다.

그룹 층은 **항상 바닥**이므로 그리로 되돌아가는 것은 `popToTop` 이다(`use-open-tab.ts`). 층끼리는
바가 `popTo` 로 판정한다(`Main.tsx`).

옛 동작과 갈리는 자리가 하나 있다: 예전에는 «스케줄러 → 가계부 → 스케줄러 → ←» 가 **가계부**로
돌아왔다(`history` 가 계속 자랐다). 지금은 **설정**(가계부에 들어오기 전 자리)으로 나간다. 층이
중복되지 않으므로 깊이가 무한정 자라지 않는 쪽을 택했다.

## 대가

- **네비게이션 코어 전면 개편이다.** `routes.ts` · `RootNavigator` · `TabNavigator` · `bar-model` ·
  `bar-store` · `BottomBar` 배선 · `use-root-back` 과 그 테스트 1,458줄이 함께 움직인다. [[ADR-132]] 는
  정정이 30건 넘게 쌓인 문서이고, 이 앱에서 제일 예민한 부분이다.
- **그룹을 나가면 그 하위 화면들이 언마운트된다.** 스크롤 위치가 초기화된다(로컬 상태는 재 봤고 거의
  없다). 그룹 **안**에서의 옆걸음은 결정 3 이 지킨다.
- **`Main` 이라는 층이 하나 늘어난다.** 스택 안에 스택이라 개발자 도구에서 계층이 한 겹 깊어진다.
- **`INITIAL_TAB_ROUTE` 의 의미가 갈린다** — 앱은 그룹 층의 `Today` 에서 시작하므로 «탭 아홉 중 첫
  화면» 이 아니라 «그룹 층의 첫 화면» 이 된다. 타입도 `keyof GroupLayerParamList` 로 좁혔다.
- **그룹 하나를 여러 번 오가면 뒤로 갈 자리가 옛것과 다르다**(결정 8 마지막 문단).

## 검증 (실기기)

- iOS: 그룹 행 → 하위 진입이 **오른쪽에서 밀려 들어오는가**, 가장자리 스와이프로 **되돌아가는가**.
- iOS: 하위 → 하위(컨텐츠 ↔ 보스)가 **즉시**인가(밀리지 않아야 한다).
- iOS: 하위 페이지 열하나가 열릴 때 **바가 함께 밀려 나가는가**([[ADR-120]] 결정 4 회귀 확인).
- 안드로이드: 하드웨어 백이 «하위 → 그룹 → 백그라운드» 순서로 도는가.
- 두 플랫폼: today 위젯 타일 → 보스 수익 → ← 가 **today** 로 돌아오는가([[ADR-132]] 결정 4 의 그 결함).
