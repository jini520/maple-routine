# ADR-250 누를 때 흐려지지 않는다

> 🟢 유효
> 관련 소스: `__tests__/press-dim-policy.test.ts`

## 배경

누르는 동안 흐려지는 효과(NativeWind 의 `active:opacity-*`)는 카드에서 먼저 걷었다. today 위젯([[ADR-058]] 결정 11)과
파티 스케줄 회차 카드가 먼저 따랐고, 가계부 리디자인([[ADR-095]]) 때 앱의 모든 카드로 넓혔다. 그때 작은 버튼 · 글자
링크 · 입력 칸은 카드가 아니라서 흐려짐을 남겼다. 2026-11-16 에 25개 파일의 33곳이 그렇게 남아 있었다.

사용자가 남은 흐려짐도 모두 걷고, 앞으로 만들지 말라고 정했다(2026-11-16).

## 결정

### 결정 1. 앱의 어떤 것도 누르는 동안 흐려지지 않는다

카드 · 버튼 · 글자 링크 · 입력 칸 · 아이콘 버튼이 모두 같다(사용자 지정). 그래서 `active:opacity-*` 클래스와
`TouchableOpacity` · `activeOpacity` 를 쓰지 않는다. `Pressable` 의 `style` 함수에서 `pressed` 로 투명도를 바꾸는 것도
같은 효과라 쓰지 않는다.

카드에서 먼저 걷은 이유는 카드 하나가 통째로 흐려지면 그 카드만 다른 카드와 따로 논다는 것이었다. 이번에는 카드가
아닌 것까지 넓혔다.

흐려짐을 걷은 자리에 다른 누름 표시를 대신 넣지 않는다. 디자인 원칙의 `시킨 것만 넣는다` 를 따른다.

### 결정 2. 흐려지지 않는 누름 표시와 막힌 표시는 그대로 둔다

다음은 흐려지는 효과가 아니라서 이 규칙의 대상이 아니다.

- 누르는 동안 바탕색이 바뀌는 것(`active:bg-*`). `NumberPad` 의 숫자 키 · `SelectField` 의 목록 줄 · `InputCard` 의 버튼이 쓴다.
- 보스 스케줄러 카드가 누르는 동안 살짝 작아지는 것(`app/boss-scheduler/BossScreen.tsx` 의 `active:scale-[.985]`).
- 막힌 버튼이나 고를 수 없는 줄을 흐리게 그리는 것. 누름 표시가 아니라 지금 누를 수 없다는 표시다.
