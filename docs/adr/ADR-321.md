# ADR-321: 로그인 화면은 넥슨 로그인을 주 경로로 세운다. API 키는 그 아래 남는다

> 🟡 부분 폐기 · **결정 7 의 내보내는 때는 [[ADR-334]] 가 대체했다**(2026-10-04. 스토어 1.0.12 에 꺼진 채로 싣고, 꺼진 동안 결정 8 의 키 블록은 펼친 채로 선다) · **구현 완료** 2026-09-28(`SignInScreen` · `ApiKeyForm` · `native/browser`) · 사용자 지정(시안 I 채택) · **실기기는 물론 시뮬레이터에서도 안 봤다**

**관련**: [[ADR-215]] 결정 2(키 입력 화면이 곧 로그인 화면) · [[ADR-296]] 결정 1(대체가 아니라 병행)·결정 7
· [[ADR-318]] 결정 6(버튼이 서는 자리) · [[ADR-110]](가이드는 안내 사이트에 · 링크는 둘) · [[ADR-194]](문구 규칙)

## 맥락

`SignInScreen` 은 지금 **키 폼이 먼저이고 넥슨 버튼이 그 아래 붙어 있다.** 그 자리는 로그아웃한
사용자가 다시 들어올 길을 내려고 급히 낸 것이고([[ADR-318]] 결정 6 정정), 화면의 위계는 여전히
키가 1차 경로다.

그 위계를 뒤집는다. 넥슨 로그인은 키 발급 7단계를 건너뛰므로, 검수를 통과하면 처음 쓰는
사용자에게 확실히 더 짧은 길이다. 지금은 키 쪽이 첫 화면의 대부분을 차지해 그 길이 안 보인다.

**키를 걷지는 않는다.** Open ID 로 열리는 것은 프렌즈 API 넷뿐이고 병행이 전제다([[ADR-296]]
결정 1). 다른 넥슨 계정의 캐릭터를 붙이는 길도 키뿐이다(같은 결정 2).

## 결정

### 결정 1. 넥슨이 위, 키가 아래다 (사용자 지정)

화면 머리 다음에 넥슨 블록이 서고 그 아래 키 블록이 선다. 화면 하나에 둘 다 있고 스크롤이 없다.

키를 다음 화면으로 밀거나 시트로 올리는 안도 만들어 봤는데(시안 C·G) 고르지 않았다. 둘 다
키 사용자에게 탭을 하나 더 물리는데, 검수를 통과하기 전에는 **키가 실제로 되는 유일한
경로**라서다.

### 결정 2. 화면 머리는 앱 아이콘과 두 문장이다

`assets/icon.png` 를 72px 둥근 사각형으로 놓고, 그 아래 **왜 인증이 필요한지**를 두 줄로 적는다.
아이콘과 두 문장은 가운데 정렬이고 그 아래 두 블록은 왼쪽 정렬이다.

```
내 메이플 스토리 스케줄 정보 조회를 위해서
로그인 또는 API 키 입력이 필요해요.
```

- **앱 이름을 안 쓴다**(사용자 지정). 아이콘이 이미 그 일을 하고, 이름을 적으면 그 줄이 제목
  자리를 먹어 정작 필요한 설명이 보조로 밀린다.
- **글자를 안 키운다**(사용자 지정). 두 문장 다 14px 흐린 글자다. 첫 줄을 제목 크기로 올려
  봤다가 되돌렸다.
- 모서리는 크기의 22.4% 다(72px 에 16px). iOS 앱 아이콘이 잘리는 비율이라 **앱 아이콘으로
  읽힌다.** `border-border` 한 겹을 두르는 것은 아이콘 바탕 `#F0DAD6` 과 페이지 `#F2F0E2` 가
  거의 같은 밝기라 그것 없이는 경계가 안 보여서다. 그림자가 아닌 것은 `Card` atom 이 RN 에서
  그림자를 안 쓰기 때문이다. 이 앱에 카드 그림자라는 것이 없다.

### 결정 3. 두 경로가 같은 골격을 쓴다

```
게임 데이터 활용 로그인으로 시작하기      15px semibold · text
게임 데이터 활용 로그인이란?             13px · primary-ink · 링크
[ 넥슨ID 로그인 ]                       NexonLoginButton

API 키로 시작하기                       15px semibold · text        ⌄
넥슨 오픈 API에서 받은 키를 넣어요        13px · text-muted           아코디언 머리
  Nexon Open API 키                    라벨                        펼쳤을 때만
  [ 입력칸 ]
```

소제목 · 둘째 줄 · 입력 수단의 세 줄 구조가 두 블록에서 같다. 둘째 줄만 성질이 갈려 색이
다르다. 넥슨 쪽은 누를 수 있는 링크라 `primary-ink` 에 바깥 화살표가 붙고, 키 쪽은 설명이라
`text-muted` 다.

**링크 셋의 글자 굵기는 `normal` 이다**(사용자 지정 2026-09-28). 처음에는 `medium` 이었는데 한 단
내렸다. 굵기까지 주면 소제목과 무게가 붙어, 소제목 · 둘째 줄의 위아래 관계가 흐려진다.

구분선(`아직 API 키가 없나요?`)은 걷는다. 소제목이 이미 두 블록을 가르는데 선까지 두면 같은
일을 두 번 한다. 선은 둘을 **같은 무게로** 갈라놓기도 한다.

**링크는 글자 폭만큼만 차지한다**(`align-self: flex-start`). 줄 전체로 늘리면 옆 빈 자리를 눌러도
반응해 어디까지가 링크인지 알 수 없다.

### 결정 4. 키 쪽 버튼 둘을 한 단씩 내린다

| | 전 | 후 |
|---|---|---|
| `확인` | `primary`(채운 알약) | `tint` |
| `API 키 발급 방법 보기` | `outline` 알약 + 7단계 캡션 | 인라인 링크 |

**7단계 캡션은 안심 문구 자리와 맞바꾼다.** 두 줄을 다 두면 작은 중앙 정렬 글이 셋 연달아 서서
어느 것도 안 읽힌다. 남기는 쪽은 안심 문구다. 키를 넣기 직전에 필요한 말이라서다.

**채운 알약이 한 화면에 둘이면 주 동작이 둘로 보인다.** 넥슨 버튼이 파란 채움이라, 그 아래
주황 채움이 또 서면 무엇을 먼저 눌러야 하는지가 색으로 안 갈린다. `tint` 는 채운 알약보다 한 단
약한 주 동작 자리이고([[ADR-230]] 결정 6) 이 자리가 정확히 그것이다.

**뒤집는 것은 [[ADR-110]] 이 아니라 `docs/features/auth.md` 의 갈림길 레이아웃**(2026-08-08,
이슈 #61)이다. 가이드가 거기서 처음으로 누를 수 있는 크기가 된다고 적은 자리이고, 그 근거는
가이드가 1차 경로인데 화면에서 가장 작고 흐렸다는 것이었다. **키가 1차 경로일 때의 근거**라
넥슨이 1차가 되면 전제가 사라진다.

[[ADR-110]] 의 결정 둘은 그대로 산다. 가이드는 앱이 아니라 안내 사이트가 들고, 링크는 둘이며
중복이 아니라 서로 다른 두 진입점이다. 바뀌는 것은 그 둘째 링크가 화면에서 차지하는 크기뿐이다.

### 결정 5. 넥슨 설명은 앱이 안 싣고 링크가 연다 (사용자 지정)

넥슨의 `게임 데이터 활용 로그인` 소개 다섯 문장을 화면에 얹어 봤다가 걷었다. 카드로 담으니
309px 를 먹어 화면이 904px 가 됐고, 접이식으로 줄여도 **넥슨 버튼이 설명 아래로 밀렸다.**

남는 것은 `게임 데이터 활용 로그인이란?` 링크 하나다. 설명은 그 링크가 여는 넥슨 페이지
(`openapi.nexon.com/ko/data-util/introduction/`)가 든다. 넥슨이 문구를 고치면 앱을 안 고쳐도
따라간다.

### 결정 6. 로그인 화면의 바깥 링크 셋은 인앱 브라우저로 연다 (사용자 지정)

`게임 데이터 활용 로그인이란?` · `openapi.nexon.com에서 확인` · `API 키 발급 방법 보기` 셋이다.
`expo-web-browser` 의 `openBrowserAsync` 이고, 지금 쓰는 `Linking.openURL`(시스템 브라우저)을
대신한다.

**한 화면에 두 방식이 섞이지 않게 하는 것이 이유다.** 같은 크기 같은 색의 링크 셋이 하나는 앱을
떠나고 둘은 안 떠나면, 누르기 전에는 어느 쪽인지 알 수 없다.

- **`native/browser.ts` 와 `native/adapters/rn-browser.ts` 한 쌍을 새로 만든다.** `app/` 에서
  `expo-web-browser` 를 직접 부르면 어댑터 경계가 깨진다([[ADR-003]] 결정 1).
- **바깥 화살표 아이콘은 남긴다**(사용자 지정 2026-09-28, 정정). 처음에는 뗐다 - 그 아이콘이
  앱을 떠난다는 뜻인데 인앱 브라우저는 안 떠나서다. 되돌린 이유는 **링크라는 표식이 색 하나만
  남기 때문**이다. `primary-ink` 는 밝은 테마에서 표면 대비가 2.2~2.4 라([[ADR-230]] 정정 4 의
  실측) 색만으로는 누를 수 있다는 것이 안 읽힌다.
- **범위는 이 화면뿐이다.** 설정·공지의 링크는 그대로 시스템 브라우저다. 앱 전체를 바꾸는 것은
  별도 작업이다.
- 지문을 안 바꾼다. `expo-web-browser` 가 이미 번들에 있어 OTA 로 갈 수 있는 변경이다.

### 결정 7. 검수 통과 뒤 스토어 빌드에 묶어 내보낸다 (사용자 지정)

이 화면은 순수 JS 라 OTA 로 먼저 나갈 수 있지만 안 보낸다. **검수를 통과하기 전에는 등록된
테스트 사용자만 로그인이 되므로**([[ADR-296]] 결정 7), 넥슨 버튼을 맨 위 주 동작으로 세워
놓으면 나머지 사용자가 제일 큰 버튼을 눌러 실패한다.

[[ADR-318]] 결정 5 가 이미 **다음 스토어 빌드에 묶고 그 사이에 검수를 넣는다**고 적었다. 이
화면도 같은 배에 탄다.

### 결정 8. 키 블록은 접힌 채로 선다 (사용자 지정, 2026-09-28)

머리 두 줄이 곧 펼침 단추이고 오른쪽 끝에 셰브론이 선다. 누르면 그 아래로 라벨 · 입력칸 · 표시
토글 · 넥슨 바로 가기 · `확인` · 발급 안내 · 안심 문구가 펼쳐진다.

**접지 않으면 결정 1 이 화면에서 무너진다.** 넥슨을 위로 올려도 그 아래 인풋과 버튼 넷이 늘
펼쳐져 있으면 키 블록이 화면의 대부분을 먹어, 주 경로가 무엇인지가 자리만으로는 안 읽힌다.

- **머리 두 줄은 접혀 있어도 보인다.** 키로 가는 길이 사라지지 않는다. 사라지면 키가 1차 경로인
  검수 통과 전에 들어온 사용자가 막힌다.
- **셰브론은 `ChevronDown`·`ChevronUp` 이다.** 이 앱에서 오른쪽 셰브론은 **다른 화면으로 간다**는
  뜻이고(`SettingsLinkRow`), 아래위 셰브론이 **그 자리에서 펼친다**는 뜻이다
  (`boss-profit/CharacterAccordion`). 여기서 열리는 것은 같은 화면이라 뒤쪽이다.
- **`aria-expanded` 를 준다.** RN 의 `Pressable` 이 그것을 `accessibilityState.expanded` 로 접으므로
  테스트도 그 자리를 본다.
- 둘째 줄 문구가 `넥슨 오픈 API에서 받은 키를 직접 넣어요` 에서 **`직접` 을 뺀 것**으로 바뀐다
  (사용자 지정).

**저장된 키가 있어도 접힌 채로 연다**(사용자 지정 2026-09-28). 키가 죽어 다시 넣으러 온
사용자도 같은 화면을 만난다.

이유는 둘이다. **화면이 조건에 따라 갈리면 사용자가 그 화면을 두 가지로 배운다.** 어떤 날은
펼쳐지고 어떤 날은 접혀 있으면, 접힌 것이 정상인지 고장인지 가릴 방법이 없다. 그리고 **저장된
키가 있다는 것이 지금 키를 고치러 왔다는 뜻은 아니다.** 넥슨으로 갈아타러 온 사용자도 같은
화면에 선다.

## 대가

- **키 사용자의 동선이 길어진다.** 인풋이 화면 아래로 내려가 한 번 더 내려다봐야 한다. 검수를
  통과하기 전에는 키가 실제로 되는 유일한 경로인데 그쪽이 아래에 선다.
- **`확인` 이 약해진다.** `tint` 는 테마에 따라 바탕과 대비가 낮아, 키를 넣고 나서 무엇을 눌러야
  하는지가 채운 알약만큼 뚜렷하지 않다. 실기기에서 볼 것.
- **인앱 브라우저가 키 복사를 어렵게 할 수 있다.** `API 키 발급 방법 보기` 는 넥슨 사이트에서
  키를 복사해 앱으로 돌아오는 흐름이다. 인앱 브라우저에서 복사가 되는지 실기기에서 볼 것.
- **화면 머리에 제목이 없다.** 앱 이름을 뺐고 설명을 안 키워서 진한 글자가 소제목 둘뿐이다.
  눈이 어디서 시작할지를 아이콘 하나가 진다.
- **키 사용자에게 탭이 하나 는다**(결정 8). 검수를 통과하기 전에는 키가 실제로 되는 유일한
  경로인데 그 경로가 접혀 있다. 키 재입력으로 온 사용자도 마찬가지다.

## 실측

**없다.** 코드는 섰고 테스트는 초록이지만 **시뮬레이터에서도 안 띄워 봤다.** 지금까지 본 것은
캔버스의 목업뿐이다. 실기기에서 볼 것 셋은 위 대가에 적었다(`tint` 인 `확인` 의 대비 · 인앱
브라우저에서 키 복사 · 화면 머리에 제목이 없는 것).
