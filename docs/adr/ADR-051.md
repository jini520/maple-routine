### ADR-051: 메이플 ID 계정 선택 — 단일 계정 자동 확정 폐기, 항상 선택 화면 경유 (설계, 구현 전)

**배경**: 지금은 메이플 ID(계정)가 **정확히 1개면 선택 화면을 건너뛰고 자동 확정**한 뒤 곧바로 예열([[ADR-016]])로 넘어간다. [[ADR-016]] 결정 1에 "계정이 확정되면(단일 계정 자동 확정 또는 다중 계정 중 선택)"으로 명시된 의도적 동작이고, 온보딩(`features/onboarding/state.ts`의 `API_KEY_VERIFIED`)과 설정의 계정 변경(`features/settings/state.ts`의 `ACCOUNTS_VERIFIED`) 두 경로에 각각 복제돼 있다.

자동 확정은 탭 한 번을 아끼지만, 그 대가로 **사용자가 "어떤 메이플 ID로 연동됐는지"를 한 번도 보지 못하고 지나간다.** 나중에 부계정을 만들어 계정이 2개 이상이 되면 설정의 계정 변경 화면에서 그제서야 목록을 처음 보게 되는데, 그전까지 자신이 무엇에 연결돼 있었는지 확인할 기회가 아예 없었다. 이슈 #60.

**결정**:

1. **온보딩·설정 두 경로 모두 계정 수와 무관하게 항상 `selectingAccount` 상태를 거친다.** `API_KEY_VERIFIED`(온보딩)·`ACCOUNTS_VERIFIED`(설정) 리듀서의 `accounts.length === 1` 분기를 제거한다. 계정이 1개든 여러 개든 `AccountSelectionList`가 뜨고, 사용자가 "계속하기"를 눌러야 예열이 시작된다.

2. **`selectedAccountId` 저장은 오직 사용자가 "계속하기"를 눌렀을 때의 `selectAccount` 경로 하나로 일원화한다.** 리듀서에 이벤트를 보내기 **전에** 계정을 미리 저장하던 선제 호출(온보딩 `finalizeVerifiedAccounts`, 설정 `finalizeAccounts`)을 제거한다. 이 선제 저장은 [[ADR-008]]의 "자동으로 다음 단계로 전이할 때도 `selectedAccountId`가 먼저 저장돼야 한다"는 요구에서 나온 것인데, **자동 전이 자체가 없어지므로 전제가 사라진다** — 남겨두면 사용자가 고르기도 전에 저장되는 앞선 부수효과가 된다.

3. **계정이 정확히 1개일 때는 그 항목을 초기 하이라이트로 지정한다.** `AccountSelectionList`는 항목을 눌러 하이라이트 → "계속하기"로 확정하는 2단계 구조인데, 이 결정의 목적은 **화면을 보여주는 것**이지 탭 수를 늘리는 게 아니다. 선택지가 하나뿐이라 고를 것도 없으므로 항목 선택 탭 1회는 아껴주고, "계속하기"라는 확정 행위만 남긴다.

**이유**:
- 사용자가 자기 계정이 무엇에 연동됐는지 **최소 한 번은 눈으로 확인하고 스스로 확정하는** 지점을 만든다. 계정이 하나뿐인 사용자는 지금 구조에서 그 화면을 평생 볼 일이 없다 — 부계정을 만들어 계정이 2개가 되는 날에야 처음 보게 되는데, 그때는 이미 "내가 그동안 무엇에 연결돼 있었나"를 되짚을 근거가 없다.
- 온보딩과 설정이 **같은 규칙을 공유**하게 된다. 지금은 동일한 자동 확정 분기가 두 리듀서에 복제돼 있어 한쪽만 고치면 어긋난다.
- **예열([[ADR-016]] 결정 1)은 그대로 유지되고, 바뀌는 건 예열이 시작되는 시점(자동 확정 직후 → 사용자 확정 직후)뿐이다.** 파이프라인 구조·진행률 계산·캐시 기록·개별 실패 처리 등 [[ADR-016]]의 나머지는 아무것도 건드리지 않는다.

**트레이드오프**:
- 계정이 1개인 대다수 사용자에게 온보딩 단계가 화면 하나만큼 늘어난다. 결정 3의 초기 하이라이트 덕분에 실제 조작은 "계속하기" 탭 1회다.
- 자동 확정 경로가 사라지면서 온보딩 `finalizeVerifiedAccounts`/설정 `finalizeAccounts`의 "확정 후 곧바로 예열" 분기도 함께 사라진다 — 예열 트리거가 `selectAccount` 한 곳으로 모이므로 두 store의 흐름이 단순해지는 부수 효과가 있다.

**저장소**: 스키마 변경 없음. 저장되는 값(`selectedAccountId`)도 동일하고, 저장 시점만 "검증 직후"에서 "사용자 확정 직후"로 옮겨간다.
