### ADR-229: **도메인과 정적 사이트를 Oracle 로 옮긴다.** 미니 PC 는 `/v1` 만 받는다 (2026-09-08, 사용자 지시)

> 🟡 **구현 완료** (2026-09-08). 결정 여섯이 다 섰다.
>
> 이전이 끝났다. `mapleroutine.store` 가 Oracle 을 가리키고 정적 5경로와 `/v1` 이 다 돈다.
> 인증서는 HTTP-01 자동 갱신으로 옮겼고 모의 갱신까지 확인했다.
>
> **터널이 섰고 집 공유기에 열린 서비스 포트가 0개다.** 그전에는 셋이 열려 있었다.
>
> **정정 1 이 결정 2 의 배포 방식을 바꿨다.** 인용 전에 문서 끝의 정정을 볼 것.

**배경**: [[ADR-228]] 결정 6 이 공지 목록·상세의 서버 조회를 남겨 뒀고, 그것이 **앱에서 서버로
가는 첫 요청**이라 [[ADR-227]] 결정 2 의 프록시 층이 여기서 처음 필요해진다. 같은 작업에
사용자가 하나를 더 얹었다. **GitHub Pages 에 있는 `mapleroutine.store` 를 우리 서버로 옮긴다.**

그 도메인에 걸려 있는 것이 넷이고, 셋은 **앱 기능이 아니다.**

| 경로 | 무엇이 걸려 있나 |
|---|---|
| `/privacy` | Play·App Store 에 **등록된** 개인정보 처리방침 URL |
| `/support` | 스토어 문의 URL |
| `/api-key` | 앱 안에서 여는 링크(`app/auth/api-key-links.ts` 의 `GUIDE_URL`) |
| `/app-ads.txt` | AdMob 판매 권한 선언. 못 읽으면 인벤토리가 미승인이 된다 |

**관련**: [[ADR-227]](서버를 들인 결정 · 이 문서가 결정 2 의 층을 실제로 세운다) ·
[[ADR-228]](공지 계약 · 결정 6 이 여기 붙는다) · [[ADR-110]](API 키 발급 가이드가 이 사이트에 있는 이유) · [[ADR-003]](어댑터 경계).
**문서**: `features/site.md` · `features/notifications.md` · `foundation/release.md`

### 결정 1. **정적 사이트는 Oracle 이 직접 서빙한다.** 미니 PC 를 안 거친다 (사용자 선택)

nginx 가 파일을 자기 디스크에서 읽어 낸다. 터널 너머로 안 넘긴다.

**이유는 가용성의 등급이 다르기 때문이다.** [[ADR-227]] 이 *"가용성이 집 회선을 탄다"* 를 대가로
적었지만 그것은 앱 **기능** 이야기였다. 위 표의 넷 중 셋은 기능이 아니라 **스토어 컴플라이언스와
광고 승인**이다. 처방침 URL 이 안 열리면 Play 가 등록정보를 문제 삼고, `app-ads.txt` 를 못 읽으면
AdMob 이 인벤토리를 미승인으로 본다. 정전 한 번이 그것을 만든다.

```
mapleroutine.store ──▶ Oracle 무료 등급 (nginx)
                         ├─ /privacy /support /api-key /app-ads.txt   디스크에서 직접
                         └─ /v1/…                    ──▶ 터널 ──▶ 집 미니 PC
```

**그래서 미니 PC 가 꺼져도 처방침과 `app-ads.txt` 는 열린다.** 공지 조회만 안 되고, 그것은
[[ADR-228]] 결정 4 가 이미 *"서버가 죽어도 받은 공지는 열린다"* 로 감당해 둔 자리다.

---

### 결정 2. **원본은 이 저장소에 남는다.** 바뀌는 것은 배포처 하나다

`site/` 와 루트의 `PRIVACY.md` 가 계속 원본이고 `scripts/build-site.mjs` 가 계속 `dist-site/` 를
만든다. GitHub Actions 도 계속 돈다. **`actions/deploy-pages` 자리에 Oracle 로 올리는 단계가
들어갈 뿐이다.**

사이트 소스를 서버 저장소로 옮기지 않는다. 이유 둘.

- **처방침의 원본이 하나여야 한다.** `PRIVACY.md` 는 앱 저장소 루트에 있고 빌드가 거기서 읽는다
  (`build-site.mjs` 가 그 이유를 적어 뒀다). 서버 저장소로 옮기면 법적 문서가 두 벌이 된다.
- **`app-ads.txt` 의 퍼블리셔 ID 가 네 곳과 맞아야 한다.** `AndroidManifest.xml` · `Info.plist` ·
  `native/ads.ts` 와 같은 계정이어야 하고 `native/__tests__/ads.test.ts` 가 그 드리프트를 잡는다.
  파일이 다른 저장소로 가면 그 테스트가 못 본다.

[[ADR-227]] 결정 3 이 *"서버 코드는 별도 저장소"* 라고 한 것과 어긋나지 않는다. **정적 사이트는
서버 코드가 아니라 이 앱의 산출물**이고, 서버는 그것을 서빙만 한다.

### 결정 3. Oracle 과 미니 PC 사이의 **전송은 WireGuard** 다

[[ADR-227]] 결정 2 가 정한 것은 **nginx** 였다. 그것은 Oracle 쪽에서 무엇이 요청을 받아 넘기는지
이고, **그 아래로 무엇이 흐르는지**는 안 정했다. 여기서 정한다.

**미니 PC 가 밖으로 걸어 나간다.** 집 공유기에 인바운드 포트를 열지 않는다. 열면 그 포트가 곧
집으로 들어오는 문이고, 가정용 회선 주소는 바뀌므로 Oracle 이 그 주소를 계속 쫓아야 한다.
WireGuard 는 미니 PC 가 Oracle 로 접속을 유지하므로 **Oracle 쪽에서 보면 주소가 고정**이다.

nginx 는 그 사설 주소로 `proxy_pass` 한다. `10.8.0.1` 이 Oracle 이고 `10.8.0.2` 가 미니 PC 다.

**구현하며 확인한 것 셋**(2026-09-08).

- **`PersistentKeepalive = 25` 가 없으면 안 된다.** 공유기의 NAT 는 조용한 통로를 일정 시간 뒤
  닫는다. 이 줄이 없으면 한동안 요청이 없다가 갑자기 안 붙는데, 그 실패는 재현이 어렵다.
- **`AllowedIPs` 를 `10.8.0.0/24` 로 좁힌다.** 미니 PC 쪽에서 이것을 넓게 잡으면 그 기계의
  인터넷 전체가 터널로 흐른다.
- **Oracle 은 방화벽이 두 겹이다.** 콘솔의 보안 목록과 인스턴스 안의 `ufw` 를 **둘 다** 열어야
  한다. 하나만 열면 조용히 안 붙는다.

**얻은 것이 셋인데 그중 하나는 예정에 없던 것이다.** 암호화와 열린 포트 0개는 이 결정이 노린
것이고, **집 공인 IP 가 바뀌어도 안 끊긴다**가 덤이다. 그전에는 `116.122.92.238` 이 nginx 에
박혀 있어서 가정용 회선 주소가 바뀌면 손으로 고쳐야 했다. 터널 안 주소는 안 바뀐다.

### 결정 4. **확인이 DNS 보다 먼저다.** 순서를 여기 못박는다

이 문서에서 순서를 틀리면 대가가 가장 큰 결정이다. DNS 를 먼저 돌리면 그 사이 **등록된 처방침
URL 이 죽는다.**

1. Oracle 에 nginx 를 세우고 사이트를 올린다. **도메인 없이 IP 로 먼저 연다.**
2. 네 경로를 IP 로 직접 때려 내용이 지금과 **같은지** 확인한다. 특히 `/app-ads.txt` 는 한 글자도
   달라지면 안 된다.
3. TLS 를 붙인다(결정 5).
4. **그다음에** DNS 를 Oracle 로 돌린다.
5. 전파를 기다려 네 경로를 도메인으로 다시 확인한다.
6. 확인이 끝난 뒤에 GitHub Pages 배포를 끈다.

**6번을 서두르지 않는다.** DNS 전파는 몇 시간이 걸리고 그동안 일부 사용자는 여전히 Pages 를 본다.
그쪽을 먼저 끄면 그 사용자들에게 사이트가 없어진다.

---

### 결정 5. TLS 는 **Let's Encrypt** 이고 Oracle 이 끝낸다

인증서는 Oracle 에 있고 nginx 가 거기서 복호화한다. 미니 PC 로 넘어가는 구간은 WireGuard 안이라
이미 암호화돼 있다.

**갱신 실패가 조용하면 안 된다.** 90일마다 도는 일이라 잊기 쉽고, 만료되면 앱의 서버 조회와
처방침이 **같은 날 함께** 죽는다. 갱신이 실패했을 때 우리가 알 방법을 함께 둔다.

---

### 결정 6. 앱은 조회 실패를 **화면 전체의 실패로 만들지 않는다**

[[ADR-228]] 결정 4·6 이 이미 정한 성질을 여기서 다시 못박는다. 목록 화면은 기기에 쌓인 것을 먼저
그리고, 서버 조회는 그 위에 얹는다. 조회가 실패하면 **로컬 것만 보인다.** 빈 화면이나 에러 화면이
아니다.

상세도 같다. 로컬에 있으면 그것을 그리고, 서버가 답하면 본문을 덮는다.

이것이 [[ADR-227]] 이 열린 질문으로 남긴 *"미니 PC 가 꺼져 있을 때 앱이 무엇을 보여주는가"* 의
공지 쪽 답이다. **아무것도 안 말한다.** 있는 것을 그대로 그린다. 수집 쪽은 아직 답이 없다.

## 대가

- **Oracle 무료 등급 위에 스토어 컴플라이언스가 올라간다.** GitHub Pages 보다 죽을 확률이 높고,
  무료 등급 정책은 우리가 못 정한다(유휴 인스턴스 회수 같은 것이 통보 하나로 온다).
- **TLS 갱신이 우리 일이 된다.** Pages 는 그것을 대신해 줬다.
- **배포가 SSH 를 탄다.** GitHub Actions 에 Oracle 접속 열쇠를 둬야 하고, 그 열쇠가 새면 서버가
  열린다.
- **DNS 이전 중에는 되돌리기가 느리다.** 전파가 양방향으로 몇 시간이다.

## 기각

- **정적 사이트도 미니 PC 가 서빙한다.** 결정 1. 정전이 곧 컴플라이언스 문제가 된다.
- **사이트 소스를 서버 저장소로 옮긴다.** 결정 2. 처방침이 두 벌이 되고 `app-ads.txt` 의 드리프트
  가드가 눈을 잃는다.
- **집 공유기에 포트를 연다.** 결정 3.
- **GitHub Pages 를 즉시 끈다.** 결정 4 의 6번.

## 열린 질문

- **배포를 무엇으로 하는가.** GitHub Actions 에서 `rsync` 인지 `scp` 인지, 열쇠를 어떻게 두는지.
- **TLS 갱신 실패를 어떻게 아는가.** 만료 전에 우리에게 닿는 길이 필요하다.
- **Oracle 인스턴스가 회수되면 무엇이 남는가.** 무료 등급의 유휴 회수 정책에 걸리지 않게 하는
  방법이 있는지, 걸렸을 때 복구가 몇 시간인지.
- **`/v1` 에 속도 제한을 어떻게 거는가.** 인증이 없어 누구나 부른다([[ADR-228]] 열린 질문).
- **목록을 언제 갱신하는가.** 화면에 들어갈 때마다인지 당겨서 새로고침인지.

## 정정 1. 배포는 **CI 가 아니라 손**이다 (2026-09-08)

결정 2 는 *"GitHub Actions 도 계속 돈다. `actions/deploy-pages` 자리에 Oracle 로 올리는 단계가
들어갈 뿐이다"* 라고 적었다. 그 자리를 `scripts/deploy-site.sh` 로 바꾼다.

**대가를 다시 보니 값이 안 맞는다.** 이 문서의 대가 항목이 *"GitHub Actions 에 Oracle 접속 열쇠를
둬야 하고, 그 열쇠가 새면 서버가 열린다"* 를 이미 적어 뒀다. 그런데 이 사이트가 바뀌는 것은
처방침을 고칠 때 정도이고 **1년에 몇 번**이다. 상시 열려 있는 열쇠를 그 빈도에 내주는 것이 맞지
않는다. 그 열쇠는 정적 사이트만이 아니라 **서버 전체**를 여는 것이기도 하다.

`npm run deploy:site` 가 빌드하고 `rsync` 로 올린 뒤 다섯 경로를 확인한다. 열쇠는 사람의
`~/.ssh` 에만 있다.

**자주 바뀌게 되면 그때 CI 로 옮긴다.** 그 판단의 기준은 편의가 아니라 빈도다.

## 정정 2. `CNAME` 과 `.nojekyll` 을 안 만든다 (2026-09-08)

둘 다 GitHub Pages 에게 하는 말이었다. nginx 는 도메인을 vhost 로 알고 Jekyll 을 안 돈다.

남겨 두면 `https://mapleroutine.store/CNAME` 로 **열린다.** 아무 뜻도 없는 파일이 공개되는 것이라
빌드에서 뺐다.
