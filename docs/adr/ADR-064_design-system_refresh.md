# ADR-064 당겨서 새로고침

> 🟢 유효
> 옛 번호: ADR-072 · ADR-130 · ADR-160 · ADR-218 결정 3 · ADR-226
> 관련 소스: `components/templates/ScreenScroll/` · `hooks/usePullRefresh.ts` · `features/refresh/progress.ts` · `features/ledger/useLedgerData.tsx` · `components/organisms/LoadingModal/`

## 배경

넥슨에서 받아 온 값이나 기기에 쌓인 기록을 다시 읽고 싶을 때, 사용자는 화면 맨 위에서 아래로
당긴다. 화면마다 따로 만들면 인디케이터 색이 하나쯤 빠지거나, 당기지 않았는데 인디케이터가 열리는
일이 화면마다 다르게 생긴다. 그래서 당김은 화면 스크롤 셸 `ScreenScroll` 한 곳에서 만든다.

## 결정

### 결정 1. 인디케이터는 RN 의 `RefreshControl` 을 그대로 쓴다

안드로이드 `ScrollView` 는 맨 위에서 더 당겨도 콘텐츠가 내려가지 않고 `contentOffset.y` 도 0 아래로
내려가지 않는다. 얼마나 당겼는지 알 수 없으니, 직접 그린 인디케이터를 쓰려면 스크롤 위에 제스처를
따로 얹고 맨 위 판정과 목록 이동을 다시 만들어야 한다. 그 비용이 커서 OS 인디케이터를 쓴다.

그래서 iOS 에서는 시스템 스피너가, 안드로이드에서는 원형 화살표가 보인다. 디자인은 고를 수 없고 색만
넘긴다. `tintColor`(iOS) · `colors`(안드로이드)에는 테마의 `primaryInk` 를, 안드로이드
`progressBackgroundColor` 에는 `surface` 를 준다. 인디케이터에는 문구가 없다.

### 결정 2. 화면은 `ScreenScroll` 에 `onRefresh` 함수만 준다

인디케이터를 만들고, 색을 입히고, 당긴 동안만 돌게 하는 일은 셸에서 처리한다. 화면이 직접 조립하면 같은
코드가 화면 수만큼 생기고, 그중 하나가 테마 색을 빠뜨려도 알아채기 어렵다. `onRefresh` 를 주지 않은
화면에는 당김이 없다. `onRefresh` 는 그 화면에 다시 읽을 것이 있을 때만 준다.

`RefreshControl` 은 `ScrollView` 의 프롭이라 제스처와 인디케이터가 스크롤 뷰 안에 있다. 그래서
내비게이터 쪽으로 올려 한 번에 걸 수는 없다.

모달이나 바텀시트 안에서 시작한 터치는 그쪽 스크롤 뷰가 받으므로 페이지 당김이 되지 않는다. 하위
페이지가 열려 있을 때도 아래 화면이 덮여 있어서 아래 화면의 당김이 일어나지 않는다. 둘 다 따로
막는 코드가 없다.

### 결정 3. 인디케이터는 사용자가 당긴 회차에만 돈다

`refreshing` 을 스토어의 `status === 'loading'` 에 묶으면 안 된다. 화면이 마운트될 때 하는 자동
조회도 같은 값을 `loading` 으로 바꾸기 때문에, 탭을 옮기기만 해도 인디케이터가 열리고 상단에 빈 띠가 생긴다.

그래서 `usePullRefresh` 가 화면마다 상태를 따로 둔다. 당기면 참으로 바꾸고, 넘겨받은 재조회
프라미스가 끝나면 성공이든 실패든 거짓으로 돌린다. 실패해도 닫지 않으면 상단이 빈 채로 멈추기
때문이다. 실패 자체는 이 훅이 알리지 않는다. 스토어에 `error` 가 들어오면 토스트가 알리므로, 여기서
또 알리면 같은 실패가 두 번 보인다.

상태를 스토어에 두지 않는 이유는 두 스케줄러가 같은 스토어를 함께 쓰기 때문이다. 스토어에 두면 한
화면에서 당겼을 때 다른 화면의 인디케이터도 열린다.

today 는 재조회가 넷이라 `Promise.allSettled` 로 묶어 넘긴다. 하나가 실패해도 나머지가 끝날 때까지
기다렸다가 인디케이터를 닫아야 하기 때문이다.

### 결정 4. 인디케이터를 상단 안전영역 페이드 아래로 내린다

`ScreenScroll` 은 상단 안전영역에서 콘텐츠가 투명해지도록 스크롤 영역을 `MaskedView` 로 감싼다
([[ADR-063]]). 인디케이터는 iOS 에서는 스크롤 뷰의 하위 뷰이고, 안드로이드에서는 `ScrollView` 를
감싼 `AndroidSwipeRefreshLayout` 안에 그려진다. 어느 쪽이든 마스크 안이라, 그대로 두면 페이드
구간에 같이 가려져 당겨도 보이지 않는다.

그래서 `progressViewOffset` 으로 인디케이터를 페이드 높이만큼 내린다. 내리는 양은
`resolvePullIndicatorOffset` 이 플랫폼마다 다르게 정한다.

| 플랫폼 | 내리는 양 | 이유 |
|---|---|---|
| iOS | 페이드 높이 | 인디케이터가 화면 맨 위에서 시작한다 |
| 안드로이드 | 페이드 높이 − 24, 0 미만이면 0 | 원이 오프셋 0 에서도 이미 24dp 내려와 멈춘다 |
| 상단 페이드가 없는 화면 | 0(프롭을 넘기지 않는다) | 가려질 일이 없다 |

안드로이드의 24 는 RN 이 원의 정지 위치를 `offset + 64 − 원 지름 40` 으로 잡기 때문에 나오는 값이다.
원 크기를 `large` 로 바꾸면 지름이 56 이 되므로 이 값도 함께 바꿔야 한다. 음수를 넘기면 원이 위로
올라가 다시 가려지므로 0 에서 멈춘다.

페이드를 끄는 방법은 쓰지 않았다. 당김이 있는 화면이 앱의 주요 화면이어서, 끄면 콘텐츠가 상태바
밑에서 딱 끊기는 문제가 그 화면들에 다시 생긴다.

### 결정 5. 무엇을 다시 받을지는 화면이 고른다

화면마다 당겨서 하는 일은 같고 부르는 API 만 다르다. 그래서 당김 연결은 `ScreenScroll` 한 곳에 두고
(결정 2), 화면은 자기가 다시 받을 것만 함수로 넘긴다. 보스 수익과 가계부는 같은 원장 데이터(`useLedgerData`)를 쓰므로
`reload(parts)` 에 받을 조각(`LedgerReloadPart`)을 골라 넘긴다.

| 부르는 곳 | 조각 |
|---|---|
| 원장 데이터 마운트 | `window` · `enhancement` |
| 보스 수익 당김 | `live` · `window` |
| 가계부 · 통계 당김 | `live` · `window` · `enhancement` |

보스 수익은 강화 기록을 쓰지 않아 당길 때 받지 않는다. `window` 는 두 화면 모두 받는다. 가계부의 보스
결정석 수익 줄이 그 표에서 오기 때문이다. 원장 데이터가 마운트될 때는 강화도 계속 받는다. 빼면 가계부를 처음 열 때
한 달치 수집이 그제야 시작되어 로딩 모달이 한 번 더 뜬다(사용자 지정).

today 는 새로고침이 끝난 뒤 대표 캐릭터 한 명의 프로필을 캐시에서 다시 읽는다. 새로 받은 경험치가
캐시에만 쓰이고 화면은 마운트 때 한 번만 읽기 때문이다. 대표 한 명만 읽는 이유는 저장소를 한 번 읽을 때마다
네이티브 호출이 한 번 일어나기 때문이다. 대표가 누구인지는 스토어 값을 따른다([[ADR-029]]).

### 결정 6. 진행률은 누구나 회차를 열 수 있고, 회차 수를 센다

`useRefreshProgress` 는 `beginRound()` 로 회차를 열고 돌려받은 함수로 닫는다. 회차 안에서는
`start(total)` 로 자기 몫을 열고 `advance` 로 진척을 올린다. 마지막 회차가 닫힐 때 몫을 한꺼번에
비운다. 한 몫이 끝날 때마다 비우면, 단계가 순서대로 실행되는 원장 갱신에서 앞 단계가 끝나는 순간 분모가
0 이 되어 바가 꺼졌다 켜진다.

- `syncSchedules` 는 진척을 직접 올린다. 실제 진행을 아는 곳이 그 함수뿐이라, 합류한 호출도 같은 값을 읽는다.
  다만 호출부가 `onProgress` 로 진행을 맡으면 자기 몫을 따로 열지 않는다. 맡는 쪽은 총량을 이미
  잡아 두었으므로, 도중에 몫이 늘면 바가 처음으로 되돌아간다.
- 원장 데이터 공급자(`useLedgerData`)는 라이브 · 창 · 강화 기록의 분모를 실행 전에 먼저 다 잡고 몫 셋을 연 뒤 실행한다. 그래서
  가계부의 바가 되돌아가지 않고 한 번에 찬다. 라이브의 분모는 추적 캐릭터 수로 추정하고, 실제 수가 오면 `advance` 가
  고친다. 안 고치면 바가 끝까지 차지 않는다.

### 결정 7. 그릴 것이 없을 때만 로딩 모달을 띄운다

today 와 원장 화면은 갱신 중에 `LoadingModal` 을 띄운다. 아직 그릴 것이 없을 때만 띄운다.
today 는 추적 캐릭터가 있고 스케줄 캐시가 하나도 없으며 회차가 진행 중일 때만 띄운다. 캐시가 있으면
캐시를 먼저 그리므로 띄우지 않는다. 두 모달 모두 400ms 가 지나야 나타난다. 짧은 회차마다 모달이
깜빡이지 않게 하기 위해서다. today 의 문구는 `체크리스트를 불러오고 있어요` 다.
