# ADR-104 — 테마 선택 모달을 프리뷰 타일 + 카테고리 섹션 + 모드 필터로 재설계한다

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-08-06
**상태**: **구현 완료**, 2026-08-06 — 테스트 2,471개 통과 · lint clean · 빌드(타입 포함) 통과 · 브라우저 실물 확인(설정 행에서 스와치 제거, 모달 섹션·필터·빈 섹션 감춤). **미verify: 실기기**
**채택 경위**: 시안 4종(A/B/C/D)과 라이트·다크 분리 3안을 `job-themes.json` 실제 색값으로 그려 비교한 뒤 사용자가 채택(2026-08-06). 첫 채택은 **D**(탭 + 분할 디스크)였다가 **B**(프리뷰 타일)로 바뀌었고, 그 뒤 "라이트·다크를 갈라 보여주는 건 어떤가"라는 물음에서 모드 필터(2안)가 붙었다
**관련**: [[ADR-009]](테마 시스템) · [[ADR-064]] 결정 10·11(레지스트리·스키마 테스트) · [[ADR-088]](배경 이미지) · [[ADR-018]](탭 토글 모양) · [[ADR-006]](게임 데이터는 사람이 확인) · 이슈 #140

## 맥락

테마 선택 모달은 **분류 없는 평평한 목록**이다. `ThemeSelector` 가 `THEME_NAMES` 를 그대로 `map` 해 한 줄씩 내고, 각 행은 `ThemeSwatchDots`(16px 원 3개) + 이름뿐이다. 표시 순서는 `job-themes.json` 의 키 순서이고, 레지스트리 주석이 그것을 규약으로 못박아 뒀다. 같은 `ThemeSwatchDots` 를 설정 화면 행(`SettingsScreen.tsx:66`)도 쓴다 — **바꾸면 두 자리가 같이 바뀐다.**

지금 6종이지만 목표는 **수십 종**이고([[ADR-009]]), 스키마·파생·등록 방식이 전부 그 전제로 서 있다. 그래서 이 결정의 기준은 "6종에서 예쁜가"가 아니라 "**늘어날 때 무엇이 먼저 무너지는가**"다.

### 시안을 그려서 알게 된 것

네 방향을 실제 색값·실제 모달 폭(358px)으로 그렸다. 길이는 "테마 하나가 먹는 세로"로 쟀다.

| | A 섹션 목록 | B 프리뷰 타일 | C 와이드 프리뷰 | D 탭 + 디스크 |
|---|---|---|---|---|
| 테마 1종 | 54px (1열) | 51px (2열) | 82px (1열) | 30px (3열) |
| 24종이면 | 약 1,350px | 약 1,290px | 약 2,030px | 약 780px |
| 라이트·다크 | 안 보임 | 그림으로 | 그림으로 | 글리프로만 |

- **"2열이니 길이가 절반"은 틀렸다.** 타일이 행의 두 배 높이라 B와 A는 사실상 같은 길이다. B를 고르는 이유는 길이가 아니라 **판단 속도**여야 한다.
- **배경 이미지를 목록에 쓰면 `dim` 이 하나 더 생긴다.** 앱의 값(혼테일 0.82 · 검은마법사 0.78)은 전체 화면에서 글자를 살리려는 값이라 74px 행이나 92px 타일에 그대로 덮으면 **그냥 검은 띠**다. 시안에서는 0.42로 낮추고 이름에 그림자를 줘야 그림이 보였다 — 즉 목록 노출은 그림 한 장이 아니라 **값 하나를 새로 관리하는 일**이다.

## 결정

### 결정 1 — 카테고리는 셋, 겹침은 없다

**기본 · 직업 · 보스** 세 개이고, 한 테마는 **한 카테고리에만** 속한다.

| 카테고리 | 테마 |
|---|---|
| 기본 | 머쉬맘 · 혼테일 |
| 직업 | 렌 · 엔젤릭버스터 · 레테 |
| 보스 | 검은마법사 |

소속은 게임 도메인이라 **사용자 확인으로 정했다**(2026-08-06, [[ADR-006]]) — AI 가 추정해 넣지 않는다. 머쉬맘·혼테일은 보스이기도 하지만 **앱의 기본 라이트/다크**라는 역할이 우선이라 기본에만 둔다.

겹침을 허용하면 `category` 가 배열이 되고 같은 테마가 목록에 두 번 나온다. 지금 필요한 최소는 **문자열 한 개**다. 그 대가로 보스 카테고리에는 검은마법사 하나만 남는데, 감추지 않고 그대로 둔다 — 보스 테마가 늘어날 자리이고, 섹션이 하나라고 틀린 정보를 주지는 않는다.

### 결정 2 — 목록은 2열 프리뷰 타일(시안 B)

타일 하나가 그 테마의 `bg` 위에 `surface`·`surface2`·`primary` 로 미니 화면을 그리고, 이름을 그 테마의 `text` 색으로 얹는다. 이름 옆 ☀/☾ 가 `mode` 다.

이름만 보고 고르던 것에서 벗어나는 것이 요점이다 — **"이걸 고르면 화면이 이렇게 된다"가 타일 안에 있다.** 라이트와 다크가 섞인 목록에서 특히 크게 작용한다. 길이 이득은 없다(위 표).

### 결정 3 — 카테고리는 섹션, 라이트·다크는 필터 칩

카테고리와 모드는 **서로 직교하는 축**이라 둘 다 섹션 제목이 될 수 없다. 카테고리가 제목 자리를 갖고(이슈의 요구), 모드는 목록 위 **필터 칩**이 된다.

- 칩은 **전체 · 라이트 · 다크**, 기본값은 **전체**.
- **필터 상태는 저장하지 않는다.** 모달을 닫으면 전체로 돌아온다 — 영속화하면 저장 스키마가 하나 늘고, 다음에 열었을 때 목록이 왜 짧은지 설명할 자리가 없다.
- **거른 결과가 0인 카테고리 섹션은 헤더째 감춘다.** 빈 제목만 남는 것을 막는다.
- **현재 선택된 테마가 필터에서 빠지는 것은 정상으로 둔다** — 라이트를 보는 중에 다크를 쓰고 있을 수 있다.
- 칩 모양은 새로 만들지 않고 `design-system.md` 「탭 토글」([[ADR-018]])을 그대로 쓴다 — 활성 `rounded-full bg-primary-tint text-primary-ink`, 비활성 `text-text-muted`.

반려된 두 대안: **정렬만**(섹션 안에서 라이트 먼저)은 공짜지만 "다크만 보기"를 못 하고, **모드를 섹션으로** 올리면 이슈가 요구한 분류가 제목 자리에서 밀려나며 직업 테마가 수십 종이 됐을 때 라이트 섹션 하나가 그 전부를 담아 다시 평평해진다.

### 결정 4 — 배경 이미지는 목록에 노출하지 않는다

타일은 **색만** 쓴다. 그림을 넣으면 모달 열 때 이미지 2장이 함께 로드되고, 맥락에서 적은 대로 **썸네일용 `dim` 값이 새로 생긴다**. 배경은 테마를 적용한 뒤 화면 전체로 보는 것이 원래 자리다([[ADR-088]]). 이 결정이 시안 C(와이드 프리뷰 행)를 탈락시켰다.

### 결정 5 — 설정 화면 행에서 대표 컬러를 없앤다

행에는 **테마 이름 배지만** 남는다. 어떤 테마인지는 이름이 말하고, 그 색은 지금 눈앞의 화면 전체가 이미 말하고 있다.

그 결과 `ThemeSwatchDots` 는 **사용처가 0이 되어 컴포넌트·테스트째 삭제**한다(모달 쪽은 타일이 대신한다). "공유 컴포넌트라 두 자리가 같이 바뀐다"는 이슈의 우려는, 한쪽을 없애는 것으로 풀린다.

### 결정 6 — "JSON 키 순서 = 표시 순서" 규약을 바꾼다

새 규약은 **카테고리 순서(기본 → 직업 → 보스) → 그 안에서 JSON 키 순서**다. `theme-registry.ts` 의 주석과 `THEME_NAMES` 파생을 함께 고친다. 카테고리 순서는 데이터가 아니라 **프로덕트 결정**이라 `DEFAULT_THEME` 과 같은 자리(레지스트리)에 상수로 둔다 — JSON 에 순서 번호를 넣으면 테마를 추가할 때마다 번호를 다시 매기게 된다.

테마 추가가 **JSON 한 블록**이라는 성질([[ADR-064]] 결정 10)은 유지된다. 블록에 `category` 한 줄이 늘 뿐이다.

### 결정 7 — 테마를 고른다고 모달이 닫히지 않는다

적용은 **여전히 즉시**다(고르는 순간 `selectTheme`). 달라지는 것은 **닫기가 따라오지 않는다**는 것뿐이고, 닫기는 새로 다는 **"완료"** 버튼과 오버레이 탭이 맡는다.

프리뷰 타일을 넣은 이 화면에서 특히 맞는 동작이다 — 모달 자신이 선택 테마의 색으로 그려지므로, 닫지 않으면 **고르는 자리에서 그대로 갈아입혀 본다**(칩·헤더·타일 링이 그 자리에서 바뀐다). 전에는 한 번 고를 때마다 모달이 닫혀서, 두 개를 비교하려면 설정 행 → 모달을 다시 여는 왕복이 필요했다.

버튼은 하나다. `TrackingModeModal` 의 취소/적용 2단계([[ADR-035]] 결정 23)를 따르지 않는 이유는 **되돌릴 것이 없기 때문**이다 — 그쪽은 고르는 것과 적용하는 것이 분리돼 "취소"에 뜻이 있지만, 테마는 이미 적용돼 있어 취소할 대상이 없다. 골격(`mt-4 flex justify-end`)과 `Button` 은 그대로 공유한다.

## 트레이드오프

| 얻는 것 | 잃는 것 |
|---|---|
| 고를 때 이름이 아니라 **화면을 본다** — 라이트/다크가 섞인 목록에서 특히 | 타일이 행보다 두 배 높아 목록 길이는 줄지 않는다. 밀도가 목적이면 D(30px)가 맞았다 |
| 카테고리와 모드 두 축이 중첩 없이 산다 — 섹션 하나, 필터 하나 | 필터 상태(UI 상태 하나)가 새로 생기고, "0이면 섹션을 감춘다"는 규칙을 테스트가 지켜야 한다 |
| 지금 6종에서 다크를 누르면 섹션마다 한 장씩만 남아 **성겨 보인다** — 테마가 늘면 해소되는, 지금만의 어색함이다 |
| 설정 행이 단순해지고 공유 컴포넌트 하나가 사라진다 | 행에서 색을 미리 보던 것이 없어진다(그 자리에서 테마를 비교하던 사용법이 있었다면 잃는다) |
| 고른 뒤에도 모달이 남아 그 자리에서 여러 테마를 갈아입혀 본다(결정 7) | 닫는 동작이 한 번 더 필요해진다 — 한 번 고르고 끝내는 사람에게는 탭이 하나 늘어난다 |
| 배경 이미지 관련 값·로드가 모달에 들어오지 않는다 | 배경을 가진 테마가 목록에서 다른 테마와 똑같아 보인다 |

## 검증

테마가 늘어도 테스트가 늘지 않게, **값이 아니라 스키마·규칙**을 단언한다([[ADR-064]] 결정 11 방식).

| 항목 | 방법 |
|---|---|
| 모든 테마가 `category` 를 갖고 세 값 중 하나다 | `theme-registry` 스키마 테스트 — 테마 목록을 순회한다(이름 나열 금지) |
| 섹션이 기본 → 직업 → 보스 순으로, 그 안은 JSON 키 순서로 나온다 | 그룹핑 함수 단위 테스트 |
| 기본 필터는 전체다 | `ThemeSelector` — 6종이 모두 보인다 |
| 다크 필터가 라이트 테마를 감춘다 | `ThemeSelector` — 라이트 테마 이름이 사라진다 |
| 거른 결과가 0인 섹션은 헤더도 사라진다 | `ThemeSelector` — 다크 필터에서 항목 0이 되는 카테고리 헤더 부재 |
| 선택 계약은 그대로다 | 기존 `ThemeSelector` 테스트(`aria-pressed`·`onSelect`)를 타일 구조에서 유지 |
| 설정 행에 색 표식이 없다 | `SettingsScreen` — 스와치 testid 0건 |
| 모달이 배경 이미지를 로드하지 않는다 | `ThemeSelector` — 타일에 `background-image` 없음 |
| 테마를 골라도 모달이 안 닫힌다 | `ThemeModal` — 선택 후 `selectTheme` 는 불리고 `onClose` 는 안 불린다 |
| "완료"와 오버레이 탭이 닫는다 | `ThemeModal` — 각각 `onClose` 1회 |

## 미결

- **직업 테마의 단위**(직업 대분류인가 5차 전직 세부인가)는 여전히 미정이다 — `theme.md` 의 열린 질문으로 남는다. 이 ADR 은 그 답에 의존하지 않는다(어느 쪽이든 `category: "직업"` 이다).
- 보스 카테고리가 1종인 상태. 감추는 규칙은 **0일 때만** 적용한다.
