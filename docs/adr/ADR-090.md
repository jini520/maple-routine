# ADR-090 — 광고 도입: 탭 전환 전면광고 + 3중 노출 게이트

**날짜**: 2026-08-03
**상태**: 구현 완료 (실 광고 ID 반영 2026-08-04 · **스토어 미게시라 노출 제한** · 실기기 미검증)
**관련**: [[ADR-005]](네이티브 어댑터 레이어) · [[ADR-003]](로컬 전용·계정 없음) · [[ADR-007]](넥슨 약관·출처 표기) · [[ADR-013]](탭 구조) · [[ADR-022]](OTA 수동 체크) · 이슈 #58

## 맥락

이슈 #58은 "테마 기본/프리미엄 구분 + 인앱 결제"로 열렸지만, 검토 과정에서 범위가 네 번
바뀌었고 **최종은 "판매 상품 없음, 광고만"** 이다. 경위를 남겨야 이 문서가 왜 IAP·구독을
다루지 않는지 알 수 있다.

1. 테마 유료 판매 → 사용자가 "파는 건 광고 제거지 테마가 아니다"로 정정
2. 광고 제거 **구독** + 테마는 무료 리워드 → 넥슨 약관 검토 후 구독 철회
3. **후원 페이지**로 받고 후원자에게 광고 제거·테마 해제 → 리워드가 붙으면 스토어가 후원이
   아니라 인앱 구매로 분류(Google Play가 *"ad-free version of an app"* 을 Play Billing 필수
   예시로 명시 / Apple 3.2.1(vii) *"connected to or associated at any point in time with
   receiving digital content or services must use in-app purchase"*)
4. **광고만** — 판매 상품 없음

### 넥슨 약관 검토 결과

두 문서가 걸린다.

- **API 이용약관 제6조⑥** — API로 얻은 데이터·저작물을 "회사의 승낙 없이 영리 목적으로 이용"
  금지. **광고만 달아도 해당한다.** 승낙으로 해소되는 조항이다.
- **게임IP 사용 가이드**(2024-09-13) — "UGC를 영리적인 용도로 사용하는 것은 허용되지 않습니다",
  단 **"무료 콘텐츠 플랫폼에 게재하여 광고 및 후원금 수익을 얻을 수 있습니다"** 가 명시적 예외다.
  가이드가 스스로 정의한 UGC는 "게임굿즈·게임영상·팬아트·팬소설 등 2차 창작물"이라, API 기반
  유틸리티 앱이 여기 해당하는지는 문서만으로 판단할 수 없다.

**선례 조사(2026-08-03)** 가 판단을 갈랐다. 동종 서비스가 광고를 달고 운영 중이다.

| 서비스 | 푸터 | 비고 |
|---|---|---|
| maplescouter.com | "**MAPLESTORY PARTNERS** \| Data Based on NEXON OPEN API. Maplescouter is not associated with NEXON Korea and does not provide any warranty." | 후원 페이지(`/ko/donate`) 운영 |
| maple.gg | "Maple.GG is not associated with NEXON Korea. Data based on NEXON Open API." (Hosted by PlayXP Inc.) | 파트너스 표기 없음 |
| chuchu.gg | "This site is not associated with NEXON Korea. Data based on NEXON OpenAPI." | 파트너스 표기 없음 |

셋 다 **게임 애셋 이미지를 광범위하게 쓴다** — 이 앱도 마찬가지다(`src/assets/` 312개: 보스
초상화 36 · 아이템 아이콘 99 · 맵 24 · 월드 15 · 테마 배경 2). 즉 게임 애셋 사용은 이 앱만의
특수 리스크가 아니라 **이 카테고리의 공통 전제**이고, 테마 배경 2장만 오리지널 아트로 교체하는
완화책은 나머지 310개가 남는 한 의미가 없다(초안에서 제안했다가 철회).

**결론**: 광고 게재는 선례가 충분해 실무 리스크가 낮다고 보고 진행한다. 파트너스 신청은
사용자 결정으로 이번 범위에서 제외한다.

**함께 반영**: 3사 공통 관행인 **비제휴 고지**가 이 앱에만 없어 설정 footer에 추가했다
([settings.md](../features/settings.md) footer 표기).

## 결정

### 1. AdMob 네이티브 SDK 경로 — 웹 광고는 정책상 불가

"Capacitor 플러그인 말고 WebView에 웹 광고를 붙이면 안 되나"를 검토했고, **막힌다.**

AdSense 프로그램 정책 "Ad placement" 조항이 금지 배치로 이렇게 적는다:

> "Integrated into a software application **(does not apply to AdMob)** of any kind, including
> toolbars."

괄호가 답이다 — 소프트웨어 애플리케이션에는 AdMob을 쓰라는 뜻이고, Capacitor 앱은 스토어에
배포되는 소프트웨어 애플리케이션이다. 덧붙여 Google 광고 스크립트는 User-Agent·DOM 속성으로
WebView 환경을 감지해 렌더링을 억제한다(invalid traffic 방지). 붙여도 안 나올 수 있다.

`WebView API for Ads`(`registerWebView`)는 예외 통로가 아니다 — **인앱 브라우저**(앱이 외부 웹
페이지를 띄우는 프레임)의 광고에 앱 시그널을 전달하는 API이고, 앱 자체 UI가 WebView인 하이브리드
프레임워크는 구글 문서가 다루지 않는다.

위반 대가가 비대칭이라는 점도 근거다. AdSense와 AdMob은 결제 계정 체계를 공유해서,
**AdSense가 막히면 AdMob 경로까지 같이 죽는다.**

### 2. 포맷은 **Interstitial**, 지점은 **탭 전환**

사용자 요구는 "전면광고"이고 "배너는 넣지 말 것"이다. 그 제약 아래 정책이 허용하는 자리를
찾은 결과다.

**App Open이 먼저 탈락했다 — 정책이 아니라 플러그인 때문이다.** 앱 시작 팝업에는 App Open이
정확한 포맷이지만(앱 시작 Interstitial은 금지, 아래), **배포판에 구현이 없다.**

| 플러그인 | App Open | 주간 다운로드 |
|---|---|---|
| `@capacitor-community/admob` 8.0.0 | ❌ (`main`에 2026-04-10 머지됐으나 **미배포**, 마지막 릴리스 2025-12-27) | 41,520 |
| `@capgo/capacitor-admob` 8.1.13 | ❌ | — |
| `capacitor-admob-nextgen` 1.0.9 | ✅ | **333** |

`main`에서 직접 설치하는 것도 안 된다 — `prepare` 스크립트가 빌드가 아니라 `husky`라 git 설치
시 `dist/` 가 생성되지 않는다. 남은 길은 주간 333 다운로드짜리 플러그인을 쓰거나 주류 플러그인을
포크·빌드해 벤더링하는 것인데, **사용자가 그 의존성 리스크를 지지 않기로 했다.**

**앱 시작 Interstitial은 정책이 명시적으로 금지한다.**

> "**Do not place interstitial ads on app load** and when exiting apps as interstitials should
> only be placed in between pages of app content."

**그래서 탭 전환이다.** `/content` ↔ `/boss` ↔ `/profit` ↔ `/settings` 이동은 정책이 허용 예시로
든 "between pages of app content"에 정확히 해당한다([[ADR-013]] 탭 구조).

여기서 오해하기 쉬운 지점을 명시해 둔다 — **위반은 "지점"이 아니라 "빈도"다.**

> "Examples of non-compliant implementations include...: Placing an interstitial ad
> **after every user action**, including but not limited to clicks, swipes, etc."

즉 "탭 전환**마다**"가 위반이지 "탭 전환**에**"가 위반이 아니다. 그래서 결정 3의 게이트가
설계의 본체가 된다. (초안에서 탭 전환을 "너무 잦음"으로 뭉뚱그려 기각했던 것은 부정확했다.)

**하단 배너는 채택하지 않는다**(사용자 결정). 정책상으로는 가장 안전하고 노출도 가장 많지만,
하단 탭바와 세로 공간이 2겹이 된다.

**관리 화면 이탈 지점**(`/content/manage`→`/content`)도 정책상 안전한 후보였으나 기각했다 —
추적 목록은 처음 설정하고 나면 몇 주에 한 번 열까 말까라 노출이 사실상 0에 수렴한다.

### 3. 노출 게이트 3중 — 이게 정책 준수의 본체다

세 조건을 **모두** 만족할 때만 띄운다.

| 게이트 | 값 | 이유 |
|---|---|---|
| 마지막 노출로부터 경과 | `AD_MIN_INTERVAL_MS` = **30분** | "every user action" 금지를 넘기는 장치. 사용자 결정 |
| 앱 시작으로부터 경과 | `AD_MIN_UPTIME_MS` = **60초** | 앱을 열자마자 탭을 누르면 실행 2~3초 뒤 광고가 뜨는데, 이는 **"app load 시 전면광고"로 읽힌다** — 금지 조항에 걸리는 모습이 된다 |
| 사전 로드 완료 | 준비된 광고가 있을 때만 | 탭을 누른 뒤 요청하면 왕복 동안 화면이 이미 바뀌고 그 위를 광고가 덮는다 = **"콘텐츠를 보는 중 갑자기 뜨는"** 위반 형태. 준비된 게 없으면 **조용히 건너뛴다** |

**"준비된 광고가 없으면 건너뛴다"가 핵심이다.** 광고를 기다리느라 화면 전환을 지연시키지
않는다 — 네비게이션은 광고 상태와 무관하게 즉시 수행하고, 광고는 그 위에 얹힐 뿐이다.

**스플래시 시퀀스는 건드리지 않는다.** 앱 시작에 광고를 띄우지 않게 되면서 초안의 `AD_BUDGET_MS`
(스플래시를 붙잡고 광고 로드를 기다리는 예산)가 통째로 불필요해졌다. `App.tsx` 의
`MIN_SPLASH_MS` 흐름과 `native/splash-screen.ts` 는 무변경이다.

**마지막 노출 시각은 영속 저장한다** — 앱 재시작을 넘어야 하므로 메모리로는 부족하다.
`storage/ads.ts` + Preferences([[ADR-003]] 레이어 규칙). **`KEEP_KEYS`에는 넣지 않는다** —
캐시 삭제로 지워져도 광고가 한 번 더 뜨는 것뿐이라 무해하고, 보존할 사용자 자산이 아니다.

### 4. 어댑터 레이어 `native/ads.ts` — 웹 스텁 포함

CLAUDE.md 아키텍처 규칙과 [[ADR-005]] 그대로다. `features/*`·`app/*` 에서 AdMob 플러그인을
직접 import하지 않는다.

`npm run dev`는 브라우저에서 돌고 AdMob은 네이티브 전용이라 **웹에서는 no-op 스텁**이어야 한다
(`native/splash-screen.ts`가 `Capacitor.getPlatform() === 'web'` 으로 가드하는 것과 같은 패턴).
스텁이 없으면 개발 서버가 부팅 중 죽는다.

플러그인이 "로드됐는지" 조회하는 API를 주지 않으므로(`prepareInterstitial`/`showInterstitial`
두 개뿐) **어댑터가 준비 상태를 자체 플래그로 들고 있는다** — `prepareInterstitial` 이 resolve
하면 준비됨, 표시하면 소진. 판정 로직은 `features/ads/policy.ts` 의 순수 함수로 분리해
테스트한다.

광고 단위 ID는 플랫폼별로 다르므로 어댑터가 갈라 쓴다 — AdMob이 Android·iOS를 **별개 앱으로
등록**하기 때문이고, 한쪽 ID를 양쪽에 쓰면 정책 위반이다.

**테스트 광고 여부는 빌드 시점 환경 변수로 가른다** — `npm run build` 는 실 광고,
`build:test-ads`(`VITE_ADS_TEST=1`)와 `build:beta` 는 테스트 광고다. 실 ID로 자기 광고를 누르면
무효 트래픽으로 **계정이 정지**될 수 있고 되돌리기가 매우 어렵다.

**`import.meta.env.DEV` 로 가르려던 초안은 아무것도 막지 못했다**(2026-08-04 수정). Vite가
`vite build` 산출물에서 그 값을 **항상 `false`** 로 치환하는데, Capacitor 앱은 개발 중에도
**언제나 빌드된 번들**로 돌기 때문이다 — 실기기 테스트 빌드에 실 광고가 나가고 있었다. `DEV` 가
`true` 인 곳은 브라우저(`npm run dev`)뿐이고 거기선 플랫폼이 `web` 이라 어댑터가 no-op 이다.
프로덕션 번들에서 `getPlatform(), !1` 로 치환된 것을 실제로 확인해 잡았고, 판정은 순수 함수
`shouldUseTestAds(env)` 로 분리해 테스트한다.

ID가 **세 곳**(어댑터 · `AndroidManifest.xml` · `Info.plist`)에 흩어져 있는데 **틀려도 화면에는
아무 증상이 없다** — 테스트 ID가 남으면 광고는 뜨는데 수익만 0이고, 앱 ID가 샘플로 남으면 SDK가
초기화에서 죽는다. 그래서 `native/__tests__/ads.test.ts` 가 세 파일을 모두 읽어 드리프트를 잡고,
ID 선택은 순수 함수 `resolveInterstitialAdId(platform, isDev)` 로 분리해 테스트 가능하게 뒀다.

**스토어 미게시 상태에서는 노출이 제한된다** — AdMob은 미게시 앱에 *"limited ad serving"* 을
적용하고, 스토어 게시 → AdMob에서 앱 연결 → 검토(2~3일)를 거쳐야 정상 노출된다. 실 ID를 넣고도
광고가 안 뜨는 것은 이 단계 때문이지 구현 결함이 아니다.

### 5. 스토어·법적 부수 요건

광고가 붙으면 코드 밖에서 따라오는 것들이다.

| 항목 | 상태 |
|---|---|
| 개인정보 처리방침 | ✅ `PRIVACY.md` 작성 + `mapleroutine.store/privacy` 게시(2026-08-04, [site.md](../features/site.md)) |
| AdMob 앱 등록 + 광고 단위 ID | ✅ Android·iOS 각각 등록·반영(2026-08-04) |
| `app-ads.txt` 게시 | ✅ `site/app-ads.txt` → `mapleroutine.store/app-ads.txt`(2026-08-07). AdMob이 스토어 등록정보의 개발자 웹사이트 URL을 통해 찾아온다 |
| Android `AD_ID` 권한 · `APPLICATION_ID` 메타데이터 | ✅ |
| iOS `GADApplicationIdentifier` | ✅ |
| **스토어 게시 + AdMob 앱 연결·검토** | ⏳ iOS 게시 완료(2026-08-06) → **AdMob 콘솔 연결·검토가 남았다.** Play 미게시 |
| Play 데이터 안전 섹션 · "광고 포함" 설문 | ❌ |
| iOS ATT(`NSUserTrackingUsageDescription`) | ❌ 개인화 광고를 쓸 경우 |
| 배포 | AdMob 플러그인은 네이티브라 **OTA로 못 보낸다** — 새 바이너리 + 스토어 출시 필요 |

## 열린 질문

- `AD_MIN_INTERVAL_MS` 30분 · `AD_MIN_UPTIME_MS` 60초의 적정값 — 실사용 후 조정
- 사전 로드 실패율이 높아 "거의 안 뜨는" 상태가 되면 포맷·지점 재검토
- 넥슨 파트너스 신청 — 범위 제외됐으나, 승인받으면 광고 제거 유료 판매가 열린다

## 폐기된 대안

- ~~AdSense/GPT 웹 태그를 WebView에 삽입~~ → AdSense "Ad placement" 조항이 소프트웨어
  애플리케이션 통합을 금지(결정 1)
- ~~**App Open 광고 + 스플래시 시퀀스 통합**(`AD_BUDGET_MS` 2500ms 하드 실링)~~ → 정책상으로는
  가장 정확한 포맷이었으나 **배포판 플러그인에 구현이 없다**(결정 2). 되살리려면
  `capacitor-admob-nextgen`(주간 333) 또는 community 플러그인 벤더링이 선행돼야 한다
- ~~컨텐츠 카드 사이 인라인 광고~~ → 플러그인 미지원 + 배너가 WebView 위 네이티브 뷰라 구조적 불가
