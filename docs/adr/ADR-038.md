### ADR-038: 보스 수익(주간) — 드롭 아이템 기록(바텀시트·랜덤 상자 드릴다운), `lib/item-icons` 구현, 고가 아이템 드롭 연출 (구현 완료 2026-07-26)

> 🟡 **PARTIALLY SUPERSEDED — 일부 폐기.** 시트 구현은 [[ADR-039]]→RN `@gorhom/bottom-sheet`, fps 는 [[ADR-103]] 이 대체.
> 나머지 결정은 유효하다 — 인용 전 본문에서 해당 결정 번호를 확인할 것.

**배경**: [[ADR-010]]·[[ADR-011]]이 설계하고 [[ADR-032]] 결정 4가 "이번 범위 밖(placeholder 표시까지만)"으로 미뤄둔 물욕 아이템 드롭 입력(핵심 기능 5)을 구현한다. 사용자 확정(2026-07-26): ① 이번엔 **기록만**(시세 반영이 최종 목표이나 시세 갱신 소스가 미정 — 크롤링 유력), ② 드롭 기록·랜덤 상자·연출을 **한 번에** 구현, ③ 수정이 잦을 수 있어 **수정 용이성 우선**, ④ 이펙트 **최적화본만 커밋**. 추가로 [[ADR-011]] 결정 6이 이름만 정하고 미구현으로 남긴 `lib/item-icons`를 이번에 실제로 만든다. "고가 아이템 드롭 시 전체화면 연출"은 이 ADR에서 신규 도입한다(와이어프레임 시안으로 상호작용·타이밍·에셋 기법을 먼저 확정).

**결정**:
1. **진입·UI(기록만)**: 보스 수익 주간 화면에서 **보스 행을 탭하면 바텀시트**가 올라와 그 보스의 드롭 후보(`item-drop-table.json`의 `boss`+`difficulty` 기준, `고정`/`장비`/`소비` 3분류 그대로)를 아이콘 그리드로 보여주고, 실제 획득 아이템을 탭으로 토글해 기록한다. **이번 구현은 수익 합계에 반영하지 않는다(기록만)** — 단 **시세 반영이 최종 목표**다: 아이템 가치가 계속 변하므로 시세를 지속적으로 업데이트해 반영할 예정이며(갱신 방식 미정, 크롤링 유력), [[ADR-010]] 결정 1의 방향을 유지한다. 지금 record-only인 이유는 시세 소스가 아직 없어서일 뿐이므로, **레코드는 나중에 재평가 가능한 형태**(아이템명·카테고리·상자 개봉 결과·수량)로 저장하고 **가격은 별도의 갱신 가능한 소스로 분리**해(향후 크롤링 대상) 읽기 시점에 붙인다. 즉 record-only는 종착이 아니라 시세 소스가 붙기 전 단계다.
2. **랜덤 상자 결과 지정(2단계 드릴다운)**: `보스 반지 상자`·`칠흑 장신구 상자`는 개봉 결과가 랜덤이므로, 시트에서 상자 타일을 탭하면 **같은 시트 안에서 드릴다운**(뒤로가기 있는 2단계)으로 실제 나온 결과를 직접 선택한다 — 반지 상자는 **등급(상자별 `levelProbabilities`) + 반지 종류(`itemProbabilities`)** 2축, 칠흑 장신구 상자는 **후보 7종 1축**(`accessory-boxes.json`). [[ADR-010]] 결정 2 재확인: 확률로 자동 추정하지 않고 사용자가 직접 선택하며, 상자가 아니라 **개봉 결과(반지 레벨+종류 / 장신구 종류)를 기록**한다. 반지 목록·등급 범위는 상자마다 다르므로(녹옥·홍옥 31종 / 흑옥·백옥 11종 / 생명 10종) 탭한 상자의 목록만 로드한다.
3. **행 결과 표시**: 접힌 보스 행의 **이름 라인 오른쪽(메소 라인 위)**에 획득 드롭을 아이콘 스택+개수(`+N`)로 요약하고, 없으면 `＋ 드롭 추가` 칩으로 유도한다. 상자 결과는 상자가 아니라 **실제 나온 아이템(반지 등) 아이콘**으로 표시한다.
4. **`lib/item-icons` 구현**([[ADR-011]] 결정 6): `lib/boss-icons.ts` 패턴을 미러해 `getItemIconUrl(name, slot?)`을 만든다. `import.meta.glob('../assets/items/*.{png,webp}')` + `.../items/rings/*.{png,webp}`를 `{ eager:true, import:'default' }`로 모아 **`iconFile` 전체 파일명**을 키(NFC 정규화)로 조회하고, `item-icons.json`(일반 아이템 `iconFile`/`iconFileBySlot`)·`boss-ring-boxes.json`(반지, `rings/`)의 매핑을 사용, 없으면 placeholder. (ADR-011의 "링 접미사 휴리스틱"보다 `iconFile` 직접 조회가 단순·정확해 그쪽으로 확정.)
5. **저장(어댑터 경유)**: 신규 `boss_drop_records` 테이블을 기존 `boss_profit` DB에 추가(`CREATE TABLE IF NOT EXISTS`를 `storage/sqlite/db.ts` `openBossProfitDb`에, DB 버전 범프 없음). 키는 `(ocid, boss, difficulty, period_key)`. 신규 `storage/boss-drops.ts` 어댑터는 `storage/boss-profit.ts`를 미러(upsert/get). 스토어 드롭 액션은 `setPartySize` 패턴을 그대로 따른다 — upsert 후 `rows`와 **`latestSyncSnapshot`을 이중 갱신**([[ADR-032]] 결정 3, 누락 시 탭 전환에 되돌아감), `requestGeneration` 주의. `features/*`는 직접 storage 접근 금지, 어댑터만 사용([[ADR-003]]). **스키마는 수정 용이성 우선**(사용자 요청) — 한 보스에 드롭이 여럿이라 PK에 `drop_index`를 더한 **다중 행**(아이템 단위 추가/삭제/재평가가 쉬움)으로 저장하고, **계산된 금액은 레코드에 넣지 않는다**(시세가 바뀌면 과거 기록까지 재평가돼야 하므로 가격은 별도 소스에서 조인 — [[ADR-006]] "가격은 별도 관리"와 동일). 레코드엔 아이템명·카테고리·상자 출처·반지 레벨/종류·수량 등 **재평가에 필요한 구조화 데이터**만 담는다.
6. **타입**: `types/drops.ts` 신규(`DropCategory`를 `as const` 유니온으로, `DropItem`, `BoxResult`) + `index.ts` 재노출. DB row 타입(`BossDropRecord`)은 기존 컨벤션대로 `storage/boss-drops.ts` 옆에 둔다.
7. **컴포넌트**: `components/BottomSheet/`·`components/DropEffectOverlay/` 신규, 둘 다 `createPortal(document.body)`(Modal 패턴 미러), `lib/swipe-dismiss.ts`·`lib/use-body-scroll-lock.ts` 재사용, z는 오버레이 관례상 `z-[60]` 이상.
8. **고가 아이템 드롭 연출(신규)**: 고가 아이템 획득 시 **전체화면 연출** — backdrop(불투명 어둠) + 중앙 아이템 + `ScreenEff`(18fps 1회, `object-fit:cover`로 화면 채움) + **ScreenEff 8프레임 시점에 아이템 등장 + `DropEff`**(pre 16fps → loop 8fps ∞, 아이템 하단 기준 상승) 병렬, **화면 탭 시 `end`(14fps) 1회 후 종료**. 프레임은 `import.meta.glob`으로 조회(파일명 숫자 정렬 주의: `10` < `2` 렉시코 정렬 함정).
9. **이펙트 에셋 최적화**: 원본 `src/assets/ScreenEff/**`는 29MB(ScreenEff 25MB)로 앱 바이너리·OTA 매니페스트에 과대([[ADR-022]] — OTA 매니페스트 `size`는 사용자 승인 대상). **검은 배경 합성 + black-crush(JPEG로 뜬 검정을 순수 `#000`으로 눌러 `screen` 블렌드 사각 박스 아티팩트 제거) + JPEG + `mix-blend-mode:screen`(빛만 가산 합성)**으로 ~2MB로 경량화하면서 해상도·선명도는 오히려 높인다. 이 기법을 실제 앱 에셋 파이프라인으로 채택한다. **원본 PNG 시퀀스(29MB)는 저장소에 커밋하지 않고 최적화본(JPEG)만 커밋한다**(사용자 요청) — 원본은 로컬 전처리 입력일 뿐이라 저장소에서 제외(`.gitignore` 또는 미추가).
10. **고가 아이템 리스트(1차 확정, 2026-07-26)**: 연출 발동 대상을 신규 `src/data/valuable-drops.json`으로 판별한다. **수정 용이성**을 위해 개별 이름 나열이 아니라 **세트명 + 개별명** 기준으로 정의한다 — 세트 `칠흑의 보스 세트`·`광휘의 보스 세트`(`item-drop-table.json`의 `set` 필드 매칭) + 개별 아이템 `생명의 연마석`·`신념의 연마석`·`혼돈의 칠흑 장신구 상자`·`메이린의 칠흑 장신구 상자`. 세트/이름 목록만 고치면 대상이 바뀌므로 편집이 쉽다(사용자 지시 "일단 칠흑 장신구·광휘 장신구·연마석 2종·칠흑 장신구 상자만"을 데이터로 매핑). **세트 전 구성원을 고가로 포함(사용자 확인 2026-07-26)** — 칠흑 세트의 비-장신구(컴플리트 언더컨트롤[기계심장]·창세의 뱃지·선택 상자류)와 광휘 세트의 불멸의 유산(훈장)도 모두 고가, 별도 제외 없음. 나머지 고가 아이템은 추후 세트/이름 추가.

**데이터**: 기존 `item-drop-table.json`·`item-icons.json`·`boss-ring-boxes.json`·`accessory-boxes.json`을 그대로 사용(신규 수치 추정 없음). 신규 — `valuable-drops.json`(세트명+개별명, 1차 확정), 이펙트 최적화 산출물(JPEG). `priceMeso`는 전부 `null` 유지하고, **가치(시세)는 이 데이터와 분리된 갱신 가능 소스**로 두어 향후 지속 업데이트(크롤링 등)로 채운다([[ADR-006]]).

**이유**:
- 기록만(임시): 시세 소스가 아직 없어(방식 미정·크롤링 유력) 지금 반영할 값이 없을 뿐, 시세 반영이 최종 목표다. 레코드를 재평가 가능한 구조로 남기고 가격을 분리해 두면 시세 소스가 붙을 때 과거 기록까지 소급 평가할 수 있다([[ADR-010]] "가격 없는 항목은 합계 제외" 폴백과도 일치).
- 바텀시트+드릴다운: 후보(특히 반지 31종)가 많아 인라인 확장은 목록을 과도하게 밀고 중첩 아코디언을 만든다. 시트는 공간·확장 여유가 크고, 드릴다운은 깊이를 얕게 유지하며 등급/반지 2축을 한 화면에 배치.
- JPEG+screen: 빛 효과는 검정 배경 위 가산 합성이 물리적으로 맞고, JPEG가 글로우를 잘 압축해 고해상도를 저용량으로 담는다. black-crush는 JPEG로 뜬 검정이 screen 블렌드에서 사각 박스로 드러나는 아티팩트를 제거(진단 확인).

**트레이드오프**:
- 수익 미반영(임시): 지금은 "무엇이 나왔나"만 남고 금액 합산은 없음 — 시세 소스가 붙으면 저장된 레코드를 재평가해 합산. 가격을 레코드에 안 넣는 대신 표시 시점에 별도 소스 조인이 필요(약간의 조회 비용).
- 이펙트: 최적화해도 프레임 수(55장)는 남고, `cover`는 가로로 긴 버스트의 좌우를 자른다(중심은 채움). 브라우저 백그라운드 탭에선 `requestAnimationFrame`이 스로틀되나 실기기 포그라운드는 정상.
- 이름 기반 조회 결합은 [[ADR-011]] 트레이드오프와 동일(이름 바뀌면 매핑도 갱신).

**미확정 — 추후 확정 필요**:
- **시세(가치) 갱신 방식** — 크롤링 유력이나 미확정. 가격 소스 스키마·업데이트 주기는 별도 설계.
- 연출의 최종 fps·z순서·크기는 와이어프레임에서 잠정 확정했으나 실기기 검증 필요.
- 한 보스에서 같은 상자/아이템 **여러 개** 획득 시 개수 처리, 상자를 **안 연** 상태 표기.
- 그 외 고가 아이템(다른 세트·아이템) 추가 시점.

**TDD**: `lib/item-icons`(실제 번들 에셋 대상, `boss-icons.test.ts` 미러) → `storage/boss-drops`(`../sqlite/db` mock, SQL·params 단언, `boss-profit.test.ts` 미러) → `sqlite/db`(CREATE TABLE 단언 추가) → 스토어 드롭 액션(rows+snapshot 이중 갱신 회귀) → 컴포넌트(바텀시트 토글·드릴다운 선택, jsdom 도크블록) → `data/__tests__` 정합성 확장(신규 매핑/후보 추가 시). 전부 테스트 먼저 작성 후 구현, `npm run test`·`npm run lint`·`build` 통과 확인.
