# ADR-108 — 검은마법사 배경을 합성 한 장으로 되돌린다: 알파 하늘 + `cover` + `dim` 0.65

> 🟢 **ACTIVE — 유효.** 현행 RN 앱에 적용되는 결정이다.

**날짜**: 2026-08-07
**상태**: 구현 완료 (배치 값은 사용자가 눈으로 확정)
**관련**: [[ADR-088]](배경 이미지 구조 — 스키마 그대로 씀) · [[ADR-106]](배경 0건 상태의 정상 종료) · [[ADR-105]](이 테마의 색) · [[ADR-006]](에셋·배치는 사용자 확인)

## 맥락

[[ADR-106]] 이 "새 그림은 JSON 블록 하나로 다시 붙는다"고 적어 둔 그 자리다. 사용자가 바닥·사슬·
블레이드를 **한 장으로 합성해** 넣었고(`blackmage-background`, 1980×800), 배치는 사용자가 직접
값을 만지며 잡았다.

중간에 오브젝트를 레이어로 쌓는 안을 만들었다가 **되돌렸다**(사용자 지시) — 합성 한 장이면
[[ADR-088]] 스키마가 그대로 맞고 스키마를 건드릴 이유가 없다.

## 결정

### 1. 스키마·코드 변경 없음 — `background` 블록 하나

```jsonc
"background": {
  "image": "blackmage-background",
  "size": "cover",
  "position": "25% bottom",
  "dim": 0.65,
  "fadeTop": "0px"
}
```

[[ADR-064]] 결정 10 의 "테마 추가는 JSON 한 블록"이 배경에도 그대로 성립한다는 확인이다.
제품 코드·타입·CSS 는 한 줄도 안 바뀐다.

### 2. 하늘은 **알파**로 비워 이음매를 없앤다

처음 받은 그림은 불투명이었고 맨 윗줄이 `#221D28` 이라 테마 `bg`(`#0B0509`)와 붙는 자리에
**가로 띠**가 생겼다. `fadeTop` 은 이걸 못 고친다 — 그 값은 **뷰포트 상단**을 `bg` 로 페이드하는
것이지 그림의 윗변을 다루지 않는다.

사용자가 하늘을 투명하게 다시 뽑아 해결됐다(완전 투명 36%, 아래로 갈수록 불투명 → 100%).
이제 하늘 자리는 테마 `bg` 가 그대로 비쳐 이음매가 **구조적으로** 없다.

**그래서 webp 변환에서 알파를 지키는 것이 필수다.** `Image.open(png).convert('RGB').save(...)` 는
하늘을 검게 채워 이음매를 되살린다. RGBA 그대로 저장해야 한다(1,198 → 251KB).

### 3. `.png` 원본을 `src/assets/themes/` 에 남기지 않는다

에셋 해석 glob 은 `*.{webp,jpg,png}` 라 `blackmage-background.png` 와 `.webp` 가 **같은 슬러그로
충돌한다** — 맵에서 한쪽이 조용히 다른 쪽을 덮고(어느 쪽이 이길지는 glob 순서에 달렸다), 게다가
1.2MB PNG 가 번들에 그대로 실린다. 변환 후 원본은 지운다.

### 4. `size: cover` — 세로를 채운다 (사용자 결정), 대가는 기록해 둔다

사용자 지시는 "높이를 꽉 채워"다. 다만 이 캔버스에서 그 대가가 크고, 값으로 풀 수 있는 문제가
아니라 **캔버스 비율 문제**라 남긴다.

| | 값 |
|---|---|
| 아트워크 종횡비 | 2.475 (1980×800) |
| 폰 뷰포트 종횡비 | 0.462 (390×844) |
| 차이 | **5.4배** |
| `cover` 배율 | 1.05 → 렌더 2088×844 |
| **가로 노출** | **19%** |

즉 세로를 채우면 **가로는 19%만 보인다** — 양쪽 사슬·블레이드가 잘려 나가고 바닥은 2.6배
확대돼 뭉갠다. `position` 을 옮기면 어느 19%를 볼지만 고를 수 있다(사용자가 `25%` 로 잡아 왼쪽
블레이드가 오게 했다).

**대안은 캔버스를 세로로 다시 뽑는 것뿐이다** — 종횡비를 0.462 이하(예: 1080×2340)로 재구성하면
`size: 100% auto` 로 자르지 않고 가로·세로가 모두 찬다. 하늘이 이미 투명이라 그때도 이음매는 없다.

### 5. `dim` 0.65 — 그림이 카드와 경쟁하지 않게

0 으로 두니 "너무 도드라진다"(사용자). 브라우저에서 0.35·0.6·0.72 를 견줘 **0.65** 로 잡았다 —
0.35 는 과하고 0.72 는 거의 텍스처만 남는다.

기존 기준선(혼테일 0.82 · 옛 검은마법사 0.78)보다 밝은데, **하늘이 투명이라 어두워지는 면적이
이미 작기 때문**이다. `dim` 그라디언트는 백드롭 전체를 덮지만 하늘 자리는 이미 `bg`(거의 검정)라
더 어두워질 게 없고, 실제로 눌리는 것은 아래쪽 불투명 영역뿐이다.

### 6. `blackmage-throne.webp` 삭제

[[ADR-106]] 결정 2 가 정한 정상 종료다 — "새 그림을 넣는 커밋에서 같이 지운다". 조건이 충족됐다.
`hontail-cave.webp` 는 혼테일의 새 그림이 아직 없어 그대로 둔다(여전히 죽은 126KB).

## 결과

- `src/data/job-themes.json` 검은마법사에 `background` 블록 + `src/assets/themes/blackmage-background.webp`.
- 제품 코드·타입·CSS·테스트 변경 없음. 배경 선언이 0 → 1 이 되면서 [[ADR-106]] 결정 4 의
  `it.skipIf` 두 건이 **손대지 않아도 되살아났다**(skip 2 → 0). 그 장치가 의도대로 동작한 확인이다.
- 남은 값 조정은 `size`·`position`·`dim` 세 줄이다.
