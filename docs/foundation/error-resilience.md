# 에러 핸들링 및 복원력 (Resilience)

> **범위**: 실패 처리·빈 상태·참조 무결성·멱등성·엣지 케이스의 제품 원칙과 계층별 구현 지점. 결정의 이유·트레이드오프는 [[ADR-008]].
> **관련 소스**: `nexon/client` · `nexon/schedule` · `nexon/character` · `storage/*` 어댑터 · `native/notification-sync` · `lib/error-reporting` · 앱 전역 에러 바운더리.
> **관련 ADR**: [[ADR-008]] [[ADR-004]] [[ADR-030]] [[ADR-067]] [[ADR-101]] [[ADR-114]] [[ADR-115]]. **관련 문서**: [architecture.md](./architecture.md), [nexon-api.md](./nexon-api.md), [../features/onboarding.md](../features/onboarding.md)(401 이후의 단계 재개).

## 제품 원칙
1. **실패는 숨기지 않는다** — 조용히 이전 상태를 유지하는 대신 무엇이 실패했고 마지막 성공이 언제인지 보여준다("마지막 동기화 n분 전" + 새로고침).
2. **빈 상태는 에러가 아니다** — 게임에 아직 아무것도 등록 안 한 신규 캐릭터의 "표시할 항목 없음"은 다음 행동을 안내하는 빈 상태 화면. 반대로 **"확인 자체를 못 한" 상태를 빈 상태로 위장하지도 않는다**([[ADR-060]]) — 보스 수익 롤링 조회 윈도우 밖 기간("조회 불가", [[ADR-032]])은 빈 상태와 디자인을 공유하지 않고 별도 정보 톤 알림(`UnavailableNotice`)으로 그린다. 세 상태(조회 중 / 확정된 빈 상태 / 확인 불가·실패)는 항상 서로 구분 가능해야 한다.
   - **"확정된 빈 상태"는 시간이 지나도 확정이어야 한다**([[ADR-067]] 결정 3) — 조회해서 0건을 확인한 기간이 롤링 윈도우를 벗어나는 순간 "조회 불가"로 격하되면, 한 번 확정된 사실이 시간이 지나며 불확실해진다. 확인 기록(`boss_profit_period_checks`)을 표시 단계에서도 읽어야 한다.
   - **"아직 안 읽었다"(`null`)를 "0건"(`[]`)과 같은 조건에 묶지 않는다**([[ADR-101]] 결정 1) — 세 메인 화면이 `isEmpty = trackedOcids === null || trackedOcids.length === 0` 이라 콜드 스타트 첫 페인트가 **아직 모르는 사실을 단정했다**("표시할 캐릭터가 없습니다"가 한 프레임 스쳤다, 실기기 2026-08-06). 올바른 형태는 `trackedOcids !== null && trackedOcids.length === 0` — 빈 상태는 저장소를 읽고 0건임을 **확인한 뒤에만** 그린다. `T[] | null` 처럼 `null` 이 "미로드"를 뜻하는 상태를 화면에서 읽을 때는 항상 이 형태인지 확인할 것.
3. **실패에는 원인과 행동을 함께 준다**([[ADR-062]]) — "실패했다"만 말하고 끝내지 않는다. 원인(무효 키 / 한도 초과 / 네트워크)을 구분해 말하고, **그 원인을 실제로 푸는 행동**을 액션으로 붙인다. 401에 "다시 시도"를 주는 것은 눌러도 실패하는 버튼을 주는 것이라 금지 — **키 입력 화면으로 보낸다**([[ADR-115]] 결정 1·7, 2026-08-08 — 옛 목적지 "설정"에는 키를 바꿀 자리가 없었다). 그리고 401에는 **액션조차 주지 않는다**: 이동이 자동으로 이미 일어났으므로 누를 것이 없다. 429에도 액션을 주지 않는다(지금 누르면 또 429다). 표시 껍데기는 공용 `ErrorState`([design-system.md](./design-system.md) "실패 상태"), 보여줄 항목이 있는 채로 실패했으면 목록을 지우지 말고 그 위에 스탈 배너를 얹는다.
   - **401/403 의 처방은 안내가 아니라 이동이다**([[ADR-115]] 결정 1·2) — 토스트 한 줄(`API 키가 더 이상 유효하지 않습니다`)을 띄우고 곧바로 키 입력 화면으로 보낸다. 배너를 새로 만들지 않고, 사용자가 누를 때까지 기다리지도 않는다. **무효 키 상태에서는 어느 화면도 제 기능을 못 하므로 남겨 둘 화면이 없다.** 이동은 온보딩 상태를 뒤집는 것으로 일어나고(앱 라우트 가드가 받는다) 스토어는 라우터를 모른다 — `window.location` 을 쓰면 문서가 리로드돼 네이티브 SQLite 커넥션이 stale 하게 남는다([[ADR-050]]).
   - **429의 처방은 "잠시 후 재시도"가 아니라 키 단계 확인이다**([[ADR-114]] 결정 1·2, 이슈 #158) — 사용자는 각자 발급받은 **개발 단계 키**를 쓰므로(초당 5건·일 1,000건, [nexon-api.md](./nexon-api.md)) 일 한도를 소진했으면 다음 날까지 안 풀리고, 초당 한도면 앱이 버스트를 쏘는 한 다시 눌러도 또 429다. 문구는 단계를 판정하지 않고 "입력하신 API 키가 서비스 단계 키인지 확인해주세요"로 안내한다. **그래서 429·401 에는 `ErrorState` 든 스탈 배너든 재시도를 붙이지 않는다** — 처방이 재시도가 아닌데 버튼이 재시도면 화면이 두 말을 한다.
   - **스탈 배너도 원인별로 갈린다**([[ADR-114]] 결정 3) — 위 마지막 문장("그 위에 스탈 배너를 얹는다")은 배너가 원인을 무시해도 되는 것처럼 읽히지만 아니다. 문구·액션 모두 원인에 따라 다르고 **액션이 없을 수 있다**(429·`characterUnavailable`·온보딩의 401). 배너에서 액션을 뺄 수 있는 이유는 자리에 있다 — **배너는 목록이 남아 있어 액션이 없어도 막다른 길이 아니다**. 같은 401 이 온보딩 `ErrorState` 에서는 재시도를 유지하는 것이 같은 근거의 뒷면이다(목록이 없어 액션을 빼면 화면에 아무 길도 없다). 표는 [features/content-scheduler.md](../features/content-scheduler.md).
   - **원인을 버리지 않는다**([[ADR-063]] 결정 2) — `catch` 에서 잡은 에러를 `{ kind: 'network' }` 로 하드코딩하면 401/429가 화면에 도달할 경로가 사라진다. 반드시 `toScheduleSyncError(error)` 를 통과시킨다. 400 본문의 넥슨 에러 코드도 `nexon/http` 에서 `NexonBadRequestError.code` 로 살린다([[ADR-067]] 결정 1) — status만 보면 성질이 다른 세 실패가 한 덩어리가 된다.
   - **실패 종류 switch에는 소진 가드(`assertNever`)를 둔다.** tsconfig에 `noImplicitReturns` 가 없어 case를 빠뜨려도 타입 오류가 나지 않는다 — `ScheduleSyncError` 에 종류를 더했을 때 `formatScheduleSyncError` 가 조용히 `undefined` 를 반환하는 사고가 실제로 있었다(2026-07-31). 문구 매퍼는 그 자리에서 컴파일 오류를 내야 한다.
4. **실패를 어디에 띄우는가는 한 질문으로 정한다**([[ADR-063]]) — **그 문구가 사라진 자리에 남는 것이 있는가.**
   - 남는 게 있으면(새로고침 옆 "n분 전", 파티원 스테퍼, 기간 라벨) 실패는 **이벤트**다 → **토스트**. 액션을 붙일 수 있어 더 낫다.
   - 문구 자체가 그 자리의 **내용**이면(그리드 자리, 모달 본문, 설정 행의 값) 옮기는 순간 빈 칸이 남는다 → **인라인**.
   - **예외 메시지를 화면에 그대로 내보내지 않는다** — `err.message` 를 렌더하면 개발자용 문구(`함수명: …`)와 네이티브 원문이 사용자에게 샌다. 사용자용 문구로 바꿔 토스트로 알린다.
   - **"토스트로 옮겼다"는 그 실패가 실제로 토스트에 도달할 때만 참이다**([[ADR-083]]) — 스케줄러 두 화면은 전역 실패 문단만 걷어내고 캐릭터별 문단을 남겼는데, `syncSchedules` 는 캐릭터 단위 실패를 던지지 않고 결과에 실어 반환하므로 실패의 대부분이 전역 `error` 를 채우지 않았다. 결과적으로 두 화면에서는 토스트가 아예 뜨지 않고 액션 없는 인라인 문단만 남았다. **문단을 지웠는지가 아니라 "그 실패가 어느 값을 타고 오는지"를 확인해야 한다.**
   - **한 실패가 자리에 따라 두 얼굴을 가질 수 있다**([[ADR-083]] 결정 3) — 보스 수익 기간 로드 실패는 **카드가 있으면 토스트**(기간 라벨·카드가 남는다), **카드가 없으면 `ErrorState`**(옮기면 빈 칸이 남는다). 기준은 하나인데 자리 조건이 갈리는 것이라 예외가 아니다.
5. **과거 기록은 지우지 않는다** — 게임 데이터(보스 목록 등)가 바뀌어도 사용자 기록(수익·드랍)은 보존. 단 사용자가 실수로 남긴 획득 기록은 직접 삭제 가능.
6. **자동 재시도는 최소화한다** — 네트워크 실패 시 백그라운드 무한 재시도 금지, 사용자가 명시적으로 새로고침(배터리 보호). 단 알림 발송 판단만은 실시간 재확인 예외([[ADR-004]]).
7. **크래시 리포팅은 opt-in** — 기본 OFF. 켠 사용자에 한해 Sentry 등으로 익명 스택트레이스 전송, 캐릭터명·API 키 등 개인 식별 정보 제외.

## 문구 어미 ([[ADR-062]] 결정 5)
| 구분 | 어미 | 예 |
|---|---|---|
| 실패·에러·불가 | **`~습니다`** | "네트워크 오류가 발생했습니다" · "저장하지 못했습니다" · "이 기간은 조회할 수 없습니다" |
| 성공·안내 | `~어요` | "캐릭터 정보를 모두 불러왔어요" · "주간 12개를 모두 선택했어요" |
| 진행 중 | `~하고 있어요` | [[ADR-061]] 결정 9 |

`UnavailableNotice`(조회 불가)는 실패가 아니지만 `~습니다` 를 따른다 — 정보 톤은 색(info-tint)이 담당하지 어미가 담당하지 않는다.

## 계층별 실패 처리
| 실패 유형 | 감지 위치 | 처리 |
|---|---|---|
| 네트워크 없음/타임아웃/5xx | `nexon/schedule` wrapper | 마지막 캐시 유지, 동기화 상태 `error`, "마지막 동기화 n분 전" + 새로고침 |
| 401/403 (키 무효) | `nexon/schedule` 응답 인터셉터 | 캐시 유지 · 무효 키 자동 재시도 금지(둘 다 종전대로) + **토스트 1회(`API 키가 더 이상 유효하지 않습니다`, 액션 없음) → 키 입력 화면 자동 이동**, 저장된 **`apiKey` 만** 삭제([[ADR-115]] 결정 1·3 — `selectedAccountId`·`trackingMode`·`trackedCharacters` 는 남겨야 재입력 후 재개된다). 감지 지점 셋(동기화 토스트·피커 로스터·설정 계정 변경 `refreshAccounts`)이 **진입점 하나**를 부르고, 멱등성은 "`completed` 일 때만 성립"으로 얻는다(결정 6·7) |
| 429 (`OPENAPI00007`) | `nexon/client` 인터셉터 | **실제로 만나는 실패다**([[ADR-114]], 이슈 #158) — 로스터·예열 경로에는 큐잉도 동시성 캡도 없고 사용자는 개발 단계 키(초당 5건·일 1,000건)를 쓴다. 문구는 단계를 판정하지 않고 "호출 한도를 초과했습니다 / 서비스 단계 키인지 확인해주세요"([[ADR-114]] 결정 1), **액션은 주지 않는다**(결정 2 — `ErrorState`·스탈 배너·토스트 전부) |
| 400 `OPENAPI00003` (조회 불가 ocid) | `nexon/http` 본문 파싱([[ADR-067]] 결정 1) | **영구 실패** — 재시도 액션을 주지 않는다. 그 캐릭터를 "조회할 수 없음"으로 표시하고 추적 해제 경로를 남긴다(숨기면 사용자가 벗어날 수 없다, 이슈 #78 A-1) |
| 400 `OPENAPI00004` (그 날짜 조회 불가) | 같음 + 호출 측 날짜 판정 | 코드가 원인을 구분해주지 않으므로 **날짜로 갈라낸다** — 윈도우 밖/월드 이전 이전이면 영구("조회 불가"), 미래면 애초에 호출하지 않는다 |
| 400 `OPENAPI00009` (아직 집계 전) | 같음 | **시간이 지나면 풀리는 유일한 400** — 실패로 굳히지 않고(`markPeriodChecked` 금지) "아직 집계되지 않았습니다"로 알린 뒤 다음 방문에 재시도. 집계 시각은 미계측이라 특정 시각에 의존하는 로직을 두지 않는다 |
| `character/list` 조회 실패 | `nexon/character` wrapper | "캐릭터 목록을 가져오지 못했습니다" + 재시도. **키 무효면 401/403 행으로 귀결**하므로 재시도가 아니라 키 입력 화면으로 간다([[ADR-115]]) — 설정 계정 변경(`refreshAccounts`)이 저장된 키로 재조회하다 맞는 401 도 같은 자리다 |
| 개별 `character/basic` 실패([[ADR-015]]) | `nexon/character` 병렬 개별 실패 | 그 캐릭터만 이름/레벨 + 플레이스홀더 이미지. 전역 실패면 피커 전체 에러 상태 — 단 **401/403 은 그 화면에 머물지 않고** 위 401/403 행으로 귀결한다([[ADR-115]]), 429 는 액션 없는 에러 상태로 남는다([[ADR-114]] 결정 2) |
| 응답 스키마 불일치 | `nexon/schedule` 파서 | 항목 단위 try/catch, 실패 항목만 "표시 불가" 스킵, 나머지 정상 |
| 응답이 JSON 아님(WAF/CDN 차단) | `nexon/client` | JSON 파싱 try/catch, 네트워크 실패와 동일 폴백 |
| 미매핑 보스명/콘텐츠명 | `nexon/schedule` 정규화 | 원문 그대로 "알 수 없는 콘텐츠"(크래시 금지) |
| 로컬 저장소 쓰기 실패 | `storage/` 어댑터 | 실패를 호출부에 전파, 토스트로 알린다(무시 금지). 관리 화면 토글은 "추적 목록을 저장하지 못했습니다"([[ADR-065]] 결정 4) |
| 온보딩 중 키 저장 실패 | `features/onboarding` `setApiKey` try/catch | 온보딩 미완료 처리 + `storageWriteFailed` 토스트([[ADR-065]] 결정 1) |
| 알림 권한 거부(최초) | `native/` 초기화 | 기능 진입 시 요청, 거부 시 설정에서 재요청 안내 |
| 알림 권한 런타임 취소 | 예약/재확인 직전 | 예약 전 권한 재확인, 꺼져 있으면 예약 스킵 + 배너 |
| 알림 64개 한도 초과 | 재예약 로직 | [[ADR-004]] 우선순위 정책(사냥 타이머 폴백도 동일 풀), 나머지는 설정에 미예약 개수 표시 |
| Foreground Service/Live Activity 시작 실패 | `native/hunting-timer` | 상시 알림 없이 완료 알림/사운드만 로컬 알림 폴백 |

## 참조 무결성
`src/data/` 에서 보스가 제거돼도(카이 사례, [[ADR-006]]) 과거 로컬 기록은 삭제하지 않는다. 조회 시 참조 테이블에 없는 키를 만나면 "(더 이상 지원하지 않는 콘텐츠)"로 표시. 계정(메이플 ID) 변경 시에도 이전 계정 기준 로컬 기록(보스 수익·드랍)은 삭제하지 않고 보존, 현재 계정 캐릭터만 노출.

## 멱등성
보스 수익 기록은 `(characterId, boss, difficulty, weekOf)` 를 유니크 키로 upsert — 같은 주에 여러 번 동기화해도 중복 생성 안 됨.

## 엣지 케이스
- **신규 캐릭터, 게임 내 미등록**: `registration_flag` 전부 `"false"` — 에러 아닌 정상 빈 상태("게임에서 스케줄러에 등록해주세요").
- **리셋 경계**: 주간 = KST 목요일 00:00(`lib/reset-clock` 과 일치), 월간 보스 = 매월 1일 00:00 KST([[ADR-030]] 확정).
- **캐릭터 미접속 스케줄 누락**([[ADR-030]]): `daily_contents`/`weekly_contents` 가 통째로 비면 그 주기 미접속으로 간주, 마지막 캐시 폴백(진행값만 리셋). 응답 `date` 는 항상 조회 요청일을 반환해 타임스탬프 비교 불가.
  - **실제 축약은 "통째로 빔"이 아니라 단계적이다**(실측 2026-07-31, [nexon-api.md](./nexon-api.md) "미접속 캐릭터의 응답 축약"). 미접속 캐릭터의 weekly 6건 중 2건이 character 범위라 `isWeeklySectionMissing` 이 못 잡고, `bossMonthly` 2건이 살아남아 `isMonthlyBossStale` 이 false가 된다 → **월간 보스 완료가 신선한 false로 덮어써져 소실된다**([[ADR-067]] 결정 4).
- **월드 이전(월드 리프·챌린저스 이전)**: 이전 날짜 이전은 `date` 조회가 영구히 400 `OPENAPI00004` 다(실측). 윈도우 밖과 코드가 같아 구분되지 않으므로 호출 측이 날짜로 판정한다. 과거 응답도 `world_name` 은 **현재** 월드라 과거 주가 새 월드로 귀속된다([[ADR-054]] 결정 5의 알려진 한계).
- **조회 불가 ocid**: `character/list` 가 반환한 ocid가 `basic`·`scheduler` 에서 400 `OPENAPI00003` 일 수 있고, **계정 단위로 전원 그럴 수 있다**(실측 — 13/13). 온보딩 계정 선택([[ADR-051]])이 그 계정을 정상 후보로 제시하므로, 고른 뒤 "이 계정은 조회할 수 없습니다"를 알릴 자리가 필요하다.
- **개발 단계 키의 일 한도 소진은 다음 날까지 풀리지 않는다** — 재시도로 풀리는 실패가 아니다([[ADR-114]]). 429 응답(`OPENAPI00007`)은 일 한도와 초당 한도를 구분해주지 않으므로 앱도 둘을 구분해 말하지 않는다.
- **미해결 섹션 백필 루프**: 보스가 0건인 캐릭터(특수 월드·저레벨)는 과거 날짜도 0건이라 `fillMissingSections` 가 13일을 다 소모하고도 해결하지 못해 **매 동기화 14회 호출이 영구 반복**된다. 원칙 6(자동 재시도 최소화)에 어긋나므로 상한·포기 기록이 필요하다([[ADR-067]] 결정 5).
- **월드/계정 공유 콘텐츠**([[ADR-030]]): 몬스터파크(world)·에픽 던전 3종(account)·주간 드래곤 퇴치(world)는 개별 `registration_flag` 대신 `worldSharedProgress`/`accountSharedProgress` 원장 누적값 기준 노출. 상세 [features/content-scheduler.md](../features/content-scheduler.md).
- **"마지막 활성 캐릭터" API 오염(한계)**: world/account 콘텐츠에서 마지막 접속 캐릭터 상태가 다른 캐릭터 응답에 샌다. 몬스터파크 월드 간 오염은 구분 신호가 없어 미처리 확정 — world 원장이 그대로 흡수.
- **일부 `max_count` API 오류**: 길드 주간 미션 포인트가 실제론 항상 10인데 API가 가끔 0 → `scheduler-content-catalog.json` 의 `maxCountOverride`.
- **멀티 디바이스**: 같은 키를 여러 기기에 입력해도 캐시는 기기별 독립(동기화 없음). 버그 아님([[ADR-003]] 자연 결과).
- **캐릭터 서버 이전/개명**: 목록을 캐싱 안 하고 매번 재조회하므로 별도 무효화 없이 다음 조회에서 최신 반영.
- **캐릭터 식별**: 모든 캐릭터 식별은 개명 가능한 캐릭터명이 아니라 항상 **ocid** 기준.
- **벨로나 출시**: `status: "unreleased"` 인 채 API가 실제 데이터를 반환하기 시작하면 참조 테이블 갱신 전까지 표기 어긋남 — 출시 시 데이터 갱신 필요.
- **파티원 수 검증**: 양의 정수, 상한은 보스별(`boss-crystal-prices.json` maxPartySize) — 경계에서 버튼 비활성화.
- **동일 캐릭터 중복 / `account_list` 빈 배열 / 캐릭터 없는 계정**: ocid 기준 dedup, "이 계정에 캐릭터가 없습니다" 빈 상태.
- **계정의 캐릭터를 전부 고를 수 없게 되는 경우**: 두 경로가 있고 지금은 **둘 다 설명 없는 빈 목록**이다 — ① 전원 조회 불가(400 `OPENAPI00003`, 실측), ② 전원 장기 미접속(조회는 200인데 [[ADR-053]] 결정 1이 목록에서 제외). 둘은 원인도 처방도 다르지만 화면이 같아 "캐릭터가 없다"로 오해된다([features/onboarding.md](../features/onboarding.md) 열린 질문).
- **동률 레벨 계정 대표**: 최고 레벨 캐릭터로 대표하되 동률이면 캐릭터명 정렬(한글>알파벳>숫자, 그룹 내 가나다/abc/123).
- **게임 내 캐릭터 삭제**: 로컬 기록 보존, 조회 시 "삭제된 캐릭터"로 표시([[ADR-008]] 참조 무결성 확장).
- **사냥 타이머 강제 종료**: 재실행 시 진행 이어가지 않고 정지 상태로 시작(경고 표시).
- **기기 시계 부정확**: `lib/reset-clock` 은 타임존 차이는 보정하나 기기 시각 자체 오류는 미보정(알려진 한계).
