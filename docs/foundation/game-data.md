# 게임 레퍼런스 데이터 (src/data)

> **범위**: `src/data/*.json` 정적 참조 데이터의 역할·조인 방식·컨벤션. **CRITICAL: AI가 수치를 임의 추정해 채우지 않는다. 반드시 사용자(도메인 전문가) 확인 후 반영**([[ADR-006]]).
> **관련 소스**: `src/data/*.json` · `src/data/__tests__/bundled-game-data.spec.ts` · `lib/game-data/table` · `lib/game-data/sections` · `features/game-data/query` · `server/game-data` · `storage/query-persister` · `scripts/sync-game-data.mjs` · `lib/boss/boss-matching` · `lib/boss/bosses` · `lib/boss/catalog` · `lib/assets/asset-lookup`.
> **관련 ADR**: [[ADR-006]] [[ADR-007]] [[ADR-010]] [[ADR-011]] [[ADR-030]] [[ADR-055]] [[ADR-261]] [[ADR-270]] [[ADR-271]] [[ADR-349]] [[ADR-350]]. **관련 문서**: [nexon-api.md](./nexon-api.md), [features/item-drop.md](../features/item-drop.md), [features/boss-profit.md](../features/boss-profit.md).

## 원칙 ([[ADR-006]])
게임 패치로 자주 바뀌는 수치를 로직과 분리해 JSON 으로 둔다. 실제 값은 사용자가 확정해 채우고, AI는 임의 하드코딩하지 않는다(부정확 위험 회피). 초기엔 placeholder 로만 동작할 수 있음을 감수.

## 서버 통로 ([[ADR-350]])

게임 수치 파일 열셋은 전부 서버 표로 옮겼다(앱 쪽 전환 2026-10-18, [[ADR-350]] 정정 7). 서버가 기준이고 번들 파일은 그 사본이다.

- 끝점은 `GET /v1/game-data` 하나다. 칸 하나가 표 하나이고 칸마다 `updatedAt` 을 든다. 칸은 열셋이다. `bosses` · `dropItems` · `bossDrops` · `dropBoxes` · `crystalPrices` · `worlds` · `spendCatalog` · `symbolCosts` · `contents` · `equipmentItems` · `enhancementCosts` · `mvpGrades` · `huntingGrounds`.
- 번들 파일은 `src/data/<칸>.json` 이고 모양은 응답의 그 칸 그대로다. 선택 칸의 `null` 도 그대로 적힌다. 값의 출처 · 경위 글은 파일에 안 적고 이 문서와 ADR 에 적는다.
- 표마다 현재 값을 드는 자리가 하나다(`lib/game-data/table` 의 `createTable`). 번들 값을 그 칸의 계약 검사(`parse`)에 통과시킨 것이 초기값이라 응답의 `null` 은 코드에서 빠진 칸이다. 조회 모듈은 그 표를 읽고, 모듈 꼭대기에서 만들던 Map · 정렬 상수는 `derive` 가 표가 바뀐 뒤 첫 읽기에서 다시 만든다. 칸 열셋의 표와 `parse` 는 `lib/game-data/sections` 가 한 표로 든다.
- 받기 · 기기 사본 · 다시 그리기는 TanStack Query 다(`features/game-data/query`). 쿼리 하나(`['game-data']`)에 응답 전체를 두고 `initialData` 가 번들 열셋이다. 앱을 켜면 `hydrateGameData` 가 기기 사본(Preferences `queryCache`, `storage/query-persister`)을 복원한 뒤 서버를 한 번 받아 `null` 이 아닌 칸만 덮는다. 실패는 한 번 다시 시도하고, 켜 둔 동안은 다시 받지 않는다. 쿼리 캐시 구독 하나가 칸을 표의 `set` 으로 넘기고, 화면은 `useGameTable('contents')` 로 칸을 구독해 바뀐 칸을 그리는 화면만 다시 그린다. 계약이 바뀌면 `GAME_DATA_CONTRACT` 를 올려 옛 사본을 통째로 버린다.
- 서버 응답은 `server/game-data` 가 칸마다 `parse` 로 본다. 어긴 칸만 `null` 이고 못 받으면 `null` 하나다.
- 빌드 전에 `node scripts/sync-game-data.mjs` 가 응답을 받아 번들 파일 열셋을 다시 쓴다. `package.json` 의 `scripts` 에는 넣지 않는다(OTA 지문 재료, `release.md`).
- 서버 표의 첫 채움은 서버 저장소의 씨앗 CLI 가 했다. 비어 있는 표만 채운다. 그 뒤는 관리 화면 폼이다.
- 앱에 남는 검사는 `src/data/__tests__/bundled-game-data.spec.ts` 하나다. 칸마다 번들이 계약을 통과하는지와 번들이 가리키는 그림 파일이 있는지를 본다. 값 · 참조 · 기간 겹침 · 경계 규칙은 서버의 FK · CHECK · 쓰기 검사가 든다([[ADR-350]] 결정 11).

## 게임 데이터 파일 ([[ADR-006]] 대상: 사용자 확인 필수)
- **`bosses.json`**: 보스 26개(주간 24 · 시즌 주간 1 메이린 · 월간 1 검은 마법사)와 규칙 둘을 든다. **보스 key 마스터 표다**([[ADR-280]] 결정 12, 2026-09-15, 이슈 #445). **모양은 서버 `GET /v1/game-data` 의 `bosses` 칸과 같다**([[ADR-349]] 결정 5 · [[ADR-350]] 결정 1, 2026-10-16). 서버가 보스 표의 기준이고 이 파일은 그 사본이다. 그래서 값은 서버 관리 화면(`/admin/bosses`)의 폼으로 고친다. 맨 위 `updatedAt` 은 서버가 가장 최근에 넣은 시각이다. `null` 이면 서버에서 받은 적이 없는 사본이다. `rules` 가 한도 둘(`weeklyBossSelectionLimit` 12 · `weeklyCrystalSaleLimit` 90)을 들고, `bosses[]` 의 배열 차례가 곧 앱 전체의 보스 순서다. 보스 한 줄은 `key`(보스 key. 기록이 이 값을 든다) · `name`(Nexon API `content_name` 표기, 화면에 보이는 이름) · `alias`(좁은 자리의 이름. 통계 화면의 보스 타일이 쓴다. 이름이 길어 타일 한 줄을 넘는 넷만 줄이고 나머지는 `name` 과 같다. `선택받은 세렌`→`세렌` · `감시자 칼로스`→`칼로스` · `가디언 엔젤 슬라임`→`가엔슬` · `시즌 보스 메이린`→`메이린`, 사용자 확정 2026-09-29, 이슈 #352) · `cycle`(`weekly` · `event_weekly` · `monthly`) · `portraitSlug`(`assets/bosses/{portraitSlug}.webp` 조회 키, 난이도 무관) · `difficulties[]` 를 들고, 난이도 한 줄이 `{ difficulty, requiredLevel, maxPartySize, from, until }` 이다. 난이도 key 는 `easy` · `normal` · `hard` · `chaos` · `extreme` 이고 줄의 차례가 그 순서다. `crystal-prices.json` · `boss-drops.json` 의 `boss` 는 보스 key, `difficulty` 는 난이도 key 다. **앱이 읽는 자리는 `lib/boss/bosses.ts` 한 곳이다.** 번들의 이 파일이 `lib/boss/catalog.ts` 의 표 초기값이고, 앱을 켜면 위 서버 통로가 기기 사본과 서버 응답으로 덮는다. 관리 화면은 `useGameTable('bosses')` 로 표를 구독한다. **파티 인원 상한도 이 표가 든다**([[ADR-350]] 정정 1 · 7, 2026-10-18). `rules.defaultMaxPartySize`(6)가 필수 칸이고 난이도 줄의 `maxPartySize` 가 예외를 든다(스우 익스트림 2인, 최초의 대적자 · 찬란한 흉성 · 벨로나 · 림보 · 발드릭스 · 유피테르 3인, 메이린 1인). 조회는 `lib/boss/bosses` 의 `getMaxPartySize(boss, difficulty)` 하나다. 결정석 가격 줄에서 상한 칸이 빠진 자리다. `bosses.ts` 가 `cycle` 에서 관리 화면 묶음 `section`(`weekly` · `eventWeekly` · `monthly`)을, 난이도 줄에서 `difficulties` 배열과 `requiredLevels` 맵을 만든다. 빌드 전에 `node scripts/sync-game-data.mjs` 가 서버에서 받아 이 파일을 다시 쓴다. API 표기가 옛 데이터 표기와 다르다고 확인된 이름은 `검은 마법사` · `블러디퀸` 둘이고, 나머지 24는 데이터 표기를 적어 첫 응답과 대조한다(매칭은 공백을 지워 비교하므로 key 는 안 갈린다). `weeklyBossSelectionLimit`(12)은 원래 `weekly_boss_clear_limit_count` 대조용이었고, [[ADR-055]](이슈 #62) 이후 **수동 모드 보스 관리 페이지의 선택 한도로도 쓰인다**(자동 모드는 여전히 게임 등록 목록 그대로라 제약 없음). `event_weekly`(시즌보스)는 12마리 제한 예외라 "n/12" 카운터에서 `weekly` 보스만 분모·분자에 포함. **`weeklyCrystalSaleLimit`(90)은 이름만 비슷할 뿐 단위가 다른 별개 값이다**([[ADR-054]], 2026-07-29 사용자 확정). `weeklyBossSelectionLimit`(12)이 **캐릭터당** 주간 보스 등록/처치 한도인 반면 `weeklyCrystalSaleLimit`(90)은 **월드당** 주간 결정석 판매 한도이며, 주간 보스만 포함하고(월간 보스=검은마법사 결정석은 90에 불포함) 시즌 보스는 제외하며 안 판 결정석은 다음 주로 이월되지 않는다(매주 초기화). 두 값 모두 `lib/boss/boss-matching`(`WEEKLY_BOSS_CLEAR_LIMIT`·`WEEKLY_CRYSTAL_SALE_LIMIT`)에서 나란히 읽는다. 출시 전 보스를 숨기던 `status: "unreleased"` 칸은 서버 모양에 없어 걷었다([[ADR-349]] 결정 5). 출시 전 보스는 표에 넣지 않는다. 카이는 시즌 종료로 제외. **보스 줄은 `from` · `until` 유효 기간을 들 수 있다**([[ADR-349]] 정정 2, 2026-10-16). KST 글자이고 기간 첫날로 판정한다(`isBossActiveIn`). 시즌 보스의 끝은 관리 화면에서 적는다. **난이도 줄도 `from` · `until` 을 들 수 있다**([[ADR-349]] 정정 3). 새로 생긴 난이도의 시작이고, 보스의 기간이 먼저 서고 난이도 줄이 든 칸이 그것을 덮는다.
- **`crystal-prices.json`** (칸 `crystalPrices`, 서버 표 `boss_crystal_prices`, [[ADR-350]] 정정 1 · 7): 보스×난이도 "강력한 힘의 결정" 정가(1인 기준). `prices[]` 한 줄이 `{ boss, difficulty, priceMeso, from, until }` 이고 106줄이다. 실수령은 `floor(priceMeso / partySize)` 이고 그 식은 코드가 든다. `priceMeso` 는 서버가 NOT NULL 로 들어 가격 미확정 경로가 없다. 메이린은 결정이 아닌 황금 메소 주머니(1개=1000만) 총 가치로 채웠다. 파티 인원 상한은 이 파일이 아니라 `bosses.json` 이 든다. **한 보스·난이도에 줄이 여럿일 수 있다**([[ADR-261]]). 줄마다 `from`(이 날부터)·`until`(이 날 전까지)을 들고, 처치의 기간이 그 줄을 고른다(`findPriceEntry(boss, difficulty, periodKey, now)`, `lib/boss/boss-crystal-prices`). 값이 바뀌면 옛 줄을 지우지 않는다. 관리 화면(`/admin/crystal-prices`)에서 새 가격을 열면 지금 줄이 닫힌다. 과거 기간이 옛 값을 계속 읽기 때문이다. `until` 이 없는 줄이 지금 가격이다. 줄들이 겹침 없이 이어지고 경계가 그 보스의 기간 경계(주간 목요일 · 월간 1일)에 서는 것은 서버 쓰기 검사가 지킨다.
- **`boss-drops.json`** (칸 `bossDrops`, 서버 표 `boss_drop_rewards`, [[ADR-350]] 정정 1 · 7): 보스×난이도 보상 전체(고정 보상/장비/소비). `rewards[]` 한 줄이 `{ boss, difficulty, category, item, amount, from, until }` 이고 387줄이다. 줄 표 그대로 납작하고, 보스 · 난이도 · 갈래로 묶는 것은 `lib/boss/boss-drops` 다. 버튼 노출 항목은 사용자가 선별한다(코드가 임의 선별 금지). **단 재화 셋은 원본에 있어도 이 표에 넣지 않는다**. 강렬한 힘의 결정(가격 표의 존재 이유)·메소(그 결정의 `priceMeso` 로 들어간다, 여기 또 적으면 두 번 세어진다)·마일리지(26엔트리가 한 번도 적지 않은 승계 사항). 근거와 판정은 [[ADR-151]] 결정 2. **갈래는 `fixed`·`equipment`·`consumable` 셋이고 서버 ENUM 이다**. 원본의 `scroll`(주문서 교환권 3종)은 [[ADR-070]]에서 `consumable` 로 흡수했고, 옛 파일의 `misc`("태초의 정수" 2건)는 서버로 가지 않았다([[ADR-350]] 정정 1 이 걷었다). 줄의 `slot`([[ADR-351]]) · `set` · `note`(교환 가능 · 불가 글자)도 걷었다. **줄도 `from`·`until` 을 든다**([[ADR-261]]). 교환권 셋은 `until: 2026-09-17T10:00`, 소울 에테르 넷은 `from: 2026-09-17T10:00` 이고, 메멘토 큐브 수량이 바뀐 칸은 옛 줄과 새 줄이 나란히 선다. 판정은 기록의 기간 첫날로 한다. 그래서 9월 기간의 검은마법사는 교환권을 얻을 수 있고 10월 기간부터 못 얻는다. 표에서 지우지 않는 것은 획득 판정이 못 먹는 기록을 DB 에서 지우기 때문이다. 관리 화면은 `/admin/boss-drops` 다.
- **`drop-boxes.json`** (칸 `dropBoxes`, 서버 표 `drop_boxes` · `drop_box_contents`, [[ADR-010]], [[ADR-011]], [[ADR-350]] 정정 1 · 7): 개봉 결과를 직접 고르는 랜덤 상자 일곱. `boxes[]` 한 줄이 `{ item, levelMin, levelMax, contents[] }` 다. "OO옥의 보스 반지 상자" 5종(녹옥/홍옥/흑옥/백옥/생명의)은 반지 레벨 범위(`levelMin` ~ `levelMax`)와 반지 후보를, "혼돈의 칠흑 장신구 상자"·"메이린의 칠흑 장신구 상자"(이름만 다르고 후보 동일)는 레벨 없이(`null`) 장신구 후보 7종을 든다. 후보는 자동 추정용이 아니라 사용자가 획득 기록 시 고를 목록이고, 옛 파일의 확률(`probabilityPercent`)과 `priceMeso` · `description` 은 걷었다. 상자와 내용물은 `item`(아이템 key)으로 가리키고 그림은 `drop-items.json` 이 든다([[ADR-280]] 결정 11). 반지 상자의 명명 반지 기준(백옥 상자의 후보)과 연마석 · `기타` 반지 묶음은 `lib/boss/boss-drops` 의 앱 상수다. 관리 화면은 `/admin/drop-boxes` 다.

`apiName` 은 API 이름이고, 응답을 정규화하는 자리가 NFC 뒤 공백을 지우고 완전 일치로 key 를 얻는다. 못 찾으면 key 가 `null` 이고 그 항목은 자동 모드 스케줄러에만 원문 이름으로 선다. 보스는 `bosses.json` 이 따로 든다. 길드 셋과 메이플 유니온 둘은 그림이 없고 카드 코드가 고정 그림을 쓴다. 요구 레벨(`requiredLevel`)은 잠금이 아니라 표시다([[ADR-055]] 정정 2 가 잠금만 걷었다). `lib/scheduler/required-level` 이 읽어 카드 배지 · 진행률 분모 · today 의 남은 스케줄에서 그 캐릭터가 못 가는 항목을 가른다. 아래 "데이터 확정 현황". 에픽 던전 넷의 `maxCount` 는 **총 스테이지 수 5** 이고 깬 스테이지 수가 `now_count` 다(사용자 확인 2026-09-11). **줄이 `from` 을 들 수 있다**([[ADR-261]] 정정 1). 그 날 전인 주간 기간에는 컨텐츠 관리 목록과 수동 모드 스케줄러에 안 선다. 출시 전인 컨텐츠를 지금 할 수 있는 일로 그리지 않기 위해서다. 추적 목록과 key 집합(`templateKeysOf`)은 기간을 안 본다. 거르면 이미 고른 항목을 잃는다. **공유 범위도 이 표의 칸이다**([[ADR-030]] · [[ADR-350]] 결정 10). `shareScope` 가 캐릭터 33 · 월드 3 · 계정 5 이고, 공유 줄은 today 공유 위젯의 글자 `sharedShortName`(`일간` · `앵글러컴퍼니`)을 든다. today 공유 컨텐츠 위젯은 줄을 응답이 아니라 이 표에서 만들고 줄의 기간(`from`)도 같은 줄에서 읽는다. **`trustRegistrationFlag` 가 참인 줄은 응답의 `registration_flag` 를 그대로 쓴다**([[ADR-270]]). 메이플 유니온 두 줄만이다(사용자 결정 2026-09-13). 나머지 공유 항목은 원장의 `active` 가 한 번 참이면 계속 참이다([[ADR-030]] 결정 4). `onlyWhenScheduled`(today 위젯이 줄을 그릴지)와는 뜻이 달라 칸을 따로 둔다. `cumulativeScore` 는 리셋 없이 누적되는 개인 점수(길드 지하 수로)이고 `maxCountOverride` 는 API 오류 덮어쓰기 전용(길드 주간 미션 포인트 10)이다. 새 컨텐츠가 게임에 추가되면 관리 화면 `/admin/contents` 에서 더한다([[ADR-006]] 절차). 옛 파일 둘(`scheduler-content-template.json` · `scheduler-content-catalog.json`)과 `registration_flag` · `now_count` · `quest_state` · 설명 칸 9개는 걷었다.

- **`hunting-grounds.json`** (칸 `huntingGrounds`, 서버 표 셋 `hunting_regions` · `hunting_grounds` · `hunting_ground_levels`, [[ADR-175]] 결정 2, [[ADR-350]] 정정 6 · 7): 사냥터 참조표. `regions[]` 21줄(`{ key, name, forceType }`, 아케인 12 · 어센틱 9) · `grounds[]` 408줄(`{ key, region, name, force, mobs }`) · `groundLevels[]` 460줄(`{ ground, level }`)이고 2026-08-28 사용자 제공분이다. 줄 표 그대로 납작하고, 지역 안에 사냥터를 · 사냥터 안에 레벨을 묶어 지금의 `HuntingRegion`(`grounds[].levels`)을 만드는 것은 `lib/cashbook/hunting-grounds` 다(`huntingRegions()`). 사냥터마다 `force`(아케인/어센틱 포스 요구치, 어느 쪽인지는 지역의 `forceType` 이 안다) · `mobs`(맵 몬스터 마릿수) · 레벨 줄을 든다. 레벨이 **목록**인 이유는 원 자료가 ‘lv.200-201’(붙은 둘)과 ‘lv.217,219’(떨어진 둘)를 둘 다 쓰기 때문이고, 셋 이상인 맵은 없다(하나인 맵 356 · 둘인 맵 52). **사냥터 key 가 전역 유일**이라 기록에 지역을 안 적고 key 로 되짚는다([[ADR-280]] 결정 10, 2026-09-15, 이슈 #443). 사냥터 key 는 `지역 key_번역` 이다([[ADR-280]] 결정 9). 이름도 전역 유일이고, 이름으로 찾는 `findHuntingGroundByName` 은 이름만 든 옛 기록을 옮기는 이관만 쓴다. 지역 목록을 거르는 근거는 **사냥터의 몬스터 레벨**이다([[ADR-175]] 결정 6, `monsterLevelRangeOf`). 옛 파일의 추천 캐릭터 레벨(`minLevel` · `maxLevel`) · `slug` · `group` 은 걷었다. 심볼 FK 는 두지 않는다(사용자: 사냥터는 포스 수치만 중요하다). 계산에 쓰는 상수(분당 8젠 · 몬스터 레벨 × 7.5 · 레벨 차이 페널티 표 둘 · 아이템 증가율 둘)는 **JSON 이 아니라 `lib/cashbook/hunting-meso.ts`** 에 산다. 맵마다 다른 값이 아니라 게임 전체의 규칙이라서다. 그 값들도 전부 사용자 제공이고, 페널티 표 둘은 합이 각각 80·70 이라 **정확히 −100% 에서 끝나는지**를 테스트가 지킨다. 힘 종류의 이름 · 아이콘도 앱 상수다. 관리 화면은 `/admin/hunting-grounds` 다.

## UI 표시 전용 설정 파일 ([[ADR-006]] 대상 아님: 게임 수치 아님)
게임 밸런스/수치가 아니라 화면 크롭 파라미터이므로 사용자가 이미지 넣을 때마다 직접 조정(디버그 프리뷰에서 값 복사).
- **`boss-portrait-crops.json`** ([[ADR-018]]): 보스 스케줄러 새 보스 카드 bleed 일러스트의 `portraitSlug → { size, position }`(CSS background-size/position). 매핑 없으면 cover/center. 값 조정은 전용 디버그 화면에서 눈으로 맞췄고, 그 화면은 조정을 마치고 삭제했다(ADR-092: 다시 만질 일이 생기면 복원 선행). `bellona` 두 항목은 2026-08-19 사용자가 직접 채웠다([[ADR-151]]). **같은 날 카링 일러스트가 960×873(불투명) → 422×500(알파) 로 교체되면서 카링 크롭도 함께 바뀌었다**. 원본이 코퍼스 규격(422×500, 벨로나·유피테르와 동일)으로 내려오며 필요한 확대가 줄었다(카드 `200% auto` → `90% auto`, 원형 `800% auto` → `250% auto`). 원형 확대 800% 는 이 파일에서 유일한 극단값이었고 그 원인이 일러스트 규격이었다. 찬란한 흉성 원형 확대도 같은 날 210% → 250% 로 조정됐다(위치는 그대로). 주간 콘텐츠 카드 배경(에픽 던전 3종·길드 지하수로)도 이 파일 재사용([[ADR-021]]). **아우룸 레기스(`lesa`)도 한 줄을 갖는다**(2026-09-12). 시작값은 `100% auto` · `50% 35%` 이고 사용자가 카드를 보며 맞춘다. 값이 `숫자% auto` · `숫자% 숫자%` 형식이 아니면 읽히지 않고 `cover` 로 떨어진다(`lib/image-crop.ts`).
- **`boss-portrait-icon-crops.json`** (2026-07-14): `BossPortrait`(원형 아이콘, 보스 수익 화면)의 크롭. 형식은 위와 동일하나 값은 공유하지 않는 별도 파일(원형/사각형은 이상적 크롭이 다름). 조정 화면은 ADR-092 에서 삭제.
- **`daily-quest-region-crops.json`** ([[ADR-020]]): 지도 배경 슬러그(템플릿 줄의 `background.map`) → `{ size, position }`. 조정 화면은 ADR-092 에서 삭제. 길드 미션 포인트(`hallOfHeroes`)·플래그 레이스(`flagRace`, jpg)도 추가([[ADR-021]]).
- **`job-themes.json`** ([[ADR-009]], [[ADR-064]], [[ADR-104]]): 테마별 38토큰 컬러 + `mode` + 선택 `background` + **`category`**(기본/직업/보스: 소속은 게임 도메인이라 사용자 확인으로 정한다) → [features/theme.md](../features/theme.md).
