# 게임 레퍼런스 데이터 (src/data)

> **범위**: `src/data/*.json` 정적 참조 데이터의 역할·조인 방식·컨벤션. **CRITICAL: AI가 수치를 임의 추정해 채우지 않는다. 반드시 사용자(도메인 전문가) 확인 후 반영**([[ADR-006]]).
> **관련 소스**: `src/data/*.json` · `src/data/__tests__/data-consistency.spec.ts` · `lib/boss/boss-matching` · `lib/assets/asset-lookup` · `lib/assets/asset-lookup`.
> **관련 ADR**: [[ADR-006]] [[ADR-007]] [[ADR-010]] [[ADR-011]] [[ADR-030]] [[ADR-055]] [[ADR-261]] [[ADR-270]] [[ADR-271]]. **관련 문서**: [nexon-api.md](./nexon-api.md), [features/item-drop.md](../features/item-drop.md), [features/boss-profit.md](../features/boss-profit.md).

## 원칙 ([[ADR-006]])
게임 패치로 자주 바뀌는 수치를 로직과 분리해 JSON 으로 둔다. 실제 값은 사용자가 확정해 채우고, AI는 임의 하드코딩하지 않는다(부정확 위험 회피). 초기엔 placeholder 로만 동작할 수 있음을 감수.

## 조인 키

> **[[ADR-280]] 이 이 절을 key 로 바꾼다(2026-09-15 사용자 결정).** 이름 글자로 잇던 것을 묶음마다
> 마스터 표 하나의 영문 snake_case key 로 잇는다. 순서는 손입력 가계부, 보스 드롭 아이템, 보스, 컨텐츠 · 강화 ·
> 월드다. 묶음 하나를 옮길 때마다 아래 문장 중 그 묶음의 것을 `폐기된 정책 (history)` 로 내린다. 손입력 가계부
> 묶음은 옮겼다(이슈 #443). 그 묶음의 파일 둘은 아래 `spend-catalog.json` · `hunting-grounds.json` 이 든다. 보스 드롭 아이템(이슈 #444) · 보스(이슈 #445) · 컨텐츠(이슈 #446 의 첫 PR) 묶음도 옮겼다. 컨텐츠는 아래 `scheduler-content-template.json` 이 마스터 표다.
`weekly-bosses.json`·`boss-crystal-prices.json`·`item-drop-table.json` 세 파일은 **보스명(`boss`) + 난이도(`difficulty`)** 를 공통 키로 조인한다. 컨테이너 상자 파일(`boss-ring-boxes.json`·`accessory-boxes.json`)은 아이템 `name` 문자열로 `item-drop-table.json` 과 연결한다.

## 게임 데이터 파일 ([[ADR-006]] 대상: 사용자 확인 필수)
- **`weekly-bosses.json`**: 주간 보스(24종)+이벤트 주간(1종, 메이린)+월간(1종, 검은마법사) 명단·난이도. **보스 key 마스터 표다**([[ADR-280]] 결정 12, 2026-09-15, 이슈 #445). 줄마다 `key`(보스 key) · `name`(Nexon API `content_name` 표기, 화면에 보이는 이름) · `difficulties`(난이도 key: `easy` · `normal` · `hard` · `chaos` · `extreme`) · `requiredLevels`(난이도 key 로) · `portraitSlug` 를 든다. `boss-crystal-prices.json` · `item-drop-table.json` 의 `boss` 는 보스 key, `difficulty` 는 난이도 key 다. 조회는 `lib/boss/bosses.ts` 한 곳이다. API 표기가 옛 데이터 표기와 다르다고 확인된 이름은 `검은 마법사` · `블러디퀸` 둘이고, 나머지 24는 데이터 표기를 적어 첫 응답과 대조한다(매칭은 공백을 지워 비교하므로 key 는 안 갈린다). `weeklyBossSelectionLimit`(12)은 원래 `weekly_boss_clear_limit_count` 대조용이었고, [[ADR-055]](이슈 #62) 이후 **수동 모드 보스 관리 페이지의 선택 한도로도 쓰인다**(자동 모드는 여전히 게임 등록 목록 그대로라 제약 없음). `eventWeekly`(시즌보스)는 12마리 제한 예외라 "n/12" 카운터에서 `weekly` 섹션만 분모·분자에 포함. **`weeklyCrystalSaleLimit`(90)은 이름만 비슷할 뿐 단위가 다른 별개 값이다**([[ADR-054]], 2026-07-29 사용자 확정). `weeklyBossSelectionLimit`(12)이 **캐릭터당** 주간 보스 등록/처치 한도인 반면 `weeklyCrystalSaleLimit`(90)은 **월드당** 주간 결정석 판매 한도이며, 주간 보스만 포함하고(월간 보스=검은마법사 결정석은 90에 불포함) 시즌 보스는 제외하며 안 판 결정석은 다음 주로 이월되지 않는다(매주 초기화). 두 값 모두 `lib/boss/boss-matching`(`WEEKLY_BOSS_CLEAR_LIMIT`·`WEEKLY_CRYSTAL_SALE_LIMIT`)에서 나란히 읽는다. `status: "unreleased"`(참조표엔 남기되 **보스 관리 목록에서는 이 필드로 걸러 숨긴다**. [[ADR-056]] 결정 1)인 엔트리는 **현재 0개**다. 벨로나가 출시되며 그 필드를 지웠다([[ADR-151]] 결정 1). 필터는 다음 미출시 보스를 위해 그대로 남는다([[ADR-151]] 결정 4). 카이는 시즌 종료로 제외. `portraitSlug` = `assets/bosses/{portraitSlug}.webp` 조회 키(난이도 무관).
- **`boss-crystal-prices.json`**: 보스×난이도 "강력한 힘의 결정" 정가(1인 기준). 실수령 = `partySizeScaling.formula`(`floor(priceMeso / partySize)`). `priceMeso: null` 인 항목은 **현재 0개**다(벨로나 출시로 확정: [[ADR-151]]). null 일 때의 "가격 미확정" 경로는 그대로 남는다. 메이린은 결정이 아닌 황금 메소 주머니(1개=1000만) 총 가치로 채움(entry `note`). 입장 인원 상한: `partySizeScaling.defaultMaxPartySize`(6) + entry별 `maxPartySize`(예외: 스우 익스트림 2인, 최초의 대적자·찬란한 흉성·벨로나·림보·발드릭스·유피테르 3인, 메이린 1인). **한 보스·난이도에 줄이 여럿일 수 있다**([[ADR-261]]). 줄마다 `from`(이 날부터)·`until`(이 날 전까지)을 들 수 있고, 처치의 기간이 그 줄을 고른다(`findPriceEntry(boss, difficulty, periodKey)`). 값이 바뀌면 옛 줄을 지우지 않고 `until` 을 적은 뒤 새 줄을 더한다. 과거 기간이 옛 값을 계속 읽기 때문이다. `until` 이 없는 줄이 지금 가격이다. 한 보스·난이도의 줄들은 겹침 없이 이어지고, 경계는 그 보스의 기간 경계(주간 목요일 · 월간 1일)에 서며, 같은 `maxPartySize` 를 든다. 셋 다 `data-consistency.spec.ts` 가 지킨다.
- **`item-drop-table.json`**: 보스×난이도 보상 전체(고정 보상/장비/소비/기타)를 원본 그대로. 버튼 노출 항목은 사용자가 선별(코드가 임의 선별 금지). **단 재화 셋은 원본에 있어도 이 파일에 넣지 않는다**. 강렬한 힘의 결정(가격 파일의 존재 이유)·메소(그 결정의 `priceMeso` 로 들어간다, 여기 또 적으면 두 번 세어진다)·마일리지(26엔트리가 한 번도 적지 않은 승계 사항). 근거와 판정은 [[ADR-151]] 결정 2. 아이템 시세(`priceMeso`, [[ADR-010]])는 컨벤션만 정하고 값은 확정 시 채움. **코드가 읽는 카테고리는 `fixed`·`equipment`·`consumable` 뿐**이라 그 밖의 키는 화면에 나오지 않는다. 원본에 있던 `scroll`(주문서 교환권 3종)은 [[ADR-070]]에서 `consumable` 로 흡수했고, `misc`("태초의 정수" 2건)는 죽은 데이터로 두기로 확정했다(사용자 확인 2026-07-31). **아이템 줄도 `from`·`until` 을 든다**([[ADR-261]]). 교환권 셋은 `until: 2026-09-17`, 소울 에테르 넷은 `from: 2026-09-17` 이고, 메멘토 큐브 수량이 바뀐 칸은 옛 줄과 새 줄이 나란히 선다. 판정은 기록의 기간 첫날로 한다. 그래서 9월 기간의 검은마법사는 교환권을 얻을 수 있고 10월 기간부터 못 얻는다. 표에서 지우지 않는 것은 획득 판정이 못 먹는 기록을 DB 에서 지우기 때문이다.
- **`boss-ring-boxes.json`** ([[ADR-010]], [[ADR-011]]): "OO옥의 보스 반지 상자" 5종(녹옥/홍옥/흑옥/백옥/생명의)의 레벨별·반지별 확률표. 확률은 자동 추정용이 아니라 사용자가 획득 기록 시 고를 후보 목록. 상자와 내용물은 `item`(아이템 key)으로 가리키고, 반지 그림(`assets/items/rings/` GMS 영문 파일명)은 `drop-items.json` 이 든다([[ADR-280]] 결정 11).
- **`accessory-boxes.json`** ([[ADR-010]]): "혼돈의 칠흑 장신구 상자"·"메이린의 칠흑 장신구 상자"(이름만 다르고 후보 동일) 후보 7종. 레벨 개념 없고 개별 확률 비공개라 후보 목록만(확률 `null`). 상자와 내용물은 `item`(아이템 key)으로 가리킨다.
- **`drop-items.json`** ([[ADR-280]] 결정 11, 2026-09-15, 이슈 #444): 보스 드롭 아이템의 key 마스터 표. 드롭 표 이름 77 · 반지 31 · `기타` 가 key · 이름 · 그림 파일(`iconFile`)을 들고, 세트 넷이 key · 이름을 든다. **이름과 그림은 이 파일에만 적는다.** `item-drop-table.json`(줄의 `item` · `set`) · 상자 파일 둘 · `valuable-drops.json` 은 key 로 가리키고, 가리키는 key 가 모두 표에 있는지는 `drop-items.spec.ts` 가 지킨다. key 는 기록(`boss_drop_records.item_key` · `box_origin_key`)에 저장되므로 한 번 정한 key 는 바꾸지 않고, 이름을 바꿀 때는 `name` 만 고친다. 그림 매핑은 옛 `item-icons.json`(확신도 높은 매칭만, [[ADR-011]])과 반지 상자 파일의 `iconFile` 을 옮겼다.
- **`scheduler-content-template.json`** ([[ADR-035]] 결정 7·8, [[ADR-280]] 결정 13): **컨텐츠 마스터 표다**(2026-09-15, 이슈 #446). 컨텐츠 41 줄이 영문 snake_case `key` · 갈래 key(`category`) · 카드와 관리 화면의 이름(`displayName`) · 좁은 자리의 이름(`shortName`) · 카드 그림(`background`, 지도 배경 `{ map }` 또는 보스 초상 `{ portrait }`) · 참고 태그를 덮는 글자(`countTag`)를 든다. 캐시 · 추적 목록 · 공유 원장 · 카탈로그는 컨텐츠 key 로 이 파일을 가리키고, 조회는 `lib/scheduler/contents.ts` 하나다. 갈래 표(보이는 글자 · 참고 태그 · 관리 화면 차례)는 `lib/scheduler/content-categories.ts` 에 있다. 코드가 갈래로 카드 모양과 길드 판정을 가르기 때문이다. `content_name` 은 API 이름이고, 응답을 정규화하는 자리가 NFC 뒤 공백을 지우고 완전 일치로 key 를 얻는다. 못 찾으면 key 가 `null` 이고 그 항목은 자동 모드 스케줄러에만 원문 이름으로 선다. 줄마다 수동 트래킹 모드에서 `schedulerCache` 에 한 번도 잡힌 적 없는 항목에 쓸 **캐릭터 무관 default 값**(`type` · `now_count` · `max_count` · `quest_state`)도 든다. 보스는 `weekly-bosses.json` 이 따로 든다. 길드 셋과 메이플 유니온 둘은 `background` 가 없고 카드 코드가 고정 그림을 쓴다. 새 컨텐츠가 게임에 추가되면 이 파일부터 갱신([[ADR-006]] 절차). 요구 레벨 필드(`requiredLevel`)는 값만 채워져 있고 **읽는 코드가 없다**([[ADR-055]] 정정 2). 아래 "데이터 확정 현황". 에픽 던전 넷의 `max_count` 는 **총 스테이지 수 5** 이고 `now_count` 는 깬 스테이지 수다(사용자 확인 2026-09-11). 그 전에는 0 으로 적혀 있었다. **줄이 `from` 을 들 수 있다**([[ADR-261]] 정정 1). 그 날 전인 주간 기간에는 컨텐츠 관리 목록과 수동 모드 스케줄러에 안 선다. 출시 전인 컨텐츠를 지금 할 수 있는 일로 그리지 않기 위해서다. 추적 목록과 템플릿 key 집합(`TEMPLATE_WEEKLY_KEYS`)은 기간을 안 본다. 거르면 이미 고른 항목을 잃는다.
- **`scheduler-content-catalog.json`** ([[ADR-030]]): character 범위(기본값)가 아닌 예외만 등록: `worldShared`/`accountShared` 배열(`{ content, section, shortName }`), `maxCountOverrides`(`{ 컨텐츠 key: 고정값 }`). `content` 는 템플릿의 컨텐츠 key 다([[ADR-280]] 결정 13). 줄의 `shortName` 은 today 공유 위젯만의 글자(`일간` · `앵글러컴퍼니`)라 템플릿의 `shortName` 과 따로 둔다. `section` 은 daily/weekly 어디서 오는지(빈 응답 stale 시 원장 복원용). `maxCountOverrides` 는 API 알려진 오류 필드 덮어쓰기 전용. 조회는 `lib/scheduler/scheduler-content-scope.ts`. [[ADR-006]] 취지 준용. today 공유 컨텐츠 위젯은 줄을 응답이 아니라 이 파일에서 만들고, 줄의 기간(`from`)은 같은 컨텐츠 key 의 템플릿 줄에서 읽는다([[ADR-261]] 정정 1). 그래서 그 날 전인 주간 기간에는 줄을 안 그린다. **`trustRegistrationFlag: true` 인 줄은 응답의 `registration_flag` 를 그대로 쓴다**([[ADR-270]]). 메이플 유니온 두 줄만 든다(사용자 결정 2026-09-13). 나머지 공유 항목은 원장의 `active` 가 한 번 참이면 계속 참이다([[ADR-030]] 결정 4). `onlyWhenScheduled`(today 위젯이 줄을 그릴지)와는 뜻이 달라 칸을 따로 둔다. **`groupWeeklyLimits` 는 계열의 주간 진행 한도다**([[ADR-271]]). 키는 갈래 key(템플릿의 `category`)이고 지금은 `epic_dungeon: 3` 하나다(에픽 던전 4종 중 주 3회, 사용자 확인 2026-09-13). 게임 규칙이라 코드에 박지 않고, API 오류를 덮는 `maxCountOverrides` 에도 두지 않는다.
- **`spend-catalog.json`** ([[ADR-166]]): 가계부 지출의 선택 목록(갈래 · 묶음 · 항목 · 가격). **항목 줄이 `from` 을 들 수 있다**([[ADR-261]] 정정 1). 적는 날짜가 든 주간 기간이 그 날 전이면 타일이 안 선다. 이미 적힌 기록을 되짚는 `findSpendChoice` · `findSpendRewardChoice` 는 기간을 안 본다. `tile` 이 같은 줄들은 `from` 이 같아야 한다. 기간제 이벤트의 `groups.active` 와는 다른 칸이다. 그쪽은 날짜로 판정하지 않는 수동 스위치다([[ADR-166]] 정정 5). **이 파일이 지출 선택 목록의 key 마스터 표다**([[ADR-280]] 결정 10, 2026-09-15, 이슈 #443). 묶음 11 · 타일 32 · 항목 45 가 영문 snake_case key 를 갖고, 기록은 그 key 로 이 파일을 가리킨다. `tiles` 가 타일마다 이름과 그림(아이템 그림 파일 `file` 또는 지역 아이콘 `map`)을 들고, 항목은 `tile` · `group` · `category` 를 key 로 가리킨다. 그림이 없는 타일은 셋이다(출석 이벤트 패스 · 보약 버프 추가 구매 · 보약 버프 초기화).
- **`symbol-costs.json`** ([[ADR-301]], 2026-09-19): 가계부 지출 `심볼 강화` 의 비용 표. 묶음 셋(아케인 심볼 · 어센틱 심볼 · 그랜드 어센틱 심볼)이 `maxLevel`(20 · 11 · 11) · 심볼을 고르면 서는 `defaultRange`(아케인 `[7, 12]` · 나머지 `[5, 8]`, 사용자 지정 2026-09-19) · 심볼 목록을 들고, 심볼마다 착용 레벨 `requiredLevel`(사용자 확인 2026-09-19. 사냥터 표의 지역 `minLevel` 과 같은 값이지만 그 칸은 추천 레벨이라 따로 적는다)이 있으며, 심볼마다 `costs` 가 한 단계 올리는 메소를 레벨 차례로 든다(`costs[i]` 는 Lv.(i+1) 에서 Lv.(i+2)). 심볼 key 는 `hunting-grounds.json` 의 지역 `key` 를 그대로 쓰고, `icon` 은 `src/assets/items/` 의 심볼 그림 파일이다. 표 전체의 `from` 은 `2026-09-17` 이고, 적는 날짜가 든 주간 기간이 그 날보다 앞서면 타일이 안 선다. 옮겨 적은 값은 테스트가 모양으로 지킨다. 길이, 한 심볼 안에서 레벨마다 커지는지, 같은 단계에서 심볼 차례대로 커지는지다.
- **`enhancement-prices.json`** ([[ADR-223]] 정정 1 · 13 · 14, [[ADR-300]]): 강화 1회의 메소 비용. 큐브 감정비용 식 · 잠재 재설정 표(레벨 구간 × 등급) · 스타포스 식 · **소울 잠재능력 재설정 표(등급 넷, 레벨 무관, 2026-09-19 사용자 제공)** 를 든다. 소울 표의 `from`(`2026-09-17`)은 패치 날짜이고, 그 전 날짜는 소울 사용 내역을 안 부른다. 재설정 비용은 **누르기 전 등급**으로 매기고 그 등급은 응답의 사용 전 옵션에서 읽는다(응답의 등급 칸은 오른 뒤 값이다).
- **`mvp-grades.json`** ([[ADR-306]] 결정 1): MVP 등급 일곱(일반 · 브론즈 · 실버 · 골드 · 다이아 · 레드 · 블랙)의 경매장 수수료(%)와 스타포스 할인(%). 값은 사용자 확인(2026-09-22)이고 표는 ADR 결정 1 에 있다. 스타포스 할인을 이벤트 할인과 어떻게 겹치는지(곱연산)는 수치가 아니라 식이라 `lib/enhancement/cost.ts` 가 갖는다([[ADR-306]] 결정 5).
- **`equipment-items.json`** ([[ADR-223]]): 강화 비용을 매길 장비 표. 467줄이 `key` · `name`(붙여 쓴 이름) · `group` · `level`(착용 레벨)을 든다. 스타포스 응답에 `item_level` 이 없어 이 표가 레벨을 준다. 이름과 레벨은 사용자 제공이거나 넥슨 히스토리 API 가 준 값이고 출처는 파일의 `source` · `note` 에 있다. 강화할 수 없는 장비는 담지 않는다. **이 파일이 장비 마스터 표다**([[ADR-280]] 결정 14, 2026-09-15, 이슈 #446). 기록(`enhancement_history.item_key`)이 key 로 가리키고 조회는 `lib/equipment/equipment-items.ts` 하나다. 이름은 붙여 쓴 채 두고, 화면은 기록의 API 이름을 보인다. 드롭 아이템 표(`drop-items.json`)와 key 가 어긋났던 같은 장비 9개는 드롭 표 key 로 맞췄고, 두 표의 같은 이름이 같은 key 인지 `equipment-items.spec.ts` 가 지킨다. 한 번 기록에 저장된 key 는 바꾸지 않는다.
- **`valuable-drops.json`** ([[ADR-038]], [[ADR-040]]): 고가 아이템 리스트(칠흑·광휘 세트 + 연마석 2종 + 칠흑 장신구 상자 + 익셉셔널 해머). 세트 key + 아이템 key 기준으로 수정 용이. `isValuableDropItem` 판정·고가 드롭 강조 연출에 사용.
- **`worlds.json`** ([[ADR-006]], [[ADR-280]] 결정 15, 2026-09-15, 이슈 #446): **월드 마스터 표다.** 19줄이 월드 key · `name`(API `world_name` 표기, 보이는 이름) · `emblem`(엠블럼 파일 basename) · `challengers` · `event` 를 든다. 기록 · 원장 · 판정은 월드 key 로 이 표를 가리키고, 조회는 `lib/world/worlds.ts` 하나다. 챌린저스 넷(`challengers` · `challengers_2` · `challengers_3` · `challengers_4`)은 월드마다 key 이고 엠블럼 `challengers` 만 같이 쓴다. `challengers` 칸이 시즌 보스 표시와 월드 리프 판정을 정하므로, 새 챌린저스 월드가 열리면 이 표부터 고친다(이름 앞부분으로 가리지 않는다, 사용자 결정). 이벤트 월드 `스페셜`(`special`)은 엠블럼이 없고 `event` 칸으로 강화 지출에서 빠진다. 표에 없는 월드는 생기지 않는다(사용자 확인).
- **`hunting-grounds.json`** ([[ADR-175]] 결정 2): 사냥터 참조표: **지역 21개(아케인 리버 12 · 그란디스 9) · 사냥터 408개**, 2026-08-28 사용자 제공. 사냥터마다 `force`(아케인/어센틱 포스 요구치) · `mobs`(맵 몬스터 마릿수) · `levels`(몬스터 레벨). `levels` 가 **배열**인 이유는 원 자료가 ‘lv.200-201’(붙은 둘)과 ‘lv.217,219’(떨어진 둘)를 둘 다 쓰기 때문이고, 셋 이상인 맵은 없다(408개 실측 · 레벨이 둘인 맵 52개). 지역과 사냥터가 `key` 를 들고, **사냥터 key 가 전역 유일**이라 기록에 지역을 안 적고 key 로 되짚는다([[ADR-280]] 결정 10, 2026-09-15, 이슈 #443). 사냥터 key 는 `지역 key_번역` 이다([[ADR-280]] 결정 9). 이름도 전역 유일이고(중복 0), 이름으로 찾는 `findHuntingGroundByName` 은 이름만 든 옛 기록을 옮기는 이관만 쓴다. 지역의 `minLevel`·`maxLevel` 은 **추천 캐릭터 레벨**이고 그 안의 몬스터 레벨과 **다르다**. 리버스 시티는 205-209 로 적혀 있지만 몬스터가 213 까지 있다. 그래서 지역 목록을 거르는 근거는 이 칸이 아니라 **사냥터의 몬스터 레벨**이다([[ADR-175]] 결정 6, `lib/cashbook/hunting-grounds.ts` 의 `monsterLevelRangeOf`). 지역 `slug` 는 `assets/maps/icons/` 의 기존 지역 슬러그를 그대로 쓴다. 지금은 아이콘을 안 그리지만 이름이 갈리면 표가 하나 더 생긴다. 계산에 쓰는 상수(분당 8젠 · 몬스터 레벨 × 7.5 · 레벨 차이 페널티 표 둘 · 아이템 증가율 둘)는 **JSON 이 아니라 `lib/cashbook/hunting-meso.ts`** 에 산다. 맵마다 다른 값이 아니라 게임 전체의 규칙이라서다. 그 값들도 전부 사용자 제공이고, 페널티 표 둘은 합이 각각 80·70 이라 **정확히 −100% 에서 끝나는지**를 테스트가 지킨다(옮겨 적다 틀리면 거기서 잡힌다).

## UI 표시 전용 설정 파일 ([[ADR-006]] 대상 아님: 게임 수치 아님)
게임 밸런스/수치가 아니라 화면 크롭 파라미터이므로 사용자가 이미지 넣을 때마다 직접 조정(디버그 프리뷰에서 값 복사).
- **`boss-portrait-crops.json`** ([[ADR-018]]): 보스 스케줄러 새 보스 카드 bleed 일러스트의 `portraitSlug → { size, position }`(CSS background-size/position). 매핑 없으면 cover/center. 값 조정은 전용 디버그 화면에서 눈으로 맞췄고, 그 화면은 조정을 마치고 삭제했다(ADR-092: 다시 만질 일이 생기면 복원 선행). `bellona` 두 항목은 2026-08-19 사용자가 직접 채웠다([[ADR-151]]). **같은 날 카링 일러스트가 960×873(불투명) → 422×500(알파) 로 교체되면서 카링 크롭도 함께 바뀌었다**. 원본이 코퍼스 규격(422×500, 벨로나·유피테르와 동일)으로 내려오며 필요한 확대가 줄었다(카드 `200% auto` → `90% auto`, 원형 `800% auto` → `250% auto`). 원형 확대 800% 는 이 파일에서 유일한 극단값이었고 그 원인이 일러스트 규격이었다. 찬란한 흉성 원형 확대도 같은 날 210% → 250% 로 조정됐다(위치는 그대로). 주간 콘텐츠 카드 배경(에픽 던전 3종·길드 지하수로)도 이 파일 재사용([[ADR-021]]). **아우룸 레기스(`lesa`)도 한 줄을 갖는다**(2026-09-12). 시작값은 `100% auto` · `50% 35%` 이고 사용자가 카드를 보며 맞춘다. 값이 `숫자% auto` · `숫자% 숫자%` 형식이 아니면 읽히지 않고 `cover` 로 떨어진다(`lib/image-crop.ts`).
- **`boss-portrait-icon-crops.json`** (2026-07-14): `BossPortrait`(원형 아이콘, 보스 수익 화면)의 크롭. 형식은 위와 동일하나 값은 공유하지 않는 별도 파일(원형/사각형은 이상적 크롭이 다름). 조정 화면은 ADR-092 에서 삭제.
- **`daily-quest-region-crops.json`** ([[ADR-020]]): 지도 배경 슬러그(템플릿 줄의 `background.map`) → `{ size, position }`. 조정 화면은 ADR-092 에서 삭제. 길드 미션 포인트(`hallOfHeroes`)·플래그 레이스(`flagRace`, jpg)도 추가([[ADR-021]]).
- **`job-themes.json`** ([[ADR-009]], [[ADR-064]], [[ADR-104]]): 테마별 38토큰 컬러 + `mode` + 선택 `background` + **`category`**(기본/직업/보스: 소속은 게임 도메인이라 사용자 확인으로 정한다) → [features/theme.md](../features/theme.md).
