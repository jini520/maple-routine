# 서버 전송

앱이 기기 기록에서 뽑아 서버로 올리는 값과 서버에서 받아 기기에 넣는 값을 정리한다. 사용자의 기록은 바뀔 때마다 대기 표
(`server_sync_queue`)에 들어간다. 한 번의 동기화가 그 표를 `POST /v1/sync/push` 로 올린 뒤 `POST /v1/sync/pull` 로 다른 기기가
올린 기록을 받는다. 그 밖에 서버가 이 기기의 넥슨 계정을 알게 하는 일(메이플 ID 알리기 · 부계정 등록과 해제), 강화 합계에서 빠진
줄의 상황 알림([[ADR-102]]), 앱 사용 로그([[ADR-158]])를 보낸다. 누구의 값으로 받는지는 [[ADR-017]] 에, 사용자가 만든 기록을 서버에
두고 같은 사람의 기기끼리 맞추는 결정은 [[ADR-099]] 에 있다.

서버로 보내는 넥슨 식별자(ocid · 메이플 ID)는 원문이 아니라 SHA-256 해시다. 서버에는 넥슨 식별자의 원문을 두지 않는다([[ADR-017]]
결정 11). 기기에는 원문을 둔다.

앱은 드롭 판매가를 따로 보내지 않는다. 1.0.15 서버에는 드롭 판매가 경로(`/v1/drop-prices`)도 과거 드롭 묶음 경로도 없다. 드롭은
기기 간 동기화의 올리기로 올라가고, 서버가 드롭을 받을 때 시세에 쓰는 판매가 줄을 적는다([[ADR-099]] 결정 2 · 26). 1.0.15 서버(서버 develop)는 받기 · 올리기 ·
데이터 삭제 경로를 갖췄고([[ADR-099]] 결정 66) 앱은 지금 올리기와 받기를 부른다. 앱이 부르는 방법과 구현 차례는 [[ADR-099]] 결정 67 에
있고, 차례마다 이 문서를 구현한 모양으로 고친다.

## 신원

쓰기 요청에는 메인 신원 하나를 싣는다([[ADR-099]] 결정 67, [[ADR-017]] 결정 5).

| 경우 | 싣는 헤더 |
|---|---|
| 넥슨 로그인 세션이 있다 | `Authorization: Bearer <세션>`. 세션은 그 로그인에 등록한 부계정의 메이플 ID 까지 쓸 수 있어, 부계정 키의 신원으로 따로 보내지 않는다 |
| 로그인 없는 키만 있다 | `x-maple-id-hash`. 메인 키의 넥슨 계정에서 본 메이플 ID(`character_accounts`) 가운데 정렬해 맨 앞의 것의 해시다. 같은 키로 늘 같은 값을 보내야 서버가 넥슨 계정 줄을 새로 만들었다가 합치지 않는다 |
| 둘 다 없거나 본 메이플 ID 가 없다 | 보내지 않는다(`serverIdentityHeaders` 가 `null`) |

- 키 해시(`x-api-key-hash`)는 싣지 않는다. 1.0.15 서버는 받지 않는다.
- 메이플 ID 는 기기 변환을 기다리지 않고 읽는다(`getMapleIdsOfNexonAccountUngated`). 변환이 실패한 실행에서도 사용 로그를 보내야
  하기 때문이다([[ADR-286]] 결정 1).
- 기기가 만든 넥슨 계정 id 는 싣지 않는다. 기기마다 다른 값이라 서버가 읽지 않는다([[ADR-099]] 결정 6).

## 언제 보내나

| 사용자 동작 · 앱 일 | 보내는 것 |
|---|---|
| 앱을 켬 | 메인 계정의 메이플 ID 를 알리고 지금 로그인의 부계정 키를 등록한 뒤, 대기 표를 올리고 받는다 |
| 스케줄 회차가 넥슨에서 받음 | 동기화를 깨운다. 회차는 동기화를 기다리지 않고 받은 스케줄로 화면을 먼저 그린다. 배경 실행(`schedule-alert/background-refresh.ts`)의 회차와 하나도 받지 못한 회차는 깨우지 않는다 |
| 기록을 씀 | 동기화를 깨워 대기 표를 올리고 받는다. 기록 판을 올리는 저장 함수는 판 알림으로, 그 밖의 저장 함수와 Preferences 기록은 `noteRecordsWritten` 으로 알린다. 반복 쓰기 안의 여러 쓰기는 한 번으로 모은다. 동기화가 화면을 다시 읽으려고 올린 판은 깨우지 않는다 |
| 부계정 키 추가 · 변경 | 저장하기 전에 그 키의 메이플 ID 해시로 부계정을 등록한다 |
| `API 키 삭제` | 기기에서 지우기 전에 그 계정의 메이플 ID 해시로 부계정 등록을 해제한다 |
| 로그아웃 | 대기 표와 사용 로그 표를 비운다. 서버에는 알리지 않는다 |
| 계정 삭제 | 서버에 삭제를 예약하고(30일 뒤 지우고, 보낸 기록은 익명으로 남는다), 대기 표와 사용 로그 표를 비운다 |

- 결과를 기다리지 않는 전송(동기화 · 사용 로그)은 실패해도 사용자에게 알리지 않는다. 올리기의 두 거절(`duplicate_record` ·
  `record_deleted`)만 알린다(`거절 알림`). 설정에서 전송을 끌 수는 없다.
- 동기화는 한 번에 하나만 돈다(`kick.ts`). 두 동기화가 겹치면 같은 줄을 두 번 보내고, 받은 줄을 넣는 사이에 다른 받기가 번호를
  앞질러 적는다.

## 계정 알리기와 부계정

서버는 기록의 메이플 ID 가 보낸 신원이 쓸 수 있는 것일 때만 적는다. 그래서 동기화마다 기록보다 먼저 계정을 알린다([[ADR-101]] 결정 14 ·
25).

- 메이플 ID 알리기(`PUT /v1/me/maple-ids`)는 메인 신원으로 메인 계정의 메이플 ID 해시만 보낸다. 서버가 마지막으로 돌려준 목록에 다
  있으면 보내지 않는다. 부계정의 메이플 ID 는 등록이 알린다.
- 부계정 등록(`POST /v1/me/sub-accounts`)과 해제(`DELETE /v1/me/sub-accounts`)는 세션으로 그 키의 메이플 ID 해시만 보낸다. 키 해시는
  보내지 않는다([[ADR-101]] 결정 6).
- 동기화는 지금 로그인의 부계정 키 가운데 등록한 적이 없는 키를 등록한다. 등록했거나 같은 넥슨 ID 라고 거절된(`same_account`) 키는
  Preferences `serverAccounts` 에 `로그인 계정 id:키 해시` 로 적어 다시 보내지 않는다. 그 밖의 거절과 응답이 없는 것은 적지 않아
  다음 동기화가 다시 보낸다.
- 부계정을 지우면 서버가 해제를 받은 뒤에 기기의 키와 그 적은 값을 지운다. 해제를 받지 못하면 아무것도 지우지 않는다.
- 키 사용자가 넥슨 로그인을 붙이면 같은 메이플 ID 의 키를 서버에 알리지 않고 기기에서 거둔다. 로그인 세션의 메이플 ID 알리기가 서버의
  두 넥슨 계정 줄을 합친다([[ADR-017]] 결정 9, [[ADR-025]] 결정 4).

## 강화 합계에서 빠진 줄

수집기가 합계에서 빼거나 이벤트 월드를 판정하지 못한 줄을 날짜 · 종류 · 이유 · 장비마다 세어 회차 동안 모았다가, 회차가 끝날 때
`POST /v1/enhancement-anomalies` 로 한 번 보낸다(`features/enhancement-history/anomalies.ts`). 기록이 아니라 운영자가 예상하지 못한
상황을 보는 값이라 대기 표를 거치지 않고, 실패하면 버린다. 캐릭터 이름은 싣지 않는다. 장비 표에 없는 장비의 스타포스는 시도 뒤
10성 이상인 줄만 센다. 이유와 서버 표는 [[ADR-102]] 에 있다.

## 사용 로그

방문 · 화면 · 동작 사건을 기기의 SQLite 표 `usage_events` 에 쌓았다가, 앱이 백그라운드로 갈 때와 다음에 앱을 켤 때 묶어
`POST /v1/usage-events` 로 보낸다(`features/usage-log/`). 화면을 옮길 때마다 보내면 요청이 사용자 동작 수만큼 늘어서다.

| 사건 | 언제 적나 |
|---|---|
| 방문(`visit`) | 앱을 새로 열 때, 백그라운드에 30분 넘게 있다 돌아올 때. OS 가 앱을 배경에서 띄운 실행은 처음 앞으로 나올 때 적는다. 사용자가 열지 않은 실행이 방문자로 잡히지 않게 하려는 것이다 |
| 화면(`screen`) | 보이는 화면이 바뀔 때. 떠날 때 머문 시간을 적고, 백그라운드에 있던 시간은 뺀다. 앱을 새로 열 때 진입 단계를 읽기 전에 서 있는 로그인 화면은 적지 않는다 |
| 동작(`action`) | 드롭 · 판매가 저장(`drop-save`), 가계부 수입 · 지출 추가(`cashbook-add`) |

- 묶음에 플랫폼과 앱 버전을 싣는다. 캐릭터 · 월드 · 기록의 값은 싣지 않는다.
- 꺼낸 묶음은 기기 표에서 지우고 보낸다. 실패하면 버리고 다시 보내지 않는다. 대기 표를 거치지 않는다.
- 기기 표는 500 건이 상한이다. 신원이 없으면 보내지 않고 두며, 넘치면 오래된 것부터 지운다.
- 로그아웃 · 계정 삭제 때 기기 표를 비운다. 끌 수는 없다.
- 서버는 사건 하나를 줄 하나로 두고 180일 뒤 지운다. 관리자 화면은 대시보드 두 장이다. `사용자` 는 사람 수와 그 일별 ·
  요일별 증감을, `사용 로그` 는 방문 · 화면 조회 · 동작 횟수와 화면별 방문자 · 체류 시간을 차트로 보인다. 일별 막대 아래에는
  그 날 보낸 앱 공지 · 게임 알림 수가 놓인다([[ADR-158]] 결정 4 ~ 8).

## 대기 표에 넣기

기록이 바뀌면 대기 표(`server_sync_queue`)에 서버 표 이름(`record_type`, [[ADR-099]] 결정 66)과 기록 id(`record_id`)가 들어간다
([[ADR-099]] 결정 67). 값은 담지 않는다. 올리기가 원본의 지금 값을 읽고, 원본이 없으면 지우기를 보낸다. 한 기록에 줄은 하나이고, 이미 있으면
그대로 둔다. 넣은 차례는 표의 rowid 다.

| 기록 | 넣는 쪽 | `record_type` | `record_id` |
|---|---|---|---|
| SQLite 기록 표 열다섯(보스 셋 · 가계부 여섯 · 인벤토리 · 강화 합계 · 강화 조회 기록 · 강화 레벨 기억 · MVP 등급 · 월드 리프) | 트리거(`storage/sqlite/server-sync-triggers.ts`) | 서버 표 이름. 가계부의 딸린 줄 다섯은 `cashbookEntries`, 강화 조회 기록은 `enhancementSettledDays` | 줄의 id. 가계부의 딸린 줄은 기록의 id |
| Preferences 의 약속 · 계산기 기록 | 저장 함수 | `partyAppointments` · `bossProfitCalculatorRecords` | 기록의 id |
| Preferences 의 수동 추적 항목 · 공유 진행 · 메이플 ID 이름 · 추적 캐릭터와 대표 · 대표 캐릭터 동작 | 저장 함수 | `manualTrackedItems` · `sharedContentProgress` · `mapleIdNames` · `trackedCharacters` · `representativeCharacterMotions` | `표 이름:유일 기준의 값`. 값은 `/` 로 잇는다(`manualTrackedItems:{ocid}/{type}/{targetId}`) |
| Preferences 의 설정 일곱 키 | 저장 함수 | `accountSettings` · `bottomBarSubPageOrders` | `accountSettings:{칸 이름}` · `bottomBarSubPageOrders:{그룹}`. 서버가 실은 칸과 그룹만 고쳐서 칸마다, 그룹마다 넣는다 |

- 트리거는 줄을 넣거나, 서버로 가는 칸의 값을 바꾸거나, 줄을 지울 때 넣는다. 기기만 쓰는 칸(수익 건의 `over_crystal_sale_limit`)만
  고쳤거나 같은 값을 다시 적은 쓰기는 넣지 않는다. 강화 조회 기록은 굳은 날(`settled` 1)이 된 줄만 넣는다.
- 트리거는 1.0.15 기기 변환을 마친 DB 에만 있다. 변환이 끝난 직후와 변환을 마친 DB 를 열 때 걸고, 정의가 바뀌었으면 다시 만든다.
  변환이 옮긴 줄은 처음 동기화가 넣는다.
- Preferences 기록의 저장 함수는 앞 값과 새 값을 견주어 바뀐 항목만 넣는다. 로그인할 때 추적 목록과 대표를 비우는 일은 넣지 않는다.
  넣으면 새 기기의 로그인이 서버의 추적 목록을 지운다.
- 한 줄짜리 표 `server_sync_pause` 에 줄이 있으면 트리거와 Preferences 넣기가 넣지 않는다. `withServerSyncPaused` 가 트랜잭션 안에서
  그 줄을 넣고 일을 마치면 뺀다. 받은 줄을 넣거나 올리기의 결과로 기기 줄을 고칠 때 쓴다.
- 데이터 삭제는 기록 그룹을 하나라도 고르면 대기 표를 비운다. 지운 기록의 지우기가 대기 표에 들어가도 함께 비워진다.
- 로그아웃 · 계정 삭제도 대기 표를 비운다. 누가 만든 줄인지 적혀 있지 않아, 남기면 다음에 다른 키로 로그인한 사람의 신원으로 나간다.

1.0.14 에서 올라온 기기의 대기 표는 기기 변환이 비우고, 과거 드롭을 어디까지 올렸는지 적던 Preferences `serverBackfill` 도
지운다([[ADR-286]] 결정 8).

## 올리기

동기화가 계정을 알린 뒤 대기 표를 올린다(`push.ts`, [[ADR-099]] 결정 67). 신원이 없으면 아무것도 하지 않는다.

1. 대기 줄을 [[ADR-099]] 결정 66 의 표 차례(`SERVER_SYNC_TABLES`)로, 같은 표 안에서는 넣은 차례로 늘어놓는다.
2. 줄마다 원본의 지금 값을 읽어 서버 칸으로 바꾼다(`push-records.ts`). 원본이 없으면 지우기를 싣는다. 지우기가 없는 표(굳은 날 ·
   하위 페이지 차례)는 대기 줄만 지운다.
3. 한 요청은 100건과 본문 256KB(`JSON.stringify` 의 UTF-8 바이트)를 넘지 않는다. 수익 건과 드롭, 인벤토리와 가계부 기록은 한 요청에
   함께 싣지 않는다. 서버가 수익 건이나 인벤토리 줄을 다른 줄로 합치면 받은 id 의 줄을 지워서, 같은 요청의 드롭이 그 id 를 가리키면
   거절되기 때문이다.
4. 결과를 다루고, 남은 줄로 다음 요청을 만든다.

| 서버 칸 | 기기 값 |
|---|---|
| `mapleId` · `ocid` 와 다른 캐릭터를 가리키는 칸 | 원문의 SHA-256. `#` 로 시작하는 값은 이미 해시라 `#` 만 뗀다 |
| 캐릭터 기록의 `mapleId` | `character_accounts` 에서 그 ocid 를 가장 늦게 본 소속의 메이플 ID. 모르면 보내지 않고 대기 표에 둔다 |
| 가계부의 `transferInput.receiverMapleId` | 받는 캐릭터의 메이플 ID. 받는 캐릭터는 다른 메이플 ID 의 캐릭터일 수 있다 |
| 굳은 날의 `mapleId` | 기기의 넥슨 계정 id 로 그 계정에서 본 메이플 ID 를 찾아 정렬해 맨 앞의 것 |
| 참 거짓 칸 | SQLite 의 1 · 0 을 `true` · `false` 로 |
| 수익 건 | 서버가 난이도에서 채우는 보스 줄과 기기만 쓰는 `over_crystal_sale_limit` 은 싣지 않는다 |
| 빈 칸 | 뺀다. 설정은 바뀐 칸 하나를 빈 값이어도 싣는다. 빠진 칸은 고치지 않는다는 뜻이다 |

| 결과 | 대기 줄 · 기기 줄 |
|---|---|
| 받았다 | 대기 줄을 지운다. 보낸 뒤에 원본이 또 바뀌었으면 남긴다. 서버가 돌려준 id 가 다르면 기기 줄과 그 줄을 가리키는 줄, 대기 줄을 그 id 로 바꾼다 |
| `duplicate_record` · `record_deleted` | 대기 줄과 기기 줄을 지우고 알린다 |
| `maple_id_not_registered` · 코드 없는 거절 | 횟수를 센다. 다섯 번째면 대기 줄을 뺀다. 기기 줄은 둔다. 그 동기화에서는 다시 보내지 않는다 |
| 응답이 안 왔다 · 요청 전체가 거절됐다(401 · 403 · 400 · 413 · 500 · 읽을 수 없는 본문) | 아무것도 세지 않고 그 동기화의 올리기를 멈춘다. 받기는 한다 |
| 메이플 ID 를 모른다 | 보내지 않고 세지 않는다 |

- 기기 줄을 고치고 지우는 일은 넣지 않는 동안(`withServerSyncPaused`)에 한다. 서버가 이미 아는 값이라 다시 올리지 않는다.
- 응답이 왔는지로 횟수를 가르는 이유는 [[ADR-099]] 결정 10 에 있다. 비행기 모드로 앱을 다섯 번 켠 사용자가 그동안 쌓인 것을 잃지
  않게 하려는 것이다.

## 거절 알림

사용자가 적은 기록이 `duplicate_record` 나 `record_deleted` 로 거절되면 올리기가 끝날 때 토스트로 알린다(`rejection-notice.ts`,
[[ADR-099]] 결정 10). 문구와 기록 이름은 그 결정의 표에 있다.

- 거절마다 한 장이다. 한 건이면 기록 이름을 넣고, 여러 건이거나 이름의 재료가 기기에 없으면 `기록 N건은` 으로 쓴다.
- 입력이 저장되지 않았다는 알림이라 오류 토스트로 띄운다. 다른 저장 실패처럼 사용자가 닫을 때까지 남는다.
- 보스는 처치를 적는 보스 수익 화면과 같은 정식 이름(`bossNameOf`)으로 부른다. 짧은 이름은 어느 줄인지 찾기 어렵다.
- 넥슨에서 받아 기기가 스스로 적는 기록(자동으로 적은 처치 · 강화 합계 · 공유 진행 · 기억한 레벨)은 알리지 않는다.
- 처음 동기화의 거절은 알리지 않는다. 올리기를 `notify: false` 로 부른다.

## 받기

올리기 다음에 `POST /v1/sync/pull` 로 다른 기기가 올린 기록을 받는다(`pull.ts`, [[ADR-099]] 결정 9 · 67). 올리기가 멈춰도 받는다.
아직 못 올린 기록은 대기 줄이 있어 받기가 건너뛴다. 신원이 없으면 아무것도 하지 않는다.

1. `#` 를 붙여 넣은 값 가운데 `character_accounts` 에 짝이 생긴 것을 원문으로 바꾼다(`짝이 생긴 # 바꾸기`).
2. Preferences `serverSyncCursors` 의 번호를 보낸다. 사람(넥슨 계정 줄 id 와 번호)과 메이플 ID 해시마다의 번호다. 처음이면 빈 번호다.
3. 첫 응답의 메이플 ID 목록에서 앞 받기의 목록에 있던 메이플 ID 가 빠졌으면 그 부계정을 이 기기에서 뺀다(`다른 기기의 부계정 해제`).
   응답의 `oldestDeletedChangeSeq` 보다 보낸 번호가 작은 주인이 있으면(번호 0 은 빼고) 그 주인의 기록을 비우고 번호를 0 으로 적은 뒤
   다시 받는다. 그 응답의 줄은 넣지 않는다.
4. 받은 줄을 표 차례대로 기기 칸으로 바꿔(`pull-records.ts`) 넣는다.
5. 응답의 `cursors` 를 적는다. `hasMore` 가 켜져 있으면 2 로 돌아간다. 번호가 그대로면 멈춘다. 한 동기화는 100쪽(5만 줄)까지
   받고, 남은 줄은 다음 동기화가 이어 받는다.
6. 넣은 표의 화면을 다시 읽게 한다(`refresh.ts`).

응답이 없거나 요청 전체가 거절되면(401 · 403 · 400 · 500 · 읽을 수 없는 본문) 번호를 두고 멈춘다. 다음 동기화가 같은 번호로 받는다.

### 넣는 규칙

- 줄 하나를 트랜잭션 하나로 넣는다(`withServerSyncPaused`). 트리거와 Preferences 넣기가 대기 표에 넣지 않아 받은 줄을 다시 올리지
  않는다. 기기 표의 CHECK 에 걸리는 줄은 그 줄만 건너뛴다. 한 줄 때문에 받기가 멈추면 번호가 오르지 않아 같은 줄에서 계속 멈춘다.
- 대기 표에 같은 기록이 있으면 넣지 않는다. 아직 못 올린 기기 값이 다음 올리기로 서버를 덮는다. id 가 없는 Preferences 기록은
  대기 줄 id(`표 이름:유일 기준의 값`)로 견준다.
- 기기 표의 유일 기준이 같고 id 가 다른 기기 줄은 서버 줄로 바꾼다. id 와 값, 그 줄을 가리키는 줄(드롭의 수익 건 · 가계부 품목의
  인벤토리 줄 · 가계부의 딸린 줄)을 서버 id 로 바꾸고, 기기 줄의 대기 줄을 뺀다. 서버 id 의 줄이 기기에 따로 있으면 겹친 기기 줄을
  지우고 그 줄을 가리키던 줄을 서버 id 로 옮긴다.
- `deletedAt` 이 찬 줄은 기기에서 지운다. 수익 건을 지우면 드롭도 외래키를 따라 지워진다. 지운 굳은 날은 기기의 조회 기록 줄을 지운다.
  굳은 표시만 내리면 조회 기록의 커서가 같아 넥슨을 다시 불러도 합계를 다시 적지 않는다.
- 가리키는 수익 건이 기기에 없는 드롭은 넣지 않는다. 가계부 품목이 가리키는 인벤토리 줄이 없으면 비운다.
- 같은 줄이 두 번 와도 한 번 넣은 것과 같다.

| 기기 칸 | 서버 값 |
|---|---|
| ocid · 메이플 ID 와 다른 캐릭터를 가리키는 칸 | 해시를 `character_accounts` 의 원문을 해시한 값과 맞춰 원문으로. 짝이 없으면 `#` 를 붙인 해시 |
| 추적 캐릭터 · 대표 | 짝이 없으면 넣지 않는다. 그 기기에 부를 키가 없는 캐릭터다([[ADR-099]] 결정 15) |
| 가계부 기록의 `ocid` · `account_id` | 캐릭터 기록이면 ocid 만 적고 `account_id` 는 비운다. 메이플 ID 기록이면 `account_id` 만 적는다 |
| 참 거짓 칸 | `true` · `false` 를 1 · 0 으로 |
| 강화 합계의 `superior_cost_meso` | 빈 값은 0 |
| 수익 건의 `over_crystal_sale_limit` | 기기만 쓰는 칸이라 있던 값을 둔다 |
| 가계부의 이전 · 환전 입력 | 기기가 비울 수 없는 칸이 비었으면 그 입력 줄만 넣지 않는다 |
| 굳은 날의 `nexon_account_id` | 메이플 ID 를 `character_accounts` 에서 찾은 넥슨 계정 id. 짝이 없으면 넣지 않는다 |
| 공유 진행의 `nowCount` · `maxCount` | 빈 값은 0 |
| 추적 목록 | 받은 `sortOrder` 로 다시 놓는다. 받지 않은 캐릭터는 지금 자리를 차례로 쓴다. 대표 표시가 참이면 대표로, 거짓인데 지금 대표면 대표를 지운다 |
| 설정 | 칸마다 넣는다. 대기 줄이 있는 칸과 빈 칸은 두고, 참 거짓 칸의 거짓은 키를 지운다(저장 함수와 같다) |

### 넥슨에 `#` 를 보내지 않는다

`#` 로 시작하는 ocid 는 해시라 넥슨 식별자가 아니다. 캐릭터마다 넥슨을 부를 자격을 고르는 `credentialsOfOcids` · `credentialOfOcid`
가 그 ocid 에 자격을 주지 않는다. 기록의 ocid 로 넥슨을 부르는 곳(처치 날짜 채우기 · 강화 레벨 기억 · 메소 획득량 · 스케줄 창)은 모두
이 함수로 자격을 받아 자격이 없으면 부르지 않는다. 추적 캐릭터는 `#` 가 될 수 없어(받기가 넣지 않는다) 회차의 넥슨 조회에 들지 않는다.

### 짝이 생긴 `#` 바꾸기

다른 기기에서 받은 캐릭터와 메이플 ID 가 이 기기의 `character_accounts` 에 없으면 `#` 를 붙인 해시로 적는다. 부계정 키를 등록하거나 넥슨
목록이 늘면 짝이 생긴다. 받기를 시작할 때마다 기기의 `#` 값을 훑어 짝이 생긴 값만 원문으로 바꾼다(`replaceMatchedNexonIds`).

- SQLite 기록 표의 ocid · 메이플 ID 칸과 Preferences 기록(수동 추적 항목 · 공유 진행의 키, 메이플 ID 이름 · 대표 캐릭터 동작의 열쇠,
  약속 · 계산기 기록의 `ocid`)을 바꾼다.
- 서버는 같은 해시를 이미 들고 있어 바꾸는 쓰기는 대기 표에 넣지 않는다(`withServerSyncPaused`). Preferences 기록은 저장 함수를
  거치지 않고 키에 바로 적는다.
- 원문으로 바꾸면 유일 기준이 겹치는 기기 줄이 있으면 그 줄은 두고, 같은 받기가 서버 줄을 넣을 때 겹친 기기 줄을 서버 줄로 바꾼다.
  Preferences 의 키와 열쇠가 겹치면 원문 쪽 항목을 두고 원문 쪽에 없는 항목만 옮긴다. 원문 쪽은 이 기기에서 고른 값이다.
- 바꾼 표의 화면을 다시 읽게 한다.

### 다른 기기의 부계정 해제

해제는 서버가 기준이다([[ADR-101]] 결정 6). 다른 기기에서 부계정을 해제하면 다음 받기의 응답의 메이플 ID 목록에서 그 메이플 ID 가
빠진다. 이 기기는 그 메이플 ID 를 든 부계정 키를 지우고 그 계정의 캐릭터를 추적에서 뺀다(`forgetReleasedSubAccounts`). 서버의 등록은
이미 없어 해제를 부르지 않는다. 남기면 동기화가 그 키를 다시 등록해 해제를 되돌린다.

- 앞 목록은 번호(`serverSyncCursors`)의 메이플 ID 열쇠다. 서버는 이 신원이 쓸 수 있는 메이플 ID 마다 번호를 돌려준다.
- 번호의 넥슨 계정 줄이 응답과 같을 때만 견준다. 다른 사람으로 로그인했거나 줄이 합쳐졌으면 목록이 바뀌는 것이 해제가 아니다.
- 키는 지금 로그인에 귀속된 부계정 키만 본다. 메이플 ID 는 `character_accounts` 에서 그 키의 넥슨 계정으로 찾는다.
- 그 메이플 ID 의 기록은 아직 이 기기에 남는다. 비우는 일은 [[ADR-099]] 결정 67 의 구현 차례 다섯째다.

### 주인의 기록 비우기

받은 지 180일이 넘어 서버가 지운 표식을 놓친 주인의 기록을 비운다(`clearServerSyncOwners`). 대기 표에 남은 기록은 비우지 않는다.

| 주인 | 비우는 것 |
|---|---|
| 메이플 ID | 그 메이플 ID 의 캐릭터(`character_accounts`)의 보스 기록 셋 · 강화 합계 · 레벨 기억 · 리프 · 가계부 기록, 그 메이플 ID 의 가계부 기록 · 인벤토리 · MVP 등급, 그 넥슨 계정의 굳은 날(조회 기록 줄), Preferences 의 수동 추적 항목 · 공유 진행 · 메이플 ID 이름 · 대표 캐릭터 동작 |
| 사람 | 추적 목록과 대표 · 약속 · 계산기 기록. 설정과 하위 페이지 차례는 삭제 표식이 없어 비우지 않는다 |

- `#` 로 적은 캐릭터의 기록은 어느 메이플 ID 의 것인지 기기가 몰라 비우지 않는다.

### 넣은 뒤 화면

| 표 | 다시 읽는 것 |
|---|---|
| 보스 기록 셋 | 보스 수익 · 드롭 판 |
| 가계부 · 인벤토리 | 수입 · 지출 · 인벤토리 판 |
| 강화 합계 · 굳은 날 | 강화 합계 판 |
| MVP 등급 | 화면이 읽는 등급 문맥(`useMvpGradeStore`), MVP 등급 설정 화면(읽은 적이 있을 때). 자동 수수료는 등급을 바꾼 기기가 다시 세어 올린 값이 함께 와서 다시 세지 않는다 |
| 수동 추적 항목 · 공유 진행 | 컨텐츠 · 보스 스케줄러의 기기 값 |
| 메이플 ID 이름 · 대표 캐릭터 동작 | 그 스토어 |
| 추적 목록 | 추적 목록 쿼리와 대표 |
| 설정 · 하위 페이지 차례 | 추적 방식 · 빠른 이동 · 하단바 순서 스토어, MVP 등급 설정 화면 |
| 약속 | 약속 쿼리와 알림 다시 맞추기 |
| 계산기 기록 | 계산기 스토어 |

- 동기화가 올린 판은 동기화를 다시 깨우지 않는다(`after-write.ts`). 깨우면 바뀐 것이 없는 받기가 한 번 더 나간다.
