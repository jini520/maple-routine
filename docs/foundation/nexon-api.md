# Nexon Open API 연동

> **범위**: Nexon Open API 호출·인증·엔드포인트·정규화·호출 제한. 별도 서버/프록시 없이 사용자 개인 키로 기기에서 직접 호출한다([[ADR-003]], [[ADR-007]]).
> **관련 소스**: `nexon/client` · `nexon/character` · `nexon/schedule`(client/normalize) · `lib/boss-matching`.
> **관련 ADR**: [[ADR-007]] [[ADR-003]] [[ADR-006]] [[ADR-067]] [[ADR-095]]. **관련 문서**: [architecture.md](./architecture.md), [error-resilience.md](./error-resilience.md), [features/content-scheduler.md](../features/content-scheduler.md), [features/boss-scheduler.md](../features/boss-scheduler.md).

## 클라이언트·인증
- 호출 도메인은 **`https://open.api.nexon.com/`**(문서 사이트 `openapi.nexon.com` 과 다름). 모든 요청 헤더에 **`x-nxopen-api-key: <저장된 개인 API 키>`**.
- **타임아웃 10초**(공식 권장값 없어 모바일 관례상 채택, 2026-07-09).
- **호출 제한**: 개발 단계 초당 5건/일 1,000건, 서비스 단계 초당 500건/일 2,000만 건. **정상 사용자는 전부 서비스 단계 키다 — 개발 단계 키는 온보딩을 통과해 살아남을 수 없다**([[ADR-116]] 결정 1, 2026-08-08). 429 를 만나는 자리마다 `removeApiKey()` 로 저장된 키를 지우고 「서비스 단계 키로 다시 입력해주세요」 모달을 거쳐 키 입력 화면으로 되돌리기 때문이다(`features/onboarding/store.ts` 의 `confirmApiKeyNotice`). 그래서 **병렬 호출의 예산은 초당 500건**이고, 여러 캐릭터 동기화 병렬화([[ADR-008]] 2026-07-17 정정)와 날짜 스윕·백필 병렬화([[ADR-148]])가 그 위에 선다.
  - **이 전제를 떠받치는 것은 「429 가 키를 지운다」 하나다.** 사슬은 `useApiKeyNotice` → `noticeApiKeyIssue` → `confirmApiKeyNotice` → `removeApiKey` 이고, 어디든 끊으면 개발 단계 키가 다시 살아남아 **병렬 구조 전체의 근거가 함께 무너진다**. 그 사슬을 만질 땐 위 예산부터 다시 계산할 것.
  - **429 를 만났을 때 화면이 하는 말**은 [[ADR-114]] 결정 1 — 앱은 키의 단계를 **판정하지 않고**(API 가 알려주지 않고 429 만으로는 구분 불가) 단계 무관 문구로 "입력하신 API 키가 서비스 단계 키인지 확인해주세요"를 안내한다. 액션은 자리마다 갈린다([[ADR-116]] 이 [[ADR-114]] 결정 2 를 `ErrorState` 자리에서만 정정했다).
- 별도 서버/프록시 없음 — 키는 기기에만 저장되고 호출도 기기에서 직접 나간다([[ADR-003]]).
- 이용약관 출처 표기: 영문 원문 **"Data based on NEXON Open API"** 를 **설정 화면 하단**(앱 버전·카피라이트와 함께) 상시 노출([[ADR-007]], 앱 전역 footer는 만들지 않음).

## Analytics 스크립트 (데이터 조회 API 아님, [[ADR-095]])
- 넥슨이 개발자에게 제공하는 웹 애널리틱스. `index.html` `<head>` 에 한 줄:
  `<script type="text/javascript" src="https://openapi.nexon.com/js/analytics.js?app_id=322698" async></script>`
- **위 데이터 조회 API와 도메인이 반대다** — 조회는 `open.api.nexon.com`, 이 스크립트는 **문서 사이트 쪽 `openapi.nexon.com`** 에서 받는다.
- **경로는 `/js/analytics.js`** — 가이드 본문 예시(`/analytics.js`)와 다르다. 손으로 옮겨 적지 말고 애플리케이션 상세 하단의 구문을 그대로 쓸 것.
- `app_id` 는 공개 식별자(넥슨 마이 페이지 > 애플리케이션 상세 하단). 사용자 개인 API 키와 층이 다르다 — 그쪽은 기기 보안 영역에만 있다([[ADR-007]]).
- 지표는 "마이 페이지 > Analytics 대시보드". 연동 성립까지 **최대 24시간**, 성립 여부는 애플리케이션 상세 하단의 "연동 완료" 표기로 본다.
- **앱 코드는 이 기능을 모른다** — `analytics.js` 가 정의하는 전역을 아무도 참조하지 않으므로 오프라인·넥슨 장애 시 조용히 실패하고 끝난다. 참조하기 시작하면 넥슨 도메인 가용성이 앱 동작의 의존성이 된다([[ADR-003]]).
- **미확인**: 웹뷰 origin(`https://localhost`·`capacitor://localhost`)에서 연동이 성립하는지. 가이드는 "웹 서비스" 기준이고 origin 언급이 없다.

## 엔드포인트
- **`GET /maplestory/v1/character/list`** (`nexon/character`): 계정 소속 캐릭터 목록. 캐릭터명+월드 수동 입력 폼은 없다. 응답: `{ account_list: [{ account_id, character_list: [{ ocid, character_name, world_name, character_class, character_level }] }] }`. **하나의 키가 여러 `account_id`(메이플 ID)를 반환할 수 있다**(실측, 2026-07-09) — `account_list.length > 1` 이면 계정 선택 UI. `ocid` 는 길이가 계정마다 다르므로(32~65자 관찰) 불투명 문자열로 다룬다. 키가 등록된 Nexon 계정 캐릭터만 반환(다른 계정은 별도 키 필요). **`character_list` 가 빈 계정이 섞여 올 수 있다**([[ADR-127]], 2026-08-12) — 그런 계정은 `normalizeCharacterList` 가 걸러 도메인 모델로 올리지 않는다(캐릭터가 0명이면 대표 캐릭터를 세울 수 없어 계정 선택 화면이 렌더 중에 던졌다). ⚠️ **넥슨이 어떤 조건에서 그 응답을 내는지는 모른다** — 테스터 크래시에서 역산한 것이고 그 응답을 직접 받아 본 적이 없다.
- **`GET /maplestory/v1/character/basic`** (`nexon/character`, ocid별, [[ADR-015]]): 캐릭터 이미지(`character_image`)·`access_flag`·`world_name`·`character_level`·`character_guild_name`. "캐릭터 관리" 피커·아바타에 사용, 병렬 호출. **상시 호출 시점은 둘이다**([[ADR-097]] 결정 7·8) — ① 피커를 열 때 계정 전체 캐릭터(TTL 밖, 현행 유지 · `features/schedule-sync/character-roster.ts`) ② **추적 캐릭터**는 `syncSchedules` 편승(스케줄 동기화가 실제로 도는 회차에만, best-effort · `features/schedule-sync/schedule-sync.ts`). 온보딩의 예열(`features/onboarding/prefetch.ts`)과 계정 후보 판정(`use-account-probes.ts`)도 이 API 를 부르지만 **계정 확정 1회성 경로**라 이 둘에 세지 않는다. ②가 없던 동안 레벨·외형이 피커를 마지막으로 연 시점에 굳었다(이슈 #139). 이 응답 하나가 캐릭터 단위 파생 정보의 공용 원천이다 — 월드([[ADR-054]] 결정 5), 레벨([[ADR-055]] 결정 6), 길드([[ADR-057]] 결정 1)를 모두 여기서 꺼내 쓰므로 새 판정에 캐릭터 속성이 필요하면 **추가 호출 전에 이 응답부터 확인**할 것.
  - **`character_guild_name` 은 세 상태를 구분해 정규화한다**([[ADR-057]] 결정 2): 문자열=그 길드 소속, `null`·빈 문자열=**가입한 길드 없음**, 필드 자체가 없음=**모름**. `normalizeCharacterBasic` 이 앞의 둘을 `null`, 마지막을 `undefined` 로 매핑한다. 둘을 합치면 응답·캐시가 불완전할 때 모든 캐릭터가 "미가입"으로 보여 길드 콘텐츠가 잘못 잠긴다.
- **`GET /maplestory/v1/scheduler/character-state`** (`nexon/schedule`, ocid별): `daily_contents`/`weekly_contents`/`boss_contents` 를 앱 도메인 모델로 변환.
  - `boss_contents.cycle` = `bossDaily`/`bossWeekly`/`bossMonthly`(실측). **`bossWeekly`·`bossMonthly` 만 사용, `bossDaily` 무시** — 힐라(하드)·핑크빈(카오스) 등 일간 격하 보스가 `bossDaily` 로 온다([[ADR-006]] 일치).
  - **`date`(YYYY-MM-DD) 쿼리 파라미터** 지원(공식 문서 확인, 2026-07-14, [[ADR-023]]) — 보스 수익 과거 기간 재조회에 사용. 조회 가능 구간은 **하한과 상한이 모두 있다** — 아래 "date 조회 가능 구간" 참고([[ADR-032]], [[ADR-067]]).

### 공지사항 엔드포인트 — **미실측** ([[ADR-146]] 결정 2)

알림 시스템이 공지 푸시를 위해 쓸 예정이지만 **경로도 응답 형태도 아직 확인하지 않았다.** 추정으로
적지 않는다 — `scripts/probe-nexon-api.mjs` 로 실제 응답을 받은 뒤 이 절을 채운다. 함께 확인할 것 둘:

- **호출 주체가 서버다.** 사용자 개인 키가 아니라 **개발자 키로 Cloudflare Worker 가 주기 폴링**한다
  (공개 정보라 [[ADR-003]] 을 건드리지 않는다는 판단). **그 사용이 이용약관상 허용되는지는 확인 전이다.**
- 공지·업데이트·이벤트·캐시샵이 갈린 엔드포인트인지, 하나인지 — 알림 범위 결정이 여기 달려 있다.

## `date` 조회 가능 구간 (실측 2026-07-31, [[ADR-067]])

기준일 2026-07-31(KST 01:5x)에 `scheduler/character-state` 를 날짜 전수 스윕한 결과다. **하한만 있는 게 아니라 상한도 있다.**

| `date` | 결과 |
|---|---|
| 없음(당일 상태) | **200** |
| 오늘 | 400 `OPENAPI00004` |
| **오늘−1일** | **시각에 따라 갈린다** — 새벽엔 400 `OPENAPI00009`(아직 집계 전), 집계가 끝나면 200 |
| 오늘−2 ~ 오늘−13 | **200** |
| 오늘−14 이상 과거 | 400 `OPENAPI00004` |
| 미래 | 400 `OPENAPI00004` |
| 형식 오류(`20260731`, `2026-7-1`) | 400 `OPENAPI00004` |

- 실효 조회 구간은 **`[오늘−13, 오늘−1]`** 이고, 그중 `오늘−1` 은 새벽 한때만 `OPENAPI00009` 다. 하한 상수 `ROLLING_QUERY_WINDOW_DAYS = 13` 은 실측과 정확히 일치하지만(오늘−13 O, 오늘−14 X) **상한은 코드에 없었다**.
- **하한의 정체는 "14일"이다**(사용자 확인 2026-07-31). 넥슨이 두는 한도는 14일이고, 주간 정산 시각 때문에 마지막 날이 **몇 시간 일찍 닫힌다** — 그래서 날짜 단위로 재면 오늘−14가 하루 종일 실패하고 실효 하한이 오늘−13이 된다. 두 숫자는 층이 다르므로 각자 자리를 지킨다: **코드 상수는 13**(실측 경계 = 우리가 호출을 막아야 하는 선), **사용자 문구는 14일**(넥슨이 약속한 한도 = 사용자가 이해하는 값). [[ADR-068]] 결정 1에서 문구를 "최근 14일"로 확정했다.
- 고정 하한 `MIN_SCHEDULER_DATE`(2026-07-01)는 2026-07-14 이후로 **롤링 하한에 영구히 가려진다** — 판정에는 더 이상 기여하지 않지만 "이 API 이전 데이터는 존재하지 않는다"는 사실 자체는 유효하므로 상수는 남긴다.
- `OPENAPI00009` 만 **시간이 지나면 풀리는 실패**다. 같은 날 같은 날짜(`date=2026-07-30`)를 두 번 조회해 경계를 좁혔다(2026-07-31 실측): **KST 01:52 → 400 `OPENAPI00009` / KST 03:44 → 200**. 즉 어제 데이터는 **KST 새벽 01:52~03:44 사이**에 준비된다. 더 좁히려면 `scripts/probe-nexon-api.mjs dates <캐릭터명>` 을 그 시간대에 반복 실행하면 된다.
  - 정확한 시각을 상수로 박지 않는다 — 넥슨이 배치 시각을 바꿀 수 있고 우리에게 필요한 건 "지금 되는가"뿐이다. **`오늘−1일` 은 일단 호출하고, `OPENAPI00009` 면 `notCollected` 로 처리**한다([[ADR-067]] 결정 2 정정 2). 문구도 시각을 말하지 않는다([[ADR-068]] 결정 1).

**주간·월간 조회일이 이 경계와 충돌한다**: weekly 조회일은 항상 그 주의 수요일이라 **목요일에는 오늘−1일**이 되고, monthly 조회일은 그 달 마지막 날이라 **매월 1일에는 오늘−1일**이 된다. 즉 지난 기간 백필은 **매주 목요일 새벽·매월 1일 새벽**(집계 완료 전, 실측 기준 대략 00:00~03시 KST)에만 `OPENAPI00009` 로 막히고 그 뒤에는 정상이다.

## 에러 코드 (실측)

| 코드 | status | 뜻 | 재시도 |
|---|---|---|---|
| `OPENAPI00003` | 400 | **조회할 수 없는 ocid** — `character/list` 가 반환한 ocid여도 발생 | 무의미(영구) |
| `OPENAPI00004` | 400 | **그 ocid로 그 날짜를 조회할 수 없다** — 윈도우 밖·미래·형식 오류·**그 날짜엔 이 캐릭터가 지금 월드에 없었음**을 모두 이 하나로 답한다 | 원인에 따라 다름(아래) |
| `OPENAPI00005` | **400** | **무효한 API 키**(`"The apikey is not valid."`) — **401/403 이 아니다** | 무의미(키를 바꿔야 한다) |
| `OPENAPI00007` | 429 | 호출 한도 초과 | 백오프 후 |
| `OPENAPI00009` | 400 | **아직 집계되지 않음**(오늘−1일) | 유의미 — 나중에 자동 복구 |

### `OPENAPI00005` — 무효 키는 401 이 아니라 400 이다 (실측 2026-08-08)

`character/list` 를 아무 문자열 키로 호출한 실측이다.

```
$ curl -H "x-nxopen-api-key: test_invalid_key_..." \
       https://open.api.nexon.com/maplestory/v1/character/list
HTTP 400
{"error":{"name":"OPENAPI00005","message":"The apikey is not valid."}}
```

- **발견 당시엔 `network` 로 흡수되고 있었다.** `nexon/http.ts` 가 400 을 `NexonBadRequestError(code)`
  로 만들지만 `toScheduleSyncError`·`toOnboardingError`·`toSettingsError` 는 `00003`·`00004`·`00009`
  만 알아보고 나머지 400 은 `network` 로 degrade 했다([[ADR-067]] 트레이드오프의 안전판이 여기선
  **원인을 삼켰다**). 그래서 ① 온보딩 키 오입력이 "네트워크 오류가 발생했습니다"로 보이고
  ② [[ADR-115]] 의 자동 이동이 발동하지 않았다.
- **지금은 `invalidApiKey` 다** ([[ADR-115]] 결정 9). 판정은 `nexon/errors.ts` 의
  **`isInvalidApiKeyError(error)`** 한 곳에 있고 `401`·`403`·`400 OPENAPI00005` 를 같게 본다 —
  위 세 매퍼가 첫 분기로 그것을 쓴다. **세 곳에 조건을 복사하지 않는다**: "무엇이 무효 키인가"는
  넥슨이 정하는 사실 하나다.
- **폐기된 키도 같은 응답이다 (확인 2026-08-08).** 처음엔 *애초에 존재한 적 없는 키* 만 실측해
  "폐기된 키도 그런지는 미확인" 으로 남겼으나, **사용자가 정상 키로 온보딩을 마친 뒤 넥슨에서 그 키를
  삭제하고 재현**해 확정했다 — 저장돼 있던(한때 유효했던) 키로 `character/list` 를 부르면 똑같이
  **400 `OPENAPI00005`** 다. **401/403 은 오지 않는다.**
  - 그래서 **[[ADR-115]] 의 키 무효화 자동 이동은 실제 상황에서 발동하지 않는다** — 그 ADR 이 전제한
    401/403 은 이 API 에서 무효 키의 응답이 아니다. 이슈 #157 이 말한 "경우 B"가 곧 이 응답이다.
  - 발견 당시 화면에는 **"네트워크 오류가 발생했습니다"** 만 반복해 떴다(사용자 보고 + iOS 시뮬레이터
    실측). 이 실측이 [[ADR-115]] 결정 9 를 낳았다.

- **`OPENAPI00004` 는 네 가지 원인을 구분해주지 않는다.** "미래"는 시간이 지나면 풀리고, "월드 이전 이전 날짜"는 영구히 안 풀린다 — 코드만으로는 갈라낼 수 없으므로 **호출 측이 날짜를 보고 판정**해야 한다(윈도우 밖인가 / 미래인가 / 그 외인가).
- **`nexon/http.ts` 는 응답 본문을 읽지 않는다** — 401/403/429만 갈라내고 나머지 비-2xx는 전부 `NexonNetworkError` 다. 위 코드를 쓰려면 400 본문의 `error.name` 을 살리는 것이 선행 작업이다([[ADR-067]] 결정 1).

## 미접속 캐릭터의 응답 축약 (실측 2026-07-31)

`access_flag: "false"` 캐릭터도 **세 엔드포인트 모두 200**이다(`character/basic`·당일 `scheduler`·과거 `date` 전부). "비활성이면 200이 아니다"는 관찰은 **반증됐다** — 실제로 400을 뱉는 것은 위의 조회 불가 ocid와 날짜 문제다. 대신 **응답에 담기는 항목 수가 미접속 정도에 따라 단계적으로 줄어든다**.

| 캐릭터 상태 | 당일 응답 (daily/weekly/boss) | 과거 `date` 응답 |
|---|---|---|
| 오늘 접속 | 18 / 22 / 77 | 18 / 22 / 77 |
| `access_flag: true`, 오늘 미접속 | 1 / 22 / **53**(bossDaily 0) | 18 / 22 / 77 |
| `access_flag: false` | 1 / **6** / **2**(bossMonthly만) | 1 / 22 / 53 |
| 특수 월드·저레벨 | 1 / 6 / **0**(보스 없음) | 1 / 6 / 0 |

축약 응답에서 **살아남는 항목이 우리 stale 판정을 좌우한다**:

| 살아남는 것 | 우리 판정 | 결과 |
|---|---|---|
| daily 1건 = `몬스터파크`(world 공유) | `isDailySectionMissing`(character 범위 항목 유무, [[ADR-034]]) | **잡힌다** ✓ |
| weekly 6건 — 그중 `[메이플 유니온] PC방 주간 드래곤 퇴치`·`[몬스터파크] 익스트림 몬스터파커에 도전해보겠나?` 가 **character 범위로 잡히던 것** | `isWeeklySectionMissing` | **해소** ✓ (2026-08-03) — 두 항목을 카탈로그에 등록해 공유로 분류했다([[ADR-086]] 정정 1). 앞은 월드, 뒤는 **계정** 공유다(사용자 확인) |
| `bossMonthly` 2건(`reg=false`·`comp=false`) | `isMonthlyBossStale = !some(bossMonthly)` | **못 잡는다** ✗ — 축약 응답을 신선한 데이터로 신뢰한다 |
| `bossWeekly` 0건 | `isWeeklyBossStale` | 잡힌다 ✓ |

- **일부 항목의 `now_count` 는 리셋되지 않고 누적된다** (실측 2026-08-03). `[길드] 지하 수로` 는 73635(07-26) → 75889(08-01) → 79579(당일)로 **07-30 주간 리셋을 통과해도 줄지 않는다**. 이 값은 개인 기록이지만 "이번 주기에 했는가"를 말해주지 않는다 — `now_count > 0` 을 최근 활동의 증거로 쓰면 그 콘텐츠를 해본 캐릭터가 영원히 활동 중으로 읽힌다([[ADR-086]] 정정 2). 같은 `[길드]` 접두라도 `주간 미션 포인트`(10/10 · 5/10)·`플래그 레이스` 는 주기마다 리셋된다.
- **공유 항목 이름은 접두·수식이 붙은 변형으로 온다** (실측 2026-08-03). `getShareScope` 는 공백만 제거하고 **완전 일치**로 비교하므로 `몬스터파크` 는 `[몬스터파크] 익스트림 몬스터파커에 도전해보겠나?` 를 잡아주지 않는다 — 카탈로그에는 **API가 보내는 이름 그대로** 넣어야 한다. 위 표의 ✗ 두 줄이 그 사각이었고, [[ADR-086]] 자격 판정이 그 위에 세워져 미접속 캐릭터가 후보 목록에 남는 결함으로 재등장했다(정정 1).
  - 계측 재현: `NEXON_KEY=<키> node scripts/probe-nexon-api.mjs items <캐릭터명>` 이 전 항목의 이름과 현재 분류를 나란히 찍는다. `eligibility <캐릭터명>` 은 어느 날짜의 무엇이 자격을 켰는지까지 찍는다.
  - **같은 계열이라도 공유 단위가 다르다** — `[메이플 유니온] 주간 드래곤 퇴치`(월드) vs `[메이플 유니온] PC방 주간 드래곤 퇴치`(계정). 이름으로 유추하지 말 것([[ADR-006]]).
- **보스가 0건인 캐릭터(특수 월드·저레벨)는 과거 날짜도 0건**이라 `fillMissingSections` 가 13일을 다 훑고도 해결하지 못한다 → 캐릭터 1명당 매 동기화 **14회 호출**이 영구히 반복된다([[ADR-067]] 결정 5).
- 주간 보스 완료가 축약으로 소실되는 경우는 실질적으로 없다 — `access_flag: false` 는 7일 이상 미접속이고 주간 리셋 주기가 7일이라 그 주에 처치가 있을 수 없다. **월간은 최대 31일이라 다르다**(그 달에 처치한 뒤 미접속 → 완료 소실).

## 월드 이전(월드 리프·챌린저스 이전) (실측 2026-07-31)

한 캐릭터(2026-07-23에 챌린저스2 → 엘리시움)로 확인:

- `date=2026-07-23`(이전 당일) **200** / `date=2026-07-22`(그 전날) **400 `OPENAPI00004`** — 이전 이전 날짜는 영구히 조회할 수 없다. 캐릭터 생성일(2026-06-19)이 아니라 **이전 날짜**가 경계다.
- 윈도우 밖·형식 오류와 **에러 코드가 같아** "이 캐릭터는 그때 다른 월드였다"를 API 응답만으로는 알 수 없다. 게다가 같은 400의 원인이 월드 리프인지 **휴면 캐릭터 해제**인지도 구분할 수 없다(사용자 확인) — 그래서 앱은 원인을 추정해 말하지 않는다([[ADR-068]] 결정 6).
- **이전은 캐릭터 1~2개 단위가 흔하고 계정 전체가 옮기는 경우는 극히 드물다**(사용자 확인 2026-07-31). 조회 가능 구간 판정을 계정·월드 단위로 뭉치면 안 되고 **항상 ocid 단위**여야 한다.
- **과거 `date` 응답도 `world_name`·`character_level` 은 "현재" 값을 담는다**(이전 전 날짜의 응답도 새 월드·현재 레벨). 즉 과거 응답은 *현재 캐릭터 속성 + 그 날짜의 콘텐츠 상태*라는 혼합 빈티지다 — 월드별 집계([[ADR-054]] 결정 5)는 과거 주도 새 월드로 귀속된다.

## 조회 불가 ocid (실측 2026-07-31)

한 API 키가 반환한 두 계정 중 **한 계정(13명) 전원**이 `character/basic`·`scheduler` 에서 400 `OPENAPI00003` 이었다(다른 계정 60명은 전원 200).

- `character/list` 는 그 13명을 정상 반환하고, `/maplestory/v1/id?character_name=` 도 **같은 ocid** 를 돌려준다 — ocid 자체는 유효한 형태다.
- 같은 월드(베라)의 **다른 사람 캐릭터는 200** 이므로 월드 문제도, 키 소유권 문제도 아니다.
- 원인은 확정하지 못했다(삭제/이전 등 계정 상태로 추정). 확정할 수 없어도 **앱이 다뤄야 하는 사실**은 분명하다: 온보딩 계정 선택([[ADR-051]])은 이 계정을 정상 후보로 제시하고, 고르면 모든 캐릭터가 영구히 조회 불가라 피커가 빈 목록이 된다.

## 정규화
- 난이도: 영문 소문자 ↔ 한글 변환(`nexon/normalize`).
- 보스명: **양쪽 문자열 공백을 전부 제거한 뒤 비교**(`lib/boss-matching`). 공백이 API 쪽에 더 있을 때도, 데이터 쪽에 더 있을 때도 있어 한쪽으로 가정하면 안 됨(예: API `검은 마법사` vs 데이터 `검은마법사`, 반대로 API `블러디퀸` vs 데이터 `블러디 퀸`). 공백 제거로도 못 잡는 예외(API `시즌 보스 메이린` ↔ 데이터 `메이린`)는 `weekly-bosses.json` 의 `apiAlias` 로 명시 매핑. 매핑 실패는 원문 그대로 "알 수 없는 콘텐츠"(크래시 금지).
- `nexon/` 은 `src/data/` 를 몰라야 독립 테스트가 가능하므로, 보스명 매칭은 `nexon/` 이 아니라 `lib/boss-matching` 이 담당하고 결과를 feature 가 소비한다.

## 확인 완료된 사실 (레퍼런스)
- `access_flag` 는 boolean이 아니라 **문자열 `"true"`/`"false"`** — `normalizeCharacterBasic` 이 `=== 'true'` 로 변환한다(실측 재확인 2026-07-31). truthy 검사로 바꾸면 모든 캐릭터가 활성으로 읽힌다.
- **경험치는 `character/basic` 에 두 필드로 온다**(사용자 확인 2026-08-17, [[ADR-147]] 결정 7의 열린 질문을 닫는다):
  ```
  "character_exp": 1390734270108,      // number — 누적 경험치 절대값
  "character_exp_rate": "80.300"       // string — 현재 레벨 진행률(%), 소수 3자리
  ```
  **`character_exp_rate` 는 숫자가 아니라 문자열이다.** `access_flag` 와 같은 모양의 함정이라 정규화가 반드시 변환한다 — 문자열째로 비교·연산하면 `"9.500" > "80.300"` 이 참이 되고(사전순), 진행률 바가 조용히 뒤집힌다. `character_exp` 는 `Number.MAX_SAFE_INTEGER` 안이지만(1.39e12) 레벨이 오를수록 커지는 값이라 합산·누적에 쓰지 않는다.
- `character/basic`·`scheduler` 응답의 `date` 필드는 당일 조회에서 `null` 이거나 요청일을 그대로 돌려준다 — **타임스탬프 비교에 쓸 수 없다**(마지막 갱신 시각이 아니다).
- `weekly_boss_clear_count`·`weekly_boss_clear_limit_count` 는 wire 타입에만 있고 **앱이 소비하지 않는다**. 미접속 캐릭터는 `limit_count: 0` 으로 오므로(실측) 이 값을 분모로 쓰기 시작하면 축약 응답에서 0으로 나눈다.
- `weekly_boss_clear_limit_count` = 캐릭터당 주간 보스 12마리 제한 카운트. 시즌보스(메이린)는 예외.
- 주간 리셋 = KST 목요일 00:00(`lib/reset-clock` 과 정확히 일치). 월간 보스 리셋 = 매월 1일 00:00 KST([[ADR-030]] 확정).
- 온보딩 계정 표기: 각 `account_id` 는 그 계정 최고 레벨 캐릭터의 닉네임+직업+레벨로 표기(`account_id` 해시 비노출).
