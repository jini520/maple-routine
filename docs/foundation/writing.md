# 문서 쓰기

이 저장소의 문서 · 소스 주석 · 앱 문구를 쓰는 방법이다. 왜 이렇게 정했는지는 [[ADR-003]] 에 있다.

## 관련 소스

| 파일 | 하는 일 |
|---|---|
| `docs/ADR.md` | ADR 인덱스 · 파일 이름 규칙 · 카테고리 표 · ADR 형식 |
| `docs/adr/` | ADR 본문. 파일 하나에 기능 하나 |
| `docs/features/` · `docs/foundation/` · `docs/persistence/` | 기능 문서. 무엇을 하는지를 적는다 |
| `src/__tests__/adr-policy.test.ts` | ADR 파일 이름 · 번호 · 배지 · 인용 검사, 소스가 ADR 번호를 적지 않는지 검사 |
| `src/__tests__/comment-style-policy.test.ts` | 장식 기호와 파일 머리 주석 형태 검사 |

## 문서의 종류

| 문서 | 쓰는 것 | 쓰지 않는 것 |
|---|---|---|
| ADR(`adr/ADR-NNN_카테고리_기능.md`) | 배경 · 결정과 그 이유 · 결정을 지키는 테스트 · 꼭 풀어야 하는 열린 질문 · 번호 기록 | 경위, 계측값, 폐기된 결정 |
| 기능 문서(`features/` · `foundation/` · `persistence/`) | 그 기능이 무엇을 하는지. 범위 · 관련 소스 표 · 동작 표 | 이유. 이유는 `[[ADR-NNN]]` 으로 가리킨다 |
| 소스 주석 | 이 코드가 무엇이고 어떻게 쓰는지, 어기면 버그가 나는 값 | ADR 번호, 경위, 계측값 |

ADR 형식과 파일 이름 규칙은 `docs/ADR.md` 에 있다. 상태는 🟢 유효 · ⚪ 미구현 둘이고, 결정이 뒤집히면 죽은
결정을 본문에서 지운다. 옛 내용은 git 히스토리에서 찾는다.

## 쓰기 전에

- 적을 파일 이름 · 함수 이름 · 저장 키 · 화면 문구를 `src/` 에서 검색해 실제로 있는지 본다. 문서와 코드가
  다르면 코드를 따른다.
- 구현된 것만 쓴다. 계획은 ADR 에 ⚪ 미구현으로 둔다.

## 문장

| 규칙 | 예 |
|---|---|
| 코드에 있는 이름을 쓴다. `src/` 에서 검색되지 않는 비유는 바꾼다 | `벽지` → 테마 배경 이미지 · `층` → 스택 |
| 규칙에는 이유를 붙인다 | 어기면 무엇이 깨지는지를 같은 문장이나 다음 문장에 |
| 한 문장에 개념을 셋 넣지 않는다 | 문장을 나눈다 |
| 직역투를 쓰지 않는다 | `X 하는 것은 Y 다` · 물건이 주어인 영어식 문장 · 위치를 지정하는 `유일한` |
| 다 쓴 뒤 한 문장씩 소리 내어 읽는다 | 한국 사람이 실제로 그렇게 말하는지 |

## 기호

| 기호 | 대신 |
|---|---|
| `—` | 문장이면 마침표, 라벨이면 콜론, 짧은 덧말이면 괄호 |
| `«»` | 지우고 볼드 |
| `「」` | 앱 문구는 `‘’`, 문서와 주석은 백틱 |
| `·` | 그대로 쓴다 |

## 앱 문구의 낱말

| 쓰는 말 | 쓰지 않는 말 | 이유 |
|---|---|---|
| `수입` | 단독 `수익`(`보스 수익` · `총 수익` · `수익·지출` 등) | 가계부의 수입 · 지출과 같은 말을 써야 한 화면에서 두 낱말이 같은 뜻인지 다른 뜻인지 묻지 않는다(사용자 지정 2026-10-26) |
| `순 수익` | `순수익` | 띄어쓰기가 섞여 있었다. 한 가지로 맞춘다(사용자 지정 2026-10-26) |

지난 업데이트 노트(`src/data/release-notes.ts`)는 그때 쓴 글이라 고치지 않는다.

표에서 해당 없음을 뜻하는 `| — |` 칸은 그대로 둔다. 앱 문구는 뜻이 바뀌지 않게 기호만 바꾼다.

## 주석

- `/** */` 로 쓰고 파일 머리 · 타입 · 상수 · 함수 · 프롭에 붙인다.
- 태그는 `@param`(위치 인자를 받는 함수) · `@example`(실제 호출부에서 가져온 사용법) · `@returns`(자명하지 않을
  때) · `@see`(같은 저장소의 파일) 넷만 쓴다.
- 역할을 적는 주석은 명사로 끝낸다(`한 값을 무한 반복시키는 훅`). 조건과 제약은 완전한 문장으로 쓴다.
- `[[ADR-NNN]]` 이나 `ADR-NNN` 을 쓰지 않는다. 인용이 이유를 대신하고 있었다면 이유를 한 줄로 적는다.

## 테스트와 문서

ADR 의 테스트 표에는 그 결정을 지키는 테스트만 적고, 각 테스트가 무엇을 지키는지를 `~인지 본다` 로 쓴다.
값 하나를 그대로 비교하는 테스트와 입력 · 출력이 뻔한 테스트는 코드에서 지운다([[ADR-006]]).
