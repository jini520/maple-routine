# 가계부 (수익·지출 캘린더)

> 「수익·지출」 그룹의 둘째 하위 탭. **지금은 캘린더만 있다** — 기록 데이터는 아직 붙지 않았다
> ([[ADR-169]] 결정 6).

## 무엇인가

한 달 격자를 그리고, 날짜를 고르면 그날의 수익·지출을 보여주는 자리다. 이슈 #187 의 요구
*«사냥 수익 + 지출을 한 캘린더 페이지로 통합»* 에서 **그릇에 해당하는 조각**이 여기까지다.

## 자리

```
[ 수익·지출 ]          ← 그룹 (`GroupId 'ledger'`, 라벨은 «수익·지출»)
 보스 수익 | 가계부      ← 하위 탭 둘 ([[ADR-169]] 결정 1)
```

- 라우트 이름은 `Cashbook`, 경로는 `/cashbook` — `Ledger` 가 아닌 이유는 [[ADR-169]] 결정 3.
- 사냥 수익·지출 두 껍데기 탭은 **삭제됐다**([[ADR-169]] 결정 2 · [[ADR-132]] 결정 12 부분 폐기).
  둘은 사라진 것이 아니라 이 화면 안으로 들어온다.

## 구성

| 조각 | 파일 | 하는 일 |
|---|---|---|
| 격자 계산 | `lib/calendar-month.ts` | 달 → «몇 주 × 7칸», 각 칸의 KST 날짜 키. 달 이동·라벨 · 열지도 단계(`heatLevel`·`monthIncomeMax`) |
| 금액 표기 | `lib/meso-compact.ts` | 좁은 칸용 축약(「54.74억」·「3,908만」) — `formatMesoUnits` 와 목적이 다르다 |
| 격자 표시 | `components/molecules/CalendarMonth/` | 받은 주 배열을 그린다. **판정을 하지 않는다** |
| 화면 | `app/cashbook/CashbookScreen.tsx` | 달 이동 + 격자 + 고른 날의 상세 |

계산과 표시를 가른 이유는 [[ADR-147]] 결정 8 과 같다 — 배치 규칙이 렌더러 안에 있으면 화면을
띄워야만 검증된다([[ADR-169]] 결정 7).

## 규칙

- **축은 달력 월**이다. 보스의 목요일 리셋 축(`lib/boss-profit-period.ts`)과 무관하다
  ([[ADR-169]] 결정 4 · [[ADR-166]] 결정 4).
- **주는 일요일에 시작**한다([[ADR-169]] 결정 8).
- **달 경계의 빈칸은 앞뒤 달 날짜로 채우고 흐리게 그린다.** 빈 칸으로 두면 6주째가 통째로 비는
  달에서 격자 높이가 달라진다([[ADR-169]] 결정 7).
- **날짜 칸은 금액 두 줄이다**([[ADR-169]] 정정 1) — 위가 수익(`+`, `rise-ink`), 아래가 지출
  (`−`, `fall-ink`). **수익 줄은 0 도 「0」 으로 적고 지출 줄은 0 이면 비우되, 둘 다 자리는
  차지한다.** 좁은 칸에 들어가도록 `formatMesoCompact` 로 줄여 적는다.
- **지출 줄은 메소만이다.** 앱이 환율을 만들지 않으므로([[ADR-166]] 결정 1 · [[ADR-006]]) 캐시·메포를
  이 숫자에 섞을 수 없다. 통화가 섞인 날의 표현은 **지출 기록이 붙을 때** 정한다.
- **칸 바탕을 그날 수익에 비례해 칠한다**(열지도, 단계 넷). 기준은 **그 달 안에서 상대적**이고
  앞뒤 달로 채운 칸은 기준에 안 든다 — 절대 금액으로 자르면 초반 캐릭터의 달이 통째로 흐려진다.
- **오늘은 테두리, 고른 날은 채움**으로 구분한다. 둘이 같은 칸일 수 있으므로 표현이 겹치면 안 된다.

## 아직 없는 것 (그리고 무엇이 그것을 가져오나)

| 없는 것 | 가져올 것 |
|---|---|
| 지출 기록 | [[ADR-166]] — 설계가 다 섰다. 참조 데이터 `src/data/spend-catalog.json`(24항목 · 3갈래 · 9묶음) · 카테고리 다섯(컨텐츠 · 상점·편의 · 버프 · 아이템 구매 · 기타) · 수량 칸(`금액 = 단가 × 수량`)까지 [[ADR-166]] 정정 1 이 확정했다. **남은 것은 화면과 저장소 코드**이고, 캐시 항목만 사용자 확인 대기다 |
| 수익 기록의 **날짜** | **#239** — `boss_profit_records` 의 `periodKey` 는 주간·월간뿐이라 «며칟날 잡았나»를 앱이 모른다 |
| 사냥 수익 | 참조 데이터 셋([[ADR-006]] 대기) + 사냥 타이머 네이티브(`docs/features/hunting-timer.md`, 구현 0줄) |

`CalendarMonth` 의 `amounts` 프롭은 **위 둘이 채울 자리**다. 지금 화면이 빈 객체를 넘기는 것은
누락이 아니라 기록된 상태이고, 그동안 칸은 모든 날을 「0」 으로 그린다 — **지우지 말고 채울 것**
([[ADR-169]] 결정 6 · 정정 1).

**레퍼런스에서 아직 안 온 것**([[ADR-169]] 정정 1, 사용자 지정 «칸 숫자만 먼저»): 머리의 「월 수입」
합계 · 「모아보기」 칩 · 선택일의 수입/소비 두 구역과 「+ 추가」 버튼 둘 · 미래 날짜 흐림.

## 열린 질문

- 기록이 쌓이면 상세가 격자를 밀어낸다 — 격자를 접나, 상세를 시트로 올리나. **데이터가 붙은 뒤** 결정.
- **열지도가 수익만 따르는 것이 맞나** — 지출이 큰 날은 안 칠해진다. 기록이 붙은 뒤 다시 본다.
- 두 줄 글자 크기(9px)가 좁은 기기에서 읽히는지 — 실기기 확인.
- 주 소계·월 합계의 표현. [[ADR-166]] 결정 1 때문에 한 줄이 아니라 통화별 세 줄이다.
