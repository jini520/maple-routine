# 로그인

넥슨을 부를 인증 수단을 받아 기기에 저장하고, 그 수단으로 더 조회할 수 없게 되면 사용자에게 알려 다시
로그인하게 한다. 인증 수단은 API 키와 넥슨 로그인 두 가지다. API 키에 관한 결정은 [[ADR-024]],
넥슨 로그인에 관한 결정은 [[ADR-025]] 에 있다.

넥슨 로그인 입구는 `NEXON_LOGIN_ENABLED` 로 켜고 끈다. 지금은 켜져 있다(`true`). 넥슨의 콜백 주소 검수가
승인돼 1.0.13 스토어 바이너리에서 연다([[ADR-025]] 결정 9).

키를 쓰던 사용자가 넥슨으로 로그인하면, 기기는 로그인과 메이플 ID 가 같은 키를 서버에서 로그인한 사람과 이은 뒤 지운다
([[ADR-025]] 결정 4). 로그인은 그 키의 넥슨 계정 id 를 이어받아 기기 기록이 그대로 이어진다([[ADR-098]] 결정 5). 서버는 키로
보낸 기록을 로그인한 사람에게 옮긴다([[ADR-017]] 결정 9).

앱을 켰을 때 어느 화면이 나오는지는 [[ADR-026]], 키 발급 안내 사이트는 [[ADR-015]] 에 있다.

## 저장하는 것

| 수단 | 개수 | 저장하는 값 |
|---|---|---|
| 넥슨 로그인 | 0 ~ 1 | 우리 서버가 발급한 세션. 넥슨 토큰은 서버에만 있다 |
| API 키 | 0 이상 | 키 값과 이름(`label`). 이름은 사용자가 붙이지 않으면 비어 있다. 부계정 키가 무효가 되면 무효 표시와 그때 추적에서 뺀 캐릭터를 함께 둔다 |

메인 계정의 수단이 없으면 로그인 화면이 나오고, 있으면 앱이 열린다. 메인 계정은 로그인이 있으면 로그인이고, 없으면
로그인 없이 쓰는 메인 키(`mainKeyId`)다. 부계정 키는 등록한 넥슨 로그인에 귀속되고(`loginId`), 그 로그인이 살아 있을 때만
부른다. 로그인이 만료되거나 로그아웃해도 부계정 키는 귀속된 채 남고, 같은 넥슨 ID 로 다시 로그인하면 이어진다. 다른 넥슨 ID
나 API 키로 로그인하면 이어지지 않는다([[ADR-101]] 결정 5).

로그인 화면의 로그인은 새 로그인이라 앞 메인 수단을 버린다. 귀속되지 않은 키는 지우고 남은 넥슨 로그인은 뗀다. today 의
`넥슨 ID 연동하기` 는 새 로그인이 아니라 메인 키가 그 로그인의 부계정이 된다.

캐릭터는 그 캐릭터가 속한 넥슨 계정의 수단으로 부른다. 어느 계정인지는 `character_accounts` 에서 찾고, 모르면 메인 계정의
수단으로 부른다([[ADR-101]] 결정 4).

## 로그인 화면

넥슨 로그인이 주 경로이고 API 키는 되도록 쓰지 않게 한다. 앞으로 일부 기능은 넥슨 로그인으로만 쓸 수 있게 되기 때문이다.
그래서 키로 가는 길은 첫 화면 맨 아래의 작은 글자 버튼 하나이고, 누르면 경고를 먼저 보여 준다. 이유는 [[ADR-025]] 결정 7 에 있다.

| 블록 | 입구가 켜져 있을 때 | 입구가 꺼져 있을 때(지금) |
|---|---|---|
| FAQ | 왼쪽 위 글자 버튼 `자주 묻는 질문`. 누르면 `로그인` 묶음의 FAQ 시트가 열린다. 문항이 없으면 버튼이 없다([[ADR-150]] 결정 8) | 같다 |
| 머리 | 스플래시의 잎과 이름 묶음(잎 `primary` · 메이플스토리 서체 글자 `text` · 글자 34) · 64 아래 `넥슨 Open API의 메이플스토리 스케줄러와 강화 기록을` · `불러오려면 넥슨 로그인이 필요해요.` | 둘째 줄이 `불러오려면 API 키 입력이 필요해요.` |
| 넥슨 | 로그인 버튼 · `게임 데이터 활용 로그인이란?` | 없음 |
| API 키 | 화면 맨 아래 글자 버튼 `API 키로 시작하기`. 누르면 경고 모달 | 넥슨 버튼 자리의 `API 키로 로그인`. 넥슨 버튼과 같은 모양(같은 비율 · 모서리 6 · 열쇠 아이콘)에 테마 `primary` 바탕이다. 누르면 경고 모달 없이 키 입력 상단 시트가 열린다 |

경고 모달(`ApiKeyWarningModal`)은 다음과 같다.

| 항목 | 동작 |
|---|---|
| 머리 | 경고 삼각형 · `API 키로 시작할까요?` |
| 칸 둘 | 자물쇠 · `일부 기능은 넥슨 로그인으로만 쓸 수 있어요` 와 `앞으로 나오는 기능도 넥슨 로그인을 기준으로 만들어요.` |
| 넥슨 로그인 버튼 | 모달을 닫고 넥슨 로그인을 시작한다 |
| `그래도 API 키로 시작하기` | 모달을 닫고 키 입력 상단 시트를 연다 |
| 스크림 · 뒤로가기 | 모달만 닫는다 |

키 입력 상단 시트(`ApiKeySheet`)는 위에서 내려온다. 키보드가 아래에서 올라오므로 입력칸을 가리지 않는다.

| 항목 | 동작 |
|---|---|
| 머리 | 열쇠 · `API 키로 시작하기` · 알약 `⚠ 일부 기능 제한`. 입구가 꺼져 있으면 알약이 없다. 넥슨 로그인이 없으면 무엇에 비해 제한된다는 것인지 말이 되지 않는다 |
| 라벨 줄 | `Nexon Open API 키` 와 오른쪽 `openapi.nexon.com에서 확인`(넥슨 오픈 API 를 인앱 브라우저로 연다) |
| 입력칸 | 시트가 열려도 초점을 주지 않는다. 기본은 가림이고 오른쪽 눈 아이콘으로 보이게 한다. 자동 대문자 · 자동 수정 · 맞춤법 검사는 끈다 |
| `확인` | 키를 검증한다. 검증하는 동안 시트는 그대로 두고 버튼만 스피너로 바뀐다. 실패하면 시트를 둔 채 토스트로 알린다 |
| `API 키 발급 방법 보기` | 키 발급 안내 사이트(`mapleroutine.store/api-key`)를 인앱 브라우저로 연다 |
| 닫기 | 위로 밀기 · 스크림 탭 · 뒤로가기. 친 키는 버린다 |

로그인 화면으로 돌아왔을 때 저장된 키가 있으면 시트를 열 때 입력칸에 채워 둔다.

## 키를 넣으면

| 결과 | 사용자가 보는 것 |
|---|---|
| 검증 성공 · 개발 단계 아님 | `API 키를 확인했어요` 토스트. 다음 단계로 간다 |
| 무효 키 | `API 키가 유효하지 않습니다` 토스트. 폼이 그대로 있다 |
| 429 | `호출 한도를 초과했습니다` 토스트 |
| 네트워크 오류 | `네트워크 오류가 발생했습니다` 토스트 |
| 저장 실패 | `기기에 저장하지 못했습니다` 토스트 |
| 개발 단계 키 | 토스트 없이 `이 키로는 연결할 수 없습니다` 모달. 닫으면 폼으로 돌아간다 |

## 저장된 수단으로 조회할 수 없게 되면

앱을 쓰다가 조회가 아래 가운데 하나로 실패하면, 지금 화면 위에 닫을 수 없는 모달이 뜬다. 본문은 `확인` 을 누른 뒤 가는 곳을 말한다.

| 원인 | 제목 | 본문 | 확인을 누르면 |
|---|---|---|---|
| 지금 로그인의 부계정 키가 무효 | `API 키가 더 이상 유효하지 않습니다` | `이 키의 캐릭터를 추적에서 빼고 계정 관리로 이동합니다.` | 키에 무효 표시를 붙이고 그 키의 추적 캐릭터를 뺀 뒤 계정 관리 목록을 연다 |
| 같은데 남은 추적 캐릭터가 없음 | 같다 | `이 키의 캐릭터를 추적에서 빼고 캐릭터 설정으로 이동합니다.` | 같이 하고 캐릭터 설정으로 간다 |
| 메인 키가 무효 | 같다 | `키 입력 화면으로 이동합니다.` | 그 키를 지우고 로그인 화면으로 간다 |
| 넥슨 로그인 만료 | `넥슨 로그인이 만료됐습니다` | `다시 로그인해주세요.` | 넥슨 로그인을 지운다. 남은 수단이 있으면 앱을 계속 쓰고, 없으면 로그인 화면으로 간다 |

부계정 키를 지우지 않는 것은, 부계정을 기기마다 따로 관리해서 지우면 계정 관리에서 그 계정이 사라지기 때문이다. 남겨 두면 사용자가
어느 계정의 키가 문제인지 보고 그 계정에서 `API 키 변경` 을 한다. 무효 표시가 붙은 키는 부르지 않고 서버에 등록하지도 않는다. 같은
넥슨 계정의 새 키로 바꾸면 표시를 걷고, 뺐던 캐릭터를 추적 목록 끝에 다시 넣는다([[ADR-101]] 결정 15).

저장된 API 키가 429 를 받으면 키를 지우지 않고 다시 시도 모달이 뜬다([[ADR-024]] 결정 11). 제목은 `호출 한도를 초과했습니다` 이고,
`서비스 단계 키인지 확인해주세요` 와 발급 안내 두 칸, `API 키 발급 방법 보기` 링크, 버튼 `다시 시도` · `다른 키 입력` 이 있다. 같은 키로
처음 받은 429 는 `다시 시도` 가, 연달아 두 번째부터는 `다른 키 입력` 이 주 버튼이다. 다른 키를 넣어 저장한 뒤에만 옛 키를 지운다.
메인 키의 `다른 키 입력` 은 키 입력 시트를 연다. 부계정 키의 `다른 키 입력` 은 그 계정의 상세 페이지를 열고 `API 키 변경` 시트를
바로 띄운다(아래 `계정 관리`).

넥슨 Open API 마이 페이지에서 정보 활용 동의를 철회해도 `넥슨 로그인 만료` 모달이 뜬다. 철회하면 넥슨이 1분 안에
이 앱의 토큰을 모두 거절한다(400 `OPENAPI00012`). 서버는 조회가 이 응답을 받으면 그 자리에서 세션을 지우므로,
철회한 뒤 다음 조회에서 바로 모달이 뜬다([[ADR-016]] 결정 8).

로그인 화면에서 키를 넣거나 넥슨 로그인을 하면 추적 캐릭터를 비우고 캐릭터 설정부터 다시 한다([[ADR-101]] 결정 14).
키가 무효화되어 로그인 화면으로 온 경우도 같다. today 의 `넥슨 ID 연동하기` 는 비우지 않는다. 보스 수익 · 가계부 · 드롭 ·
강화 기록은 어느 쪽이든 지우지 않는다.

## 넥슨 로그인 (입구가 켜져 있을 때)

| 위치 | 언제 보이나 |
|---|---|
| 로그인 화면 넥슨 블록 | 늘 |
| today 머리의 `넥슨 ID 연동하기` 가 여는 연동 시트 | 넥슨 로그인이 없을 때. 화면에 들어올 때마다 확인하고, 확인하기 전에는 머리 버튼이 없다 |

`넥슨 ID 연동하기` 는 캐릭터 관리 버튼 왼쪽의 글자 버튼이다. 누르면 아래에서 연동 시트(`NexonLinkSheet`)가 올라온다.
머리에 넥슨 버튼을 바로 두지 않는 이유는 [[ADR-025]] 결정 6 에 있다.

| 항목 | 동작 |
|---|---|
| 제목 · 설명 | `넥슨 ID 연동하기` 와 그 아래 두 줄 `일부 기능은 넥슨 로그인으로만 쓸 수 있어요.` · `앞으로 나오는 기능도 넥슨 로그인을 기준으로 만들어요.` 왼쪽 정렬이다. 제목은 시트 머리에 고정되고 설명은 스크롤 안에 있다. 머리가 없으면 끌어 올릴 때 핸들 띠 뒤로 내용이 비친다 |
| 넥슨 버튼 | 시트를 닫고 넥슨 로그인을 시작한다 |
| `게임 데이터 활용 로그인이란?` | 넥슨의 소개 페이지를 인앱 브라우저로 연다 |
| 닫기 | 끌어 내리기 · 스크림 탭. 닫기 버튼은 없다 |

| 결과 | 사용자가 보는 것 |
|---|---|
| 성공 | `넥슨 계정을 연결했어요` 토스트. 메이플 ID 가 같은 API 키는 서버에서 이은 뒤 지운다. 로그인 화면에서 했으면 캐릭터 설정으로 넘어간다 |
| 실패 | `넥슨 로그인에 실패했습니다` 토스트 |
| 메이플 ID 가 없는 넥슨 ID | `이 넥슨 ID 에 연결된 메이플 ID 를 찾지 못했어요` 토스트. 로그인을 저장하지 않는다. 로그인 화면이면 로그인 화면에 남고, 연동 시트면 앱과 API 키가 그대로다 |
| 사용자가 창을 닫음 | 아무 일도 없다 |
| 넥슨 동의 화면에서 `취소` | 아무 일도 없다. 창을 닫은 것과 같다 |
| 캐릭터 목록을 못 받음 | `넥슨 로그인에 실패했습니다` 토스트. 목록은 로그인을 저장하기 전에 받아서, 로그인은 저장되지 않았다 |
| 로그인 중에 넥슨 버튼을 다시 누름 | 아무 일도 없다. 진행 중인 로그인이 그대로 간다 |

### 캐릭터 없는 넥슨 ID 로 들어왔을 때

넥슨 ID 를 여럿 가진 사용자가 메이플 ID 가 없는 ID 로 먼저 들어오면, 넥슨은 빈 계정 목록을 준다. 그런 로그인은 저장하지 않고
`이 넥슨 ID 에 연결된 메이플 ID 를 찾지 못했어요` 토스트를 띄운다(위 결과 표, [[ADR-025]] 결정 10).

1.0.13+7 전에 그런 로그인이 이미 저장된 기기는 캐릭터 설정 화면과 설정의 캐릭터 관리에서 같은 빈 화면을 본다.

| 목록을 부른 수단 | 빈 화면 | 버튼을 누르면 |
|---|---|---|
| 넥슨 로그인 | `조회되는 캐릭터가 없어요` · `이 넥슨 ID 에 연결된 메이플 ID 를 찾지 못했어요` · `다른 넥슨 ID 로 로그인` | 넥슨 로그인만 뗀다. 로그인 없이 쓰는 API 키가 남아 있으면 그 키로 목록을 다시 받고, 없으면 로그인 화면으로 간다 |
| API 키 | `조회되는 캐릭터가 없어요` · `이 API 키에 연결된 메이플 ID 를 찾지 못했어요` · `API 키 다시 입력` | 키 문제 알림(`invalid`)을 띄운다 |

로그인 창은 브라우저와 쿠키를 나누지 않고, 닫으면 쿠키를 버린다. 그래서 넥슨 로그인 창에서 네이버 · 구글 같은 소셜 계정을
골라도 매번 새로 고른다. 쿠키를 나누면 그 서비스가 앞서 고른 계정으로 묻지 않고 돌려보내, 잘못 고른 계정에서 벗어날 수
없었다([[ADR-025]] 결정 3).

| 기기 | 로그인 창 |
|---|---|
| iOS | 쿠키를 나누지 않는 인증 창(`preferEphemeralSession`). 1.0.13+7 부터 |
| 안드로이드 · 기본 브라우저가 지원 | 기본 브라우저의 Ephemeral Custom Tab. 1.0.14 부터 |
| 안드로이드 · 기본 브라우저는 지원하지 않고 Chrome 이 지원 | Chrome 의 Ephemeral Custom Tab |
| 안드로이드 · 둘 다 지원하지 않음 | 기본 브라우저의 보통 탭. 다른 소셜 계정으로 바꾸려면 그 브라우저에서 그 서비스에 로그아웃해야 한다 |

Ephemeral Custom Tab 은 Chrome 136 이상이 지원한다. 삼성 인터넷 30 은 지원하지 않아, 기본 브라우저가 삼성 인터넷인 갤럭시는
로그인 창이 Chrome 으로 열린다(갤럭시 Z 플립3 실측).

## 계정 관리

설정의 `계정 · 캐릭터 · 보스` 카드 맨 위 `계정 관리` 가 연다([[ADR-101]] 결정 1 · 2). 넥슨 로그인 사용자는 다른 넥슨 계정의 API
키를 부계정으로 넣고 지운다. 넥슨 계정은 로그인을 포함해 5개까지다. 메이플 ID 이름은 로그인하지 않은 사용자도 바꾼다. 이름은
가계부에도 보이기 때문이다.

### 목록

| 사용자 | 위에서부터 |
|---|---|
| 넥슨 로그인 | `넥슨 ID 계정 설정` 카드, 오른쪽 `API 키 추가` 글자 버튼, API 키 계정 카드 |
| 로그인 안 함 | 넥슨 로그인 블록(`부계정을 추가하려면 넥슨 로그인이 필요해요.` 와 넥슨 버튼), `API 키 계정 설정` 카드 |

- 계정마다 `넥슨 ID 계정 설정` · `API 키 1 계정 설정` 같은 행 하나를 누를 수 있고, 그 아래에 그 계정의 메이플 ID 이름과 대표
  캐릭터 이름을 글자로 둔다. API 키의 번호는 등록한 차례다.
- API 키가 하나도 없으면 API 키 카드 자리에 빈 상태 카드(`등록한 API 키가 없어요`)를 둔다. 추가는 위 글자 버튼 하나다.
- 이 기기의 넥슨 계정이 5개면 `API 키 추가` 를 누를 때 `더 추가할 수 없어요` 모달이 뜬다. 버튼을 숨기면 왜 추가할 수 없는지 보이지 않는다.
- 목록에는 이 기기에 키가 있는 계정만 선다. 부계정은 기기마다 따로 관리하기 때문이다(아래 `기기마다 따로 관리한다`). 다른 기기에서
  등록한 부계정은 이 기기에서 그 키를 추가해야 선다.
- 키가 무효가 된 계정은 행 오른쪽에 빨간 `유효하지 않은 키` 를 둔다(위 `저장된 수단으로 조회할 수 없게 되면`). 사용자는 그 계정의
  상세에서 `API 키 변경` 으로 같은 넥슨 계정의 새 키를 넣는다.
- 로그인하지 않은 사용자의 넥슨 로그인 버튼은 today 의 `넥슨 ID 연동하기` 와 같은 연동이다. 추적 목록을 비우지 않고, 지금 키는 그
  로그인의 부계정이 된다. 이 사용자에게는 `API 키 추가` 가 없다.

### 상세 페이지

- 위는 `메이플 ID 이름` 카드다. 메이플 ID 마다 `대표 캐릭터 {이름}` 라벨, 입력칸, 연필 아이콘이 서고, 카드 맨 아래가 `저장` 이다.
  - 이름은 10자까지다. 칸을 비우고 저장하면 기본 이름(`메이플ID-` 와 ID 앞 8자)으로 돌아간다. 다른 메이플 ID 와 같은 이름도 저장한다.
  - 이름을 바꾼 적 없는 메이플 ID 는 칸이 비어 있고, 기본 이름이 흐린 안내 글자로 선다. 14자인 기본 이름을 10자 상한 칸에 채우면
    iOS 가 한 글자씩 지우는 입력을 버리기 때문이다. 바꾼 이름이 있으면 칸이 그 이름으로 시작한다.
  - `저장` 을 누르지 않고 나가면 고친 이름을 버린다.
- 아래는 `API 키` 카드다. `API 키 변경` 과 빨간 `API 키 삭제` 가 선다.
  - 넥슨 ID 계정에는 이 카드가 없다. 로그인하지 않은 사용자의 키 계정에는 `API 키 변경` 만 둔다. 이 키가 유일한 수단이라 지우면
    로그아웃과 같고, 키를 떼는 것은 `앱 정보 및 계정` 의 로그아웃이 맡는다. 이 `API 키 변경` 은 429 모달의 메인 키 바꾸기와 같다.

### 키를 넣을 때

`API 키 추가` · `API 키 변경` 은 둘 다 키 입력 시트를 연다. 제목만 연 곳의 이름이다. 저장하기 전에 아래를 차례로 보고,
걸리면 저장하지 않고 `등록할 수 없는 키예요` 모달로 알린다([[ADR-101]] 결정 3). 모달의 주 버튼은 `다시 입력하기` 이고 시트는 그대로
남는다.

| 차례 | 보는 것 | 안내 |
|---|---|---|
| 1 | `character/list` 를 한 번 부른다. 무효 키면 | `넥슨 Open API 에서 확인되지 않는 키예요. 키를 다시 확인해 주세요.` 와 발급 안내 링크 |
| 2 | 20건을 동시에 보내 429 가 오면 개발 단계 키 | `넣으신 키 · 개발 단계` 와 `필요한 키 · 서비스 단계` 두 줄과 발급 안내 링크 |
| 3 | 메이플 ID 가 하나도 없으면 | `이 API 키에 연결된 메이플 ID 를 찾지 못했어요.` |
| 4 | 새 키의 메이플 ID 가 로그인(넥슨 ID 계정)이나, 변경일 때 다른 부계정과 하나라도 겹치면 | `이미 등록된 넥슨 계정의 키예요. 같은 넥슨 계정은 한 번만 등록할 수 있어요.` |
| 5 | 변경일 때 그 계정의 메이플 ID 와 하나도 겹치지 않으면 | `이 계정과 넥슨 계정이 일치하지 않는 키예요. 다른 API 키를 넣어 주세요.` |

- 차례 1 에서 무효 키가 아닌 실패(네트워크 · 점검 · 429)는 모달이 아니라 키 입력 실패 토스트다.
- 겹침은 계정마다 `character_accounts` 에 있는 메이플 ID 로 본다. 변경은 그 계정을 빼고 본다.
- `API 키 추가` 로 넣은 키가 등록된 부계정과 겹치면 막지 않고 그 계정의 키를 바꿀지 묻는다([[ADR-101]] 결정 3). 모달 제목은
  `이미 등록된 계정의 API 키예요`, 안내는 `API 키 1 계정의 키를 새로 입력한 키로 바꿀까요?`, 버튼은 `바꾸기` · `취소` 다. `바꾸기` 는
  아래 변경과 같이 저장하고, `취소` 는 키 입력 시트로 돌아간다. 키가 무효가 된 계정이면 무효 표시를 걷고 뺐던 캐릭터를 되돌린다.
- 추가는 서버 등록(`POST /v1/me/sub-accounts`)부터 한다. 서버가 같은 넥슨 ID 라고 거절하면 저장하지 않고 차례 4 의 안내로 알린다.
  그 밖에 서버가 받지 못하면 기기에 저장하고 다음 서버 전송 회차가 다시 등록한다. 그 사이에는 기기의 키로 그 계정을 부른다.
- 변경은 새 키를 같은 넥슨 계정 id 와 귀속으로 저장한 뒤 옛 키를 빼고, 서버에 새 키로 다시 등록한다. 그래서 그 계정의 추적 캐릭터와
  기록이 이어진다. 무효 표시가 붙은 키를 바꾸면 표시를 걷고, 뺐던 캐릭터를 추적 목록 끝에 다시 넣는다.
- 끝나면 시트를 닫고 `API 키를 확인했어요` 토스트를 띄운다. 추가한 계정은 목록에 새 행으로 서고, 다른 화면으로 옮기지 않는다.

### 지울 때

`API 키 삭제` 는 확인 모달(`API 키를 삭제할까요?`)을 띄운다. 주 버튼이 `취소` 이고 그 아래 빨간 글자 버튼이 `API 키 삭제` 다.

- 이 기기의 키를 지우고, 그 계정의 메이플 ID 에 속한 추적 캐릭터를 목록에서 뺀다. 보스 수익 · 가계부 기록은 남는다. 추적 캐릭터가
  하나도 남지 않으면 캐릭터 설정으로 간다.
- 서버의 등록 정보는 지우지 않는다([[ADR-101]] 결정 2). 같은 키를 다른 기기에서 계속 쓰면 그 기기의 기록이 이 사람에게 이어져야
  하기 때문이다.

### 기기마다 따로 관리한다

서버는 어느 키가 그 사람의 부계정인지만 적는다([[ADR-101]] 결정 6). 앱은 서버의 부계정 목록을 받지 않고, 이 기기에 있는 지금 로그인의
부계정 키만 보여 주고 부른다. 목록을 맞추려면 다른 기기에서 지운 키를 이 기기에서도 지우거나 숨겨야 하기 때문이다.

- 다른 기기에서 등록하거나 지운 부계정은 이 기기에 나타나지도 사라지지도 않는다.
- 넥슨 계정 5개 상한은 이 기기의 계정으로 센다. 서버는 부계정 수를 세지 않는다. 기기에서 지운 부계정도 서버에 남기 때문이다.

## 로그아웃과 계정 삭제

둘 다 설정의 `앱 정보 및 계정` 화면의 `계정` 묶음에 있다. 규칙과 이유는 [[ADR-017]] 결정 6 ~ 8 에 있다.

| | 확인 모달 | 지우는 것 | 남기는 것 |
|---|---|---|---|
| 로그아웃 | `로그아웃할까요?` · 주 버튼 `로그아웃` | 넥슨 로그인 · 메인 키 · 서버 세션 · 못 보낸 대기 표와 사용 로그 | 앱 데이터 · 서버 데이터 · 넥슨 로그인에 귀속된 부계정 키 |
| 계정 삭제 | `계정을 삭제할까요?` · 주 버튼 `취소` | 서버 세션은 바로, 서버의 계정 · 열쇠는 30일 뒤. 그다음 로그아웃과 같은 것 | 앱 데이터 · 부계정 키. 서버에 보낸 기록은 누구의 것인지 모르게 남는다 |

- 둘 다 끝나면 로그인 화면으로 간다.
- 계정 삭제가 서버에서 실패하면 토스트로 알리고 로그아웃하지 않는다.
- 유예 30일 안에 같은 키나 넥슨 계정으로 다시 로그인하면 `삭제 예정인 계정이에요` 확인 창이 뜬다. `삭제 취소` 면 그대로 들어가고,
  `로그아웃` 이면 예약을 둔 채 나간다. 앱을 켤 때도 한 번 묻는다.
