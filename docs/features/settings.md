## 정책
진입 경로는 **하단 탭바 4번째 탭**(별도 헤더 아이콘 아님, 확정 2026-07-12).

### 화면 구조 — 본화면 2카드 5행 + 하위 페이지 4 ([[ADR-118]], 구현 완료 2026-08-09, 이슈 #135·#161)

설정은 **한 화면이 아니라 얕은 계층**이다. 가르는 기준은 "행이 몇 개인가"가 아니라 **성격이 다른 것을 붙여 두지 않는다**이다.

```
설정 (본화면 — 고정 헤더 없음)
 [카드 1]  스케줄 관리 방법            자동 ›      ← 값을 고르는 행(모달)
           테마                      혼테일 ›
 [카드 2]  개발 노트                        ›      ← 화면이 넘어가는 행
           계정 및 데이터            1.2 MB ›
           앱 정보                    1.0.3 ›
 [footer]  v1.0.3 / © 2026 메이플 루틴 / Data based on NEXON Open API / 비제휴 고지

/settings/release-notes  개발 노트     — 버전별 변경 목록(데이터·배포 연동은 [[ADR-119]])
/settings/release-notes/:guideId
                         기능 안내     — 그 기능이 어디 있고 어떻게 쓰는지(이미지 + 문단)
                                          ([[ADR-125]], 이슈 #198). release-notes 의 **자식**이다 —
                                          안내를 가진 노트 항목을 눌러 들어간다. 2단 스택 둘째
/settings/account-data   계정 및 데이터 — [카드1] 계정 변경 / [카드2] 캐시 데이터 삭제 · 연결 해제(둘 다 위험 색)

                                          about 의 **자식**이다 — 그 화면의 행에서 열리므로
                                          2단 스택. 오프라인이면 안내 + 브라우저로 열기
```

#### 기능 안내 — 개발 노트의 드릴다운 ([[ADR-125]], 구현 전, 이슈 #198)

개발 노트 한 줄은 *"바뀐 것이 있다"* 까지만 말한다. **안내를 가진 항목만** 눌러 들어갈 수 있고 `›` 가 붙는다 — 나머지 항목은 DOM 이 종전과 같다(버그 수정 한 줄에 붙일 사용법은 없고, 액션 없는 자리에 비활성 버튼을 두지 않는다).

- **축은 버전이다** — 기능 카탈로그를 따로 두지 않는다(두 축은 반드시 어긋난다). 오래된 기능이 옛 버전 카드에 묻히는 것이 대가이고, 그 요구가 실제로 생기면 그때 얹는다.
- **본문은 `release-notes.ts` 밖에 산다** — `scripts/publish-live-update.mjs` 가 그 파일을 **Node 에서 직접 import** 하므로(`.webp` import 를 넣으면 배포가 죽는다) 항목엔 `guideId?: string` 만 남기고 본문은 `src/data/release-note-guides.ts` 다. 갈라짐은 **양방향 참조 무결성 테스트**가 막는다(모든 `guideId` 에 가이드가 있고, 모든 가이드가 어느 항목엔가 물려 있다).
- **이미지는 앱 번들**(`src/assets/guide/`, 명시적 import) — 원격 로드는 오프라인에서 안내가 통째로 비어 기각. `import.meta.glob` 을 안 쓰는 이유는 파일명이 틀렸을 때 `undefined` 로 조용히 통과하는 대신 **빌드가 실패해야** 하기 때문이다.
- **OTA 는 dist 전체를 압축**하므로 지연 로드가 용량을 깎아 주지 않는다 — 한 장당·누적 상한을 정해 관리한다(값은 첫 촬영분 실측 후).
- `:guideId` 는 버전이 아니라 **항목** 식별자다. 없는 id 로 들어오면 `/settings/release-notes` 로 `replace`.

- **섹션 제목은 달지 않는다** — 두 무리를 덮는 제목(「동작·표시」/「관리·정보」)은 행 이름보다 덜 구체적이라 읽는 사람이 얻는 것이 없다. 카드 경계만으로 가른다. 기존 「데이터 관리」·「앱 업데이트」 제목은 그 아래 행이 하나뿐이라 사실상 행 이름이었고, 두 섹션이 하위 페이지로 내려가면서 함께 사라진다.
- **파괴적 행은 `/settings/account-data` 안에서 별도 카드로 내린다.** 본화면에서 빼는 것만으로는 분리가 아니다 — 옮긴 곳에서 다시 `계정 변경` 과 붙으면 같은 문제가 한 층 내려갈 뿐이다. 아래 카드에도 제목을 달지 않는다(위험 색 + 카드 경계가 이미 말한다).
- **하위 페이지 넷은 `/boss/manage`·`/content/manage` 와 같은 골격**이다 — 공용 `StackScreen`([[ADR-120]]) + `PageHeader`([[ADR-094]]) + 좌측 `ArrowLeft`(`aria-label="뒤로"`). 라우트는 `/settings` 의 **중첩 자식**이고 가드는 부모가 대신 건다(부모가 `/onboarding` 으로 리다이렉트되면 자식은 매칭될 자리가 사라진다). 중첩인 이유는 [[ADR-077]] 의 "부모 상태 보존"이 아니라 **전환 중 아래 화면이 보여야 하기 때문**이다 — 그러려면 언마운트되면 안 된다.
  - 뒤로는 `navigate(-1)` **진짜 pop** 이고(딥링크 진입만 부모로 `replace`), 왼쪽 가장자리 스와이프로도 돌아온다. 하위 페이지에는 **탭바가 없다**.
  - **`SettingsScreen` 도 `ScreenScroll` 로 옮겨갔다**([[ADR-120]] 딸림 작업) — 문서 스크롤에 얹혀 있던 마지막 탭 화면이었다. 그래야 스택의 아래 화면이 되고, 하위 페이지를 열었다 닫아도 보던 자리가 남는다.
- **카테고리 행은 대표값 하나를 미리 보여준다** — `계정 및 데이터` = 캐시 총 용량(`getCacheDataSizes()` 두 그룹의 합), `앱 정보` = 현재 버전(`currentVersion ?? packageJson.version`). `개발 노트` 는 보여줄 대표값이 없어 **비운다**("최신 버전"은 바로 아래 행과 같은 값이고 "n개"는 뜻이 없다 — 없는 대표값을 지어내지 않는다).
  - **조회 전 자리는 `- KB` 로 잡는다**([[ADR-061]] 결정 7) — 빈 문자열이면 값이 툭 나타나며 행이 밀린다. 조회 실패도 같은 자리표시로 남는다(설정을 못 여는 실패가 아니다).
  - **캐시 용량은 본화면과 `/settings/account-data` 가 각각 마운트 시 읽어, 드릴다운하면 조회가 2회다**(구현 확인 2026-08-09 — 옛 구조는 `CacheDataSection` 마운트 1회). 값을 프롭·스토어로 물려 내리지 않은 이유는 하위 화면이 **직접 진입 가능한 라우트**라 본화면을 거치지 않으면 물려받을 값이 없기 때문이다. **체감 지연은 미측정**이고, 확인되면 그때 캐싱 위치를 정한다([[ADR-118]] 미검증 3).
- **`계정 변경` 행에는 현재값을 두지 않는다** — `accountId` 는 불투명 문자열이고 대표 캐릭터 이름은 파생·변동값이다(프로브·캐시 상태에 따라 달라지고 429·조회 불가에서는 아예 없다 — [[ADR-113]]·[[ADR-116]]). 대표값 규칙은 "확실히 아는 값이 있으면 보여준다"이지 "칸을 채운다"가 아니다.

### "API 키 변경" 행은 되살리지 않는다 ([[ADR-118]] 결정 9, 2026-08-09)

[[ADR-115]] 결정 8 이 *"#135 와 함께 본다"* 로 미뤄 둔 미정의 **결론**이다.

- 무효 키(400 `OPENAPI00005`·401/403)와 429 는 이미 해결돼 있다 — 닫을 수 없는 안내 모달 → `확인` → 키 입력 화면 + 저장된 `apiKey` 삭제, 뒤 단계는 저장된 값으로 재개([[ADR-115]] 결정 10·4, [[ADR-116]] 결정 1). 사용자가 설정을 뒤져 키를 바꿀 이유가 없다.
- 남는 경우는 **"오류가 아닌데 자발적으로 갈아타는"** 드문 경우뿐이라(다른 넥슨 계정 키, 서비스 단계 키 승급 — 후자는 429 안내가 이미 그리로 보낸다), 설정 구조를 정리하는 이 개편에서 행을 하나 더 늘리지 않는다.
- **`useSettingsStore.changeApiKey` 는 지우지 않는다** — 로직·테스트가 살아 있고 **배선만 없는 상태로 계속 남는다.** 되살릴 땐 UI 만 붙이면 되고, 그 경로의 401 은 "방금 나쁜 키를 입력한 것"이라 무효화와 성질이 달라 인라인 카드에 남는다는 것까지 정해져 있다.

### 항목별 정책

- **계정(메이플 ID) 변경**: API 키 재입력 없이, 저장된 키로 `character/list` 를 다시 호출해 계정 선택 UI(`AccountSelectionList` 재사용)를 다시 보여준다. **계정이 1개여도 선택 UI를 보여준다**([[ADR-051]]) — 온보딩과 설정 두 경로가 "계정 수와 무관하게 항상 선택 화면 경유, 사용자가 '계속하기'로 확정해야 예열" 이라는 같은 규칙을 공유한다(상세 [onboarding.md](./onboarding.md)). **전원 조회 불가인 계정은 고를 수 없다**([[ADR-086]] 결정 8 — 같은 컴포넌트라 온보딩과 함께 적용). 계정 관련 로컬 기록(보스 수익·드랍 히스토리)은 삭제하지 않음([[ADR-008]] 참조 무결성). 이전 계정 캐릭터 기록도 보존, 현재 계정 캐릭터만 노출.

### 계정 변경은 캐릭터를 다시 고를 때까지 커밋하지 않는다 ([[ADR-086]] 결정 6, 2026-08-03)
흐름이 `확정 → 저장 → 예열 → 닫기` 에서 **`확정 → 예열 → 캐릭터 선택 → (저장 시점에) 커밋`** 으로 바뀐다.
- 커밋은 `setSelectedAccountId` + `setTrackedCharacterOcids` 두 쓰기를 **캐릭터 선택 저장 한 지점**에 모은다. 취소하거나 도중에 앱이 죽으면 **이전 계정이 온전히 그대로**다 — 온보딩의 "끝내지 않은 단계는 이전 상태를 깨지 않는다"([[ADR-086]] 결정 1)를 설정 경로에 그대로 적용한 것이다.
- 전에는 `selectedAccountId` 만 갱신하고 `trackedCharacters` 는 이전 계정 ocid 를 그대로 들고 있었다. 거기에 피커의 stub 단계가 계정 구분 없는 인덱스를 읽어(결정 9) **계정은 바뀌었는데 이전 계정 캐릭터가 보이는** 상태가 만들어졌다.
- 예열·로스터는 저장된 `selectedAccountId` 가 아니라 **후보 계정 id 를 인자로** 받는다(`resolveRegisteredCharacters(accountIdOverride?)`). 커밋 전 구간에 예열이 쓴 캐시는 **후보 계정의 인덱스**로 들어가므로 이전 계정 화면을 오염시키지 않고, 나중에 실제로 그 계정으로 전환하면 따뜻한 캐시로 재사용된다.
- **같은 계정을 다시 고르면** 아무 쓰기 없이 닫는다(추적 목록 보존).

#### 계정 검증·프로브 대기는 진행률 바 하나로 이어진다 ([[ADR-113]] 결정 3·5, 2026-08-08, 이슈 #163)
`AccountFlowStatus` 는 온보딩과 **같은 `AccountSelectionList`** 를 쓰므로, "전수 프로브가 settle 할 때까지 목록을 그리지 않는다"([[ADR-113]] 결정 3)가 계정 변경 경로에도 그대로 적용된다 — 상세는 [onboarding.md](./onboarding.md) "계정 선택 프로브".
- 그래서 이 모달에는 **연달아 오는 대기가 둘**이다: `verifying`(저장된 키로 `character/list` 재조회) → `selectingAccount` 진입 직후의 프로브 대기.
- **`verifying` 단계는 문구가 아니라 진행률 바 0% 다.** 전에는 "캐릭터 목록을 확인하고 있어요..." 텍스트 한 줄이었다. 뒤따르는 프로브 대기가 진행률 바인데 앞 단계가 텍스트면 **마크가 중간에 바뀌어 사용자가 두 번 기다린 것으로 읽는다** — 같은 자리에 같은 프리미티브를 두어 **하나의 연속된 로딩**으로 보이게 한다. `character/list` 는 한 번이라 총량을 미리 알 수 없어 0% 로 세워 둔다(그 구간이 진행을 표현하지 않는 것은 사실 그대로다).
  - **이어지는 것은 프리미티브와 자리이지 내용이 아니다** — `verifying` 은 숫자 없이 바 하나이고, 뒤따르는 프로브 대기에는 `(완료/전체)` 한 줄이 붙는다(총량을 아는 쪽이라 그렇다, [onboarding.md](./onboarding.md)). `verifying` 에 가짜 진행률이나 없는 총량을 지어내지 않는다.
  - 이 컴포넌트의 다른 상태들과 같은 `Card` + `p-6` 골격 안이다(모달이 `card={false}` 로 감싸는 것이 전제) — `selectingAccount` 로 넘어가도 카드는 그대로 있고 안의 내용만 바뀐다.
- 예열(`prefetching`) 단계의 진행률 바는 그대로다 — 세 대기가 모두 같은 `ProgressBar` 프리미티브([[ADR-061]] 결정 6)를 쓰게 된다.

#### 계정 플로우 `error` 카드 — 429 에는 "다시 시도"를 달지 않는다 ([[ADR-114]] 결정 1·2, 2026-08-08, 이슈 #158)
`AccountFlowStatus` 의 `error` 상태는 모달 본문 전체를 차지하므로 **인라인으로 남는다**([[ADR-063]] — 토스트로 옮기면 빈 상자가 된다). 다만 그 카드가 원인과 무관하게 "다시 시도" 버튼을 달던 것을 **`rateLimited` 일 때만 뺀다**.
- 문구는 `formatSettingsError`(`app/settings/error-message.ts`)가 정한다. `rateLimited` 는 **"호출 한도를 초과했습니다. 입력하신 API 키가 서비스 단계 키인지 확인해주세요"** — 여기는 모달 본문이라 토스트와 달리 처방까지 담을 자리가 있다([[ADR-114]] 결정 4).
- 버튼을 빼는 이유는 처방이 재시도가 아니기 때문이다. 이 카드에서는 재시도가 **유일한 진행 수단**이었으므로([[ADR-063]] "남는 인라인" 표) 429 에서는 모달을 닫는 것 외에 진행 경로가 없었다. 나머지 원인(`network`·`storageWriteFailed`)의 "다시 시도"는 그대로다.
  - **이제 그 자리에도 진행 경로가 생긴다**([[ADR-116]] 결정 1, 2026-08-08, 이슈 #178) — 429 는 `invalidApiKey` 와 **같은 사슬**(닫을 수 없는 안내 모달 → `확인` → 키 입력 화면 + 저장된 `apiKey` 삭제)을 타고 문구만 갈린다(`호출 한도를 초과했습니다` / `서비스 단계 키로 다시 입력해주세요.`).
    - **그래서 `refreshAccounts` 의 429 는 이 카드에 도달하지 않는다**(구현 확인 2026-08-08) — 진입점을 부른 뒤 `RESET` 까지 하므로 계정 모달 자체가 `idle` 로 닫히고, 남는 것은 안내 모달 하나다(지나간 실패가 나중에 설정을 다시 열었을 때 되살아나지 않게 하는 것도 같은 이유). 카드의 `rateLimited` 문구·버튼 없음은 **코드에 그대로 남지만**, 지금 그 분기로 갈 수 있는 경로는 미배선 상태인 `changeApiKey` 뿐이다([[ADR-115]] 결정 8). 그 자리에 재시도를 되살리지 않는다는 판단은 유효하다([[ADR-114]] 결정 2).
- **`invalidApiKey` 는 이 카드에 더 이상 도달하지 않는다**([[ADR-115]] 결정 7, 2026-08-08). `refreshAccounts` 는 **저장된 키**로 재조회하므로 그 401 은 곧 저장된 키의 무효화다 — 인라인 카드에 머무르면 키를 바꿀 자리가 없어 막다른 길이라(이슈 #157), 무효화 진입점(`invalidateApiKey`)으로 넘기고 설정 스토어는 `RESET` 으로 돌아간다(지나간 실패를 남기지 않고, `idle` 복귀가 모달의 닫힘 판정이라 모달도 함께 정리된다). 카드의 `invalidApiKey` 분기와 문구(`formatSettingsError`)는 **지우지 않고 남는다** — `changeApiKey` 경로가 그것을 쓰지만 그 경로는 아직 배선되지 않았다(아래 폐기 이력·[[ADR-115]] 결정 8).
- **연결 해제(로그아웃)**: `storage/api-key.ts` 의 `clearAuthConfig()` + `features/onboarding` 의 `RESET` 이벤트를 재사용해 온보딩 화면으로 복귀(신규 로직 없이 기존 두 조각 연결). **키 무효화(401/403) 복구 경로는 더 이상 이것이 아니다**([[ADR-115]], 2026-08-08) — 무효 키는 안내 모달의 `확인` 으로 키 입력 화면에 보내고 뒤 단계는 저장된 값으로 재개하므로, 사용자가 위험 색 행을 눌러 계정 선택부터 다시 할 이유가 없다. 연결 해제는 "이 기기에서 이 계정을 떼어낸다"는 사용자 의도 전용으로 남는다. 두 경로가 지우는 범위도 다르다 — 연결 해제는 `apiKey` + `selectedAccountId` 둘 다(`clearAuthConfig`), 무효화는 **`apiKey` 하나만**([[ADR-115]] 결정 3 — `clearAuthConfig` 를 쓰면 재개가 불가능해진다).
- **데이터 관리(캐시 데이터 삭제)**: 지울 데이터를 **2그룹 중 선택**해서 지운다([[ADR-058]]) — "일반 데이터"(동기화 캐시·추적 목록·수동 추적 항목·공유 진행 원장·파티 설정)와 "보스 수익·드롭 기록"(복구 불가). 인증·사용자 설정 5개(`KEEP_KEYS`)는 어떤 선택에서도 보존되므로 이 기능으로 온보딩으로 돌아가지 않는다 — 연결 해제는 별도. 범위의 정확한 정의와 그룹 경계의 근거는 [../persistence/lifecycle.md](../persistence/lifecycle.md).
- **테마 선택**: 등록된 테마 중 선택 → 즉시 반영. 목록은 카테고리 섹션(기본·직업·보스) + 2열 프리뷰 타일이고 위에 라이트·다크 필터 칩이 붙는다([[ADR-104]]). **고른다고 모달이 닫히지는 않는다** — 모달 자신이 선택 테마 색으로 그려지므로 그 자리에서 갈아입혀 보게 두고, 닫기는 "완료" 버튼과 오버레이 탭이 맡는다([[ADR-104]] 결정 7). 상세 [theme.md](./theme.md).
- **스케줄 관리 방법(트래킹 모드)**: 자동/수동 전역 토글([[ADR-035]]). 상세는 아래 UI.
- **footer 표기**(확정 2026-07-13, 비제휴 고지 추가 2026-08-03): 본화면 맨 아래에 앱 버전(`package.json`)·카피라이트("© {연도} 메이플 루틴")·이용약관 제6조④ 요구 영문 문구 "Data based on NEXON Open API"(원문 그대로, 의역 금지)·**비제휴 고지 "Maple Routine is not associated with NEXON Korea"**. 앱 전역 footer는 만들지 않음.
  - **개인정보 처리방침 링크가 빠져 고지 4줄만 남는다**([[ADR-118]] 결정 8, 2026-08-09). 전부 읽고 끝나는 정적 문구가 되어 톤(`text-text-disabled`)이 균일해진다 — 한 줄만 밝은 색이던 이유가 "이것만 눌러야 해서"였고 그 예외가 사라진다.
  - 비제휴 고지는 약관이 **요구하는 것이 아니라** 동종 서비스의 공통 관행을 따른 것이다(2026-08-03 조사) — maple.gg("Maple.GG is not associated with NEXON Korea")·chuchu.gg("This site is not associated with NEXON Korea")·maplescouter.com("Maplescouter is not associated with NEXON Korea and does not provide any warranty") 셋 다 출처 표기와 **함께** 비제휴 고지를 단다. 출처 표기만 있으면 넥슨 공식 서비스로 오인될 여지가 남는다.
  - **문구도 3사와 같은 영문 형태로 맞춘다**(사용자 결정 2026-08-04, 초안의 한글안 폐기). 같은 문구를 안내 사이트 footer(`site/template.html`)와 `PRIVACY.md` 말미도 공유한다.
- **개인정보 처리방침 링크**(2026-08-04, 스토어 요건): `mapleroutine.store/privacy` 로 나가는 링크. **Play 사용자 데이터 정책은 스토어 등록정보와 앱 안 양쪽에 링크를 요구한다** — 콘솔에 URL을 넣는 것만으로는 충족되지 않는다([../foundation/release.md](../foundation/release.md)).
  - **위치는 `/settings/about` 의 행**이다([[ADR-118]] 결정 7, 2026-08-09). 옛 위치(footer 맨 위)는 *"정적 고지 문구 사이에 끼면 링크로 안 읽힌다"* 를 색과 밑줄로 달래던 자리였고, **독립된 행이 되면 그 문제 자체가 없어져** 달래던 장치도 함께 필요 없어진다.
  - **스토어 요건은 그대로 충족된다** — 정책이 요구하는 것은 *"앱 안에 링크"* 이지 *"첫 화면에 링크"* 가 아니다. 설정 → 앱 정보는 두 번의 탭이고, 스토어 등록정보 쪽 URL 은 이 변경과 무관하다.
  - **오른쪽 아이콘은 chevron 이 아니라 외부 링크 표식**이다(행 5종 중 "외부 링크 행", 아래 UI). 이 행은 다음 화면을 여는 것이 아니라 **앱을 떠나 시스템 브라우저로 간다** — chevron 을 쓰면 다른 이동 행과 같은 약속을 하고 다른 일을 한다.
  - **외부 링크 열기는 `<a target="_blank" rel="noopener noreferrer">`** — `ApiKeyForm` 의 `openapi.nexon.com` 링크와 같은 방식이다. 별도 브라우저 플러그인을 들이지 않는다.
  - URL은 `PRIVACY.md` 를 렌더링해 서빙하는 그 주소다([site.md](./site.md)) — 앱 안에 정책 본문 사본을 만들지 않는다. 사본을 두면 법적 문서가 두 벌이 된다.
- **개발 노트**(`/settings/release-notes`, [[ADR-119]], 2026-08-09, 이슈 #161): 버전별 변경 목록을 **앱 번들 내장 데이터**(`src/data/release-notes.ts`)로 보여준다 — 네트워크 0회·오프라인에서도 과거 전체가 보인다. 같은 파일에서 배포 스크립트가 그 버전의 노트를 뽑아 `latest.json` 의 `notes` 로 파생시켜 업데이트 모달이 쓴다(원천 하나 + 소비 둘). 버전 축은 OTA 번들 버전이다. 과거 버전은 **GitHub 마일스톤에 닫힌 이슈가 있는 것만** 싣는다([[ADR-119]] 결정 4) — 커밋을 읽고 사후 재구성하지 않으므로 마일스톤이 없는 `1.0.1` 은 목록에서 건너뛴다. 항목마다 **카테고리**(`기능`·`개선`·`버그`, 이슈 접두사 승계)가 붙고 화면은 배지가 아니라 **그 카테고리로 묶어** 보여준다(순서는 기능 → 개선 → 버그 고정, 빈 묶음은 제목째 감춤 — [[ADR-119]] 결정 9). **안 읽음 표시(뱃지·점)는 두지 않는다** — 키가 하나 늘고 그 신호는 업데이트 모달이 이미 말한다([[ADR-118]] 결정 9).

## UI

### 본화면에는 고정 헤더가 없다 — 하위 페이지 셋은 쓴다 ([[ADR-098]] 결정 3 · [[ADR-118]] 결정 2·8)
**본화면**(`/settings`)은 `PageHeader` 셸이 없고 `p-4 space-y-4` 안의 평범한 `h1` 이다 — 그래서 스케줄러에서 관측된 **탭 복귀 프레임 튐**([[ADR-098]])이 이 화면에서는 구조적으로 일어날 수 없다(날아갈 고정 헤더가 없다). 그 ADR 이 단 재판단 조건은 *"행이 늘어 세로가 길어지면"* 인데, [[ADR-118]] 개편은 행을 4 → 5 로 하나 늘리면서 섹션 둘(캐시·앱 업데이트 = 4행 + 제목 2줄 + 버튼 하나)과 개인정보 처리방침 한 줄을 하위 페이지로 내려보내 **순증이 아니라 순감**이라 조건에 걸리지 않는다. 본화면은 계속 고정 헤더 없이 간다.

- **높이는 여전히 실측이 아니다.** 잰 값은 개편 **전** 구조의 것이다(390px 폭 + iPhone 안전영역 59/34 기준 **필요 높이 835pt**, 대부분 기기에서 스크롤 없음·13 mini·SE 급에서만 20pt 남짓). 개편 후 5행 + 고지 4줄의 실제 높이는 **구현 뒤에도 재지 않았다** — jsdom 은 레이아웃을 계산하지 않아 자동 테스트가 원리적으로 못 본다([[ADR-118]] 미검증 1). 실기기에서 스크롤이 생기면 그때 고정 헤더 도입을 판단한다.
- **하위 페이지 셋(`/settings/release-notes`·`/settings/account-data`·`/settings/about`)은 반대로 `PageHeader` 를 쓴다** — 뒤로 가기 버튼이 필요하고, 그 셸은 이미 `fixed` + 실측 spacer([[ADR-085]]·[[ADR-112]])라 이 ADR 이 막은 결함을 물려받지 않는다. 셋 다 `ScreenScroll` + `PageHeader` + `ArrowLeft`(`aria-label="뒤로"`) + `useScreenNavigate('/settings')` 로 `/boss/manage`·`/content/manage` 와 **같은 골격**이다.

### 설정 리스트 행 + 모달 — 2026-07-13 (구조 갱신 [[ADR-118]], 2026-08-09)
행은 **공용 `Card` atom**(`rounded-[14px] border border-border bg-surface`, [[ADR-094]]) 안에 `px-6 divide-y divide-border` 로 이어붙인다 — 여백·구분선은 레이아웃이라 호출부가 준다(Card atom 규약). 본화면은 이 카드가 **둘**이고([[ADR-118]] 결정 1) 하위 페이지도 같은 카드를 쓴다(`/settings/account-data` 는 둘, `/settings/about` 은 하나).

행 자체의 골격은 **`row-class.ts` 의 `SETTINGS_ROW_CLASS`** 한 곳에 있다(`flex w-full items-center justify-between py-4 text-left`). 왼쪽 라벨은 `text-sm font-medium text-text`(위험 동작은 `text-error-ink`), 오른쪽은 아래 5종.

- **행 컴포넌트는 둘이고 시맨틱이 다르다** — `SettingsRow` 는 `<button>`(탭하면 모달·화면), `SettingsLinkRow` 는 `<a target="_blank" rel="noopener noreferrer">`(앱을 떠난다). **한 컴포넌트로 합치지 않는 이유**는 합치면 `onClick` 이 선택 필드가 되어 호출부가 어느 쪽인지 타입으로 알 수 없기 때문이다.
- **골격이 컴포넌트 파일이 아니라 별도 파일인 이유는 lint 다** — 컴포넌트 파일이 컴포넌트 아닌 값을 함께 export 하면 fast refresh 가 깨진다(`react-refresh/only-export-components`). `Button/variants.ts` 와 같은 판단.
- **모달**: 공용 `components/Modal`([../foundation/design-system.md](../foundation/design-system.md)) — 계정 변경 모달·계정 선택 목록은 `card={false}` 로 자체 카드를 담음. 하위 페이지에서 모달은 **카드 밖이자 `ScreenScroll` 밖**의 형제다 — 카드 안이면 `divide-y` 가 형제로 잡아 구분선이 하나 더 그려지고, 셸 안이면 그 `fixed` 셸이 만든 스태킹 컨텍스트에 갇혀 오버레이가 탭바 아래로 그려진다([[ADR-099]]).

#### 행의 우측 표기는 5종으로 고정한다 ([[ADR-118]] 결정 4, 2026-08-09)

| 종류 | 왼쪽 | 오른쪽 | 쓰는 곳 |
|---|---|---|---|
| **설정 행** | 라벨 | 현재값 배지 **+** chevron | 스케줄 관리 방법 · 테마 |
| **이동 행** | 라벨 | 대표값(있으면) **+** chevron | 개발 노트 · 계정 및 데이터 · 앱 정보 · 계정 변경 |
| **표시 행** | 라벨 | 값 평문, **탭 불가** | 현재 버전 · 상태 |
| **외부 링크 행** | 라벨 | 외부 링크 아이콘 | 개인정보 처리방침 |
| **실행 행** | **위험 색** 라벨 | 보조 수치, **chevron 없음** | 캐시 데이터 삭제 · 연결 해제 |

**`SettingsRow` 의 배타(`rightContent ?? chevron`)를 병기로 바꾼다.** 전에는 값이 있으면 화살표가 사라져서, 같은 "탭하면 모달이 열린다"는 세 행 중 `계정 변경` 에만 화살표가 있었다 — 화살표가 **동작이 아니라 값의 유무**를 말하고 있었다.

> **chevron 이 있으면 누르면 무언가 열린다. 없는 위험 색 행은 누르면 지운다.**

- `showChevron={false}` 로 호출부마다 판단하게 두지 않는다(그것이 옛 상태이고, 판단이 흩어져 있으면 새 행마다 다시 틀린다). 모든 행에 chevron 을 다는 것도 아니다 — 위험 색 행에 화살표가 붙으면 "다음 화면이 있다"로 읽혀 확인 모달이 의외가 된다.
- **표시 행은 탭 불가**다 — 아무 일도 일어나지 않는 것을 누를 수 있게 그리지 않는다.
- **테마 행 오른쪽에 색 표식을 두지 않는다**는 것은 그대로다([[ADR-104]] 결정 5, 2026-08-06) — 어떤 테마인지는 이름이 말하고, 그 색은 지금 눈앞의 화면 전체가 이미 말하고 있다. 바뀐 것은 그 이름 배지 **옆에 chevron 이 병기**된다는 것뿐이고, 그것은 테마 행의 규칙이 아니라 모든 행에 걸리는 규칙이다.
- **테마 선택 모달(`ThemeSelector`)**: 라이트·다크 필터 칩(전체·라이트·다크, 기본 전체, 저장 안 함) + 카테고리 섹션 헤더 + **2열 프리뷰 타일**. 타일은 그 테마의 `bg`/`surface`/`surface2`/`primary`/`text` 로 미니 화면을 그린다 — `job-themes.json` 직접 import(비활성 테마 색이라 CSS 커스텀 프로퍼티로 부족). 거른 결과가 0인 섹션은 헤더째 감춘다. 선택 계약은 그대로 `aria-pressed` + `onSelect`. 정책·카테고리 소속은 [theme.md](./theme.md).
  - **버튼은 "완료" 하나**다(`mt-4 flex justify-end`, `TrackingModeModal`·`DisconnectConfirm` 과 같은 골격). 취소/적용 2단계를 쓰지 않는 이유는 선택이 이미 적용돼 **취소할 대상이 없기** 때문이다 — 되돌리려면 원래 테마를 다시 고르면 된다.
- **캐시 데이터 삭제 행/모달(`SettingsAccountDataScreen`/`CacheClearConfirm`)** — 자리는 `/settings/account-data` 의 아래 카드다([[ADR-118]] 결정 3). 「데이터 관리」 섹션 제목은 함께 사라진다(그 아래 행이 하나뿐이라 사실상 행 이름이었다). **`CacheDataSection.tsx` 는 옮겨진 것이 아니라 삭제됐다**(2026-08-09) — 용량 조회·`isClearing`·`clearCacheDataAndReload`·`reload` 주입이 전부 화면 안으로 흡수됐고 테스트 12케이스도 함께 이관됐다(껍데기만 남을 컴포넌트를 살려 두면 "두 자리 중 어디를 고쳐야 하는가"가 생긴다). 총 용량은 **본화면 `계정 및 데이터` 행의 대표값으로도 올라간다**(결정 5) — 같은 `getCacheDataSizes()` 합이라 정보가 줄지 않는다. 행 라벨은 위험 동작이라 `text-error-ink`, 오른쪽에 총 용량(`getCacheDataSizes()` 그룹별 값의 합). 모달은 체크박스 2행(`role="checkbox"`, 행 전체가 탭 영역) — 각 행에 그룹 이름·설명·그룹 용량, "보스 수익·드롭 기록" 행에는 복구 불가 경고. **보존 항목("유지됨") 줄은 두지 않는다**([[ADR-058]] 결정 9). **기본은 두 그룹 모두 체크**라 열고 바로 삭제하면 기존 전체 삭제와 같고, 전부 해제하면 삭제 버튼이 비활성이다([[ADR-058]] 결정 6). 삭제 중에는 두 버튼과 체크박스가 비활성(`isClearing`). 삭제 후 흐름은 선택과 무관하게 동일 — 타임아웃 경쟁 → **`closeBossProfitDb()` → 스플래시 → 리로드**([[ADR-050]], 결정 7 · 순서는 [[ADR-117]] 결정 8). **커버가 닫기 뒤인 것이 요점이다** — 먼저 올리면 닫기가 매달리는 동안 사용자가 브랜드 주황 화면에 갇히고 그 화면에서는 터치도 죽는다(이슈 #175 의 OTA 적용과 증상이 같고 트리거만 다른 두 번째 문이었다). 닫기에는 5초 상한이 있고 던지지 않는다([[ADR-117]] 결정 5). `native/live-update.ts` 의 적용 경로와 **마지막 한 줄(`set()`/`reload()`)만 다른 같은 모양**이다. **실패·타임아웃이면 리로드 뒤에 토스트로 알린다**([[ADR-065]] 결정 3) — 리로드가 화면 신호를 파괴하므로 `storage/pending-notice`(sessionStorage)에 플래그를 남기고 부팅 후 "캐시를 일부만 삭제했습니다"를 띄운다. 리로드를 막거나 부분 삭제를 되돌리는 조치는 하지 않는다. Preferences가 아니라 sessionStorage인 이유는 "리로드는 넘기되 앱 종료와 함께 사라진다"가 이 알림의 수명이기 때문이다.
- **앱 업데이트 섹션(`AppUpdateSection`)** — 자리는 `/settings/about` 이다([[ADR-118]] 결정 2). 「앱 업데이트」 섹션 제목은 화면 제목이 대신하므로 사라진다. 안은 **표시 행 둘**(`현재 버전`·`상태` — 값 평문, 탭 불가)과 `업데이트 확인` 버튼, 그리고 개인정보 처리방침 **외부 링크 행**이다. 현재 버전은 본화면 `앱 정보` 행의 대표값으로도 올라간다(결정 5 — 같은 `currentVersion ?? packageJson.version`).
  - **`up-to-date` 문구는 `최신 버전입니다`**([[ADR-118]] 결정 10, 2026-08-09 · 이전 `최신입니다`). `현재 버전` 행 바로 아래 `상태` 행에 놓이는 값이라 주어가 생략되면 무엇이 최신인지가 문장 안에 없다. 다른 상태 문구와 같은 하십시오체 어미 규칙([[ADR-062]])은 그대로다.
  - **`AppUpdateSection` 은 섹션 제목을 스스로 그리지 않는다** — 이 카드가 놓이는 화면의 제목이 이미 「앱 정보」라 같은 화면에 제목이 둘이 된다. `<section>` + `<h2>` 껍데기를 **떼고 `Card` 만 반환**한다(제목을 숨기는 프롭을 받는 방식이 아니다 — 그러면 "제목을 그릴 수도 있다"는 죽은 분기가 남는다).
- **개발 노트 화면(`SettingsReleaseNotesScreen`)** — `RELEASE_NOTES` 를 **배열 순서 그대로** 카드로 그린다(버전 + 날짜 + 항목 목록). **화면이 다시 정렬하지 않는다** — "최신이 먼저"는 데이터 파일의 계약이고 그 강제는 데이터 테스트가 한다(화면이 정렬하면 같은 규칙의 진실이 두 곳에 생긴다).
  - 지금 실행 중인 번들과 같은 버전의 카드에만 `사용 중` 배지(`primary`). `requiresStoreUpdate` 항목에는 그 항목 아래에 「스토어 업데이트 필요」 배지(`third` — 스토어 이동을 말하는 `UpdatePromptModal` 의 `store-required` 와 같은 톤). **표식은 버전이 아니라 항목에 붙는다**([[ADR-119]] 결정 3).
  - **로딩·에러 상태가 없다** — 데이터가 번들 안에 있어 네트워크를 타지 않는다. 목록이 0건이면 `EmptyState`(컨텍스트 아이콘 + inline, [[ADR-060]])인데 지금은 도달할 수 없는 자리다(1.0.3 한 건이 있고, 배포 가드가 빈 버전을 막는다).
- **스케줄 관리 방법 행/모달(`TrackingModeModal`/`TrackingModeSelector`, [[ADR-035]] 결정 1)**: 자동/수동 전역 전환. 행 라벨·모달 제목 "스케줄 관리 방법"(2026-07-25 개편, 이전 "트래킹 모드" — 내부 컴포넌트/store 이름은 `TrackingMode*` 그대로). 오른쪽 배지에 현재 모드("자동"/"수동"). 옵션 목록은 `ThemeSelector` 와 동일 선택 카드 패턴(`aria-pressed`, 선택 시 `border-primary bg-primary-tint`).

**선택과 적용은 분리한다** ([[ADR-035]] 결정 23, 2026-08-03) — 옵션 탭은 **고르는 것일 뿐**이고, 모달이 고른 값을 자기 상태로 들고 있다가 "적용"에서 한 번만 `setMode` 를 부른다.
```
버튼:   우측 정렬 취소(고스트) + 적용 — DisconnectConfirm/CacheClearConfirm 과 같은 골격
        취소  rounded-full px-5 py-2.5 text-sm font-medium text-text-muted hover:text-text
        적용  rounded-full bg-primary text-on-primary px-5 py-2.5 text-sm font-semibold
              (파괴적 동작이 아니라 진행 동작이라 저 둘의 border-error 가 아니다)
적용 중: 버튼 안 MapleSpinner size={16} + 라벨 "적용 중" + disabled + aria-busy
```
- **현재 모드와 같으면 적용 버튼이 비활성**이다 — 바뀐 것이 없으면 누를 것도 없다. 닫기는 취소·오버레이가 맡는다.
- 수동 전환 시 `setMode` 가 시드([[ADR-035]] 결정 14(a)) 끝날 때까지 resolve 안 되므로 그동안 **옵션·취소도 비활성**이고 **오버레이 클릭 닫힘 금지**(저장 도중 못 닫음 원칙)는 그대로다.
- 옵션 카드 안쪽 구조는 아래 "트래킹 모드 옵션 카드" — 온보딩과 공유한다. 이제 **흐름(선택 → 확정 버튼)까지 온보딩 `TrackingModeStep` 과 같다**.

#### 트래킹 모드 옵션 카드 — 온보딩과 공유하는 내부 구조 ([[ADR-035]] 결정 22, 2026-08-03)
카피(`features/tracking-mode/copy.ts`)와 **카드 안쪽 구조**를 온보딩 `TrackingModeStep` 과 공유한다 — 한쪽만 고치면 같은 선택지가 두 화면에서 다르게 생긴다. 카피는 세 필드다: `title`(자동/수동) · `description`(한 문장) · `caution`(그 모드의 한계 한 문장, 신규). 문구 전문과 그 이유는 [[ADR-035]] 결정 22.
```
카드 안쪽:  flex items-start gap-3
            아이콘  h-5 w-5 flex-none text-primary-ink — 자동 Gamepad2 / 수동 ListChecks (배지 없이 단독)
            제목    text-sm font-semibold text-text
            설명    text-sm text-text-muted   ← 접지 않고 항상 표시(고르기 전에 비교하는 화면)
주의 줄:    mt-2 flex items-start gap-1.5 rounded-[8px] bg-info-tint px-2.5 py-1.5 text-xs text-info-ink
            + Info h-3.5 w-3.5 flex-none (strokeWidth 1.75), 아이콘 행 아래 카드 폭 전체
```
- 주의 줄이 `error` 가 아니라 **정보 톤**인 이유는 `UnavailableNotice` 와 같다 — 사용자가 고칠 수 없는 알려진 제약이라 error 색은 과하다([[ADR-060]] 결정 5). 규격도 그 컴포넌트의 compact 변형을 카드 안 크기로 축소해 승계했다. **컴포넌트 자체를 재사용하지 않는 것은** `UnavailableNotice` 가 문구를 자기 안에 고정으로 갖기 때문이다(임의 문구를 못 받는다).
- 선택 표시는 테두리+틴트뿐이고 **체크 마크를 두지 않는다** — 보스 관리 화면 선례와 통일.
- **바깥 카드 클래스(`rounded-[10px] border ... px-4 py-3`)는 `AccountSelectionList`/`ThemeSelector` 와 계속 공유**한다. 바뀐 것은 안쪽뿐이다.
