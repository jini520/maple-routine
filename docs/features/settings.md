## 화면 구조

[[ADR-118]](구현 완료 2026-08-09, 이슈 #135·#161)이 정하고 [[ADR-125]]·[[ADR-140]]·[[ADR-144]] 가
행을 더했다.

**설정은 한 화면이 아니라 얕은 계층이다.** 가르는 기준은 행이 몇 개인가가 아니라 **성격이 다른 것을
붙여 두지 않는다**이다.

```
설정 (본화면: 고정 헤더 없음)
 [카드 1]  스케줄 관리 방법            자동 ›      ← 값을 고르는 행
           테마                      혼테일 ›
           캐릭터 관리                  3개 ›
 [카드 2]  기능 설명                        ›      ← 화면이 넘어가는 행
           개발 노트                        ›
           계정 및 데이터            1.2 MB ›
           앱 정보                    1.0.7 ›
 [footer]  v1.0.7 / © 2026 메이플 루틴 / Data based on NEXON Open API / 비제휴 고지
```

하위 화면은 여덟이다. 라우트 이름은 `navigation/routes.ts` 가 갖는다.

| 경로 | 화면 | 내용 |
|---|---|---|
| `/settings/guide` | `SettingsFeatureGuideList` | 기능 축 카탈로그. **사용법 설명의 원천**([[ADR-125]] 결정 1) |
| `/settings/guide/:guideId` | `SettingsFeatureGuide` | 안내 상세. 목차 + 이미지 + 문단, `?s=` 로 마디 지정 |
| `/settings/release-notes` | `SettingsReleaseNotes` | 버전별 변경 목록([[ADR-119]]) |
| `/settings/release-notes/:guideId` | `SettingsReleaseNoteGuide` | **위와 같은 화면에 같은 데이터.** 경로만 둘이다 |
| `/settings/account-data` | `SettingsAccountData` | 캐시 데이터 삭제 · 연결 해제. 둘 다 위험 색 |
| `/settings/characters` | `SettingsCharacters` | 캐릭터 관리([[ADR-144]]) |
| `/settings/about` | `SettingsAbout` | 현재 버전 · 상태 · 업데이트 확인 · 개인정보 처리방침 |
| `/settings/about/privacy` | `SettingsPrivacy` | 안내 사이트를 `WebView` 로 싣는다([[ADR-120]] 결정 11) |

### 본화면에는 고정 헤더가 없다

`SettingsScreen` 은 `PageHeader` 셸 없이 `p-4` 안의 평범한 제목이다(⛔ ADR-098 결정 3).

원래 근거는 스케줄러에서 관측된 **탭 복귀 프레임 튐**이 이 화면에서는 날아갈 고정 헤더가 없어
구조적으로 일어날 수 없다는 것이었다. RN 에서는 [[ADR-131]] 이 모든 화면의 고정을 없앴으므로 그
차이 자체가 없어졌지만, 이 화면이 `PageHeader` 를 안 쓰는 것은 그대로다.

**하위 화면 여덟은 반대로 `PageHeader` 를 쓴다.** 뒤로 가기 버튼이 필요하기 때문이다. 셸은
`ScreenScroll` + `PageHeader` + 좌측 `ArrowLeft` 이고 루트 스택 위로 push 된다. 하위 화면에는 탭바가
없다.

**높이는 아직 실측하지 않았다.** ⛔ ADR-098이 잰 값(390px 폭 + iPhone 안전영역 59/34 기준 필요 높이
835pt)은 [[ADR-118]] **개편 전** 구조의 것이다. 개편 후 7행 + 고지 4줄의 실제 높이는 구현 뒤에도 재지
않았다. jsdom은 레이아웃을 계산하지 않아 자동 테스트가 원리적으로 못 본다([[ADR-118]] 미검증 1).

### 섹션 제목을 달지 않는다

두 카드를 덮는 제목(‘동작·표시’ / ‘관리·정보’)은 행 이름보다 덜 구체적이라 읽는 사람이 얻는 것이
없다. **카드 경계만으로 가른다.**

옛 제목 둘(‘데이터 관리’ · ‘앱 업데이트’)은 그 아래 행이 하나뿐이라 사실상 행 이름이었고, 두 섹션이
하위 화면으로 내려가면서 함께 없어졌다.

### 파괴적 행은 하위 화면 안에서 다시 가른다

본화면에서 빼는 것만으로는 분리가 아니다. 옮긴 곳에서 다시 다른 행과 붙으면 같은 문제가 한 층
내려갈 뿐이다. 그래서 `/settings/account-data` 안에서도 **별도 카드**로 내린다. 그 카드에도 제목을
달지 않는다. 위험 색과 카드 경계가 이미 말한다.

### 대표값은 확실히 아는 것만 보여준다

카테고리 행은 오른쪽에 대표값 하나를 미리 보여준다.

| 행 | 대표값 |
|---|---|
| 계정 및 데이터 | 캐시 총 용량(`getCacheDataSizes()` 두 그룹의 합) |
| 앱 정보 | 현재 버전(`currentVersion ?? packageJson.version`) |
| 기능 설명 · 개발 노트 | **비운다** |

**없는 대표값을 지어내지 않는다**([[ADR-118]] 결정 5). 개발 노트의 "최신 버전"은 바로 아래 행과 같은
값이고, 둘 다 "n개"는 뜻이 없다.

- **조회 전 자리는 `- KB` 로 잡는다**([[ADR-061]] 결정 7). 빈 문자열이면 값이 툭 나타나며 행이 밀린다.
  조회에 실패해도 같은 자리표시로 남는다. 설정을 못 여는 실패가 아니다.
- **캐시 용량 조회는 드릴다운하면 2회다.** 본화면과 `/settings/account-data` 가 각각 마운트할 때
  읽는다(구현 확인 2026-08-09). 값을 프롭이나 store로 물려 내리지 않은 이유는 하위 화면이 **직접
  진입할 수 있는 라우트**라, 본화면을 거치지 않으면 물려받을 값이 없기 때문이다. **체감 지연은
  측정하지 않았고**, 확인되면 그때 캐싱 위치를 정한다([[ADR-118]] 미검증 3).

## 행 규격

행은 공용 `Card` atom(`rounded-[14px] border border-border bg-surface`, [[ADR-094]]) 안에 이어붙인다.
여백과 구분선은 레이아웃이라 호출부가 준다(Card atom 규약). 본화면은 이 카드가 둘이고
([[ADR-118]] 결정 1) 하위 화면도 같은 카드를 쓴다.

행 골격은 `row-class.ts` 의 **`SETTINGS_ROW_CLASS`** 한 곳에 있다
(`flex w-full items-center justify-between py-4 text-left`). 왼쪽 라벨은
`text-sm font-medium text-text` 이고 위험 동작은 `text-error-ink` 다.

**골격이 컴포넌트 파일이 아니라 별도 파일인 이유는 lint 다.** 컴포넌트 파일이 컴포넌트 아닌 값을
함께 export 하면 fast refresh가 깨진다(`react-refresh/only-export-components`). `Button/variants.ts`
와 같은 판단이다.

### 우측 표기 5종

[[ADR-118]] 결정 4(2026-08-09)다.

| 종류 | 왼쪽 | 오른쪽 | 쓰는 곳 |
|---|---|---|---|
| **설정 행** | 라벨 | 현재값 배지 **+** chevron | 스케줄 관리 방법 · 테마 |
| **이동 행** | 라벨 | 대표값(있으면) **+** chevron | 개발 노트 · 계정 및 데이터 · 앱 정보 · 캐릭터 관리 |
| **표시 행** | 라벨 | 값 평문, **누를 수 없다** | 현재 버전 · 상태 |
| **외부 링크 행** | 라벨 | 외부 링크 아이콘 | (지금 호출부 없음. 아래 참고) |
| **실행 행** | **위험 색** 라벨 | 보조 수치, **chevron 없음** | 캐시 데이터 삭제 · 연결 해제 |

> **chevron이 있으면 누르면 무언가 열린다. 없는 위험 색 행은 누르면 지운다.**

- **배지와 chevron을 병기한다.** 전에는 `rightContent ?? chevron` 이라 값이 있으면 화살표가
  사라졌고, 그래서 같은 "누르면 모달이 열린다"는 세 행 중 하나에만 화살표가 있었다. 화살표가 **동작이
  아니라 값의 유무**를 말하고 있었다.
- **`showChevron={false}` 로 호출부마다 판단하게 두지 않는다.** 그것이 옛 상태이고, 판단이 흩어져
  있으면 새 행마다 다시 틀린다. 그렇다고 모든 행에 chevron을 다는 것도 아니다. 위험 색 행에
  화살표가 붙으면 "다음 화면이 있다"로 읽혀 확인 모달이 의외가 된다.
- **표시 행은 누를 수 없다.** 아무 일도 일어나지 않는 것을 누를 수 있게 그리지 않는다.
- **테마 행 오른쪽에 색 표식을 두지 않는다**([[ADR-104]] 결정 5, 2026-08-06). 어떤 테마인지는 이름이
  말하고, 그 색은 지금 눈앞의 화면 전체가 이미 말한다.

### 행 컴포넌트 둘

**시맨틱이 달라서 하나로 합치지 않는다.** 합치면 `onPress` 가 선택 필드가 되어 호출부가 어느 쪽인지
타입으로 알 수 없다.

| 컴포넌트 | 무엇 | 눌렀을 때 |
|---|---|---|
| `SettingsRow` | 버튼 | 모달이 열리거나 화면이 push 된다 |
| `SettingsLinkRow` | `Pressable role="link"` + `Linking.openURL` | **앱을 떠나 시스템 브라우저로 간다** |

**`SettingsLinkRow` 는 지금 호출부가 없다.** 유일한 호출부였던 개인정보 처리방침이 [[ADR-120]] 결정
11로 앱 안 하위 화면이 되면서 사라졌다. 그래도 남겨 두는 이유는 위 5종 규격이 이 프리미티브로
고정돼 있어서다. 다섯 중 하나를 지우면 다음에 외부 링크 행이 필요할 때 규격이 아니라 그때의 즉흥이
다시 자리를 잡는다.

RN으로 옮기며 `<a target="_blank">` 가 `Pressable` + `Linking.openURL` 이 됐고,
`rel="noopener noreferrer"` 는 사라졌다. 그것은 브라우저 탭 사이의 문제였고(새 컨텍스트가
`window.opener` 로 원래 문서를 만지는 것) RN 에는 그 관계 자체가 없다. OS 브라우저는 우리 프로세스
밖이다.

### 모달

공용 `components/Modal` 을 쓴다([../foundation/design-system.md](../foundation/design-system.md)).

**하위 화면에서 모달은 카드 밖이자 `ScreenScroll` 밖의 형제다.** 카드 안이면 구분선이 하나 더
그려지고, 셸 안이면 그 셸이 만든 스태킹 컨텍스트에 갇혀 오버레이가 탭바 아래로 그려진다
([[ADR-099]]).

## 카드 1: 고르는 행

이 카드의 성질은 **누르면 고르고, 고르면 그 자리에서 끝난다**이다.

### 스케줄 관리 방법 (트래킹 모드)

자동·수동 전역 토글이다([[ADR-035]] 결정 1). 행 라벨과 모달 제목이 "스케줄 관리 방법"이고(2026-07-25
개편, 이전 이름은 "트래킹 모드") 내부 컴포넌트와 store 이름은 `TrackingMode*` 그대로다. 오른쪽
배지에 현재 모드(자동 · 수동)를 보여준다.

**고르는 것과 적용하는 것을 나눈다**([[ADR-035]] 결정 23, 2026-08-03). 옵션을 누르는 것은 고르는
것뿐이고, 모달이 고른 값을 자기 상태로 갖고 있다가 ‘적용’에서 한 번만 `setMode` 를 부른다.

```
버튼   우측 정렬 취소(고스트) + 적용. DisconnectConfirm·CacheClearConfirm 과 같은 골격
       취소  rounded-full px-5 py-2.5 text-sm font-medium text-text-muted
       적용  rounded-full bg-primary text-on-primary px-5 py-2.5 text-sm font-semibold
             (파괴적 동작이 아니라 진행 동작이라 저 둘의 border-error 가 아니다)
적용 중 버튼 안 MapleSpinner size={16} + 라벨 "적용 중" + disabled + aria-busy
```

- **현재 모드와 같으면 적용 버튼이 비활성이다.** 바뀐 것이 없으면 누를 것도 없다. 닫기는 취소와
  오버레이가 맡는다.
- **수동으로 바꾸는 동안에는 옵션과 취소도 비활성이다.** `setMode` 가 시드([[ADR-035]] 결정 14(a))가
  끝날 때까지 resolve 되지 않기 때문이다. 저장 도중에는 오버레이를 눌러도 닫히지 않는다.
- **적용이 끝나면 컨텐츠 → 보스 → 수익 세 탭 스토어를 순차로 다시 읽힌다**([[ADR-140]] 결정 5 정정,
  2026-08-16). 시드는 저장소(`manualTrackedContent`)를 채우지만 수동 모드의 표시 목록을 정하는 것은
  **store 메모리의 사본**(`manualTrackedByOcid`)이고, RN 탭 화면은 마운트된 채 남아 스스로 다시 읽지
  않는다. 이 재로드가 없으면 자동에서 수동으로 바꾼 직후 세 화면이 ‘모드는 수동인데 멤버십은 빈 맵’을
  그렸다(보스 탭의 "추적할 주간 보스가 없습니다". 새로고침하면 나왔다). 취소나 오버레이로 닫으면
  부르지 않는다. 순차 실행 · 기다리지 않음 · 실패 삼킴은 캐릭터 저장 뒤 재로드와 같은 정책이고 코드도
  같은 파일(`settings/reload-tab-stores.ts`)을 쓴다.

#### 옵션 카드 안쪽

[[ADR-035]] 결정 22(2026-08-03)다. 카피는 화면이 아니라
`features/tracking-mode/copy.ts` 가 갖는다. **화면에 손으로 적으면 같은 선택지의 설명이 두 벌이
된다.**

카피는 세 필드다. `title`(자동 · 수동) · `description`(한 문장) · `caution`(그 모드의 한계 한 문장).
문구 전문과 그 이유는 [[ADR-035]] 결정 22에 있다.

```
카드 안쪽:  flex items-start gap-3
            아이콘  h-5 w-5 flex-none text-primary-ink: 자동 Gamepad2 / 수동 ListChecks (배지 없이 단독)
            제목    text-sm font-semibold text-text
            설명    text-sm text-text-muted   ← 접지 않고 항상 표시(고르기 전에 비교하는 화면)
주의 줄:    mt-2 flex items-start gap-1.5 rounded-[8px] bg-info-tint px-2.5 py-1.5 text-xs text-info-ink
            + Info h-3.5 w-3.5 flex-none (strokeWidth 1.75), 아이콘 행 아래 카드 폭 전체
```

- **주의 줄이 `error` 가 아니라 정보 톤인 이유**는 `UnavailableNotice` 와 같다. 사용자가 고칠 수 없는
  알려진 제약이라 error 색은 과하다([[ADR-060]] 결정 5). 규격도 그 컴포넌트의 compact 변형을 카드 안
  크기로 줄여 승계했다. **컴포넌트 자체를 재사용하지 않는 것은** `UnavailableNotice` 가 문구를 자기
  안에 고정으로 갖기 때문이다. 임의 문구를 못 받는다.
- **선택 표시는 테두리와 틴트뿐이고 체크 마크를 두지 않는다.** 보스 관리 화면 선례와 통일한다.
- **바깥 카드 클래스(`rounded-[10px] border ... px-4 py-3`)는 `ThemeSelector` 와 계속 공유한다.**
  바뀐 것은 안쪽뿐이다.

### 테마

등록된 테마 중 하나를 고르면 즉시 반영된다. 목록은 카테고리 섹션(기본 · 직업 · 보스)과 2열 프리뷰
타일이고 위에 라이트·다크 필터 칩이 붙는다([[ADR-104]]).

**고른다고 모달이 닫히지 않는다.** 모달 자신이 선택한 테마 색으로 그려지므로 그 자리에서 갈아입혀
보게 두고, 닫기는 ‘완료’ 버튼과 오버레이 탭이 맡는다([[ADR-104]] 결정 7).

**버튼은 ‘완료’ 하나다**(`mt-4 flex justify-end`. `TrackingModeModal`·`DisconnectConfirm` 과 같은
골격). 취소와 적용 2단계를 쓰지 않는 이유는 선택이 이미 적용돼 **취소할 대상이 없기** 때문이다.
되돌리려면 원래 테마를 다시 고르면 된다.

`ThemeSelector` 는 `job-themes.json` 을 직접 import 한다. 비활성 테마의 색이라 CSS 커스텀
프로퍼티로는 부족하다. 거른 결과가 0인 섹션은 헤더째 감춘다. 선택 계약은 `aria-pressed` 와
`onSelect` 다. 정책과 카테고리 소속은 [theme.md](./theme.md) 에 있다.

### 캐릭터 관리

**피커를 여는 유일한 곳이다**([[ADR-140]], 2026-08-16). 스케줄러 두 화면의 헤더 버튼을 없애고 이 한
행으로 모았다.

카드 1에 드는 이유는 성질이 이 카드와 같기 때문이다. 누르면 고르고, 고르면 끝난다. 위치는 ‘테마’
아래다(사용자 지정).

**[[ADR-144]] 가 그 모달을 하위 화면으로 바꿨다**(2026-08-16 결정, 구현 완료 2026-08-17). 계정
드롭다운 · 후보 · 선택됨 · 순서 · 대표가 한 화면에 들어가면 385px 모달 본문(⛔ ADR-107 결정 2)에
담기지 않는다. **행의
위치와 배지는 그대로**이고 갈리는 것은 누르면 무엇이 뜨는가뿐이라, 카드 1의 성질은 유지된다. 화면이
pop 되면 설정으로 돌아온다.

- **배지는 추적 캐릭터 수다**(`3개`). [[ADR-144]] 결정 8이 ‘명’을 ‘개’로 정정했다. 캐릭터는 사람이
  아니고 계정 선택 목록도 이미 ‘캐릭터 {N}개’였다. [[ADR-118]] 결정 5의 "없는 대표값을 지어내지
  않는다"에 걸리지 않는다. 파생값이나 추정값이 아니라 저장된 목록의 길이이고, 피커를 열려면 어차피
  읽는 값이다. 아직 못 읽었으면(`null`) 배지를 그리지 않는다([[ADR-101]] 결정 1).
- **저장은 컨텐츠 스케줄러 store의 `saveTrackedOcids` 를 그대로 부른다**([[ADR-140]] 결정 4. 세 번째
  사본을 만들지 않는다). 그 뒤 보스와 수익 store를 순차로 다시 읽힌다(결정 5). 로스터 로딩 · 실패 ·
  재시도 정책은 [content-scheduler.md](./content-scheduler.md) 의 "캐릭터 관리 피커" 절 그대로다.
- **`openPicker` 파라미터로 열린 채 진입할 수 있다.** 보스 수익의 "캐릭터 선택하러 가기"([[ADR-068]]
  결정 4)와 두 스케줄러의 빈 상태 CTA가 그리로 보낸다. 마운트 직후 `setParams` 로 지운다. 안 지우면
  탭을 떠났다 돌아올 때마다 다시 열린다.

#### 순서는 핸들을 끌어서 바꾼다

[[ADR-144]] 결정 5(구현 완료 2026-08-17)다. 놓은 자리가 곧 배열 순서이고, 그 배열이 저장 순서이자
표시 순서다([[ADR-143]] 결정 3). **끌기 자체는 `react-native-sortables` 가 한다**([[ADR-207]],
2026-09-03. 그 전에는 손으로 만든 것이었다).

- **핸들에서만 시작한다.** 행 아무 데서나 끌리면 페이지 세로 스크롤과 충돌한다. 아래 층(후보)에는
  핸들도 끌기도 없다. 그쪽 순서는 사용자 것이 아니라 레벨 내림차순이다.
- **두 층이 한 격자다**([[ADR-213]]). 카드가 층을 넘는 것이 그 격자 안의 재배열이라, 눌러서
  옮겨도 카드가 옛 자리에서 새 자리로 미끄러진다. 두 목록으로 가르면 그 움직임이 사라진다.
  끌어서 층을 넘을 수는 없다. 구분자와 후보 행이 고정이라 위층 행이 내려갈 자리가 없다.
- **끄는 동안 화면 위아래 가장자리에서 자동으로 스크롤된다.** 고정 영역을 두지 않기로 했으므로
  ([[ADR-131]]) 목록이 화면보다 길면 이것 없이는 끝으로 옮길 수 없다. 스크롤 주체는 화면의
  `ScreenScroll`·`OnboardingStep` 이라, 화면이 `useAnimatedRef` 하나를 만들어 그 셸과 목록 양쪽에
  넘긴다. 셸에는 `tracksScrollOffset` 을 함께 켠다 — 안 켜면 iOS 가 스크롤이 멈출 때 한 번만
  이벤트를 보내 끌기 중 오프셋이 낡는다([[ADR-207]] 결정 4).
- **접근성 액션 ‘위로 옮기기’·‘아래로 옮기기’가 같은 결과를 낸다.** 끌기는 스크린리더로 조작할 수
  없고 **라이브러리에는 접근성이 한 줄도 없다**. 액션은 핸들에 붙고(그 자리의 이름이 ‘{이름} 순서
  변경’이다) **할 수 있는 것만 준다**(첫 행에 ‘위로’가 없다). 두 경로가 같은 순수 함수 `moveOcid`
  하나를 부른다. 그 함수가 남아 있는 이유가 이것이다.
- **끌기가 그리던 순서와 저장되는 순서가 같은지 테스트가 맞대 본다.** 화면에 그려지는 순서는
  라이브러리가 만들고 저장되는 배열은 `moveOcid` 가 만든다. 갈리면 손을 떼는 순간 목록이 눈에
  보이던 것과 다르게 튄다([[ADR-207]] 결정 3).
- **저장할 때 정렬을 다시 계산하지 않는다.** 레벨 내림차순은 ‘아직 순서를 정하지 않았을 때의
  초기값’으로 내려갔다([[ADR-143]] 결정 3).

## 카드 2: 넘어가는 행

### 기능 설명

[[ADR-125]](구현 완료(글만) 2026-08-10, 이슈 #198)다. 개발 노트 한 줄은 *"바뀐 것이 있다"* 까지만
말한다. **사용법은 기능 축 카탈로그 한 벌**(`/settings/guide`)에 있고 **개발 노트는 거기로 링크만
건다.** 같은 설명이 두 벌 있으면 반드시 갈라지고, 버전 축만으로는 *"지금 이 앱을 어떻게 쓰나"* 에 답할
곳이 없다.

- **그룹은 `컨텐츠·보스·수익·유틸리티·설정` 이다**(사용자 지정). 넷은 하단 탭바와 글자까지 같고
  `유틸리티` 만 그 축 밖이며 **지금은 비어 있다.**
- **‘캐릭터 관리’ 안내는 컨텐츠·보스·설정 세 그룹에 함께 나온다.** 앞의 둘은 양쪽이 같은 피커를 쓰기
  때문이고, 설정은 RN 앱에서 그것을 여는 곳이기 때문이다([[ADR-140]] 결정 6). 그래서 안내는 `group`
  하나가 아니라 `groups` 배열을 갖고, 사본이 아니라 **같은 글 한 벌**이 여러 탭에 나온다. 반대로
  ‘인게임 데이터 연동’은 컨텐츠 편과 보스 편이 **다른 글**이다. 같은 API 지만 신경 쓸 것이 다르다.
- **비어 있는 그룹은 탭째 감춘다**(개발 노트 카테고리 묶음 · `ThemeSelector` 와 같은 규칙). 지금
  `유틸리티` 가 그렇다.
- **그룹이 하나면 탭 줄 자체를 그리지 않는다.** 선택지가 둘 이상일 때만 탭이 뜻을 갖는다. 탭
  스타일은 공용 탭 토글 그대로다([[ADR-018]]).
- **개발 노트에서는 안내를 가진 항목만** 눌러 들어갈 수 있고 `›` 가 붙는다. 나머지 항목은 종전과
  같다. 버그 수정 한 줄에 붙일 사용법은 없고, 액션 없는 곳에 비활성 버튼을 두지 않는다.

#### 상세가 두 부모 아래 각각 라우팅되는 이유

`/settings/guide/:guideId` 와 `/settings/release-notes/:guideId` 둘이다. 한쪽으로 몰 수 없는 이유는
`resolveStackDirection`(`lib/stack-transition.ts`)이 push 인지 pop 인지를 **경로 접두 관계**로 판정하기
때문이다. 형제로 건너뛰면 `replace` 가 되어 밀려 들어오는 전환이 사라진다.

화면과 데이터는 한 벌이고 경로만 둘이라, 상세는 부모를 `resolveParentPath(pathname)` 로 **깎아
쓴다.** 어디서 왔든 그리로 돌아가야 한다. 없는 `:guideId` 로 들어오면 **들어온 쪽 목록**으로
`replace` 한다.

#### 본문과 이미지가 사는 곳

- **본문은 `release-notes.ts` 밖에 산다.** `scripts/publish-live-update.mjs` 가 그 파일을 **Node에서
  직접 import** 하므로 `.webp` import를 넣으면 배포가 죽는다. 그래서 노트 항목엔 `guideId?: string`
  만 남기고 본문은 `src/data/feature-guides/` 에 둔다. 갈라짐은 **미아 참조 금지** 테스트가 막는다.
  **반대 방향은 강제하지 않는다.** 카탈로그가 원천이므로 노트가 가리키지 않는 안내는 정상이다.
- **안내 하나가 파일 하나다**([[ADR-125]] 결정 8, 2026-08-11). 폴더는 그룹을 따르되 **두 그룹에 나오는
  안내는 `shared/`** 다(`character-manage`). 폴더는 소유를 뜻하는데 소유자가 둘이기 때문이다.
  `index.ts` 는 **조립만** 하고 본문을 담지 않는다. 쪼개면서 생긴 실패는 **파일은 만들었는데
  `index.ts` 에 안 넣는 것**이고, 데이터 테스트가 폴더를 훑어 막는다(안내 수 = 파일 수).
- **이미지는 앱 번들에 넣는다**(`src/assets/guide/<안내 id>/`). 안내 파일이 직접 명시적으로 import
  한다. 원격 로드는 오프라인에서 안내가 통째로 비어 기각했다. 파일 목록을 자동으로 훑지 않는 이유는
  파일명이 틀렸을 때 `undefined` 로 조용히 통과하는 대신 **빌드가 실패해야** 하기 때문이다. 규약은
  `src/assets/guide/README.md` 에 있다.
- **OTA는 번들 전체를 압축**하므로 지연 로드가 용량을 깎아 주지 않는다. 한 장당 상한과 누적 상한을
  정해 관리한다(값은 첫 촬영분을 실측한 뒤). 기준선(이미지 0장)은 zip 5.6MB 다.

#### 노트는 안내가 아니라 그 안의 마디를 가리킨다

[[ADR-125]] 결정 7이다. 릴리스에서 바뀌는 것은 보통 기능 전체가 아니라 그중 한 마디다. 안내는
`sections` 를 갖고 화면 위에 **목차**가 뜬다(마디가 둘 이상일 때만). 목차는 **카드 없이** ‘목차’ 제목과
번호 목록이고, 번호는 버튼 밖이라 누를 수 있는 이름이 마디 제목 그대로다.

- **마디는 라우트 파라미터 `section` 이다**([[ADR-125]] 결정 7 정정). 목차를 누르면
  `navigation.setParams` 로 그 값만 갈아 끼운다 — 스택을 건드리지 않으므로 화면이 밀려 들어오지
  않는다. 웹에서는 같은 목적을 쿼리 `?s=` 로 이뤘고, 그때 세그먼트를 피한 이유였던
  `resolveStackDirection` 은 RN 에 아예 없다.
- **스크롤은 즉시 하고 한 번만 한다.** 전환과 겹치면 둘 다 어그러지고, 여러 번 하면 목차로 옮겨 놓고
  되끌려 간다.
- **없는 마디는 조용히 첫머리로 가므로 데이터 테스트가 실재 여부를 막는다.** 참조 중복 금지도 안내가
  아니라 **(안내, 마디) 쌍** 단위다.
- **목록은 안내 본문을 import 하지 않는다.** 목록이 상세 모듈에서 상수를 가져오면 안내 카탈로그
  전체가 목록의 import 그래프에 딸려 들어온다. RN 은 경로를 조립하지 않고 라우트 이름과 파라미터만
  넘기므로 이것이 저절로 지켜진다 — 웹이 쓰던 `lib/guide-route.ts` 는 그래서 삭제됐다(2026-08-31).

### 개발 노트

[[ADR-119]](2026-08-09, 이슈 #161)다. 버전별 변경 목록을 **앱 번들에 넣은 데이터**
(`src/data/release-notes.ts`)로 보여준다. 네트워크를 0회 타고 오프라인에서도 과거 전체가 보인다.

같은 파일에서 배포 스크립트가 그 버전의 **핵심 목록**(`highlights`)을 뽑아 `latest.json` 으로
파생시키고 업데이트 모달이 그것을 쓴다. 원천 하나에 소비자 둘이다. 모달은 전체가 아니라 3~4줄이다
([[ADR-126]] 결정 2).

**이 화면에 들어오는 길은 둘이다.** 설정의 행, 그리고 **업데이트 적용 후 재시작 직후 뜨는 ‘업데이트를
마쳤어요’ 안내의 ‘자세히 보기’**([[ADR-126]] 결정 1)다. 뒤쪽이 여기로 오는 이유는 그 시점에야 새 버전
노트가 앱 안에 있기 때문이다.

- **버전 축은 OTA 번들 버전이다.** 과거 버전은 **GitHub 마일스톤에 닫힌 이슈가 있는 것만** 싣는다
  ([[ADR-119]] 결정 4). 커밋을 읽고 사후에 재구성하지 않으므로 마일스톤이 없는 `1.0.1` 은 건너뛴다.
- **항목마다 카테고리가 붙는다**(`기능` · `개선` · `버그`. 이슈 접두사 승계). 화면은 배지가 아니라 **그
  카테고리로 묶어** 보여준다. 순서는 기능 → 개선 → 버그로 고정이고 빈 묶음은 제목째 감춘다
  ([[ADR-119]] 결정 9).
- **화면이 `RELEASE_NOTES` 를 배열 순서 그대로 그린다.** "최신이 먼저"는 데이터 파일의 계약이고 그 강제는 데이터 테스트가
  한다. 화면이 정렬하면 같은 규칙의 진실이 두 곳에 생긴다.
- **표식은 버전이 아니라 항목에 붙는다**([[ADR-119]] 결정 3). 지금 실행 중인 번들과 같은 버전의
  카드에만 `사용 중` 배지(`primary`)를 달고, `requiresStoreUpdate` 항목에는 그 항목 아래에 ‘스토어
  업데이트 필요’ 배지(`third`)를 단다. 스토어 이동을 말하는 `UpdatePromptModal` 의 `store-required`
  와 같은 톤이다.
- **로딩과 에러 상태가 없다.** 데이터가 번들 안에 있어 네트워크를 타지 않는다. 목록이 0건이면
  `EmptyState` 인데 지금은 도달할 수 없는 곳이다.
- **안 읽음 표시(배지·점)는 두지 않는다.** 키가 하나 늘고, 그 신호는 업데이트 모달이 이미 말한다
  ([[ADR-118]] 결정 9).

### 계정 및 데이터

#### 캐시 데이터 삭제

[[ADR-058]] 이다. 지울 데이터를 **2그룹 중 골라서** 지운다.

| 그룹 | 범위 |
|---|---|
| 일반 데이터 | 동기화 캐시 · 추적 목록 · 수동 추적 항목 · 공유 진행 원장 · 파티 설정 |
| 보스 수익 · 드롭 기록 | **복구 불가** |

인증과 사용자 설정 5개(`KEEP_KEYS`)는 어떤 선택에서도 보존되므로 이 기능으로 온보딩으로 돌아가지
않는다. 범위의 정확한 정의와 그룹 경계의 근거는
[../persistence/lifecycle.md](../persistence/lifecycle.md) 에 있다.

- **행은 위험 색**(`text-error-ink`)이고 오른쪽에 총 용량을 보여준다.
- **모달은 체크박스 2행**이다(`role="checkbox"`, 행 전체가 탭 영역). 각 행에 그룹 이름 · 설명 · 그룹
  용량이 있고, "보스 수익·드롭 기록" 행에는 복구 불가 경고가 붙는다.
- **보존 항목(‘유지됨’) 줄은 두지 않는다**([[ADR-058]] 결정 9).
- **기본은 두 그룹 모두 체크**라 열고 바로 삭제하면 기존 전체 삭제와 같다. 전부 해제하면 삭제 버튼이
  비활성이다([[ADR-058]] 결정 6). 삭제 중에는 두 버튼과 체크박스가 비활성이다.
- **삭제 후 흐름은 선택과 무관하게 같다.** 타임아웃 경쟁 → **`closeBossProfitDb()` → 스플래시 →
  리로드** 순이다(⛔ ADR-050 결정 7, 순서는 [[ADR-117]] 결정 8).
  - **커버가 닫기 뒤인 것이 요점이다.** 먼저 올리면 닫기가 매달리는 동안 사용자가 브랜드 주황 화면에
    갇히고 그 화면에서는 터치도 죽는다. 이슈 #175의 OTA 적용과 증상이 같고 트리거만 다른 두 번째
    문이었다.
  - 닫기에는 5초 상한이 있고 예외를 던지지 않는다([[ADR-117]] 결정 5). `native/live-update.ts` 의 적용
    경로와 **마지막 한 줄만 다른 같은 모양**이다.
  - **실패하거나 타임아웃이면 리로드 뒤에 토스트로 알린다**([[ADR-065]] 결정 3). 리로드가 화면 신호를
    파괴하므로 `storage/pending-notice` 에 플래그를 남기고 부팅 후 "캐시를 일부만 삭제했습니다"를
    띄운다. 리로드를 막거나 부분 삭제를 되돌리지는 않는다. **앱의 다른 저장은 전부 Preferences 인데
    여기만 세션 저장소인 이유**는 이 알림의 수명이 "리로드는 넘기되 앱 종료와 함께 사라진다"이기
    때문이다. Preferences 는 영속이라 앱을 다시 켜도 남아 한참 뒤 엉뚱한 시점에 뜬다.

#### 연결 해제

`storage/api-key.ts` 의 `clearAuthConfig()` 와 `features/onboarding` 의 `RESET` 이벤트를 재사용해
온보딩 화면으로 돌아간다. 새 로직이 없고 기존 두 조각을 잇기만 한다.

**키 무효화(401/403) 복구 경로는 더 이상 이것이 아니다**([[ADR-115]], 2026-08-08). 아래
[API 키](#api-키) 를 볼 것. 연결 해제는 "이 기기에서 이 계정을 떼어낸다"는 사용자 의도 전용으로
남는다.

**두 경로가 지우는 범위가 다르다.** 연결 해제는 `apiKey` 와 `selectedAccountId` 둘 다 지우고
(`clearAuthConfig`), 무효화는 **`apiKey` 하나만** 지운다([[ADR-115]] 결정 3. `clearAuthConfig` 를 쓰면
재개가 불가능해진다).

### 앱 정보

`AppUpdateSection` 이 이 화면에 있다([[ADR-118]] 결정 2). 안은 **표시 행 둘**(`현재 버전` · `상태`.
값 평문, 누를 수 없다)과 `업데이트 확인` 버튼, 그리고 개인정보 처리방침으로 가는 행이다.

- **`AppUpdateSection` 은 섹션 제목을 스스로 그리지 않는다.** 이 카드가 놓이는 화면의 제목이 이미
  ‘앱 정보’라 같은 화면에 제목이 둘이 된다. 껍데기를 **떼고 `Card` 만 반환한다.** 제목을 숨기는 프롭을
  받는 방식이 아니다. 그러면 "제목을 그릴 수도 있다"는 죽은 분기가 남는다.
- **`up-to-date` 문구는 `최신 버전입니다` 다**([[ADR-118]] 결정 10, 2026-08-09. 이전은 `최신입니다`).
  `현재 버전` 행 바로 아래 `상태` 행에 놓이는 값이라, 주어가 생략되면 무엇이 최신인지가 문장 안에
  없다. 다른 상태 문구와 같은 하십시오체 어미 규칙([[ADR-062]])은 그대로다.

#### 개인정보 처리방침

2026-08-04 스토어 요건이다. **Play 사용자 데이터 정책은 스토어 등록정보와 앱 안 양쪽에 링크를
요구한다.** 콘솔에 URL을 넣는 것만으로는 충족되지 않는다
([../foundation/release.md](../foundation/release.md)).

**위치는 `/settings/about` 의 행이다**([[ADR-118]] 결정 7, 2026-08-09). 옛 위치(footer 맨 위)는 *"정적
고지 문구 사이에 끼면 링크로 안 읽힌다"* 를 색과 밑줄로 달래던 곳이었고, 독립된 행이 되면 그 문제
자체가 없어져 달래던 장치도 함께 필요 없어진다.

**스토어 요건은 그대로 충족된다.** 정책이 요구하는 것은 *"앱 안에 링크"* 이지 *"첫 화면에 링크"* 가
아니다. 설정에서 앱 정보까지는 두 번의 탭이고, 스토어 등록정보 쪽 URL은 이 변경과 무관하다.

**본문은 앱 안 화면이 `WebView` 로 싣는다**(`/settings/about/privacy`, [[ADR-120]] 결정 11, 구현 완료
2026-08-09). `about` 의 **자식**이라 2단 스택이다. 오프라인이면 안내와 함께 브라우저로 여는 버튼을
준다(`Linking.openURL`).

- **URL은 `mapleroutine.store/privacy` 다.** `PRIVACY.md` 를 렌더링해 서빙하는 그
  주소다([site.md](./site.md)). 앱 안에 정책 본문
  사본을 만들지 않는다. 사본을 두면 법적 문서가 두 벌이 된다.
- **웹의 8초 타임아웃은 사라졌다.** 그것을 유일한 신호로 삼았던 이유는 교차 출처 `iframe` 이 네트워크
  실패에 `error` 를 신뢰성 있게 발화하지 않기 때문이었다. `WebView` 는 `onError` 를 발화한다.

## API 키

### 무효 키는 안내 모달로 처리한다

무효 키(400 `OPENAPI00005` · 401/403)와 429는 **같은 사슬**을 탄다([[ADR-115]] 결정 10·4 ·
[[ADR-116]] 결정 1, 이슈 #178).

```
닫을 수 없는 안내 모달 → `확인` → 키 입력 화면 + 저장된 apiKey 삭제 → 뒤 단계는 저장된 값으로 재개
```

진입점은 `features/onboarding/store.ts` 의 `noticeApiKeyIssue(kind)` 이고, `useApiKeyNotice` 훅이
동기화 에러를 보고 부른다. 중복 호출은 그 안의 멱등 가드가 막는다.

문구만 원인에 따라 갈린다. `호출 한도를 초과했습니다` · `서비스 단계 키로 다시 입력해주세요.`

### ‘API 키 변경’ 행은 되살리지 않는다

[[ADR-118]] 결정 9(2026-08-09)다. [[ADR-115]] 결정 8이 *"#135와 함께 본다"* 로 미뤄 둔 미정의
**결론**이다.

- 무효 키와 429는 위 사슬로 이미 해결돼 있다. **사용자가 설정을 뒤져 키를 바꿀 이유가 없다.**
- 남는 경우는 **오류가 아닌데 자발적으로 갈아타는** 드문 경우뿐이라(다른 넥슨 계정 키, 서비스 단계
  키 승급. 후자는 429 안내가 이미 그리로 보낸다), 설정 구조를 정리하는 개편에서 행을 하나 더 늘리지
  않는다.
- **`useSettingsStore.changeApiKey` 는 지우지 않는다.** 로직과 테스트가 살아 있고 **배선만 없는
  상태로 계속 남는다.** 되살릴 땐 UI만 붙이면 되고, 그 경로의 401은 "방금 나쁜 키를 입력한 것"이라
  무효화와 성질이 달라 인라인 카드에 남는다는 것까지 정해져 있다.

  건드리지 않았다. 이슈 #135의 *"새 설정 항목 추가가 포함되는가"* 는 **포함되지 않는 것으로 확정**

  하나도 없는데 설정만 있으면 그 화면이 거짓말을 한다.** 첫 알림과 함께 OTA로 온다(화면은 전부 JS 라
  심사를 기다리지 않는다). 권한 요청 시점도 이 화면에서 켜는 순간 하나뿐이다. iOS는 한 번 거부하면
  다시 못 묻는다. 상세는 [notifications.md](./notifications.md) 에 있다.
- **업데이트 모달에 노트를 그리는 형태**(이슈 #164). 매니페스트에 `notes` 가 실리는 데까지는 됐고
  ([[ADR-119]] 결정 5), 모달은 아직 버전과 용량만 말한다.

## 열린 질문

- **[[ADR-118]] 개편의 미검증 4건**(2026-08-09 신설. 구현 완료 후에도 그대로 남는다. 넷 다 눈과
  실기기로만 판정된다).
  1. 본화면 7행 + 고지 4줄이 정말 스크롤 없이 들어가는가. 위 [본화면에는 고정 헤더가
     없다](#본화면에는-고정-헤더가-없다) 를 볼 것.
  2. 배지와 chevron 병기가 360px 폭에서 붐비지 않는가.
  3. 캐시 총 용량 조회 비용. **구현 결과 1회가 아니라 2회다.** 체감 지연 여부는 측정하지 않았다.
  4. 두 탭 깊이의 개인정보 처리방침이 스토어 심사에서 문제되지 않는가. 정책 문언상 충족하지만
     심사자 판단은 겪어 봐야 안다.
- **[[ADR-119]] 노트 원천의 미검증 2건.** ① 노트 한 벌이 두 소비자에게 정말 충분한가(**모달 쪽이 아직
  안 그려졌다.** 이슈 #164. 갈라야 하면 그때 필드를 나눈다. 지금 나누면 이중관리다) ② `notes` 를 실은
  새 매니페스트를 **옛 설치본**이 무사히 읽는가(테스트가 덮은 것은 반대 방향이다).
- **RN의 7번째 행이 ⛔ ADR-098 결정 3의 재판단 조건에 닿는가**([[ADR-140]], 2026-08-16 신설). 그
  결정은 *"행이 늘어 세로가 길어지면"* 고정 헤더를 다시 보라고 적었고, 이 개편은 [[ADR-118]] 이후
  **처음으로 행을 늘린 변경**이다(6 → 7). 다만 늘어난 것은 값 카드의 한 행뿐이라 판단은 눈으로 한다.
- **캐릭터 관리가 화면이 되면 카드 1의 성질이 흔들리는가**([[ADR-144]] 결정 1, 2026-08-16 신설). 그
  카드는 *"누르면 고르고, 고르면 그 자리에서 끝난다"* 인데 이 행만 화면을 push 한다. 행 셋 중 하나가
  chevron의 뜻을 달리 쓰는 셈이고, **그 차이가 실제로 읽히는지는 눈으로만 판정된다.** 읽힌다면 그
  행을 카드 2로 옮기는 것이 처방이다.

## 폐기된 정책 (history)

### 계정 변경: 화면과 코드가 전부 없어졌다

[[ADR-143]] 결정 7·10(2026-08-16, 구현 완료 2026-08-17)이다. 계정을 바꾸는 일이 **캐릭터 관리 화면의
드롭다운 안으로 들어갔다.** ‘바꾸면 추적 목록을 통째로 다시 고른다’는 전제 자체가 없어졌다. 이제
여러 계정의 캐릭터를 **함께** 고른다.

지워진 것: 화면 `AccountModal` · `AccountFlowStatus` · `AccountSelectionList` 와 그 셋만 쓰던
`app/settings/error-message.ts`(`formatSettingsError`). store 액션 `refreshAccounts` ·
`selectAccount` · `commitAccountChange` 는 소비자가 없다(정리 대상). 그래서 `/settings/account-data`
는 카드가 하나다(위험 색 행 둘).

**살아남은 계약 하나**: `resolveRegisteredCharacters(accountIdOverride?)` 가 계정을 인자로 받는
성질은 이 결정이 만든 것이고, 캐릭터 관리의 드롭다운이 바로 그 인자를 쓴다([[ADR-143]] 결정 5).
폐기되는 것은 플로우이지 그 계약이 아니다.

아래는 그 플로우의 기록이다.

- ~~계정 변경 행: 저장된 키로 `character/list` 를 다시 불러 계정을 고르고, 캐릭터를 다시 골라야
  커밋된다~~ → 흐름이 `확정 → 저장 → 예열 → 닫기` 에서 **`확정 → 예열 → 캐릭터 선택 → (저장
  시점에) 커밋`** 으로 바뀌었다가([[ADR-086]] 결정 6, 2026-08-03) 통째로 폐기됐다. 커밋을 캐릭터 선택
  저장 한 지점에 모아, 취소하거나 도중에 앱이 죽으면 이전 계정이 온전히 남게 한 것이었다.

- ~~계정 플로우 `error` 카드의 429 에는 ‘다시 시도’를 달지 않는다~~ → [[ADR-114]] 결정 1·2
