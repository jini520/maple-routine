# 온보딩 (Onboarding)

> **범위**: API 키 입력·계정(메이플 ID) 선택·전체 캐릭터 예열. 설정에서의 계정 변경/연결 해제는 [settings.md](./settings.md).
> **관련 소스**: `app/onboarding/` · `features/onboarding/` · `nexon/character` · `storage/api-key` · `storage/character-basic-cache` · `storage/scheduler-cache` · `AccountSelectionList` · `ApiKeyForm`.
> **관련 ADR**: [[ADR-007]] [[ADR-016]] [[ADR-015]] [[ADR-006]] [[ADR-051]] [[ADR-053]] [[ADR-086]]. **관련 문서**: [../foundation/nexon-api.md](../foundation/nexon-api.md), [../foundation/architecture.md](../foundation/architecture.md).

## 정책
- **키 입력**: `openapi.nexon.com` 링크 + 샘플 이미지 + 설명 문구로 가볍게 안내(앱 내 단계별 위저드 아님). 키는 `storage/` 보안 영역에 저장.
- **계정 선택**: 키 제출 즉시 `character/list` 호출(별도 검증 엔드포인트 없이 이 호출 자체가 키 검증). **계정 수와 무관하게 항상 "어느 메이플 ID를 쓸지" 선택 화면을 보여준다**([[ADR-051]]) — 계정이 1개여도 건너뛰지 않으며, 사용자가 "계속하기"로 확정해야 예열이 시작된다. 선택은 이후 설정에서 변경 가능. `storage/` 에는 `apiKey` 와 선택 `accountId` 만 저장(캐릭터 목록은 캐싱 안 함).
- **예열([[ADR-016]])**: 계정 확정 즉시 온보딩을 끝내지 않고, 그 계정 **전체 캐릭터**(추적 대상 무관) 데이터를 진행률 바와 함께 미리 받는다 — 이후 스케줄러·피커 첫 진입 시 로딩 없이 뜨게 하기 위함. `OnboardingStatus` 에 `'prefetching'` 추가, 각 캐릭터에 `character/basic` → `scheduler/character-state` 순서의 독립 파이프라인을 병렬 실행하고 하나 끝날 때마다 즉시 캐시 기록 + 진행률 갱신. 개별 실패는 그 캐릭터만 캐시 없이 넘어가고 전체를 막지 않는다. 전체 완료 시 `'completed'`. 캐릭터 많은 계정은 수 초 걸릴 수 있음(사용자 수용).
  - **`access_flag` 게이트를 걷어냈다**([[ADR-086]] 결정 3, 2026-08-03) — 전에는 `access_flag: true` 인 캐릭터만 scheduler 를 예열했다. [[ADR-067]] 계측이 "false 여도 세 엔드포인트 모두 200"을 확인했으므로 그 게이트는 **받을 수 있는 데이터를 안 받는 것**이었다. 대신 예열이 후보 자격 판정(`resolveCharacterEligibility`)을 함께 수행한다 — `access_flag: false` 이고 오늘 응답도 비었으면 과거 날짜를 거슬러 올라가며 활동 기록을 찾는다([content-scheduler.md](./content-scheduler.md) "후보 자격"). 휴면 캐릭터 1명당 최대 13회가 더 들지만 **캐릭터당 평생 한 번**이다(조회 원장이 재조회를 막는다).

## 단계 재개 — 끝내지 않은 온보딩은 그 지점부터 ([[ADR-086]] 결정 1·2, 2026-08-03)
온보딩은 `API 키 → 계정 선택 → 예열 → 스케줄 관리 방법 → 관리 캐릭터 선택` 다섯 단계다. 어느 단계에서 앱을 종료하든 **다음 실행에서 그 단계부터 이어간다**. 전에는 `restoreFromStorage` 가 `selectedAccountId` 하나만 보고 곧바로 `completed` 로 전이해, 모드·캐릭터를 고르지 않은 채 빈 메인으로 떨어졌다.

재개 지점은 **저장된 값에서 파생한다 — 진행 상태 전용 키를 두지 않는다.** 각 단계의 산출물이 이미 영속화돼 있어서, 진행 상태를 따로 쓰면 진실이 둘이 되고 한쪽만 써진 채 앱이 죽는 순간 어긋난다(고치려는 결함과 같은 종류의 결함이다).

| 저장 상태 | 재개 단계 |
|---|---|
| `apiKey` 없음 | `awaitingApiKey` |
| `selectedAccountId` 없음 | `selectingAccount`(저장된 키로 `character/list` 재조회) |
| `trackingMode` 미선택 | `selectingTrackingMode` |
| `trackedCharacters` 가 `null` 또는 `[]` | `selectingContentCharacters` |
| 그 외 | `completed` |

- **뒤 두 단계는 네트워크 없이 재개된다** — 모드 선택은 순수 UI, 캐릭터 선택은 `getCharacterPickerRoster` 가 자체 조회한다. **예열([[ADR-016]])을 다시 돌리지 않는다**(원장·캐시가 이미 부분적으로 따뜻하고, 조회 원장이 중복 호출을 막는다 — [content-scheduler.md](./content-scheduler.md) "조회 원장").
- **`trackedCharacters === []` 는 완료가 아니다** — 최소 1명 규칙이 있으므로 빈 배열은 미완료와 동치다. 저장 레이어의 `null` vs `[]` 구분([[ADR-012]])은 그대로 두고, 온보딩 게이트에서만 둘을 같게 읽는다.
- **`trackingMode` 미선택을 `'auto'` 로 읽지 않는다.** `getTrackingMode()` 가 `TrackingMode | null` 을 반환하고 소비처가 `?? 'auto'` 로 흡수한다 — **동작 기본값은 그대로 자동**([[ADR-035]] 결정 2)이고, 바뀌는 것은 "골랐는가"를 구분할 수 있게 된 것뿐이다. 고르지 않은 값을 화면이 "선택됨"으로 표시하는 것만 없앤다.
- **마이그레이션**: `trackingMode` 키가 없는데 `selectedAccountId` 와 비어 있지 않은 `trackedCharacters` 가 이미 있으면([[ADR-035]] 이전 설치본 완주자) `'auto'` 를 1회 기록한다 — 안 하면 정상 사용자가 온보딩으로 되돌려진다.

## UI

### API 키 검증 중 — 폼 유지 + 버튼 스피너 (2026-07-16)
키 제출 시 화면을 이동시키지 않고 `ApiKeyForm` 을 그대로 유지한다(정상 경로 1초 미만이라 "확인 중" 문구가 깜빡이는 게 거슬림 → 문구 제거). `verifyingApiKey` 동안 `isSubmitting` 으로 유지, 입력값·위치 그대로, 제출 버튼 내용만 "확인"→스피너로 바꾸고 비활성화. 예열(prefetching)처럼 수 초 이상 걸리는 작업은 제외(진행률 바 표시).
```
버튼 스피너: h-5 w-5 rounded-full border-2 border-bg/30 border-t-bg animate-spin motion-reduce:animate-none
접근성: aria-busy, aria-label="확인 중", 스피너 aria-hidden
```

### 계정(메이플 ID) 선택 목록 — `AccountSelectionList`, 2026-07-16, [[ADR-006]]
각 계정 = [대표 캐릭터 얼굴 아바타 36px 원형] + 텍스트 2줄. 1줄 `[월드 엠블럼] {월드} · {이름} · Lv.{레벨}`, 2줄 `text-text-muted` `캐릭터 {N}개`. **직업 미표시**(이름이 길면 넘겨서 대신 월드를 첫 줄로). 월드 엠블럼 `src/assets/worlds/*`, `h-[18px] w-auto object-contain shrink-0`, 미매핑 월드는 텍스트만. 1줄 `truncate`, 텍스트 컬럼 `min-w-0`. 월드→엠블럼 매핑은 `world-emblems.json`(챌린저스1~4 모두 `challengers`). 컴포넌트는 온보딩 페이지형 레이아웃에 맞춰 자체 카드 없이 `w-full space-y-4` — 설정 계정 변경 모달이 이걸 카드로 감싸 재사용(모달 `card={false}`).
**계정이 1개면 그 항목을 초기 하이라이트로 지정한다**([[ADR-051]]) — 고를 것이 하나뿐이므로 항목 선택 탭은 생략하고 "계속하기" 확정 행위만 남긴다.

### 예열 진행률 바 — [[ADR-016]]
진행률 바 프리미티브([../foundation/design-system.md](../foundation/design-system.md)) 재사용 + "캐릭터 정보를 준비하고 있어요 (18/45)" `text-sm text-text-muted`. **세로 중앙 배치**(2026-07-16): 예열은 온보딩 유일의 수 초 대기 화면이라 상단 붙임보다 중앙이 대기 화면다움. 컨테이너 `min-h-[calc(100dvh-var(--sa-top)-var(--sa-bottom))]` + `flex items-center justify-center`(온보딩엔 하단 탭바 없어 `--sa-bottom` 까지 빼야 정중앙). 설정의 재인증 예열(`AccountFlowStatus`, 모달 안)은 대상 아님.

시드 단계(`seedingTracking`)는 진행률 숫자가 없어 스피너만 쓴다 — `MapleSweepSpinner size={32} text-primary` + "체크리스트를 준비하고 있어요". 화면 전체 대기라 셸 승계 카드는 씌우지 않는다([[ADR-061]] 결정 2).

### 추적 캐릭터 선택 단계 — 후보 목록 로딩 ([[ADR-053]], 구현 완료 2026-07-29)
**API 키 단계 실패 표시 ([[ADR-065]] 결정 1)**: 실패는 **토스트**로 알린다 — 문구가 사라져도 이 자리엔 폼이 남으므로([[ADR-063]] 원칙 4) 인라인 문구를 두지 않는다. 세 경로 모두 `formatOnboardingError`(위치: `features/onboarding/format.ts` — 스토어가 쓰므로 `app/` 이 아니다) 로 **원인별 문구**를 띄운다.
- `submitApiKey` 실패 — 전에는 원인과 무관하게 한 문구였다(바로 아래에서 원인을 계산해 state에 넣으면서도 토스트는 그 값을 안 썼다).
- `hydrate` 실패(저장된 키로 재실행했다가 조회 실패) — 전에는 토스트가 아예 없어 아무 설명 없이 입력 화면으로 되돌아갔다.
- `setApiKey`(키 저장) 실패 — 전에는 `try` 밖이라 미처리 rejection이었다. 이제 `storageWriteFailed` 로 알린다(그 문구가 처음으로 도달 가능해졌다).
- 액션은 두지 않는다 — 온보딩 중에는 설정 화면이 없고 재시도는 폼에서 한다.

`ContentCharacterStep`([[ADR-035]] 결정 13)은 캐릭터 관리 피커와 같은 `getCharacterPickerRoster` 를 쓰므로 같은 정책을 따른다(원문은 [content-scheduler.md](./content-scheduler.md) "캐릭터 관리 피커 — 후보 목록 로딩"): **활성(`access_flag: true`)이 확인된 캐릭터만** 표시, 표시할 캐시가 없으면 **스피너 → 조회 완료 후 한 번에** 목록(캐시가 있으면 기존 [[ADR-016]] 즉시 표시 + 개별 patch 유지), 조회가 끝났는데 목록이 비면 **"활성 캐릭터 없음"과 "조회 실패"를 구분**해 안내한다.
- 이 단계는 예열([[ADR-016]]) 직후라 정상 경로에서는 캐시가 항상 따뜻하다 — 콜드 스타트 분기는 예열이 통째로 실패했을 때만 밟는다. 그래서 여기서는 특히 **"조회 실패"를 빈 상태로 위장하지 않는 것**이 중요하다(선택할 캐릭터가 없으면 CTA가 비활성이라 온보딩이 진행 불가 상태로 멈춘다).
- 모달이 아니라 페이지라 판정 분기는 `ContentCharacterStep` 안의 `RosterBody` 가 직접 그린다(피커와 동일한 우선순위·마크업). 실패도 피커와 같은 공용 `ErrorState` 를 쓰고([[ADR-062]]), 스탈 배너 분기도 같다. **다른 것은 액션뿐** — 온보딩 중에는 설정 화면이 없으므로 `invalidApiKey` 도 **다시 시도**이고 설명만 "API 키를 다시 확인해주세요"로 갈린다(피커는 "설정에서 키를 다시 등록해주세요" + 설정 열기).
- **후보가 0건이면 "계정 다시 선택"을 준다**([[ADR-086]] 결정 8, 2026-08-03). 결정 8이 조회 불가 계정을 잠갔어도 고른 뒤 전원이 조회 불가로 바뀌는 경로는 남는다 — 온보딩에는 설정 화면이 없어 계정 선택 단계로 되돌아가는 것이 유일한 탈출구다. 피커의 빈 상태 문구("표시할 캐릭터가 없어요")를 그대로 쓰되 여기에만 이 액션이 붙는다.
- **최소 1명을 골라야 저장된다**([[ADR-086]] 결정 7) — 0명은 화면을 빈 상태로 만들 뿐 어떤 의도도 표현하지 않는다. 피커도 같은 규칙이다([content-scheduler.md](./content-scheduler.md)).

## 계정 선택 프로브 ([[ADR-068]] 결정 4)
계정 선택 화면은 각 계정의 **전체 캐릭터**에 `character/basic` 을 프로브한다(`features/onboarding/use-account-probes`). 전에는 대표 1명만 조회해 초상화만 채웠다.
- **대표는 "조회 가능한 캐릭터 중 최고 레벨"** — `character/list` 의 최고 레벨이 조회 불가일 수 있어(실측) 계정 표기가 조회 불가 캐릭터의 이름·레벨이 되던 문제를 없앤다. 프로브 완료 전에는 `character/list` 기준으로 잠깐 보여주고 결과가 오면 교체한다.
- **전원 조회 불가면 그 계정 카드에 경고**("이 계정의 캐릭터를 조회할 수 없습니다"). 전수 프로브라 "이 계정 전체"를 단정할 수 있다 — 표본 1명으로는 못 한다(월드 리프는 캐릭터 1~2개 단위가 흔하다).
- **그 계정은 고를 수 없다**([[ADR-086]] 결정 8, 2026-08-03). 전에는 경고만 띄우고 선택은 허용했는데, 고르면 후보가 0명이라 "최소 1명" 규칙을 만족할 수 없어 온보딩이 진행 불가 상태로 멈춘다 — 들어갈 수 없는 문은 잠근다. **프로브 도착 전에는 선택 가능**하고(모르는 것을 단정하지 않는다) 결과가 오면 그때 비활성으로 바뀐다. 설정의 계정 변경도 같은 컴포넌트를 쓰므로 같이 적용된다.
- **조회 불가(`OPENAPI00003`)만 영구로 다룬다** — 네트워크 등 그 외 실패는 후보 자격을 유지하고 초상화만 비운다.
**계정 선택 실패 표시 ([[ADR-083]] 결정 4, 2026-08-02)**: 목록 상단 인라인 문구(`AccountSelectionList` 의 `errorMessage` prop)를 없애고 **토스트**로 통일했다 — 계정 목록·"계속하기"가 그 자리에 남으므로([[ADR-063]] 원칙 4) 인라인일 이유가 없었다.
- 네 종류 중 `invalidApiKey`·`rateLimited`·`network` 는 **이미 스토어가 토스트를 띄우고 있어** 인라인은 중복이었다([[ADR-065]] 결정 1이 API 키 경로에 넣은 것).
- `storageWriteFailed`(계정 선택 저장 실패)만 토스트가 없어 인라인을 지우면 무음이 된다 — `selectAccount` 의 `catch` 에 토스트를 추가했다. 액션은 두지 않는다(다시 계정을 누르면 되는 일이라 중복).
- 설정의 계정 변경 모달(`AccountFlowStatus`)은 이미 `errorMessage={null}` 을 넘기고 있어 표시가 바뀌지 않는다. 모달 본문 전체를 차지하는 그 컴포넌트 자신의 `error` 케이스는 여전히 인라인이다(그 자리의 내용).

- **결과를 `character-basic-cache` 에 쓰지 않는다** — 고르지 않은 계정 캐릭터가 캐시에 들어가면 피커의 stub 단계([[ADR-017]] 결정 6)가 다른 계정 캐릭터를 보여준다. 그래서 예열([[ADR-016]])의 캐싱 범위는 그대로다(호출은 그만큼 중복되지만 사용자가 지연을 감수하기로 했다, 2026-07-31).

## 열린 질문
- 캐릭터 관리 피커 개선([[ADR-015]]) 잔여: Nexon `character/look` 이미지 얼굴 크롭 쿼리 공식 지원 여부(미지원 시 CSS 근사), 개선을 다른 캐릭터 선택 UI로 확장할지.
