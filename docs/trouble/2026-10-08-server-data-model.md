> 이 문서는 **세션 인수인계**다. 결정의 원본은 ADR-340 · 341 · 342 · 343 · 344 이고

## 어디서 시작했나

사용자 요청: 앱이 거의 서버리스라 서버 작업이 안 돼 있다. `user` 부터 시작해 서버에 무엇을 저장할지
정하고 표를 정의해야 하는데 서버 개발 경험이 부족해 막막하다.

조사 결과 **백지가 아니었다.** 서버는 이미 돌고 있었고(Fastify 5 + raw `pg` + `node-pg-migrate`,
집 미니 PC 도커, Oracle nginx 앞단) 없는 것은 둘이었다 - **사용자 표가 없고, 앱이 서버에 데이터를
쓰는 경로가 0개**였다.

## 결정된 것 (ADR 본문이 원본)

- **기존 기능은 인증 수단으로 안 가른다.** 새 기능(크레딧 #609 · 드롭스 #620 · 상점 ·
  내보내기 #612)만 넥슨 로그인을 요구한다 (ADR-340 결정 1)
- **사람은 `users` 한 표**이고 열쇠 둘(`nexon_uid` · `api_key_hash`)을 칸으로 든다 (결정 2)
- **키 사용자의 데이터도 모은다**(#610 · #611 · #507). 해시가 사실상 비밀번호인 것을 알고 골랐다 (결정 3)
- **키를 더하는 기능은 로그인 사용자에게만** 열어 서버가 보는 열쇠가 늘 하나다 (결정 8)
- **PK 는 항상 uuid 한 칸.** 복합 PK 도, 복합 `UNIQUE` 도 안 쓴다. 유일성은 uuid 칸 하나에
  걸고, 조회 속도는 평범한 인덱스로, 소유 확인은 쿼리 문장(`WHERE … = EXCLUDED.user_id`)으로
- **게임 수치 16개만 서버로.** 좌표 넷 · `job-themes` · `release-notes` · `feature-guides` 는
  번들 그림에 묶여 안 간다 (ADR-341)
- **드롭 가격 전송**: 기기가 uuid 를 만들고, 기기 저장이 먼저, 저장·수정 그 자리에서 한 건,
  실패는 대기 표, 부팅에 백그라운드로 훑고 **5회까지. 네트워크가 없으면 안 센다** (ADR-342 · 343)
- **기능이 나간 뒤 시작된 기간만** 보낸다. 기준은 불변인 `period_key` (ADR-342 결정 8)

## 다음에 할 일

### 1. 앱 브랜치를 올린다

`feat/drop-record-uuid` 가 로컬에만 있다. PR 을 열고 머지한다. 본문에 **되돌릴 수 없는 것이
없다는 점**(기기 이관은 칸 추가와 PK 재작성뿐, 기존 월드는 안 채움)을 적는다.

### 2. `server_sync_queue` (ADR-343) — 아직 0줄

ADR-343 이 결정 여섯을 적었고 코드가 없다. 만들 것.

```
server_sync_queue   id uuid PK · kind · record_id UNIQUE · attempts · last_error · created_at
읽기/보내기 함수를 kind 마다 등록하는 레지스트리 (선례: app/today/widgets/registry.ts)
훑는 고리는 종류를 모른다 - 원본이 있으면 올리고 없으면 지운다
고리와 레지스트리는 features/ 에, 원본 읽기는 storage/ 어댑터를 거친다 (ADR-003)
```

**함정**: 종류를 레지스트리에 안 더하면 표에 행만 쌓이고 조용히 안 나간다. 위젯 레지스트리처럼
테스트가 지켜야 한다.

### 3. 서버의 #610 시세 표 — 이름과 칸이 미정

ADR-342 결정 7 이 모양만 정했다. `id uuid` PK + `drop_record_id uuid UNIQUE` + `user_id`.
`REFERENCES` 는 안 붙인다(참조할 표가 서버에 없다). 나머지 칸은 #610 이 사용자 결정으로 열어 뒀다.

### 4. 앱이 가격을 보내는 경로

`BossDropSheet` 저장 → `drop-price-store` 가 그 자리에서 한 건 보냄. `'entered'` 만.
`period_key >= 기준` 만. SHA-256 구현(API 키 해시용)을 고르는 것이 선행이다.

## 열린 질문 (ADR 본문에 있고, 무거운 것만)

- **집계 단위** (ADR-340 · 342, 결정은 #611 이 소유). 사람 단위로 합산하면 계정 여럿인 사람의
  값이 한 계정으로 **닿을 수 없는 값**이 된다(사용자 지적). 앱 화면의 합계 단위와 서버 분포의
  단위가 같아야 하는데 `features/stats/aggregate.ts` 는 추적 목록 전체를 더해 메이플 ID 를
  가로지른다(ADR-297 미구현). 선 채로 틀리지 않는 것은 `ocid` 단위뿐이다
- **SHA-256 구현 선택**. 순수 JS 면 OTA, 네이티브면 스토어 빌드. **uuid 는 이 질문에서
  빠졌다** - SQLite 가 만든다
- **처리방침 · Play 데이터 안전 · App Store 라벨**. 결정 3 이 수집을 전원으로 넓혀 넥슨 승인을
  기다릴 수 없다. 스토어 빌드가 나가기 전에 끝나야 한다
- **넥슨 로그인은 아직 꺼져 있다**(`NEXON_LOGIN_ENABLED = false`, ADR-334). 프로덕션 승인 전까지
  새 기능이 아무에게도 안 열리고 유도할 자리도 없다
- `slot` · `ring_level` 을 서버로 보내나 (게임 지식이라 ADR-006 절차로 사용자 확인 필요)

## 이 세션에서 값을 치르고 배운 것

- **`pool.query<T>` 는 검증이 아니라 단언이다.** SQL 을 `notice_key` 로 고쳐도 지역 행 타입이
  `id` 를 말하면 타입 검사를 통과하고 런타임에 `undefined` 가 된다. 세 자리가 그 상태였다
- **표 본문을 공유하는 마이그레이션이 과거를 깨뜨린다.** `BOSS_DROP_RECORDS_BODY` 를 버전 4 의
  재작성이 함께 쓰므로, 새 칸을 `NOT NULL` PK 로 두자 그 버전에서 `INSERT OR IGNORE` 가 드롭
  기록을 통째로 버렸다. 파일 머리가 경고해 둔 그 함정이다
- **ADR 배지를 먼저 보라는 규칙이 실제로 필요했다.** ADR-296 의 「토큰은 서버가 든다」를 전제로
  설계하다가 ADR-320 을 열어 보고서야 뒤집힌 것을 알았다. 그 사실이 어디에도 기록돼 있지 않았다
- **마이그레이션 검증은 `pg_dump -s`(또는 전체)로 운영을 임시 DB 에 복제해서** 한다. 로컬에
  `psql` 이 없고 도커 데몬도 꺼져 있어 이 길이 유일했다. SQL 은 파일에 두고
  `ssh … "docker exec -i postgres psql …" < 파일.sql` 로 넣으면 따옴표 함정이 없다

## 작업 규약 (이 세션에서 지적받은 것)

- **한국어로 답한다.** docs-first → TDD. 테스트는 **영향 범위 경로만** 지정해 돌린다
  (`--testPathIgnorePatterns /node_modules/ /.claude/` 를 꼭 붙일 것 - 워크트리 사본이 섞인다)
- **없는 표·칸 이름을 지어내지 말 것.** 아직 없는 것은 이슈 번호로 부른다. 이 세션에서
  `drop_price_reports` · `device_record_id` · `op` 로 세 번 지적받았다
- **단정하기 전에 코드나 DB 로 확인한다.** ADR 에 적힌 말을 그대로 옮기면 틀린다
  (「Hermes 에 `crypto` 가 없다」는 결과적으로 맞았지만 확인 없이 여러 번 말했다)
- **결론을 먼저 내놓고 단서를 뒤에 붙이지 말 것.** 「서버 파서는 필요 없다」고 한 뒤 썬데이
  때문에 필요하다고 덧붙여 혼란을 만들었다
- 장식 기호 금지: `—` · `«»` · `「」` 를 쓰지 않고 `-` · 볼드 · 백틱을 쓴다. 가운뎃점 `·` 은 쓴다
