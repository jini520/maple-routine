## 공통 규칙 (이 step 의 모든 위젯에 걸린다)

- **위젯은 스토어를 모른다.** `data: TodayViewModel` 프롭만 읽는다([[ADR-146]] 결정 4).
- **`w`·`h` 로 갈라 스스로 다르게 그린다** — 큰 타일이 작은 타일을 확대한 것이 아니다.
  크기가 줄면 **무엇을 버릴지 위젯이 정한다.**
- **타일은 스스로 커지거나 줄지 않는다.** 크기는 배치가 준다(`4×auto` 만 예외, 정정 1).
- **타일 안에서 스크롤하지 마라.** 넘치면 자르거나 접는다 — 타일 안 스크롤은 페이지 스크롤과
  제스처를 두고 싸운다.
- **위젯은 사라지지 않는다**([[ADR-146]] 결정 5). 데이터가 없어도 **자기 타일 안에서** 빈 상태를 말한다 —
  좌표 배치라 자리를 빼면 빈 사각형이 남는다.
- **«없다» 와 «모른다» 를 가른다.** 동기화 실패로 모르는 것을 «0» 으로 그리지 마라
  (예외는 주간 보스 수익 하나 — 정정 4).
- **색은 테마 토큰만 쓴다.** 하드코딩 hex 금지(`/docs/features/theme.md`).
- **선언한 크기를 전부 구현한다**(사용자 확정) — v1 배치가 안 쓰는 크기도 나중 편집 기능을 위해 남긴다.
  각 크기는 **스냅샷 테스트**로 검증한다(그것이 안 쓰이는 분기의 유일한 안전망이다).


## 작업

### 1. 대표 캐릭터 — `widgets/RepresentativeCharacterWidget.tsx`

**세 크기 전부 같은 구조**(엠블럼 + 세 줄 + EXP):

```
[초상화] [엠블럼] 단풍루틴
         Lv. 291  아크메이지(불,독)
         백호단
         EXP ────────────── 80.300%
```

| 크기 | 형태 |
|---|---|
| **4x1** (기본) | 초상화 44 · 이름 13px · 2줄 10.5px · 3줄 10px · EXP 는 **오른쪽 70px 열**(퍼센트 + 얇은 바) |
| 4x2 | 초상화 72 · 이름 19px · EXP 바가 아래 전체 폭 |
| 2x2 | 가운데 정렬 · 초상화 56 · **직업이 잘린다**(158폭의 한계 — 말줄임) |

- **월드는 텍스트 배지가 아니라 엠블럼 이미지**다 — `lib/world-emblem.ts` 의 `worldEmblemUrl(world)`.
  **매핑에 없거나 파일이 없으면 `null` 이고 그때는 엠블럼만 생략한다**(그 함수가 이미 정한 폴백).
- **EXP 는 소수 3자리 그대로**(`80.300%`) — API 가 주는 값이 그렇다. 반올림하지 마라.
- **`expRate` 가 없으면 EXP 줄 자체를 그리지 않는다.** 0% 바를 그리면 «경험치가 0» 으로 읽힌다.
  «EXP 없음» 을 **설계된 상태로 다루지는 않는다**(정정 8) — 방어적 기본값일 뿐이다.
- **«대표 없음» 상태는 없다**(정정 2). 뷰모델이 `resolveDisplayRepresentative` 로 이미 답을 준다.
  `representative === null` 은 **추적 캐릭터가 하나도 없을 때뿐**이고, 그때만 최소한의 빈 문구를 그린다.
- **«임시 대표» 라는 표시를 하지 마라**([[ADR-144]] 결정 4).

### 2. 남은 스케줄 — `widgets/RemainingScheduleWidget.tsx` (`4×auto`)

**행 하나의 구조**:

```
[초상화 32] 야간비행                일퀘  4   주간퀘  1
                              주간 보스  1     검마  1
```

- **수치는 배지가 아니라 텍스트**다(정정 9). 알약을 쓰지 마라.
- **2×2 격자로 세운다**(정정 12) — col A = 일퀘/주간 보스, col B = 주간퀘/검마.
  **라벨 폭을 고정**하고 숫자에 `tabular-nums` 를 걸어 **모든 행의 숫자가 같은 x** 에 서게 한다.
  이것이 이 위젯의 형태 전부다 — 그냥 나열하면 라벨 길이가 제각각(「일퀘」 2자 · 「주간 보스」 4자)이라
  숫자가 행마다 다른 자리에서 끝나고 세로로 훑을 수가 없다.
- **`·` 구분자를 쓰지 마라** — 열이 있으면 구분자가 할 일이 없다.
- **강조는 굵기 하나뿐**: 숫자 `font-weight: 800`, 라벨 400. **크기는 같다.**
  색은 **라벨 `text-muted` · 숫자 `text`**(읽기 2 확정). **테마 색(`primary-ink` 등)을 쓰지 마라** —
  칠하면 이 타일 하나에 강조색이 캐릭터 수만큼 반복돼 격자에서 «여기가 제일 중요하다» 를 잘못 말한다.
- **빈 칸은 격자 자리로 남긴다**(고정 행 높이). 보스가 0인 캐릭터는 둘째 줄이 비는데, 행을 줄이면
  **행 높이가 데이터마다 달라져** auto 높이 계산이 성립하지 않는다.
- **배지는 특수 케이스만** — `CLEAR`(완료) 와 「동기화 실패」. 둘은 수치가 아니라 **상태**라 다른 형태를
  가질 근거가 있다. **「다 했습니다」 같은 문장을 쓰지 마라.**
- 행 사이에 **헤어라인**(`border-border`), 헤더 아래에 `border-strong` 한 줄.
- 헤더 합계도 칩이 아니라 텍스트(`14개`, 숫자만 굵게).
- **모든 캐릭터를 그린다** — 「외 N명」 접기 없음. **«전부 완료» 전용 UI 도 없다**(같은 목록이 전부
  `CLEAR` 로 서는 것이 전부 — 형태가 안 바뀌어야 «어제와 같은 화면» 으로 읽힌다).
- 실측 목표 **`55 + 45n` px**(2명 145 · 4명 236 · 6명 326). 이 값에 맞추려고 내용을 줄이지는 말고,
  실제 높이가 나오면 그 값으로 `resolveWidgetPositions` 가 아래를 민다.

## 금지사항

- **수치를 알약(배지)으로 그리지 마라.** 이유: 정정 9.
- **숫자에 테마 색을 쓰지 마라.** 이유: 위 절.
- **행 높이를 데이터에 따라 바꾸지 마라.** 이유: auto 높이 계산이 깨진다.
- **「외 N명」·상한·«전부 완료» 축하 UI 를 만들지 마라.** 이유: 사용자 확정.
- **`character_exp`(누적 절대값)를 그리지 마라.** 이유: 레벨이 오를수록 커져 «얼마나 남았나» 를 못 말한다.
- 기존 테스트를 깨뜨리지 마라.
