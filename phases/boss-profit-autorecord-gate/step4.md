## 작업

### 1. `docs/adr/ADR-111.md` 를 구현 완료 상태로 정정

- `**상태**` 를 `**구현 완료**, 2026-08-08, 이슈 #160` 으로 바꾸고, 무엇을 근거로 그렇게 말하는지 함께 적어라(`npm test` 통과 개수·lint clean). **실기기 검증은 하지 않았으므로 "실기기 미검증"을 명시하라** — [[ADR-097]] 이 같은 형식으로 적어둔 것을 참고하라.
- `## 검증` 절을 **설계 시점 목록에서 "실제 확인된 것"으로 다시 쓴다.** [[ADR-097]] 의 `## 검증` 절이 하는 방식을 그대로 따라라 — **자동 테스트로 확인됨**(확인한 것 / 결정 / 테스트 경로 3열 표)과 **실기기·실사용으로만 확인되는 것**(미확인)으로 가른다.
  - 자동 테스트 표에는 실제 존재하는 `describe`/`it` 이름과 파일 경로를 적어라. 없는 테스트를 적지 마라.
  - 실기기 미확인 항목에는 최소 이슈 #160 의 검증 조건을 넣어라: **콜드 스타트 → `/content` → 수익 탭에서 새로고침 없이 총 수익이 바로 맞게 나온다.**
- 설계 시점 서술과 실제 구현이 달라진 부분이 있으면 **지우지 말고** [[ADR-097]] 처럼 `**정정 N (구현, 2026-08-08) — …**` 형식으로 아래에 덧붙여라. 왜 달라졌는지를 함께 적어라.

## 금지사항

- **`src/` 아래 파일을 수정하지 마라.** 이유: 이 step 은 문서 마감이다. 코드 수정이 필요할 만큼의 결함을 발견했다면 고치지 말고 `error` 로 보고하라 — 그래야 어느 step 이 미완이었는지가 남는다.
- **실기기에서 확인하지 않은 것을 "확인됨"으로 적지 마라.** 이유: [[ADR-097]] 이 같은 자리에서 "자동 테스트로 확인된 것"과 "실기기로만 확인되는 것"을 가른 이유가 바로 그것이고, 거짓 확인 표기는 다음 사람이 검증을 건너뛰게 만든다.
- **테스트 경로를 추측해서 적지 마라.** 이유: 문서의 회귀 가드 표는 다음 사람이 그 자리를 실제로 열어보는 용도다. 파일을 열어 `describe`/`it` 이름을 확인하고 적어라.
- **ADR-097 의 결정 1~5·7·8 을 고치지 마라.** 이유: 네트워크 재조회 정책은 이번 작업에서 바뀌지 않았다.
- **`docs/ADR.md` 에 ADR 전문을 쓰지 마라.** 이유: 그 파일은 슬림 인덱스이고, 전문은 `docs/adr/ADR-NNN.md` 에 산다.
- 기존 테스트를 깨뜨리지 마라
